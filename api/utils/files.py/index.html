    files.py

    Source: utils/files.py

    Following the filtering and pattern sanitization established in exclude_patterns.py, the repository ingestion engine requires utilities to format, index, and retrieve source file contents efficiently. The utils/files.py module provides transformation and selective retrieval helpers that bridge raw ingested file tuples and downstream prompt synthesis nodes.

    Technical Overview

    utils/files.py acts as a lightweight data transformation and selective access layer within the codebase documentation pipeline. After ingestion nodes (such as crawl_local_files.py and crawl_github_files.py) read source trees and filter out non-essential assets, the collected codebase is typically represented in memory as an ordered sequence of file paths and their contents. This module provides formatting tools to project this in-memory list into structural representations optimized for Large Language Model (LLM) prompts, as well as targeted accessors to pull specific file contents on demand.

    The primary architectural role of files.py is optimizing LLM token budgets. Rather than injecting the entire codebase content into an initial reasoning prompt—which would rapidly exhaust context windows or incur excessive costs—the pipeline uses build_directory_tree() to construct a compact, human-readable directory hierarchy where each file is tagged with its zero-based integer index. Upstream analysis nodes (such as ContextRouter, IdentifyAbstractions, MapAbstractions, and CombineTutorial in nodes.py) provide this structural map to LLMs so they can evaluate project architecture and return lists of relevant file indices. Subsequently, get_content_for_indices() resolves those indices back into concrete file contents, loading only the source code necessary for detailed analysis.

    Public API

    build_directory_tree()

    Visibility: Public
    Signature: def build_directory_tree(files_data: list[tuple[str, str]]) -> str:

    Description: Constructs a compact, hierarchical directory tree formatted as a single string from an enumerated list of (path, content) tuples. Files are grouped by their parent directory paths, with root-level files assigned to ".". Directories and filenames within each directory are sorted lexicographically to guarantee deterministic output across different operating systems and execution runs. Each file entry is annotated with its integer index in files_data (e.g., basename (idx:0)), allowing downstream LLM nodes to reference files by index rather than passing full filesystem paths.

    Parameters: * files_data (list[tuple[str, str]]): Ordered collection of two-element tuples, where index 0 is the relative file path string and index 1 is the decoded text content of the file.

    Returns: * str: A multiline string displaying directory paths terminated with / followed by two-space indented file entries with appended (idx:{i}) identifiers.

    Raises: * This function raises no custom exceptions. If files_data is malformed (e.g., contains items that cannot be unpacked into two variables), a standard Python ValueError or TypeError will propagate.

    Phase 1: Directory Grouping and Index Tagging

        dir_files = defaultdict(list)
    for i, (path, _content) in enumerate(files_data):
        dirname = os.path.dirname(path) or "."
        basename = os.path.basename(path)
        dir_files[dirname].append(f"{basename} (idx:{i})")
    In this phase, the function iterates over files_data using enumerate to preserve the original integer index of each file. It decomposes each file path into its directory component (dirname) and filename component (basename) using os.path.dirname and os.path.basename. If os.path.dirname(path) returns an empty string (indicating a file situated at the root of the scanned repository), the directory defaults to ".". The formatted string f"{basename} (idx:{i})" is appended to a list in a collections.defaultdict(list), grouping all files under their respective parent directories.

    Phase 2: Hierarchical Sorting and Tree String Formatting

    In this phase, the collected directories are sorted alphabetically using sorted(dir_files.keys()). For each directory, a header line is appended with a trailing slash (f"{dirname}/"). The function then iterates over the sorted list of filenames belonging to that directory (sorted(dir_files[dirname])), indenting each entry by two spaces (" "). Finally, all lines are joined with newline characters ("\n"), producing a unified textual representation of the project hierarchy.

    Example: 

    # Extracted from utils/files.py:
def build_directory_tree(files_data):
    """Build a compact directory tree string from the list of (path, content) tuples.

    Groups files by directory and formats as a hierarchical tree with file indices.
    Used by ContextRouter, IdentifyAbstractions, MapAbstractions, and CombineTutorial
    to give LLMs structural context about the project layout.
    """
    dir_files = defaultdict(list)
    for i, (path, _content) in enumerate(files_data):
        dirname = os.path.dirname(path) or "."
        basename = os.path.basename(path)
        dir_files[dirname].append(f"{basename} (idx:{i})")

    lines = []
    for dirname in sorted(dir_files.keys()):
        lines.append(f"{dirname}/")
        lines.extend(f"  {fname}" for fname in sorted(dir_files[dirname]))
    return "\n".join(lines)

    get_content_for_indices()

    Visibility: Public
    Signature: def get_content_for_indices(files_data: list[tuple[str, str]], indices: list[int] | set[int] | collections.abc.Iterable[int]) -> dict[str, str]:

    Description: Extracts the text content for a targeted collection of integer indices from the files_data list. It performs bounds checking against the total length of files_data to silently ignore invalid or negative indices. For each valid index, it extracts the file path and content, assembling a dictionary whose key combines the integer index and the file path (formatted as "{i} # {path}"), with the value containing the raw file content string.

    Parameters: * files_data (list[tuple[str, str]]): Ordered list of (path, content) tuples representing the ingested repository. * indices (Iterable[int]): An iterable collection of integer indices specifying which files should be extracted from files_data.

    Returns: * dict[str, str]: A dictionary mapping formatted identifier strings ("{index} # {relative_path}") to their corresponding file content strings.

    Raises: * This function raises no exceptions. Out-of-bounds indices are discarded via an explicit boundary condition check.

    Bounds Validation and Map Assembly

    def get_content_for_indices(files_data, indices):
    """Get file content for specific indices from files_data list."""
    content_map = {}
    for i in indices:
        if 0 <= i < len(files_data):
            path, content = files_data[i]
            content_map[f"{i} # {path}"] = content  # Use index + path as key for context
    return content_map
    The implementation initializes an empty content_map dictionary and iterates across each index i provided in indices. The conditional expression if 0 <= i < len(files_data) protects against negative indexing and IndexError exceptions caused by hallucinated or stale indices emitted by an LLM. When an index satisfies the bounds check, the function unpacks (path, content) from files_data[i] and stores the entry using the composite key f"{i} # {path}". This composite key ensures that downstream prompts retain both the numerical identifier and the human-readable path alongside the source code content.

    Example: 

    # Extracted from utils/files.py:

    return content_map

    Data Structures

    files_data List Schema

    files_data is the standard intermediate representation passed between crawler modules, transformation functions in files.py, and orchestration nodes in nodes.py.

    Element Type Description
    [i][0] (path) str Relative file path from the repository root (e.g., "src/core/engine.py" or "README.md").
    [i][1] (content) str Decoded UTF-8 string content of the source file.

    Structural Schema Example

    [
    ("main.py", "import sys\n\ndef run():\n    pass\n"),
    ("utils/files.py", "import os\nfrom collections import defaultdict\n..."),
    ("utils/token_utils.py", "def count_tokens(text):\n    ...")
]

    Compact Directory Tree String Schema

    Generated by build_directory_tree(). It structures file paths hierarchically without nested indentation trees, using explicit directory lines followed by indented filename listings.

    Component Format Description
    Directory Header {dirname}/ The normalized directory path ending with a forward slash. Root files use ./.
    File Listing {basename} (idx:{i}) Two-space indentation followed by the filename and its corresponding index in files_data.

    Output Representation Example

    ./
  main.py (idx:0)
  README.md (idx:1)
utils/
  call_llm.py (idx:2)
  files.py (idx:3)
  token_utils.py (idx:4)

    Content Map Schema

    Generated by get_content_for_indices(). It stores extracted file contents indexed by a compound key consisting of the file's numerical index and its repository-relative path.

    Key Key Type Value Type Description
    "{i} # {path}" str str The composite key combining index i and file path path, mapped to the complete string content of the file.

    Dictionary Structure Example

    {
    "0 # main.py": "import sys\n\ndef run():\n    pass\n",
    "3 # utils/files.py": "\"\"\"File and content helpers used by multiple nodes.\"\"\"\n\nimport os..."
}

    Error Handling

    utils/files.py relies on defensive programming patterns to ensure stability when processing variable inputs:

    • Index Bounds Protection: In get_content_for_indices(), caller-provided indices often originate from unvalidated LLM output strings that are parsed into integers. To prevent out-of-range indexing crashes, the function guards list access with if 0 <= i < len(files_data). Any index that is negative or greater than or equal to len(files_data) is bypassed without raising IndexError.
    • Root Directory Normalization: In build_directory_tree(), calling os.path.dirname(path) on a file located in the root directory (e.g., "main.py") yields an empty string "". The expression os.path.dirname(path) or "." intercepts this empty string and substitutes ".", ensuring that root-level files are grouped together under a valid directory entry.
    • Empty Collection Handling: If an empty list [] is passed to build_directory_tree(), the loop over files_data does not execute, dir_files remains empty, and the function cleanly returns an empty string "". Similarly, passing an empty index list or an empty files_data list to get_content_for_indices() cleanly returns an empty dictionary {}.
