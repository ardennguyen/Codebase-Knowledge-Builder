    files.py

    Source: utils/files.py

    Technical Overview

    The utils/files.py module provides foundational in-memory file aggregation, structural layout rendering, and targeted content extraction utilities for the Codebase-Knowledge-Builder pipeline. Operating without internal project dependencies, it serves as a lightweight data presentation layer situated between repository crawlers (such as local directory scanners or remote GitHub extractors) and the pipeline's LLM-driven analysis nodes. Its primary responsibility is to transform flat sequences of ingested file tuples into compact, high-density structural representations and indexed lookup dictionaries tailored for LLM prompt ingestion.

    The module provides two public functions: build_directory_tree and get_content_for_indices. build_directory_tree groups individual file paths by their directory containers using os.path.dirname, annotates each file basename with its zero-based positional index (idx:{i}), and formats the entire codebase layout into an alphabetically sorted, indented hierarchy. This enables language models to perceive repository topology, package nesting, and file locations while consuming a fraction of the token budget required by raw path enumerations. Complementing this, get_content_for_indices accepts targeted index selections produced by downstream planning nodes, extracts the corresponding file contents using defensive boundary checks, and returns a key-annotated mapping (f"{i} # {path}") ready for prompt injection.

    Public API

    build_directory_tree()

    Visibility: Public Signature: def build_directory_tree(files_data):

    Description: Constructs a compact, human-readable directory tree string from an ordered sequence of file path and content tuples. For each entry, the directory path is isolated using os.path.dirname, defaulting to "." for root-level files, while the filename is isolated using os.path.basename. Each filename is formatted with its zero-based ordinal index suffix (idx:{i}). The parent directories and their respective file entries are sorted in lexicographical order. The resulting string lists each directory suffixed with a slash (/), followed by its indented constituent files.

    Parameters: * files_data (list[tuple[str, str]]): Sequence of (path, content) tuples representing the codebase files and their contents.

    Returns: * str: A multi-line string representing the hierarchical file tree with directory headings and two-space indented file entries.

    Raises: * TypeError: If files_data is not iterable or contains elements that cannot be unpacked into a 2-tuple. * AttributeError: If a file path within files_data is not a valid string or path-like object compatible with os.path.dirname.

    Example: 

    def build_directory_tree(files_data):
    """Build a compact directory tree string from the list of (path, content) tuples.

    Groups files by directory and formats as a hierarchical tree with file indices.
    Used by ContextRouter, IdentifyAbstractions, MapAbstractions, and CombineTutorial
    to give LLMs structural context about the project layout.
    """
    dir_files = defaultdict(list)
    for i, (path, _content) in enumerate(files_data):
        dirname = os.path.dirname(path) or "."
        basename = os.path.basename(path)
        dir_files[dirname].append(f"{basename} (idx:{i})")

    lines = []
    for dirname in sorted(dir_files.keys()):
        lines.append(f"{dirname}/")
        lines.extend(f"  {fname}" for fname in sorted(dir_files[dirname]))
    return "\n".join(lines)

    The function iterates over files_data with enumerate() to assign a stable, linear index to each file matching its position in the list. It builds a collections.defaultdict(list) where each unique directory path maps to a list of annotated basename strings. By applying sorted() across both the directory keys and the basename lists, the rendered output remains completely deterministic regardless of the order in which files were crawled. Each directory name is printed with a trailing / header, and member files are indented by two spaces (), minimizing total character count while preserving visual and semantic hierarchy for upstream LLM prompts.

    get_content_for_indices()

    Visibility: Public Signature: def get_content_for_indices(files_data, indices):

    Description: Selectively extracts the source code content for a specific subset of file indices from the master files_data collection. For each index in indices, it validates that the index lies within the valid array bounds [0, len(files_data) - 1]. For matching entries, it records the content in a returned dictionary keyed by a composite string combining the index and file path (f"{i} # {path}"). Any index that is negative or exceeds the maximum index of files_data is silently ignored.

    Parameters: * files_data (list[tuple[str, str]]): Master sequence of (path, content) tuples representing the ingested repository. * indices (iterable[int]): Collection of integer indices identifying which files must be retrieved.

    Returns: * dict[str, str]: A dictionary where each key is formatted as "{index} # {path}" and each value is the corresponding file content string.

    Raises: * TypeError: If indices contains elements that cannot be compared with integer bounds, or if files_data elements cannot be unpacked.

    Example: 

    def get_content_for_indices(files_data, indices):
    """Get file content for specific indices from files_data list."""
    content_map = {}
    for i in indices:
        if 0 <= i < len(files_data):
            path, content = files_data[i]
            content_map[f"{i} # {path}"] = content  # Use index + path as key for context
    return content_map

    This helper performs targeted, selective context extraction, avoiding the memory and token overhead of passing the entire codebase payload into downstream LLM calls. The bound-checking condition 0 <= i < len(files_data) provides fail-soft protection against invalid or hallucinated file indices produced by upstream LLM routing steps. Keying the resulting dictionary by f"{i} # {path}" embeds self-documenting contextual metadata into the prompt dictionary, enabling downstream models and parsers to correlate extracted code blocks directly with the structural tree previously rendered by build_directory_tree.

    Data Structures

    Ingested Codebase Payload

    The standard input structure passed to both functions in this module is a sequence of two-element tuples, typically assembled by repository crawling utilities such as crawl_local_files or crawl_github_files.

    Element Index Field Name Type Description
    [0] path str Relative or normalized POSIX file path within the target repository.
    [1] content str Complete decoded text content of the source file.

    Directory Tree String Schema

    The multi-line string generated by build_directory_tree adheres to a strict two-tier hierarchical layout.

    Line Type Format Pattern Description Example
    Directory Header {dirname}/ Lexicographically sorted directory path, or . for files in the repository root. utils/
    File Entry {basename} (idx:{i}) Two-space indented file name paired with its zero-based position in files_data. files.py (idx:7)

    Index Content Map

    The dictionary returned by get_content_for_indices maps composite identifier keys to source code contents.

    Field Type Description Example Key
    Key str Formatted string containing the file index and relative path separated by #. "7 # utils/files.py"
    Value str The complete text content of the referenced source file. "\"\"\"File and content helpers...\"\"\""

    Error Handling

    The module implements defensive data normalization and boundary checks rather than raising custom domain exceptions:

    • Missing Parent Directory Normalization: In build_directory_tree, top-level files that have no parent directory return an empty string from os.path.dirname(path). The expression os.path.dirname(path) or "." normalizes empty directory strings to ".", preventing empty headers or root-path formatting errors.
    • Safe Index Slicing: In get_content_for_indices, the conditional check 0 <= i < len(files_data) protects against negative index lookups (which in standard Python negative slicing would wrap around and select files from the end of the array) and protects against IndexError exceptions caused by out-of-range indices.
    • Empty Input Handling: Passing an empty list ([]) as files_data safely produces an empty string ("") in build_directory_tree and an empty dictionary ({}) in get_content_for_indices without raising errors.

    See Also

    • utils/files.py operates as an independent utility module and does not import or depend on any other internal project modules. It relies exclusively on Python standard library modules (os and collections.defaultdict).
