    files.py

    Source: utils/files.py

    Following the filtering of excluded assets established in exclude_patterns.py, the codebase processing pipeline relies on structured representations of surviving files to drive downstream language model prompts. While modules like crawl_local_files.py and crawl_github_files.py manage raw ingestion and decoding, files.py provides pure functional transformations that organize and index in-memory file content.

    Technical Overview

    The files.py module serves as the structural serialization and content extraction layer within the Codebase-Knowledge-Builder architecture. Its primary responsibility is converting unstructured collections of file paths and file contents into compact, machine-readable text and indexed lookups. By formalizing repository structures into deterministic trees and providing indexed random-access content retrieval, it ensures that downstream reasoning nodes in nodes.py (such as ContextRouter, IdentifyAbstractions, MapAbstractions, and CombineTutorial) can interact with codebases without overflowing LLM context windows or losing file-to-path context.

    The module operates on a standard files_data collection—an ordered list of (path, content) 2-tuples assembled during codebase traversal. In build_directory_tree(), the module extracts directory hierarchies and associates each file with an integer index corresponding to its position in files_data. This indexing allows subsequent pipeline stages to instruct LLMs to reference, score, and select files solely by lightweight integer handles. When specific files are targeted for in-depth reasoning, get_content_for_indices() resolves those integer handles back into content mappings, formatting dictionary keys with metadata comments ("{i} # {path}") to reinforce spatial and structural grounding for the language model.

    Public API

    build_directory_tree()

    Visibility: Public
    Signature: def build_directory_tree(files_data: list[tuple[str, str]]) -> str:

    Description: Constructs a compact, deterministic string representation of the codebase hierarchy from a collection of (path, content) tuples. The function groups files by their parent directory and suffixes each leaf filename with its integer offset in the input list ((idx:{i})). This index-tagging scheme gives downstream LLMs structural awareness of the repository layout while establishing a unified coordinate system used by pipeline nodes in nodes.py to select files for deep inspection.

    Directory Grouping and Index Tagging

        dir_files = defaultdict(list)
    for i, (path, _content) in enumerate(files_data):
        dirname = os.path.dirname(path) or "."
        basename = os.path.basename(path)
        dir_files[dirname].append(f"{basename} (idx:{i})")

    The grouping phase initializes an in-memory defaultdict(list) and iterates across the files_data sequence. For each entry, os.path.dirname partitions the file path into a directory prefix, defaulting to "." for root-level files where dirname evaluates to an empty string. The corresponding filename is extracted via os.path.basename, appended with its sequential index marker (idx:{i}), and appended to the directory's list bucket. Ignoring file content during this pass ensures the structural tree is assembled with minimal computational overhead.

    Hierarchical Line Formatting and Sorting

        lines = []
    for dirname in sorted(dir_files.keys()):
        lines.append(f"{dirname}/")
        lines.extend(f"  {fname}" for fname in sorted(dir_files[dirname]))
    return "\n".join(lines)

    The formatting phase enforces strict lexicographical ordering on both the directory keys and the underlying file lists. Sorting directory names ensures deterministic output across different platforms and filesystem walk orders, which directly stabilizes prompt hash generation and enables effective prompt caching in call_llm.py. Directory headers are rendered with a trailing slash (/), and nested files are indented by two spaces (), resulting in an ultra-compact visual hierarchy delimited by standard newline characters.

    Parameters: * files_data (list[tuple[str, str]]): Ordered collection of 2-tuples where index 0 is the relative POSIX file path and index 1 is the decoded text content.

    Returns: * str: A multiline formatted string depicting the codebase directory tree, where each directory appears as dirname/ and each file appears indented as filename.ext (idx:N).

    Raises: * No explicit exceptions are raised. Handles empty input gracefully by returning an empty string.

    Example: 

    # Extracted from source implementation in utils/files.py
def build_directory_tree(files_data):
    dir_files = defaultdict(list)
    for i, (path, _content) in enumerate(files_data):
        dirname = os.path.dirname(path) or "."
        basename = os.path.basename(path)
        dir_files[dirname].append(f"{basename} (idx:{i})")

    lines = []
    for dirname in sorted(dir_files.keys()):
        lines.append(f"{dirname}/")
        lines.extend(f"  {fname}" for fname in sorted(dir_files[dirname]))
    return "\n".join(lines)

    get_content_for_indices()

    Visibility: Public
    Signature: def get_content_for_indices(files_data: list[tuple[str, str]], indices: list[int] | set[int] | collections.abc.Iterable[int]) -> dict[str, str]:

    Description: Resolves a subset of file contents from files_data by their numerical indices. For each valid index, it constructs a composite dictionary key pairing the index with the file path ("{i} # {path}"), mapping directly to the file's text content. This contextual key formatting guarantees that when the resulting dictionary is rendered as JSON or Markdown within LLM prompts, the language model retains explicit visibility over both the numerical handle and the semantic file path.

    Boundary Validation and Contextual Key Assembly

    def get_content_for_indices(files_data, indices):
    """Get file content for specific indices from files_data list."""
    content_map = {}
    for i in indices:
        if 0 <= i < len(files_data):
            path, content = files_data[i]
            content_map[f"{i} # {path}"] = content  # Use index + path as key for context
    return content_map

    The function iterates over the collection of requested integer indices and performs defensive boundary checks (0 <= i < len(files_data)). Any negative indices or indices that exceed the boundaries of the files_data list are silently bypassed, preventing IndexError exceptions if an LLM hallucinates out-of-range identifiers. For valid offsets, the (path, content) tuple is unpacked, and the dictionary key is formatted using an inline Python-style comment delimiter (#). This structure yields a self-documenting payload for prompt contexts that connects index references to filesystem paths.

    Parameters: * files_data (list[tuple[str, str]]): Master list of codebase files represented as (path, content) tuples. * indices (Iterable[int]): An iterable of integer index references indicating which files to extract.

    Returns: * dict[str, str]: A dictionary where keys follow the pattern "{index} # {relative_file_path}" and values contain the corresponding file content strings.

    Raises: * No explicit exceptions are raised; invalid or out-of-bounds indices are discarded.

    Example: 

    # Extracted from source implementation in utils/files.py
def get_content_for_indices(files_data, indices):
    content_map = {}
    for i in indices:
        if 0 <= i < len(files_data):
            path, content = files_data[i]
            content_map[f"{i} # {path}"] = content
    return content_map

    Data Structures

    FilesData

    An ordered list representing the ingested codebase assets passed between workflow stages.

    Field Type Description
    [i][0] str Relative file path normalized to POSIX style (e.g., src/core/engine.py).
    [i][1] str Complete decoded UTF-8 file content.

    IndexedContentMap

    Dictionary generated by get_content_for_indices() providing targeted source content for LLM reasoning prompts.

    Field Type Description
    Key str Context identifier formatted as "{index} # {filepath}" (e.g., "4 # src/utils/files.py").
    Value str Raw UTF-8 source code content corresponding to the targeted file.

    DirectoryTreeString

    A compact multiline string generated by build_directory_tree(). It uses indentation and index annotations to summarize the codebase hierarchy.

    Component Format Pattern Example
    Directory Header "{dirname}/" utils/ or ./
    File Item " {basename} (idx:{index})" files.py (idx:4)

    Error Handling

    The functions in files.py apply defensive programming techniques to guarantee predictable execution when handling dynamic file structures and unstructured LLM outputs:

    • Directory Name Normalization: Root-level files have an empty directory component when processed by os.path.dirname(path). The expression os.path.dirname(path) or "." normalizes empty strings to ".", ensuring root files are grouped predictably rather than keyed under an empty string.
    • Deterministic Output Sorting: To maintain idempotent LLM prompt payloads across disparate operating systems, build_directory_tree() sorts both directory keys (sorted(dir_files.keys())) and child files (sorted(dir_files[dirname])). This prevents arbitrary filesystem iteration orders from busting prompt caches managed by call_llm.py.
    • Defensive Range Checking: In get_content_for_indices(), index bounds are validated using 0 <= i < len(files_data). If a downstream model hallucinates an invalid or negative integer index, the entry is dropped without raising an IndexError or halting the execution pipeline.
