    files.py

    Source: utils/files.py

    Technical Overview

    The utils/files.py module provides foundational, in-memory filesystem aggregation and extraction utilities for the Codebase Knowledge Builder pipeline. During the repository ingestion phase, source code extractors such as crawl_local_files.py and crawl_github_files.py scan target repositories and normalize codebase files into ordered lists of (path, content) tuples. This module acts as the formatting and selective retrieval layer that translates these raw tuple collections into token-efficient structural representations and contextual prompt payloads for large language model (LLM) processing nodes.

    The module provides two deterministic operations: build_directory_tree and get_content_for_indices. The build_directory_tree function reorganizes linear file records into a two-level lexicographically sorted directory hierarchy where each file is tagged with its array index. This compact tree allows reasoning nodes (such as context routing and abstraction mapping) to inspect the complete directory topology without exhausting prompt context windows on full file contents. The get_content_for_indices function provides surgical extraction of source contents for specific index subsets identified by downstream analysis, generating contextual composite keys that combine positional indices with relative file paths.

    Both functions are deterministic, side-effect-free, and stateless. Directory grouping leverages standard library associative containers (collections.defaultdict) and explicit sorting to guarantee identical output regardless of the underlying operating system or crawl order. Defensive indexing prevents out-of-bounds exceptions when processing LLM-selected file indices, ensuring that transient model hallucinations or empty index sets do not crash pipeline nodes.

    Public API

    build_directory_tree()

    Visibility: Public

    Signature: def build_directory_tree(files_data):

    Description: Constructs a compact, human- and machine-readable directory tree string from an enumerated list of (path, content) tuples. The function groups files under their parent directory, appends each file's positional index in the format (idx:{i}), and sorts both directory paths and file entries lexicographically to guarantee deterministic output.

    Parameters:

    • files_data (list[tuple[str, str]]): Ordered list of 2-tuples where each element consists of a relative file path (str) and the corresponding file content (str).

    Returns:

    • str: A multi-line string representing the directory structure, with directory headers terminated by / and nested files indented by two spaces.

    Raises:

    • TypeError: Raised if files_data is not iterable or contains elements that cannot be unpacked into a 2-tuple.

    Example:

    def build_directory_tree(files_data):
    """Build a compact directory tree string from the list of (path, content) tuples.

    Groups files by directory and formats as a hierarchical tree with file indices.
    Used by ContextRouter, IdentifyAbstractions, MapAbstractions, and CombineTutorial
    to give LLMs structural context about the project layout.
    """
    dir_files = defaultdict(list)
    for i, (path, _content) in enumerate(files_data):
        dirname = os.path.dirname(path) or "."
        basename = os.path.basename(path)
        dir_files[dirname].append(f"{basename} (idx:{i})")

    lines = []
    for dirname in sorted(dir_files.keys()):
        lines.append(f"{dirname}/")
        lines.extend(f"  {fname}" for fname in sorted(dir_files[dirname]))
    return "\n".join(lines)

    The function iterates over files_data using enumerate to track each item's integer index. For each file path, it splits the string into its directory path and base filename using os.path.dirname and os.path.basename. When a file resides in the root scanning directory, os.path.dirname evaluates to an empty string; the expression dirname = os.path.dirname(path) or "." ensures such files are grouped under the . directory. Filenames are formatted with their index suffix (f"{basename} (idx:{i})") and collected in a defaultdict(list). Finally, directory keys are sorted alphabetically, each directory is printed with a trailing slash (f"{dirname}/"), and its associated file entries are sorted and indented by two spaces before being joined by newline characters.

    get_content_for_indices()

    Visibility: Public

    Signature: def get_content_for_indices(files_data, indices):

    Description: Retrieves file contents for a specific sequence of integer indices from the files_data list. For each valid index, it constructs a dictionary key that pairs the index with the file path (f"{i} # {path}"), mapping directly to the file's raw content string.

    Parameters:

    • files_data (list[tuple[str, str]]): Ordered list of (path, content) tuples representing the codebase.
    • indices (iterable[int]): Collection of integer indices indicating which files should be extracted.

    Returns:

    • dict[str, str]: Mapping where keys are formatted as "{index} # {relative_path}" and values are file text contents.

    Raises:

    • TypeError: Raised if indices is not iterable or if files_data does not support indexed sequence access.

    Example:

    def get_content_for_indices(files_data, indices):
    """Get file content for specific indices from files_data list."""
    content_map = {}
    for i in indices:
        if 0 <= i < len(files_data):
            path, content = files_data[i]
            content_map[f"{i} # {path}"] = content  # Use index + path as key for context
    return content_map

    The function initializes an empty content_map dictionary and iterates through the provided indices sequence. Before accessing files_data, it verifies bounds using 0 <= i < len(files_data). If the index is negative or greater than or equal to the length of files_data, the entry is bypassed without throwing an IndexError. For each valid index, the corresponding (path, content) tuple is unpacked, and a composite key formatted as f"{i} # {path}" is populated with content. This composite key structure embeds index tracking and file provenance directly into downstream prompt templates without requiring secondary dictionary lookups.

    Data Structures

    files_data collection

    The primary input contract accepted by both functions in utils/files.py. It is an ordered sequence representing all ingested repository files.

    Element Type Description
    path str Relative file path from the repository root (e.g., utils/files.py or main.py).
    content str Complete decoded text content of the source file. 
    # Structural representation of files_data
files_data = [
    ("main.py", "import os\n..."),
    ("utils/files.py", "import os\n..."),
]

    content_map dictionary

    The return structure generated by get_content_for_indices(). It provides a keyed mapping of selected files optimized for prompt injection.

    Field Type Description
    "{i} # {path}" str (Key) Composite identifier combining the zero-based index i with the relative file path.
    content str (Value) Raw source code or text content corresponding to the indexed file. 
    # Structural representation of content_map
content_map = {
    "0 # main.py": "import os\n...",
    "1 # utils/files.py": "import os\n...",
}

    Directory tree text schema

    The formatted string output produced by build_directory_tree(). It structures repository paths into a two-space indented hierarchy.

    Component Format Description
    Directory Header {dirname}/ Directory path terminated by a trailing slash, sorted alphabetically. Root files use ./.
    File Line {basename} (idx:{i}) File name indented by two spaces, followed by (idx:{i}) where {i} is the integer index in files_data. 
    ./
  main.py (idx:10)
utils/
  files.py (idx:49)

    Error Handling

    Index boundary protection

    In get_content_for_indices(), index lookups are guarded against IndexError using an explicit boundary check:

    if 0 <= i < len(files_data):
    path, content = files_data[i]
    content_map[f"{i} # {path}"] = content

    When an LLM hallucination or an upstream routing step supplies an out-of-bounds index (e.g., negative indices or values exceeding len(files_data) - 1), the module discards the invalid index silently rather than raising an exception. This guarantees non-crashing behavior during prompt preparation loops.

    Root path resolution fallback

    In build_directory_tree(), root-level files whose paths contain no directory delimiters cause os.path.dirname(path) to return an empty string (""):

    dirname = os.path.dirname(path) or "."

    By using the logical or "." fallback, empty strings are normalized to ".", preventing orphan files from rendering with a leading / or causing malformed tree lines.

    Empty payload handling

    Both functions handle empty inputs gracefully: * If files_data is empty ([]), build_directory_tree returns an empty string (""), and get_content_for_indices returns an empty dictionary ({}). * If indices is empty ([]), get_content_for_indices immediately returns an empty dictionary ({}).
