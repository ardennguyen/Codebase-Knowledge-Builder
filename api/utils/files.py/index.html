    files.py

    Source: utils/files.py

    Following the sanitization and filtering boundary established in exclude_patterns.py, which eliminates non-essential assets, binaries, and sensitive paths from the crawling boundary, utils/files.py provides deterministic data restructuring and selective content extraction utilities. These helpers bridge raw filesystem ingestion outputs with downstream Large Language Model (LLM) context preparation pipelines.

    Technical Overview

    The utils/files.py module defines core transformation routines that operate on sequential collections of repository source files. During the codebase analysis workflow, source files extracted by crawl_local_files.py or crawl_github_files.py are normalized into indexed tuples of (path, content). Because production repositories often contain hundreds of files whose collective token volume exceeds model context windows, the pipeline cannot eagerly inject entire codebases into single prompt invocations. Instead, utils/files.py facilitates a two-stage topological ingestion model: high-level structural exploration followed by targeted content retrieval.

    The first stage relies on build_directory_tree(), which parses file path hierarchies and compiles a canonical, human-readable directory tree string where each file name is mapped to its explicit zero-based integer index (e.g., basename (idx:0)). Upstream graph nodes in nodes.py—such as IdentifyAbstractions, MapAbstractions, and routing components—inject this compact tree string into initial reasoning prompts. This layout provides LLMs with global structural context regarding project topology, package organization, and file naming semantics while consuming a minimal fraction of the token budget.

    The second stage is executed through get_content_for_indices(). Once an upstream LLM reasons over the structural directory tree and identifies a subset of files critical to a specific module or architectural abstraction, it emits a sequence of file indices. get_content_for_indices() acts as an index-bounded projection layer, extracting only the specified file payloads from the source collection and formatting them into key-value pairs formatted as "{index} # {path}". This approach isolates downstream inference passes from irrelevant source code, maximizes prompt cache hits across repeated invocations, and enforces safety bounds against model-generated index hallucinations.

    Public API

    build_directory_tree()

    Visibility: Public
    Signature: def build_directory_tree(files_data: list[tuple[str, str]]) -> str:

    Description:
    Constructs a compact, hierarchical ASCII directory tree representation from a sequence of (path, content) tuples. The function groups files by their parent directory paths, attaches zero-based integer index tags (idx:N) to each file entry, and formats the output deterministically using alphabetical sorting across directories and files. This formatted string is consumed by pipeline reasoning nodes to grant LLMs complete visibility into project organization without expending token budgets on file contents.

    The implementation operates across two distinct phases: directory grouping and hierarchical string assembly.

    Phase 1: Directory Grouping and Index Tagging

        dir_files = defaultdict(list)
    for i, (path, _content) in enumerate(files_data):
        dirname = os.path.dirname(path) or "."
        basename = os.path.basename(path)
        dir_files[dirname].append(f"{basename} (idx:{i})")

    The grouping phase initializes a collections.defaultdict parameterized with list and enumerates through files_data. For each entry, the file content string is ignored (aliased to _content) while the relative path string is decomposed using os.path.dirname and os.path.basename. If a file resides at the root level of the analyzed codebase, os.path.dirname returns an empty string, which the boolean or "." fallback converts into a standard dot (.) directory key. The filename is formatted with its integer sequence position as {basename} (idx:{i}) and appended to the directory's file list.

    Phase 2: Canonical Ordering and String Serialization

        lines = []
    for dirname in sorted(dir_files.keys()):
        lines.append(f"{dirname}/")
        lines.extend(f"  {fname}" for fname in sorted(dir_files[dirname]))
    return "\n".join(lines)

    The serialization phase enforces strict determinism required for LLM prompt caching. It sorts the discovered directory keys lexicographically using sorted(dir_files.keys()). For every directory, it appends a trailing-slash header (e.g., src/core/) to the output line list, followed by two-space indented entries for each file within that directory, also sorted in ascending alphabetical order. The resulting list of strings is joined with newline delimiters (\n) and returned as a single unified text block.

    Parameters: * files_data (list[tuple[str, str]]): An ordered list of two-element tuples, where index 0 is the normalized relative file path and index 1 is the decoded text content of the file.

    Returns: * str: A multi-line string containing the alphabetically sorted, two-space indented representation of the codebase hierarchy, complete with parent directory paths and (idx:N) identifiers.

    Raises: * This function does not explicitly raise custom exceptions. If files_data contains elements that cannot be unpacked into a 2-tuple, standard ValueError or TypeError exceptions may propagate from Python's runtime unpacking mechanism.

    Example: 

    from utils.files import build_directory_tree

# files_data represents normalized repository files
files_data = [
    ("main.py", "import flow\n..."),
    ("utils/files.py", "import os\n..."),
    ("utils/output.py", "def emit(): pass\n..."),
]

tree_view = build_directory_tree(files_data)
# tree_view outputs:
# ./
#   main.py (idx:0)
# utils/
#   files.py (idx:1)
#   output.py (idx:2)

    get_content_for_indices()

    Visibility: Public
    Signature: def get_content_for_indices(files_data: list[tuple[str, str]], indices: list[int] | set[int]) -> dict[str, str]:

    Description:
    Extracts file contents from a master files_data sequence for an arbitrary iterable of integer indices. The function performs defensive bounds verification on each requested index, prevents IndexError exceptions caused by generative model hallucinations, and formats the output dictionary keys as composite strings containing both the numeric index and the file path ("{index} # {path}").

    The implementation isolates lookup and contextual key construction in a guarded loop.

    Phase 1: Boundary Verification and Contextual Mapping

    def get_content_for_indices(files_data, indices):
    """Get file content for specific indices from files_data list."""
    content_map = {}
    for i in indices:
        if 0 <= i < len(files_data):
            path, content = files_data[i]
            content_map[f"{i} # {path}"] = content  # Use index + path as key for context
    return content_map

    The function initializes an empty content_map dictionary and iterates sequentially over the provided indices collection. For every index integer i, it evaluates the defensive conditional 0 <= i < len(files_data). If the index is negative or greater than or equal to the total count of loaded files, the loop silently bypasses the entry. For valid indices, it unpacks files_data[i] into its constituent path and content components. It assigns the raw file content buffer to a formatted key string (f"{i} # {path}"). This key format preserves the exact numeric reference used in prior LLM reasoning steps while embedding human-readable file path metadata into the prompt dictionary.

    Parameters: * files_data (list[tuple[str, str]]): Master sequence of indexed (path, content) tuples representing the analyzed repository. * indices (list[int] | set[int] | Iterable[int]): An iterable collection of integer file indices requested for deep inspection.

    Returns: * dict[str, str]: A dictionary mapping composite context keys ("{index} # {path}") to their corresponding UTF-8 string file contents.

    Raises: * This function handles out-of-bounds integer indices defensively without raising errors. If an element in indices cannot be evaluated in a comparison expression against integers (e.g., passing a non-numeric string), Python raises a runtime TypeError.

    Example: 

    from utils.files import get_content_for_indices

files_data = [
    ("main.py", "print('hello')"),
    ("config.py", "DEBUG = True"),
]

# Requesting valid index 1 and an out-of-bounds hallucinated index 99
selected = get_content_for_indices(files_data, [1, 99])
# selected contains:
# {"1 # config.py": "DEBUG = True"}

    Data Structures

    The utils/files.py module operates over standard Python container structures rather than dedicated class instances. However, it establishes strict structural conventions for repository data interchange across upstream crawlers, graph execution nodes, and LLM prompting engines.

    files_data (Repository File Collection)

    The foundational input structure consumed by both functions in this module. It represents an indexed snapshot of the target codebase after crawl-phase exclusion patterns have been applied.

    Element Type Description
    Sequence Container list[tuple[str, str]] Ordered list of 2-element tuples maintaining stable integer indexing.
    Tuple Index 0 str Normalized relative filesystem path (e.g., src/core/router.py).
    Tuple Index 1 str Full UTF-8 decoded source code text content of the target file.

    content_map (Contextual File Map)

    The dictionary schema returned by get_content_for_indices(). It packages selected file contents with descriptive identifiers optimized for direct serialization into prompt templates.

    Key Type Description Example
    "{i} # {path}" str Composite key combining the zero-based array index i with the relative file path path. "4 # utils/token_utils.py"
    Value str Complete string content of the requested source file. "import tiktoken\n..."

    Compact Directory Tree Layout

    The text output returned by build_directory_tree() follows a strict schema designed to minimize token usage while clarifying structural relationships for downstream LLMs:

    {directory_path}/
  {file_name} (idx:{integer_index})
    • Root directory marker: Root-level files without a directory prefix are nested under the ./ header.
    • Indentation rule: Exactly two spaces () prefix each file name under its corresponding parent directory line.
    • Lexicographical sort order: Directory paths are sorted alphabetically, and file entries within each directory are independently sorted alphabetically.
    • Index annotation: Each file terminates with a single space followed by (idx:N), matching the precise array index in files_data.

    Error Handling

    The functions within utils/files.py apply defensive programming techniques to maintain pipeline stability during automated operations:

    • Directory Normalization Fallback: In build_directory_tree(), invoking os.path.dirname(path) on a top-level file (such as main.py or README.md) yields an empty string "". In standard Python dictionaries, an empty string key can cause inconsistent formatting or malformed tree headers. The implementation uses short-circuit evaluation (os.path.dirname(path) or ".") to redirect empty directories into the explicit ./ root path.
    • Index Hallucination Guard: Generative LLMs parsing the directory tree occasionally output negative numbers, out-of-bounds array indices, or duplicate identifiers. In get_content_for_indices(), the condition 0 <= i < len(files_data) acts as an error boundary. Out-of-bounds indices are discarded, preventing runtime IndexError terminations and allowing downstream synthesis nodes to process all valid indices without failing the entire documentation run.
    • Empty Collection Resilience: When evaluated against an empty files_data collection ([]), build_directory_tree() returns an empty string "", and get_content_for_indices() returns an empty dictionary {} without triggering unexpected exceptions.
