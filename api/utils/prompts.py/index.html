    prompts.py

    Source: utils/prompts.py

    Technical Overview

    Following the centralized logging and telemetry mechanisms established in output.py, the prompts.py module serves as the prompt management and response deserialization engine for the Codebase-Knowledge-Builder architecture. It encapsulates the structural boundary between workflow execution nodes and large language models by standardizing how instructions are compiled, dispatched, and interpreted. The module isolates prompt generation logic from node orchestration, preventing repetitive string interpolation and template loading boilerplate across processing stages.

    The module provides two complementary prompt assembly mechanisms alongside robust parsing utilities. For complex, multi-stage reasoning tasks such as abstraction mapping and relationship synthesis, it reads Markdown templates from structured subdirectories within the prompts/ repository root, supporting dynamic execution modes (tutorial, advanced, or arbitrary custom directory overrides). For targeted tasks that do not require external templates, it provides programmatic inline prompt builders for filtering source code modules and generating structured four-dimensional chapter summaries. To resolve responses, the module provides defensive deserialization functions that extract YAML blocks from markdown code fences and sanitize integer file indices from noisy model outputs.

    Public API

    parse_file_index()

    Visibility: Public
    Signature: def parse_file_index(idx_value) -> int | None:

    Description: Extracts the first integer identifier from an LLM-returned file index token or string representation. Model outputs often deviate from raw integers by returning annotated strings (such as "3 # path/to/file.py"), range formats (such as "0-3"), or integer types. This function normalizes the input into a standard Python integer using regular expression matching, returning None if no digit sequence can be discovered.

    Parameters: * idx_value (Any): The raw value returned by an LLM response or parser, typically an int, str, or numeric token.

    Returns: * int | None: The extracted integer value representing the zero-based file index, or None if the input contains no numeric digits.

    Raises: * No exceptions are explicitly raised; non-string inputs are converted via str() before pattern matching.

    Example: 

    def parse_file_index(idx_value):
    """Extract the first integer from an LLM-returned file index value.

    Handles multiple formats the LLM may produce:
    - Plain int: 3
    - Annotated string: "3 # path/to/file.py"
    - Range notation: "0-3" → returns first number only (caller handles ranges)

    Returns:
        int or None if no digits found.
    """
    nums = re.findall(r"\d+", str(idx_value))
    return int(nums[0]) if nums else None

    The implementation relies on re.findall(r"\d+", str(idx_value)) to find all continuous sequences of decimal digits within the stringified input. If one or more digit sequences are identified, the first match (nums[0]) is converted to an int and returned. In scenarios where a range like "0-3" is provided, the function intentionally extracts the lower bound (0), leaving range expansion to higher-level orchestrators. If the input contains no digits (such as empty strings or non-numeric tokens), the ternary check evaluates to None, safeguarding downstream array index operations from runtime conversion crashes.

    load_prompt_template()

    Visibility: Public
    Signature: def load_prompt_template(template_name, advanced_mode=False, mode=None) -> str:

    Description: Resolves and reads a Markdown prompt template from the project's prompts/ directory tree. It determines the appropriate target directory based on runtime operational parameters, reads the file using utf-8-sig encoding to strip potential Byte Order Marks (BOM), and logs a debug event through utils.output.emit_raw.

    Parameters: * template_name (str): The basename of the prompt file excluding the .md extension (e.g., "identify_abstractions"). * advanced_mode (bool, optional): Legacy flag indicating whether to pull from the prompts/advanced/ folder when mode is None. Defaults to False. * mode (str | None, optional): Explicit folder name under prompts/ from which to load the template (e.g., "api-reference", "tutorial", "advanced"). If omitted, falls back to advanced_mode. Defaults to None.

    Returns: * str: The decoded content of the prompt template file.

    Raises: * FileNotFoundError: If the resolved template file path does not exist on disk. * OSError: If reading the file encounters filesystem permissions or I/O errors.

    Example: 

    def load_prompt_template(template_name, advanced_mode=False, mode=None):
    """Load a prompt template file from the prompts/ directory."""
    if mode is None:
        prompt_dir = "advanced" if advanced_mode else "tutorial"
    else:
        prompt_dir = mode

    path = os.path.join(os.path.dirname(os.path.dirname(os.path.abspath(__file__))), "prompts", prompt_dir, f"{template_name}.md")
    with open(path, encoding="utf-8-sig") as f:
        content = f.read()
    from utils.output import emit_raw

    emit_raw("DEBUG", f"load_prompt_template | loaded '{template_name}.md' from prompts/{prompt_dir}/", dest="LOG")
    return content

    The function computes the absolute path to the template by resolving two levels up from utils/prompts.py to identify the repository root, then navigating into prompts/<prompt_dir>/<template_name>.md. Reading with utf-8-sig guarantees compatibility across diverse platforms, automatically stripping leading zero-width non-breaking spaces if templates are saved with Windows BOM markers. To avoid cyclical import chains between prompt loading and logging utilities during system initialization, emit_raw is lazily imported inside the function scope and dispatches a debug trace exclusively to the persistent session log (dest="LOG").

    parse_yaml_response()

    Visibility: Public
    Signature: def parse_yaml_response(response) -> Any:

    Description: Isolates, extracts, and parses a YAML document embedded within Markdown code fences in an LLM completion string. Language models frequently surround structured YAML data with conversational preamble or trailing commentary; this function isolates the code fence marked by ```yaml and deserializes it via PyYAML's safe loader.

    Parameters: * response (str): The raw text response produced by an LLM inference call.

    Returns: * Any: The parsed Python data structure (typically a dict or list) corresponding to the deserialized YAML payload.

    Raises: * ValueError: Raised if the response lacks the opening ```yaml or closing ``` code fences, or if yaml.safe_load fails to parse the extracted substring due to invalid YAML syntax.

    Example: 

    def parse_yaml_response(response):
    """Extract and parse YAML from an LLM response fenced in ```yaml blocks."""
    try:
        yaml_str = response.strip().split("```yaml")[1].split("```")[0].strip()
        return yaml.safe_load(yaml_str)
    except Exception as e:
        raise ValueError(f"Failed to parse YAML: {e}") from e

    The method cleans extraneous whitespace with .strip() before executing a two-stage .split() operation: the first split isolates text following the initial ```yaml fence tag, and the second split captures everything before the next closing ``` delimiter. The resulting substring is stripped and passed to yaml.safe_load() to prevent arbitrary code execution vulnerabilities during deserialization. Any exception thrown during string splitting (such as an IndexError when fences are missing) or parsing (yaml.YAMLError) is caught and re-raised as a standardized ValueError with the underlying exception chained via from e.

    build_code_file_filter_prompt()

    Visibility: Public
    Signature: def build_code_file_filter_prompt(project_name: str, file_listing: str) -> str:

    Description: Constructs an inline prompt used by workflow mappers (such as DeterministicFileMapper in API reference mode) to identify functional source code files while excluding configuration, UI layout, static assets, and documentation files. It instructs the language model to return only a fenced YAML sequence of numeric file indices.

    Parameters: * project_name (str): The name of the project or repository being analyzed. * file_listing (str): A formatted directory listing or index-tagged list of file paths generated from the ingestion pipeline.

    Returns: * str: The fully interpolated prompt string ready for submission to call_llm().

    Raises: * No exceptions are explicitly raised; string formatting errors occur only if arguments cannot be coerced to strings.

    Example: 

    def build_code_file_filter_prompt(project_name: str, file_listing: str) -> str:
    """Build the prompt for DeterministicFileMapper to filter non-code files.

    Used in api-reference mode to identify which files are actual code modules
    (APIs, functions, classes, business logic) vs. UI layouts, configs, assets.
    """
    return (
        f"For the project `{project_name}`, here is the list of all files in the codebase:\n\n"
        f"{file_listing}\n\n"
        f"Your task is to identify WHICH of these files are ACTUAL CODE files that contain "
        f"APIs, functions, classes, or core business logic.\n"
        f"EXCLUDE: UI layouts (like .xaml, .storyboard, .html), configuration files "
        f"(like .xml, .json, .manifest, .ini), static assets, build scripts "
        f"(like .csproj, .sln), and documentation.\n\n"
        f"Return ONLY a YAML list of the file indices that should be documented as code modules.\n\n"
        f"```yaml\n- 0\n- 1\n- 3\n```"
    )

    The function generates a deterministic, zero-shot classification prompt enforcing strict negative and positive constraints. By providing an explicit few-shot YAML schema example (```yaml\n- 0\n- 1\n- 3\n```) and listing non-code file extensions to exclude (such as .xaml, .xml, .json, .csproj), it steers the model away from conversational chatter. The resulting output conforms directly to the contract expected downstream by parse_yaml_response() and parse_file_index().

    build_chapter_summary_prompt()

    Visibility: Public
    Signature: def build_chapter_summary_prompt(chapter_num: int, abstraction_name: str, chapter_content: str, language: str = "english") -> str:

    Description: Constructs the prompt used to synthesize a four-dimensional technical brief from an already-generated documentation chapter. This summary is injected into subsequent pipeline stages as cumulative context, ensuring architectural continuity and cross-chapter coherence across large documentation builds.

    Parameters: * chapter_num (int): The numeric sequence index of the chapter. * abstraction_name (str): The title or conceptual abstraction covered by the chapter (e.g., "Authentication & Session Management"). * chapter_content (str): The full Markdown text of the generated chapter. * language (str, optional): The target output language for the summary. If set to anything other than "english" (case-insensitive), a localization instruction is prepended. Defaults to "english".

    Returns: * str: The complete summary generation prompt string.

    Raises: * No exceptions are explicitly raised.

    Example: 

    def build_chapter_summary_prompt(chapter_num: int, abstraction_name: str, chapter_content: str, language: str = "english") -> str:
    """Build the prompt for generating a technical summary of a written chapter.

    Used after each chapter is generated to create a concise technical summary
    for cross-chapter context. The summary is fed into subsequent chapters'
    prompts so the LLM maintains coherence across the full document.

    The summary captures 4 technical dimensions with 3-5 sentences each:
    1. Component scope & responsibility
    2. Key classes/services/functions and their roles
    3. Implementation patterns & architectural decisions
    4. Inter-component interfaces & dependencies
    """
    lang_instruction = f"Write the entire summary in {language.capitalize()}. " if language.lower() != "english" else ""
    return (
        f"{lang_instruction}"
        f"Summarize the following documentation chapter as a structured technical brief. "
        f"For EACH of the 4 points below, write 3-5 concise technical sentences:\n\n"
        f"(1) **Component Scope & Responsibility**: What is the main technical domain this "
        f"chapter covers? What problems does it solve and what role does it play in the system?\n\n"
        f"(2) **Key Technical Elements**: What are the specific classes, services, functions, "
        f"data models, or protocols discussed? Name them and describe their concrete roles.\n\n"
        f"(3) **Implementation Patterns & Architecture**: What design patterns, communication "
        f"protocols, data flow strategies, error handling mechanisms, or security measures "
        f"are covered? How are they implemented?\n\n"
        f"(4) **System Integration & Dependencies**: How does this component interface with "
        f"other parts of the system? What does it consume from or provide to other components? "
        f"What are the key integration points?\n\n"
        f"---\n"
        f"Chapter {chapter_num}: {abstraction_name}\n"
        f"{chapter_content}"
    )

    The prompt divides technical evaluation into four distinct analytical pillars: scope, concrete technical elements, internal patterns, and external system integrations. To enforce detail without context bloat, it constrains each section to exactly 3-5 sentences. When language differs from "english", the function prepends a directive ("Write the entire summary in <Language>. "), ensuring multi-lingual consistency across generated documentation suites.

    Data Structures

    The module operates primarily on string payloads and scalar primitives, but enforces specific structural schemas for LLM prompts and parsed YAML outputs.

    File Index Values

    Extracted file indices are represented as integers or None, accommodating multiple LLM string variations:

    Representation Type Raw Format Example Resolved Return Value Description
    int 3 3 Pure numeric integer returned by structured JSON/YAML.
    str (Annotated) "3 # utils/prompts.py" 3 Index followed by comment annotations or file paths.
    str (Range) "0-3" 0 Range sequence; lower bound is returned for caller expansion.
    str (Non-numeric) "none", "" None Unparseable or empty token indicating no matching index.

    Code File Filter Output Schema

    The expected output format extracted by parse_yaml_response after executing the prompt generated by build_code_file_filter_prompt:

    Field / Element Type Description
    [index] list[int] A sequential list of zero-based integer indices corresponding to code files. 

    # Example Expected YAML Payload:
```yaml
- 0
- 1
- 4
- 12
    ```

    Chapter Summary Four-Dimension Schema

    The textual structure produced when executing prompts generated by build_chapter_summary_prompt:

    Dimension Heading Description Length Constraint
    1 (1) **Component Scope & Responsibility** High-level technical domain, resolved problems, and system role. 3-5 sentences
    2 (2) **Key Technical Elements** Specific classes, functions, services, models, and protocols. 3-5 sentences
    3 (3) **Implementation Patterns & Architecture** Design patterns, protocols, data flows, and security measures. 3-5 sentences
    4 (4) **System Integration & Dependencies** Inter-component interfaces, consumed resources, and export points. 3-5 sentences

    Error Handling

    The module employs localized defensive parsing and explicit exception wrapping to prevent corrupted LLM responses from causing silent pipeline failures:

    • Fenced Block Extraction Failures: In parse_yaml_response(), responses that do not contain the opening ```yaml or trailing ``` delimiters trigger an IndexError during string splitting. This is captured by the blanket except Exception as e: block and re-raised as ValueError(f"Failed to parse YAML: {e}") from e.
    • Corrupt YAML Payloads: If the content between code fences is not valid YAML syntax, yaml.safe_load() raises yaml.YAMLError. The method intercepts this exception and wraps it in a descriptive ValueError, providing context to the calling pipeline node.
    • Non-Numeric Token Fallbacks: In parse_file_index(), if regex matching yields an empty match list (nums == []), the function returns None rather than attempting an out-of-bounds list access on nums[0].
    • BOM Preservation and Decoding: load_prompt_template() opens files with encoding="utf-8-sig". This transparently absorbs byte order marks present on certain operating systems or editors without raising UnicodeDecodeError.
