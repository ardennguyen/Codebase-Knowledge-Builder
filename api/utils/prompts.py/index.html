    prompts.py

    Source: utils/prompts.py

    Technical Overview

    Building directly upon the centralized logging and diagnostic output infrastructure of output.py (doc: utils/output.py.md), prompts.py provides template loading, string compilation, and resilient response-parsing routines that mediate interactions between pipeline nodes and language models. The module acts as the core prompt engineering and deserialization substrate across tutorial, advanced, SDK, and API-reference documentation generation modes. It encapsulates prompt asset resolution from the filesystem (prompts/{mode}/), generates contextual prompt segments such as verified AST facts blocks and focus notes, and provides specialized inline prompt generators for file filtering and chapter summarization.

    A primary technical challenge addressed by this module is the fragility of structured data extraction from large language models. LLMs frequently emit invalid YAML due to unquoted colons in code signatures, syntax indicators (@, #, *, &) at the beginning of identifiers, unescaped quote marks in extracted evidence, and conversational Markdown fences. Furthermore, responses truncated by context or generation token limits can result in syntactically complete prefixes that silently omit critical data. prompts.py solves this through a multi-tiered, fail-soft parsing pipeline that pairs truncation detection with progressive normalization, regex-based block scalar conversion, and granular list item salvage routines.

    The module also prepares grounded contextual blocks for code documentation generation. Through build_verified_facts_block, it synthesizes source-verified symbol signatures, cross-module import targets, configuration keys, and error definitions into prompt context blocks. This ensures that downstream chapter drafting agents remain strictly aligned with physical source code facts extracted by upstream analysis stages.

    Public API

    parse_file_index()

    Visibility: Public Signature: def parse_file_index(idx_value):

    Description: Extracts the first integer match found in an index representation returned by an LLM. It accommodates various scalar and string formats emitted by models, including raw integers, annotated index strings (e.g., "3 # path/to/file.py"), and range notation (e.g., "0-3"). When encountering a range, it yields the initial integer; caller logic is expected to handle full interval expansions.

    Parameters: * idx_value (Any): The raw index value returned by the model (integer, string, or arbitrary object).

    Returns: * int | None: The extracted non-negative integer, or None if no numerical digits are present in the string representation.

    Raises: * No exceptions raised; non-matching formats return None.

    Example: 

    def parse_file_index(idx_value):
    """Extract the first integer from an LLM-returned file index value.

    Handles multiple formats the LLM may produce:
    - Plain int: 3
    - Annotated string: "3 # path/to/file.py"
    - Range notation: "0-3" → returns first number only (caller handles ranges)

    Returns:
        int or None if no digits found.
    """
    nums = re.findall(r"\d+", str(idx_value))
    return int(nums[0]) if nums else None

    The function executes a coarse regular expression scan r"\d+" over the stringified input representation. By selecting index [0] of the matched numeric sequences, it strips trailing comments, path annotations, and trailing delimiter bounds. If no numeric digits exist in the stringified value, the method gracefully returns None.

    parse_file_indices()

    Visibility: Public Signature: def parse_file_indices(idx_value) -> list[int]:

    Description: Strictly parses an LLM-returned index item into a list of constituent file indices. Unlike parse_file_index(), which aggressively takes the first numeric match from any arbitrary string, this function enforces strict syntactic validation to prevent file paths containing digits (e.g., src/v2/api.py) or negative numbers from being incorrectly mapped to index slots. It handles explicit booleans, integers, single annotated index entries, and contiguous index ranges up to an interval length of 10,000.

    Parameters: * idx_value (Any): A single entry from a model-generated index list.

    Returns: * list[int]: A list containing the parsed integer index, the expanded range of indices, or an empty list if validation fails.

    Raises: * No exceptions raised.

    Example: 

    def parse_file_indices(idx_value) -> list[int]:
    """Strictly parse one entry of an index list the LLM returned → the indices it names.

    An int, an annotated number (``"3 # path"``) or an ascending range (``"0-3"``, ``"4..7"``, expanded). Anything
    else — a negative number, a path with a digit in it (``src/v2/api.py``), prose — names no index, instead
    of the first digit run picking an unrelated file."""
    if isinstance(idx_value, bool):
        return []
    if isinstance(idx_value, int):
        return [idx_value] if idx_value >= 0 else []
    text = str(idx_value) if isinstance(idx_value, str) else ""
    single = _INDEX_RE.match(text)
    if single:
        return [int(single.group(1))]
    span = _INDEX_RANGE_RE.match(text)
    if span and int(span.group(1)) <= int(span.group(2)) and int(span.group(2)) - int(span.group(1)) < 10000:
        return list(range(int(span.group(1)), int(span.group(2)) + 1))
    return []

    The parsing sequence enforces short-circuit guards: booleans are rejected immediately to prevent Python's bool subclassing behavior from treating True/False as 1/0. Non-negative integers are wrapped directly. For string inputs, _INDEX_RE checks for solitary numbers optionally followed by hash-delimited comments. If that does not match, _INDEX_RANGE_RE evaluates range expressions supporting hyphen (-), double-dot (..), en-dash (\u2013), or "to" delimiters. If the interval is non-inverted and spans fewer than 10,000 items, range() generates the full index list; otherwise, an empty list is returned.

    load_prompt_template()

    Visibility: Public Signature: def load_prompt_template(template_name, advanced_mode=False, mode=None):

    Description: Loads a Markdown prompt template from the project's prompts/ subdirectories. It resolves directory routing based on mode flags, reads the target file using utf-8-sig encoding to handle potential Byte Order Marks transparently, logs a debug tracing message via utils.output.emit_raw, and returns the raw template contents.

    Parameters: * template_name (str): Base name of the prompt template file (without the .md extension). * advanced_mode (bool, optional): Legacy flag indicating whether to use prompts/advanced/ instead of prompts/tutorial/ when mode is None. Defaults to False. * mode (str | None, optional): The execution mode directory (e.g., "api-reference", "sdk", "advanced", "tutorial", "common"). Overrides advanced_mode when supplied. Defaults to None.

    Returns: * str: Raw string content of the prompt template file.

    Raises: * FileNotFoundError: If the constructed prompt path does not resolve to an existing file on disk. * IOError: If reading the file encounters filesystem access failures.

    Example: 

    def load_prompt_template(template_name, advanced_mode=False, mode=None):
    """Load a prompt template file from the prompts/ directory."""
    if mode is None:
        prompt_dir = "advanced" if advanced_mode else "tutorial"
    else:
        prompt_dir = mode

    path = os.path.join(os.path.dirname(os.path.dirname(os.path.abspath(__file__))), "prompts", prompt_dir, f"{template_name}.md")
    with open(path, encoding="utf-8-sig") as f:
        content = f.read()
    from utils.output import emit_raw

    emit_raw("DEBUG", f"load_prompt_template | loaded '{template_name}.md' from prompts/{prompt_dir}/", dest="LOG")
    return content

    Path resolution computes the absolute root by taking the parent directory of utils/ and appending prompts, the selected prompt_dir, and {template_name}.md. File reading is executed within a context manager using encoding="utf-8-sig". A deferred import of emit_raw from utils.output is utilized to emit a localized debug trace to the log channel without triggering circular module-level imports.

    parse_yaml_response()

    Visibility: Public Signature: def parse_yaml_response(response):

    Description: Extracts and deserializes YAML data enclosed within Markdown code fences (yaml ...) from an LLM response. It enforces truncation detection: if the response object has its truncated attribute set to True, the function raises an explicit ValueError to force the calling orchestration node to retry rather than operating on incomplete data structures.

    Parameters: * response (str | Any): The raw text response or response object (e.g., TruncatedResponse) returned by the LLM client.

    Returns: * Any: The deserialized Python data structure (typically a dict or list) parsed from the YAML block.

    Raises: * ValueError: Raised if the response is flagged as truncated, if no ```yaml fence exists, or if yaml.safe_load() fails due to syntax errors.

    Example: 

    def parse_yaml_response(response):
    """Extract and parse YAML from an LLM response fenced in ```yaml blocks."""
    # A reply cut off at max tokens (llm_common.TruncatedResponse) can still contain a parseable
    # fenced prefix that silently drops items — raise so the node retries instead.
    if getattr(response, "truncated", False):
        raise ValueError("LLM response was truncated before the YAML block completed")
    try:
        yaml_str = response.strip().split("```yaml")[1].split("```")[0].strip()
        return yaml.safe_load(yaml_str)
    except Exception as e:
        raise ValueError(f"Failed to parse YAML: {e}") from e

    The function checks getattr(response, "truncated", False) upfront to prevent processing partial outputs where token limits severed the payload. It extracts the YAML substring by splitting on ```yaml and subsequently on the closing ``` fence. The extracted string is parsed via yaml.safe_load(). Any parsing exception or indexing failure is wrapped and raised as a ValueError with contextual details.

    parse_grouping_response()

    Visibility: Public Signature: def parse_grouping_response(response):

    Description: Parses the multi-section YAML output returned by the group_modules.md prompt, which defines documentation sections, descriptions, and inter-module dependencies. Because models frequently introduce syntax errors in long structural YAML blocks—such as wrapping section roles in backticks or misformatting single description entries—this function incorporates a multi-phase recovery mechanism. If full-block parsing fails, it strips backticks from role fields and splits the YAML into independent top-level key blocks (sections:, descriptions:, dependencies:), parsing each independently and aggregating valid components.

    Parameters: * response (str | Any): The raw response string or response object from the LLM.

    Returns: * dict: Deserialized grouping payload containing at least a "sections" list, alongside any recovered "descriptions" and "dependencies" mappings.

    Raises: * ValueError: Raised if the response is truncated, lacks a ```yaml block, or if the "sections" block cannot be recovered.

    Standard YAML Evaluation

        try:
        return parse_yaml_response(response)
    except ValueError:
        if getattr(response, "truncated", False) or "```yaml" not in response:
            raise
    The execution begins by attempting a strict parse through parse_yaml_response(). If this succeeds, the deserialized dictionary is returned immediately. If it raises a ValueError, the function evaluates whether recovery is viable; if the input is marked as truncated or completely lacks a ```yaml marker, recovery is skipped and the exception is re-raised.

    Section-Wise Chunk Recovery

            yaml_str = response.split("```yaml", 1)[1].split("```", 1)[0]
        yaml_str = re.sub(r"(?m)^(\s*(?:-\s+)?role\s*:\s*)`([^`\n]*)`", r"\1\2", yaml_str)
        parsed = {}
        for chunk in re.split(r"(?m)^(?=(?:sections|descriptions|dependencies)\s*:)", yaml_str):
            try:
                part = yaml.safe_load(chunk)
            except Exception:
                continue
            if isinstance(part, dict):
                parsed.update(part)
        if not isinstance(parsed.get("sections"), list):
            raise ValueError("Failed to parse YAML: no sections list in the grouping reply") from None
        return parsed
    During the recovery phase, the function extracts the raw YAML substring and uses re.sub to unwrap invalid backtick annotations on role: keys (e.g., role:core` ->role: core). It splits the text along top-level section boundaries using lookahead assertions forsections:,descriptions:, ordependencies:. Each chunk is parsed independently viayaml.safe_load(). Any chunk that fails does not invalidate others. Finally, the function validates that a valid"sections"list was recovered; if missing, it raises a terminalValueError`.

    build_verified_facts_block()

    Visibility: Public Signature: def build_verified_facts_block(facts: dict | None, doc_paths: dict) -> str:

    Description: Constructs the {verified_facts} context block for draft_chapters.md prompts in API-reference documentation mode. It formats verified code facts—such as symbols, signatures, module dependencies, configuration keys, and error handling declarations—extracted by the ExtractFacts pipeline stage. Signatures are normalized to single lines with decorator prefixes stripped, wrapped in collision-resistant inline code spans, and annotated with continuation markers if truncated.

    Parameters: * facts (dict | None): A dictionary of verified claims extracted from the source file. If None, empty, or lacking verified claims, an empty string is returned. * doc_paths (dict[str, str]): Mapping of internal module source paths to their corresponding documentation chapter filenames (used to render See Also reference targets).

    Returns: * str: Formatted Markdown block ready for prompt interpolation, or an empty string if no valid facts exist.

    Raises: * No exceptions raised.

    Guard and Preconditions Check

        if not facts or facts.get("claims") is None:
        return ""
    symbols = facts.get("symbols") or []
    modules = list(dict.fromkeys(edge["module"] for edge in facts.get("depends_on") or []))
    config = facts.get("config") or []
    errors = list(dict.fromkeys(item["name"] for item in facts.get("errors") or [] if item.get("role", "raised") != "caught"))
    if not (symbols or modules or config or errors):
        return ""
    The routine verifies that the input facts dictionary is non-empty and contains an active claims payload. It extracts symbol lists, deduplicates dependency target module paths using dict.fromkeys(), extracts configuration references, and compiles error entries that represent raised (non-caught) exceptions. If all collections are empty, the method returns "".

    Formatting and Block Assembly

        lines = ["VERIFIED FACTS OF THIS FILE (extracted from it and checked against its source code):"]
    if symbols:
        lines.append(
            "Symbols — document every one; copy each signature as written here (one marked 'start of the declaration' continues in the source: copy it in full from there):"
        )
        for symbol in symbols:
            owner = f"{symbol['parent']}." if symbol.get("parent") else ""
            visibility = f", {symbol['visibility']}" if symbol.get("visibility") else ""
            signature, partial = _fact_signature(symbol)

            lines.append(

    if errors:
        lines.append("Errors it raises or defines: " + ", ".join(errors))

Symbols are rendered with their kind, qualified parent ownership, visibility level, declaration line number, and sanitized signature. Target dependencies are mapped against the doc_paths dictionary to supply exact (doc: ...) Markdown link targets. Configuration accessors and raised errors are formatted into comma-delimited summaries.

    build_facts_focus_note()

    Visibility: Public Signature: def build_facts_focus_note(lines: list[tuple[int, str]], limit: int = FACTS_FOCUS_LIMIT) -> str:

    Description: Constructs the {focus_note} prompt segment for follow-up passes of extract_facts.md. When an initial extraction pass fails to account for lines that appear to contain code declarations or import statements, this helper formats up to limit (default 60) uncovered lines with their 1-based line numbers, truncating oversized or minified lines to _FOCUS_LINE_CHARS to instruct the model to report facts specifically on those omitted lines.

    Parameters: * lines (list[tuple[int, str]]): Sequence of (line_number, line_text) tuples representing uncovered source lines. * limit (int, optional): Maximum number of lines to explicitly detail before appending an aggregate count of remaining lines. Defaults to FACTS_FOCUS_LIMIT (60).

    Returns: * str: Formatted follow-up instruction string.

    Raises: * No exceptions raised.

    Example: 

    def build_facts_focus_note(lines: list[tuple[int, str]], limit: int = FACTS_FOCUS_LIMIT) -> str:
    """The ``{focus_note}`` of an extract_facts.md follow-up: the uncovered lines a first pass left out."""

    def shown_line(text: str) -> str:
        text = text.strip()
        return text if len(text) <= _FOCUS_LINE_CHARS else text[: _FOCUS_LINE_CHARS - 3] + "..."

    shown = "\n".join(f"  {number}: {shown_line(text)}" for number, text in lines[:limit])
    more = f"\n  ... and {len(lines) - limit} more such lines" if len(lines) > limit else ""
    return (
        "FOLLOW-UP: a first pass over this file reported nothing for the lines below, which look like declarations "
        "or imports. Report ONLY the facts on these lines, with the same four lists and rules; a line that is not a "
        "declaration a reader looks up (a local variable, a statement) gets nothing.\n"
        f"Lines:\n{shown}{more}\n"
    )

    The nested helper shown_line strips whitespace and clamps lines longer than _FOCUS_LINE_CHARS (200 characters) by appending ellipses (...). The formatted lines are joined with 2-space indentation. If the list exceeds the specified limit, an aggregate trailer (... and N more such lines) is appended, signaling the model that additional uncovered lines exist in the file.

    parse_facts_response()

    Visibility: Public Signature: def parse_facts_response(response, keys: tuple = FACTS_KEYS) -> dict:

    Description: Parses and validates the structured YAML response emitted by extract_facts.md (or extract_manifest.md). To prevent silent data loss from LLM formatting quirks, the function executes a four-phase parsing and recovery routine: it checks for truncation, extracts the fenced YAML payload, quotes indicator-prefixed identifiers (e.g., @pkg/name, *args), rewrites plain scalar code snippets into block scalars, and falls back to item-by-item chunk recovery via _salvage_yaml_lists() if standard parsing fails. It ensures all scalar values remain raw strings via yaml.BaseLoader to prevent automatic type coercion of strings like "on", "404", or "3.10".

    Parameters: * response (str | Any): The model response text or TruncatedResponse object. * keys (tuple, optional): The expected top-level list keys in the payload. Defaults to FACTS_KEYS (("symbols", "dependencies", "config", "errors")).

    Returns: * dict: A dictionary containing lists of mapping items for each key in keys, plus an "unparsed" integer key indicating the count of lost or invalid items.

    Raises: * ValueError: Raised if the response is flagged as truncated, if no ```yaml fence is detected, or if no valid facts lists can be recovered.

    Phase 1: Truncation Check and Markdown Fence Extraction

        if getattr(response, "truncated", False):
        raise ValueError("LLM response was truncated before the YAML block completed")
    match = _FACTS_BLOCK_RE.search(response) or _FACTS_OPEN_RE.search(response)
    if not match:
        raise ValueError("Failed to parse YAML: no ```yaml block in the facts reply")
    indent = match.group(1)
    yaml_str = _quote_indicator_values("\n".join(line.removeprefix(indent) for line in match.group(2).split("\n")))
    unparsed = 0
    Execution begins by verifying response integrity via getattr(response, "truncated", False). The function then searches for fenced YAML code blocks using _FACTS_BLOCK_RE (closed fence matching the indentation of the opening fence) or _FACTS_OPEN_RE (an open fence extending to end-of-string). Any leading indentation on the opening fence is stripped uniformly across all lines to preserve internal YAML indentation hierarchies.

    Phase 2: Cascading Deserialization and List Salvaging

        try:
        data = _load_strings(yaml_str)
    except Exception:
        try:
            data = _load_strings(_block_quotes(yaml_str))
        except Exception:
            data, unparsed = _salvage_yaml_lists(_block_quotes(yaml_str), keys)
    if not isinstance(data, dict) or not any(key in data for key in keys):
        raise ValueError("Failed to parse YAML: no fact lists in the facts reply")
    The deserialization pipeline applies a three-tiered fallback sequence. It first attempts _load_strings(yaml_str). If that fails (typically due to unescaped colons in signatures), it applies _block_quotes() to convert plain scalars into |- block scalars and retries. If parsing still fails, it invokes _salvage_yaml_lists() to isolate individual lists and salvage items item-by-item, tracking the count of corrupted items in unparsed. If the final result is not a dictionary containing at least one expected key, a terminal ValueError is raised.

    Phase 3: Structural Validation and Unparsed Metric Calculation

        result = {}
    for key in keys:
        items = data.get(key)
        items = items if isinstance(items, list) else []
        result[key] = [item for item in items if isinstance(item, dict)]
        unparsed += len(items) - len(result[key])
    result["unparsed"] = unparsed
    return result
    In the post-processing phase, the function iterates through the expected keys. Missing or non-list entries default to empty lists. List items are filtered to ensure only dictionary mappings are preserved; any non-dict entries (such as stray strings or incomplete syntax artifacts) are discarded and increment the unparsed counter. The aggregated dictionary, including the final "unparsed" metric, is returned to the caller.

    build_code_file_filter_prompt()

    Visibility: Public Signature: def build_code_file_filter_prompt(project_name: str, file_listing: str) -> str:

    Description: Constructs the prompt for the DeterministicFileMapper pipeline node in API-reference documentation mode. It formats instructions requesting the LLM to classify repository files into actionable code files (containing APIs, classes, and logic) versus package manifests (such as package.json, Cargo.toml, go.mod), while explicitly excluding non-code assets, UI layouts, configs, build scripts, and static documentation.

    Parameters: * project_name (str): The display name or identifier of the project being processed. * file_listing (str): Pre-formatted directory tree or indexed file listing generated by utils.files.build_directory_tree.

    Returns: * str: The complete prompt string instructing the LLM to return a YAML structure containing code and manifests index lists.

    Raises: * No exceptions raised.

    Example: 

    def build_code_file_filter_prompt(project_name: str, file_listing: str) -> str:
    """Build the prompt for DeterministicFileMapper to filter non-code files.

    Used in api-reference mode to identify which files are actual code modules
    (APIs, functions, classes, business logic) vs. UI layouts, configs, assets, and which of the
    others are manifests that declare the names the code imports itself by (ExtractFacts reads those).
    """
    return (
        f"For the project `{project_name}`, here is the list of all files in the codebase:\n\n"
        f"{file_listing}\n\n"
        f"Your task is to identify WHICH of these files are ACTUAL CODE files that contain "
        f"APIs, functions, classes, or core business logic.\n"
        f"EXCLUDE: UI layouts (like .xaml, .storyboard, .html), configuration files "
        f"(like .xml, .json, .manifest, .ini), static assets, build scripts "
        f"(like .csproj, .sln), and documentation.\n\n"
        f"Separately, list the MANIFESTS among the other files: files that declare a package, module, crate or "
        f"workspace name, or import path aliases, for this project's own code (for example package.json, "
        f"tsconfig.json, go.mod, Cargo.toml, pyproject.toml, setup.cfg, composer.json, pom.xml, build.gradle, "

    Internal Helpers

    _fact_signature()

    Visibility: Private Signature: def _fact_signature(symbol: dict) -> tuple[str, bool]:

    Description: Normalizes and cleans a symbol's raw signature string for display within prompt context blocks. It strips leading language decorators or attributes (such as @property, #[inline], or [Obsolete]), collapses multiline signatures and internal whitespace into a single line, detects whether the signature was cut short (due to upstream truncation, unbalanced parentheses/brackets, or exceeding _FACT_SIGNATURE_CHARS), and appends a trailing ellipsis if partial.

    Parameters: * symbol (dict): The symbol facts dictionary containing keys such as "signature" and "truncated".

    Returns: * tuple[str, bool]: A 2-tuple (text, partial) containing the sanitized single-line signature string and a boolean flag indicating whether the signature is truncated or incomplete.

    Raises: * No exceptions raised.

    Example: 

    def _fact_signature(symbol: dict) -> tuple[str, bool]:
    """A verified signature for the prompt: ``(one-line text, cut short)``."""
    lines = str(symbol.get("signature", "")).split("\n")
    while len(lines) > 1 and re.match(r"\s*(?:@|#\[|\[[A-Z])", lines[0]):  # @property, #[inline], [Obsolete]
        lines = lines[1:]
    text = " ".join(" ".join(lines).split())
    code = re.sub(r"\"(?:\\.|[^\"\\])*\"|'(?:\\.|[^'\\])*'", "", text)
    partial = bool(symbol.get("truncated")) or code.count("(") > code.count(")") or code.count("[") > code.count("]")
    if len(text) > _FACT_SIGNATURE_CHARS:
        text, partial = text[:_FACT_SIGNATURE_CHARS].rstrip(), True
    return (text + " …" if partial else text), partial

    The function splits the signature on line breaks and drops leading lines matching common decorator patterns across Python, Rust, and C#. It collapses internal whitespace sequences via " ".join(" ".join(lines).split()). To detect structural truncation accurately without being misled by brackets inside string literals, it strips quoted literals via re.sub before counting parentheses and square brackets. If brackets are unbalanced, if the symbol is explicitly marked truncated, or if text length exceeds _FACT_SIGNATURE_CHARS (200 characters), partial is set to True and the string is truncated with an appended " …".

    Description: Wraps a given string into a Markdown inline code span such that backticks contained within the string cannot prematurely close the span. It calculates the longest run of consecutive backtick characters present in text, creates a fence delimiter with one additional backtick, and adds padding spaces if the text itself contains backticks.

    Parameters: * text (str): The raw text to wrap inside an inline code span.

    Returns: * str: The formatted inline code span string.

    Raises: * No exceptions raised.

    Example: 

    def _code_span(text: str) -> str:
    """*text* as inline code that its own backticks cannot close (a run one longer than any inside, padded)."""
    fence = "`" * (max((len(run) for run in re.findall(r"`+", text)), default=0) + 1)

    _load_strings()

    Visibility: Private Signature: def _load_strings(text: str):

    Description: Deserializes a YAML string using yaml.BaseLoader. Standard YAML parsers automatically convert unquoted tokens such as 404, on, off, yes, no, or version numbers like 3.10 into integers, booleans, or floats. By enforcing BaseLoader, this helper guarantees that all scalar values are parsed purely as raw Python str instances, preventing data corruption when extracting code identifiers, status codes, and configuration keys.

    Parameters: * text (str): YAML formatted string.

    Returns: * Any: Parsed Python data structure consisting exclusively of str, list, and dict types.

    Raises: * yaml.YAMLError: If the YAML string contains syntactic errors.

    Example: 

    def _load_strings(text: str):
    """YAML with every scalar kept as the reply's text: ``404``, ``on``, ``3.10`` stay strings."""
    return yaml.load(text, Loader=yaml.BaseLoader)  # BaseLoader builds only str / list / dict: safe

    This helper wraps yaml.load(text, Loader=yaml.BaseLoader). Because BaseLoader does not resolve scalar tags to arbitrary Python objects or native primitive types (like booleans and numbers), it also provides a security boundary against arbitrary object instantiation during YAML deserialization.

    _block_quotes()

    Visibility: Private Signature: def _block_quotes(text: str) -> str:

    Description: Converts unquoted or malformed multi-line scalar values on signature: or evidence: lines into YAML literal block scalars (|-). A frequent LLM mistake is outputting code signatures (e.g., signature: def run(self):) or evidence lines containing colons or # characters as plain unquoted scalars, which breaks YAML syntax. This helper detects such occurrences and rewrites them into properly indented block scalars.

    Parameters: * text (str): YAML text containing potentially malformed plain scalar lines.

    Returns: * str: Transformed YAML string with affected scalar lines formatted as block scalars.

    Raises: * No exceptions raised.

    Example: 

    def _block_quotes(text: str) -> str:
    return _PLAIN_QUOTE_RE.sub(lambda m: m[0] if _WHOLE_SCALAR_RE.match(m[3]) else f"{m[1]}{m[2]}: |-\n{' ' * (len(m[1]) + 2)}{m[3]}", text)

    The regular expression _PLAIN_QUOTE_RE captures signature: and evidence: lines. If _WHOLE_SCALAR_RE matches the value (confirming it is already a fully quoted scalar or a valid block scalar indicator), the match is retained unmodified (m[0]). Otherwise, the value is rewritten as : |-\n followed by the original value indented with two additional spaces relative to the parent key's indentation.

    _salvage_yaml_lists()

    Visibility: Private Signature: def _salvage_yaml_lists(yaml_str: str, keys: tuple) -> tuple[dict, int]:

    Description: High-resilience fallback parser for severely malformed YAML payloads. When document-level parsing fails, this helper partitions the YAML text by top-level keys (symbols, dependencies, config, errors). If a list chunk still fails to parse as a whole, it splits the list along item boundary prefixes (-) based on indentation and parses each item individually. Successfully parsed items are retained, while unparseable items increment a lost item counter.

    Parameters: * yaml_str (str): The corrupted YAML string. * keys (tuple): Tuple of top-level list keys to look for.

    Returns: * tuple[dict, int]: A 2-tuple (parsed, lost) where parsed maps recovered keys to lists of valid dictionary items, and lost is the integer count of discarded items.

    Raises: * No exceptions raised.

    Example: 

    def _salvage_yaml_lists(yaml_str: str, keys: tuple) -> tuple[dict, int]:
    """Parse each top-level ``key:`` list of a broken YAML block on its own; a list that still fails is
    parsed item by item (split at its own ``- `` indentation) and keeps the items that parse.
    Returns ``(lists, number of items lost)``."""
    names = "|".join(keys)
    parsed, lost = {}, 0
    for chunk in re.split(rf"(?m)^(?=(?:{names})\s*:)", yaml_str):
        head = re.match(rf"({names})\s*:", chunk)
        if not head:
            continue
        try:
            part = _load_strings(chunk)
        except Exception:
            part = None
        if isinstance(part, dict):
            parsed.update(part)
            continue
        body = chunk[head.end() :]
        first = re.search(r"(?m)^([ \t]*)- ", body)
        if not first:
            continue
        indent = first.group(1)
        items = []
        for piece in re.split(rf"(?m)^(?={re.escape(indent)}- )", body):
            if not piece.startswith(f"{indent}- "):
                continue
            text = "\n".join(line.removeprefix(indent) for line in piece.split("\n"))
            try:
                item = _load_strings(text)
            except Exception:
                lost += 1
                continue
            if isinstance(item, list) and item and isinstance(item[0], dict):
                items.append(item[0])
            else:
                lost += 1
        parsed[head.group(1)] = items
    return parsed, lost

    The function splits the text across key names using a multiline positive lookahead (?m)^(?=(?:{names})\s*:). For each chunk, it tests whether the entire section parses via _load_strings(chunk). If parsing fails, it determines the indentation level of the initial list item (first.group(1)). It then splits the body across item boundaries matching (?m)^(?={indent}- ). Each piece has its outer indentation stripped and is parsed individually via _load_strings. Valid mapping entries are appended to the list, while malformed pieces increment lost.

    Error Handling

    The module implements a strict fail-fast approach for fatal conditions, paired with multi-tiered recovery for recoverable syntax flaws:

    1. Truncation Detection: The parsing functions (parse_yaml_response, parse_grouping_response, and parse_facts_response) inspect incoming response payloads using getattr(response, "truncated", False). When an upstream LLM client (such as llm_anthropic, llm_gemini, or llm_openrouter) emits a TruncatedResponse due to generation token exhaustion, the parser raises an immediate ValueError: 

      if getattr(response, "truncated", False):
    raise ValueError("LLM response was truncated before the YAML block completed")
      This prevents pipeline execution from proceeding with partial data structures that would silently drop modules, symbols, or sections.

    2. Cascading YAML Recovery: In parse_facts_response, parsing errors trigger a multi-stage fallback:

    3. Stage 1 (Strict): Raw extraction using yaml.BaseLoader.
    4. Stage 2 (Scalar Normalization): If Stage 1 fails, _block_quotes() transforms unquoted colons and hash characters on signature: and evidence: lines into |- literal block scalars.
    5. Stage 3 (Item-by-Item Salvage): If Stage 2 fails, _salvage_yaml_lists() splits the payload into individual section chunks and parses items individually along - item boundaries.

    6. Loss Accounting: Dropped items are tallied in the "unparsed" field so upstream validation stages can audit extraction completeness.

    7. Malformed Grouping Recovery: In parse_grouping_response, invalid backtick formatting around section roles (e.g., role:core`) is scrubbed using regex, and section blocks are parsed independently. If the primary"sections"list cannot be constructed, a descriptiveValueError` is raised.
