    prompts.py

    Source: utils/prompts.py

    Technical Overview

    Building directly upon the telemetry and messaging infrastructure provided by utils/output.py, utils/prompts.py serves as the centralized prompt template loader, inline prompt constructor, and resilient response parsing engine for the codebase knowledge generation pipeline. It abstracts the retrieval of prompt files across varied architectural documentation modes (tutorial, advanced, api-reference, sdk), formats dynamic contextual payloads for downstream Large Language Model (LLM) calls, and transforms raw model outputs into structured, typed Python dictionaries. By decoupling prompt formatting and deserialization from workflow execution nodes, the module standardizes communication boundaries and shields downstream components from provider-specific generation quirks.

    A central responsibility of the module is robust, fault-tolerant parsing of non-deterministic LLM completions. Generative language models frequently introduce syntax errors into YAML payloads, such as unquoted indicator characters (@, #, *), bare scalar quotes containing colons, invalid backtick wrapping around YAML keys, or premature response truncation caused by generation token ceilings. To prevent catastrophic pipeline failures during multi-stage indexing runs, utils/prompts.py implements a multi-tiered recovery architecture. It sequentially attempts standard deserialization, regex-driven indicator quoting, scalar-to-block conversion (|-), top-level key segmentation, and granular line-by-line item salvaging, tracking unparsed artifacts to preserve factual claims without aborting entire batch jobs.

    Public API

    parse_file_index()

    Visibility: Public

    Signature: def parse_file_index(idx_value):

    Description: Extracts the first integer encountered from an LLM-returned file index value. It accommodates various scalar representations returned by models, including raw integers, annotated file path strings, and hyphenated numeric ranges, returning the leading integer component while delegating full range expansion to other utilities.

    Parameters:

    • idx_value (Any): The raw input value representing a file index, typically an int, str, or composite string.

    Returns:

    • int | None: The first parsed integer extracted from the string representation of the argument, or None if no numeric digits are found.

    Raises:

    • Does not raise exceptions. Non-numeric or empty string conversions safely evaluate to None.

    Example:

    def parse_file_index(idx_value):
    nums = re.findall(r"\d+", str(idx_value))
    return int(nums[0]) if nums else None

    The function executes a regular expression search over the string cast of idx_value, isolating all contiguous sequences of ASCII digits. If the match list is populated, the first element is converted to a native Python int and returned immediately. This design provides basic tolerance for models that return prose annotations alongside numeric IDs (such as "3 # path/to/file.py"), though it truncates hyphenated ranges to their starting index without evaluating downstream boundaries.

    parse_file_indices()

    Visibility: Public

    Signature: def parse_file_indices(idx_value) -> list[int]:

    Description: Strictly parses an index representation returned by an LLM into an explicit list of integer indices. Unlike parse_file_index(), this function discriminates between explicit file indices, annotated numeric comments, and expanded ascending index ranges, actively rejecting file paths containing digits or arbitrary prose to avoid linking hallucinated files.

    Phase 1: Primitive Type Guarding

        if isinstance(idx_value, bool):
        return []
    if isinstance(idx_value, int):
        return [idx_value] if idx_value >= 0 else []
    text = str(idx_value) if isinstance(idx_value, str) else ""

    The initial phase screens against primitive Python types to prevent standard type coercion errors. Booleans are rejected outright because Python treats bool as a subclass of int (which would otherwise evaluate True to index 1). Non-negative integers are packaged directly into single-element lists, while negative integers are discarded to avoid negative indexing bugs. Non-string inputs are converted to empty strings to guarantee that subsequent regular expression operations execute against clean character sequences.

    Phase 2: Single Index Matching

        single = _INDEX_RE.match(text)
    if single:
        return [int(single.group(1))]

    The second phase evaluates the input string against _INDEX_RE. This regular expression matches single non-negative integers bounded by whitespace and optionally followed by a hash comment (#) containing trailing file path metadata. If a match occurs, the isolated integer token from capture group 1 is parsed and returned as a single-item list. This pattern ensures annotated tokens like "3 # utils/prompts.py" resolve strictly to [3] without executing arbitrary range scans.

    Phase 3: Range and Span Expansion

        span = _INDEX_RANGE_RE.match(text)
    if span and int(span.group(1)) <= int(span.group(2)) and int(span.group(2)) - int(span.group(1)) < 10000:
        return list(range(int(span.group(1)), int(span.group(2)) + 1))
    return []

    The final phase evaluates candidate ranges using _INDEX_RANGE_RE, matching ascending intervals separated by hyphens, double periods, en-dashes, or the word "to". To prevent Denial of Service (DoS) memory exhaustion from maliciously crafted or hallucinated LLM responses, the lower boundary must be less than or equal to the upper boundary, and the total span difference must be strictly under 10,000 items. If these validation constraints pass, the inclusive range is expanded into a Python list[int]; otherwise, an empty list is returned to signal an unparseable entry.

    load_prompt_template()

    Visibility: Public

    Signature: def load_prompt_template(template_name, advanced_mode=False, mode=None):

    Description: Reads and returns the raw Markdown prompt template from the project's prompts/ directory tree. It resolves template directory hierarchies dynamically based on operating mode configurations and records file retrieval telemetry to the debug log destination.

    Parameters:

    • template_name (str): The base filename of the template, excluding the .md extension (e.g., "extract_facts").
    • advanced_mode (bool, default: False): Fallback flag toggling between "advanced" and "tutorial" template directories when mode is unspecified.
    • mode (str | None, default: None): Explicit operating mode subdirectory (e.g., "api-reference", "sdk", "common"). Overrides advanced_mode if provided.

    Returns:

    • str: The complete decoded text contents of the prompt template file.

    Raises:

    • FileNotFoundError: If the constructed prompt template file path does not exist on disk.
    • OSError: If the file cannot be accessed or read due to filesystem permission constraints.

    Example:

    def load_prompt_template(template_name, advanced_mode=False, mode=None):
    if mode is None:
        prompt_dir = "advanced" if advanced_mode else "tutorial"
    else:
        prompt_dir = mode

    path = os.path.join(os.path.dirname(os.path.dirname(os.path.abspath(__file__))), "prompts", prompt_dir, f"{template_name}.md")
    with open(path, encoding="utf-8-sig") as f:
        content = f.read()
    from utils.output import emit_raw

    emit_raw("DEBUG", f"load_prompt_template | loaded '{template_name}.md' from prompts/{prompt_dir}/", dest="LOG")
    return content

    The function computes an absolute path to the target Markdown file by traversing up two directory levels from the current script location to locate the repository root. The file is ingested using utf-8-sig encoding, ensuring that any leading Byte Order Marks (BOM) are stripped cleanly without corrupting prompt preambles. To avoid circular import cycles during early application bootstrapping, it lazily imports emit_raw from utils.output within local function scope, dispatching a debug telemetry log before returning the string content.

    parse_yaml_response()

    Visibility: Public

    Signature: def parse_yaml_response(response):

    Description: Extracts and deserializes raw YAML payloads contained within Markdown code fences from an LLM completion string. It validates that the completion was not prematurely terminated by token context limits prior to invoking PyYAML.

    Parameters:

    • response (str | Any): The text response returned by the LLM, or a response object implementing a truncated boolean attribute.

    Returns:

    • Any: The deserialized Python data structure (typically a dict or list) parsed from the YAML block.

    Raises:

    • ValueError: Raised if the response object has its truncated attribute set to True, if the response does not contain matching ```yaml fences, or if PyYAML fails to parse the extracted block.

    Example:

    def parse_yaml_response(response):
    if getattr(response, "truncated", False):
        raise ValueError("LLM response was truncated before the YAML block completed")
    try:
        yaml_str = response.strip().split("```yaml")[1].split("```")[0].strip()
        return yaml.safe_load(yaml_str)
    except Exception as e:
        raise ValueError(f"Failed to parse YAML: {e}") from e

    The function first guards against truncated completions by inspecting getattr(response, "truncated", False). This prevents silent data loss where an LLM reaches an output token limit mid-generation, leaving a validly fenced prefix that omits subsequent structural elements. It isolates the YAML substring by splitting on the opening ```yaml marker and closing ``` delimiter. If delimiter extraction fails or if yaml.safe_load encounters malformed syntax, the original error is wrapped and re-raised as a descriptive ValueError.

    parse_grouping_response()

    Visibility: Public

    Signature: def parse_grouping_response(response):

    Description: Parses the multi-section YAML reply generated by the group_modules.md prompt. It handles structural errors introduced by language models, such as wrapping YAML key values in Markdown backticks or producing invalid document boundaries, by executing top-level chunked recovery across section headers.

    Phase 1: Direct YAML Deserialization

        try:
        return parse_yaml_response(response)
    except ValueError:
        if getattr(response, "truncated", False) or "```yaml" not in response:
            raise

    The function initially attempts an optimistic parse via parse_yaml_response(). If this succeeds without syntax errors, the parsed dictionary is returned immediately. If a ValueError is raised, the function checks whether the response was explicitly truncated or entirely lacks a ```yaml fence; if either condition is true, recovery is impossible, and the exception is propagated immediately to trigger downstream node retries.

    Phase 2: Syntax Normalization and Chunk Recovery

            yaml_str = response.split("```yaml", 1)[1].split("```", 1)[0]
        yaml_str = re.sub(r"(?m)^(\s*(?:-\s+)?role\s*:\s*)`([^`\n]*)`", r"\1\2", yaml_str)
        parsed = {}
        for chunk in re.split(r"(?m)^(?=(?:sections|dependencies)\s*:)", yaml_str):
            try:
                part = yaml.safe_load(chunk)
            except Exception:
                continue
            if isinstance(part, dict):
                parsed.update(part)
        if not isinstance(parsed.get("sections"), list):
            raise ValueError("Failed to parse YAML: no sections list in the grouping reply") from None
        return parsed

    When standard parsing fails, the recovery phase isolates the YAML payload and applies regex normalization to unwrap backticks from around role: specifications (e.g., - role:core` becomes- role: core). It then splits the document on top-level section boundaries (sections:,descriptions:,dependencies:) using lookahead regex matching. Each chunk is parsed independently viayaml.safe_load(), allowing a syntax error inside one component (such as an unescaped character in a description) to be discarded without invalidating the navigation sidebar or dependency linkages. If the recovered dictionary fails to contain a validsectionslist, aValueError` is raised.

    build_verified_facts_block()

    Visibility: Public

    Signature: def build_verified_facts_block(facts: dict | None, doc_paths: dict) -> str:

    Description: Constructs the {verified_facts} Markdown prompt context block used during API reference chapter drafting (draft_chapters.md). It aggregates verified AST declarations, cross-module import paths, configuration parameters, and raised error classes into an authoritative reference block that instructs the model to adhere strictly to verified source facts.

    Phase 1: Claims Validation and Target Filtering

        if not facts or facts.get("claims") is None:
        return ""
    symbols = facts.get("symbols") or []
    modules = list(dict.fromkeys(edge["module"] for edge in facts.get("depends_on") or []))
    config = facts.get("config") or []
    errors = list(dict.fromkeys(item["name"] for item in facts.get("errors") or [] if item.get("role", "raised") != "caught"))
    if not (symbols or modules or config or errors):
        return ""

    The function inspects the input facts dictionary, returning an empty string immediately if the dictionary is missing, if claims is None (signaling failed extraction), or if all fact categories are empty. It deduplicates imported dependency targets while preserving encounter order using dict.fromkeys(). For error structures, it filters out purely caught exceptions, retaining only exceptions explicitly raised or defined by the module to ensure the prompt accurately depicts the component's error-throwing contracts.

    Phase 2: Markdown Section Assembly

        lines = ["VERIFIED FACTS OF THIS FILE (extracted from it and checked against its source code):"]
    if symbols:
        lines.append(
            "Symbols — document every one; copy each signature as written here (one marked 'start of the declaration' continues in the source: copy it in full from there):"
        )
        for symbol in symbols:
            owner = f"{symbol['parent']}." if symbol.get("parent") else ""
            visibility = f", {symbol['visibility']}" if symbol.get("visibility") else ""
            signature, partial = _fact_signature(symbol)
            marker = " — start of the declaration" if partial else ""
            lines.append(
                f"- {symbol.get('kind') or 'symbol'} {owner}{symbol['name']}{visibility} (line {symbol['line']}): {_code_span(signature)}{marker}"
            )
    if modules:
        lines.append("Project files this file imports — See Also must link each of them:")
        lines.extend(f"- {module} (doc: {doc_paths.get(module, module + '.md')})" for module in modules)
    if config:
        lines.append("Configuration it reads: " + ", ".join(f"{item['name']} ({item.get('kind') or 'config'})" for item in config))
    if errors:
        lines.append("Errors it raises or defines: " + ", ".join(errors))
    return "\n".join(lines) + "\n"

    The second phase compiles the filtered categories into formatted Markdown bullet points. Each symbol entry formats its parent ownership, access visibility, source line, and signature string wrapped in backtick fences via _code_span(). Truncated or multi-line signatures are flagged with " — start of the declaration" to mandate that the model copy full definitions from the source code. Imported modules are annotated with their destination chapter paths via doc_paths, and configuration items and error classes are listed as comma-delimited summaries.

    build_facts_focus_note()

    Visibility: Public

    Signature: def build_facts_focus_note(lines: list[tuple[int, str]], limit: int = FACTS_FOCUS_LIMIT) -> str:

    Description: Generates the {focus_note} prompt segment for follow-up AST extraction passes (extract_facts.md). When an initial extraction pass fails to account for lines that resemble declarations or imports, this function constructs targeted prompt instructions that constrain the LLM to analyze only the specified unverified line numbers.

    Parameters:

    • lines (list[tuple[int, str]]): A list of tuples, each pairing a 1-based source line number with its corresponding raw text string.
    • limit (int, default: FACTS_FOCUS_LIMIT = 60): The maximum number of physical code lines to render directly inside the prompt note.

    Returns:

    • str: The formatted follow-up instruction string containing enumerated line previews and remaining count warnings.

    Raises:

    • Does not raise exceptions.

    Example:

    def build_facts_focus_note(lines: list[tuple[int, str]], limit: int = FACTS_FOCUS_LIMIT) -> str:
    def shown_line(text: str) -> str:
        text = text.strip()
        return text if len(text) <= _FOCUS_LINE_CHARS else text[: _FOCUS_LINE_CHARS - 3] + "..."

    shown = "\n".join(f"  {number}: {shown_line(text)}" for number, text in lines[:limit])
    more = f"\n  ... and {len(lines) - limit} more such lines" if len(lines) > limit else ""
    return (
        "FOLLOW-UP: a first pass over this file reported nothing for the lines below, which look like declarations "
        "or imports. Report ONLY the facts on these lines, with the same four lists and rules; a line that is not a "
        "declaration a reader looks up (a local variable, a statement) gets nothing.\n"
        f"Lines:\n{shown}{more}\n"
    )

    The function defines an internal helper, shown_line(), which strips leading and trailing whitespace and truncates lines exceeding _FOCUS_LINE_CHARS (200 characters) with an ellipsis (...). It slices the incoming line list up to limit entries, formatting each line with two-space indentation and its physical line number. If the total unverified line count exceeds the limit, a summary line is appended noting the remaining quantity. The assembled string establishes strict boundaries that instruct the LLM not to report local variables or procedural statements.

    parse_facts_response()

    Visibility: Public

    Signature: def parse_facts_response(response, keys: tuple = FACTS_KEYS) -> dict:

    Description: Parses the YAML completion from extract_facts.md or extract_manifest.md into a structured dictionary containing symbol lists, dependencies, configurations, and errors. It implements a multi-pass parsing and salvage routine that recovers valid declarations from syntactically malformed model responses while recording the count of unparseable items.

    Phase 1: Truncation Check and Fence Extraction

        if getattr(response, "truncated", False):
        raise ValueError("LLM response was truncated before the YAML block completed")
    match = _FACTS_BLOCK_RE.search(response) or _FACTS_OPEN_RE.search(response)
    if not match:
        raise ValueError("Failed to parse YAML: no ```yaml block in the facts reply")
    indent = match.group(1)
    yaml_str = _quote_indicator_values("\n".join(line.removeprefix(indent) for line in match.group(2).split("\n")))
    unparsed = 0

    The parsing pipeline begins by asserting that the response was not cut off by context boundaries via the truncated attribute check. It then searches for Markdown code blocks using _FACTS_BLOCK_RE (matching closed fences at uniform indentation) or _FACTS_OPEN_RE (matching unclosed fences reaching EOF). The common indentation prefix of the fence is stripped from all lines, and name-like fields containing YAML indicators are double-quoted via _quote_indicator_values() to prevent PyYAML parser exceptions on characters like @ or *.

    Phase 2: Indicator Quoting and Multi-Tier Parsing

        try:
        data = _load_strings(yaml_str)
    except Exception:
        try:
            data = _load_strings(_block_quotes(yaml_str))
        except Exception:
            data, unparsed = _salvage_yaml_lists(_block_quotes(yaml_str), keys)
    if not isinstance(data, dict) or not any(key in data for key in keys):
        raise ValueError("Failed to parse YAML: no fact lists in the facts reply")

    The second phase employs three tiered parsing attempts. First, it attempts a direct string load using _load_strings() (which utilizes yaml.BaseLoader to retain all scalars as strings). If this fails due to plain scalars containing syntax-breaking colons or quotes, it transforms single-line quotes into block scalars via _block_quotes() and retries _load_strings(). If the re-parse fails again, execution falls back to _salvage_yaml_lists(), which isolates individual list chunks and parses item-by-item to salvage valid records while counting lost entries.

    Phase 3: Dict Key Assembly and Lost Item Accounting

        result = {}
    for key in keys:
        items = data.get(key)
        items = items if isinstance(items, list) else []
        result[key] = [item for item in items if isinstance(item, dict)]
        unparsed += len(items) - len(result[key])
    result["unparsed"] = unparsed
    return result

    In the final phase, the parsed object is verified to contain at least one expected category key. The function iterates across the requested keys tuple (defaulting to FACTS_KEYS), ensuring that missing or null fields normalize to empty Python lists. It filters each list to keep only dictionary mappings, adding any non-mapping items (such as bare strings resulting from YAML formatting errors) to the running unparsed counter. The aggregated unparsed total is injected into the returned dictionary under the "unparsed" key.

    def build_code_file_filter_prompt(project_name: str, file_listing: str) -> str:

    build_chapter_summary_prompt()

    Visibility: Public

    Signature: def build_chapter_summary_prompt(chapter_num: int, abstraction_name: str, chapter_content: str, language: str = "english") -> str:

    Description: Constructs the prompt for generating a structured, four-dimension technical summary of a newly drafted chapter. This summary is injected into subsequent chapter drafting prompts to maintain narrative coherence, dependency context, and architectural consistency across the generated documentation suite.

    Parameters:

    • chapter_num (int): The numeric sequence index of the chapter.
    • abstraction_name (str): The title or architectural abstraction represented by the chapter.
    • chapter_content (str): The full Markdown text of the generated chapter.
    • language (str, default: "english"): Target language for the summary generation.

    Returns:

    • str: The complete prompt requesting a four-point technical brief.

    Raises:

    • Does not raise exceptions.

    Example:

    def build_chapter_summary_prompt(chapter_num: int, abstraction_name: str, chapter_content: str, language: str = "english") -> str:
    lang_instruction = f"Write the entire summary in {language.capitalize()}. " if language.lower() != "english" else ""
    return (
        f"{lang_instruction}"

    Internal Helpers

    _fact_signature()

    Visibility: Private

    Signature: def _fact_signature(symbol: dict) -> tuple[str, bool]:

    Description: Normalizes and truncates a verified symbol signature string for safe inclusion in prompt Markdown code spans. It strips leading decorators or compiler attributes, squashes multi-line declarations into a single space-delimited string, checks for bracket balance, and clamps string length against _FACT_SIGNATURE_CHARS.

    Parameters:

    • symbol (dict): A symbol fact mapping extracted from the codebase, containing "signature", "truncated", and name fields.

    Returns:

    • tuple[str, bool]: A 2-tuple containing:
      1. The sanitized, single-line signature text (appended with an ellipsis " …" if partial).
      2. A boolean indicating whether the signature was cut short or requires full source verification.

    Example:

    def _fact_signature(symbol: dict) -> tuple[str, bool]:
    lines = str(symbol.get("signature", "")).split("\n")
    while len(lines) > 1 and re.match(r"\s*(?:@|#\[|\[[A-Z])", lines[0]):
        lines = lines[1:]
    text = " ".join(" ".join(lines).split())
    code = re.sub(r"\"(?:\\.|[^\"\\])*\"|'(?:\\.|[^'\\])*'", "", text)
    partial = bool(symbol.get("truncated")) or code.count("(") > code.count(")") or code.count("[") > code.count("]")
    if len(text) > _FACT_SIGNATURE_CHARS:
        text, partial = text[:_FACT_SIGNATURE_CHARS].rstrip(), True
    return (text + " …" if partial else text), partial

    The function splits the signature on newlines and drops leading lines starting with decorators or attribute annotations (@property, #[inline], [Obsolete]). It squashes all internal whitespace runs into single spaces. To determine if the signature represents an incomplete fragment, it strips string literals (to avoid counting characters inside quotes) and tests whether opening parentheses or brackets exceed closing ones. Finally, if the line exceeds 200 characters (_FACT_SIGNATURE_CHARS), it is sliced and marked as partial.

    _code_span()

    Visibility: Private

    Signature: def _code_span(text: str) -> str:

    Description: Wraps a code snippet in an inline Markdown backtick span designed so that internal backtick characters cannot accidentally close the span.

    Parameters:

    • text (str): The raw code or signature text to encapsulate.

    Returns:

    • str: The backtick-wrapped Markdown code span, padded with spaces if internal backticks exist.

    Example:

    def _code_span(text: str) -> str:
    fence = "`" * (max((len(run) for run in re.findall(r"`+", text)), default=0) + 1)
    return f"{fence} {text} {fence}" if "`" in text else f"{fence}{text}{fence}"

    The function inspects text for all contiguous sequences of backtick characters (```). It generates an enclosing delimiter sequence whose length is strictly one character longer than the longest backtick run found inside the text (defaulting to a single backtick if none exist). If the text contains any backticks, CommonMark rules mandate space padding adjacent to the boundary fences to prevent parser collisions; otherwise, it formats the fence flush against the string.

    _load_strings()

    Visibility: Private

    Signature: def _load_strings(text: str):

    Description: Deserializes a YAML string while forcing all scalar primitives to remain native Python strings. Prevents unintended type coercion of values like HTTP status codes (404), boolean literals (on, no), or software version strings (3.10).

    Parameters:

    • text (str): The raw YAML string to load.

    Returns:

    • Any: A data structure where all primitive values are typed as str, list, or dict.

    Example:

    def _load_strings(text: str):
    return yaml.load(text, Loader=yaml.BaseLoader)

    The function invokes yaml.load() using PyYAML's yaml.BaseLoader. Unlike yaml.SafeLoader or yaml.FullLoader, BaseLoader skips standard type resolvers, meaning numbers, dates, booleans, and nulls are ingested without transformation as string objects. This protects symbol names, configuration values, and module identifiers from corruption during AST parsing.

    _quote_indicator_values()

    Visibility: Private

    Signature: def _quote_indicator_values(text: str) -> str:

    Description: Wraps name-like YAML values that begin with special indicator characters inside double quotes. Eliminates syntax errors caused by symbols like @decorator, #channel, or *args.

    Parameters:

    • text (str): The YAML document text to sanitize.

    Returns:

    • str: The sanitized YAML string with offending indicator-prefixed values escaped and enclosed in double quotes.

    Example:

    def _quote_indicator_values(text: str) -> str:
    return _INDICATOR_VALUE_RE.sub(lambda m: m[1] + '"' + m[2].replace("\\", "\\\\").replace('"', '\\"') + '"', text)

    The function uses _INDICATOR_VALUE_RE to scan for dictionary keys like name:, entry:, alias:, or target: followed by tokens starting with indicator characters (@, ,, #, *, &, !, %). The substitution callback preserves the key indentation while escaping backslashes and quotes within the value string, enclosing the result in double quotes. This allows values like name: @acme/core or name: *args to pass PyYAML tokenization without being misconstrued as YAML anchors or invalid syntax.

    _block_quotes()

    Visibility: Private

    Signature: def _block_quotes(text: str) -> str:

    Description: Converts plain single-line signature: and evidence: scalar entries into YAML literal block scalars (|-). Resolves parsing errors caused by source code quotes that contain colons, hash symbols, or unbalanced quotes.

    Parameters:

    • text (str): The YAML text containing candidate scalar lines.

    Returns:

    • str: The transformed YAML text where bare code quotes are rewritten into indented block scalars.

    Example:

    def _block_quotes(text: str) -> str:
    return _PLAIN_QUOTE_RE.sub(lambda m: m[0] if _WHOLE_SCALAR_RE.match(m[3]) else f"{m[1]}{m[2]}: |-\n{' ' * (len(m[1]) + 2)}{m[3]}", text)

    The function evaluates lines matching _PLAIN_QUOTE_RE. If the value after signature: or evidence: already constitutes a valid quoted string or block indicator (verified via _WHOLE_SCALAR_RE), it is left unchanged. Otherwise, it rewrites the line to introduce a |- literal block indicator (which strips trailing newlines) and shifts the code quote to a new line indented two spaces deeper than the parent key. This prevents internal colons (e.g., def run(self):) from prematurely terminating scalar parsing.

    _salvage_yaml_lists()

    Visibility: Private

    Signature: def _salvage_yaml_lists(yaml_str: str, keys: tuple) -> tuple[dict, int]:

    Description: Granular recovery parser that salvages valid entries from a broken YAML document. It isolates each top-level key list independently, and if a list still fails to parse, breaks it into individual list items based on indentation to recover all valid dictionaries while accounting for lost items.

    Phase 1: Chunk Identification by Key Header

        names = "|".join(keys)
    parsed, lost = {}, 0
    for chunk in re.split(rf"(?m)^(?=(?:{names})\s*:)", yaml_str):
        head = re.match(rf"({names})\s*:", chunk)
        if not head:
            continue
        try:
            part = _load_strings(chunk)
        except Exception:
            part = None
        if isinstance(part, dict):
            parsed.update(part)
            continue

    The function constructs a dynamic regex from the requested category keys (e.g., "symbols|dependencies|config|errors"), splitting the document on lines where those keys begin. For each isolated section chunk, it extracts the key header and attempts to parse the chunk in isolation using _load_strings(). If the chunk parses cleanly as a dictionary, its contents are merged into parsed and the loop advances to the next section without item-level decomposition.

    Phase 2: Item-by-Item Indentation Extraction

            body = chunk[head.end() :]
        first = re.search(r"(?m)^([ \t]*)- ", body)
        if not first:
            continue
        indent = first.group(1)
        items = []
        for piece in re.split(rf"(?m)^(?={re.escape(indent)}- )", body):
            if not piece.startswith(f"{indent}- "):
                continue
            text = "\n".join(line.removeprefix(indent) for line in piece.split("\n"))
            try:
                item = _load_strings(text)
            except Exception:
                lost += 1
                continue
            if isinstance(item, list) and item and isinstance(item[0], dict):
                items.append(item[0])
            else:
                lost += 1
        parsed[head.group(1)] = items
    return parsed, lost

    When an entire list section fails to parse, the function isolates the list body and identifies the indentation of its first list item delimiter (-). It then splits the body into individual item pieces using a lookahead on that exact indentation pattern. Each item is stripped of its relative indentation prefix and parsed independently via _load_strings(). Successfully parsed dictionary items are collected into the items list; any item that throws an exception or fails to deserialize as a dictionary increments the lost counter. The recovered items are stored under their respective top-level key.

    Internal Regular Expression Constants

    The module defines compiled regular expressions to support its parsing and transformation subroutines:

    Constant Pattern / Definition Purpose
    _INDEX_RE re.compile(r"^\s*(\d+)\s*(?:#.*)?$") Matches single integers optionally followed by hash comments (e.g., "3 # file.py").
    _INDEX_RANGE_RE re.compile(r"^\s*(\d+)\s*(?:-|\.\.\|\u2013\|to)\s*(\d+)\s*(?:#.*)?$") Matches ascending ranges using hyphens, dots, en-dashes, or "to" (e.g., "0-3", "4..7").
    _FACTS_BLOCK_RE re.compile(r"(?msi)^([ \t]*)```ya?ml[^\n]*\n(.*?)^\1```[ \t]*$") Matches closed YAML blocks where opening and closing fences share identical indentation.
    _FACTS_OPEN_RE re.compile(r"(?msi)^([ \t]*)```ya?ml[^\n]*\n(.*)") Matches unclosed YAML blocks reaching the end of the completion text.
    _PLAIN_QUOTE_RE re.compile(r"(?m)^([ \t]*(?:- )?)(signature\|evidence):[ \t]+(\S.*)$") Matches unescaped scalar code quotes under signature: or evidence: keys.
    _WHOLE_SCALAR_RE re.compile(r"""^(?:"(?:\\.\|[^"\\])*"\|'(?:''\|[^'])*'\|[\|>][-+0-9]*)[ \t]*(?:#.*)?$""") Identifies valid quoted scalars or block indicators that do not require block scalar wrapping.
    _INDICATOR_VALUE_RE re.compile(r"(?m)^([ \t]*(?:- )?(?:name\|entry\|alias\|target\|base\|parent):[ \t]+)([@#&!%]\S||>\S)(?:[ \t]+#.)?$")` Matches name-like fields whose values begin with YAML indicator symbols.
    _FACT_SIGNATURE_CHARS 200 Maximum character length allocated for verified signatures in prompt blocks before truncation.
    _FOCUS_LINE_CHARS 200 Maximum character width rendered for individual code lines inside the facts focus note.

    Error Handling

    The module relies primarily on ValueError to report parsing and structural anomalies, avoiding custom exception hierarchies. Errors are surfaced under specific conditions:

    • Truncation Rejection: In both parse_yaml_response() and parse_facts_response(), incoming response objects are inspected for the attribute truncated. If getattr(response, "truncated", False) evaluates to True, a ValueError is raised immediately. This prevents incomplete YAML documents from being partially parsed, which would silently drop declarations or section links.
    • Missing YAML Fences: When parse_yaml_response() or parse_facts_response() cannot identify an opening ```yaml or ```yml code fence, a ValueError is raised rather than falling back to guessing scalar boundaries.
    • Missing Required Keys: In parse_grouping_response(), if the recovered structure lacks a valid sections list, a ValueError is raised. Similarly, parse_facts_response() raises a ValueError if the output dictionary contains none of the requested category keys.
    • PyYAML Exception Wrapping: Unhandled parsing errors from yaml.safe_load are caught, contextualized, and re-raised using Python's from e exception chaining syntax to maintain debugging tracebacks.
