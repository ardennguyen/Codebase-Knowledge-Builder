    prompts.py

    Source: utils/prompts.py

    Technical Overview

    Connecting from the logging and telemetry facilities implemented in utils/output.py, utils/prompts.py utilizes the module's diagnostic emission mechanisms while serving as the central prompt template loader, inline prompt constructor, and fault-tolerant LLM response parser for the documentation pipeline. The module acts as the serialization boundary between pipeline nodes and Large Language Model (LLM) inference endpoints. It supplies parameterized prompts for codebase file classification, chapter summarization, verified fact grounding, and structural module grouping, while also loading disk-based prompt templates across different operational documentation modes such as tutorial, advanced, SDK, and API reference modes.

    A primary technical challenge addressed by this module is the inherent syntactic instability of LLM-generated structured text. Foundation models frequently output YAML blocks containing unquoted special characters (such as @, #, and *), unescaped colons in code signatures, missing closing Markdown code fences, or premature cutoffs caused by context window or output token limits. To prevent catastrophic pipeline failures, utils/prompts.py implements a resilient multi-tiered parsing and salvage strategy. Instead of failing outright on syntax errors, it progressively sanitizes indicator tokens, converts unquoted scalar declarations into YAML block scalars, decomposes corrupted blocks into independent section chunks, and parses individual list items in isolation, accurately tracking discarded facts within an explicit metadata tally.

    Parameters:

    Returns:

    • int | None: The first parsed integer from the input value, or None if no numerical digits are present.

    Raises:

    Example:

    # Extracted from utils/prompts.py
def parse_file_index(idx_value):
    nums = re.findall(r"\d+", str(idx_value))
    return int(nums[0]) if nums else None

    The function converts the input argument to a string and executes a regular expression search for contiguous digit runs. If at least one digit sequence is discovered, the leading match is cast to an integer and returned. If no matching digits exist, it safely returns None.

    parse_file_indices()

    Visibility: Public

    Signature: def parse_file_indices(idx_value) -> list[int]:

    Description: Strictly validates and parses an index specification entry returned by an LLM into a concrete list of integer file indices. Unlike parse_file_index(), this function enforces strict syntactic rules: it rejects boolean values, discards negative integers, strips inline comment annotations, and evaluates bounded ascending ranges (supporting separators -, .., –, or to). Any string containing embedded prose, negative offsets, or file paths with numbers is rejected and returns an empty list to prevent mapping errors.

    Parameters:

    • idx_value (Any): The raw index object (integer, string, or boolean) returned from an LLM payload.

    Returns:

    • list[int]: A list containing the parsed file indices. Single indices produce a one-element list, valid ascending ranges are expanded into a sequence of consecutive integers, and invalid inputs return an empty list.

    Raises:

    • Does not raise exceptions. Invalid, negative, or malformed values are silently filtered to an empty list.

    Example:

    # Extracted from utils/prompts.py
def parse_file_indices(idx_value) -> list[int]:
    if isinstance(idx_value, bool):
        return []
    if isinstance(idx_value, int):
        return [idx_value] if idx_value >= 0 else []
    text = str(idx_value) if isinstance(idx_value, str) else ""
    single = _INDEX_RE.match(text)
    if single:
        return [int(single.group(1))]
    span = _INDEX_RANGE_RE.match(text)
    if span and int(span.group(1)) <= int(span.group(2)) and int(span.group(2)) - int(span.group(1)) < 10000:
        return list(range(int(span.group(1)), int(span.group(2)) + 1))
    return []

    The function performs explicit type discrimination. Booleans are rejected immediately to prevent Python's boolean subclassing rules from treating True as 1. If passed an integer, non-negative values are wrapped in a list, while negative values yield an empty list. For string representations, the input is evaluated against _INDEX_RE to match single indices with optional trailing comments; if matched, the single integer is returned. If that fails, it evaluates _INDEX_RANGE_RE to identify ranges separated by hyphens, periods, en-dashes, or the word "to". When a valid ascending span with a distance of fewer than 10,000 items is matched, range() generates the full inclusive integer sequence.

    parse_yaml_response()

    Visibility: Public

    Signature: def parse_yaml_response(response):

    Description: Parses structured YAML content from an LLM response string enclosed within triple-backtick Markdown blocks (```yaml ... ```). It guards against truncated responses by checking the response's metadata before attempting extraction and parsing via PyYAML.

    Parameters:

    • response (str | Any): The text response returned by the LLM, or a specialized string wrapper instance (such as TruncatedResponse).

    Returns:

    • Any: The deserialized Python data structure (typically a dictionary or list) resulting from yaml.safe_load().

    Raises:

    • ValueError: Raised if the response carries an active truncated = True attribute, if no valid ```yaml fence is found, or if yaml.safe_load() encounters a syntax error.

    Example:

    # Extracted from utils/prompts.py
def parse_yaml_response(response):
    if getattr(response, "truncated", False):
        raise ValueError("LLM response was truncated before the YAML block completed")
    try:
        yaml_str = response.strip().split("```yaml")[1].split("```")[0].strip()
        return yaml.safe_load(yaml_str)
    except Exception as e:
        raise ValueError(f"Failed to parse YAML: {e}") from e

    The implementation first inspects the truncated attribute on the incoming response object; if truthy, it immediately aborts parsing with a ValueError so calling nodes can trigger retries rather than processing partial data. It then splits the text across delimiters, isolating the content between the first opening ```yaml fence and the next closing ``` marker. The resulting substring is stripped of whitespace and passed to yaml.safe_load(). Any parsing or delimiter extraction failure is caught and re-raised as a descriptive ValueError.

    parse_grouping_response()

    Visibility: Public

    Signature: def parse_grouping_response(response):

    Description: Parses the YAML payload generated by the group_modules.md prompt, which defines documentation sidebar sections, descriptive overviews, and inter-module dependencies. If standard YAML parsing fails, the function falls back to a lenient recovery strategy: it strips illegal backticks enclosing section role values and partitions the payload by its primary keys (sections:, descriptions:, dependencies:), parsing each chunk independently.

    Parameters:

    • response (str | Any): The raw text response returned by the LLM.

    Returns:

    • dict[str, Any]: The parsed dictionary containing the recovered grouping data, guaranteed to include a valid "sections" list.

    Raises:

    • ValueError: Raised if the response was truncated, lacks a ```yaml code fence, or if the primary "sections" list cannot be recovered.

    Example:

    # Extracted from utils/prompts.py
def parse_grouping_response(response):
    try:
        return parse_yaml_response(response)
    except ValueError:
        if getattr(response, "truncated", False) or "```yaml" not in response:
            raise
        yaml_str = response.split("```yaml", 1)[1].split("```", 1)[0]
        yaml_str = re.sub(r"(?m)^(\s*(?:-\s+)?role\s*:\s*)`([^`\n]*)`", r"\1\2", yaml_str)
        parsed = {}
        for chunk in re.split(r"(?m)^(?=(?:sections|descriptions|dependencies)\s*:)", yaml_str):
            try:
                part = yaml.safe_load(chunk)
            except Exception:
                continue
            if isinstance(part, dict):
                parsed.update(part)
        if not isinstance(parsed.get("sections"), list):
            raise ValueError("Failed to parse YAML: no sections list in the grouping reply") from None
        return parsed

    The function first attempts a strict parse via parse_yaml_response(). If that raises a ValueError, it checks whether the failure was caused by response truncation or a completely missing code block, re-raising immediately if so. Otherwise, it extracts the raw YAML substring and applies a multiline regular expression substitution to remove backticks wrapping role: values, which models often generate when quoting roles. It then splits the text using a positive lookahead regex matching the top-level keys (sections:, descriptions:, dependencies:). Each chunk is individually parsed with yaml.safe_load() and merged into a composite dictionary. If the resulting dictionary does not contain a list under "sections", the function raises a terminal ValueError.

    build_verified_facts_block()

    Visibility: Public

    Signature: def build_verified_facts_block(facts: dict | None, doc_paths: dict) -> str:

    Description: Constructs the {verified_facts} prompt injection block for api-reference/draft_chapters.md. It formats ground-truth assertions validated by AST analysis—including verified symbols with normalized signatures, imported module dependencies linked to documentation filenames, configuration settings, and raised or defined errors. If facts are absent or extraction failed (claims is None), it returns an empty string.

    Parameters:

    • facts (dict | None): A dictionary containing verified file facts conforming to the schema created by utils.facts. Expected keys include "claims", "symbols", "depends_on", "config", and "errors".
    • doc_paths (dict[str, str]): A mapping of repository module paths to their target Markdown chapter documentation filenames (e.g., {"utils/output.py": "utils/output.py.md"}).

    Returns:

    • str: A formatted Markdown text block detailing the verified facts, or an empty string if no valid facts exist.

    Raises:

    • Does not raise exceptions. Missing dictionary keys default to empty collections.

    Example:

    # Extracted from utils/prompts.py
def build_verified_facts_block(facts: dict | None, doc_paths: dict) -> str:
    if not facts or facts.get("claims") is None:
        return ""
    symbols = facts.get("symbols") or []
    modules = list(dict.fromkeys(edge["module"] for edge in facts.get("depends_on") or []))
    config = facts.get("config") or []
    errors = list(dict.fromkeys(item["name"] for item in facts.get("errors") or [] if item.get("role", "raised") != "caught"))
    if not (symbols or modules or config or errors):
        return ""
    lines = ["VERIFIED FACTS OF THIS FILE (extracted from it and checked against its source code):"]
    if symbols:
        lines.append(
            "Symbols — document every one; copy each signature as written here (one marked 'start of the declaration' continues in the source: copy it in full from there):"
        )
        for symbol in symbols:
            owner = f"{symbol['parent']}." if symbol.get("parent") else ""
            visibility = f", {symbol['visibility']}" if symbol.get("visibility") else ""
            signature, partial = _fact_signature(symbol)
            marker = " — start of the declaration" if partial else ""
            lines.append(
                f"- {symbol.get('kind') or 'symbol'} {owner}{symbol['name']}{visibility} (line {symbol['line']}): {_code_span(signature)}{marker}"
            )
    if modules:
        lines.append("Project files this file imports — See Also must link each of them:")
        lines.extend(f"- {module} (doc: {doc_paths.get(module, module + '.md')})" for module in modules)
    if config:
        lines.append("Configuration it reads: " + ", ".join(f"{item['name']} ({item.get('kind') or 'config'})" for item in config))
    if errors:
        lines.append("Errors it raises or defines: " + ", ".join(errors))
    return "\n".join(lines) + "\n"

    The function checks that facts is present and that facts.get("claims") is not None. It extracts unique module dependencies from depends_on, configuration items from config, and non-caught error types from errors. If no items exist across all categories, it returns an empty string. Otherwise, it compiles a structured bulleted text block. Each symbol is formatted with its parent ownership, visibility modifier, line coordinate, and signature generated by _fact_signature(). Signatures flagged as partial receive an explicit " — start of the declaration" suffix instructing downstream generation steps to extract full signatures from source.

    build_facts_focus_note()

    Visibility: Public

    Signature: def build_facts_focus_note(lines: list[tuple[int, str]], limit: int = FACTS_FOCUS_LIMIT) -> str:

    Description: Generates the {focus_note} prompt segment for follow-up fact extraction requests using extract_facts.md. When an initial extraction pass overlooks code lines that appear to contain declarations or imports, this function formats those lines up to limit entries, truncating overly long lines to prevent prompt token bloat.

    Parameters:

    • lines (list[tuple[int, str]]): A list of tuples where each element contains the 1-based line number and the raw text of an uncovered source code line.
    • limit (int): The maximum number of uncovered lines to render explicitly. Defaults to FACTS_FOCUS_LIMIT (60).

    Returns:

    • str: The formatted follow-up instruction string including line-indexed excerpts and an optional count of remaining omitted lines.

    Raises:

    • Does not raise exceptions.

    Example:

    # Extracted from utils/prompts.py
def build_facts_focus_note(lines: list[tuple[int, str]], limit: int = FACTS_FOCUS_LIMIT) -> str:
    def shown_line(text: str) -> str:
        text = text.strip()
        return text if len(text) <= _FOCUS_LINE_CHARS else text[: _FOCUS_LINE_CHARS - 3] + "..."

    shown = "\n".join(f"  {number}: {shown_line(text)}" for number, text in lines[:limit])
    more = f"\n  ... and {len(lines) - limit} more such lines" if len(lines) > limit else ""
    return (
        "FOLLOW-UP: a first pass over this file reported nothing for the lines below, which look like declarations "
        "or imports. Report ONLY the facts on these lines, with the same four lists and rules; a line that is not a "
        "declaration a reader looks up (a local variable, a statement) gets nothing.\n"
        f"Lines:\n{shown}{more}\n"
    )

    The function defines an internal helper, shown_line(), which strips leading/trailing whitespace and truncates lines exceeding _FOCUS_LINE_CHARS (200 characters), appending an ellipsis (...). It slices the input lines sequence up to limit, formatting each as " {number}: {text}". If the total line count exceeds limit, an overflow string ("... and N more such lines") is appended. The resulting lines are embedded into a standardized instruction block directing the LLM to inspect only the designated line coordinates.

    parse_facts_response()

    Visibility: Public

    Signature: def parse_facts_response(response, keys: tuple = FACTS_KEYS) -> dict:

    Description: Parses the YAML output of extract_facts.md or extract_manifest.md into a structured dictionary mapping fact categories to item lists. It incorporates a resilient parsing strategy: scalars are kept as raw strings via yaml.BaseLoader, indicator-led values are escaped, and plain-text quotes are converted to block scalars. If full-document parsing fails, it falls back to item-by-item salvage via _salvage_yaml_lists(). Non-dictionary entries and unrecoverable elements are recorded in an "unparsed" count.

    Parameters:

    • response (str | Any): The text response returned by the LLM, or a response wrapper.
    • keys (tuple[str, ...]): The collection of expected top-level section keys. Defaults to FACTS_KEYS (("symbols", "dependencies", "config", "errors")).

    Returns:

    • dict[str, list[dict] | int]: A dictionary containing the parsed list of mapping objects for each key in keys, alongside an "unparsed" integer key indicating the count of lost or invalid entries.

    Raises:

    • ValueError: Raised if the response object has truncated = True, if no opening YAML code block is found, or if none of the target keys can be parsed.

    Phase 1: Truncation Check and Fence Extraction

    # Extracted from utils/prompts.py
    if getattr(response, "truncated", False):
        raise ValueError("LLM response was truncated before the YAML block completed")
    match = _FACTS_BLOCK_RE.search(response) or _FACTS_OPEN_RE.search(response)
    if not match:
        raise ValueError("Failed to parse YAML: no ```yaml block in the facts reply")
    indent = match.group(1)
    yaml_str = _quote_indicator_values("\n".join(line.removeprefix(indent) for line in match.group(2).split("\n")))

    The initial phase validates that the generation was not truncated by inspecting the truncated attribute. It then searches for a Markdown code fence using _FACTS_BLOCK_RE (closed block with matching fence indentation) or _FACTS_OPEN_RE (unclosed block). If neither pattern matches, a ValueError is raised. The common indentation captured from the opening fence is stripped from every line of the body, and _quote_indicator_values() sanitizes values starting with YAML indicator tokens.

    Phase 2: Tiered Parsing and Salvage Execution

    # Extracted from utils/prompts.py
    unparsed = 0
    try:
        data = _load_strings(yaml_str)
    except Exception:
        try:
            data = _load_strings(_block_quotes(yaml_str))
        except Exception:
            data, unparsed = _salvage_yaml_lists(_block_quotes(yaml_str), keys)
    if not isinstance(data, dict) or not any(key in data for key in keys):
        raise ValueError("Failed to parse YAML: no fact lists in the facts reply")

    The parsing phase attempts deserialization across three progressive tiers. First, it tries parsing the sanitized string directly with _load_strings(). If a syntax error occurs, it rewrites plain scalar signatures and evidence lines into YAML block scalars (|-) via _block_quotes() and retries _load_strings(). If that also fails, it invokes _salvage_yaml_lists(), which decomposes the text by section and recovers list items individually while counting dropped elements. If the recovered data is not a dictionary or contains none of the requested keys, execution terminates with a ValueError.

    Phase 3: List Filtering and Unparsed Fact Accounting

    # Extracted from utils/prompts.py
    result = {}
    for key in keys:
        items = data.get(key)
        items = items if isinstance(items, list) else []
        result[key] = [item for item in items if isinstance(item, dict)]
        unparsed += len(items) - len(result[key])
    result["unparsed"] = unparsed
    return result

    In the final phase, each target key is normalized into a list of dictionaries. If a key is missing or set to None, it defaults to an empty list. Any item within a list that is not a dictionary mapping (for example, raw strings or nested arrays generated by formatting errors) is excluded, and its omission increments unparsed. The resulting mapping containing all filtered lists and the final unparsed count is returned.

    Visibility: Private

    Signature: def _fact_signature(symbol: dict) -> tuple[str, bool]:

    Description: Formats and normalizes a verified symbol signature for prompt injection. It strips leading decorators or language-specific attributes, collapses multiline whitespace into a single line, removes string literals to check bracket balance, and detects truncation.

    Parameters:

    • symbol (dict): The symbol dictionary extracted by static analysis, containing keys like "signature" and "truncated".

    Returns:

    • tuple[str, bool]: A 2-tuple containing the sanitized signature string and a boolean flag indicating whether the signature is incomplete (True) or complete (False).

    # Extracted from utils/prompts.py
def _fact_signature(symbol: dict) -> tuple[str, bool]:
    lines = str(symbol.get("signature", "")).split("\n")
    while len(lines) > 1 and re.match(r"\s*(?:@|#\[|\[[A-Z])", lines[0]):  # @property, #[inline], [Obsolete]
        lines = lines[1:]
    text = " ".join(" ".join(lines).split())
    code = re.sub(r"\"(?:\\.|[^\"\\])*\"|'(?:\\.|[^'\\])*'", "", text)
    partial = bool(symbol.get("truncated")) or code.count("(") > code.count(")") or code.count("[") > code.count("]")
    if len(text) > _FACT_SIGNATURE_CHARS:
        text, partial = text[:_FACT_SIGNATURE_CHARS].rstrip(), True
    return (text + " …" if partial else text), partial

    The function splits the signature on newlines and drops leading decorator and attribute lines matching patterns like @property, #[inline], or [Obsolete]. It collapses all remaining whitespace runs into single spaces. To test whether the signature was cut short, it strips string literals and checks for unbalanced opening parentheses or square brackets. If the signature is marked truncated, has unbalanced brackets, or exceeds _FACT_SIGNATURE_CHARS (200 characters), partial is set to True, and the signature text is truncated with a trailing " …".

For each identified chunk, it extracts the matching key name. It first attempts to parse the entire chunk with _load_strings(). If successful and the result is a dictionary, the chunk is merged into parsed and the loop advances to the next section.

    Phase 2: Granular Item-by-Item Salvage

        body = chunk[head.end() :]
        first = re.search(r"(?m)^([ \t]*)- ", body)
        if not first:

    If the entire section chunk fails to parse, the helper strips the header line and locates the indentation of the first bullet list item (-). Using that indentation level, it splits the section body into individual item fragments. For each fragment, it removes the common bullet indentation and attempts to parse it via _load_strings(). If an item fails to parse or resolves to something other than a single-item list containing a dictionary, the lost counter increments. Valid dictionary items are appended to items, and the section key is updated with the recovered items before returning the (parsed, lost) tuple.

    Error Handling

    utils/prompts.py enforces explicit error-handling strategies to balance data integrity with fault tolerance during LLM inference:

    • Truncation Detection: Functions that parse LLM output (parse_yaml_response(), parse_grouping_response(), and parse_facts_response()) inspect incoming response objects for an active truncated = True attribute (typically set on TruncatedResponse instances from llm_common). When detected, they immediately raise a ValueError rather than parsing incomplete YAML that might silently drop symbols, dependencies, or chapters.
    • Progressive Parsing Fallback: When structured YAML syntax errors occur, parse_facts_response() applies a multi-tiered recovery process rather than failing immediately. It runs regex transformations to quote unquoted indicators, converts plain scalar quotes into block scalars, and partitions corrupted sections down to individual list items via _salvage_yaml_lists().
    • Unparsed Fact Accounting: Dropped, unparseable, or non-mapping items encountered during YAML salvage do not abort execution; instead, they increment an explicit "unparsed" integer counter returned to the caller. This allows downstream quality-assurance systems (such as chapter_check.py) to account for claimed-but-unverified assertions.
    • Lenient Recovery with Fail-Fast Validation: In parse_grouping_response(), syntax recovery is attempted by unwrapping backtick-enclosed roles and splitting the input across known top-level keys. However, if the recovered payload still lacks a valid "sections" list, it raises a ValueError to ensure downstream site generators do not receive invalid navigation structures.
