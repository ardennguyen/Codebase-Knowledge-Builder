    i18n.py

    Source: utils/i18n.py

    Technical Overview

    While utils/files.py structures and formats local source code repositories into serialized hierarchical representations for pipeline consumption, utils/i18n.py manages runtime UI localization and translation automation. The module provides dynamic internationalization facilities that detect untranslated UI and logging strings across execution phases, query large language models for bulk translation, and mutate the centralized localization ledger (strings.csv) in place.

    Architecturally, this module was extracted from utils/output.py to decouple a problematic circular dependency chain: output.py $\rightarrow$ utils/call_llm.py $\rightarrow$ utils/token_utils.py $\rightarrow$ output.py. By isolating the translation workflow within utils/i18n.py, the system ensures that inference logic is only invoked on demand when missing string definitions are identified. The rest of the reporting infrastructure can emit messages without requiring premature loading of LLM client libraries or inference configurations.

    The operational pipeline reads a UTF-8 with BOM (utf-8-sig) formatted CSV file, inspects header columns for target language coverage, compiles untranslated entries into a structured JSON payload, formats a prompt from an external Markdown template, and invokes the inference provider via utils/call_llm.py. Upon obtaining a valid model response, it uses defensive regular expressions to parse out the translated JSON dictionary, updates the CSV schema if a new language column is introduced, and writes the mutated records back to disk with BOM encoding intact.

    Public API

    auto_translate()

    Visibility: Public Signature: def auto_translate(lang_col: str, language: str, csv_path: str, use_cache: bool, thinking_level: str) -> bool:

    Description: Evaluates the localization catalog for absent translations corresponding to the specified language column, queries an LLM to generate missing phrases, and writes the updated keys back to disk. If the target language is already set to English, if the CSV file path is invalid, or if all keys possess non-empty translations, the function terminates early without initiating network traffic.

    Phase 1: Preconditions and CSV Schema Verification

        from utils.output import emit_raw

    if lang_col == "english":
        return False

    if not csv_path or not os.path.exists(csv_path):
        return False

    # Collect strings that have no translation in the target language column
    missing = {}
    is_new_column = False
    with open(csv_path, encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        fieldnames = list(reader.fieldnames)
        is_new_column = lang_col not in fieldnames

    The function performs guard checks against default execution states. Because English acts as the foundational source language for all UI messages in the application, passing lang_col == "english" causes an immediate exit with False. It verifies the physical existence of the file specified by csv_path. When reading strings.csv, it utilizes the utf-8-sig codec to properly handle and strip any leading Byte Order Mark (BOM) signature (\xef\xbb\xbf). The reader parses the file header to extract fieldnames and determines whether the requested language constitutes a completely new column that must eventually be appended to the file.

    Phase 2: Identification of Untranslated String Keys

            for row in reader:
            key = row.get("STRING_KEY", "").strip()
            if not key or key.startswith("#"):
                continue
            # Check if the language column exists and has a value
            lang_text = row.get(lang_col, "").strip() if lang_col in fieldnames else ""
            if lang_text:
                continue  # Already translated

            english_text = row.get("english", "").strip()
            if english_text:
                missing[key] = english_text

    if not missing:
        return False

    # Report what we found
    if is_new_column:
        emit_raw("PROGRESS", f"[i18n] New language '{language}' — adding column to strings.csv")
    emit_raw("PROGRESS", f"[i18n] {len(missing)} strings need translation to {language}")

    During the iteration over CSV rows, rows representing comment markers (keys beginning with #) or blank keys are ignored. If the column header already exists, the function checks whether a non-empty string is present for the target key. Keys missing a localized counterpart are retained only if an English baseline text exists in the english column. If the resulting missing dictionary contains zero entries, the function returns False. When missing keys are present, the function uses lazy-imported emit_raw() from utils/output.py to log telemetry progress indicating the language display name and total number of untranslated phrases.

    Phase 3: Translation Prompt Construction and Model Inference

        # Batch translate via LLM
    try:
        from utils.call_llm import call_llm

        entries_json = json.dumps(missing, ensure_ascii=False, indent=2)

        # Load prompt template from prompts/common/translate_strings.md
        prompt_path = os.path.join(
            os.path.dirname(os.path.dirname(os.path.abspath(__file__))),
            "prompts",
            "common",
            "translate_strings.md",
        )
        with open(prompt_path, encoding="utf-8") as pf:
            prompt_template = pf.read()
        prompt = prompt_template.format(language=language, entries=entries_json)

        emit_raw("PROGRESS", f"[i18n] Calling LLM to translate {len(missing)} strings...")
        response = call_llm(prompt, use_cache=use_cache, thinking_level=thinking_level)

    The translation workflow constructs a batch payload by serializing the missing dictionary into a formatted JSON string using ensure_ascii=False to preserve Unicode characters. It dynamically resolves the absolute path to the prompt template at prompts/common/translate_strings.md relative to the module root. The template is loaded and formatted with the target language and the JSON-serialized string entries. The module then invokes call_llm() from utils/call_llm.py, forwarding the caching flag use_cache and the specified thinking_level to regulate reasoning effort and token allocation.

    Phase 4: JSON Extraction and CSV Persistence

            # Extract JSON from response
        json_match = re.search(r"\{[^{}]*(?:\{[^{}]*\}[^{}]*)*\}", response, re.DOTALL)
        if json_match:
            translations = json.loads(json_match.group())
            translated_count = len(translations)

            # Write translations back into strings.csv
            _write_translations_to_csv(csv_path, lang_col, fieldnames, translations)
            emit_raw("SUCCESS", f"[i18n] Translated {translated_count}/{len(missing)} strings — saved to strings.csv")
            return True
        emit_raw("WARNING", "[i18n] LLM response did not contain valid JSON — falling back to English")

    except Exception as e:
        emit_raw("WARNING", f"[i18n] Translation failed: {e} — falling back to English")

    return False

    Because model completions may contain introductory or concluding conversational prose despite system instructions, the response is processed with a regular expression designed to locate the outermost JSON structure: r"\{[^{}]*(?:\{[^{}]*\}[^{}]*)*\}". Once extracted, the JSON fragment is parsed into a Python dictionary. If valid, the translations are passed to _write_translations_to_csv() for persistence, a success notice is dispatched, and the function returns True to signal that caller caches should reload. If JSON extraction fails, or if an unhandled network or decoding exception occurs within the try block, an alert is logged via emit_raw("WARNING", ...) and the function returns False to maintain runtime continuity via fallback English strings.

    Parameters: * lang_col (str): Lowercase target language column name matching CSV headers (e.g., "vietnamese", "japanese"). * language (str): Capitalized human-readable language name used inside the prompt template (e.g., "Vietnamese", "Japanese"). * csv_path (str): Absolute filesystem path pointing to the centralized strings.csv file. * use_cache (bool): Flag determining whether LLM prompt-response memoization is active via llm_cache.json. * thinking_level (str): Provider reasoning intensity level passed down to call_llm() ("low", "medium", or "high").

    Returns: * bool: True if new translations were received, parsed, and successfully persisted to the CSV file (indicating that the caller should refresh in-memory string maps); False if no translations were needed or if the operation failed.

    Raises: * This function does not allow exceptions to bubble up. All standard and I/O exceptions during prompt loading, network inference, JSON decoding, or file updates are caught by a blanket except Exception handler, resulting in a diagnostic log and a False return value.

    Internal Helpers

    _write_translations_to_csv()

    Visibility: Private Signature: def _write_translations_to_csv(csv_path: str, lang_col: str, fieldnames: list[str], translations: dict[str, str]) -> None:

    Description: Persists updated translation dictionaries to the localization CSV file. It reads existing records, modifies or adds the designated language column, assigns newly translated text to matching string keys, and writes the entire dataset back out using UTF-8-SIG encoding.

    Phase 1: Row Transformation and Column Schema Extension

        rows = []

    with open(csv_path, encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        fieldnames = list(reader.fieldnames)
        # Add language column if it doesn't exist
        if lang_col not in fieldnames:
            fieldnames.append(lang_col)
        for row in reader:
            key = row.get("STRING_KEY", "").strip()
            if key in translations:
                row[lang_col] = translations[key]
            rows.append(row)

    The function reads the existing CSV records into memory to prevent partial writes in case of read errors. It inspects fieldnames and dynamically appends lang_col if it represents a newly registered language. As it iterates through each row, it matches STRING_KEY against the keys in the translations dictionary. If a match is found, the value for row[lang_col] is assigned the translated string while all other columns remain untouched.

    Phase 2: UTF-8-SIG File Serialization

        # Write with BOM so Excel opens as UTF-8 without extra import steps
    with open(csv_path, "w", encoding="utf-8-sig", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=fieldnames)
        writer.writeheader()
        writer.writerows(rows)

    The aggregated rows and expanded fieldnames list are written back to csv_path. The file is explicitly opened with encoding="utf-8-sig" and newline="" to ensure consistent newline handling across operating systems. The use of the UTF-8 Byte Order Mark (\xef\xbb\xbf) guarantees that external spreadsheet editors like Microsoft Excel automatically identify the file as UTF-8 without corrupting multibyte characters (such as Vietnamese diacritics, Cyrillic, or CJK ideographs).
