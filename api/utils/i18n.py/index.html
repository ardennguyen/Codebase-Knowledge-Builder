    i18n.py

    Source: utils/i18n.py

    Technical Overview

    utils/i18n.py provides the internationalization (i18n) and automated translation subsystem for user interface strings within the repository. Originally factored out of utils/output.py, this module breaks a circular dependency cycle (output.py → call_llm.py → token_utils.py → output.py). By isolating the inference dependencies required for string localization into a dedicated component, output.py can delegate translation jobs to i18n.py without coupling itself directly to LLM orchestration infrastructure.

    The module inspects the localized string registry (strings.csv), identifies entries missing translations for a requested target language, and compiles missing key-value pairs into a structured translation payload. It dynamically loads the translation prompt template, logs token estimation telemetry, and dispatches an LLM inference call through utils.call_llm.call_llm. If the target language column does not yet exist in strings.csv, the module dynamically provisions it.

    Once the language model returns translated values, the module extracts the JSON response via regular expressions, parses the translated keys, and persists them back to disk using UTF-8 with Byte Order Mark (utf-8-sig) encoding. This encoding preserves special characters across varying operating systems and ensures compatibility with spreadsheet applications such as Microsoft Excel. If translation fails due to network issues, malformed LLM outputs, or unparseable JSON, the module emits a diagnostic warning and falls back to default English strings without halting application execution.

    Public API

    auto_translate()

    Visibility: Public

    Signature: def auto_translate(lang_col, language, csv_path, use_cache, thinking_level):

    Description: Discovers missing translation keys for a given language column in strings.csv, executes an LLM inference pass to translate them, and persists the updated records back to the CSV file. If translations are written, it signals callers to reload localized caches.

    Parameters:

    • lang_col (str): Lowercase language column name in the CSV file (e.g., "vietnamese").
    • language (str): Capitalized human-readable language display name (e.g., "Vietnamese").
    • csv_path (str): Absolute file path to strings.csv.
    • use_cache (bool): Flag indicating whether LLM caching should be used for the call.
    • thinking_level (str | int): Model reasoning effort or thinking level passed to the LLM backend.

    Returns:

    • bool: True if new translations were successfully written to disk (signaling the caller to reload its string cache), or False if no translations were needed or if an error occurred.

    Raises:

    • None directly. All file I/O, token estimation, network inference, and parsing exceptions are caught internally and handled with diagnostic warnings.

    Phase 1: Input Validation and Translation Inspection

        from utils.output import emit_raw

    if lang_col == "english":
        return False

    if not csv_path or not os.path.exists(csv_path):
        return False

    # Collect strings that have no translation in the target language column
    missing = {}
    is_new_column = False
    with open(csv_path, encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        fieldnames = list(reader.fieldnames)
        is_new_column = lang_col not in fieldnames
        for row in reader:
            key = row.get("STRING_KEY", "").strip()
            if not key or key.startswith("#"):
                continue
            # Check if the language column exists and has a value
            lang_text = row.get(lang_col, "").strip() if lang_col in fieldnames else ""
            if lang_text:
                continue  # Already translated

            english_text = row.get("english", "").strip()
            if english_text:
                missing[key] = english_text

    if not missing:
        return False

    This initial phase validates preconditions and inspects the persistent storage file. If the requested language is "english", or if csv_path is invalid or missing, the function terminates early with False. The file is opened using utf-8-sig encoding to handle potential byte order marks cleanly. As rows are parsed, comments prefixed with # and empty keys are bypassed. If the target column does not yet exist or contains an empty string for a given key, the corresponding English string is placed into the missing dictionary. If no untranslated keys are identified, execution exits without incurring network overhead.

    Phase 2: Prompt Formatting and Token Telemetry

        # Report what we found
    if is_new_column:
        emit_raw("PROGRESS", f"[i18n] New language '{language}' — adding column to strings.csv")
    emit_raw("PROGRESS", f"[i18n] {len(missing)} strings need translation to {language}")

    # Batch translate via LLM
    try:
        from utils.call_llm import call_llm

        entries_json = json.dumps(missing, ensure_ascii=False, indent=2)

        # Load prompt template from prompts/common/translate_strings.md
        prompt_path = os.path.join(
            os.path.dirname(os.path.dirname(os.path.abspath(__file__))),
            "prompts",
            "common",
            "translate_strings.md",
        )
        with open(prompt_path, encoding="utf-8") as pf:
            prompt_template = pf.read()
        prompt = prompt_template.format(language=language, entries=entries_json)

        emit_raw("PROGRESS", f"[i18n] Calling LLM to translate {len(missing)} strings...")
        from utils.token_utils import log_token_estimation, resolve_max_tokens

        try:
            context_tokens = resolve_max_tokens({})
        except Exception:
            context_tokens = 0
        log_token_estimation("TranslateStrings", prompt, context_tokens)

    In the second phase, telemetry notices inform the user of newly introduced language columns and the count of strings requiring translation. The missing dictionary is serialized to formatted JSON without escaping Unicode characters (ensure_ascii=False). The system loads the prompt template from prompts/common/translate_strings.md relative to the module root and interpolates the language name and serialized entries. Before dispatching the request, token usage is estimated via log_token_estimation, safely resolving maximum tokens through resolve_max_tokens with an exception guard that falls back to 0.

    Phase 3: LLM Dispatch, Parsing, and Persistence

            response = call_llm(prompt, use_cache=use_cache, thinking_level=thinking_level, step="translate_strings")

        # Extract JSON from response
        json_match = re.search(r"\{[^{}]*(?:\{[^{}]*\}[^{}]*)*\}", response, re.DOTALL)
        if json_match:
            translations = json.loads(json_match.group())
            translated_count = len(translations)

            # Write translations back into strings.csv
            _write_translations_to_csv(csv_path, lang_col, fieldnames, translations)
            emit_raw("SUCCESS", f"[i18n] Translated {translated_count}/{len(missing)} strings — saved to strings.csv")
            return True
        emit_raw("WARNING", "[i18n] LLM response did not contain valid JSON — falling back to English")

    except Exception as e:
        emit_raw("WARNING", f"[i18n] Translation failed: {e} — falling back to English")

    return False

    The final phase invokes call_llm with the step identifier "translate_strings". To isolate the translated dictionary from potential conversational preamble or markdown code blocks returned by the model, the response is filtered using a balanced regular expression matching nested JSON braces. Once parsed by json.loads, the dictionary is dispatched to _write_translations_to_csv for atomic in-place persistence. If the model output fails regex matching or raises an unhandled exception, a warning is emitted via emit_raw, and the function returns False, allowing the application to continue using default English text.

    Internal Helpers

    _write_translations_to_csv()

    Visibility: Private

    Signature: def _write_translations_to_csv(csv_path, lang_col, fieldnames, translations):

    Description: Updates existing rows and introduces new language columns into strings.csv, persisting translated key-value pairs back to disk for subsequent runs.

    Parameters:

    • csv_path (str): Absolute file system path to the target strings.csv file.
    • lang_col (str): Column header name corresponding to the target language.
    • fieldnames (list[str]): List of current CSV header fields from the original read pass.
    • translations (dict[str, str]): Key-value mapping of string identifiers to their translated text.

    Returns:

    • None: Mutates the file on disk directly.

    Raises:

    • OSError: If the target path cannot be read or written due to file system permission issues.
    def _write_translations_to_csv(csv_path, lang_col, fieldnames, translations):
    """Write LLM translations back into strings.csv, persisting them for future runs.

    If the target language column doesn't exist, it is added to the CSV.
    """
    rows = []

    with open(csv_path, encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        fieldnames = list(reader.fieldnames)
        # Add language column if it doesn't exist
        if lang_col not in fieldnames:
            fieldnames.append(lang_col)
        for row in reader:
            key = row.get("STRING_KEY", "").strip()
            if key in translations:
                row[lang_col] = translations[key]
            rows.append(row)

    # Write with BOM so Excel opens as UTF-8 without extra import steps
    with open(csv_path, "w", encoding="utf-8-sig", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=fieldnames)
        writer.writeheader()
        writer.writerows(rows)

    The function performs a two-pass update against the persistent storage file. First, it re-reads strings.csv with utf-8-sig encoding, ensuring fieldnames contains lang_col by appending it to the list if previously absent. For each row parsed by csv.DictReader, if STRING_KEY is present in the translations dictionary, the row dictionary is updated with the translated text. In the second pass, the updated row objects are written out using csv.DictWriter with encoding="utf-8-sig" and newline="", ensuring that spreadsheet applications render multi-byte Unicode strings properly without corrupting line endings.

    Example:

    # Internal invocation inside auto_translate():
_write_translations_to_csv(
    csv_path="/path/to/strings.csv",
    lang_col="vietnamese",
    fieldnames=["STRING_KEY", "english"],
    translations={"PROMPT_START": "Bắt đầu tiến trình", "PROMPT_END": "Hoàn tất"},
)

    Data Structures

    Missing Strings Collection

    An in-memory dictionary created during the initial scanning phase that aggregates strings requiring localization.

    Field Type Description
    key str The unique uppercase identifier for the UI string (e.g., "STEP_EXTRACT_FACTS").
    value str The canonical English text associated with the key, used as the translation source. 
    {
  "CONSOLE_RUNNING": "Running documentation workflow...",
  "PROGRESS_PARSING": "Parsing source repository files"
}

    Parsed Translations Mapping

    A dictionary extracted from the LLM JSON response payload representing the model's translated outputs.

    Field Type Description
    key str The matching uppercase identifier for the UI string.
    value str The localized text translated into the target language. 
    {
  "CONSOLE_RUNNING": "Đang chạy quy trình tài liệu hóa...",
  "PROGRESS_PARSING": "Đang phân tích các tệp mã nguồn"
}

    strings.csv File Record Structure

    The tabular format enforced by csv.DictReader and csv.DictWriter when reading and persisting localization records.

    Field Type Description
    STRING_KEY str Primary lookup key identifying the UI string, or # comment lines.
    english str The reference English translation string.
    <lang_col> str Dynamic column header (e.g., vietnamese, japanese) containing localized text.

    Error Handling

    utils/i18n.py implements defensive boundaries to prevent localization errors from causing workflow crashes:

    • Missing File and Precondition Guards: auto_translate verifies file existence and validates that lang_col is not "english". If these checks fail, it exits immediately with False.
    • Token Estimation Resilience: Resolving token bounds can fail in environments lacking configuration attributes. The call to resolve_max_tokens({}) is wrapped in a dedicated try/except block, defaulting context_tokens to 0 on failure so logging can continue.
    • Non-JSON LLM Output Interception: Large language models occasionally prepend markdown formatting or explanations. The module uses a regular expression (re.search(r"\{[^{}]*(?:\{[^{}]*\}[^{}]*)*\}", response, re.DOTALL)) to isolate JSON blocks. If no JSON structure is detected, it logs a warning via emit_raw("WARNING", ...) and returns False.
    • Global Translation Safety Net: The entire inference and persistence sequence is encapsulated in a generic except Exception as e: block. Any transport errors, file lock contentions, or deserialization failures emit a descriptive warning and gracefully degrade execution back to English.
