    utils.prompts

    Source: utils/prompts.py

    The utils.prompts module provides reusable inline prompt builders, documentation configuration generators, and navigation tree processors for internal Large Language Model (LLM) operations and site artifact generation across the Codebase-Knowledge-Builder architecture. Unlike user-facing document templates located in mode-specific template directories (e.g., prompts/{mode}/), the builders in this module are programmatic, deterministic string formatters and structural parsers used during intermediate graph node executions.

    Key capabilities provided by this module include: - Generating classification prompts that instruct LLMs to identify pure code files from raw file listings while excluding non-code assets. - Constructing structured chapter summary prompts that capture 4-dimensional technical briefs (scope, key elements, patterns, dependencies) to provide context propagation across sequential chapter generation nodes. - Generating MkDocs configuration files (mkdocs.yml) configured with the Material for MkDocs theme, syntax highlighting, zoom extensions, and custom Mermaid rendering handlers. - Providing CSS style overrides to ensure proper color rendering and contrast for Mermaid diagrams within Material themes. - Traversing recursive hierarchy trees to compile formatted MkDocs navigation YAML trees and extracting module lists.

    Architecture & Integration Flow

    The prompt and configuration generators in utils.prompts support distinct phases of the documentation generation lifecycle: file filtering, iterative chapter contextualization, and final MkDocs static site generation.

    Module-Level Functions

    build_code_file_filter_prompt()

    Visibility: Public
    Signature: def build_code_file_filter_prompt(project_name: str, file_listing: str) -> str:

    Description:
    Constructs an LLM prompt string designed for DeterministicFileMapper to filter out non-code assets from an ingested repository index. The prompt explicitly details which file classes constitute code modules (APIs, core business logic, functions, classes) and commands the LLM to discard UI templates (.xaml, .storyboard, .html), configurations (.xml, .json, .ini), build system artifacts (.csproj, .sln), and static documentation. The returned instruction enforces a strict YAML list containing the zero-based indices of matching files.

    Parameters: * project_name (str): The name of the project repository being analyzed. * file_listing (str): An indexed, line-separated string listing of repository files.

    Returns: * str: A formatted prompt instructing the LLM to output a YAML list of valid code indices.

    Raises: * This function does not raise exceptions internally.

    Example: 

    def build_code_file_filter_prompt(project_name: str, file_listing: str) -> str:
    return (
        f"For the project `{project_name}`, here is the list of all files in the codebase:\n\n"
        f"{file_listing}\n\n"
        f"Your task is to identify WHICH of these files are ACTUAL CODE files that contain "
        f"APIs, functions, classes, or core business logic.\n"
        f"EXCLUDE: UI layouts (like .xaml, .storyboard, .html), configuration files "
        f"(like .xml, .json, .manifest, .ini), static assets, build scripts "
        f"(like .csproj, .sln), and documentation.\n\n"
        f"Return ONLY a YAML list of the file indices that should be documented as code modules.\n\n"
        f"```yaml\n- 0\n- 1\n- 3\n```"
    )

    The function performs template injection using Python f-strings to format the project name and the catalog of crawled files. Downstream nodes parse the LLM's raw markdown response to extract the YAML list of numeric indices, mapping them back to physical file paths for downstream analysis.

    build_chapter_summary_prompt()

    Visibility: Public
    Signature: def build_chapter_summary_prompt(chapter_num: int, abstraction_name: str, chapter_content: str, language: str = "english") -> str:

    Description:
    Builds the prompt used to summarize a completed documentation chapter. The generated summary serves as historical context for subsequent chapter generation nodes in multi-chapter pipelines, preventing hallucinations and ensuring continuity across modules. The prompt enforces a structured four-dimension technical summary format (Component Scope, Key Technical Elements, Implementation Patterns & Architecture, System Integration & Dependencies), requiring 3-5 concise technical sentences per dimension. If a non-English language is configured, an explicit target language instruction is prepended.

    Parameters: * chapter_num (int): The sequence number of the completed chapter. * abstraction_name (str): The technical abstraction or title of the chapter. * chapter_content (str): The full Markdown or text content of the generated chapter. * language (str, optional): The target language for the summary output. Defaults to "english".

    Returns: * str: The formatted prompt directing the LLM to summarize the chapter across four technical dimensions.

    Raises: * This function does not raise exceptions internally.

    Example: 

    def build_chapter_summary_prompt(chapter_num: int, abstraction_name: str, chapter_content: str, language: str = "english") -> str:
    lang_instruction = f"Write the entire summary in {language.capitalize()}. " if language.lower() != "english" else ""
    return (
        f"{lang_instruction}"
        f"Summarize the following documentation chapter as a structured technical brief. "
        f"For EACH of the 4 points below, write 3-5 concise technical sentences:\n\n"
        f"(1) **Component Scope & Responsibility**: What is the main technical domain this "
        f"chapter covers? What problems does it solve and what role does it play in the system?\n\n"
        f"(2) **Key Technical Elements**: What are the specific classes, services, functions, "
        f"data models, or protocols discussed? Name them and describe their concrete roles.\n\n"
        f"(3) **Implementation Patterns & Architecture**: What design patterns, communication "
        f"protocols, data flow strategies, error handling mechanisms, or security measures "
        f"are covered? How are they implemented?\n\n"
        f"(4) **System Integration & Dependencies**: How does this component interface with "
        f"other parts of the system? What does it consume from or provide to other components? "
        f"What are the key integration points?\n\n"
        f"---\n"
        f"Chapter {chapter_num}: {abstraction_name}\n"
        f"{chapter_content}"
    )

    The prompt structure standardizes intermediate technical representations across arbitrarily long documentation pipelines. By enforcing four concrete dimensions, downstream nodes receive consistent details regarding dependencies and data structures introduced in prior chapters.

    build_mkdocs_config()

    Visibility: Public
    Signature: def build_mkdocs_config(site_name: str, nav_yaml: str) -> str:

    Description:
    Generates a complete mkdocs.yml configuration string optimized for documentation produced by Codebase-Knowledge-Builder. The configuration configures the Material for MkDocs theme, light/dark mode palette switching, search, interactive pan-zoom for diagrams (panzoom), code copy buttons, Python Markdown extensions (pymdownx.highlight, pymdownx.inlinehilite), and custom Mermaid diagram fences via pymdownx.superfences. It injects the custom stylesheet reference stylesheets/mermaid-vibrant.css and combines the generated navigation snippet with a default Home index link.

    Parameters: * site_name (str): The title of the documentation website. * nav_yaml (str): The YAML formatted navigation hierarchy string (starting with or without a nav: header).

    Returns: * str: The complete contents of a valid mkdocs.yml file.

    Raises: * This function does not raise exceptions internally.

    Example: 

    def build_mkdocs_config(site_name: str, nav_yaml: str) -> str:
    # Extract nav items from nav_snippet (strip the "nav:" header line)
    nav_lines = nav_yaml.split("\n")
    nav_body = "\n".join(nav_lines[1:]) if nav_lines else ""

    return (
        f"site_name: '{site_name}'\n"
        f"theme:\n"
        f"  name: material\n"
        f"  features:\n"
        f"    - content.code.copy\n"
        f"    - navigation.indexes\n"
        f"  palette:\n"
        f"    - scheme: default\n"
        f"      toggle:\n"
        f"        icon: material/brightness-7\n"
        f"        name: Switch to dark mode\n"
        f"    - scheme: slate\n"
        f"      toggle:\n"
        f"        icon: material/brightness-4\n"
        f"        name: Switch to light mode\n"
        f"plugins:\n"
        f"  - search\n"
        f"  - panzoom:\n"
        f"      include_selectors:\n"
        f"        - '.mermaid'\n"
        f"markdown_extensions:\n"
        f"  - pymdownx.highlight:\n"
        f"      anchor_linenums: true\n"
        f"      use_pygments: true\n"
        f"  - pymdownx.superfences:\n"
        f"      custom_fences:\n"
        f"        - name: mermaid\n"
        f"          class: mermaid\n"
        f"          format: !!python/name:pymdownx.superfences.fence_code_format\n"
        f"  - pymdownx.inlinehilite\n"
        f"extra_css:\n"
        f"  - stylesheets/mermaid-vibrant.css\n"
        f"nav:\n"
        f"  - Home: index.md\n"
        f"{nav_body}\n"
    )

    The function normalizes the input nav_yaml snippet by splitting lines and stripping the leading nav: declaration, ensuring no syntax errors occur when embedding the navigation body underneath the default - Home: index.md root item.

    build_mermaid_css()

    Visibility: Public
    Signature: def build_mermaid_css() -> str:

    Description:
    Returns a CSS stylesheet string that overrides default Material for MkDocs Mermaid styling. Material for MkDocs overrides internal Mermaid %%{init}%% directives, which can cause SVG diagrams to render with muted, low-contrast palettes. This CSS payload restores high-contrast, vibrant visual styling: - Warm yellow backgrounds (#ffffde) with mustard borders (#aaaa33) for subgraphs/clusters. - Light lavender node fills (#ECECFF) with purple borders (#9370DB). - Explicit dark text colors (#333) across labels, edge text, and solid edge strokes.

    Parameters: * None.

    Returns: * str: CSS styling definitions targeted at .mermaid container selectors.

    Raises: * This function does not raise exceptions internally.

    Example: 

    def build_mermaid_css() -> str:
    return """\
/* Vibrant Mermaid diagram theme — overrides Material's muted colors */
/* Matches Mermaid's built-in 'default' theme (yellow subgraphs, lavender nodes) */

/* Subgraph/cluster backgrounds — warm yellow */
.mermaid .cluster rect {
  fill: #ffffde !important;
  stroke: #aaaa33 !important;
  stroke-width: 1px !important;
}

/* Cluster/subgraph title text */
.mermaid .cluster text {
  fill: #333 !important;
}

/* Node fills — light lavender */
.mermaid .node rect,
.mermaid .node polygon,
.mermaid .node circle {
  fill: #ECECFF !important;
  stroke: #9370DB !important;
  stroke-width: 1px !important;
}

/* Node text */
.mermaid .nodeLabel {
  color: #333 !important;
}

/* Edge label backgrounds */
.mermaid .edgeLabel {
  background-color: #e8e8e8 !important;
  color: #333 !important;
}

/* Edge lines */
.mermaid .edge-pattern-solid {
  stroke: #333 !important;
}
"""

    The returned CSS utilizes !important declarations on all rules to override specificity from the compiled Material theme CSS bundle, ensuring uniform diagram presentation across browser environments.

    build_grouped_nav()

    Visibility: Public
    Signature: def build_grouped_nav(sections: list, chapter_files: list, indent: int = 4) -> list[str]:

    Description:
    Recursively constructs a list of indented YAML lines representing a nested MkDocs navigation hierarchy. The function iterates through a section tree (typically parsed from an LLM grouping response). For each section, it appends the section title, recurses into any nested children sections with increased indentation, and matches leaf modules against the provided chapter_files metadata list. When a match is found, it adds a leaf entry linking the short module display name to its output file path (e.g., api/{filename}).

    Parameters: * sections (list): A list of dictionaries representing section groups. Each dictionary may contain "name" (str), "children" (list), and "modules" (list[str]). * chapter_files (list): A list of dictionaries mapping generated chapters, where each dictionary contains "module_name" (str) and "filename" (str). * indent (int, optional): The base space indentation level for the current depth. Defaults to 4.

    Returns: * list[str]: A list of formatted YAML lines ready to be joined into a navigation block.

    Raises: * This function does not raise exceptions internally.

    Example: 

    def build_grouped_nav(sections: list, chapter_files: list, indent: int = 4) -> list[str]:
    lines = []
    pad = " " * indent
    for section in sections:
        lines.append(f"{pad}- {section['name']}:")
        if "children" in section:
            lines.extend(build_grouped_nav(section["children"], chapter_files, indent + 2))
        for mod_name in section.get("modules", []):
            match = next((cf for cf in chapter_files if cf["module_name"] == mod_name), None)
            if match:
                display = mod_name.split(".")[-1] if "." in mod_name else mod_name
                lines.append(f"{pad}  - '{display}': 'api/{match['filename']}'")
    return lines

    The recursive step increments indentation by 2 spaces (indent + 2) for nested child sections, preserving YAML structural syntax across arbitrary hierarchy depths. Module display names are shortened to the final dot-delimited segment (mod_name.split(".")[-1]) to maintain clean navigation labels.

    collect_all_modules()

    Visibility: Public
    Signature: def collect_all_modules(sections: list) -> set:

    Description:
    Recursively traverses a section hierarchy tree and collects all unique module names referenced across all sections and child subsections into a single flat set. This is used for validation and completeness checking against the target file list.

    Parameters: * sections (list): A hierarchical list of section dictionaries, potentially containing nested "children" lists and "modules" lists.

    Returns: * set: A unique set of all string module identifiers discovered across all depths of the section tree.

    Raises: * This function does not raise exceptions internally.

    Example: 

    def collect_all_modules(sections: list) -> set:
    result = set()
    for section in sections:
        result.update(section.get("modules", []))
        if "children" in section:
            result.update(collect_all_modules(section["children"]))
    return result

    This helper ensures exhaustive traversal by combining set union operations (result.update) across top-level entries and recursive invocations on nested child nodes.
