    llm_common.py

    Source: utils/llm_common.py

    Technical Overview

    The utils/llm_common.py module provides provider-neutral foundation primitives, data structures, and stateful tracking mechanisms shared across all Large Language Model (LLM) vendor adapters within the codebase. It operates strictly without external third-party SDK dependencies, relying entirely on the Python standard library (contextlib, contextvars, and hashlib). By isolating common abstractions from provider specifics, this module decouples core workflow nodes from vendor implementations such as Anthropic, Google Gemini, and OpenRouter, establishing a consistent runtime contract for error signaling, refusal management, and financial token accounting.

    Architecturally, the module fulfills four primary responsibilities:

    1. Signal In-Band Truncation: Provides the TruncatedResponse string specialization to denote model replies that hit token generation ceilings without raising immediate runtime errors. This allows callers to inspect partial responses while explicitly barring them from disk caches and downstream parsers.
    2. Refusal Circuit Breaking and Memoization: Implements the LLMRefusalError hierarchy and an in-memory SHA-256 hash registry (_refused). This registry captures safety, moderation, and policy refusals, distinguishing between unretryable prompt-level rejections (which are short-circuited to avoid billable retries) and retryable candidate-generation blocks.
    3. Multi-Dimensional Telemetry and Ledger Accounting: Tracks token metrics, reasoning tokens, prompt caching breakdowns (reads and writes), USD monetary costs, and operational events across both vendor providers and pipeline workflow steps using an execution context variable (_current_step).
    4. Log De-duplication: Supplies a call-site memoization utility (warn_once) that suppresses redundant warning messages across batch generation loops.

    Public API

    TruncatedResponse

    Visibility: Public

    Signature: class TruncatedResponse(str):

    Description: A specialized subclass of Python's built-in str that signals that an LLM completion was prematurely cut off by the provider due to token constraints (such as reaching max_tokens or exhausting the context window). It behaves as a standard string for string inspection and printing operations, but exposes a boolean class attribute truncated = True. Gateway callers such as call_llm use this attribute to identify partial responses, ensuring they are excluded from the persistent disk cache and prompting downstream YAML or JSON parsers to reject the output and trigger retries.

    Example:

    class TruncatedResponse(str):
    """Response text from a reply that was cut off; call_llm returns it but never caches it."""

    truncated = True

    The implementation relies on subclassing the immutable primitive str and binding the class-level marker truncated = True. Because TruncatedResponse is an instance of str, functions that handle plain text strings can inspect, log, or evaluate its length without type casting. However, downstream persistence layers intercept this class specifically to prevent storing partial code blocks, truncated JSON documents, or cut-off Markdown chapters in long-term caches.

    LLMRefusalError

    Visibility: Public

    Signature: class LLMRefusalError(RuntimeError):

    Description: Exception raised when an LLM provider or its configured fallback candidates refuse to process or complete a prompt. This encompasses Claude refusals, Google Gemini safety or recitation blocks, and OpenRouter content moderation filters. It differentiates between deterministic refusals (retryable=False, representing static prompt policy violations that must never be re-sent) and stochastic candidate rejections (retryable=True, representing output generation blocks where re-sampling may produce a valid completion).

    Phase 1: Initialization

        def __init__(self, model: str, category: str | None, provider: str = "ANTHROPIC", retryable: bool = False):
        self.model = model
        self.category = category
        self.provider = provider
        self.retryable = retryable
        super().__init__(f"{provider} model {model} declined the request (category={category or 'unknown'})")

    The constructor accepts the target model identifier, an optional refusal category string supplied by the provider, the canonical provider name, and a boolean flag indicating whether the failure is retryable. It assigns these parameters to instance attributes for runtime introspection and initializes the underlying RuntimeError base class with a standardized diagnostic message formatted as "{provider} model {model} declined the request (category={category})".

    request_key()

    Visibility: Public

    Signature: def request_key(provider: str, model: str, thinking_level: str | None, prompt: str) -> str:

    Description: Generates an authoritative 64-character SHA-256 hexadecimal hash string uniquely identifying an LLM invocation. The hash is constructed by combining the provider name, the model string, a normalized thinking effort level, and the prompt text. This hash serves as the cache lookup key in the in-memory refusal memoization table to identify repeated requests across workflow steps and node retries.

    Parameters:

    • provider (str): Canonical provider name (e.g., "ANTHROPIC", "GEMINI", "OPENROUTER").
    • model (str): Model name or identifier string.
    • thinking_level (str | None): Reasoning effort configuration (e.g., "low", "high", or None), which defaults to "default".
    • prompt (str): The complete UTF-8 prompt payload dispatched to the model.

    Returns:

    • str: A 64-character SHA-256 hexadecimal digest string.

    Raises: None.

    Example:

    def request_key(provider: str, model: str, thinking_level: str | None, prompt: str) -> str:
    scope = f"{provider}|{model}|{(thinking_level or 'default').lower()}\n"
    return hashlib.sha256((scope + prompt).encode("utf-8")).hexdigest()

    The function computes the hash by first formatting a single-line scoping prefix containing the provider, model, and lowercase thinking level separated by pipe delimiters and terminated by a newline. It concatenates this prefix with the raw prompt text, encodes the aggregate string into UTF-8 bytes, and processes it through hashlib.sha256(). This design ensures that identical prompts evaluated under different models, providers, or reasoning levels produce distinct keys.

    remember_refusal()

    Visibility: Public

    Signature: def remember_refusal(key: str, error: LLMRefusalError) -> None:

    Description: Stores a non-retryable refusal exception in the module-level memoization dictionary _refused. When a deterministic policy rejection occurs, recording it prevents downstream retry mechanisms from resubmitting the identical payload, thereby preventing rate-limit consumption and redundant API charges for partial streams.

    Parameters:

    • key (str): The unique 64-character SHA-256 request identifier computed via request_key().
    • error (LLMRefusalError): The refusal exception instance capturing model, provider, and category metadata.

    Returns:

    • None

    Raises: None.

    Example:

    def remember_refusal(key: str, error: LLMRefusalError) -> None:
    _refused[key] = error

    The helper performs a direct assignment of the LLMRefusalError instance into the module-level _refused dictionary keyed by the calculated hash. Because Python dictionaries retain in-memory state across imports within the same process lifecycle, any subsequent invocation throughout the pipeline run can instantly inspect prior refusal states without performing remote network calls.

    Parameters:

    • key (str): The 64-character SHA-256 request hash generated by request_key().

    Returns:

    • LLMRefusalError | None: The cached refusal exception if previously encountered and recorded, or None if the request has not been refused.

    The implementation performs a safe retrieval from the internal _refused dictionary using .get(key). If a matching key is found, the caller (typically call_llm) immediately re-raises the stored exception without dispatching HTTP requests or SDK calls, thereby protecting API budgets and avoiding pipeline delays.

    usage_step()

    Visibility: Public

    Signature: def usage_step(step: str | None):

    Description: A context manager that scopes LLM token usage and event accounting to a specific pipeline execution step. It temporarily modifies the thread- and task-local _current_step context variable, ensuring that all invocations of record_usage() and count_event() within the enclosed code block attribute their metrics to the specified workflow node.

    Parameters:

    • step (str | None): Name of the active pipeline step (e.g., "draft_chapters", "map_abstractions"). If None or empty, defaults to "other".

    Returns:

    • Generator context manager yielding control to the enclosed code block.

    Raises: None.

    Example:

    @contextlib.contextmanager
def usage_step(step: str | None):
    """Attribute every record_usage / count_event inside the block to `step`."""
    token = _current_step.set(step or "other")
    try:
        yield
    finally:
        _current_step.reset(token)

    The function utilizes @contextlib.contextmanager to encapsulate the lifecycle of a contextvars.Token. Upon entry, it calls _current_step.set(step or "other") and stores the resulting token. The enclosed logic executes within a try block, and the finally block guarantees that _current_step.reset(token) restores the prior context state, preserving step boundaries even when exceptions occur inside the context.

    record_usage()

    Visibility: Public

    Signature:

    def record_usage(
    provider: str,
    model: str,
    *,
    input_tokens: int = 0,
    output_tokens: int = 0,
    thinking_tokens: int = 0,
    cache_read: int = 0,
    cache_write: int = 0,
    cost: float | None = None,
    measured: bool = True,
) -> None:

    Description: Records the resource consumption, token metrics, and monetary cost of an individual API request. It increments running totals in both the provider-level ledger (_usage) and the active step-level ledger (_steps).

    Parameters:

    • provider (str): Name of the LLM provider (e.g., "ANTHROPIC", "GEMINI").
    • model (str): Identifier of the specific model that processed the request.
    • input_tokens (int, keyword-only): Total prompt tokens counted by the provider, including cached tokens. Defaults to 0.
    • output_tokens (int, keyword-only): Total generated tokens, including reasoning/thinking tokens. Defaults to 0.
    • thinking_tokens (int, keyword-only): Explicit subset of output tokens dedicated to reasoning. Defaults to 0.
    • cache_read (int, keyword-only): Tokens read from the provider's prompt cache. Defaults to 0.
    • cache_write (int, keyword-only): Tokens written to the provider's prompt cache. Defaults to 0.
    • cost (float | None, keyword-only): Billed request cost in USD. If None, indicates unknown pricing and increments the unpriced call counter. Defaults to None.
    • measured (bool, keyword-only): Indicates whether the provider returned verified usage metrics. If False (such as on an unbilled decline or uninstrumented endpoint), the request increments unmeasured_calls. Defaults to True.

    Returns:

    • None

    Raises: None.

    Example:

    def record_usage(
    provider: str,
    model: str,
    *,
    input_tokens: int = 0,
    output_tokens: int = 0,
    thinking_tokens: int = 0,
    cache_read: int = 0,
    cache_write: int = 0,
    cost: float | None = None,
    measured: bool = True,
) -> None:
    """Accumulate one API request. `input_tokens` = total prompt tokens (cached included);
    `output_tokens` includes thinking. `cost` is USD; None = unknown price (counted as unpriced).
    measured=False: the provider reported no usage, or the request was an unbilled decline — it counts
    as a request but is left out of estimate-vs-billed comparisons (`unmeasured_calls`)."""
    for entry in (_usage.setdefault(provider, _new_entry()), _steps.setdefault(current_step(), _new_entry())):
        if model:
            entry["models"].add(model)
        entry["calls"] += 1
        if not measured:
            entry["unmeasured_calls"] += 1
        entry["input"] += input_tokens or 0
        entry["output"] += output_tokens or 0
        entry["thinking"] += thinking_tokens or 0
        entry["cache_read"] += cache_read or 0
        entry["cache_write"] += cache_write or 0
        if cost is None:
            entry["unpriced_calls"] += 1
        else:
            entry["cost"] += cost

    The function iterates over two ledger target dictionaries: the entry for the specified provider within _usage and the entry for the active step within _steps (resolved via current_step()). If an entry does not exist, setdefault initializes it using _new_entry(). It tracks distinct model names in the models set, increments the total call count, and conditionally increments unmeasured_calls when measured is False. Token counts are accumulated using defensive fallback checks (or 0). When cost is None, the function increments unpriced_calls; otherwise, it adds the floating-point USD amount to cost.

    count_event()

    Visibility: Public

    Signature: def count_event(provider: str, event: str) -> None:

    Description: Increments an operational event counter (such as "refusals", "fallbacks", or "truncations") for both the specified provider and the currently active workflow step.

    Parameters:

    • provider (str): Target provider name.
    • event (str): Event key corresponding to a counter defined in _new_entry() (typically "refusals", "fallbacks", or "truncations").

    Returns:

    • None

    Raises: None.

    Example:

    def count_event(provider: str, event: str) -> None:
    """Increment 'refusals' | 'fallbacks' | 'truncations' for a provider (and the current step)."""
    _usage.setdefault(provider, _new_entry())[event] += 1

    record_estimate()

    Visibility: Public

    Signature: def record_estimate(step: str, estimated_input: int, *, cache_hit: bool = False) -> None:

    Description: Records an upfront token estimation or cache hit for a specific step. This telemetry allows the system to compare estimated prompt tokens against billed provider metrics or track computational savings from local disk cache hits.

    Parameters:

    • step (str): Name of the pipeline workflow step. If empty, falls back to "other".
    • estimated_input (int): Number of estimated input prompt tokens before dispatch.
    • cache_hit (bool, keyword-only): Whether the request was served directly from the local disk cache without hitting the provider network. Defaults to False.

    Returns:

    • None

    Raises: None.

    Example:

    def record_estimate(step: str, estimated_input: int, *, cache_hit: bool = False) -> None:
    """Add call_llm's input estimate for a call (billed or served from the LLM cache) to a step."""
    entry = _steps.setdefault(step or "other", _new_entry())
    if cache_hit:
        entry["cache_hits"] += 1
    else:
        entry["estimated_input"] += estimated_input or 0

    The function locates the target step dictionary within _steps. If cache_hit is true, it increments cache_hits, bypassing input token accumulation since no remote prompt tokens were processed. If cache_hit is false, it increments estimated_input by the estimated token count, providing the baseline for subsequent estimation accuracy calculations.

    usage_snapshot()

    Visibility: Public

    Signature: def usage_snapshot(provider: str) -> dict:

    Description: Captures a snapshot of a provider's current metrics, excluding non-numeric set fields such as models. By taking snapshots immediately before and after an API invocation, callers can calculate per-call token usage differentials via usage_delta().

    Parameters:

    • provider (str): Canonical provider name to inspect.

    Returns:

    • dict: A dictionary containing copies of all metric counters for the provider, excluding the models key. If the provider has no recorded usage, returns an initialized dictionary of zeroed counters.

    Raises: None.

    Example:

    def usage_snapshot(provider: str) -> dict:
    """Copy of a provider's running totals (diff two snapshots to get one call's usage)."""
    entry = _usage.get(provider)
    return {k: v for k, v in entry.items() if k != "models"} if entry else {k: v for k, v in _new_entry().items() if k != "models"}

    The function checks whether an entry exists for provider in _usage. If present, it uses a dictionary comprehension to copy all keys except "models". If no entry exists, it generates a default entry via _new_entry() and strips "models", ensuring callers always receive a uniform dictionary schema with zeroed values.

    usage_delta()

    Visibility: Public

    Signature: def usage_delta(before: dict, after: dict) -> dict:

    Description: Calculates the arithmetic difference between two usage snapshots, producing a delta dictionary representing the net resources consumed by an operation.

    Parameters:

    • before (dict): Usage snapshot taken prior to request execution.
    • after (dict): Usage snapshot taken following request completion.

    Returns:

    • dict: A dictionary where each key maps to the difference after[k] - before.get(k, 0).

    Raises: None.

    Example:

    def usage_delta(before: dict, after: dict) -> dict:
    return {k: after[k] - before.get(k, 0) for k in after}

    The function iterates over the keys of the after snapshot, subtracting the corresponding numeric value from before (defaulting missing keys in before to 0). This differential calculation isolates the exact token and cost footprint of a single call, even when concurrent or sequential calls are updating the global ledger.

    get_usage_summary()

    Visibility: Public

    Signature: def get_usage_summary() -> dict:

    Description: Compiles a comprehensive usage summary for all providers that processed at least one API call during the current execution run. The returned dictionary formats internal sets into sorted lists and includes derived metadata flags.

    Parameters: None.

    Returns:

    • dict: A dictionary mapping provider names to sanitized public ledger entries. Providers with zero recorded calls are omitted.

    Raises: None.

    Example:

    def get_usage_summary() -> dict:
    """{provider: totals} for every provider that made at least one call this run."""
    return {provider: _public(entry) for provider, entry in _usage.items() if entry["calls"]}

    The function iterates over _usage.items(), filtering out any provider entry whose calls counter equals 0. For all active providers, it transforms the raw internal ledger entry into a public-facing dictionary using _public(), converting the internal models set into a sorted list and evaluating whether all costs are fully known.

    get_step_summary()

    Visibility: Public

    Signature: def get_step_summary() -> dict:

    Description: Compiles an aggregated summary of usage across all pipeline workflow steps that recorded at least one API call or served at least one prompt from the local disk cache.

    Parameters: None.

    Returns:

    • dict: A dictionary mapping step names (in order of first appearance) to sanitized public ledger entries.

    Raises: None.

    Example:

    def get_step_summary() -> dict:
    """{step: totals} in first-use order, including steps answered only from the LLM cache."""

    The function iterates through the _steps dictionary, preserving its insertion order. It retains steps that executed remote API calls (entry["calls"] > 0) or fulfilled queries via cache hits (entry["cache_hits"] > 0). Each qualifying entry is passed through _public() to normalize fields for summary reporting.

    warn_once()

    Visibility: Public

    Signature: def warn_once(key: str, *parts) -> bool:

    Description: Tracks diagnostic warning events to ensure that a given warning key and its argument tuple are logged only once per process execution.

    Parameters:

    • key (str): Unique category identifier or warning format string.
    • *parts (Any): Variable arguments that distinguish specific instances of the warning (e.g., model name, threshold value).

    Returns:

    • bool: True if this specific (key, *parts) combination has not been logged previously during the current run; False if it has already been observed.

    Raises: None.

    Example:

    def warn_once(key: str, *parts) -> bool:
    """True the first time a (key, parts) combination is seen this run."""
    marker = (key, *parts)
    if marker in _warned:
        return False
    _warned.add(marker)
    return True

    The function constructs a composite tuple marker = (key, *parts) and checks its membership against the module-level _warned set. If the marker is already present, it returns False. If absent, it inserts the marker into _warned and returns True, signaling to the caller that the warning should be emitted.

    Internal Helpers

    Description: Module-level dictionary mapping 64-character SHA-256 request hash strings to their corresponding LLMRefusalError instances. It acts as an in-memory cache to prevent repeated submission of declined prompts.

    _usage

    Visibility: Private

    Signature: _usage = {}

    Description: Module-level dictionary mapping provider name strings (e.g., "ANTHROPIC", "GEMINI") to their respective ledger entry dictionaries generated by _new_entry().

    Visibility: Private

    Signature: _steps = {}

    Description: Module-level dictionary mapping pipeline step names (e.g., "draft_chapters", "reduce_abstractions") to their cumulative ledger entry dictionaries generated by _new_entry(). Maintains insertion order based on when each step first records activity.

    Visibility: Private

    Description: An execution context variable used to track the currently active workflow step across nested calls and asynchronous boundaries. Defaults to "other" when no step context manager is active.

    _warned

    Visibility: Private

    Signature: _warned = set()

    Description: Module-level set storing (key, *parts) tuples that have already triggered warnings via warn_once(). Used to suppress duplicate log messages across repetitive loops.

    _new_entry()

    Visibility: Private

    Signature: def _new_entry() -> dict:

    Description: Factory function that creates and returns a new zeroed ledger dictionary schema. Used to initialize new provider or workflow step entries in _usage and _steps.

    Parameters: None.

    Returns:

    • dict: A dictionary initialized with default counter values and an empty set of models.

    Raises: None.

    Example:

    def _new_entry() -> dict:
    return {
        "models": set(),
        "calls": 0,
        "input": 0,
        "output": 0,
        "thinking": 0,
        "cache_read": 0,
        "cache_write": 0,
        "cost": 0.0,
        "unpriced_calls": 0,
        "unmeasured_calls": 0,
        "refusals": 0,
        "fallbacks": 0,
        "truncations": 0,
        "estimated_input": 0,
        "cache_hits": 0,
    }

    The factory instantiates a dictionary containing all fifteen standard tracking fields. The "models" key is initialized to an empty set() to accumulate unique model identifiers without duplication. All token, call, and event counters are set to 0, while the monetary "cost" is initialized to 0.0.

    _public()

    Visibility: Private

    Signature: def _public(entry: dict) -> dict:

    Description: Transforms an internal ledger dictionary into a public-facing representation suitable for serialization and reporting. It converts the mutable models set into a sorted list and appends a derived boolean flag cost_known.

    Parameters:

    • entry (dict): An internal ledger dictionary structured according to _new_entry().

    Returns:

    • dict: A shallow copy of the input entry with models sorted as a list of strings and cost_known set to True if unpriced_calls == 0, or False otherwise.

    Raises: None.

    Example:

    def _public(entry: dict) -> dict:
    return dict(entry, models=sorted(entry["models"]), cost_known=entry["unpriced_calls"] == 0)

    The function uses the dict() constructor to clone entry while overriding the models key with sorted(entry["models"]). This produces deterministic, JSON-serializable output for downstream consumers. It also calculates cost_known = (entry["unpriced_calls"] == 0), allowing external callers to immediately verify whether the recorded cost accurately reflects the entire operational volume or is missing unpriced requests.

    Deterministic vs. Retryable Refusals

    When a provider rejects a prompt, the adapter wraps the rejection in an LLMRefusalError:

    • Deterministic Refusals (retryable=False): Occur when a prompt violates safety policies, system instructions, or content guardrails (e.g., Claude refusals, blocked prompt filters). The gateway invokes remember_refusal(key, error). Any subsequent attempt to execute that exact prompt under the same provider, model, and thinking level triggers an immediate short-circuit via previous_refusal(key), which re-raises the exception and bypasses network dispatch.
    • Retryable Refusals (retryable=True): Occur when output-side sampling triggers a block on candidate tokens (e.g., Gemini RECITATION or candidate safety triggers, OpenRouter content_filter). Because an alternative sampling path may succeed, these errors are not memoized in _refused, allowing node-level retries to re-dispatch the prompt with fresh random seeds or updated temperatures.

    In-Band Truncation Handling

    Rather than raising an exception when an LLM runs out of output tokens, providers return TruncatedResponse(text). This allows the calling orchestration layer to inspect the partial generation or log diagnostics. Because TruncatedResponse has truncated = True, cache storage logic avoids caching the incomplete response, and downstream structured data parsers (such as YAML and JSON parsers) fail validation on the incomplete syntax, prompting the workflow node to trigger a retry with expanded token headroom.
