    llm_common.py

    Source: utils/llm_common.py

    Following the implementation of provider-specific transport engines such as llm_anthropic.py, llm_common.py serves as the shared, provider-neutral architectural foundation across all LLM backends in the system. It eliminates vendor lock-in and dependency bloat by relying exclusively on Python standard library modules (contextlib, contextvars, hashlib), purposefully avoiding imports from vendor SDKs such as google-genai or anthropic.

    The module acts as the centralized accounting, memoization, and signaling layer for the entire inference pipeline. It maintains thread-safe and asynchronous task-safe step attribution using context variables, aggregates dual-ledger token and cost metrics across both providers and workflow execution steps, and persists deterministic request refusals to short-circuit wasteful API retries. Furthermore, it defines custom response markers and exception primitives that govern cache invalidation and retry semantics throughout upstream orchestration engines.

    Technical Overview

    llm_common.py implements four core operational capabilities required across all model interactions:

    1. Refusal Memoization: Large language models may decline requests due to safety guidelines, content filtering, or recitation checks. When an endpoint returns a deterministic, non-retryable refusal (such as a Claude policy refusal), continuing to retry the request within pipeline loops consumes rate limits and incurs billing penalties. llm_common.py maintains an in-memory SHA-256 digest mapping of refused requests via _refused, allowing subsequent attempts to immediately raise a cached LLMRefusalError without performing network I/O.
    2. Dual-Ledger Token and Cost Tracking: In-flight token consumption is categorized simultaneously across two dimensions: the LLM provider (e.g., Anthropic, Gemini, OpenRouter) and the workflow execution step (e.g., identify_abstractions, order_chapters). By utilizing a contextvars.ContextVar (_current_step), calls made deep within helper functions are automatically attributed to the active pipeline phase without requiring explicit parameter threading. The ledger tracks input, output, internal thinking tokens, prompt cache reads/writes, invocation counts, and micro-dollar API costs.
    3. Execution Diagnostics and Warning De-duplication: To prevent repetitive standard error output during long-running batch migrations or parallel node evaluations, the module provides a tuple-based deduplication mechanism (warn_once) that suppresses duplicate operational warnings.
    4. Flow Control Signaling: The module provides custom data structures such as TruncatedResponse to flag outputs that exceeded model token ceilings. This signals to downstream cache handlers that the response must not be written to disk, and informs orchestrator nodes that regeneration or context escalation is necessary.

    Public API

    TruncatedResponse

    Visibility: Public Signature: class TruncatedResponse(str):

    Description: A specialized string subclass used to represent LLM generation text that was cut short by context length ceilings or max_tokens limits. By attaching the class attribute truncated = True, callers can treat the object as a regular string for logging while upstream orchestrators (such as call_llm.py or response parsers) can inspect the boolean flag to reject partial YAML/JSON schemas, bypass the on-disk LLM response cache, and trigger workflow retry policies.

    Parameters: * Inherits standard str instantiation parameters.

    Returns: * TruncatedResponse: An immutable string instance with .truncated set to True.

    Raises: * None.

    Example: 

    class TruncatedResponse(str):
    """Response text from a reply that was cut off; call_llm returns it but never caches it."""

    truncated = True
    The TruncatedResponse type provides transparent interoperability with standard string operations, allowing logging and text inspection without type coercion. However, because call_llm.py explicitly inspects isinstance(response, TruncatedResponse) or checks getattr(response, "truncated", False), responses wrapped in this class are prevented from poisoning the long-term cache (llm_cache_v2.json). Downstream parsers that encounter an unclosed JSON or YAML document utilize this flag to differentiate between malformed model syntax and hard token cutoffs.

    LLMRefusalError

    Visibility: Public Signature: class LLMRefusalError(RuntimeError):

    Description: Exception raised when a provider declines to answer a prompt due to policy enforcement, safety filtering, moderation violations, or recitation barriers. It carries operational metadata indicating the offending model, the specific refusal category, the originating provider, and a crucial retryable boolean flag.

    Parameters: * model (str): The identifier of the model that refused the request. * category (str | None): The refusal reason reported by the provider (e.g., SAFETY, RECITATION, content_filter, or None). * provider (str, optional): The canonical provider name (defaults to "ANTHROPIC"). * retryable (bool, optional): Indicates whether a fresh generation attempt could bypass the refusal. Defaults to False.

    Returns: * LLMRefusalError: Instantiated runtime exception.

    Raises: * None during instantiation.

    Example: 

    class LLMRefusalError(RuntimeError):
    """Raised when the provider (and any configured fallback) declines a request."""

    def __init__(self, model: str, category: str | None, provider: str = "ANTHROPIC", retryable: bool = False):
        self.model = model
        self.category = category
        self.provider = provider
        self.retryable = retryable
        super().__init__(f"{provider} model {model} declined the request (category={category or 'unknown'})")
    When retryable is False, the refusal is deterministic (for example, a system prompt containing prohibited strings), indicating that re-submitting the identical payload will produce another refusal. The calling harness registers these errors in llm_common's memoization dictionary to prevent repeated rate limit consumption. Conversely, when retryable is set to True (such as Gemini non-deterministic recitation blocks or output-side candidate safety filters), pipeline retry mechanisms are allowed to resample from the model.

    request_key()

    Visibility: Public Signature: def request_key(provider: str, model: str, thinking_level: str | None, prompt: str) -> str:

    Description: Generates a deterministic SHA-256 hash identifying a specific LLM invocation configuration and input payload. This hash serves as the lookup key in the refusal cache.

    Parameters: * provider (str): The model host or gateway name (e.g., GEMINI, ANTHROPIC, OPENROUTER). * model (str): The specific model identifier (e.g., claude-3-7-sonnet-20250219). * thinking_level (str | None): The configured reasoning budget or effort level (e.g., low, medium, high, or None). * prompt (str): The complete serialized prompt text sent to the model.

    Returns: * str: A 64-character hexadecimal SHA-256 digest.

    Raises: * None.

    Example: 

    def request_key(provider: str, model: str, thinking_level: str | None, prompt: str) -> str:
    scope = f"{provider}|{model}|{(thinking_level or 'default').lower()}\n"
    return hashlib.sha256((scope + prompt).encode("utf-8")).hexdigest()
    The hashing strategy incorporates the provider, model, normalized thinking level, and prompt into a single scoped string before computing the SHA-256 digest. By converting thinking_level to lowercase and falling back to "default", variations in parameter casing are normalized. This ensures that memoized refusals are accurately bound to identical runtime configurations, preventing false cache hits across differing models or reasoning depths.

    remember_refusal()

    Visibility: Public Signature: def remember_refusal(key: str, error: LLMRefusalError) -> None:

    Description: Stores an LLMRefusalError instance in the internal process-level refusal registry keyed by its request hash digest.

    Parameters: * key (str): The 64-character SHA-256 string generated by request_key(). * error (LLMRefusalError): The refusal exception instance to record.

    Returns: * None

    Raises: * None.

    Example: 

    def remember_refusal(key: str, error: LLMRefusalError) -> None:

    This function populates the private _refused dictionary. It is invoked by calling gateways (e.g., call_llm.py) immediately upon trapping a non-retryable refusal from any downstream provider adapter. Storing the complete exception instance ensures that the original error context, category, and provider details are preserved for subsequent lookup.

    previous_refusal()

    Visibility: Public Signature: def previous_refusal(key: str) -> LLMRefusalError | None:

    Description: Queries the process-level refusal registry to check if an identical request configuration has previously resulted in a refusal.

    Parameters: * key (str): The 64-character SHA-256 string generated by request_key().

    Returns: * LLMRefusalError | None: The cached refusal exception if a prior decline exists; otherwise None.

    Raises: * None.

    Example:

This prevents unnecessary network round-trips and protects API quota when downstream pipeline nodes execute automated retry attempts on deterministic failures.

    usage_step()

    Visibility: Public Signature: def usage_step(step: str | None):

    Description: A context manager that scopes all token usage and event logging executed within its context block to a named workflow pipeline step.

    Parameters: * step (str | None): The identifier of the workflow step (e.g., identify_abstractions, order_chapters, group_modules). If None or empty, defaults to "other".

    Returns: * Context manager generator yielding execution control.

    Raises: * None directly; preserves and propagates exceptions raised within the wrapped block.

    Example: 

    @contextlib.contextmanager
def usage_step(step: str | None):
    """Attribute every record_usage / count_event inside the block to `step`."""
    token = _current_step.set(step or "other")
    try:
        yield
    finally:
        _current_step.reset(token)
    The context manager leverages Python's contextvars.ContextVar to manage step context. When entering the block, it assigns the step identifier to _current_step and stores the resulting reset token. Inside the finally block, it restores the previous context variable state using _current_step.reset(token). This structure guarantees accurate step attribution even across deeply nested generator flows, exception bubbles, or asynchronous task boundaries.

    Description: Retrieves the active workflow step identifier from the execution context.

    Parameters: * None.

    Returns: * str: The active step name set by the surrounding usage_step() context, or "other" if called outside of a scoped block.

    Raises: * None.

    Example: 

    def current_step() -> str:

    record_usage()

    Visibility: Public Signature: 

    def record_usage(
    provider: str,
    model: str,
    *,
    input_tokens: int = 0,
    output_tokens: int = 0,
    thinking_tokens: int = 0,
    cache_read: int = 0,
    cache_write: int = 0,
    cost: float | None = None,
    measured: bool = True,
) -> None:

    Description: Accumulates token consumption, cache performance metrics, and financial costs for an API request into both the provider-level ledger and the current step ledger.

    Parameters: * provider (str): Target provider name (e.g., "GEMINI", "ANTHROPIC"). * model (str): Target model name. If non-empty, it is registered in the entry's model tracking set. * input_tokens (int, optional): Total prompt tokens counted by the provider, including cached tokens. Defaults to 0. * output_tokens (int, optional): Total output tokens returned, including reasoning/thinking tokens. Defaults to 0. * thinking_tokens (int, optional): Explicit reasoning or thinking tokens reported by the provider. Defaults to 0. * cache_read (int, optional): Subset of prompt tokens retrieved from provider-side prompt cache. Defaults to 0. * cache_write (int, optional): Subset of prompt tokens written to provider-side prompt cache. Defaults to 0. * cost (float | None, optional): Financial cost of the call in USD. If None, the call is marked as unpriced. * measured (bool, optional): Whether the provider returned verified usage metrics. When False, increments unmeasured_calls. Defaults to True.

    Returns: * None

    Raises: * None.

    Example: 

    def record_usage(
    provider: str,
    model: str,
    *,
    input_tokens: int = 0,
    output_tokens: int = 0,
    thinking_tokens: int = 0,
    cache_read: int = 0,
    cache_write: int = 0,
    cost: float | None = None,
    measured: bool = True,
) -> None:
    for entry in (_usage.setdefault(provider, _new_entry()), _steps.setdefault(current_step(), _new_entry())):
        if model:
            entry["models"].add(model)
        entry["calls"] += 1
        if not measured:
            entry["unmeasured_calls"] += 1
        entry["input"] += input_tokens or 0
        entry["output"] += output_tokens or 0
        entry["thinking"] += thinking_tokens or 0
        entry["cache_read"] += cache_read or 0
        entry["cache_write"] += cache_write or 0
        if cost is None:
            entry["unpriced_calls"] += 1
        else:
            entry["cost"] += cost
    record_usage updates two distinct tracking dictionaries simultaneously: _usage (partitioned by provider) and _steps (partitioned by the active context step). Safe integer coercion via or 0 ensures that None values passed by upstream provider adapters do not cause TypeError exceptions during arithmetic accumulation. If cost is None, the unpriced_calls counter is incremented, signaling to downstream reporting summaries that the financial total represents an incomplete minimum lower bound.

    count_event()

    Visibility: Public Signature: def count_event(provider: str, event: str) -> None:

    Description: Increments designated lifecycle event counters ("refusals", "fallbacks", or "truncations") for both the provider and the active execution step.

    Parameters: * provider (str): Target provider name. * event (str): The metric key to increment. Must be one of "refusals", "fallbacks", or "truncations".

    Returns: * None

    Raises: * KeyError: If event is not a valid key defined in _new_entry().

    Example: 

    def count_event(provider: str, event: str) -> None:
    """Increment 'refusals' | 'fallbacks' | 'truncations' for a provider (and the current step)."""
    _usage.setdefault(provider, _new_entry())[event] += 1
    _steps.setdefault(current_step(), _new_entry())[event] += 1
    This function provides a lightweight telemetry interface for tracking runtime occurrences that do not produce standard token responses. For example, when llm_anthropic.py recovers from a context limit error by activating server-side fallback flags, or when call_llm.py encounters a model truncation, invoking count_event() ensures these events are tracked across both provider summaries and pipeline step reports.

    record_estimate()

    Visibility: Public Signature: def record_estimate(step: str, estimated_input: int, *, cache_hit: bool = False) -> None:

    Description: Records pre-flight token estimates or local cache hit events for a given workflow step.

    Parameters: * step (str): The name of the pipeline step being measured. * estimated_input (int): The locally calculated input token estimate (e.g., derived via tiktoken). * cache_hit (bool, optional): Indicates whether the request was satisfied by the local cache (llm_cache_v2.json) without making a network call. Defaults to False.

    Returns: * None

    Raises: * None.

    Example: 

    def record_estimate(step: str, estimated_input: int, *, cache_hit: bool = False) -> None:
    """Add call_llm's input estimate for a call (billed or served from the LLM cache) to a step."""
    entry = _steps.setdefault(step or "other", _new_entry())
    if cache_hit:
        entry["cache_hits"] += 1
    else:
        entry["estimated_input"] += estimated_input or 0
    This function enables token budgeting calibration. When a request is served entirely from the local cache, incrementing cache_hits ensures the step summary accounts for avoided API requests. When a network call is required, accumulating estimated_input allows the system to evaluate estimation drift against the actual provider-billed input metrics.

    usage_snapshot()

    Visibility: Public Signature: def usage_snapshot(provider: str) -> dict:

    Description: Creates a point-in-time copy of a provider's numeric usage counters, omitting non-scalar values such as model sets.

    Parameters: * provider (str): The provider whose metrics should be captured.

    Returns: * dict: A dictionary mapping metric names to their current integer or float values.

    Raises: * None.

    Example: 

    def usage_snapshot(provider: str) -> dict:
    """Copy of a provider's running totals (diff two snapshots to get one call's usage)."""
    entry = _usage.get(provider)
    return {k: v for k, v in entry.items() if k != "models"} if entry else {k: v for k, v in _new_entry().items() if k != "models"}
    By excluding the "models" set, usage_snapshot() returns a snapshot of purely numeric fields. This dictionary is designed to be passed into usage_delta() to isolate the specific token usage and cost incurred during a single network call.

    usage_delta()

    Visibility: Public Signature: def usage_delta(before: dict, after: dict) -> dict:

    Description: Computes the difference between two usage snapshot dictionaries.

    Parameters: * before (dict): The baseline snapshot taken before executing the operation. * after (dict): The snapshot taken after completing the operation.

    Returns: * dict: A dictionary containing the net change (after[k] - before[k]) for every counter key.

    Raises: * KeyError: If a key present in after is missing from before and lacks a fallback default.

    Example: 

    def usage_delta(before: dict, after: dict) -> dict:
    return {k: after[k] - before.get(k, 0) for k in after}
    This utility calculates exact per-call resource consumption. Because client SDKs and streaming interfaces may execute internal retries or multi-segment reasoning loops, calculating the delta across cumulative snapshots reliably captures total consumption, regardless of internal transport behavior.

    get_usage_summary()

    Visibility: Public Signature: def get_usage_summary() -> dict:

    Description: Compiles a summary dictionary of usage statistics for every provider that executed at least one API call during the current process run.

    Parameters: * None.

    Returns: * dict: A mapping of provider names to public summary dictionaries (see Data Structures).

    Raises: * None.

    Example: 

    def get_usage_summary() -> dict:
    """{provider: totals} for every provider that made at least one call this run."""
    return {provider: _public(entry) for provider, entry in _usage.items() if entry["calls"]}
    Providers that were configured or initialized but made no API requests (entry["calls"] == 0) are filtered out of the summary. For active providers, internal entries are converted to public representations using _public(), sorting model sets into lists and determining price completeness flags.

    get_step_summary()

    Visibility: Public Signature: def get_step_summary() -> dict:

    Description: Compiles a summary dictionary of usage statistics partitioned by workflow step, ordered by first appearance.

    Parameters: * None.

    Returns: * dict: A mapping of step identifiers to public summary dictionaries (see Data Structures).

    Raises: * None.

    Example: 

    def get_step_summary() -> dict:
    """{step: totals} in first-use order, including steps answered only from the LLM cache."""
    return {step: _public(entry) for step, entry in _steps.items() if entry["calls"] or entry["cache_hits"]}
    get_step_summary() retains insertion ordering based on when steps were first registered during execution. Unlike provider summaries, steps are included if they made direct API calls or were satisfied by local cache hits (entry["calls"] or entry["cache_hits"]). This ensures that cached steps are accurately reflected in end-of-run execution metrics.

    warn_once()

    Visibility: Public Signature: def warn_once(key: str, *parts) -> bool:

    Description: Evaluates whether a warning identified by a composite key tuple has been emitted during the lifetime of the process.

    Parameters: * key (str): The primary identifier or category of the warning. * *parts (Any): Additional elements combined with key to form a composite identity tuple.

    _public()

    Visibility: Private Signature: def _public(entry: dict) -> dict:

    Description: Formats an internal ledger entry dictionary into an external summary representation suitable for serialization and telemetry reporting.

    Parameters: * entry (dict): An internal ledger entry created via _new_entry().

    Returns: * dict: A copy of entry with "models" converted from a set to a sorted list, and a computed "cost_known" boolean indicating whether all calls were priced.

    Data Structures

    Internal Ledger Entry (_new_entry)

    The schema used internally to aggregate metrics within _usage and _steps.

    Field Type Description
    models set[str] Set of unique model identifiers that handled requests.
    calls int Total number of API requests dispatched.
    input int Total prompt tokens reported by the provider (cached tokens included).
    output int Total output tokens returned (including reasoning tokens).
    thinking int Subset of output tokens dedicated to internal reasoning/thinking.
    cache_read int Subset of prompt tokens read from provider-side prompt cache.
    cache_write int Subset of prompt tokens written to provider-side prompt cache.
    cost float Cumulative financial cost calculated in USD.
    unpriced_calls int Count of requests where pricing models were unavailable (cost is None).
    unmeasured_calls int Count of calls where the provider returned no token usage metrics.
    refusals int Number of times requests were rejected by provider safety or policy checks.
    fallbacks int Number of times fallback configurations or beta overrides were invoked.
    truncations int Number of times response generations reached token limits.
    estimated_input int Pre-calculated prompt token estimates derived prior to invocation.
    cache_hits int Number of requests satisfied by the local cache without network calls.

    Public Summary Entry (_public)

    The transformed schema returned by get_usage_summary() and get_step_summary().

    Field Type Description
    models list[str] Alphabetically sorted list of all model names used.
    calls int Total number of API requests dispatched.
    input int Total prompt tokens counted across calls.
    output int Total output tokens generated.
    thinking int Total thinking/reasoning tokens generated.
    cache_read int Total prompt cache read tokens.
    cache_write int Total prompt cache write tokens.
    cost float Cumulative calculated cost in USD.
    cost_known bool True if every call was priced (unpriced_calls == 0); False otherwise.
    unpriced_calls int Number of calls lacking explicit pricing.
    unmeasured_calls int Number of unmeasured calls.
    refusals int Total provider refusal count.
    fallbacks int Total provider fallback count.
    truncations int Total truncated response count.
    estimated_input int Total estimated prompt tokens.
    cache_hits int Total requests answered from the local cache.

    Error Handling

    Non-Retryable Refusal Memoization

    Deterministic provider refusals pose a risk in automated pipelines with retry policies. For instance, if an input violates safety restrictions or triggers recitation filters, naive retries will repeatedly fail, consuming rate limits and increasing latency.

    llm_common.py resolves this using the following pattern: 1. call_llm.py computes a hash via request_key(provider, model, thinking_level, prompt). 2. It queries previous_refusal(key). If an entry exists and error.retryable is False, the cached exception is immediately raised without initiating a network request. 3. If an endpoint rejects an active request, the provider adapter raises LLMRefusalError(..., retryable=False). 4. Upstream catch handlers invoke remember_refusal(key, err) and record the event via count_event(provider, 'refusals').

    Truncation Signaling without Disk Poisoning

    When an LLM exhausts its max_tokens allocation or context window, returning a partially formed response can cause downstream JSON/YAML parsing errors. Rather than raising an immediate unrecoverable exception, llm_common.py defines TruncatedResponse: * Adapters wrap truncated output strings in TruncatedResponse(raw_text). * call_llm.py inspects isinstance(result, TruncatedResponse) and bypasses writing the incomplete response to llm_cache_v2.json. * Downstream orchestration nodes receive the response, evaluate its .truncated attribute, and can trigger context window escalation or prompt compression before retrying.

    Unpriced and Unmeasured Safety Fallbacks

    Pricing configurations may not cover every experimental or locally hosted model (e.g., custom Ollama checkpoints). When a request's pricing cannot be resolved: * record_usage() accepts cost=None, tracks the call, and increments unpriced_calls. * When reporting summaries via _public(), cost_known evaluates to False. This warns operators that the reported cost total represents an incomplete floor rather than a definitive invoice total. * When endpoints return zero token metrics or omit usage headers entirely, setting measured=False tracks the call count while isolating the entry from token calibration metrics via unmeasured_calls.
