    llm_common.py

    Source: utils/llm_common.py

    Technical Overview

    utils/llm_common.py serves as the foundational, provider-neutral utility library for all Large Language Model interactions within the Codebase-Knowledge-Builder architecture. It is intentionally decoupled from external provider SDKs (such as google-genai or anthropic) and third-party dependencies, relying exclusively on Python standard library modules (contextlib, contextvars, hashlib, and logging). By isolating cross-cutting concerns—such as execution response truncation wrappers, refusal exception taxonomies, usage ledger aggregation, and SDK logging bridges—the module prevents circular import chains across concrete provider drivers (llm_anthropic.py, llm_gemini.py, llm_openrouter.py) and top-level orchestrators (call_llm.py).

    The module encapsulates three primary operational capabilities:

    1. Response and Error Signaling: It defines TruncatedResponse (a specialized string subclass indicating output token exhaustion) and LLMRefusalError (a structured runtime exception differentiating deterministic prompt declines from retryable output-side policy filters). It backs this taxonomy with a SHA-256 in-memory memoization cache to prevent pipeline retries from burning rate limits on rejected prompts.
    2. Context-Aware Usage Ledger: Utilizing Python's thread-safe and asynchronous-safe contextvars.ContextVar, it tracks token expenditures (input, output, reasoning/thinking, and caching metrics), estimated token allocations, financial costs in USD, and operational failure events across two distinct dimensions: per LLM provider and per logical pipeline step.
    3. SDK Log Interception and Warning De-duplication: It implements _SdkLogBridge, a specialized logging.Handler that captures lower-level client transport events (such as provider HTTP retry notices) without modifying upstream root logging configurations, while warn_once ensures non-fatal warnings are emitted only once per execution run.

    Public API

    TruncatedResponse

    Visibility: Public

    Signature: class TruncatedResponse(str):

    Description: A specialized string subclass used to wrap model completion text that was prematurely terminated due to token constraints (such as hitting max_tokens limits or reaching context window boundaries). Downstream dispatchers in call_llm.py inspect the boolean attribute truncated to ensure truncated outputs are returned to calling pipeline nodes for handling or retrying, but are never persisted into the persistent LLM disk cache (llm_cache_v2.json).

    class TruncatedResponse(str):
    """Response text from a reply that was cut off; call_llm returns it but never caches it."""

    truncated = True

    The TruncatedResponse class functions identically to a standard Python str across all text-processing operations, string concatenation, and formatting pipelines. However, downstream parsing utilities (such as YAML deserializers) and dispatch routers identify the truncated = True attribute on the instance to reject incomplete payloads. This mechanism guarantees that partially generated code structures, incomplete JSON schemas, or sliced markdown sections do not corrupt downstream AST validation routines or poison long-term response caches.

    LLMRefusalError

    Visibility: Public

    Signature: class LLMRefusalError(RuntimeError):

    Description: An exception raised when an upstream provider declines to process or complete a prompt due to content filtering, safety moderation, or policy restrictions. The class encapsulates provider metadata, refusal category classification, and a critical retryable boolean flag that distinguishes deterministic prompt declines from sample-dependent output blocks.

    class LLMRefusalError(RuntimeError):
    """Raised when the provider (and any configured fallback) declines a request.

    retryable=False: the same request is declined again (Claude refusal, blocked prompt,
    prohibited content) — call_llm remembers it and does not re-send it on node retries.
    retryable=True: an output-side block that a new sample can pass (Gemini RECITATION / OTHER /
    SAFETY on the candidate, OpenRouter content_filter) — node retries re-sample normally.
    """

    def __init__(self, model: str, category: str | None, provider: str = "ANTHROPIC", retryable: bool = False):
        self.model = model
        self.category = category
        self.provider = provider
        self.retryable = retryable
        super().__init__(f"{provider} model {model} declined the request (category={category or 'unknown'})")

    The LLMRefusalError hierarchy models failure semantics across diverse provider APIs into a uniform interface. When retryable is set to False, the error denotes an input-level policy rejection (such as Anthropic Claude refusing a prompt or Google Gemini blocking input tokens); these rejections are cached via remember_refusal so subsequent pipeline retries fail immediately without wasting API quotas. Conversely, when retryable is set to True, the error signifies a non-deterministic candidate generation block (such as Gemini's RECITATION or SAFETY candidate filters, or OpenRouter output moderation); these allow outer execution loops to resample with alternative temperature or randomness.

    request_key()

    Visibility: Public

    Signature: def request_key(provider: str, model: str, thinking_level: str | None, prompt: str) -> str:

    Description: Computes a deterministic SHA-256 hexadecimal digest that uniquely scopes an LLM inference request by provider, model name, thinking effort level, and prompt content.

    Parameters:

    • provider (str): The target provider identifier (e.g., "ANTHROPIC", "GEMINI").
    • model (str): The model name string.
    • thinking_level (str | None): The configured reasoning or thinking tier (e.g., "low", "high", or None).
    • prompt (str): The exact text of the prompt submitted to the model.

    Returns:

    • str: A 64-character lowercase hexadecimal SHA-256 digest string.

    Example:

    # Extracted from utils/llm_common.py
def request_key(provider: str, model: str, thinking_level: str | None, prompt: str) -> str:
    scope = f"{provider}|{model}|{(thinking_level or 'default').lower()}\n"
    return hashlib.sha256((scope + prompt).encode("utf-8")).hexdigest()

    The request_key function normalizes request parameters to guarantee consistent cache addressing. It normalizes absent thinking levels to the literal string "default" in lowercase, combines the parameters with pipe delimiters and a trailing newline separator, and appends the raw prompt string. The resulting byte sequence is hashed using SHA-256 to generate a collision-resistant identifier used as the lookup key in refusal tracking.

    remember_refusal()

    Visibility: Public

    Signature: def remember_refusal(key: str, error: LLMRefusalError) -> None:

    Description: Stores an LLMRefusalError in the internal process-level refusal memoization ledger _refused under the specified request key.

    Parameters:

    • key (str): The 64-character SHA-256 digest produced by request_key.
    • error (LLMRefusalError): The refusal error instance to memoize.

    Returns:

    • None: This function mutates internal module state and returns nothing.

    Example:

    # Extracted from utils/llm_common.py
def remember_refusal(key: str, error: LLMRefusalError) -> None:
    _refused[key] = error

    This function acts as a write barrier for refused requests. When an upstream provider encounters an unrecoverable policy refusal, call_llm calls remember_refusal with the request digest. Storing the error prevents repeated invocations across framework-level node retries from re-submitting the identical prompt payload, conserving API quota and eliminating rate-limit burn.

If a non-null LLMRefusalError is returned, the caller can immediately re-raise the exception, short-circuiting network transport and execution latency.

    usage_step()

    Visibility: Public

    Signature: def usage_step(step: str | None):

    Description: A context manager that scopes all LLM token usage, cost accumulations, and operational event counters within its dynamic block to a designated pipeline step name.

    Parameters:

    • step (str | None): The logical pipeline step name (e.g., "extract_facts", "draft_chapters"). If None or empty, defaults to "other".

    Returns:

    • Iterator[None]: A context manager yielding control to the enclosed code block.

    Example:

    # Extracted from utils/llm_common.py
@contextlib.contextmanager
def usage_step(step: str | None):
    """Attribute every record_usage / count_event inside the block to `step`."""
    token = _current_step.set(step or "other")
    try:
        yield
    finally:
        _current_step.reset(token)

    This context manager relies on Python's contextvars module to guarantee safe execution contexts across coroutines and nested invocations. Upon entering the block, it assigns the step identifier (defaulting to "other" if falsy) to the context variable _current_step and captures the assignment token. Upon exiting, the finally block invokes _current_step.reset(token), restoring the previous step attribution regardless of whether execution completed normally or raised an exception.

    record_usage()

    Visibility: Public

    Signature: def record_usage(provider: str, model: str, *, input_tokens: int = 0, output_tokens: int = 0, thinking_tokens: int = 0, cache_read: int = 0, cache_write: int = 0, cost: float | None = None, measured: bool = True) -> None:

    Description: Accumulates token counts, cache metrics, and financial costs for a completed API invocation into both the provider-level ledger (_usage) and the active step-level ledger (_steps).

    Parameters:

    • provider (str): Target provider name (e.g., "ANTHROPIC", "GEMINI", "OPENROUTER").
    • model (str): Model name or identifier string used during the request.
    • input_tokens (int): Total prompt tokens billed by the provider, inclusive of cached tokens. Defaults to 0.
    • output_tokens (int): Total completion tokens billed, inclusive of reasoning/thinking tokens. Defaults to 0.
    • thinking_tokens (int): Subset of output tokens specifically generated during reasoning/thinking passes. Defaults to 0.
    • cache_read (int): Number of input tokens served via provider-side prompt caching. Defaults to 0.
    • cache_write (int): Number of input tokens written into provider-side prompt caches. Defaults to 0.
    • cost (float | None): Computed monetary cost of the request in USD, or None if the pricing model is unavailable or unknown. Defaults to None.
    • measured (bool): Flag denoting whether the provider returned verified usage figures. If False, flags the request as unmeasured for diagnostic reporting. Defaults to True.

    Returns:

    • None: Mutates internal ledger dictionaries and returns nothing.

    Example:

    # Extracted from utils/llm_common.py
def record_usage(
    provider: str,
    model: str,
    *,
    input_tokens: int = 0,
    output_tokens: int = 0,
    thinking_tokens: int = 0,
    cache_read: int = 0,
    cache_write: int = 0,
    cost: float | None = None,
    measured: bool = True,
) -> None:
    for entry in (_usage.setdefault(provider, _new_entry()), _steps.setdefault(current_step(), _new_entry())):
        if model:
            entry["models"].add(model)
        entry["calls"] += 1
        if not measured:
            entry["unmeasured_calls"] += 1
        entry["input"] += input_tokens or 0
        entry["output"] += output_tokens or 0
        entry["thinking"] += thinking_tokens or 0
        entry["cache_read"] += cache_read or 0
        entry["cache_write"] += cache_write or 0
        if cost is None:
            entry["unpriced_calls"] += 1
        else:
            entry["cost"] += cost

    The record_usage function coordinates usage attribution across two dimensions. It resolves or initializes the entry dictionary for both the provider key in _usage and the current step key in _steps using _new_entry(). It registers the model identifier into the entry's models set, increments call counts, and aggregates input, output, thinking, and caching token counts. If cost is None, it increments unpriced_calls, ensuring that downstream summary formatters can flag that financial estimates are incomplete.

    count_event()

    Visibility: Public

    Signature: def count_event(provider: str, event: str) -> None:

    Description: Increments a specific operational counter (such as "refusals", "fallbacks", or "truncations") for both the specified provider and the current execution step.

    Parameters:

    • provider (str): The provider identifier experiencing the event.
    • event (str): The name of the event metric to increment. Supported fields include "refusals", "fallbacks", and "truncations".

    Returns:

    • None: Mutates ledger records in place.

    Example:

    # Extracted from utils/llm_common.py
def count_event(provider: str, event: str) -> None:
    """Increment 'refusals' | 'fallbacks' | 'truncations' for a provider (and the current step)."""
    _usage.setdefault(provider, _new_entry())[event] += 1
    _steps.setdefault(current_step(), _new_entry())[event] += 1

    count_event tracks operational anomalies and resilience events that occur outside standard billing loops. When a model returns a truncated response, a provider fails over to a secondary fallback, or a safety refusal is triggered, count_event ensures these incidents are recorded against both the originating provider and the active pipeline step. This data is exposed in the end-of-run execution summaries.

    record_estimate()

    Visibility: Public

    Signature: def record_estimate(step: str, estimated_input: int, *, cache_hit: bool = False) -> None:

    Description: Records pre-flight token estimates and local cache hit metrics against a specified pipeline step.

    Parameters:

    • step (str): The pipeline step name receiving the estimate or cache hit.
    • estimated_input (int): The estimated input token count calculated prior to network dispatch.
    • cache_hit (bool): If True, records that the request was answered directly from the local disk cache (llm_cache_v2.json) without consuming provider API resources. Defaults to False.

    Returns:

    • None: Mutates step records directly.

    Example:

    # Extracted from utils/llm_common.py
def record_estimate(step: str, estimated_input: int, *, cache_hit: bool = False) -> None:
    """Add call_llm's input estimate for a call (billed or served from the LLM cache) to a step."""
    entry = _steps.setdefault(step or "other", _new_entry())
    if cache_hit:
        entry["cache_hits"] += 1
    else:
        entry["estimated_input"] += estimated_input or 0

    record_estimate maintains parity between estimated prompt costs and actual provider-billed metrics. When requests are resolved entirely via local caching, cache_hit=True increments the cache_hits tally without updating input token counts. When a live request is dispatched, the estimated input tokens are added to estimated_input, allowing downstream auditing routines to compare tokenizer estimations (e.g., tiktoken approximations) against actual provider billing counters.

    usage_snapshot()

    Visibility: Public

    Signature: def usage_snapshot(provider: str) -> dict:

    Description: Creates a point-in-time dictionary snapshot of all running numeric counters for a specific provider, omitting non-scalar fields.

    Parameters:

    • provider (str): The provider identifier whose totals should be captured.

    Returns:

    • dict: A shallow dictionary copy containing all numeric fields from the provider's entry, excluding the models set.

    Example:

    # Extracted from utils/llm_common.py
def usage_snapshot(provider: str) -> dict:
    """Copy of a provider's running totals (diff two snapshots to get one call's usage)."""
    entry = _usage.get(provider)
    return {k: v for k, v in entry.items() if k != "models"} if entry else {k: v for k, v in _new_entry().items() if k != "models"}

    This function enables fine-grained differential tracking across single function calls. By capturing snapshots immediately before and after an individual LLM invocation, callers can pass the returned dictionaries to usage_delta to calculate exact token consumption, cache activity, and monetary cost for that isolated call. If the provider has not yet recorded any usage, an initialized empty schema is returned.

    usage_delta()

    Visibility: Public

    Signature: def usage_delta(before: dict, after: dict) -> dict:

    Description: Computes the numerical difference between two usage snapshots, producing a delta mapping representing resource usage during the intervening interval.

    Parameters:

    • before (dict): The baseline snapshot dictionary obtained from usage_snapshot.
    • after (dict): The subsequent snapshot dictionary obtained after request execution.

    Returns:

    • dict: A dictionary containing the arithmetic difference (after[k] - before.get(k, 0)) for every numeric key in after.

    Example:

    # Extracted from utils/llm_common.py
def usage_delta(before: dict, after: dict) -> dict:
    return {k: after[k] - before.get(k, 0) for k in after}

    usage_delta iterates across all keys present in the after snapshot and subtracts the corresponding baseline value from before. This helper powers the per-call console telemetry emitted by call_llm, allowing real-time output of prompt tokens, completion tokens, and dollar expenditures without requiring providers to pass usage objects up the call stack.

    open_sdk_logger()

    Visibility: Public

    Signature: def open_sdk_logger(name: str, level: int, on_record) -> None:

    Description: Attaches a custom _SdkLogBridge handler to a named Python logger, lowering its log level to intercept internal SDK retry records and routing them to a designated callback.

    Parameters:

    • name (str): The logger name string (e.g., "anthropic._base_client", "google_genai").
    • level (int): The integer logging level threshold to set on the target logger (e.g., logging.DEBUG).
    • on_record (Callable[[logging.LogRecord], None]): Callback invoked whenever a new log record is intercepted.

    Returns:

    • None: Mutates the target logger configuration.

    Example:

    # Extracted from utils/llm_common.py
def open_sdk_logger(name: str, level: int, on_record) -> None:
    """Route SDK logger *name* through ``_SdkLogBridge``, opened to *level* (once per process): how the provider
    modules announce the retries their SDK makes and only logs."""
    logger = logging.getLogger(name)
    if any(isinstance(handler, _SdkLogBridge) for handler in logger.handlers):
        return
    passthrough = logger.getEffectiveLevel()
    logger.addHandler(_SdkLogBridge(logger, passthrough, on_record))
    logger.propagate = False
    logger.setLevel(min(level, passthrough))

    This function configures vendor SDK logging pipelines idempotently. If an _SdkLogBridge is already attached to the target logger's handlers, the function returns immediately. Otherwise, it captures the logger's current effective level as a passthrough ceiling, installs the bridge handler, disables parent log propagation (propagate = False), and lowers the logger's threshold to min(level, passthrough). This ensures low-level SDK retry events are intercepted and processed without leaking full prompt and response payloads to standard error.

    warn_once()

    Visibility: Public

    Signature: def warn_once(key: str, *parts) -> bool:

    Description: De-duplicates warning messages across an application run, returning True only the first time a given key-and-parts combination is evaluated.

    Parameters:

    • key (str): Primary warning category or identifier string.
    • *parts (Any): Optional variable arguments concatenated with the key to form a composite cache marker.

    Returns:

    • bool: True if the marker was seen for the first time during the current process execution; False if it was previously recorded.

    Example:

    # Extracted from utils/llm_common.py
def warn_once(key: str, *parts) -> bool:
    """True the first time a (key, parts) combination is seen this run."""
    marker = (key, *parts)
    if marker in _warned:
        return False
    _warned.add(marker)
    return True

    The warn_once utility provides process-wide deduplication for operational warnings. By recording composite tuples (key, *parts) in the private _warned set, it ensures that high-frequency warnings (such as unsupported sampling parameters, model downgrades, or token budget clamp notices) are displayed to the user only on their initial occurrence, keeping console output clean.

    _SdkLogBridge

    Visibility: Private

    Signature: class _SdkLogBridge(logging.Handler):

    Description: A specialized logging.Handler subclass that routes intercepted log records to an external callback while selectively forwarding records that exceed the original log level threshold to the logger's parent handlers.

    class _SdkLogBridge(logging.Handler):
    """Every record of one SDK logger, opened to a lower level, goes to ``on_record`` (the retry notices); on to the
    rest of logging go only the records the logger let through before, exactly as before (``callHandlers`` of its
    parent: the handlers up the tree, else Python's last-resort stderr handler). So opening it changes nothing else
    that is printed: a root handler some library adds never gets the SDK's debug records, which hold whole prompts,
    and the SDK's warnings still reach stderr."""

    def __init__(self, logger: logging.Logger, passthrough: int, on_record):
        super().__init__(logging.NOTSET)
        self.logger, self.passthrough, self.on_record = logger, passthrough, on_record

    def emit(self, record):
        with contextlib.suppress(Exception):  # a notice never breaks a request
            self.on_record(record)
        if record.levelno >= self.passthrough and self.logger.parent is not None:
            self.logger.parent.callHandlers(record)

    The _SdkLogBridge class solves a common issue in LLM application telemetry: third-party provider SDKs often emit transient HTTP retry notices only at DEBUG or INFO logging levels. However, opening up those loggers globally can leak prompt text or payload bodies to standard output. By installing _SdkLogBridge, all log records at or above the newly opened level are delivered to on_record, while only records meeting the original passthrough threshold are propagated to parent handlers.

    _SdkLogBridge.emit()

    Visibility: Private (Public within class scope)

    Signature: def emit(self, record):

    Description: Handles an intercepted logging.LogRecord by safely invoking the registered callback and conditionally forwarding the record to the logger's parent handlers.

    Parameters:

    • record (logging.LogRecord): The log record emitted by the target SDK logger.

    Returns:

    • None: Emits the record or swallows internal callback exceptions.

    Example:

    # Extracted from utils/llm_common.py

    emit executes a defensive telemetry pattern. It wraps invocation of self.on_record(record) inside a contextlib.suppress(Exception) block to guarantee that any error inside the diagnostic telemetry callback does not abort live inference requests. After running the callback, it evaluates whether the record's level matches or exceeds self.passthrough. If so, and the logger has a parent configured, it invokes self.logger.parent.callHandlers(record) to maintain default warning and error visibility on stderr.

    Error Handling

    utils/llm_common.py defines and enforces specific error handling patterns across the inference lifecycle:

    1. Refusal Classification via LLMRefusalError: The module uses LLMRefusalError (subclassing Python's built-in RuntimeError) to trap provider refusals. The error carries a .retryable flag:

      • Non-retryable Refusals (retryable=False): Used for policy blocks, copyright violations, or safety rejections tied deterministically to the input prompt (e.g., Anthropic safety declinations). These are registered in _refused via remember_refusal(). Subsequent attempts to execute the same prompt check previous_refusal() and fail fast without network transmission.
      • Retryable Refusals (retryable=True): Used for output-side sampling rejections (e.g., Gemini RECITATION or candidate safety filters, OpenRouter moderation). These are not cached, allowing caller retry loops to resample with varied temperature or random seeds.

    2. Defensive Callback Isolation: In _SdkLogBridge.emit(), calls to the user-supplied on_record(record) callback are wrapped in contextlib.suppress(Exception). This pattern guarantees that unexpected errors during telemetry parsing or log emission never interrupt ongoing LLM requests.

    3. Fallback Value Initialization: Numeric metric functions (record_usage, record_estimate) defensively normalize falsy or missing parameter values (e.g., input_tokens or 0, cost is None), preventing TypeError exceptions during ledger accumulation.
