    llm_anthropic.py

    Source: utils/llm_anthropic.py

    Technical Overview

    llm_anthropic.py implements the native Anthropic Claude provider adapter for the Codebase-Knowledge-Builder architecture. Dispatched by utils/call_llm.py, the module encapsulates all Claude-specific request serialization, streaming transport handling, reasoning budget configuration, and multi-tier usage accounting. By isolating vendor-specific logic, the file ensures that the core orchestration engine remains decoupled from Anthropic SDK dependencies, allowing users targeting alternative providers to run without the anthropic Python package installed.

    The module is optimized for the Claude 5 model family (defaulting to claude-sonnet-5) while maintaining backwards compatibility with Claude 4.6 and legacy models such as Claude Haiku 4.5. Every interaction executes over Anthropic's streaming API (client.messages.stream), ensuring that extended reasoning chains and large token generations (up to 128K output tokens) never trigger client-side read or HTTP timeouts. The module features automated token budgeting that clamps requests against context window margins, single-shot budget expansion retries when responses are prematurely truncated, opt-in server-side safety fallbacks via Anthropic beta headers, and calibration feedback loops that reconcile tiktoken estimations against observed Claude token counts.

    Public API

    EFFORT_LEVELS

    Visibility: Public

    Signature: EFFORT_LEVELS = ANTHROPIC_EFFORT_LEVELS

    Description: Module-level alias exposing the valid thinking effort tiers supported by Anthropic Claude models. Imported directly from utils/llm_config.py, this tuple defines levels ranging through low, medium, high, xhigh, and max.

    Example:

    EFFORT_LEVELS = ANTHROPIC_EFFORT_LEVELS

    The constant provides downstream callers and CLI configuration validators with an authoritative list of supported effort strings. It is primarily referenced during thinking level validation to warn callers when an unsupported reasoning tier is requested for a specific Claude model family.

    Description: Determines whether a given model identifier belongs to a Claude family that natively supports adaptive reasoning effort controls rather than fixed token budgets.

    Parameters:

    Returns:

Claude models supporting adaptive thinking accept structured output_config.effort configurations and dynamically determine internal reasoning lengths, whereas older Claude architectures require legacy budget_tokens allocation schemas.

    get_model_limits()

    Visibility: Public

    Signature: def get_model_limits(model: str) -> tuple[int, int]:

    Description: Retrieves the context window and maximum allowable output tokens for a specified Claude model. It queries the remote Anthropic Models API via the SDK client, caches the result in an in-memory dictionary, and falls back to hardcoded offline limits if the API call encounters network or authentication issues.

    Parameters:

    • model (str): The model identifier string whose limits are being queried.

    Returns:

    • tuple[int, int]: A two-element tuple containing (context_window, max_output_tokens).

    Example:

    def get_model_limits(model: str) -> tuple[int, int]:
    """Return (context_window, max_output_tokens) from the Models API, with offline fallback."""
    if model in _model_limits_cache:
        return _model_limits_cache[model]
    fallback = next((v for k, v in _MODEL_LIMITS.items() if model.startswith(k)), _DEFAULT_LIMITS)
    try:
        info = _get_client().models.retrieve(model)
        limits = (getattr(info, "max_input_tokens", None) or fallback[0], getattr(info, "max_tokens", None) or fallback[1])
        emit_raw("DEBUG", f"Anthropic Models API | model={model} | context={limits[0]:,} | max_output={limits[1]:,}", dest="LOG")
    except anthropic.APIError as e:
        emit("WARN_ANTHROPIC_MODEL_LOOKUP", model=model, error=str(e))
        limits = fallback
    _model_limits_cache[model] = limits
    return limits

    This method protects prompt generation from token overflow by establishing hard generation boundaries. It checks the module-level dictionary _model_limits_cache to eliminate redundant remote lookups. If the remote endpoint raises anthropic.APIError, a structured telemetry warning is emitted via utils/output.py and static limits from _MODEL_LIMITS or _DEFAULT_LIMITS (1_000_000, 128_000) are applied.

    normalize_effort()

    Visibility: Public

    Signature: def normalize_effort(model: str, level: str | None) -> str | None:

    Description: Maps a generic thinking level string to an effort setting accepted by the specified Anthropic model, accounting for model-family constraints.

    Parameters:

    • model (str): The target model identifier.
    • level (str | None): The requested thinking level (e.g., "low", "medium", "high", "xhigh", "max", or None).

    Returns:

    • str | None: The normalized effort string accepted by the model family, or None if effort configuration should fall back to model defaults.

    Example:

    def normalize_effort(model: str, level: str | None) -> str | None:
    """Map a thinking level to an effort value the model accepts (None = model default)."""
    effort = anthropic_effort(model, level)  # minimal → low; xhigh → high on the 4.6 family
    if level and effort is None:
        emit("WARN_THINKING_LEVEL_INVALID", level=level.lower(), model=model, supported=str(list(EFFORT_LEVELS)))
    return effort

    The function delegates mapping logic to anthropic_effort() in utils/llm_config.py. For instance, Claude 4.6 models do not support "xhigh", so the value is automatically downgraded to "high". If the requested level cannot be mapped to any valid tier, an emission warning WARN_THINKING_LEVEL_INVALID is published and None is returned to allow default provider behavior.

    call_anthropic()

    Visibility: Public

    Signature: def call_anthropic(prompt: str, thinking_level: str | None = None) -> str:

    Description: Coordinates the complete end-to-end single-turn prompt execution against Anthropic Claude models. The function handles token pre-estimation, request formatting, streaming message reception, automatic expansion retries upon budget truncation, server-side fallback detection, refusal interception, and usage accounting.

    Phase 1: Request Sizing and Parameter Assembly

        model = get_model()
    effort = normalize_effort(model, thinking_level)
    raw_tokens = count_tokens_raw(prompt)  # memoized: the node already counted this prompt
    max_tokens, ceiling = _resolve_max_tokens(int(raw_tokens * token_ratio()), model, effort)
    params, betas = _build_request(prompt, model, effort, max_tokens)
    emit_raw(
        "DEBUG",
        f"Anthropic request | model={model} | effort={effort or 'default'} | max_tokens={max_tokens:,} | "
        f"fallbacks={'on' if betas else 'off'} | prompt_cache={'on' if 'cache_control' in params else 'off'}",
        dest="LOG",
    )

    start = time.time()
    message = _send(params, betas)

    The execution flow begins by querying the active model and mapping the thinking level to a valid effort parameter. Raw prompt tokens are obtained from utils/token_utils.py and multiplied by the current runtime token calibration ratio. _resolve_max_tokens() calculates the planned budget and context ceiling, after which _build_request() formats the payload and determines required Anthropic beta headers before dispatching via _send().

    Phase 2: Stream Execution and Adaptive Truncation Retry

        if message.stop_reason == "max_tokens" and max_tokens < ceiling:
        # Thinking + reply outgrew the budget: retry once at the largest budget that fits.
        emit("WARN_ANTHROPIC_TRUNCATED_RETRY", max_tokens=f"{max_tokens:,}", cap=f"{ceiling:,}")
        _record_usage(message, raw_tokens, effort, time.time() - start, model=model, observe=False)  # same prompt: observe once
        params, betas = _build_request(prompt, model, effort, ceiling)
        start = time.time()
        message = _send(params, betas)

    If the generation halts prematurely because reasoning tokens and response content exceeded the planned max_tokens allocation, the function checks whether unused headroom remains below the absolute context ceiling. If available, a one-time automatic retry occurs at the full ceiling limit. The initial truncated attempt is billed into the usage ledger without repeating prompt calibration observations, ensuring fair cost tracking while attempting completion recovery.

    Phase 3: Telemetry, Server Fallbacks, and Refusal Interception

        _record_usage(message, raw_tokens, effort, time.time() - start, model=model)
    if is_debug():
        _log_thinking(message)

    if _served_by_fallback(message) and message.stop_reason != "refusal":
        count_event("ANTHROPIC", "fallbacks")
        emit("WARN_ANTHROPIC_FALLBACK_SERVED", model=model, served_by=getattr(message, "model", "unknown"))

    if message.stop_reason == "refusal":
        count_event("ANTHROPIC", "refusals")
        details = getattr(message, "stop_details", None)
        category = getattr(details, "category", None) if details else None
        emit("WARN_ANTHROPIC_REFUSAL", model=model, category=category or "unknown")
        raise LLMRefusalError(model, category, provider="ANTHROPIC")

    Once a terminal response is received, _record_usage() logs comprehensive token accounting and updates calibration metrics. If debug logging is active, reasoning summaries are extracted and emitted. The response is audited to detect whether server-side safety fallback infrastructure routed the prompt to an alternate model. If the stop reason indicates a safety refusal, telemetry events are recorded and an LLMRefusalError is raised immediately to halt retry loops.

    Phase 4: Text Extraction and Truncation Evaluation

        text = _extract_text(message)
    if message.stop_reason in _TRUNCATION_STOPS:
        count_event("ANTHROPIC", "truncations")
        emit("WARN_ANTHROPIC_TRUNCATED", max_tokens=f"{params['max_tokens']:,}")
        return TruncatedResponse(text)
    if not text:
        emit("LLM_EMPTY_REPLY", provider="Anthropic", reason=message.stop_reason)
    return text

    Finally, textual content blocks are extracted from the message container. If the generation terminated under a truncation stop reason (e.g., reaching the context limit or output cap even after retry), the response string is wrapped inside a TruncatedResponse container, signaling utils/call_llm.py to bypass caching. If the reply is empty, a diagnostic warning is published before returning the result.

    Parameters:

    • prompt (str): The complete prompt text to submit to Claude.
    • thinking_level (str | None, optional): The reasoning effort tier requested for this execution step. Defaults to None.

    Returns:

    • str: The decoded response text string, or a TruncatedResponse wrapper if truncated by context or token exhaustion.

    Raises:

    • LLMRefusalError: When Claude declines the request due to policy or safety classifiers.

    Example:

    # Invocation from utils.call_llm._call_llm_anthropic:
reply = call_anthropic(prompt, thinking_level=thinking_level)

    __call__()

    Visibility: Public

    Signature: def __call__(self, record):

    Description: Evaluates logging records emitted by anthropic._base_client, parsing retry patterns to emit unified LLM_HTTP_RETRY notifications.

    Parameters:

    • record (logging.LogRecord): The standard Python logging record intercepted from the SDK logger.

    Returns:

    None.

    Example:

        def __call__(self, record):
        message = record.getMessage()
        if message.startswith("Retrying due to status code"):
            self.cause = f"HTTP {message.rsplit(' ', 1)[-1]}"
        elif message.startswith("Retrying as header"):
            self.cause = "x-should-retry"
        elif message.startswith("Encountered") and record.exc_info and record.exc_info[1] is not None:
            self.cause = f"{type(record.exc_info[1]).__name__}: {record.exc_info[1]}"
        elif re.match(r"^\d+ retr(?:y|ies) left$", message):
            self.left = int(message.split()[0])
        elif message.startswith("Retrying request to") and len(record.args or ()) == 2:
            attempt = _SDK_MAX_RETRIES - self.left + 1 if self.left is not None else "?"
            wait = f"{float(record.args[1]):.1f}"
            emit("LLM_HTTP_RETRY", provider="Anthropic", attempt=attempt, attempts=_SDK_MAX_RETRIES + 1, error=brief(self.cause or "?"), wait=wait)
            self.cause, self.left = "", None

    The method matches incoming log messages against regex patterns and known SDK phrasing. When a log line announces a pending retry, it computes the current attempt number relative to _SDK_MAX_RETRIES, formats the wait time in seconds, and triggers emit("LLM_HTTP_RETRY") via utils/output.py before clearing internal state.

    _fallback_config()

    Visibility: Private

    Signature: def _fallback_config(model: str) -> tuple[list[str], dict]:

    Description: Evaluates environment settings and model capabilities to generate server-side safety fallback configurations and necessary beta request headers.

    Parameters:

    • model (str): The primary model identifier being invoked.

    Returns:

    • tuple[list[str], dict]: A tuple consisting of a list of beta header strings and an extra_body dictionary specifying the fallback strategy.

    Example:

    def _fallback_config(model: str) -> tuple[list[str], dict]:
    """Return (betas, extra_body) for server-side refusal fallbacks, or empty when disabled."""
    setting = (os.getenv("ANTHROPIC_FALLBACKS") or "default").strip()
    if _fallbacks_disabled or setting.lower() == "off":
        return [], {}
    if setting.lower() == "default":
        if not _matches(model, _FALLBACK_PREFIXES):
            return [], {}
        return [_FALLBACK_DEFAULT_BETA], {"fallbacks": "default"}
    targets = [m.strip() for m in setting.split(",") if m.strip()]
    return [_FALLBACK_LIST_BETA], {"fallbacks": [{"model": m} for m in targets]}

    This helper inspects ANTHROPIC_FALLBACKS. If set to "default", it enables fallbacks only for models in _FALLBACK_PREFIXES (Opus and Fable variants subject to classifier false positives). If a comma-separated list of target models is provided, it configures explicit fallback routing using _FALLBACK_LIST_BETA.

    _build_request()

    Visibility: Private

    Signature: def _build_request(prompt: str, model: str, effort: str | None, max_tokens: int) -> tuple[dict, list[str]]:

    Description: Assembles the complete parameters dictionary and beta header list required for the Anthropic Messages streaming API call.

    Parameters:

            thinking = {"type": "adaptive"}
            if is_debug():

                thinking["display"] = "summarized"
            params["thinking"] = thinking
        if effort:

    _resolve_max_tokens()

    Visibility: Private

    Signature: def _resolve_max_tokens(prompt_tokens: int, model: str, effort: str | None) -> tuple[int, int]:

    Description: Calculates the optimal output token allocation and maximum ceiling limit, taking into account model output limits, prompt sizes, safety margins, and environment overrides.

    Parameters:

    • prompt_tokens (int): The calibrated input prompt token estimate.
    • model (str): The target model identifier.
    • effort (str | None): The normalized thinking effort setting.

    Returns:

    • tuple[int, int]: A tuple of (wanted, ceiling) representing the planned token budget and the maximum allowable token limit.

    Example:

    def _resolve_max_tokens(prompt_tokens: int, model: str, effort: str | None) -> tuple[int, int]:
    """Return (max_tokens, ceiling): the planned budget and the largest budget allowed.

    `prompt_tokens` is the raw tiktoken count scaled by token_utils.token_ratio() (calibrated).
    The ceiling respects the model output cap, the context window (prompt + output +
    ANTHROPIC_CONTEXT_MARGIN — the same margin input_token_budget reserves), and
    ANTHROPIC_MAX_OUTPUT_TOKENS when set.
    """
    context_window, output_cap = get_model_limits(model)
    cap = anthropic_output_cap()
    wanted = anthropic_planned_output(model, effort)  # same value input_token_budget reserved

    room = max(context_window - prompt_tokens - ANTHROPIC_CONTEXT_MARGIN, 4_096)
    ceiling = min(output_cap, room, cap) if cap else min(output_cap, room)
    if ceiling < wanted:
        # Small shortfalls (template overhead on a budget-packed prompt) are expected; only report real cuts.
        if ceiling < wanted * 0.9:
            emit("WARN_ANTHROPIC_OUTPUT_CLAMPED", wanted=f"{wanted:,}", available=f"{ceiling:,}")
        wanted = ceiling
    return wanted, ceiling

    The resolution logic balances planned output needs against physical context boundaries. The available context room is determined by subtracting prompt tokens and ANTHROPIC_CONTEXT_MARGIN from the total context window. The hard ceiling is clamped by the model output cap, available context room, and any optional ANTHROPIC_MAX_OUTPUT_TOKENS override. If the ceiling forces a budget reduction exceeding 10%, a warning WARN_ANTHROPIC_OUTPUT_CLAMPED is emitted.

    _message_cost()

    Visibility: Private

    Signature: def _message_cost(message, served_model: str) -> float | None:

    Description: Estimates the total cost in USD for a response message, factoring in multi-attempt fallback iterations.

    Parameters:

    • message (anthropic.types.Message): The message payload.
    • served_model (str): The identifier of the model that served the response.

    Returns:

    • float | None: The calculated cost in USD, 0.0 if unbilled, or None if model rates are unknown.

    Example:

    def _message_cost(message, served_model: str) -> float | None:
    """Estimated USD cost of one response. With server-side fallbacks, usage.iterations holds the
    per-attempt usage (each billed at its own model's rate; an attempt declined before any output is
    unbilled); top-level usage covers only the attempt that produced the returned message."""
    iterations = getattr(message.usage, "iterations", None) or []
    if iterations:
        total, known = 0.0, True
        for entry in iterations:
            tokens_in, tokens_out, cache_read, cache_write = _tokens(entry)
            if tokens_out == 0:
                continue  # declined before any output (primary or fallback attempt): not billed
            cost = _price(getattr(entry, "model", None) or served_model, tokens_in, tokens_out, cache_read, cache_write)
            known = known and cost is not None
            total += cost or 0.0
        return total if known else None
    if _declined_before_output(message):
        return 0.0  # declined before any output: not billed
    return _price(served_model, *_tokens(message.usage))

    This function accounts for multi-model fallback iterations. If usage.iterations is present, each attempt is evaluated against its respective model's pricing rates, ignoring zero-output refusals. If no iterations exist, the calculation evaluates the top-level usage against served_model.

    Error Handling

    LLMRefusalError

    The module catches safety classifier refusals returned by Anthropic (stop_reason == "refusal"). Rather than triggering transient node retries, call_anthropic() extracts the refusal category from message.stop_details, logs a WARN_ANTHROPIC_REFUSAL event, and raises an LLMRefusalError:

        if message.stop_reason == "refusal":
        count_event("ANTHROPIC", "refusals")
        details = getattr(message, "stop_details", None)
        category = getattr(details, "category", None) if details else None
        emit("WARN_ANTHROPIC_REFUSAL", model=model, category=category or "unknown")
        raise LLMRefusalError(model, category, provider="ANTHROPIC")

    This error halts execution for the current prompt branch, preventing repeated submission of rejected prompts.

    Truncation Handling and TruncatedResponse

    When a generation stops due to context or budget exhaustion (max_tokens or model_context_window_exceeded), the module evaluates whether the budget can be expanded:

        if message.stop_reason == "max_tokens" and max_tokens < ceiling:
        # Thinking + reply outgrew the budget: retry once at the largest budget that fits.
        emit("WARN_ANTHROPIC_TRUNCATED_RETRY", max_tokens=f"{max_tokens:,}", cap=f"{ceiling:,}")
        _record_usage(message, raw_tokens, effort, time.time() - start, model=model, observe=False)  # same prompt: observe once
        params, betas = _build_request(prompt, model, effort, ceiling)
        start = time.time()
        message = _send(params, betas)

    If the response remains truncated after expanding to ceiling, call_anthropic() wraps the partial output in a TruncatedResponse object. This container indicates to utils/call_llm.py that the text is incomplete and must not be committed to disk cache.

    Network drops, connection resets, and HTTP status codes 408, 409, 429, and 5xx are handled by the Anthropic SDK client configured with max_retries=3. To provide observability, _SdkRetryRecords intercepts SDK debug logs and translates them into structured telemetry events:

    This mechanism surfaces transport-level retries and backoff delays to the console without interrupting execution.
