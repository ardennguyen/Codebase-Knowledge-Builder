    llm_anthropic.py

    Source: utils/llm_anthropic.py

    Technical Overview

    Operating downstream from the centralized provider routing gateway established in call_llm.py, llm_anthropic.py provides the dedicated, low-level execution harness for Anthropic's Claude model family. The module encapsulates all Anthropic-specific request construction, transport mechanics, telemetry collection, and response processing. This isolation ensures that caller modules such as call_llm.py remain thin dispatchers, while dependencies on the third-party anthropic SDK are imported lazily to avoid forcing optional provider dependencies on environments using other backends.

    The architecture is specifically optimized for Claude 5 family models (defaulting to claude-sonnet-5) while maintaining backwards compatibility across the Claude 4.6 series and Haiku 4.5. Requests are processed through an adaptive token budgeting and streaming pipeline. To prevent HTTP connection timeouts when generating large outputs (up to 128K tokens combined reasoning and response), every generation streams via the SDK's Messages API. The component handles Claude's dual reasoning paradigms: newer models receive adaptive thinking configurations with explicit effort depths, while legacy models receive token-budget constraints. Furthermore, the module handles transient output truncations via single-pass budget escalation retries, manages server-side safety fallback betas, and integrates multi-attempt accounting for accurate cost calculation and token calibration.

    Public API

    call_anthropic()

    Visibility: Public
    Signature: def call_anthropic(prompt: str, thinking_level: str | None = None) -> str:

    Description: Sends a single-turn prompt to the configured Anthropic Claude model and returns the decoded completion string. The function orchestrates the complete inference lifecycle: estimating input token budgets, configuring adaptive reasoning depth or legacy token budgets, streaming output to avoid gateway timeouts, executing an automatic single-retry escalation when reasoning exhausts the initial token ceiling, and parsing safety refusals and truncation markers into structured exceptions or string subclasses.

    Parameters: * prompt (str): The primary instruction text and codebase context to be analyzed by the model. * thinking_level (str | None): Optional reasoning intensity flag (e.g., "low", "medium", "high", "xhigh", "max"). If None, the model's default profile is applied.

    Returns: * str: The decoded response text block. If the generation terminates due to token limits after retry escalation, an instance of TruncatedResponse (a subclass of str) is returned instead.

    Raises: * LLMRefusalError: Raised when the Anthropic model refuses the input on safety classifier grounds (stop_reason == "refusal").

    Phase 1: Token Budget Resolution & Parameter Assembly

        from utils.token_utils import count_tokens_raw, token_ratio

    model = get_model()
    effort = normalize_effort(model, thinking_level)
    raw_tokens = count_tokens_raw(prompt)  # memoized: the node already counted this prompt
    max_tokens, ceiling = _resolve_max_tokens(int(raw_tokens * token_ratio()), model, effort)
    params, betas = _build_request(prompt, model, effort, max_tokens)
    emit_raw(
        "DEBUG",
        f"Anthropic request | model={model} | effort={effort or 'default'} | max_tokens={max_tokens:,} | "
        f"fallbacks={'on' if betas else 'off'} | prompt_cache={'on' if 'cache_control' in params else 'off'}",
        dest="LOG",
    )
    This phase extracts the active model name from the environment, normalizes the requested thinking level against model capabilities, and calculates the prompt token count. The raw token count is scaled by the calibrated token_ratio() to convert tiktoken counts to Anthropic tokenizer units. _resolve_max_tokens() determines both the planned output budget and the maximum allowable ceiling given context window limitations, after which _build_request() compiles the dictionary payload and required beta headers.

    Phase 2: Initial Streaming Request Dispatch

        start = time.time()
    message = _send(params, betas)
    The compiled request dictionary and beta header parameters are dispatched to _send(). Execution utilizes client-side streaming under the hood to ensure network sockets remain active and do not trip reverse-proxy or HTTP gateway timeouts when Claude performs extensive internal chain-of-thought processing prior to producing output tokens.

    Phase 3: Truncation Detection and Single-Retry Escalation

        if message.stop_reason == "max_tokens" and max_tokens < ceiling:
        # Thinking + reply outgrew the budget: retry once at the largest budget that fits.
        emit("WARN_ANTHROPIC_TRUNCATED_RETRY", max_tokens=f"{max_tokens:,}", cap=f"{ceiling:,}")
        _record_usage(message, raw_tokens, effort, time.time() - start, model=model, observe=False)  # same prompt: observe once
        params, betas = _build_request(prompt, model, effort, ceiling)
        start = time.time()
        message = _send(params, betas)
    If the model halts generation because it hit the planned max_tokens barrier (message.stop_reason == "max_tokens") and the available context window ceiling allows a larger budget (max_tokens < ceiling), a retry is initiated. The intermediate attempt's token consumption is logged without triggering token calibration observation (observe=False). A new request is assembled with max_tokens set to ceiling, giving the model maximum room to finalize its reasoning and synthesis.

    Phase 4: Telemetry, Refusal Handling, and Response Extraction

        _record_usage(message, raw_tokens, effort, time.time() - start, model=model)
    if is_debug():
        _log_thinking(message)

    if _served_by_fallback(message) and message.stop_reason != "refusal":
        count_event("ANTHROPIC", "fallbacks")
        emit("WARN_ANTHROPIC_FALLBACK_SERVED", model=model, served_by=getattr(message, "model", "unknown"))

    if message.stop_reason == "refusal":
        count_event("ANTHROPIC", "refusals")
        details = getattr(message, "stop_details", None)
        category = getattr(details, "category", None) if details else None
        emit("WARN_ANTHROPIC_REFUSAL", model=model, category=category or "unknown")
        raise LLMRefusalError(model, category, provider="ANTHROPIC")

    text = _extract_text(message)
    if message.stop_reason in _TRUNCATION_STOPS:
        count_event("ANTHROPIC", "truncations")
        emit("WARN_ANTHROPIC_TRUNCATED", max_tokens=f"{params['max_tokens']:,}")
        return TruncatedResponse(text)
    if not text:
        emit_raw("WARNING", f"Anthropic response contained no text blocks (stop_reason={message.stop_reason})", dest="LOG")
    return text
    The final message usage is passed to _record_usage() for ledger accounting and token ratio observation. The function evaluates whether server-side fallback models fulfilled the request, whether the message was refused by safety filters (raising LLMRefusalError), or whether the response remained truncated after retry escalation. If truncated, it wraps the concatenated text in TruncatedResponse to signal upstream callers in call_llm.py not to commit the incomplete payload to disk cache.

    _get_client()

    Visibility: Private
    Signature: def _get_client() -> anthropic.Anthropic:

    Description: Lazily initializes and returns the singleton anthropic.Anthropic client instance stored in the module-level _client variable. The client is instantiated with max_retries=3, which handles standard 408, 409, 429, and 5xx transient server backoffs internally before escalating back to pipeline-level retry mechanisms.

    Parameters: None.

    Returns: * anthropic.Anthropic: The configured singleton client instance.

    Raises: None.

    Example: 

    def _get_client():
    global _client
    if _client is None:
        # SDK resolves credentials (ANTHROPIC_API_KEY / AUTH_TOKEN / ant profile) and
        # ANTHROPIC_BASE_URL itself. SDK retries 408/409/429/5xx with backoff;
        # PocketFlow node retries sit on top of this.
        _client = anthropic.Anthropic(max_retries=3)
    return _client
    The internal client instance is managed as a module-scoped singleton because inference runs in this architecture are single-threaded and sequential. The Anthropic SDK automatically inspects system environment variables such as ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN, and ANTHROPIC_BASE_URL upon instantiation.

    _fallback_config()

    Visibility: Private
    Signature: def _fallback_config(model: str) -> tuple[list[str], dict]:

    Description: Determines the required server-side fallback beta headers and body configurations based on the ANTHROPIC_FALLBACKS environment variable and model compatibility. If the setting is disabled, set to "off", or previously flagged as unsupported via runtime 400 errors (_fallbacks_disabled), it returns empty structures.

    Parameters: * model (str): Target model identifier string.

    Returns: * tuple[list[str], dict]: A 2-tuple of (betas, extra_body). When fallbacks are enabled, betas contains beta feature flags (e.g., ["server-side-fallback-2026-07-01"]) and extra_body contains fallback model routing rules.

    Raises: None.

    Example: 

    def _fallback_config(model: str) -> tuple[list[str], dict]:
    """Return (betas, extra_body) for server-side refusal fallbacks, or empty when disabled."""
    setting = (os.getenv("ANTHROPIC_FALLBACKS") or "default").strip()
    if _fallbacks_disabled or setting.lower() == "off":
        return [], {}
    if setting.lower() == "default":
        if not _matches(model, _FALLBACK_PREFIXES):
            return [], {}
        return [_FALLBACK_DEFAULT_BETA], {"fallbacks": "default"}
    targets = [m.strip() for m in setting.split(",") if m.strip()]
    return [_FALLBACK_LIST_BETA], {"fallbacks": [{"model": m} for m in targets]}
    Server-side fallbacks allow requests rejected by safety classifiers on frontier models (e.g., Opus 5.x, Fable 5.x) to route automatically to secondary fallback models. If a comma-delimited list of models is passed via ANTHROPIC_FALLBACKS, the helper constructs a custom target list using the fallback list beta header server-side-fallback-2026-06-01.

    _build_request()

    Visibility: Private
    Signature: def _build_request(prompt: str, model: str, effort: str | None, max_tokens: int) -> tuple[dict, list[str]]:

    Description: Constructs the complete payload dictionary and beta header list required by the Anthropic Messages API. It configures adaptive reasoning dictionaries, legacy budget token bounds, ephemeral prompt caching options, and server-side fallback payloads.

    Parameters: * prompt (str): User prompt content string. * model (str): Target model name. * effort (str | None): Effort level name or None. * max_tokens (int): Maximum generation limit.

    Returns: * tuple[dict, list[str]]: A 2-tuple consisting of the parameter dictionary (params) and a list of beta feature strings (betas).

    Raises: None.

    Example: 

    def _build_request(prompt: str, model: str, effort: str | None, max_tokens: int) -> tuple[dict, list[str]]:
    params = {
        "model": model,
        "max_tokens": max_tokens,
        "messages": [{"role": "user", "content": prompt}],
    }
    if uses_adaptive_thinking(model):
        if effort or _matches(model, _THINKING_BY_DEFAULT_PREFIXES):
            thinking = {"type": "adaptive"}
            if is_debug():
                # Readable reasoning summaries go to the log file (never to stdout).
                thinking["display"] = "summarized"
            params["thinking"] = thinking
        if effort:
            params["output_config"] = {"effort": effort}
    elif effort:
        budget = min(_BUDGET_BY_LEVEL[effort], max_tokens - 1_024)
        if budget >= 1_024:
            params["thinking"] = {"type": "enabled", "budget_tokens": budget}

    if (os.getenv("ANTHROPIC_PROMPT_CACHE") or "off").strip().lower() == "on":
        params["cache_control"] = {"type": "ephemeral"}

    betas, extra_body = _fallback_config(model)
    if extra_body:
        params["extra_body"] = extra_body
    return params, betas
    This helper adapts payloads based on model family traits. When targeting adaptive thinking architectures, it builds an {"type": "adaptive"} structure and optionally sets display: "summarized" when debug logging is active. For legacy reasoning models, it sets fixed token budgets derived from _BUDGET_BY_LEVEL, ensuring at least 1,024 tokens remain allocated for output synthesis.

    _resolve_max_tokens()

    Visibility: Private
    Signature: def _resolve_max_tokens(prompt_tokens: int, model: str, effort: str | None) -> tuple[int, int]:

    Description: Computes the optimal generation budget (wanted) and the maximum permissible ceiling (ceiling). It takes into account the model's native context window, the model's output cap, external environment caps (ANTHROPIC_MAX_OUTPUT_TOKENS), and a safety margin defined by ANTHROPIC_CONTEXT_MARGIN.

    Parameters: * prompt_tokens (int): Scaled token estimation of the prompt text. * model (str): Model identifier string. * effort (str | None): Desired reasoning effort.

    Returns: * tuple[int, int]: A 2-tuple containing (wanted, ceiling), where wanted is the requested budget clamped to the available ceiling, and ceiling is the absolute upper boundary allowed for retries.

    Raises: None.

    Example: 

    def _resolve_max_tokens(prompt_tokens: int, model: str, effort: str | None) -> tuple[int, int]:
    """Return (max_tokens, ceiling): the planned budget and the largest budget allowed."""
    context_window, output_cap = get_model_limits(model)
    cap = anthropic_output_cap()
    wanted = anthropic_planned_output(model, effort)  # same value input_token_budget reserved

    room = max(context_window - prompt_tokens - ANTHROPIC_CONTEXT_MARGIN, 4_096)
    ceiling = min(output_cap, room, cap) if cap else min(output_cap, room)
    if ceiling < wanted:
        # Small shortfalls (template overhead on a budget-packed prompt) are expected; only report real cuts.
        if ceiling < wanted * 0.9:
            emit("WARN_ANTHROPIC_OUTPUT_CLAMPED", wanted=f"{wanted:,}", available=f"{ceiling:,}")
        wanted = ceiling
    return wanted, ceiling
    The available context headroom (room) subtracts prompt tokens and safety margins (ANTHROPIC_CONTEXT_MARGIN) from the total context window. If the calculated ceiling reduces the planned output tokens by more than 10%, WARN_ANTHROPIC_OUTPUT_CLAMPED is emitted to alert the operator of token budget restrictions.

    Description: Dispatches a streamed Messages API call through the Anthropic SDK client, returning the aggregated Message object upon stream completion.

    Parameters: * params (dict): The payload dictionary. * betas (list[str]): List of beta feature headers.

    _fallback_rejected()

    Visibility: Private
    Signature: def _fallback_rejected(error_text: str, params: dict) -> bool:

    Description: Determines whether an HTTP 400 Bad Request error indicates an unsupported server-side fallback configuration (such as invalid beta headers or lack of account entitlement) rather than a malformed user payload.

    Parameters: * error_text (str): The error string from anthropic.BadRequestError. * params (dict): The request parameter dictionary.

    Returns: * bool: True if the error was caused by server-side fallback rejection, False otherwise.

    Raises: None.

    Example: 

    def _fallback_rejected(error_text: str, params: dict) -> bool:
    """True when a 400 rejects the fallback feature itself (beta header not enabled, or
    `fallbacks: "default"` unsupported for this model/account) — not a user config error."""
    text = error_text.lower()
    if "anthropic-beta" in text and "server-side-fallback" in text:
        return True
    return params.get("extra_body", {}).get("fallbacks") == "default" and "fallbacks" in text
    This inspection utility prevents persistent pipeline failures when experimental fallback betas are not provisioned on an API key. By distinguishing syntax errors from permission rejections, it enables graceful runtime downgrades.

    _send()

    Visibility: Private
    Signature: def _send(params: dict, betas: list[str]):

    Description: Wraps _stream_message in defensive error handling to gracefully degrade requests if server-side fallbacks are rejected. When a fallback-related 400 error occurs, it permanently disables fallbacks for the remainder of the runtime session (_fallbacks_disabled = True), strips extra_body from the request parameters, and resends the request without beta headers.

    Parameters: * params (dict): Request parameters. * betas (list[str]): Beta feature header flags.

    Returns: * anthropic.types.Message: The received final message.

    Raises: * anthropic.BadRequestError: Re-raised if the 400 error is unrelated to fallback mechanics. * anthropic.APIError: Any other upstream API communication failures.

    Example: 

    def _send(params: dict, betas: list[str]):
    """Send one streamed request; disable fallbacks for the run if the feature is unavailable."""
    global _fallbacks_disabled
    try:
        return _stream_message(params, betas)
    except anthropic.BadRequestError as e:
        if "extra_body" in params and _fallback_rejected(str(e), params):
            _fallbacks_disabled = True
            emit("WARN_ANTHROPIC_FALLBACK_DISABLED", error=str(e))
            retry_params = {k: v for k, v in params.items() if k != "extra_body"}
            return _stream_message(retry_params, [])
        raise
    This error recovery path allows the application to remain functional across varying API tier subscriptions. If an account lacks access to the server-side fallback beta, the system logs WARN_ANTHROPIC_FALLBACK_DISABLED and immediately retries the base request without interruption.

    _price()

    Visibility: Private
    Signature: def _price(model: str, tokens_in: int, tokens_out: int, cache_read: int, cache_write: int) -> float | None:

    Description: Computes the estimated USD cost of an execution using the internal _PRICING lookup table. Matches model names using longest-prefix comparison against known models, factoring in base inputs, outputs, cache reads, and ephemeral cache writes (billed at 1.25x the standard input rate).

    Parameters: * model (str): Served model string. * tokens_in (int): Uncached input tokens. * tokens_out (int): Total generated output tokens. * cache_read (int): Prompt tokens read from cache. * cache_write (int): Prompt tokens written to 5-minute ephemeral cache.

    Returns: * float | None: Estimated dollar cost rounded to precision, or None if the model has no entry in _PRICING.

    Raises: None.

    Example: 

    def _price(model: str, tokens_in: int, tokens_out: int, cache_read: int, cache_write: int) -> float | None:
    price = next((_PRICING[k] for k in sorted(_PRICING, key=len, reverse=True) if (model or "").startswith(k)), None)
    if price is None:
        return None
    p_in, p_out, p_read = price
    return (tokens_in * p_in + tokens_out * p_out + cache_read * p_read + cache_write * p_in * 1.25) / 1_000_000
    Prefix sorting ensures that more specific model designations (e.g., claude-opus-5-5) match before broader base prefixes (claude-opus-5). The token counts are normalized per million tokens as specified by provider billing standards.

    def _billed_entries(message) -> list:

    _billed_tokens()

    Visibility: Private
    Signature: def _billed_tokens(message) -> tuple[int, int, int, int, int]:

    Description: Aggregates token counts across all billable attempts returned by _billed_entries().

    Parameters: * message: The Anthropic Message response object.

    Returns: * tuple[int, int, int, int, int]: A 5-tuple of (total_in, out, cache_read, cache_write, thinking) where total_in encompasses uncached inputs, cache reads, and cache writes.

    Raises: None.

    Example: 

    def _billed_tokens(message) -> tuple[int, int, int, int, int]:
    """(total input incl. cache read/write, output, cache_read, cache_write, thinking) summed over the
    billed attempts (_billed_entries), so token totals match _message_cost."""
    total_in = out = cache_read = cache_write = thinking = 0
    for entry in _billed_entries(message):
        tokens_in, tokens_out, read, write = _tokens(entry)
        total_in += tokens_in + read + write
        out += tokens_out
        cache_read += read
        cache_write += write
        thinking += _thinking_tokens(entry)
    return total_in, out, cache_read, cache_write, thinking
    Summing across all billable attempts prevents discrepancies between token counts reported in logs and the monetary costs recorded in the ledger.

    _message_cost()

    Visibility: Private
    Signature: def _message_cost(message, served_model: str) -> float | None:

    Description: Computes the aggregate USD cost across all billable execution attempts within a response message. For fallback chains, each iteration is priced according to its specific model's pricing rates.

    Parameters: * message: The Anthropic response message. * served_model (str): Fallback model identifier string if iteration-level model IDs are missing.

    Returns: * float | None: Total USD cost, 0.0 for unbilled refusals, or None if pricing is unavailable for any involved model.

    Raises: None.

    Example: 

    def _message_cost(message, served_model: str) -> float | None:
    iterations = getattr(message.usage, "iterations", None) or []
    if iterations:
        total, known = 0.0, True
        for entry in iterations:
            tokens_in, tokens_out, cache_read, cache_write = _tokens(entry)
            if tokens_out == 0:
                continue  # declined before any output (primary or fallback attempt): not billed
            cost = _price(getattr(entry, "model", None) or served_model, tokens_in, tokens_out, cache_read, cache_write)
            known = known and cost is not None
            total += cost or 0.0
        return total if known else None
    if _declined_before_output(message):
        return 0.0  # declined before any output: not billed
    return _price(served_model, *_tokens(message.usage))
    This calculation accurately accounts for requests that cycle through multiple models during fallback processing. For example, if an Opus request evaluates input tokens and transitions to a Sonnet fallback, the usage across each model is priced using its respective rate.

    _record_usage()

    Visibility: Private
    Signature: def _record_usage(message, raw_prompt_tokens: int, effort: str | None, elapsed: float, model: str = "", observe: bool = True) -> None:

    Description: Records execution usage into the global accounting ledger via utils.llm_common.record_usage(), submits observed input token counts to utils.token_utils.observe_prompt_tokens() for dynamic ratio calibration, and outputs debug telemetry lines.

    Parameters: * message: The Anthropic SDK Message object. * raw_prompt_tokens (int): Base tiktoken prompt token count. * effort (str | None): Active effort parameter string. * elapsed (float): Call duration in seconds. * model (str): Target requested model string. * observe (bool): When True, submits token ratios to dynamic calibration; when False (such as during truncation retries), calibration updates are skipped.

    Returns: None.

    Raises: None.

    Phase 1: Billed Entry Aggregation and Ledger Recording

        from utils.token_utils import observe_prompt_tokens

    served_model = getattr(message, "model", "") or ""
    has_iterations = bool(getattr(message.usage, "iterations", None))
    entries = _billed_entries(message)
    if not entries:
        record_usage("ANTHROPIC", served_model, cost=0.0, measured=False)  # declined before any output: not billed
    # One ledger request per billed attempt (primary + fallback each billed at its own model's rate), so
    # request counts, per-request estimate deviation and the model list stay correct.
    for entry in entries:
        t_in, t_out, read, write = _tokens(entry)
        entry_model = (getattr(entry, "model", None) or served_model) if has_iterations else served_model
        record_usage(
            "ANTHROPIC",
            entry_model,
            input_tokens=t_in + read + write,
            output_tokens=t_out,
            thinking_tokens=_thinking_tokens(entry),
            cache_read=read,
            cache_write=write,
            cost=_price(entry_model, t_in, t_out, read, write) if has_iterations else _message_cost(message, served_model),
        )
    Each billable attempt is recorded as a separate ledger entry under the ANTHROPIC provider key. This approach ensures multi-attempt fallbacks preserve accurate per-model request counts, ledger balance adjustments, and cache read/write breakdowns.

    Phase 2: Ratio Calibration and Diagnostic Logging

        total_in, tokens_out, cache_read, cache_write, thinking = _billed_tokens(message)  # totals for the debug line
    cost = _message_cost(message, served_model)

    # Observed Claude/tiktoken ratio of the attempt that produced this message (top-level usage),
    # fed to the calibration unless another model (server-side fallback) served it.
    tokens_in, _, read, write = _tokens(message.usage)
    attempt_in = tokens_in + read + write
    ratio = attempt_in / raw_prompt_tokens if raw_prompt_tokens else 0.0
    if observe and model and not _served_by_fallback(message):
        observe_prompt_tokens("ANTHROPIC", model, raw_prompt_tokens, attempt_in, served_model=served_model)
    emit_raw(
        "DEBUG",
        f"ANTHROPIC USAGE | model={served_model} | effort={effort or 'default'} | stop={message.stop_reason} | "
        f"in={total_in:,} | out={tokens_out:,} | thinking={thinking:,} | cache_read={cache_read:,} | cache_write={cache_write:,} | "
        f"est_cost={'$' + format(cost, '.4f') if cost is not None else 'n/a'} | elapsed={elapsed:.1f}s | observed_token_ratio={ratio:.2f}",
        dest="BOTH",
    )
    This phase calculates the ratio of observed Anthropic input tokens to estimated tiktoken counts. If the call was fulfilled by the target model rather than a fallback, the ratio is submitted to observe_prompt_tokens() in token_utils.py to refine future budget estimations. Finally, a structured ANTHROPIC USAGE debug line is emitted to both stdout and log destinations.

    Error Handling

    Refusal Trapping (LLMRefusalError)

    When Claude's safety filters reject an incoming prompt, the response sets stop_reason == "refusal". call_anthropic() traps this stop reason, extracts the violation category from message.stop_details.category, records the event in telemetry using count_event("ANTHROPIC", "refusals"), emits WARN_ANTHROPIC_REFUSAL, and raises: 

    raise LLMRefusalError(model, category, provider="ANTHROPIC")
    Upstream, call_llm.py intercepts LLMRefusalError to record the refusal signature in memory, preventing repeated execution attempts on rejected prompts.

    Truncation Detection and Single-Pass Retry

    Output truncations occur when reasoning and response generation exceed the allocated max_tokens (message.stop_reason == "max_tokens"). 1. First-Pass Truncation: If the initial budget max_tokens is less than ceiling, the system logs WARN_ANTHROPIC_TRUNCATED_RETRY, logs the initial attempt's token usage, rebuilds the request parameters with max_tokens = ceiling, and re-invokes _send(). 2. Persistent Truncation: If the response remains truncated after the retry, or if the initial budget was already at ceiling, the system emits WARN_ANTHROPIC_TRUNCATED and wraps the text in a TruncatedResponse(text) instance. Downstream cache layers detect this type and skip saving incomplete results.

    Server-Side Fallback Rejections

    When requests include beta fallback headers on accounts or models that do not support them, the API raises anthropic.BadRequestError. The _send() helper catches this error and calls _fallback_rejected(). If the failure was caused by fallback beta restrictions: 

    _fallbacks_disabled = True
emit("WARN_ANTHROPIC_FALLBACK_DISABLED", error=str(e))
retry_params = {k: v for k, v in params.items() if k != "extra_body"}
return _stream_message(retry_params, [])
    This disables fallback requests for the remainder of the session and immediately resends the stripped request, allowing the pipeline to proceed without interruption.

    Output Clamping Warnings

    During parameter resolution in _resolve_max_tokens(), if context window constraints or configuration caps reduce the planned generation budget by more than 10% (ceiling < wanted * 0.9), the system emits WARN_ANTHROPIC_OUTPUT_CLAMPED to alert operators of potential capacity-driven truncations.
