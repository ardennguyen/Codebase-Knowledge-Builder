    utils.crawl_github_files

    Source: utils/crawl_github_files.py

    The utils.crawl_github_files module provides tools for fetching source code files and repository metadata from remote GitHub repositories. It supports two primary modes of operation:

    1. SSH Git Clone (git@ or .git URLs): Uses GitPython (git.Repo.clone_from) within a temporary directory to clone the repository, evaluate .gitignore patterns via pathspec, filter files by user-specified glob patterns and size limits, and extract UTF-8 text contents into memory.
    2. GitHub REST API (https://github.com/... URLs): Parses repository owners, repository names, branch/tree references (/tree/<ref>/<subpath>), and nested subdirectories. It interacts with the GitHub API (/repos/{owner}/{repo}/contents/{path} and /repos/{owner}/{repo}/git/trees/{tree}) to recursively traverse directories, fetch raw file contents (or base64-encoded blobs), inspect HTTP content-length and rate limits, and dynamically sleep upon receiving 403 or 429 rate-limiting headers.

    crawl_github_files()

    Visibility: Public Signature: def crawl_github_files(repo_url: str, token: str | None = None, max_file_size: int = 1048576, use_relative_paths: bool = False, include_patterns: str | set[str] | None = None, exclude_patterns: str | set[str] | None = None) -> dict:

    Description: Main entry point for extracting repository contents from a specified GitHub URL or SSH repository string. Normalizes file include/exclude patterns into sets, branches between SSH cloning and REST API traversal, maintains running counters for diagnostic reporting (processed, excluded, size limit, non-text), parses remote .gitignore rules into a pathspec.PathSpec matcher, and extracts UTF-8 string file contents into an in-memory dictionary mapped to relative or repository paths.

    Parameters: * repo_url (str): Target GitHub repository URL. Can be an SSH repository URL (git@github.com:... or ending in .git) or an HTTPS URL containing optional branch and subdirectory segments (e.g., https://github.com/owner/repo/tree/commit_or_branch/sub/path). * token (str | None, optional): GitHub Personal Access Token (PAT). Required for private repositories and recommended for public repositories to raise the standard unauthenticated rate limit. Defaults to None. * max_file_size (int, optional): The maximum allowable size of a file in bytes (default: 1 * 1024 * 1024 or 1 MB). Files exceeding this threshold are bypassed and recorded in the skipped statistics. * use_relative_paths (bool, optional): When True and a subpath is targeted in the URL, strips the leading path prefix so dictionary keys are relative to the target subdirectory. Defaults to False. * include_patterns (str | set[str] | None, optional): A glob pattern or set of glob patterns matching filenames to include (e.g., "*.py", {"*.py", "*.md"}). If None, all files are candidates. * exclude_patterns (str | set[str] | None, optional): A glob pattern or set of glob patterns matching file paths or directory names to exclude. If None, no explicit glob exclusions are applied.

    Returns: * dict: A dictionary containing: * "files" (dict[str, str]): Mapping of relative file paths to their string content. * "stats" (dict): Execution metrics including "downloaded_count", "skipped_count", "skipped_files", "base_path", "include_patterns", "exclude_patterns", and optional "source".

    Raises: * ValueError: If an HTTPS GitHub URL does not contain at least an owner and a repository name (len(path_parts) < 2). * Exception: If GitHub API rate limits (HTTP 403 or 429) are encountered and no access token is supplied to allow waiting and retry.

    Core Implementation: 

        # Detect SSH URL (git@ or .git suffix)
    is_ssh_url = repo_url.startswith("git@") or repo_url.endswith(".git")

    if is_ssh_url:
        # Clone repo via SSH to temp dir
        with tempfile.TemporaryDirectory() as tmpdirname:
            print(f"Cloning SSH repo {repo_url} to temp dir {tmpdirname} ...")
            try:
                repo = git.Repo.clone_from(repo_url, tmpdirname)
            except Exception as e:
                print(f"Error cloning repo: {e}")
                return {"files": {}, "stats": {"error": str(e)}}

            # ... Directory walking, .gitignore spec loading, pattern filtering, and file extraction ...

            return {
                "files": files,
                "stats": {
                    "downloaded_count": len(files),
                    "skipped_count": len(skipped_files),
                    "skipped_files": skipped_files,
                    "base_path": None,
                    "include_patterns": include_patterns,
                    "exclude_patterns": exclude_patterns,
                    "source": "ssh_clone",
                },
            }

    # Parse GitHub URL to extract owner, repo, commit/branch, and path
    parsed_url = urlparse(repo_url)
    path_parts = parsed_url.path.strip("/").split("/")

    if len(path_parts) < 2:
        raise ValueError(f"Invalid GitHub URL: {repo_url}")

    The function orchestrates repository crawling by analyzing the structure of repo_url. When an SSH URL is detected, it delegates repository fetching to git.Repo.clone_from, safely operating within a context-managed tempfile.TemporaryDirectory. When an HTTPS URL is passed, it isolates the owner, repo, branch/tree ref, and subdirectory path, dynamically queries repository metadata through GitHub's REST API, monitors rate-limiting quotas, and prints real-time ANSI-colored progress logs.

    Example:

    should_include_file()

    Visibility: Internal Helper (Scoped inside crawl_github_files) Signature: def should_include_file(file_path: str, file_name: str, gitignore_spec: pathspec.PathSpec | None = None) -> bool:

    Description: Evaluates whether a specific file should be processed based on inclusion patterns, .gitignore path specifications, and exclusion patterns. Inclusion rules are evaluated against the basename (file_name) using fnmatch.fnmatch, .gitignore rules are evaluated against the relative path (file_path) using pathspec, and exclusion rules are matched against the relative path.

    Parameters: * file_path (str): The relative path of the candidate file within the repository or target directory. * file_name (str): The base filename (e.g., main.py). * gitignore_spec (pathspec.PathSpec | None, optional): A compiled PathSpec object holding .gitignore rules parsed from the repository root. Defaults to None.

    Returns: * bool: True if the file satisfies all inclusion patterns, is not ignored by .gitignore, and does not match any exclusion pattern; False otherwise.

    Core Implementation: 

        def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:
        """Determine if a file should be included based on patterns"""
        # If no include patterns are specified, include all files
        if not include_patterns:
            include_file = True
        else:
            # Check if file matches any include pattern
            include_file = any(fnmatch.fnmatch(file_name, pattern) for pattern in include_patterns)

        # Check gitignore if provided
        if include_file and gitignore_spec and gitignore_spec.match_file(file_path):
            return False

        # If exclude patterns are specified, check if file should be excluded
        if exclude_patterns and include_file:
            # Exclude if file matches any exclude pattern
            exclude_file = any(fnmatch.fnmatch(file_path, pattern) for pattern in exclude_patterns)
            return not exclude_file

        return include_file

    should_include_file acts as the single filtering decision point for both the local filesystem walk (SSH mode) and the recursive REST API traversal. It enforces a strict evaluation order: inclusion checks on the file name are verified first, followed by .gitignore rules against the full relative path, and finally user-defined exclusion pattern matching.

    Example: 

    # Internal invocation within crawl_github_files (REST API branch)
if not should_include_file(rel_path, item["name"], gitignore_spec=gitignore_spec):
    api_counters["excluded"] += 1
    print(f"{C_GRAY}  [{entry_num}] {rel_path} [excluded]{C_RESET}")
    continue

    fetch_branches()

    Visibility: Internal Helper (Scoped inside crawl_github_files) Signature: def fetch_branches(owner: str, repo: str) -> list[dict]:

    Description: Queries the GitHub REST API endpoint /repos/{owner}/{repo}/branches to list all branches in the remote repository. Used during URL parsing to disambiguate whether a URL segment following /tree/ refers to a branch name (which may contain forward slashes, e.g., feature/v1) or a commit SHA/Git tree object.

    Parameters: * owner (str): The GitHub account or organization name. * repo (str): The repository name.

    Returns: * list[dict]: A list of branch descriptor dictionaries returned by GitHub's API, or an empty list [] if the request fails (e.g., HTTP 404 or network failure).

    Raises: * Exception: If HTTP status code 403 or 429 is received and no access token was provided.

    Core Implementation: 

        def fetch_branches(owner: str, repo: str):
        """Get brancshes of the repository"""

        url = f"https://api.github.com/repos/{owner}/{repo}/branches"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        if response.status_code == 404:
            if not token:
                print(
                    "Error 404: Repository not found or is private.\n"
                    "If this is a private repository, please provide a valid GitHub token via the 'token' argument or set the GITHUB_TOKEN environment variable."
                )
            else:
                print(
                    "Error 404: Repository not found or insufficient permissions with the provided token.\n"
                    "Please verify the repository exists and the token has access to this repository."
                )
            return []

        if response.status_code != 200:
            print(f"Error fetching the branches of {owner}/{repo}: {response.status_code} - {response.text}")
            return []

        return response.json()

    fetch_branches handles unauthenticated rate limit detection and access errors when querying branch names. If an unauthenticated client exceeds API rate limits, it raises an explicit exception prompting for a token; if a 404 is encountered, it provides contextual error logging informing the user whether a token is missing or lacks repository permissions.

branch_names = (branch.get("name") for branch in branches)

if len(branches) == 0:
    return None

    Visibility: Internal Helper (Scoped inside crawl_github_files) Signature: def check_tree(owner: str, repo: str, tree: str) -> bool:

    Description: Validates whether a specific Git tree SHA or commit hash exists in the repository by executing a GET request against /repos/{owner}/{repo}/git/trees/{tree}.

    Parameters: * owner (str): The GitHub account or organization name. * repo (str): The repository name. * tree (str): The Git tree SHA, commit hash, or ref to verify.

    Returns: * bool: True if the tree object exists (HTTP status 200), False otherwise.

    Raises: * Exception: If GitHub API rate limits (HTTP 403 or 429) are exceeded without an authorization token.

    Core Implementation: 

        def check_tree(owner: str, repo: str, tree: str):
        """Check the repository has the given tree"""

        url = f"https://api.github.com/repos/{owner}/{repo}/git/trees/{tree}"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        return response.status_code == 200

    check_tree verifies if an arbitrary reference in a /tree/<ref> URL represents a valid Git tree object or commit hash when it cannot be matched against active branch names returned by fetch_branches. It safeguards against invalid URL paths before initiating the contents traversal loop.

    Example:

    fetch_contents()

    Visibility: Internal Helper (Scoped inside crawl_github_files) Signature: def fetch_contents(path: str) -> None:

    Description: Recursively retrieves files and directories located at path within the specified repository ref. Handles rate limit resets, base64 payload decoding, raw file streaming, .gitignore directory filtering, file size validation, and relative path adjustments.

    Parameters: * path (str): The subdirectory path in the repository to fetch. Use empty string "" to begin traversal at the repository root.

    Returns: * None: Populates the enclosing files dictionary and updates api_counters in place.

    Raises: * Exception: If GitHub rate limits are encountered without an active token.

    Core Implementation: 

        def fetch_contents(path):
        """Fetch contents of the repository at a specific path and commit"""
        url = f"https://api.github.com/repos/{owner}/{repo}/contents/{path}"
        params = {"ref": ref} if ref is not None else {}

        response = requests.get(url, headers=headers, params=params, timeout=(30, 30))

        if response.status_code in (403, 429) and "rate limit exceeded" in response.text.lower():
            if not token:
                raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")
            reset_time = int(response.headers.get("X-RateLimit-Reset", 0))
            wait_time = max(reset_time - time.time(), 0) + 1
            print(f"Rate limit exceeded. Waiting for {wait_time:.0f} seconds...")
            time.sleep(wait_time)
            return fetch_contents(path)

        if response.status_code == 404:
            # ... Handle 404 diagnostics for default branch / missing path ...
            return None

        if response.status_code != 200:
            print(f"Error fetching {path}: {response.status_code} - {response.text}")
            return None

        contents = response.json()
        if not isinstance(contents, list):
            contents = [contents]

        # ... Iterate contents: filter dirs, download raw or decode base64 files ...

    fetch_contents performs recursive descent into repository directory structures via GitHub API content listings. When an authenticated client encounters an API rate limit response (HTTP 403/429), it calculates the remaining delay from the X-RateLimit-Reset header, suspends execution with time.sleep(), and retries the request automatically. For individual files, it evaluates metadata sizes, downloads raw content via download_url (or decodes base64 blobs), checks content-length headers against max_file_size, and stores decoded UTF-8 strings into the output mapping.

    Example: 

    # Internal invocation within crawl_github_files to start crawling
fetch_contents(specific_path)
