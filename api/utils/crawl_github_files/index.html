    utils.crawl_github_files

    Source: utils/crawl_github_files.py

    Technical and API reference documentation for the utils/crawl_github_files.py module.

    Technical Overview

    The utils.crawl_github_files module provides extraction and ingestion capabilities for remote GitHub repositories. It serves as an ingestion utility for Codebase-Knowledge-Builder, pulling repository files into memory so downstream nodes can construct knowledge representations.

    The module supports two primary ingestion workflows: 1. SSH Clone Mode: Triggered when a repository URL begins with git@ or ends with .git. The module clones the remote repository into a temporary directory using git.Repo.clone_from, parses the root .gitignore file via pathspec, walks the file system using os.walk, and applies include/exclude wildcard pattern filters and maximum size boundaries. 2. REST API Traversal Mode: Triggered for standard GitHub HTTP/HTTPS repository URLs (e.g., https://github.com/owner/repo/tree/branch_or_commit/subpath). The module resolves owner, repository, branch, commit SHA, and subpath segments using GitHub REST API endpoints (/repos/{owner}/{repo}/branches, /repos/{owner}/{repo}/git/trees/{tree}, and /repos/{owner}/{repo}/contents/{path}). It fetches contents recursively, automatically detects rate-limiting headers (X-RateLimit-Reset) to pause execution when authenticated or unauthenticated quotas are exhausted, decodes Base64 or raw payloads, filters out non-text binaries, and applies .gitignore rules downloaded from the target ref.

    crawl_github_files()

    Visibility: Public
    Signature: def crawl_github_files(repo_url: str, token: str | None = None, max_file_size: int = 1048576, use_relative_paths: bool = False, include_patterns: str | set[str] | None = None, exclude_patterns: str | set[str] | None = None) -> dict:

    Description:
    Crawls and ingests files from a specific GitHub repository, reference (branch, tag, or commit SHA), and subpath. Based on the URL syntax, it routes either to an SSH-based local clone workflow inside a secure temporary directory or to an authenticated/unauthenticated recursive GitHub REST API v3 crawling workflow.

    During extraction, the function enforces pattern filtering using fnmatch, .gitignore filtering using pathspec, size ceilings (max_file_size), and text encoding validations. It formats console progress using ANSI color codes and returns a structured dictionary containing all read file contents and execution statistics.

    Parameters: * repo_url (str): Target repository URL. Accepts full GitHub tree/blob URLs (e.g., https://github.com/microsoft/autogen/tree/commit_sha/path/to/subfolder) or SSH git URLs (e.g., git@github.com:owner/repo.git). * token (str | None, optional): GitHub Personal Access Token (PAT). Required for private repositories and recommended for public repositories to raise the GitHub API rate limit from 60 to 5,000 requests per hour. Defaults to None. * max_file_size (int, optional): Maximum permissible file size in bytes to download and parse. Defaults to 1048576 (1 MB). * use_relative_paths (bool, optional): When True, output dictionary keys will be relative to the queried subdirectory rather than the root repository path. Defaults to False. * include_patterns (str | set[str] | None, optional): A glob pattern or set of glob patterns (e.g., {"*.py", "*.md"}) specifying files to include. If None, all discovered text files are candidates for inclusion. Defaults to None. * exclude_patterns (str | set[str] | None, optional): A glob pattern or set of glob patterns to exclude from ingestion (e.g., {"tests/*", "*.lock"}). Defaults to None.

    Returns: * dict: A dictionary containing: * "files" (dict[str, str]): Mapping of file paths to their string contents decoded as UTF-8. * "stats" (dict): Crawl statistics including "downloaded_count", "skipped_count", "skipped_files", "base_path", "include_patterns", "exclude_patterns", and optional "source".

    Raises: * ValueError: If the provided HTTPS GitHub URL is malformed or lacks sufficient path components (requires at least owner and repo). * Exception: If GitHub API rate limits are exceeded and no token is supplied to authorize higher quotas or retry routines.

    should_include_file()

    Visibility: Private (Internal closure inside crawl_github_files)
    Signature: def should_include_file(file_path: str, file_name: str, gitignore_spec: pathspec.PathSpec | None = None) -> bool:

    Description:
    Evaluates whether a target file should be processed based on three sequential filter layers: 1. Inclusion check: If include_patterns is populated, the file's basename (file_name) must match at least one glob pattern using fnmatch.fnmatch. 2. Gitignore check: If a gitignore_spec is provided, the full relative file_path is evaluated. If it matches a gitignore rule, it is immediately rejected. 3. Exclusion check: If exclude_patterns is populated, the full relative file_path is tested against the exclude glob patterns. If a match occurs, the file is rejected.

    Parameters: * file_path (str): The full relative path of the file from the root/subpath of the crawl. * file_name (str): The trailing basename of the file (e.g., main.py). * gitignore_spec (pathspec.PathSpec | None, optional): Compiled pathspec object containing repository .gitignore match rules. Defaults to None.

    Returns: * bool: True if the file satisfies all inclusion conditions and violates no exclusion or gitignore rules; otherwise False.

    Core Implementation Logic: 

        def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:
        """Determine if a file should be included based on patterns"""
        # If no include patterns are specified, include all files
        if not include_patterns:
            include_file = True
        else:
            # Check if file matches any include pattern
            include_file = any(fnmatch.fnmatch(file_name, pattern) for pattern in include_patterns)

        # Check gitignore if provided
        if include_file and gitignore_spec and gitignore_spec.match_file(file_path):
            return False

        # If exclude patterns are specified, check if file should be excluded
        if exclude_patterns and include_file:
            # Exclude if file matches any exclude pattern
            exclude_file = any(fnmatch.fnmatch(file_path, pattern) for pattern in exclude_patterns)
            return not exclude_file

        return include_file

    should_include_file provides filtering across both SSH and REST API traversal paths. A key detail is that include_patterns tests against the file's leaf name (file_name), whereas exclude_patterns and gitignore_spec evaluate against the full relative path (file_path).

    Example: 

    # Check include/exclude patterns
if not should_include_file(rel_path, filename, gitignore_spec=gitignore_spec):
    count_excluded += 1
    print(f"{C_GRAY}  [{entry_num}] {rel_path} [excluded]{C_RESET}")
    continue

    fetch_branches()

    Visibility: Private (Internal closure inside crawl_github_files)
    Signature: def fetch_branches(owner: str, repo: str) -> list[dict]:

    Description:
    Queries the GitHub REST API endpoint GET /repos/{owner}/{repo}/branches to list available remote branches for the specified repository. Handles HTTP status codes, alerting users to missing repositories, private access requirements, and rate-limiting thresholds.

    Parameters: * owner (str): GitHub repository owner or organization name. * repo (str): GitHub repository name.

    Returns: * list[dict]: List of branch representation dictionaries returned by the GitHub API. Returns an empty list [] if the API call fails or the repository is inaccessible.

    Raises: * Exception: If rate limits are exceeded (HTTP 403 or 429) and no authentication token is provided in the session headers.

    Core Implementation Logic: 

        def fetch_branches(owner: str, repo: str):
        """Get brancshes of the repository"""

        url = f"https://api.github.com/repos/{owner}/{repo}/branches"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        if response.status_code == 404:
            if not token:
                print(
                    "Error 404: Repository not found or is private.\n"
                    "If this is a private repository, please provide a valid GitHub token via the 'token' argument or set the GITHUB_TOKEN environment variable."
                )
            else:
                print(
                    "Error 404: Repository not found or insufficient permissions with the provided token.\n"
                    "Please verify the repository exists and the token has access to this repository."
                )
            return []

        if response.status_code != 200:
            print(f"Error fetching the branches of {owner}/{repo}: {response.status_code} - {response.text}")
            return []

        return response.json()

    The function handles edge cases surrounding repository discovery. When encountering an HTTP 404, it distinguishes between unauthenticated requests (prompting the user to supply a token for private access) and authenticated requests (indicating either non-existence or insufficient token scopes). A standard connect/read timeout of (30, 30) seconds is enforced to avoid hanging network connections.

    Example:

# Fetching branches is not successfully

    return None

    check_tree()

    Visibility: Private (Internal closure inside crawl_github_files)
    Signature: def check_tree(owner: str, repo: str, tree: str) -> bool:

    Description:
    Validates whether a specific Git tree, tag, or commit SHA exists in the remote repository by querying GET /repos/{owner}/{repo}/git/trees/{tree}. Used when URL path parsing cannot match the URL reference against named branches, allowing direct commits and detached tree SHAs to be crawled.

    Parameters: * owner (str): GitHub repository owner or organization name. * repo (str): GitHub repository name. * tree (str): Git commit SHA, tree SHA, or tag name extracted from the URL.

    Returns: * bool: True if the tree object exists (HTTP status 200), otherwise False.

    Raises: * Exception: If rate limits are exceeded (HTTP 403 or 429) without an authorization token.

    Core Implementation Logic: 

        def check_tree(owner: str, repo: str, tree: str):
        """Check the repository has the given tree"""

        url = f"https://api.github.com/repos/{owner}/{repo}/git/trees/{tree}"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        return response.status_code == 200

    check_tree distinguishes between named branches and direct commit hashes. Because URLs like /tree/6c38dc.../subpath contain raw commit SHAs rather than branch names, branch name resolution fails first; check_tree validates the SHA before attempting to crawl subdirectory paths under that commit.

    Example:

    fetch_contents()

    Visibility: Private (Internal closure inside crawl_github_files)
    Signature: def fetch_contents(path: str) -> None:

    Description:
    Recursively traverses directory trees and downloads file contents from the GitHub repository starting at path.

    For directories (type == "dir"), it checks exclusion rules and .gitignore matches before recursing. For files (type == "file"), it verifies pattern compliance, evaluates size metadata against max_file_size, and retrieves raw contents via download_url or downloads and Base64-decodes the payload from the content endpoint. Handles rate-limiting by parsing X-RateLimit-Reset and sleeping until the quota resets.

    Parameters: * path (str): Subdirectory or file path within the repository relative to the root or specified branch/ref.

    Returns: * None: Mutates the outer files, api_counters, api_skipped_size, and api_skipped_non_text data structures directly.

    Raises: * Exception: If an unauthenticated rate limit is encountered (HTTP 403 or 429 with rate limit exceeded).

    Core Implementation Logic: 

        def fetch_contents(path):
        """Fetch contents of the repository at a specific path and commit"""
        url = f"https://api.github.com/repos/{owner}/{repo}/contents/{path}"
        params = {"ref": ref} if ref is not None else {}

        response = requests.get(url, headers=headers, params=params, timeout=(30, 30))

        if response.status_code in (403, 429) and "rate limit exceeded" in response.text.lower():
            if not token:
                raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")
            reset_time = int(response.headers.get("X-RateLimit-Reset", 0))
            wait_time = max(reset_time - time.time(), 0) + 1
            print(f"Rate limit exceeded. Waiting for {wait_time:.0f} seconds...")
            time.sleep(wait_time)
            return fetch_contents(path)

        # ... [404 and error response handling] ...

        contents = response.json()
        if not isinstance(contents, list):
            contents = [contents]

        for item in contents:
            item_path = item["path"]
            # ... [Path relativity adjustment and file filtering] ...

            if item["type"] == "file":
                # ... [Size checks, raw download_url or Base64 fallback] ...
                if item.get("download_url"):
                    file_response = requests.get(item["download_url"], headers=headers, timeout=(30, 30))
                    if file_response.status_code == 200:
                        files[rel_path] = file_response.text
                        api_counters["processed"] += 1
            elif item["type"] == "dir":
                # ... [Directory pattern & gitignore exclusion checks] ...
                fetch_contents(item_path)

        return None

    fetch_contents normalizes single-item payloads (returned when querying a direct file path) into a list to share the iteration pipeline with directory responses. When downloading files, it validates payload sizes before fetching raw content or decoding Base64 strings (calculating len(content) * 0.75 as a memory safety check).

    Example: 

    # Start crawling from the specified path
fetch_contents(specific_path)

    Standalone Execution Block

    The module includes an executable entry point (if __name__ == "__main__":) that demonstrates usage against public or private GitHub repositories.

    if __name__ == "__main__":
    # Get token from environment variable (recommended for private repos)
    github_token = os.environ.get("GITHUB_TOKEN")
    if not github_token:
        print(
            "Warning: No GitHub token found in environment variable 'GITHUB_TOKEN'.\n"
            "Private repositories will not be accessible without a token.\n"
            "To access private repos, set the environment variable or pass the token explicitly."
        )

    repo_url = "https://github.com/pydantic/pydantic/tree/6c38dc93f40a47f4d1350adca9ec0d72502e223f/pydantic"

    # Example: Get Python and Markdown files, but exclude test files
    result = crawl_github_files(
        repo_url,
        token=github_token,
        max_file_size=1 * 1024 * 1024,  # 1 MB in bytes
        use_relative_paths=True,  # Enable relative paths
        include_patterns={"*.py", "*.md"},  # Include Python and Markdown files
    )

    files = result["files"]
    stats = result["stats"]

    print(f"\nDownloaded {stats['downloaded_count']} files.")
    print(f"Skipped {stats['skipped_count']} files due to size limits or patterns.")
    print(f"Base path for relative paths: {stats['base_path']}")
    print(f"Include patterns: {stats['include_patterns']}")
    print(f"Exclude patterns: {stats['exclude_patterns']}")

    # Display all file paths in the dictionary
    print("\nFiles in dictionary:")
    for file_path in sorted(files.keys()):
        print(f"  {file_path}")

    # Example: accessing content of a specific file
    if files:
        sample_file = next(iter(files))
        print(f"\nSample file: {sample_file}")
        print(f"Content preview: {files[sample_file][:200]}...")

    The execution block checks for a GITHUB_TOKEN environment variable, invokes crawl_github_files with pattern filters ({"*.py", "*.md"}), enables relative paths, and outputs ingestion statistics and a sample file preview to the console.
