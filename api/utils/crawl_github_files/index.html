    utils.crawl_github_files

    utils/crawl_github_files.py

    Following the LLM execution utilities documented in utils.call_llm, this module provides repository extraction utilities for fetching source files directly from GitHub. It serves as an ingestion mechanism for remote codebases, retrieving files and directory structures across branches, tags, specific commits, or subdirectories.

    Technical Overview

    The utils.crawl_github_files module ingests source code from remote GitHub repositories through two distinct retrieval strategies:

    1. SSH Git Clone Strategy: When provided an SSH URL (starting with git@ or ending with .git), the module clones the repository into a temporary directory via git.Repo.clone_from. It then parses .gitignore rules with pathspec.PathSpec and performs a local filesystem walk.
    2. GitHub REST API Strategy: When provided an HTTPS repository URL, the module parses repository components (owner, repo, branch/tree ref, and specific subdirectory path) via urllib.parse.urlparse. It queries GitHub's REST API endpoints (/repos/{owner}/{repo}/contents, /branches, and /git/trees), automatically handles rate limits (403/429 with X-RateLimit-Reset backoff), resolves .gitignore rules, and recursively crawls files and subdirectories.

    crawl_github_files()

    Visibility: Public
    Signature: def crawl_github_files(repo_url: str, token: str | None = None, max_file_size: int = 1 * 1024 * 1024, use_relative_paths: bool = False, include_patterns: str | set[str] | None = None, exclude_patterns: str | set[str] | None = None) -> dict:

    Description: Crawls files from a specific GitHub repository path or commit using either local SSH cloning or GitHub REST API traversal. The function filters files according to size thresholds, include/exclude glob patterns, and .gitignore specifications, returning an in-memory dictionary of relative paths mapped to decoded text content along with detailed crawler statistics.

    Parameters: * repo_url (str): URL of the GitHub repository, optionally containing branch, commit, and subdirectory paths (e.g., https://github.com/microsoft/autogen/tree/e45a15766746d95f8cfaaa705b0371267bec812e/python/packages/autogen-core/src/autogen_core or git@github.com:user/repo.git). * token (str | None, optional): GitHub Personal Access Token (PAT). Required for private repositories and recommended for public repositories to avoid rate limits. Defaults to None. * max_file_size (int, optional): Maximum allowed file size in bytes to download. Files exceeding this threshold are skipped. Defaults to 1048576 (1 MB). * use_relative_paths (bool, optional): When True, returns dictionary keys relative to the specified subdirectory instead of the repository root. Defaults to False. * include_patterns (str | set[str] | None, optional): Glob pattern(s) specifying files to include (e.g., "*.py", {"*.md", "*.txt"}). Defaults to None (all files). * exclude_patterns (str | set[str] | None, optional): Glob pattern(s) specifying files or directories to ignore. Defaults to None.

    Returns: * dict: A dictionary containing: * "files" (dict[str, str]): Mapping of relative file paths to their string content. * "stats" (dict[str, Any]): Crawling metadata containing downloaded_count, skipped_count, skipped_files, base_path, include_patterns, exclude_patterns, and optionally source.

    The function checks the format of repo_url to branch between the SSH clone strategy and the REST API crawler. For SSH URLs, it provisions a temporary directory via tempfile.TemporaryDirectory, invokes git.Repo.clone_from, and parses any repository-level .gitignore file using pathspec.PathSpec.from_lines("gitwildmatch", ...). It then walks the local filesystem while pruning excluded directories from dirs in-place, reading valid text files with utf-8-sig encoding and collecting size/text-validation error statistics.

    should_include_file()

    Visibility: Private (nested helper within crawl_github_files)
    Signature: def should_include_file(file_path: str, file_name: str, gitignore_spec: pathspec.PathSpec | None = None) -> bool:

    Description: Evaluates whether a candidate file matches the active inclusion patterns, passes .gitignore path specification rules, and is not rejected by explicit exclusion patterns.

    Parameters: * file_path (str): Relative file path from the repository or target subdirectory root. * file_name (str): Base filename (used for fnmatch matching against include_patterns). * gitignore_spec (pathspec.PathSpec | None, optional): Compiled gitignore path specification. Defaults to None.

    Returns: * bool: True if the file passes all inclusion, gitignore, and exclusion checks; False otherwise.

    Implementation Logic: 

        def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:
        """Determine if a file should be included based on patterns"""
        # If no include patterns are specified, include all files
        if not include_patterns:
            include_file = True
        else:
            # Check if file matches any include pattern
            include_file = any(fnmatch.fnmatch(file_name, pattern) for pattern in include_patterns)

        # Check gitignore if provided
        if include_file and gitignore_spec and gitignore_spec.match_file(file_path):
            return False

        # If exclude patterns are specified, check if file should be excluded
        if exclude_patterns and include_file:
            # Exclude if file matches any exclude pattern
            exclude_file = any(fnmatch.fnmatch(file_path, pattern) for pattern in exclude_patterns)
            return not exclude_file

        return include_file

    The filtering algorithm applies a three-stage filter. First, if include_patterns is populated, the base file_name must match at least one glob pattern using fnmatch.fnmatch. Second, if a compiled gitignore_spec exists and matches the file_path, the candidate is immediately rejected. Third, if exclude_patterns is present, the full file_path is evaluated against each pattern; any match results in rejection.

    Example: 

    # Invocation inside crawl_github_files during traversal:
if not should_include_file(rel_path, filename, gitignore_spec=gitignore_spec):
    count_excluded += 1
    print(f"{C_GRAY}  [{entry_num}] {rel_path} [excluded]{C_RESET}")
    continue

    fetch_branches()

    Visibility: Private (nested helper within crawl_github_files)
    Signature: def fetch_branches(owner: str, repo: str) -> list[dict]:

    Description: Retrieves the list of active branch objects for the target repository via the GitHub REST API (/repos/{owner}/{repo}/branches). Handles unauthenticated rate limits and repository access errors.

    Parameters: * owner (str): GitHub repository owner (user or organization). * repo (str): GitHub repository name.

    Returns: * list[dict]: List of branch dictionaries returned by the GitHub API, or an empty list [] if the request fails or is unauthorized.

    Raises: * Exception: If GitHub API rate limits (HTTP 403 or 429) are encountered and no authorization token was supplied.

    Implementation Logic: 

        def fetch_branches(owner: str, repo: str):
        """Get brancshes of the repository"""

        url = f"https://api.github.com/repos/{owner}/{repo}/branches"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        if response.status_code == 404:
            if not token:
                print(
                    "Error 404: Repository not found or is private.\n"
                    "If this is a private repository, please provide a valid GitHub token via the 'token' argument or set the GITHUB_TOKEN environment variable."
                )
            else:
                print(
                    "Error 404: Repository not found or insufficient permissions with the provided token.\n"
                    "Please verify the repository exists and the token has access to this repository."
                )
            return []

        if response.status_code != 200:
            print(f"Error fetching the branches of {owner}/{repo}: {response.status_code} - {response.text}")
            return []

        return response.json()

    The function executes a requests.get call targeting the repository branches endpoint with a 30-second connect/read timeout. If an HTTP 403 or 429 error occurs in the absence of a PAT token, it raises an explicit exception alerting the caller to rate limits. When encountering 404 responses, it prints diagnostic guidance distinguishing between private repository visibility and permission failures before returning an empty list.

    Example:

branches = fetch_branches(owner, repo)
branch_names = (branch.get("name") for branch in branches)

# Fetching branches is not successfully
if len(branches) == 0:
    return None

    Parameters: * owner (str): GitHub repository owner. * repo (str): GitHub repository name. * tree (str): Git commit SHA or tree SHA to validate.

    Returns: * bool: True if the tree exists (HTTP 200 status); False otherwise.

    Implementation Logic: 

        def check_tree(owner: str, repo: str, tree: str):
        """Check the repository has the given tree"""

        url = f"https://api.github.com/repos/{owner}/{repo}/git/trees/{tree}"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        return response.status_code == 200

    This helper performs a lightweight HTTP check against the Git Trees API to distinguish commit/tree SHAs from multi-part branch names when parsing URLs with /tree/{ref}/.... A 200 response confirms the tree object's existence on the remote repository.

    fetch_contents()

    Visibility: Private (nested helper within crawl_github_files)
    Signature: def fetch_contents(path: str) -> None:

    Description: Recursively navigates GitHub repository directory structures at a specific path and commit reference. Downloads raw text content for matching files and traverses child directories.

    Parameters: * path (str): Subdirectory or file path within the repository to fetch.

    Returns: * None: Mutates the enclosing files, skipped_files, and api_counters state structures.

    Raises: * Exception: If unauthenticated rate limits are encountered.

    Implementation Logic: 

        def fetch_contents(path):
        """Fetch contents of the repository at a specific path and commit"""
        url = f"https://api.github.com/repos/{owner}/{repo}/contents/{path}"
        params = {"ref": ref} if ref is not None else {}

        response = requests.get(url, headers=headers, params=params, timeout=(30, 30))

        if response.status_code in (403, 429) and "rate limit exceeded" in response.text.lower():
            if not token:
                raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")
            reset_time = int(response.headers.get("X-RateLimit-Reset", 0))
            wait_time = max(reset_time - time.time(), 0) + 1
            print(f"Rate limit exceeded. Waiting for {wait_time:.0f} seconds...")
            time.sleep(wait_time)
            return fetch_contents(path)

        # ... Directory recursion and file download logic ...

    When fetch_contents encounters authenticated rate limits (HTTP 403/429), it calculates the remaining wait time from the X-RateLimit-Reset HTTP header, sleeps using time.sleep, and retries the request recursively. For each returned item, if type == "dir", it checks directory exclusion rules before initiating recursive calls. If type == "file", it validates size thresholds and attempts to fetch raw file contents via download_url, falling back to base64 decoding of the content field if download_url is unavailable.

    Example: 

        # Start crawling from the specified path
    fetch_contents(specific_path)

    Direct Execution Interface

    When executed as a standalone script (__main__), crawl_github_files.py reads GITHUB_TOKEN from the operating system environment and crawls a predefined sample repository reference (pydantic at a specific commit):

    if __name__ == "__main__":
    # Get token from environment variable (recommended for private repos)
    github_token = os.environ.get("GITHUB_TOKEN")
    if not github_token:
        print(
            "Warning: No GitHub token found in environment variable 'GITHUB_TOKEN'.\n"
            "Private repositories will not be accessible without a token.\n"
            "To access private repos, set the environment variable or pass the token explicitly."
        )

    repo_url = "https://github.com/pydantic/pydantic/tree/6c38dc93f40a47f4d1350adca9ec0d72502e223f/pydantic"

    # Example: Get Python and Markdown files, but exclude test files
    result = crawl_github_files(
        repo_url,
        token=github_token,
        max_file_size=1 * 1024 * 1024,  # 1 MB in bytes
        use_relative_paths=True,  # Enable relative paths
        include_patterns={"*.py", "*.md"},  # Include Python and Markdown files
    )
