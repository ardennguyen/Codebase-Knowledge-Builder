    utils.crawl_github_files

    utils/crawl_github_files.py

    Overview

    The utils.crawl_github_files module provides repository ingestion capabilities for GitHub repositories within the Codebase-Knowledge-Builder architecture. It is designed to extract codebase contents across public and private repositories, handling two distinct ingestion paths based on the input URL format:

    1. SSH Git Cloning Mode: Activated when the target URL starts with git@ or ends with .git. It clones the repository into an isolated temporary directory via GitPython (git.Repo.clone_from), walks the local directory structure, enforces file inclusion/exclusion and .gitignore rules using pathspec, and reads text content directly from disk.
    2. GitHub REST API Mode: Activated for standard HTTP/HTTPS URLs (e.g., https://github.com/owner/repo/tree/ref/path). It parses the URL into structural components (owner, repository name, branch or tree SHA, and targeted subdirectory path). It queries the GitHub REST API (/repos/{owner}/{repo}/contents/{path}), handles dynamic branch and commit tree resolution, fetches repository-level .gitignore rules, performs automatic rate-limit backoff using HTTP headers (X-RateLimit-Reset), and downloads raw or base64-encoded file payloads.

    Both paths enforce strict file size filtering (max_file_size), text-encoding checks (handling UTF-8 with BOM and binary file detection), glob pattern matching via fnmatch, path rebasing (use_relative_paths), and return a normalized dictionary mapping file paths to their string contents alongside crawl statistics.

    Module-Level Functions

    crawl_github_files()

    Visibility: Public
    Signature: def crawl_github_files(repo_url, token=None, max_file_size: int = 1 * 1024 * 1024, use_relative_paths: bool = False, include_patterns: str | set[str] | None = None, exclude_patterns: str | set[str] | None = None) -> dict:

    Description: Serves as the primary public entry point for extracting text files from a remote GitHub repository. The function standardizes pattern collections, detects whether to utilize SSH cloning or the GitHub REST API, evaluates inclusion/exclusion patterns alongside .gitignore path specifications, downloads or reads files under the size threshold, and compiles a comprehensive execution summary.

    Parameters: * repo_url (str): The remote URL of the GitHub repository. Supports full HTTPS tree paths (e.g., https://github.com/microsoft/autogen/tree/commit_hash/sub/path) or SSH URLs (e.g., git@github.com:owner/repo.git). * token (str, optional): GitHub personal access token used to authorize private repository access and lift public REST API rate limits. Defaults to None. * max_file_size (int, optional): Maximum allowed size in bytes per file (default is 1 MB: 1048576 bytes). Files exceeding this limit are skipped. * use_relative_paths (bool, optional): When True, returns dictionary keys stripped of the leading subdirectory path specified in the URL. Defaults to False. * include_patterns (str | set[str] | None, optional): Glob pattern or set of glob patterns (e.g., "*.py", {"*.md", "*.txt"}) indicating which file names should be retained. If None, all files are candidates. * exclude_patterns (str | set[str] | None, optional): Glob pattern or set of glob patterns indicating which file or directory paths should be skipped.

    Returns: * dict: A dictionary containing two keys: * "files" (dict[str, str]): Mapping of resolved file paths to their decoded string file content. * "stats" (dict): Execution metadata containing counts of downloaded files, skipped files, active filter patterns, and base path configurations.

    Raises: * ValueError: Raised if the provided HTTP URL cannot be split into at least owner and repo components. * Exception: Raised when GitHub API rate limits are hit without an authorization token provided.

    Example: 

    # Extract from example usage in utils/crawl_github_files.py
repo_url = "https://github.com/pydantic/pydantic/tree/6c38dc93f40a47f4d1350adca9ec0d72502e223f/pydantic"

result = crawl_github_files(
    repo_url,
    token=github_token,
    max_file_size=1 * 1024 * 1024,  # 1 MB in bytes
    use_relative_paths=True,  # Enable relative paths
    include_patterns={"*.py", "*.md"},  # Include Python and Markdown files
)

files = result["files"]
stats = result["stats"]

    The function normalizes inputs into sets, sets up pattern matching closures, and dynamically routes between temporary disk cloning via Git and in-memory REST API tree traversal. When operating in REST API mode, it resolves branch names and commit SHAs dynamically, falling back to repository defaults when no tree parameters are supplied in the URL.

    should_include_file()

    Visibility: Private / Internal Helper (nested within crawl_github_files)
    Signature: def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:

    Description: Evaluates whether a candidate file matches the current execution criteria based on file name glob inclusions, repository .gitignore specifications, and explicit path exclusions.

    Parameters: * file_path (str): The relative path of the file within the repository or cloned working tree. * file_name (str): The base name of the file (e.g., main.py). * gitignore_spec (pathspec.PathSpec, optional): Compiled gitignore rules specifier instantiated using pathspec.PathSpec.from_lines('gitwildmatch', ...). Defaults to None.

    Returns: * bool: True if the file satisfies include filters, does not match .gitignore, and is not excluded by exclude_patterns; otherwise False.

    Example: 

        def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:
        """Determine if a file should be included based on patterns"""
        # If no include patterns are specified, include all files
        if not include_patterns:
            include_file = True
        else:
            # Check if file matches any include pattern
            include_file = any(fnmatch.fnmatch(file_name, pattern) for pattern in include_patterns)

        # Check gitignore if provided
        if include_file and gitignore_spec and gitignore_spec.match_file(file_path):
            return False

        # If exclude patterns are specified, check if file should be excluded
        if exclude_patterns and include_file:
            # Exclude if file matches any exclude pattern
            exclude_file = any(fnmatch.fnmatch(file_path, pattern) for pattern in exclude_patterns)
            return not exclude_file

        return include_file

    The inclusion evaluation follows a three-stage gating sequence. First, if include_patterns is populated, the file's basename must match at least one pattern via fnmatch.fnmatch. Second, if a compiled gitignore_spec is provided, gitignore_spec.match_file(file_path) checks the full relative path; any match immediately disqualifies the file. Finally, if exclude_patterns is defined, the full relative path is matched against all exclusion globs.

    fetch_branches()

    Visibility: Private / Internal Helper (nested within crawl_github_files)
    Signature: def fetch_branches(owner: str, repo: str) -> list[dict]:

    Description: Queries the GitHub REST API endpoint /repos/{owner}/{repo}/branches to obtain a list of all remote branches available on the target repository. This information is used to match multi-part branch names (e.g., feature/branch-name) present within complex repository URLs.

    Parameters: * owner (str): The GitHub account or organization name hosting the repository. * repo (str): The repository name.

    Returns: * list[dict]: A list of branch descriptor dictionaries returned by GitHub's API, or an empty list [] if the repository was not found or an HTTP error occurred.

    Raises: * Exception: Raised if HTTP status code 403 or 429 is received and no GitHub token was configured.

    Example: 

        def fetch_branches(owner: str, repo: str):
        """Get brancshes of the repository"""

        url = f"https://api.github.com/repos/{owner}/{repo}/branches"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        if response.status_code == 404:
            if not token:
                print(
                    "Error 404: Repository not found or is private.\n"
                    "If this is a private repository, please provide a valid GitHub token via the 'token' argument or set the GITHUB_TOKEN environment variable."
                )
            else:
                print(
                    "Error 404: Repository not found or insufficient permissions with the provided token.\n"
                    "Please verify the repository exists and the token has access to this repository."
                )
            return []

        if response.status_code != 200:
            print(f"Error fetching the branches of {owner}/{repo}: {response.status_code} - {response.text}")
            return []

        return response.json()

    The function transmits an authorized GET request with a strict 30-second connection and read timeout. It verifies status codes, explicitly separating rate-limit exhaustion (403/429), missing or unauthorized repositories (404), and general server or network errors before parsing JSON results.

    check_tree()

    Visibility: Private / Internal Helper (nested within crawl_github_files)
    Signature: def check_tree(owner: str, repo: str, tree: str) -> bool:

    Description: Verifies whether a given commit SHA or Git tree identifier exists on the remote repository by querying /repos/{owner}/{repo}/git/trees/{tree}.

    Parameters: * owner (str): The GitHub account or organization name. * repo (str): The repository name. * tree (str): The tree SHA, commit hash, or tag to validate.

    Returns: * bool: True if the tree object exists (HTTP status 200); False otherwise.

    Raises: * Exception: Raised when GitHub API rate limits are exceeded in unauthenticated mode.

    Example: 

        def check_tree(owner: str, repo: str, tree: str):
        """Check the repository has the given tree"""

        url = f"https://api.github.com/repos/{owner}/{repo}/git/trees/{tree}"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        return response.status_code == 200

    This helper handles scenarios where a URL points directly to an immutable Git tree or commit SHA rather than a named branch (e.g., /tree/e45a15766746...). By checking the Git Trees API directly, it validates commit-specific checkouts without having to iterate through all repository branches.

    The function serves as a utility during URL segment resolution.     fetch_contents()

    Visibility: Private / Internal Helper (nested within crawl_github_files)
    Signature: def fetch_contents(path: str) -> None:

    Description: Recursively fetches and processes directory contents and files from the GitHub REST API (/repos/{owner}/{repo}/contents/{path}). It handles rate-limit backoff, skips excluded directories and oversized files, downloads raw file contents via download_url or decodes base64 content blocks, and populates the outer files dictionary.

    Parameters: * path (str): Repository-relative subdirectory or file path to query against the GitHub Contents API.

    Returns: * None: Mutates the enclosing scope's files dictionary and api_counters state in-place.

    Raises: * Exception: Raised if unauthenticated rate limits are encountered during directory retrieval.

    Example: 

        def fetch_contents(path):
        """Fetch contents of the repository at a specific path and commit"""
        url = f"https://api.github.com/repos/{owner}/{repo}/contents/{path}"
        params = {"ref": ref} if ref is not None else {}

        response = requests.get(url, headers=headers, params=params, timeout=(30, 30))

        if response.status_code in (403, 429) and "rate limit exceeded" in response.text.lower():
            if not token:
                raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")
            reset_time = int(response.headers.get("X-RateLimit-Reset", 0))
            wait_time = max(reset_time - time.time(), 0) + 1
            print(f"Rate limit exceeded. Waiting for {wait_time:.0f} seconds...")
            time.sleep(wait_time)
            return fetch_contents(path)

        if response.status_code == 404:
            // ... [Handle 404 and branch warning messages]
            return None

        if response.status_code != 200:
            print(f"Error fetching {path}: {response.status_code} - {response.text}")
            return None

        contents = response.json()
        if not isinstance(contents, list):
            contents = [contents]

        for item in contents:
            item_path = item["path"]
            // ... [Calculate rel_path, check filters, download raw/base64 content, recurse dirs]

    fetch_contents performs recursive crawling over the GitHub API tree. If a rate limit is reached for an authenticated user, it inspects the X-RateLimit-Reset Unix timestamp from GitHub's response headers, suspends execution via time.sleep, and retries the request automatically upon expiration. For each item returned, if the entry is a directory, it checks inclusion/exclusion patterns before executing a recursive call. If it is a file, it checks file size constraints, issues a download request via download_url (or falls back to decoding base64-encoded strings directly from the JSON metadata), and writes decoded text directly into the outer files dictionary.
