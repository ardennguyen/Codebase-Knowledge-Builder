    utils.crawl_github_files

    Original File Path: utils/crawl_github_files.py

    Technical overview and reference documentation for the remote repository crawling module. This utility provides functionality to traverse, filter, and extract file contents from GitHub repositories via the GitHub REST API or via SSH git clones into temporary directories.

    Technical Overview

    The utils.crawl_github_files module is designed to ingest source code and documentation from GitHub repositories into an in-memory dictionary mapping file paths to their raw string contents. It supports two primary modes of operation depending on the input URL format:

    1. SSH Git Cloning (git@... or .git URLs): Clones the full repository to an OS-managed temporary directory via git.Repo.clone_from, parses local .gitignore files via pathspec, walks the file system tree, filters files by pattern and size, and reads matching UTF-8 text contents into memory.
    2. GitHub REST API Traversal (HTTPS URLs): Parses the URL components (owner, repository name, branch or tree SHA, and subdirectory path), inspects branches and tree objects through https://api.github.com, fetches the remote .gitignore file, and recursively crawls directory contents via contents/{path} endpoints. It includes automatic handling of HTTP rate limiting (403/429) with dynamic sleep backoffs calculated from X-RateLimit-Reset headers.

    Both pipelines perform path filtering via fnmatch, .gitignore pattern resolution via pathspec.PathSpec, binary/non-text file exclusion with fallback decoders, and maximum file size thresholds.

    crawl_github_files()

    Visibility: Public
    Signature: def crawl_github_files(repo_url, token=None, max_file_size: int = 1 * 1024 * 1024, use_relative_paths: bool = False, include_patterns: str | set[str] | None = None, exclude_patterns: str | set[str] | None = None) -> dict:

    Description: Serves as the main entry point for downloading text files from a remote GitHub repository. If an SSH URL (git@ or .git) is provided, the function delegates execution to a local clone workflow inside a tempfile.TemporaryDirectory(). If an HTTPS GitHub URL is provided, it parses URL parts, validates branches/trees via the GitHub REST API, fetches .gitignore rules, and recursively navigates directory trees using fetch_contents().

    Parameters: * repo_url (str): URL of the GitHub repository. Supports full URLs pointing to trees or commits (e.g., https://github.com/owner/repo/tree/commit_hash/path/to/dir) or SSH clone URLs (git@github.com:owner/repo.git). * token (str | None, optional): GitHub personal access token used for authorization headers (Authorization: token <token>). Required for private repositories and recommended to prevent HTTP 403 rate-limiting on public repositories. * max_file_size (int, optional): The maximum allowed file size in bytes. Files exceeding this limit are skipped. Defaults to 1048576 (1 MB). * use_relative_paths (bool, optional): When True, modifies keys in the returned files dictionary to be relative to specific_path rather than the repository root. Defaults to False. * include_patterns (str | set[str] | None, optional): Filename match patterns (e.g., "*.py", {"*.py", "*.md"}) evaluated via fnmatch. If None, all files are candidates for inclusion. * exclude_patterns (str | set[str] | None, optional): Directory or file match patterns to exclude from processing. If None, no pattern-based exclusions are applied.

    Returns: * dict: A dictionary containing: * "files" (dict[str, str]): Mapping of repository file paths to string contents. * "stats" (dict[str, Any]): Execution statistics, including downloaded_count, skipped_count, skipped_files, base_path, include_patterns, exclude_patterns, and optionally source or error.

    Raises: * ValueError: If the HTTPS URL cannot be split into at least two path segments (owner and repository name). * Exception: If a GitHub REST API rate limit is reached (403/429) and no authentication token was supplied.

    The function normalizes include and exclude pattern inputs by wrapping bare strings into single-element sets. If SSH cloning is selected, git.Repo.clone_from writes the repository into tempfile.TemporaryDirectory(). The function loads .gitignore rules using pathspec.PathSpec.from_lines("gitwildmatch", ...) if present at the clone root. It then walks the filesystem using os.walk(), pruning excluded subdirectories in place to avoid unnecessary traversal, and opens text files using the utf-8-sig encoding to strip UTF-8 Byte Order Marks (BOM).

    should_include_file()

    Visibility: Private (nested closure inside crawl_github_files)
    Signature: def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:

    Description: Evaluates whether an individual file meets the inclusion criteria based on the active include_patterns, exclude_patterns, and an optional pathspec.PathSpec gitignore specification.

    Parameters: * file_path (str): Full or relative repository path of the target file. * file_name (str): Base filename (e.g., main.py). * gitignore_spec (pathspec.PathSpec | None, optional): Compiled gitignore pattern matcher.

    Returns: * bool: True if the file matches inclusion criteria and does not match gitignore or exclusion rules; otherwise False.

    Core Implementation: 

        def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:
        """Determine if a file should be included based on patterns"""
        # If no include patterns are specified, include all files
        if not include_patterns:
            include_file = True
        else:
            # Check if file matches any include pattern
            include_file = any(fnmatch.fnmatch(file_name, pattern) for pattern in include_patterns)

        # Check gitignore if provided
        if include_file and gitignore_spec and gitignore_spec.match_file(file_path):
            return False

        # If exclude patterns are specified, check if file should be excluded
        if exclude_patterns and include_file:
            # Exclude if file matches any exclude pattern
            exclude_file = any(fnmatch.fnmatch(file_path, pattern) for pattern in exclude_patterns)
            return not exclude_file

        return include_file

    should_include_file prioritizes positive pattern matching on the file's basename before evaluating negative exclusions against its full path. If include_patterns is set, fnmatch.fnmatch tests file_name. If valid, it verifies that gitignore_spec.match_file(file_path) returns False. Finally, it iterates through exclude_patterns to ensure no negative patterns match file_path.

    fetch_branches()

    Visibility: Private (nested closure inside crawl_github_files)
    Signature: def fetch_branches(owner: str, repo: str) -> list[dict] | list:

    Description: Invokes the GitHub REST API endpoint GET /repos/{owner}/{repo}/branches to list branch objects for the target repository. Used to determine whether URL path components correspond to multi-segment branch names.

    Parameters: * owner (str): GitHub organization or user account name. * repo (str): GitHub repository name.

    Returns: * list[dict] | list: A list of branch descriptor dictionaries returned by GitHub, or an empty list upon failure or 404 response.

    Raises: * Exception: If HTTP status code 403 or 429 is received and no token is set in headers.

    Core Implementation: 

        def fetch_branches(owner: str, repo: str):
        """Get brancshes of the repository"""

        url = f"https://api.github.com/repos/{owner}/{repo}/branches"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        if response.status_code == 404:
            if not token:
                print(
                    "Error 404: Repository not found or is private.\n"
                    "If this is a private repository, please provide a valid GitHub token via the 'token' argument or set the GITHUB_TOKEN environment variable."
                )
            else:
                print(
                    "Error 404: Repository not found or insufficient permissions with the provided token.\n"
                    "Please verify the repository exists and the token has access to this repository."
                )
            return []

        if response.status_code != 200:
            print(f"Error fetching the branches of {owner}/{repo}: {response.status_code} - {response.text}")
            return []

        return response.json()

    The function executes a synchronous requests.get call with 30-second connect and read timeouts. If access fails with a 404, it prints contextual error messages distinguishing between unauthenticated requests to private repos and insufficient token permissions. Non-200 responses return an empty list.

        def check_tree(owner: str, repo: str, tree: str):
        """Check the repository has the given tree"""

        url = f"https://api.github.com/repos/{owner}/{repo}/git/trees/{tree}"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:

    This helper verifies whether arbitrary string identifiers parsed from the URL represent Git commit hashes or tree objects when matching against named branches fails.

    fetch_contents()

    Visibility: Private (nested closure inside crawl_github_files)
    Signature: def fetch_contents(path: str) -> None:

    Description: Recursively crawls files and subdirectories at a given repository path using the GitHub Contents API (GET /repos/{owner}/{repo}/contents/{path}). Handles pagination/lists, inspects file metadata, filters against exclude patterns and .gitignore, performs file downloads via download_url or base64 decoding, and manages rate-limiting backoffs.

    Parameters: * path (str): Repository-relative path to inspect.

    Returns: * None: Populates the outer files dictionary and api_counters dictionaries in-place.

    Raises: * Exception: When unauthenticated API requests hit rate limits.

    Core Implementation: 

        def fetch_contents(path):
        """Fetch contents of the repository at a specific path and commit"""
        url = f"https://api.github.com/repos/{owner}/{repo}/contents/{path}"
        params = {"ref": ref} if ref is not None else {}

        response = requests.get(url, headers=headers, params=params, timeout=(30, 30))

        if response.status_code in (403, 429) and "rate limit exceeded" in response.text.lower():
            if not token:
                raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")
            reset_time = int(response.headers.get("X-RateLimit-Reset", 0))
            wait_time = max(reset_time - time.time(), 0) + 1
            print(f"Rate limit exceeded. Waiting for {wait_time:.0f} seconds...")
            time.sleep(wait_time)
            return fetch_contents(path)

        if response.status_code == 404:
            # ... handles 404 logging ...
            return None

        if response.status_code != 200:
            print(f"Error fetching {path}: {response.status_code} - {response.text}")
            return None

        contents = response.json()
        if not isinstance(contents, list):
            contents = [contents]

        for item in contents:
            item_path = item["path"]
            # ... checks path, directory exclusions, file size limits, and downloads content ...

    fetch_contents traverses remote directory trees by evaluating each element returned by the contents API. If an item has type == "dir", it checks directory patterns against .gitignore and exclude_patterns (accounting for trailing /* definitions) before calling fetch_contents(item_path).

    For items where type == "file", it checks pattern compliance via should_include_file and verifies item["size"] <= max_file_size. It prefers fetching raw text through item["download_url"]. If download_url is unavailable, it queries item["url"] and decodes base64-encoded file payloads, recording non-text or binary decoding failures into api_counters["non_text"].
