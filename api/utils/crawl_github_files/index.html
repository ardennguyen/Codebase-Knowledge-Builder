    utils.crawl_github_files

    Original File Path: utils/crawl_github_files.py

    Overview

    The utils.crawl_github_files module provides comprehensive crawling and extraction mechanisms for remote GitHub repositories. It serves as one of the primary ingestion pipelines for the Codebase-Knowledge-Builder system. The module supports two primary ingestion pathways:

    1. SSH Git Clone Path: Triggered when the repository URL uses SSH syntax (starts with git@ or ends with .git). It clones the remote repository to a local temporary directory via GitPython (git.Repo.clone_from), parses any top-level .gitignore via pathspec, evaluates glob pattern inclusions/exclusions, and reads matching text files from disk.
    2. GitHub REST API Path: Triggered for standard GitHub HTTP/HTTPS URLs (including tree/branch/subdirectory URLs). It communicates directly with the GitHub REST API v3 to inspect commits, resolve branches/trees, download repository trees, handle API rate limiting with automatic sleep/retry backoff, and retrieve file contents via direct download URLs or base64-encoded JSON blobs.

    Both pathways normalize results into a dictionary mapping relative file paths to their raw string contents, along with metadata statistics describing total processed, excluded, and skipped files.

    should_include_file()

    Visibility: Private (Closure Helper)
    Signature: 

    def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:

    Description: Evaluates whether a specific file should be accepted for processing based on glob patterns and Git ignore specifications. The function checks three consecutive filtering stages: 1. Validates the file_name against include_patterns (if defined) using fnmatch.fnmatch. 2. Evaluates the full relative file_path against gitignore_spec via pathspec.PathSpec.match_file. 3. Evaluates the full relative file_path against exclude_patterns (if defined) using fnmatch.fnmatch.

    Parameters: * file_path (str): The relative path of the file within the repository. * file_name (str): The base name of the file (e.g., main.py). * gitignore_spec (pathspec.PathSpec | None, optional): A compiled PathSpec instance containing gitignore wildmatch rules. Defaults to None.

    Returns: * bool: True if the file passes inclusion checks and does not hit gitignore or exclusion rules; False otherwise.

    Core Implementation: 

        def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:
        """Determine if a file should be included based on patterns"""
        # If no include patterns are specified, include all files
        if not include_patterns:
            include_file = True
        else:
            # Check if file matches any include pattern
            include_file = any(fnmatch.fnmatch(file_name, pattern) for pattern in include_patterns)

        # Check gitignore if provided
        if include_file and gitignore_spec and gitignore_spec.match_file(file_path):
            return False

        # If exclude patterns are specified, check if file should be excluded
        if exclude_patterns and include_file:
            # Exclude if file matches any exclude pattern
            exclude_file = any(fnmatch.fnmatch(file_path, pattern) for pattern in exclude_patterns)
            return not exclude_file

        return include_file

    The matching precedence enforces that files must first satisfy positive inclusion criteria before negative exclusion criteria are evaluated. Notice that include_patterns matches strictly against the base file_name, whereas gitignore_spec and exclude_patterns evaluate against the full relative file_path. This allows users to include all *.py files while excluding nested subdirectories matching tests/*.

    fetch_branches()

    Visibility: Private (Closure Helper)
    Signature: 

    def fetch_branches(owner: str, repo: str) -> list[dict]:

    Description: Queries the GitHub API endpoint GET /repos/{owner}/{repo}/branches to list all branches available in the target repository. This is used during URL parsing to determine if a /tree/<ref>/... URL component refers to a named branch (including branches with slashes in their names such as feature/auth).

    Parameters: * owner (str): The GitHub account or organization name. * repo (str): The GitHub repository name.

    Returns: * list[dict]: A list of branch metadata dictionaries returned by the GitHub REST API. Returns an empty list [] on HTTP error status codes (404, etc.).

    Raises: * Exception: If HTTP status 403 or 429 is received without an authenticated token, indicating API rate limit exhaustion.

    Core Implementation: 

        def fetch_branches(owner: str, repo: str):
        """Get brancshes of the repository"""

        url = f"https://api.github.com/repos/{owner}/{repo}/branches"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        if response.status_code == 404:
            if not token:
                print(
                    "Error 404: Repository not found or is private.\n"
                    "If this is a private repository, please provide a valid GitHub token via the 'token' argument or set the GITHUB_TOKEN environment variable."
                )
            else:
                print(
                    "Error 404: Repository not found or insufficient permissions with the provided token.\n"
                    "Please verify the repository exists and the token has access to this repository."
                )
            return []

        if response.status_code != 200:
            print(f"Error fetching the branches of {owner}/{repo}: {response.status_code} - {response.text}")
            return []

        return response.json()

    The function incorporates custom handling for HTTP 404 and rate limiting errors. When an unauthenticated client receives a rate limit status (403 or 429), an explicit exception is raised advising the user to pass a token. For 404 errors, diagnostic messages distinguish between missing private repository credentials and missing public resources.

    Core Implementation: 

        def check_tree(owner: str, repo: str, tree: str):
        """Check the repository has the given tree"""

        url = f"https://api.github.com/repos/{owner}/{repo}/git/trees/{tree}"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:

    This helper handles commit SHA references embedded inside GitHub browser URLs (e.g., /tree/6c38dc93f40a47f4d1350adca9ec0d72502e223f/...). If branch resolution fails in crawl_github_files(), check_tree validates whether the path component represents a commit or git tree SHA.

    fetch_contents()

    Visibility: Private (Closure Helper)
    Signature: 

    def fetch_contents(path: str) -> None:

    Description: Recursively traverses repository folders and retrieves file contents via GitHub's Contents API (GET /repos/{owner}/{repo}/contents/{path}). It handles directory recursion, exclusion pruning, rate limit backoff, size validation, and content decoding.

    sequenceDiagram
    autonumber
    participant Crawler as fetch_contents(path)
    participant GH_API as GitHub Contents API
    participant RawHost as Raw Download Host

    Crawler->>GH_API: GET /repos/{owner}/{repo}/contents/{path}?ref={ref}
    alt HTTP 403 / 429 Rate Limit
        GH_API-->>Crawler: Rate limit response + X-RateLimit-Reset
        Crawler->>Crawler: sleep(wait_time)
        Crawler->>GH_API: Retry GET /contents/{path}
    end
    GH_API-->>Crawler: JSON response (file item or dir list)

    loop For each item in response
        alt item[type] == 'dir'
            Crawler->>Crawler: Evaluate dir against exclude_patterns & .gitignore
            opt Not Excluded
                Crawler->>Crawler: fetch_contents(item[path])
            end
        else item[type] == 'file'
            Crawler->>Crawler: should_include_file(rel_path, name)
            opt File Included & Size <= max_file_size
                alt item[download_url] exists
                    Crawler->>RawHost: GET item[download_url]
                    RawHost-->>Crawler: Raw text
                    Crawler->>Crawler: Store in files[rel_path]
                else base64 content in payload
                    Crawler->>Crawler: base64.b64decode(content)
                    Crawler->>Crawler: Store in files[rel_path]
                end
            end
        end
    end

    Parameters: * path (str): Repository directory path to inspect. An empty string ("") targets the repository root.

    Returns: * None: Mutates the enclosing files, api_counters, api_skipped_size, and api_skipped_non_text data structures directly.

    Raises: * Exception: If rate limits are exceeded while unauthenticated.

    Core Implementation: 

        def fetch_contents(path):
        """Fetch contents of the repository at a specific path and commit"""
        url = f"https://api.github.com/repos/{owner}/{repo}/contents/{path}"
        params = {"ref": ref} if ref is not None else {}

        response = requests.get(url, headers=headers, params=params, timeout=(30, 30))

        if response.status_code in (403, 429) and "rate limit exceeded" in response.text.lower():
            if not token:
                raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")
            reset_time = int(response.headers.get("X-RateLimit-Reset", 0))
            wait_time = max(reset_time - time.time(), 0) + 1
            print(f"Rate limit exceeded. Waiting for {wait_time:.0f} seconds...")
            time.sleep(wait_time)
            return fetch_contents(path)

        # ... [HTTP 404 / error checks] ...

        contents = response.json()
        if not isinstance(contents, list):
            contents = [contents]

        for item in contents:
            item_path = item["path"]
            # ... [Relative path normalization] ...

            if item["type"] == "file":
                # ... [Pattern check, size check, download_url or base64 decode] ...
                if item.get("download_url"):
                    file_response = requests.get(item["download_url"], headers=headers, timeout=(30, 30))
                    if file_response.status_code == 200:
                        files[rel_path] = file_response.text
                        api_counters["processed"] += 1
                # ... [Base64 fallback branch] ...
            elif item["type"] == "dir":
                # ... [Directory exclusion checks] ...
                fetch_contents(item_path)

    fetch_contents implements rate-limit recovery. If authenticated requests trigger GitHub's secondary or primary rate limits, it extracts the X-RateLimit-Reset epoch timestamp, calculates the required sleep delta using time.time(), pauses the thread via time.sleep(), and retries the call. For files, raw content is fetched from download_url if present, falling back to decoding base64 inline content strings from the API response payload.

    Processing Workflows and Filtering Rules

    SSH Workflow vs. GitHub API Workflow Comparison

    Capability / Behavior SSH Clone Workflow GitHub REST API Workflow
    Trigger Criteria URL starts with git@ or ends with .git URL matches standard HTTP/HTTPS GitHub pattern
    Network Strategy Single git clone command via GitPython Multiple HTTP REST calls per directory/file
    Temporary Disk Storage Yes (tempfile.TemporaryDirectory) No (In-memory HTTP payload processing)
    Commit/Subdirectory Selection Clones default branch; full repo downloaded Resolves specific branch/commit SHA and subdirectory path
    .gitignore Resolution Local file read from .gitignore in clone root API call to GET /repos/{owner}/{repo}/contents/.gitignore
    Rate Limit Handling Governed by SSH key authentication Implements sleep/retry using X-RateLimit-Reset headers
    Decoding Strategy Direct disk read via open(..., encoding="utf-8-sig") HTTP response .text or base64.b64decode()

    Console Reporting

    Both processing workflows provide terminal feedback using ANSI escape sequences: * C_GREEN (\033[92m): Indicates successfully downloaded and parsed files ([processed]). * C_GRAY (\033[90m): Indicates files or directories skipped due to exclusion rules or .gitignore specifications ([excluded], [excluded (.gitignore)]). * C_RED (\033[91m): Indicates processing failures, files exceeding max_file_size ([size limit: X KB]), or binary/non-text decoding errors ([cannot process: not a text file]).
