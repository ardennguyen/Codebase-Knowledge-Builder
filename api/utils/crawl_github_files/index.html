    utils.crawl_github_files

    Original File Path: utils/crawl_github_files.py

    Technical documentation and internal engineering reference for utils/crawl_github_files.py. This module provides routines for fetching, filtering, and parsing source files from remote GitHub repositories. It supports both Git-over-SSH cloning into temporary directories and recursive querying through the GitHub REST API (supporting specific branches, commit SHAs, subdirectories, .gitignore parsing via pathspec, and inclusion/exclusion pattern filtering via fnmatch).

    Architectural Overview

    The module handles two distinct remote ingestion pipelines depending on the target URL scheme: 1. SSH Git Clone Mode (git@ or .git): Clones the remote repository into a temporary directory using git.Repo.clone_from, parses local .gitignore rules, walks the local filesystem, validates file sizes, skips non-text binaries, and loads file contents into memory. 2. GitHub REST API Mode (https://github.com/...): Resolves owner, repository, commit/branch ref, and subdirectory paths via GitHub API endpoints (/repos/{owner}/{repo}/branches, /repos/{owner}/{repo}/git/trees/{tree}, and /repos/{owner}/{repo}/contents/{path}). Recursively traverses directories, evaluates .gitignore fetched from the API, handles rate limits (X-RateLimit-Reset), decodes base64-encoded blobs, and extracts file contents.

    crawl_github_files()

    Description:
    Crawls and ingests source files from a remote GitHub repository. If the repo_url points to an SSH Git endpoint (starting with git@ or ending with .git), it clones the target repository into a temporary directory, filters the filesystem against .gitignore and pattern criteria, and returns the file contents. For HTTP/HTTPS GitHub URLs, it parses the repository coordinates, resolves refs (branches or tree SHAs) against the GitHub REST API, and recursively traverses the contents tree.

    During execution, it manages GitHub API rate limits by reading the X-RateLimit-Reset header and pausing execution when rate limits are reached. It rejects non-text/binary files, enforces byte size limits (max_file_size), and supports re-rooting dictionary keys to relative subdirectories.

    Parameters: * repo_url (str): URL of the GitHub repository.     should_include_file()

    Visibility: Private (Internal Closure Helper)
    Signature: def should_include_file(file_path: str, file_name: str, gitignore_spec: pathspec.PathSpec | None = None) -> bool:

    Description:
    Evaluates whether a candidate file matches the active inclusion rules, is not matched by repository .gitignore specifications, and does not match explicit exclusion wildcards.

    Parameters: * file_path (str): The relative or repository path of the candidate file. * file_name (str): The base filename (e.g., main.py). * gitignore_spec (pathspec.PathSpec | None, optional): Compiled pathspec matcher containing .gitignore patterns. Defaults to None.

    Returns: * bool: True if the file satisfies all inclusion/exclusion rules; False if it should be skipped.

        def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:
        """Determine if a file should be included based on patterns"""
        # If no include patterns are specified, include all files
        if not include_patterns:
            include_file = True
        else:
            # Check if file matches any include pattern
            include_file = any(fnmatch.fnmatch(file_name, pattern) for pattern in include_patterns)

        # Check gitignore if provided
        if include_file and gitignore_spec and gitignore_spec.match_file(file_path):
            return False

        # If exclude patterns are specified, check if file should be excluded
        if exclude_patterns and include_file:
            # Exclude if file matches any exclude pattern
            exclude_file = any(fnmatch.fnmatch(file_path, pattern) for pattern in exclude_patterns)
            return not exclude_file

        return include_file

    The filter evaluates criteria in three sequential stages. First, if include_patterns is defined, the base file_name is evaluated using fnmatch.fnmatch. Second, if a gitignore_spec is provided, file_path is evaluated against it, immediately returning False on a match. Third, if exclude_patterns are present, the full file_path is checked against each pattern, excluding matching files.

    Description:
    Queries the GitHub API endpoint /repos/{owner}/{repo}/branches to list all branches in the target repository. Used to determine whether a segment in the URL represents a branch name.

    Parameters: * owner (str): The repository owner or organization account. * repo (str): The repository name.

    Returns: * list[dict]: List of branch dictionaries returned by the GitHub API. Returns an empty list [] on HTTP 404 or other non-200 responses.

    Raises: * Exception: Raised if HTTP status 403 or 429 is received and no token was configured.

        def fetch_branches(owner: str, repo: str):
        """Get brancshes of the repository"""

        url = f"https://api.github.com/repos/{owner}/{repo}/branches"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        if response.status_code == 404:
            if not token:
                print(
                    "Error 404: Repository not found or is private.\n"
                    "If this is a private repository, please provide a valid GitHub token via the 'token' argument or set the GITHUB_TOKEN environment variable."
                )
            else:
                print(
                    "Error 404: Repository not found or insufficient permissions with the provided token.\n"
                    "Please verify the repository exists and the token has access to this repository."
                )
            return []

        if response.status_code != 200:
            print(f"Error fetching the branches of {owner}/{repo}: {response.status_code} - {response.text}")
            return []

        return response.json()

    The function executes a requests.get with a 30-second connection and read timeout. It inspects status codes to distinguish between authentication errors, repository absence, and rate-limit exhaustion.

    Parameters: * owner (str): The repository owner or organization account. * repo (str): The repository name. * tree (str): The tree SHA, commit hash, or ref identifier to validate.

        def check_tree(owner: str, repo: str, tree: str):
        """Check the repository has the given tree"""

        url = f"https://api.github.com/repos/{owner}/{repo}/git/trees/{tree}"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        return response.status_code == 200

    This function performs a low-overhead ref validation check when a path segment in a GitHub /tree/... URL does not match any known branch name, verifying whether the identifier is a commit or tree SHA.
