    utils.crawl_github_files

    Original Source File: utils/crawl_github_files.py

    Overview

    The utils.crawl_github_files module provides an automated file-crawling system for remote GitHub repositories. It serves as an ingestion utility within the Codebase-Knowledge-Builder architecture, allowing downstream analysis pipelines (such as nodes and flow) to pull repository source code without requiring a permanent local clone on disk.

    The module supports two ingestion mechanisms: 1. SSH Git Clone Path: Triggered when the repository URL starts with git@ or ends with .git. It clones the target repository into an isolated, temporary directory using GitPython (git.Repo.clone_from), processes files matching glob and .gitignore specifications, extracts text content, and deletes the temporary directory upon completion. 2. GitHub REST API Path: Triggered for standard GitHub HTTP/HTTPS URLs (including tree URLs with specific branches, commit SHAs, or subpaths). It recursively crawls the repository via GitHub's REST API /repos/{owner}/{repo}/contents/{path} and tree endpoints, downloads raw files or decodes Base64 blobs, respects .gitignore rules retrieved directly from the repository, and automatically handles GitHub API rate limiting by sleeping until X-RateLimit-Reset.

    should_include_file()

    Visibility: Private (Closure Helper)
    Signature: def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:

    Description: Evaluates whether a candidate file path should be processed or excluded. The evaluation sequence executes in three stages: 1. Validates the file_name against include_patterns (if defined). 2. Checks the file_path against the compiled pathspec .gitignore rules (if loaded). 3. Validates the file_path against exclude_patterns (if defined).

    Parameters: * file_path (str): Relative path of the candidate file within the repository. * file_name (str): Base filename component (e.g., main.py). * gitignore_spec (pathspec.PathSpec | None, optional): Compiled pathspec object using the gitwildmatch pattern syntax. Defaults to None.

    Returns: * bool: True if the file passes all criteria and should be downloaded/read; False otherwise.

    Implementation Core: 

        def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:
        """Determine if a file should be included based on patterns"""
        # If no include patterns are specified, include all files
        if not include_patterns:
            include_file = True
        else:
            # Check if file matches any include pattern
            include_file = any(fnmatch.fnmatch(file_name, pattern) for pattern in include_patterns)

        # Check gitignore if provided
        if include_file and gitignore_spec and gitignore_spec.match_file(file_path):
            return False

        # If exclude patterns are specified, check if file should be excluded
        if exclude_patterns and include_file:
            # Exclude if file matches any exclude pattern
            exclude_file = any(fnmatch.fnmatch(file_path, pattern) for pattern in exclude_patterns)
            return not exclude_file

        return include_file

    This helper implements short-circuit evaluation logic. If include_patterns are provided and the filename fails to match at least one pattern via fnmatch.fnmatch, the function immediately marks the file for exclusion without querying the .gitignore specification.

    Example: 

    # Invoked internally inside SSH walk and API tree iteration
if not should_include_file(rel_path, filename, gitignore_spec=gitignore_spec):
    count_excluded += 1
    print(f"{C_GRAY}  [{entry_num}] {rel_path} [excluded]{C_RESET}")
    continue

    Visibility: Private (Closure Helper)
    Signature: def fetch_branches(owner: str, repo: str) -> list[dict] | None:

    Description: Queries the GitHub REST API endpoint GET /repos/{owner}/{repo}/branches to list all branches in the target repository. Used to determine whether a subpath in a /tree/... URL refers to a branch name containing forward slashes or a Git commit/tree SHA.

    Parameters: * owner (str): GitHub organization or username owning the repository. * repo (str): Name of the repository.

    Returns: * list[dict]: Parsed JSON array containing branch metadata objects returned by GitHub. Returns an empty list [] on HTTP error statuses (404 or non-200).

    Raises: * Exception: If a 403 or 429 status code indicates that the GitHub API rate limit was exceeded and no token was configured.

    Implementation Core: 

        def fetch_branches(owner: str, repo: str):
        """Get brancshes of the repository"""

        url = f"https://api.github.com/repos/{owner}/{repo}/branches"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        if response.status_code == 404:
            if not token:
                print("Error 404: Repository not found or is private.\n"
                      "If this is a private repository, please provide a valid GitHub token via the 'token' argument or set the GITHUB_TOKEN environment variable.")
            else:
                print("Error 404: Repository not found or insufficient permissions with the provided token.\n"
                      "Please verify the repository exists and the token has access to this repository.")
            return []

        if response.status_code != 200:
            print(f"Error fetching the branches of {owner}/{repo}: {response.status_code} - {response.text}")
            return []

        return response.json()

    The function transmits standard GitHub v3 JSON accept headers along with optional authorization tokens. If a 404 is encountered, contextual error messages are printed to standard output to help diagnose whether repository permissions or invalid repository paths are the root cause.

        def check_tree(owner: str, repo: str, tree: str):
        """Check the repository has the given tree"""

        url = f"https://api.github.com/repos/{owner}/{repo}/git/trees/{tree}"
        response = requests.get(url, headers=headers, timeout=(30, 30))

    Processing Logic and Workflow Details

    1. SSH Clone Mode Traversal

    When an SSH repository URL is supplied: 1. git.Repo.clone_from(repo_url, tmpdirname) clones the repository to a temporary folder. 2. If .gitignore is present at the repository root, pathspec.PathSpec.from_lines("gitwildmatch", ...) compiles the filter rules. 3. os.walk() scans all directories. Subdirectories matching .gitignore or exclude_patterns are pruned from dirs in-place to avoid unnecessary directory traversal. 4. Each file is validated via should_include_file() and size thresholds. 5. Text files are opened using utf-8-sig encoding (stripping BOM headers if present) and loaded into memory.

    2. GitHub REST API Mode Traversal

    When an HTTPS repository URL is supplied: 1. The URL path is split to identify the owner, repo, optional branch/tree ref, and subdirectory path. 2. The root .gitignore file is fetched via GET /repos/{owner}/{repo}/contents/.gitignore, decoded from Base64, and parsed into a PathSpec object. 3. fetch_contents() begins at specific_path. 4. Directory entries matching exclusion filters are ignored. File entries matching inclusion rules are retrieved via their direct raw download_url or fallback Base64 decoding.
