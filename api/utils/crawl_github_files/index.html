    utils.crawl_github_files

    Source File: utils/crawl_github_files.py

    This page documents the internal architecture, function signatures, error-handling routines, and crawling pipelines implemented in utils/crawl_github_files.py.

    Technical Overview

    The utils.crawl_github_files module provides an automated file-fetching and repository-traversal mechanism designed to extract source code and documentation from remote GitHub repositories. It supports targeting specific commits, branches, and subdirectories.

    The module operates across two distinct operational pathways based on repository protocol and target specification:

    1. Git / SSH Protocol (Cloning Pathway): When an SSH URL (e.g., beginning with git@ or ending with .git) is detected, the module clones the repository into an ephemeral temporary directory using GitPython (git.Repo.clone_from), reads .gitignore rules via pathspec, evaluates include/exclude file patterns, and extracts matching textual content.
    2. REST API Pathway: For standard GitHub HTTPS/Web URLs (e.g., https://github.com/owner/repo/tree/ref/path), the module parses owner, repository, Git tree/branch reference, and nested folder paths. It queries the GitHub REST API v3, dynamically parses .gitignore files from remote references, handles recursive directory listings, implements automatic rate-limit throttling and backoff, downloads raw content, and decodes Base64 blobs.

    Key Architectural Behaviors

    • Dynamic Pattern Filtering: Supports standard Unix shell wildcards (via fnmatch) across file names and directory trees alongside gitignore pattern matching (via pathspec.PathSpec with the gitwildmatch pattern grammar).
    • Size and Binary Constraints: Rejects binary files, decoding failures, and assets exceeding the configurable size threshold (max_file_size, defaulting to 1 MB) before in-memory storage.
    • Dynamic Rate Throttling: Parses X-RateLimit-Reset HTTP headers on 403/429 responses, sleeping dynamically until quota replenishment when authenticated with personal access tokens.

    Signature: def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:

    Description:
    Evaluates whether a candidate file satisfies the inclusion criteria, passes all exclude_patterns, and is not ignored by the active .gitignore specification.

    Core Implementation: 

        def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:
        """Determine if a file should be included based on patterns"""
        # If no include patterns are specified, include all files
        if not include_patterns:
            include_file = True
        else:
            # Check if file matches any include pattern
            include_file = any(fnmatch.fnmatch(file_name, pattern) for pattern in include_patterns)

        # Check gitignore if provided
        if include_file and gitignore_spec and gitignore_spec.match_file(file_path):
            return False

        # If exclude patterns are specified, check if file should be excluded
        if exclude_patterns and include_file:
            # Exclude if file matches any exclude pattern
            exclude_file = any(fnmatch.fnmatch(file_path, pattern) for pattern in exclude_patterns)
            return not exclude_file

        return include_file

    The function checks filename patterns using fnmatch.fnmatch against include_patterns. If the file qualifies, it is checked against gitignore_spec.match_file(file_path) using path specifications. Finally, if exclude_patterns are provided, the relative file_path is checked against each pattern. If any exclude pattern matches, the file is rejected.

    Parameters: * file_path (str): Relative file path from the repository root or temporary directory root. * file_name (str): Base filename (e.g., main.py). * gitignore_spec (pathspec.PathSpec | None, optional): Compiled pathspec rule set loaded from the repository's .gitignore. Defaults to None.

    Returns: * bool: True if the file passes all inclusion filters and avoids all exclusion rules; False otherwise.

    fetch_branches()

    Visibility: Private (Internal helper inside crawl_github_files)
    Signature: def fetch_branches(owner: str, repo: str) -> list[dict]:

    Description:
    Queries the GitHub API endpoint /repos/{owner}/{repo}/branches to enumerate all remote branches. This list is used to resolve ambiguous path segments in URLs containing the /tree/ path separator.

    Core Implementation: 

        def fetch_branches(owner: str, repo: str):
        """Get brancshes of the repository"""

        url = f"https://api.github.com/repos/{owner}/{repo}/branches"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        if response.status_code == 404:
            if not token:
                print(
                    "Error 404: Repository not found or is private.\n"
                    "If this is a private repository, please provide a valid GitHub token via the 'token' argument or set the GITHUB_TOKEN environment variable."
                )
            else:
                print(
                    "Error 404: Repository not found or insufficient permissions with the provided token.\n"
                    "Please verify the repository exists and the token has access to this repository."
                )
            return []

        if response.status_code != 200:
            print(f"Error fetching the branches of {owner}/{repo}: {response.status_code} - {response.text}")
            return []

        return response.json()

    The function issues an HTTP GET request using the configured headers (including the Authorization token if present). If rate-limited without a token, it raises an Exception. If a 404 status is returned, descriptive permission error messages are printed and an empty list is returned. On HTTP 200, it parses and returns the JSON branch payload.

    Parameters: * owner (str): The GitHub organization or username owning the repository. * repo (str): The repository name.

    Returns: * list[dict]: A list of branch descriptor objects containing keys like "name" and "commit". Returns [] upon failure.

    Raises: * Exception: Raised if HTTP 403/429 rate limits are hit without an active authentication token.

    Example: 

    # Internal invocation during URL branch resolution in crawl_github_files:
branches = fetch_branches(owner, repo)
branch_names = (branch.get("name") for branch in branches)

    The function queries /repos/{owner}/{repo}/contents/{path} with an optional ref query parameter. When a rate limit response (403/429) is received with an authenticated token, it inspects the X-RateLimit-Reset HTTP header, calculates the required sleep duration, pauses execution via time.sleep(), and retries the request.

    For each item in the payload: - Directory (item["type"] == "dir"): Evaluates .gitignore and exclude_patterns rules. If permitted, it invokes fetch_contents(item_path) recursively. - File (item["type"] == "file"): Checks should_include_file and file size metadata.
