    exclude_patterns.py

    Source: utils/exclude_patterns.py

    Following the local filesystem traversal and boundary isolation mechanisms established in crawl_local_files.py, the exclude_patterns.py module defines the centralized inventory of default exclusion rules used across the entire repository ingestion pipeline. It provides a standardized set of glob patterns designed to filter out non-textual assets, dependency trees, compiler artifacts, temporary files, and environment metadata before source files reach downstream token profiling and LLM analysis components.

    Technical Overview

    The exclude_patterns.py module acts as the authoritative filtering dictionary for both local filesystem ingestion via crawl_local_files.py and remote repository discovery via crawl_github_files.py. In automated codebase documentation architectures, unconstrained directory traversal poses severe operational hazards: injecting multi-megabyte binary blobs, minified vendor bundles, lockfiles containing thousands of repetitive entries, and compiler build caches into LLM context windows causes immediate token exhaustion, severe degradation of attention mechanisms, and runtime decoding failures. This module defines the baseline perimeter that restricts ingestion strictly to primary, human-authored source code.

    Architecturally, the exclusion inventory is organized into seven distinct functional domains: static media and binary archives, build and distribution targets, environment directories and dependency trees, language-specific compiled artifacts, operating system and version control metadata, legacy IDE workspace configurations, and modern AI agent workspaces. The module defines patterns adhering to standard fnmatch glob syntax, distinguishing between directory-level subtrees (designated with a trailing /*) and leaf file patterns (designated with filename extensions or exact basenames). When ingested by crawler modules, directory patterns enable aggressive in-place directory pruning during os.walk() traversal, eliminating entire subtrees from disk traversal without inspecting individual child inodes.

    Public API

    DEFAULT_EXCLUDE_PATTERNS

    Visibility: Public
    Signature: DEFAULT_EXCLUDE_PATTERNS: set[str]

    Description: A comprehensive set of string literals representing fnmatch-compatible glob patterns. These patterns identify directories, binary files, autogenerated lockfiles, environment configurations, and external tooling artifacts that must be omitted from codebase ingestion. The collection is segmented into seven logical categories, each targeting a specific class of non-source file artifact.

    Parameters: * None (module-level constant).

    Returns: * set[str]: A mutable set containing all 132 predefined glob pattern strings.

    Raises: * No exceptions are raised during module import or set instantiation.

    This partition targets static digital assets, compressed archives, binary documents, and generic asset storage directories. Media files such as raster images (*.png, *.jpg), vector assets (*.svg), video streams (*.mp4, *.mov), audio formats (*.wav, *.mp3), and proprietary document wrappers (*.pdf, *.docx, *.xlsx) contain no executable architecture or semantic source code. Ingesting these files into an LLM analysis pipeline consumes thousands of tokens per file in non-interpretable binary or base64 garbage, while risking decoding crashes. Directory globs such as assets/*, data/*, and public/* short-circuit traversal of frontend static resource repositories, while compressed archive extensions (*.zip, *.tar, *.gz) prevent attempts to parse packaged artifacts as plain text.

Modern web meta-frameworks compile source code into massive intermediate client and server bundles inside .next/*, .nuxt/*, or .svelte-kit/*, while native and compiled languages produce artifacts in dist/*, build/*, target/*, bin/*, and obj/*. Including these generated outputs duplicates source logic across thousands of transpiled files, corrupting documentation generation with minified artifacts. Furthermore, testing suites (test/*, tests/*), documentation repositories (docs/*), and non-production pathways (legacy/*, deprecated/*, experimental/*) are intentionally excluded to restrict architectural mapping to active, production-grade application logic.

    This section eliminates third-party dependencies, virtual environment runtimes, secret environment variables, and auto-generated dependency lockfiles. Third-party vendor trees such as node_modules/*, vendor/*, and Python virtual environments (venv/*, .venv/*) contain tens of thousands of external files that do not reflect the proprietary architecture of the host repository. Excluding .env and .env.* ensures sensitive production credentials, tokens, and secrets are strictly barred from being read or forwarded to external LLM providers. Lockfiles like package-lock.json, poetry.lock, and Cargo.lock consist of machine-generated dependency hash graphs that consume massive token budgets without providing high-level architectural insight.

    This category isolates compiler-generated bytecode, language toolchain caches, test runner states, and compiled native binaries across multiple language ecosystems. In the Python domain, it excludes bytecode caches (__pycache__/*, *.pyc), linter caches (.ruff_cache/*), and test coverage instrumentation (.coverage, htmlcov/*). In JVM ecosystems, it strips intermediate class files (*.class) and packaged Java archives (*.jar, *.war). For compiled C, C++, and Rust ecosystems, native object files (*.o, *.obj), dynamically linked libraries (*.so, *.dylib, *.dll), and executables (*.exe) are pruned to avoid binary ingestion. Mobile toolchain dependencies and build outputs (ios/Pods/*, android/.gradle/*) are likewise prevented from polluting root directory crawls.

    Category 5: Operating System and Version Control Metadata

        # 5. OS & Version Control
    ".git/*",
    ".github/*",
    ".svn/*",
    ".hg/*",
    ".DS_Store",
    "Thumbs.db",
    "desktop.ini",

    This partition safeguards against descending into underlying version control metadata databases and operating system desktop management files. Version control repositories like .git/*, .svn/*, and .hg/* maintain compressed object databases, packfiles, commit trees, and staging indices that can cause recursive traversal loops or corrupt UTF-8 text readers. The .github/* directory, while text-based, typically houses CI/CD workflows and automated issue templates that fall outside internal codebase implementation semantics. Desktop index files generated by macOS (.DS_Store) and Windows (Thumbs.db, desktop.ini) are binary artifacts created automatically by file managers and contain no source information.

    Category 6: Classic Integrated Development Environments (IDEs)

        # 6. Classic IDEs
    ".vscode/*",
    ".idea/*",
    "*.iml",
    ".eclipse/*",
    ".settings/*",
    ".classpath",
    ".project",

    This partition prunes user-specific and workspace-specific configuration trees generated by traditional integrated development environments. Directories like .vscode/*, .idea/*, .eclipse/*, and .vs/* contain localized IDE configuration state, window layouts, debugger launch hooks, and developer personal preferences. Project metadata files such as *.iml, .classpath, and .project represent internal IDE build paths rather than codebase architecture. Filtering these patterns ensures the resulting documentation represents the software project itself rather than the local toolchains of individual contributing engineers.

    Data Structures

    DEFAULT_EXCLUDE_PATTERNS Storage Contract

    The primary data structure declared in this module is DEFAULT_EXCLUDE_PATTERNS, configured as a standard Python set[str]. This set guarantees uniqueness among glob expressions and provides $O(1)$ amortized membership verification when verifying pattern existence.

    Field Type Description
    DEFAULT_EXCLUDE_PATTERNS set[str] An un-ordered collection of 132 unique string literals representing Unix-style glob expressions used to exclude directories and files during traversal.

    Categorical Breakdown of Exclusion Patterns

    The inventory contains 132 individual pattern rules across the 7 domains. The following table provides the operational breakdown, syntax classification, and rationale for each category:

    Category Index Category Domain Pattern Count Syntax Variations Present Primary Objective Risk Avoidance
    1 Media, Data, & Static Assets 32 directory/*, *.ext Prevent ingestion of images, video, audio, PDFs, and archive bundles. Context window saturation by binary encoding; UTF-8 decode exceptions.
    2 Build, Distribution, & Caches 24 directory/*, prefix*/*, *.ext Strip transpiled outputs, compilation caches, logs, and legacy/test trees. Ingestion of minified/transpiled code; redundant documentation of test fixtures.
    3 Environments & Dependencies 20 directory/*, filename, *.lock, .env* Exclude package managers, virtual environments, lockfiles, and secrets. Multi-thousand file traversal in package trees; leaking secret credentials.
    4 Language-Specific Artifacts 25 directory/*, *.ext, path/directory/* Block compiled JVM, Python bytecode, C/C++ native binaries, and mobile builds. Binary corruption; token waste on compiler caches and linter outputs.
    5 OS & Version Control Metadata 7 directory/*, filename Prevent traversal into VCS internals and OS desktop view configs. Ingestion of Git packfiles/objects; filesystem metadata noise.
    6 Classic IDE Workspaces 8 directory/*, *.ext, filename Filter local developer workspace state, debug launch files, and IDE projects. Noise from developer-specific environments and local IDE paths.
    7 Modern AI Agents & Tooling 16 directory/*, filename Block prompts, session histories, rules, and caches from AI coding tools. Self-referential prompt injection; circular knowledge contamination.

    Pattern Syntax Taxonomy

    The string patterns in DEFAULT_EXCLUDE_PATTERNS fall into three distinct syntax shapes, dictating how consumers like crawl_local_files.py and crawl_github_files.py interpret each rule:

    Syntax Type Pattern Structure Matching Semantics Crawler Action Example
    Directory Subtree Glob <path>/* or <prefix>*/* Evaluated against directory paths relative to the crawl root. Mutates the dirs list in os.walk() to prune the entire directory tree immediately. node_modules/*, output-test*/*
    Extension Wildcard *.<ext> Evaluated against the basename of each file candidate via fnmatch. Bypasses file reading and skips text decoding if the candidate ends with the extension. *.png, *.class, *.pyc, *.lock
    Exact Basename <name> or <prefix>.* Evaluated against the exact file basename or dotfile prefix. Skips specific configuration files, secrets, or desktop artifacts. .env, .env.*, .DS_Store, Thumbs.db

    Error Handling

    Because utils/exclude_patterns.py is a declarative configuration module containing only literal constants, it introduces no dynamic control flow, runtime branches, or I/O calls that raise exceptions. However, the design and consumption of these patterns rely on specific error avoidance guarantees:

    • Exception-Free Import: The module relies exclusively on Python standard built-in data types (set, str). It executes no filesystem queries, network calls, or regex compilations during module import, guaranteeing zero initialization failures.
    • Separation from Regex Backtracking (ReDoS Immunity): The patterns are formulated for Python's standard fnmatch library rather than complex regular expression engines. fnmatch converts shell wildcards into simple POSIX-compliant patterns, completely eliminating the risk of catastrophic backtracking (ReDoS) during high-throughput path evaluation.
    • Cross-Platform Separator Normalization: Because all directory patterns utilize the standard forward slash (/*), consumer modules on Windows environments must normalize path separators (converting \ to /) prior to running fnmatch. If un-normalized Windows backslashes are tested against assets/*, matching will fail silently, leading to accidental ingestion of excluded assets. Both crawl_local_files.py and crawl_github_files.py enforce this normalization before matching.
    • Boundary Guarding with Trailing /*: Directory patterns strictly append /*. This prevents accidental collisions between directory names and similarly named source files (for example, ensuring a pattern targeting a docs/* directory does not match a standalone file named docs.py).
