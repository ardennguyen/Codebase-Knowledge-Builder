    exclude_patterns.py

    Source: utils/exclude_patterns.py

    Technical Overview

    The utils/exclude_patterns.py module defines the baseline filtering configuration used across the codebase crawler infrastructure. Its primary responsibility is to provide a comprehensive, standardized collection of glob patterns (DEFAULT_EXCLUDE_PATTERNS) that prune irrelevant, non-text, autogenerated, or sensitive files and directories during recursive filesystem traversal. By eliminating non-source files prior to reading, decoding, or token counting, the module protects downstream language models from processing massive token payloads, prevents crashes caused by attempting to decode binary assets as UTF-8 text, and enforces strict security boundaries by ensuring credentials and private keys are never transmitted to external APIs or recorded in local cache stores.

    The module employs standard Unix glob syntax compatible with Python's fnmatch library. Directory exclusions explicitly terminate with a trailing wildcard suffix (/*) to signal directory-level pruning during recursive walks (such as os.walk), while file patterns target extensions, exact filenames, or path prefixes. The patterns span seven distinct domains: static and binary media, build and framework distribution outputs, virtual environments and dependency registries, programming language compilation artifacts, operating system metadata, classical IDE project settings, and modern AI coding assistant telemetry and state directories.

    Public API

    DEFAULT_EXCLUDE_PATTERNS

    Visibility: Public Signature: DEFAULT_EXCLUDE_PATTERNS = {

    Description: A module-level constant containing a Python set of glob pattern strings. These patterns define the default ignore rules applied by directory crawlers when indexing local filesystems or remote Git trees. The patterns are categorized into distinct functional domains, detailed in the subsections below.

    Parameters: * None (module-level constant).

    Returns: * set[str]: An unordered collection of unique glob strings formatted for fnmatch pattern matching.

    Raises: * None.

    The media, data, and static asset rules suppress binary assets, document containers, compressed archives, and typical web asset directories. Files bearing raster image formats (.jpg, .png, .webp), vector formats (.svg), video streams (.mp4, .mov), audio tracks (.mp3, .wav), and office productivity binaries (.pdf, .docx, .xlsx) contain binary payloads that cannot be processed as UTF-8 source code and would trigger decoding exceptions during file ingestion. Compressed archives (.zip, .tar, .gz, .7z) are similarly ignored to prevent crawling packed archives. Directory-level matchers like assets/*, data/*, public/*, and static/* ensure that local crawlers skip folders containing bundled application media rather than traversing their child nodes.

A critical security guarantee of this file is preventing the leakage of cryptographic private keys (*.pem, *.key, *.p12, *.pfx, *.jks, *.keystore) and SSH identity credentials (id_rsa, id_ecdsa, id_ed25519 and their derivatives) located at any filesystem depth. Similarly, environment variable configuration stores (.env, .env.*, */.env, */.env.*) are filtered out to prevent leaking API keys, database credentials, and session tokens to LLM providers or local cache files. For dependencies, large vendor directories (node_modules/*, vendor/*, packages/*, venv/*) and deterministic dependency lockfiles (package-lock.json, yarn.lock, Cargo.lock, poetry.lock, etc.) are filtered out because their high line counts would overwhelm context windows without offering architectural insight.

    This section covers language runtime caches, test harness caches, and binary compilation targets across major programming languages. For Python environments, it suppresses CPython bytecode directories (__pycache__/*), compiled binaries (*.pyc, *.pyo, *.pyd), linter caches (.ruff_cache/*), and test coverage instrumentation (.pytest_cache/*, .tox/*, .coverage, htmlcov/*). For the JVM ecosystem, Gradle dependency caches (.gradle/*) and compiled Java bytecode containers (*.class, *.jar, *.war, *.ear, *.nar) are eliminated. For native C, C++, and Rust builds, object files and compiled dynamic/shared/static libraries (*.o, *.obj, *.dll, *.exe, *.so, *.dylib, *.lib, *.a) are ignored. Mobile application framework subprojects under ios/Pods/* and Android build trees under android/.gradle/* and android/app/build/* are also pruned.

    The final segment handles system metadata, developer tooling configurations, and AI-assisted editor workspaces. Operating system artifacts such as macOS Finder records (.DS_Store) and Windows thumbnail databases (Thumbs.db, desktop.ini) are discarded alongside internal VCS databases (.git/*, .svn/*, .hg/*) and GitHub action workflows (.github/*). Classic IDE workspace settings from VS Code (.vscode/*), IntelliJ IDEA (.idea/*, *.iml), Eclipse (.eclipse/*, .settings/*, .classpath, .project), and Visual Studio (.vs/*) are excluded. Finally, local configuration files, context rules, and telemetry paths generated by modern AI IDEs and autonomous developer agents (including Cursor, Windsurf, Cline, Roo Code, Continue, Claude Code, and Copilot) are excluded to ensure clean code analysis.

    Example: 

    from utils.exclude_patterns import DEFAULT_EXCLUDE_PATTERNS

# Typical consumption within a crawler's exclusion check loop
def is_excluded(path: str, exclude_patterns: set[str] = DEFAULT_EXCLUDE_PATTERNS) -> bool:
    import fnmatch
    return any(fnmatch.fnmatch(path, pattern) for pattern in exclude_patterns)

    Data Structures

    DEFAULT_EXCLUDE_PATTERNS

    DEFAULT_EXCLUDE_PATTERNS is instantiated as a built-in Python set of string literals. Each entry represents a glob matching rule evaluated by crawler routines using fnmatch.fnmatch() or fnmatch.fnmatchcase().

    Category Pattern Count Example Patterns Primary Purpose
    Media, Data, and Static Assets 32 assets/*, data/*, *.jpg, *.pdf, *.zip Prevents UTF-8 decoding failures on binary files and reduces prompt token usage from non-code media.
    Build, Distribution, and Framework Caches 25 dist/*, build/*, .next/*, *.log, tests/* Avoids redundant ingestion of compiled bundles, framework artifacts, and test fixtures.
    Environments, Dependencies & Lockfiles 39 venv/*, .env, */.env, *.pem, id_rsa, node_modules/*, *.lock Prevents credential exposure to LLMs/caches and avoids traversing multi-megabyte dependency trees.
    Language-Specific Exclusions 26 __pycache__/*, *.class, *.jar, *.so, *.dylib Excludes machine-compiled bytecode, intermediate objects, and platform shared libraries.
    OS & Version Control 7 .git/*, .github/*, .DS_Store, Thumbs.db Filters out filesystem metadata and internal version control repositories.
    Classic IDEs 8 .vscode/*, .idea/*, *.iml, .classpath Excludes local developer workspace configurations and IDE project files.
    AI Agents & Modern AI IDEs 16 .cursor/*, .windsurf/*, .cline/*, .claude/* Suppresses prompt histories, local agent state, and agent-specific steering rules.

    Structural Matching Contracts

    1. Directory Patterns (dir/*): Patterns ending with /* target directory subtrees. When a crawler encounters a directory whose relative path matches the prefix, it prunes the entire subtree from traversal (e.g., modifying dirnames[:] in os.walk).
    2. Path-Scoped File Patterns (*/filename): Patterns starting with */ ensure that target filenames (such as */.env or */id_rsa) match at any subdirectory depth in the repository hierarchy.
    3. Extension Patterns (*.ext): File extension patterns evaluate against both relative paths and file basenames, identifying binary or autogenerated artifacts regardless of location.
    4. Exact Basename Patterns (name): Patterns without wildcards (such as .DS_Store or package-lock.json) target exact filename matches during traversal filtering.

    Error Handling

    Because utils/exclude_patterns.py is a declarative configuration module containing static constant assignments, it does not raise runtime exceptions, execute I/O operations, or perform dynamic evaluation during import.

    However, consumers of DEFAULT_EXCLUDE_PATTERNS should observe the following operational considerations: * Path Separator Normalization: Patterns use POSIX forward slashes (/). On Windows systems where filesystem paths use backslashes (\), consumer crawlers must normalize paths to POSIX style (e.g., via path.replace("\\", "/")) prior to evaluating them with fnmatch.fnmatch. * Collection Mutability: Because Python set instances are mutable, consumer modules should treat DEFAULT_EXCLUDE_PATTERNS as read-only. When extending the exclusion rules with repository-specific flags, callers should construct a new set using set union operations (DEFAULT_EXCLUDE_PATTERNS | custom_patterns) rather than mutating DEFAULT_EXCLUDE_PATTERNS directly.
