    exclude_patterns.py

    Source: utils/exclude_patterns.py

    Following the local filesystem crawling implementation detailed in crawl_local_files.py, the exclude_patterns.py module defines the centralized, immutable exclusion rules governing file ingestion across the entire repository analysis pipeline. It provides a standardized set of glob patterns used by both local and remote repository crawlers to filter out non-essential directories, large binaries, build outputs, environment configs, secret keys, package lockfiles, and IDE-specific configurations.

    Technical Overview

    The exclude_patterns.py module acts as a declarative security and filtering boundary for the repository ingestion pipeline. When parsing large, heterogeneous software repositories, passing uncurated file trees to downstream Large Language Models (LLMs) leads to severe failure modes: context window exhaustion, high API latency and cost, non-deterministic tokenization of binary blobs, and accidental exfiltration of confidential credentials or API secrets. This module centralizes all baseline exclusion rules into a single Python set, DEFAULT_EXCLUDE_PATTERNS, ensuring uniform filtering behavior across local filesystem traversals (crawl_local_files.py) and remote Git/REST traversals (crawl_github_files.py).

    The pattern syntax is strictly based on standard shell globbing rules interpreted via Python's standard library fnmatch module. Directory exclusions are denoted by trailing /* wildcards (such as node_modules/* and .git/*), signaling to crawling engines that an entire directory subtree should be pruned from the traversal graph prior to reading nested files. Filename and extension patterns (such as *.pem, *.pyc, or package-lock.json) target individual files across directory levels. Furthermore, deep-path prefix wildcards (such as */.env and */id_rsa) prevent accidental inclusion of nested secrets that might bypass naive root-level checks.

    By decoupling these exclusion rules into an isolated data module, the repository ingestion architecture enforces separation of concerns. Traversal algorithms remain focused strictly on path navigation, I/O streaming, and rate-limit handling, while the exclusion catalog encapsulates domain-specific knowledge regarding framework build outputs, language-specific compiled objects, and contemporary AI agent metadata directories.

    Public API

    DEFAULT_EXCLUDE_PATTERNS

    Visibility: Public
    Signature: DEFAULT_EXCLUDE_PATTERNS: set[str]

    Description: A comprehensive set of string glob patterns specifying the directories, file extensions, and file names that must be excluded during repository ingestion. Crawler implementations test relative directory and file paths against these patterns using fnmatch.fnmatch() or fnmatch.fnmatchcase(). Directory patterns terminate with /* to facilitate early directory pruning in os.walk() loops.

    The rules inside DEFAULT_EXCLUDE_PATTERNS are categorized into distinct operational domains:

    Media, Data, and Static Assets

    Filters out high-entropy binary media, static web assets, non-code office documents, and compressed file archives that cannot be processed by text-oriented LLMs.

    This segment targets resource directories and binary file extensions. Top-level folders such as assets/*, images/*, and public/* are pruned immediately by the traversal engine, avoiding disk I/O on thousands of non-text assets. File-level extensions cover raster graphics (.jpg, .png), vector graphics (.svg), video/audio formats (.mp4, .wav), document containers (.pdf, .docx), and common compression archives (.zip, .tar, .gz). Excluding these files prevents downstream UTF-8 decoding errors and protects the token processing pipeline from encountering high-entropy binary data.

    This partition prevents duplicate or ephemeral code structures from diluting the codebase knowledge representation. Standard build distribution folders (dist/*, build/*, target/*, bin/*) and framework-specific server-side rendering caches (.next/*, .nuxt/*, .svelte-kit/*) contain bundled, minified, or synthetic code that obscures original architectural abstractions. Furthermore, folders holding historical or peripheral code (legacy/*, deprecated/*, misc/*, test/*, examples/*) are bypassed so the LLM synthesis focuses purely on active, production-grade logic. Editor swap files (*.swp, *.bak) and runtime execution traces (*.log) are suppressed at the file matching level.

Secret protection rules operate defensively: .env files and SSH/TLS cryptographic private keys (id_rsa, id_ecdsa, id_ed25519, *.pem, *.p12, *.keystore) are matched both at the root level and recursively across any directory depth (*/.env, */id_rsa.*). This ensures that private tokens and credentials are never ingested, cached in llm_cache_v2.json, or transmitted over external network boundaries to LLM APIs. Concurrently, package manager directories (node_modules/*, vendor/*) and dependency lockfiles (package-lock.json, Cargo.lock, poetry.lock) are dropped, preventing hundreds of thousands of lines of machine-generated dependency trees from filling model context windows.

    This section eliminates low-level compiled runtime artifacts across diverse programming ecosystems. For Python environments, it suppresses bytecode stores (__pycache__/*, *.pyc), test/linter caches (.pytest_cache/*, .ruff_cache/*), and coverage analytics (.coverage, htmlcov/*). For JVM runtimes, it removes Gradle caches (.gradle/*) and compiled Java archives (*.class, *.jar, *.war). For native compilation (C, C++, Rust, Go), it drops object files (*.o, *.obj), shared libraries (*.so, *.dylib, *.dll), and static archives (*.a, *.lib). Mobile build outputs such as CocoaPods installations (ios/Pods/*) and Android Gradle trees (android/app/build/*) are similarly pruned prior to traversal.

    This final group strips system and tooling metadata. Operating system files (.DS_Store, Thumbs.db) and VCS engines (.git/*, .svn/*, .hg/*) contain binary databases, loose objects, and commit indexes that are irrelevant for source architecture extraction. Traditional IDE directories (.vscode/*, .idea/*, .vs/*) are excluded to avoid absorbing user-specific workspace configurations. Finally, modern AI agent caches and rule configurations (.cursor/*, .windsurf/*, .cline/*, .claude/*, .copilot/*) are omitted to prevent the knowledge extraction engine from ingesting meta-prompts, session histories, or external AI assistant state files.

    Example Usage in Traversal Logic: 

    # Extracted pattern usage pattern from codebase crawler implementations:
# Directory pruning during os.walk:
for d in list(dirs):
    dir_rel_path = os.path.relpath(os.path.join(root, d), root_dir).replace("\\", "/") + "/*"
    if any(fnmatch.fnmatch(dir_rel_path, pat) for pat in DEFAULT_EXCLUDE_PATTERNS):
        dirs.remove(d)

# File inclusion filtering:
if any(fnmatch.fnmatch(file_rel_path, pat) for pat in DEFAULT_EXCLUDE_PATTERNS):
    continue

    Data Structures

    DEFAULT_EXCLUDE_PATTERNS Schema Contract

    The table below outlines the structural composition and matching contracts enforced by DEFAULT_EXCLUDE_PATTERNS:

    Pattern Category Syntactic Pattern Format Matching Semantics Functional Purpose
    Directory Pruning <dir_name>/* Prefix/Directory match with trailing wildcard Informs os.walk handlers to immediately mutate directory queues in-place, eliminating sub-tree traversal.
    Global File Extensions *.<ext> Suffix match via fnmatch Filters binaries, images, archives, compiled bytecode, and native libraries regardless of nested depth.
    Explicit File Literals .DS_Store, .env, *.lock Exact name match or exact suffix Strips system files, root configuration files, and package manager lock states.
    Deep-Path Secret Wildcards */<filename>, */<filename>.* Intermediate path wildcard Detects credentials, SSH private keys, and .env files located inside nested sub-packages or service directories.

    Exclusion Classification Breakdown

    The 120+ default patterns in DEFAULT_EXCLUDE_PATTERNS span seven functional categories:

    Category Name Pattern Count Representative Patterns Security / Operational Rationale
    Media & Static Assets 31 assets/*, *.png, *.mp4, *.pdf, *.zip Prevents ingestion of binary assets and non-text formats that cause UTF-8 decoding failures.
    Build & Distribution Caches 24 dist/*, build/*, target/*, .next/*, *.log Suppresses minified/generated bundles, compiler output, and transient log/swap artifacts.
    Environments & Secrets 33 venv/*, .env, */.env, *.pem, id_rsa, node_modules/*, *.lock Critical security boundary preventing token leakage; prevents dependency tree explosion.
    Language-Specific Artifacts 24 __pycache__/*, *.class, *.so, ios/Pods/*, android/app/build/* Eliminates bytecode, compiled object files, native shared libraries, and mobile frameworks.
    OS & Version Control 7 .git/*, .github/*, .DS_Store, Thumbs.db Filters internal VCS index trees, hook scripts, and operating system desktop metadata.
    Classic IDE Workspace State 8 .vscode/*, .idea/*, *.iml, .vs/* Prevents workspace-specific user settings, local tooling paths, and project metadata from polluting analysis.
    AI Assistants & Modern IDEs 16 .cursor/*, .cursorrules, .claude/*, .copilot/*, .windsurf/* Excludes external prompt templates, agent chat logs, rule configurations, and IDE runtime caches.
