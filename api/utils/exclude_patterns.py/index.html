    exclude_patterns.py

    Source: utils/exclude_patterns.py

    Technical Overview

    utils/exclude_patterns.py serves as the centralized pattern registry and exclusion filter baseline for all ingestion mechanisms across the codebase documentation pipeline. Following the directory traversal and file-system extraction capabilities established in crawl_local_files.py, this module externalizes file and directory skip rules, decoupling discovery logic from crawling policies. By consolidating common build outputs, virtual environments, version control metadata, multimedia binaries, package dependencies, and vendor artifacts into a unified data structure, it ensures that only human-authored, documentation-relevant source files reach downstream AST parsing, token counting, and LLM summarization.

    The module exports a static configuration set, DEFAULT_EXCLUDE_PATTERNS, formatted according to Unix glob syntax compatible with the standard library fnmatch module. Directory exclusions explicitly use trailing wildcards (for example, dist/*, node_modules/*, .git/*) to enable in-place subtree pruning during directory walking algorithms (os.walk), while individual file exclusions target binary, compressed, lockfile, and generated formats using extension patterns (such as *.png, *.zip, *.lock) or fixed basenames (such as .DS_Store, Thumbs.db, package-lock.json). In addition to traditional software engineering artifacts, the registry features comprehensive exclusions for modern AI agent configuration directories and scratchpads (such as .cursor/*, .windsurf/*, .cline/*, .roo/*, and .copilot/*), preventing transient tool states and model prompt dumps from leaking into synthesized repository architectures.

    Public API

    DEFAULT_EXCLUDE_PATTERNS

    Visibility: Public
    Signature: DEFAULT_EXCLUDE_PATTERNS: set[str]

    Description:
    DEFAULT_EXCLUDE_PATTERNS is a module-level constant containing an unmodifiable-by-convention set of glob pattern strings. It defines standard ignore rules for repository scanning across both local and remote filesystems. The patterns are organized into seven logical categories covering binary assets, build targets, dependency directories, language-specific compiled artifacts, OS metadata, IDE configurations, and AI agent workdirs. Each pattern follows standard fnmatch glob syntax. Trailing slashes followed by asterisks (/*) denote directory trees that should be skipped entirely, allowing crawler engines to prune traversal branches before descending into subdirectories.

Archive formats (*.zip, *.tar, *.gz, *.rar, *.7z) and office suite formats (*.docx, *.xlsx, *.pptx, *.pdf) are similarly omitted because their compressed and proprietary binary encodings cannot be processed by text summarization models without specialized document-parsing pipelines.

    This segment prevents crawlers from scanning external dependencies and configuration secrets. Virtual environments (venv/*, .venv/*, env/*) and third-party dependency trees (node_modules/*, vendor/*, packages/*) represent external library code rather than the repository's native implementation logic; scanning them would cause massive memory allocation spikes and introduce millions of irrelevant tokens. Environment files (.env, .env.*) are excluded to avoid accidentally leaking API keys, database credentials, or secret tokens into prompts dispatched to remote LLM providers. Lockfiles (*.lock, package-lock.json, yarn.lock, Cargo.lock, poetry.lock) are also excluded because their massive dependency graphs contain high-frequency hash listings that degrade prompt context quality.

    This section blocks version control internals and operating system desktop metadata. VCS trees such as Git internals (.git/*), SVN repositories (.svn/*), and Mercurial trees (.hg/*) contain object databases, index packfiles, and internal hooks that do not represent application source code. While .github/* contains CI/CD workflow YAML definitions, it is filtered out from source architecture synthesis to keep the generated documentation strictly oriented around application source mechanics. OS-generated desktop database files (.DS_Store on macOS, Thumbs.db and desktop.ini on Windows) are excluded to prevent cross-platform file conflicts and non-text reading errors during crawling.

    Example Usage: 

    # Extracted from crawler implementation in utils/crawl_local_files.py
from utils.exclude_patterns import DEFAULT_EXCLUDE_PATTERNS
import fnmatch
import os

# Evaluating directory branch pruning in os.walk
for root, dirs, files in os.walk(root_dir):
    # In-place mutation of dirs list stops os.walk from descending
    dirs[:] = [
        d for d in dirs
        if not any(
            fnmatch.fnmatch(d, pat.rstrip("/*")) or fnmatch.fnmatch(f"{d}/", pat)
            for pat in DEFAULT_EXCLUDE_PATTERNS
        )
    ]

    Data Structures

    DEFAULT_EXCLUDE_PATTERNS Registry Schema

    DEFAULT_EXCLUDE_PATTERNS is instantiated as a Python set of strings. The data structure does not implement custom methods or subclasses; it serves as a configuration set. The table below details its structural contract and operational pattern groups:

    Pattern Category Target Scope Syntax Convention Example Patterns Pipeline Impact
    1. Media and Static Assets Binary files, static images, archives, docs prefix/*, *.ext images/*, *.png, *.zip, *.pdf Prevents UTF-8 decoding crashes and skips binary token waste.
    2. Build and Caches Transformed outputs, build directories dirname/*, *.log dist/*, build/*, .next/*, *.log Skips minified artifacts, sourcemaps, logs, and compiled code.
    3. Environments and Lockfiles Dependencies, secrets, lockfiles dirname/*, basename node_modules/*, .venv/*, .env, *.lock Eliminates external libraries and guards against secret leakage.
    4. Language-Specific Compiled bytecode, runtime caches dirname/*, *.ext __pycache__/*, *.class, *.so, *.dll Prevents ingestion of machine-specific binary formats.
    5. OS and VCS Version control, OS desktop databases dirname/*, basename .git/*, .DS_Store, Thumbs.db Stops crawlers from traversing VCS object graphs and OS cache files.
    6. Classic IDEs Workspace configuration directories dirname/*, *.ext .vscode/*, .idea/*, *.iml, .vs/* Prevents local developer IDE state from influencing repo docs.
    7. AI Agents and IDEs Agent scratchpads, rules, state dirs dirname/*, basename .cursor/*, .windsurf/*, .claude/* Avoids recursive agent ingestion loops and prompt transcript leakage.

    Structural Pattern Conventions

    The patterns defined in DEFAULT_EXCLUDE_PATTERNS rely on two distinct syntactic conventions evaluated via Python's fnmatch module:

    1. Directory Branch Pruning Patterns (<directory_name>/*):
    2. Any pattern terminating with /* indicates an entire directory hierarchy.
    3. When processing local directories via os.walk, consuming modules strip the trailing /* via .rstrip("/*") or match against d + "/" to prune subdirectories in-place (dirs[:] = [...]), avoiding unnecessary filesystem traversal.

    4. When processing remote GitHub tree entries in crawl_github_files.py, path segments are evaluated against these patterns to avoid fetching entire Git tree hierarchies via REST.

    5. File Extension and Basename Patterns (*.ext, .filename):

    6. Extension-based patterns (*.pyc, *.lock, *.png) evaluate against the file's basename via fnmatch.fnmatch(filename, pattern).
    7. Fixed-name patterns (.DS_Store, package-lock.json, .env) require an exact match against the basename.

    Error Handling

    Because utils/exclude_patterns.py is a declarative, constant-only module, it does not define custom exceptions or execute dynamic logic that could raise runtime errors during initialization. However, its usage across the system involves specific defensive error-handling patterns:

    • Mutable State Isolation: DEFAULT_EXCLUDE_PATTERNS is defined as a standard mutable Python set. If a consuming module were to mutate DEFAULT_EXCLUDE_PATTERNS directly (for example, by calling .add() or .clear()), those changes would alter exclusion behavior across the entire runtime process. Consuming crawlers in crawl_local_files.py and crawl_github_files.py treat this set as read-only by copying it (e.g., set(DEFAULT_EXCLUDE_PATTERNS)) or merging it with caller-specified patterns into a separate collection before traversing files.
    • Glob Evaluation Divergence: Standard Python fnmatch translates globs into regular expressions using re.escape internally. If a malformed pattern containing non-standard glob expressions is introduced, fnmatch.translate() can raise re.error. The current patterns rely strictly on standard wildcards (*, ?, []), ensuring valid regex compilation across all supported Python runtimes.
    • Path Separator Normalization: Standard fnmatch behavior on Windows can diverge when paths contain backslashes (\) instead of POSIX forward slashes (/). Consuming crawler modules defensively normalize paths to POSIX format using path.replace("\\", "/") prior to evaluating entries against DEFAULT_EXCLUDE_PATTERNS.
