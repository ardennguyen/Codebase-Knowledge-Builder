    exclude_patterns.py

    Source: utils/exclude_patterns.py

    Technical Overview

    Following the filesystem traversal mechanics detailed in crawl_local_files.py, the utils/exclude_patterns.py module defines the centralized filtering baseline for the codebase crawler infrastructure. Ingesting an entire repository into a Large Language Model (LLM) context window requires strict structural hygiene; raw source repositories consistently contain non-code assets, compiled binaries, vendored packages, lockfiles, temporary caches, and virtual environments. Left unfiltered, these non-textual or machine-generated files cause memory bloat, trigger decoding exceptions, exhaust token budgets, and dilute prompt attention with noise. utils/exclude_patterns.py resolves these issues by supplying an exhaustive, category-indexed set of glob patterns configured to intercept unneeded files and directories before disk read or remote API payload transfer occurs.

    The module operates as a declarative configuration layer centered on the DEFAULT_EXCLUDE_PATTERNS constant. The patterns follow POSIX globbing conventions via the Python fnmatch specification, distinguishing directory subtrees from leaf files through trailing /* wildcards. When directory crawling is executed by crawl_local_files.py using os.walk() or by crawl_github_files.py via the GitHub REST and Git tree APIs, traversal engines evaluate candidate paths against this pattern set. Trailing slash patterns empower directory crawlers to prune branches in-place at the root level—mutating directory lists to prevent recursing into massive hierarchies such as node_modules or .git—while extension and exact-match patterns filter individual artifacts.

    Beyond optimizing I/O throughput and preventing context saturation, utils/exclude_patterns.py enforces data sanitization and security boundaries. By default, it blocks environment configuration files (.env, .env.*), version control metadata (.git/*, .svn/*), and local developer settings (.vscode/*, .idea/*), preventing the accidental exposure of secrets, API credentials, or machine-specific paths to the inference pipeline. Furthermore, modern development tools and agent rules (.cursor/*, .cursorrules, .windsurf/*, .cline/*) are excluded to avoid prompt injection or recursive context pollution from other AI coding assistants.

    Public API

    The module exposes a single public configuration constant, DEFAULT_EXCLUDE_PATTERNS, which represents the canonical exclusion set consumed across the codebase analysis architecture.

    DEFAULT_EXCLUDE_PATTERNS

    Visibility: Public
    Signature: DEFAULT_EXCLUDE_PATTERNS: set[str]

    Description: A comprehensive Python set of glob pattern strings designed for fnmatch wildcard evaluation. Patterns targeting directory subtrees terminate with /* (e.g., node_modules/*, dist/*), instructing the crawler to truncate recursive directory descent. Patterns targeting specific file types utilize standard wildcard extensions (e.g., *.png, *.pyc), and security-critical rules leverage exact matching (e.g., .env, .DS_Store).

    Example: 

    # Consumption pattern inside utils/crawl_local_files.py
from utils.exclude_patterns import DEFAULT_EXCLUDE_PATTERNS
import fnmatch

# Pruning directory traversal in os.walk
def should_exclude(rel_path: str, exclude_patterns: set[str]) -> bool:
    for pattern in exclude_patterns:
        if fnmatch.fnmatch(rel_path, pattern):
            return True
        if pattern.endswith("/*") and fnmatch.fnmatch(rel_path, pattern[:-2]):
            return True
    return False

# Invocation within os.walk loop
active_excludes = DEFAULT_EXCLUDE_PATTERNS.copy()

    Error Handling

    Because utils/exclude_patterns.py provides only static constant definitions without runtime function invocations, it raises no exceptions directly. However, runtime issues can emerge in consuming modules during pattern evaluation:

    • Path Separator Normalization: Standard fnmatch rules assume POSIX directory separators (/). On Windows platforms, paths returned by os.walk() or os.path.join() utilize backslashes (\). Consuming crawlers must normalize paths (e.g., via path.replace("\\", "/")) prior to evaluating them against DEFAULT_EXCLUDE_PATTERNS. Failure to normalize causes patterns containing / to fail silently, resulting in inadvertent ingestion of directories like node_modules.
    • Directory Wildcard Pruning: Patterns targeting directory subtrees use the /* suffix (such as venv/*). A direct match between a raw directory name (e.g., "venv") and "venv/*" evaluates to False in standard fnmatch.fnmatch() calls. Consuming crawlers must therefore evaluate both the directory name and its trailing slash variant (f"{dirname}/*"), or strip the /* suffix, to ensure directories are pruned before recursing into them.
    • Pattern Extension Safety: When users supply custom exclusion rules via CLI arguments (e.g., --exclude), consuming modules should merge user inputs with DEFAULT_EXCLUDE_PATTERNS into a new set instance. The default set remains immutable at the module level, preventing side effects across isolated crawler runs.
