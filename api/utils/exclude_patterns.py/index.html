    exclude_patterns.py

    Source: utils/exclude_patterns.py

    Following the filesystem traversal mechanics established in crawl_local_files.py, the exclude_patterns.py module defines the baseline exclusion rules used across both local and remote repository crawling pipelines. It acts as the central filtering configuration for preventing context window exhaustion, unparseable binary ingestion, credential leaks, and redundant build artifact parsing within the Codebase-Knowledge-Builder system.

    Technical Overview

    The primary responsibility of utils/exclude_patterns.py is to declare DEFAULT_EXCLUDE_PATTERNS, an immutable baseline configuration set of glob rules formatted according to standard Unix shell wildcard syntax (fnmatch). When building knowledge graphs and architecture representations via Large Language Models (LLMs), feeding irrelevant, auto-generated, or excessively large binary files degrades generation quality and rapidly depletes input token quotas.

    This module centralizes filtering declarations into a unified constant. Rather than relying solely on repository-specific .gitignore files—which are frequently absent, misconfigured, or inadequate for LLM context curation—the rules defined here establish an aggressive, domain-aware pruning baseline.

    Key Architectural Responsibilities

    1. Token Window Protection: Automatically skips dependency directories (e.g., node_modules/, venv/), package lockfiles (e.g., package-lock.json, poetry.lock), and framework build caches (e.g., .next/, target/, dist/) that contain millions of redundant or auto-generated tokens.
    2. Binary and Media Rejection: Filters out non-text static assets (e.g., .png, .mp4, .pdf, .zip, .tar.gz) and compiled object code (.pyc, .class, .dll, .so, .exe), preventing decoding failures and memory overhead during file reads.
    3. Secret and Environment Sanitization: Blocks root and nested environmental variable files (.env, .env.*) from entering prompt generation pipelines, avoiding accidental leakage of API credentials and cryptographic secrets.
    4. Tooling and Agent Workspace Isolation: Excludes metadata, cache stores, and instruction sets from modern AI IDEs and agents (e.g., .cursor/, .windsurf/, .cline/, .agent/, .continue/), ensuring the LLM analyzes the actual software architecture rather than ephemeral agent state files.

    Pattern Evaluation Pipeline

    The rules in DEFAULT_EXCLUDE_PATTERNS are evaluated during directory discovery and file matching in both crawl_local_files.py and crawl_github_files.py. The matching logic operates in two distinct tiers: directory-level subtree pruning and file-level path filtering.

    Module-Level Constants

    DEFAULT_EXCLUDE_PATTERNS

    Visibility: Public
    Type: set[str]
    Signature: 

    DEFAULT_EXCLUDE_PATTERNS: set[str]

    Description: A constant Python set of strings containing glob patterns compatible with fnmatch.fnmatch() and standard Unix globbing. The collection encompasses 7 distinct categories of files and directories that are omitted by default during repository ingestion.

    Directory patterns explicitly terminate with a trailing /* wildcard. Crawlers inspect directory names against stripped variants of these patterns (or evaluate the directory path suffixed with /*) to immediately prune entire directory subtrees from the traversal stack prior to disk or network I/O. File patterns utilize leading wildcard extensions (*.ext), exact base names (e.g., .DS_Store), or prefix wildcards (e.g., .env.*).

    The DEFAULT_EXCLUDE_PATTERNS set is logically partitioned into 7 functional domains in the source code. The following subsections detail each category, showing the exact source code slices and explaining the underlying architectural rationale.

    Behavior & Rationale

    This category excludes raster and vector graphics, audio/video streams, office documents, compressed archive formats, and standard static asset storage directories.

    • Binary Safety: Non-text assets (such as .png, .zip, .pdf) cannot be meaningfully interpreted by source code analysis prompts without specialized multimodal parsing. Ingesting these files triggers UnicodeDecodeError exceptions in text-oriented ingestion pipelines.
    • Payload Volume: Compressed archives (.zip, .tar.gz) and multimedia files (.mp4, .mov) contain multi-megabyte payloads that would quickly exceed crawler memory buffers and API transmission boundaries.
    • Subtree Pruning: Common static directory paths such as public/*, static/*, and assets/* are bypassed entirely, eliminating hundreds of client-side web assets (favicons, bundled stylesheets, icons) that carry minimal structural information about core business logic.

    • Compiled Target Directories: Standard build output locations like target/* (Rust/Cargo/Maven), bin/* and obj/* (.NET/C#), and dist/* / build/* (C/C++, Python wheels, npm packages) contain duplicated or compiled copies of source files already present in primary source directories.
    • Documentation and Non-Core Code: Directories such as docs/*, examples/*, test/*, tests/*, deprecated/*, and legacy/* are excluded to maintain a high signal-to-noise ratio in the generated architecture knowledge base, focusing the LLM's attention on active production code.
    • Ephemeral Files: Matchers like *.log, *.tmp, *.bak, and *.swp (Vim swap files) prevent ingestion of volatile runtime data.

    Behavior & Rationale

    This partition prevents third-party package dependencies, virtual environment trees, environment secret files, and dependency lockfiles from contaminating the knowledge pipeline.

    • Dependency Directory Pruning: The presence of node_modules/*, vendor/* (PHP/Composer or Go), or venv/* / .venv/* (Python) can introduce tens of thousands of third-party source files into the crawl. Pruning these subtrees reduces traversal duration from minutes to milliseconds.
    • Lockfile Exclusions: Detailed dependency tree resolutions (e.g., package-lock.json, yarn.lock, Cargo.lock, poetry.lock) frequently span tens of thousands of lines of machine-generated metadata. Analyzing them provides low architectural value while consuming massive token budgets.
    • Secret Protection: Patterns matching .env and .env.* (e.g., .env.local, .env.production) ensure runtime credentials, database connection strings, and API keys are never captured in crawler payloads or transmitted to external LLM providers.

    • Java Virtual Machine (JVM): Excludes compiled Java bytecode (*.class), Java archives (*.jar, *.war, *.ear, *.nar), and Gradle dependency caches (.gradle/*).
    • Native C/C++/Rust Artifacts: Strips compiled machine code object files (*.o, *.obj), static libraries (*.a, *.lib), shared libraries (*.so, *.dylib, *.dll), and compiled executables (*.exe).
    • Mobile Subsystems: Bypasses CocoaPods dependency trees (ios/Pods/*) and Android Gradle compilation directories (android/.gradle/*, android/app/build/*).

    Behavior & Rationale

    This category handles operating system metadata files and version control management internals.

    • VCS Internals: Suppresses the internal database directories of version control systems, including Git (.git/*), Subversion (.svn/*), and Mercurial (.hg/*). It also excludes GitHub-specific configuration trees (.github/*, which includes CI/CD workflow YAMLs, issue templates, and dependabot configurations) to focus ingestion strictly on functional source code.
    • Operating System Metadata: Filters out macOS Finder metadata (.DS_Store), Windows Explorer thumbnail caches (Thumbs.db), and Windows folder customization files (desktop.ini), preventing platform-specific system artifacts from polluting cross-platform code crawls.

    • Agent Scratchpads and State Trees: Directories like .cursor/*, .windsurf/*, .cline/*, .roo/*, .agent/*, .agents/*, .continue/*, .aide/*, .gemini/*, .antigravity/*, .claude/*, and .copilot/* store local conversation histories, indexed vector stores, shadow workspaces, and execution state trees. Excluding these prevents cyclical prompting loops and large metadata ingestions.

    Comparative Pattern Classification

    The patterns declared in DEFAULT_EXCLUDE_PATTERNS follow four specific glob matching formats, each evaluated through distinct logic in the ingestion engines:

    Pattern Syntax Type Examples Matching Mechanism Crawler Application
    Directory Wildcard (dir/*) node_modules/*, dist/*, .git/* Matches directory paths directly. The suffix /* is stripped during directory-level evaluation. Used in os.walk() to prune dirs in-place, skipping entire subtrees before child traversal.
    File Extension Wildcard (*.ext) *.jpg, *.pyc, *.lock, *.class fnmatch.fnmatch(filename, "*.ext") or checking file suffixes. Evaluated against individual file names during directory iterations.
    Exact File Match (name) .DS_Store, .cursorrules, .env Exact string equality filename == pattern or fnmatch.fnmatch(filename, pattern). Checked against base filenames to eliminate system and configuration files.
    Prefix / Infix Wildcard (prefix*) .env.*, output-test*/* Evaluated against relative paths or filenames using fnmatch. Blocks variable-named files like .env.development or dynamic test output directories.

    Consumption in crawl_local_files.py

    In crawl_local_files.py, DEFAULT_EXCLUDE_PATTERNS is loaded as the base exclusion set. During traversal with os.walk(), directory entries are evaluated against these patterns (stripping the trailing /* for directory comparisons). Matching subdirectories are removed directly from the dirs list, which prevents os.walk() from descending into those directories. Individual files are subsequently checked against file-level glob patterns using fnmatch.fnmatch().

    Consumption in crawl_github_files.py

    In crawl_github_files.py, DEFAULT_EXCLUDE_PATTERNS is combined with repository .gitignore definitions using pathspec or fnmatch filters. When inspecting tree structures retrieved from the GitHub REST API or local temporary Git clones, paths matching these exclusion rules are discarded before blob retrieval, reducing API usage and transfer overhead.
