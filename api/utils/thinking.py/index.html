    thinking.py

    Source: utils/thinking.py

    Technical Overview

    The utils/thinking.py module establishes the configuration and resolution engine for managing reasoning effort ("thinking flows") across all Large Language Model (LLM) invocation sites in the Codebase-Knowledge-Builder pipeline. Tunable reasoning models (including Anthropic Claude 3.7 / Opus, Google Gemini 2.5 and 3.x, and DeepSeek backends exposed via OpenRouter) provide configurable reasoning token allocations. Because reasoning tokens introduce latency and consumption overhead, enforcing a single uniform thinking budget across heterogeneous pipeline tasks is suboptimal. Heavy architectural synthesis operations require extensive cognitive reasoning, whereas mechanical transformations, file filtering, and internationalization tasks require minimal or no reasoning overhead.

    This module provides an abstraction that decouples pipeline node identifiers from provider-specific thinking configurations. At its core, the module manages an ordered scale of abstract reasoning tiers (minimal through max) and maps them to pipeline execution call sites (NODE_KEYS). Thinking plans are resolved through a deterministic precedence hierarchy: explicit per-node overrides take precedence over global settings, which in turn override predefined profile matrices (economy, balanced, quality, max). The default auto profile dynamically resolves to balanced when communicating with models capable of fine-grained reasoning control (ANTHROPIC, GEMINI, OPENROUTER), and resolves to off (using provider defaults) when dispatching to local or OpenAI-compatible backends like Ollama.

    At runtime, orchestration nodes query their designated thinking level through resolve_thinking_level(), and downstream provider adapters invoke clamp_level() to project abstract levels onto concrete model-supported capabilities (such as Anthropic output effort configurations, Gemini integer budgets or discrete levels, and OpenRouter reasoning fields).

    Public API

    THINKING_LEVELS

    Visibility: Public
    Signature: THINKING_LEVELS = ("minimal", "low", "medium", "high", "xhigh", "max")

    Description: An immutable tuple defining the standardized, ordered progression of abstract reasoning effort levels. The scale extends from minimal (primarily exposed by select OpenRouter backends) up to max (reserved for intensive architectural synthesis in explicit configurations). Predefined operational profiles reference tiers from low to max, while clamp_level relies on the positional indexing of this tuple to perform nearest-neighbor mathematical distance calculations when negotiating provider capabilities.

    THINKING_PROFILES

    Visibility: Public
    Signature: THINKING_PROFILES = ("auto", "off", "economy", "balanced", "quality", "max")

    Description: An immutable tuple enumerating all valid profile names accepted by the CLI --thinking-profile argument. These profiles govern the baseline distribution of reasoning effort across pipeline execution stages. Special profiles include auto (which resolves dynamically to balanced or off depending on the active model provider) and off (which maps every node to None to preserve upstream model default behaviors).

    PROFILED_PROVIDERS

    Visibility: Public
    Signature: PROFILED_PROVIDERS = ("ANTHROPIC", "GEMINI", "OPENROUTER")

    Description: An immutable tuple designating the model providers whose client integrations natively support granular thinking and reasoning controls. When the user sets --thinking-profile auto, resolve_profile_name() checks this collection to determine whether to enable the balanced profile or default to off.

    resolve_profile_name()

    Visibility: Public
    Signature: def resolve_profile_name(profile: str | None, provider: str | None) -> str:

    Description: Resolves the user-supplied profile configuration into a concrete profile name based on provider capabilities. If the supplied profile string is None or explicitly set to "auto", the function inspects the active provider string. Providers listed in PROFILED_PROVIDERS resolve to "balanced", ensuring modern reasoning models allocate reasoning tokens according to the profile matrix. Non-profiled providers (such as local Ollama endpoints or generic OpenAI-compatible APIs) resolve to "off", causing nodes to defer to backend model defaults.

    Parameters: * profile (str | None): The requested profile identifier from CLI configuration or environment variables, or None. * provider (str | None): The resolved LLM provider identifier (e.g., "ANTHROPIC", "GEMINI", "OPENROUTER", "OLLAMA").

    Returns: * str: The normalized, lower-case profile name ("off", "economy", "balanced", "quality", or "max").

    Example: 

    def resolve_profile_name(profile: str | None, provider: str | None) -> str:
    """Resolve `auto` to a concrete profile for the active provider."""
    profile = (profile or "auto").lower()
    if profile == "auto":
        return "balanced" if provider in PROFILED_PROVIDERS else "off"
    return profile

    The function handles case-insensitivity by converting incoming strings via .lower() and defaults empty values to "auto". It acts as an early configuration gate in main.py before plans are compiled, preventing unsupported reasoning payloads from reaching endpoints that reject them.

    clamp_level()

    Visibility: Public
    Signature: def clamp_level(level: str, supported) -> str | None:

    Description: Maps an abstract reasoning effort tier to the closest level supported by a specific model. If the requested level is directly present in the supported collection, it is returned unchanged. Otherwise, the function calculates the absolute numeric distance between the index of the requested level in THINKING_LEVELS and the index of each supported candidate level. In the event of an equidistant tie between two candidate tiers, the function deterministically resolves to the lower effort level to prevent unexpected budget inflation. If the requested level is not in THINKING_LEVELS or no supported options intersect with THINKING_LEVELS, None is returned.

    Parameters: * level (str): The target thinking level string (e.g., "high", "xhigh"). * supported (Iterable[str]): A collection of thinking level strings supported by the target model or provider catalog.

    Returns: * str | None: The exact matching or nearest supported level string, or None if no valid level can be resolved.

    Example: 

    def clamp_level(level: str, supported) -> str | None:
    """Return `level` if the model supports it, else the nearest supported level on
    THINKING_LEVELS (ties → lower). None when nothing on the scale is supported."""
    if level in supported:
        return level
    ranked = [lvl for lvl in THINKING_LEVELS if lvl in supported]
    if not ranked or level not in THINKING_LEVELS:
        return None
    target = THINKING_LEVELS.index(level)
    return min(ranked, key=lambda lvl: (abs(THINKING_LEVELS.index(lvl) - target), THINKING_LEVELS.index(lvl)))

    The algorithm constructs ranked, a filtered list preserving the canonical progression of THINKING_LEVELS. The min() evaluation key calculates (abs(THINKING_LEVELS.index(lvl) - target), THINKING_LEVELS.index(lvl)). The primary tuple element minimizes index distance, while the secondary element breaks ties by selecting the smaller absolute index.

    parse_overrides()

    Visibility: Public
    Signature: def parse_overrides(values: list[str] | None) -> tuple[dict, list[str]]:

    Description: Parses and validates raw CLI --thinking-override arguments formatted as NODE=LEVEL. The function iterates over the input strings, splits each entry at the first = separator, strips extraneous whitespace, and lowercases both components. Each entry is validated against NODE_KEYS and THINKING_LEVELS. Well-formed entries are added to a dictionary mapping node names to target levels, while invalid or malformed tokens are recorded in an error list for downstream reporting.

    Parameters: * values (list[str] | None): A list of unparsed string parameters from the command line, or None.

    Returns: * tuple[dict, list[str]]: A 2-tuple containing: * dict: A dictionary mapping valid node_key strings to their overridden level strings. * list[str]: A list containing the original strings that failed syntax, node key, or level validation.

    Example: 

    def parse_overrides(values: list[str] | None) -> tuple[dict, list[str]]:
    """Parse NODE=LEVEL strings. Returns (overrides, invalid_values)."""
    overrides, invalid = {}, []
    for value in values or []:
        node, sep, level = value.partition("=")
        node, level = node.strip().lower(), level.strip().lower()
        if not sep or node not in NODE_KEYS or level not in THINKING_LEVELS:
            invalid.append(value)
        else:
            overrides[node] = level
    return overrides, invalid

    The function guarantees non-raising execution by intercepting missing assignment operators (not sep), unknown node strings (node not in NODE_KEYS), and unsupported level identifiers (level not in THINKING_LEVELS). It isolates parsing validation failures so callers can display comprehensive error messages without terminating prematurely.

    build_thinking_plan()

    Visibility: Public
    Signature: def build_thinking_plan(profile: str, mode: str, global_level: str | None, overrides: dict) -> dict:

    Description: Compiles the master thinking plan dictionary assigning a thinking level (or None) to every entry in NODE_KEYS. Precedence is strictly enforced: specific per-node overrides take highest priority; if absent, an explicit global_level is applied across all nodes; if no global level is specified, values are populated from the active profile table in _PROFILES, incorporating any mode-specific adjustments defined in _MODE_ADJUSTMENTS. If the resolved profile is "off", all nodes default to None.

    Parameters: * profile (str): The resolved profile name (must already be normalized via resolve_profile_name()). * mode (str): The active pipeline documentation mode ("tutorial", "advanced", "sdk", or "api-reference"). * global_level (str | None): An explicit effort level string specified to override profile defaults for all nodes, or None. * overrides (dict): A dictionary of node-to-level overrides (typically obtained from parse_overrides()).

    Returns: * dict: A dictionary mapping every node key in NODE_KEYS to a thinking level string or None.

    Example: 

    def build_thinking_plan(profile: str, mode: str, global_level: str | None, overrides: dict) -> dict:
    """Return {node_key: level | None} for every NODE key.

    Precedence: overrides > global_level > profile table (+ mode adjustments).
    `profile` must already be resolved (see resolve_profile_name).
    """
    if global_level:
        plan = dict.fromkeys(NODE_KEYS, global_level.lower())
    elif profile in _PROFILES:
        plan = dict(_PROFILES[profile])
        plan.update(_MODE_ADJUSTMENTS.get(profile, {}).get(mode, {}))
    else:  # "off": every node uses the model's default thinking behavior
        plan = dict.fromkeys(NODE_KEYS)
    plan.update(overrides)
    return plan

    This builder provides deterministic plan construction. When configuring from _PROFILES, it performs a shallow copy of the profile dictionary and applies any relevant mode adjustments before overlaying overrides. When global_level is supplied, profile lookup is bypassed entirely, setting all nodes to the lowercased global value before applying overrides.

    resolve_thinking_level()

    Visibility: Public
    Signature: def resolve_thinking_level(shared: dict, node_key: str) -> str | None:

    Description: Retrieves the active thinking level for an individual pipeline execution node from the shared execution context state. It inspects shared["thinking_plan"] for the given node_key. If the plan is uninitialized or does not contain the key, it falls back to the top-level shared["thinking_level"] value.

    Parameters: * shared (dict): The runtime state dictionary passed between pipeline nodes. * node_key (str): The target node identifier from NODE_KEYS.

    Returns: * str | None: The resolved thinking level string (e.g., "medium"), or None if the node should use default model behavior.

    Example: 

    def resolve_thinking_level(shared: dict, node_key: str) -> str | None:
    """Thinking level for one LLM call site. Falls back to the global level when no plan exists."""
    plan = shared.get("thinking_plan")
    if plan and node_key in plan:
        return plan[node_key]
    return shared.get("thinking_level")

    This helper serves as the standard access point for orchestrators and workflow nodes before making LLM calls. It encapsulates dictionary access guards, ensuring nodes gracefully fall back to global settings when operating outside a full plan structure.

    describe_plan()

    Visibility: Public
    Signature: def describe_plan(plan: dict, mode: str | None = None) -> str:

    Description: Generates a compact, comma-separated string representation of the thinking plan for logging and startup telemetry. To reduce noise, it filters the displayed nodes to only those that execute in the current mode (via MODE_NODES). If a mode is not provided or not found, it defaults to displaying all NODE_KEYS. Any node mapped to None or an empty value is rendered as "default".

    Parameters: * plan (dict): The compiled thinking plan dictionary mapping node keys to levels. * mode (str | None): The documentation mode filter (e.g., "api-reference"), or None.

    Returns: * str: A formatted string showing active node allocations (e.g., "filter_files=low, extract_facts=low, write_chapters=medium").

    Example: 

    def describe_plan(plan: dict, mode: str | None = None) -> str:
    """Compact one-line rendering for the startup config display (only nodes that run in `mode`)."""
    keys = MODE_NODES.get(mode, NODE_KEYS)
    return ", ".join(f"{key}={plan.get(key) or 'default'}" for key in keys)

    This function formats the startup configuration displayed in CLI logs. By scoping output to relevant node keys via MODE_NODES.get(mode, NODE_KEYS), it omits inactive pipeline nodes, keeping initialization summaries clear and focused.

    Profile Matrix Schema

    The structure of the _PROFILES dictionary maps profile identifiers to complete node-to-effort mappings.

    Field Type Description
    economy dict[str, str] Low-cost profile optimizing for token expenditure and latency.
    balanced dict[str, str] Default profile for reasoning-capable models, balancing cost and synthesis depth.
    quality dict[str, str] High-effort profile allocating elevated reasoning to planning and drafting nodes.
    max dict[str, str] Profile utilizing xhigh and max levels for complex codebases.

    Error Handling

    The module implements a fail-safe, non-raising design across all its utilities:

    • Malformed CLI Overrides: In parse_overrides(), invalid tokens—including strings lacking an = delimiter, unrecognized node keys, and unsupported level names—are appended to an invalid list rather than raising exceptions like ValueError or KeyError. This allows CLI callers to report all formatting issues in a single diagnostic output.
    • Unrecognized Profiles: In build_thinking_plan(), if an unrecognized profile name is passed, the function falls back to the "off" profile branch, safely populating all nodes with None via dict.fromkeys(NODE_KEYS).
    • Level Clamping Discrepancies: In clamp_level(), if the target level does not exist in THINKING_LEVELS or none of the provider's supported options intersect with the project's level hierarchy, the function safely returns None. Equidistant ties between supported levels resolve to the lower-index level via min() key ranking, avoiding unexpected token consumption increases.
    • Missing Runtime Plans: In resolve_thinking_level(), missing context dictionaries, null thinking_plan references, or unrecognized node keys fall back to shared.get("thinking_level") before returning None.
