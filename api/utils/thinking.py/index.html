    thinking.py

    Source: utils/thinking.py

    Following the prompt synthesis and template loading utilities documented in utils/prompts.py, the utils/thinking.py module establishes the cognitive budgeting and reasoning effort architecture across the documentation synthesis pipeline. While prompts.py controls the textual structure of messages dispatched to Large Language Models (LLMs), thinking.py dictates the depth of reasoning tokens allocated to each execution stage, balancing synthesis depth against financial expenditure and processing latency.

    Technical Overview

    The utils/thinking.py module defines the per-node reasoning effort subsystem ("thinking flows") for Codebase-Knowledge-Builder. Contemporary LLM architectures—notably the Anthropic Claude 3.7/Sonnet/Opus models, Google Gemini 2.5/3.x series, and reasoning models served through OpenRouter—support configurable reasoning budgets ("thinking tokens"). In complex codebase analysis workflows, reasoning requirements vary drastically across pipeline nodes: high-level conceptual discovery (identify_abstractions, reduce_abstractions) requires substantial cognitive exploration, whereas mechanical classifications (filter_files) or conversational translations (translate_strings) require minimal or zero thinking overhead. This module formalizes those allocations into predictable execution profiles.

    The module computes a monolithic thinking_plan mapping each known pipeline execution site (NODE_KEYS) to a discrete thinking tier. The configuration hierarchy enforces strict precedence: per-node CLI overrides (--thinking-override NODE=LEVEL) supersede a global tier setting (--thinking-level LEVEL), which in turn supersedes profile presets (--thinking-profile PROFILE). Profiles (economy, balanced, quality, max) distribute effort levels according to the analytical complexity of each node, applying mode-specific adjustments for distinct operational workflows (such as advanced versus tutorial). When the default profile auto is supplied, the module dynamically resolves it to balanced for providers exposing first-class reasoning controls (Anthropic, Gemini, OpenRouter) and disables it (off) for generic or local endpoints like Ollama.

    At inference time, call sites retrieve their assigned thinking level via resolve_thinking_level(), and provider drivers adapt this target level to specific vendor APIs using clamp_level(). Because different providers and models expose distinct discrete or continuous reasoning parameter spaces (for example, categorical effort tiers versus raw token count bounds), clamp_level() provides an arithmetic nearest-neighbor fallback that preserves the intent of the profile while strictly adhering to model-specific parameter constraints.

    Public API

    resolve_profile_name()

    Visibility: Public
    Signature: def resolve_profile_name(profile: str | None, provider: str | None) -> str:

    Description: Resolves a raw profile name argument into a concrete execution profile. If the profile string is empty or explicitly set to "auto", it inspects the designated model provider. Providers listed in PROFILED_PROVIDERS (ANTHROPIC, GEMINI, OPENROUTER) support per-node reasoning allocations and default to "balanced". All other providers (such as local OLLAMA instances or third-party OpenAI-compatible endpoints) resolve to "off", allowing the underlying model to operate with its native default reasoning configuration. Explicit profile selections (e.g., "economy", "quality") are normalized to lowercase and returned unchanged.

    Parameters: * profile (str | None): The requested profile identifier from user configuration or CLI arguments. * provider (str | None): The active LLM provider key resolved by runtime configuration.

    Returns: * str: The resolved concrete profile name ("balanced", "off", "economy", "quality", or "max").

    Raises: * This function does not raise exceptions internally.

    Example: 

    def resolve_profile_name(profile: str | None, provider: str | None) -> str:
    """Resolve `auto` to a concrete profile for the active provider."""
    profile = (profile or "auto").lower()
    if profile == "auto":
        return "balanced" if provider in PROFILED_PROVIDERS else "off"
    return profile

    The function provides predictable profile resolution early during process startup in main.py. By normalizing string casing and treating empty values identically to "auto", it ensures that downstream initialization routines receive a standardized profile key.

    clamp_level()

    Visibility: Public
    Signature: def clamp_level(level: str, supported) -> str | None:

    Description: Maps an arbitrary target thinking effort level to the nearest supported level exposed by an underlying model or provider driver. The function evaluates supported (typically a set, list, or tuple of allowed strings). If level is directly present in supported, it is returned immediately. Otherwise, it filters the canonical THINKING_LEVELS scale down to those present in supported. If no overlap exists or level is not a recognized member of THINKING_LEVELS, the function returns None. When multiple valid levels exist, it calculates the distance between the target level's index in THINKING_LEVELS and each candidate's index, selecting the candidate with minimal absolute distance; ties are deterministically resolved toward the lower index on the scale.

    Parameters: * level (str): The desired thinking level string to clamp. * supported (Iterable[str]): A collection of thinking level strings accepted by the target model or provider.

    Returns: * str | None: The exact level if supported, the nearest supported neighbor on the canonical scale, or None if the model does not support any scale levels.

    Raises: * This function does not raise exceptions internally.

    Example: 

    def clamp_level(level: str, supported) -> str | None:
    """Return `level` if the model supports it, else the nearest supported level on
    THINKING_LEVELS (ties → lower). None when nothing on the scale is supported."""
    if level in supported:
        return level
    ranked = [lvl for lvl in THINKING_LEVELS if lvl in supported]
    if not ranked or level not in THINKING_LEVELS:
        return None
    target = THINKING_LEVELS.index(level)
    return min(ranked, key=lambda lvl: (abs(THINKING_LEVELS.index(lvl) - target), THINKING_LEVELS.index(lvl)))

    This clamping algorithm allows provider drivers in llm_gemini.py, llm_anthropic.py, and llm_openrouter.py to accept uniform pipeline profiles without raising runtime errors when an upstream model exposes a restricted subset of reasoning tiers (such as only accepting low, medium, and high). The secondary sort key THINKING_LEVELS.index(lvl) ensures strict downward tie-breaking, preventing accidental escalation into higher token usage tiers when equidistant choices occur.

    parse_overrides()

    Visibility: Public
    Signature: def parse_overrides(values: list[str] | None) -> tuple[dict, list[str]]:

    Description: Parses a collection of command-line override arguments formatted as NODE=LEVEL strings. It evaluates each entry by splitting on the first = delimiter, stripping surrounding whitespace, and converting tokens to lowercase. A parsed pair is accepted only if the separator exists, the node identifier belongs to NODE_KEYS, and the effort level is an element of THINKING_LEVELS. Valid entries are aggregated into a dictionary mapping node names to level strings. Any malformed entries, unknown node keys, or invalid levels are captured in an invalid list and returned to the caller for operational logging.

    Parameters: * values (list[str] | None): List of raw key-value string arguments provided via --thinking-override.

    Returns: * tuple[dict, list[str]]: A 2-tuple containing: 1. overrides (dict[str, str]): Mapping of validated node keys to validated thinking levels. 2. invalid (list[str]): Raw argument strings that failed syntax or schema validation.

    Raises: * This function does not raise exceptions internally.

    Example: 

    def parse_overrides(values: list[str] | None) -> tuple[dict, list[str]]:
    """Parse NODE=LEVEL strings. Returns (overrides, invalid_values)."""
    overrides, invalid = {}, []
    for value in values or []:
        node, sep, level = value.partition("=")
        node, level = node.strip().lower(), level.strip().lower()
        if not sep or node not in NODE_KEYS or level not in THINKING_LEVELS:
            invalid.append(value)
        else:
            overrides[node] = level
    return overrides, invalid

    By decoupling parsing from exception raising, parse_overrides() allows the application entry point main.py to gracefully collect all syntax and semantic configuration anomalies in a single pass. This ensures comprehensive CLI feedback before halting pipeline execution or proceeding with sanitized parameters.

    build_thinking_plan()

    Visibility: Public
    Signature: def build_thinking_plan(profile: str, mode: str, global_level: str | None, overrides: dict) -> dict:

    Description: Constructs the complete mapping of pipeline node keys to thinking effort levels for a workflow execution session. The construction follows a strict four-tier hierarchy: 1. If global_level is provided, every node in NODE_KEYS is initialized to that global tier. 2. Otherwise, if profile matches an entry in _PROFILES, base levels are copied from that profile table, and any differential adjustments defined in _MODE_ADJUSTMENTS for the active mode are merged. 3. If profile is "off" or unrecognized, every node is assigned None, directing providers to use their default inference settings. 4. Finally, validated per-node overrides are merged onto the plan, taking unconditional precedence over all preceding tiers.

    Parameters: * profile (str): The resolved profile name (must be pre-resolved via resolve_profile_name()). * mode (str): The execution mode of the pipeline (e.g., "tutorial", "advanced", "sdk", "api-reference"). * global_level (str | None): Optional uniform thinking level applied across all nodes. * overrides (dict[str, str]): Validated dictionary of per-node level overrides.

    Returns: * dict[str, str | None]: A complete dictionary mapping every key in NODE_KEYS to a thinking level string or None.

    Raises: * This function does not raise exceptions internally.

    Example: 

    def build_thinking_plan(profile: str, mode: str, global_level: str | None, overrides: dict) -> dict:
    """Return {node_key: level | None} for every NODE key.

    Precedence: overrides > global_level > profile table (+ mode adjustments).
    `profile` must already be resolved (see resolve_profile_name).
    """
    if global_level:
        plan = dict.fromkeys(NODE_KEYS, global_level.lower())
    elif profile in _PROFILES:
        plan = dict(_PROFILES[profile])
        plan.update(_MODE_ADJUSTMENTS.get(profile, {}).get(mode, {}))
    else:  # "off": every node uses the model's default thinking behavior
        plan = dict.fromkeys(NODE_KEYS)
    plan.update(overrides)
    return plan

    The construction strategy guarantees that the emitted dictionary contains an entry for every known pipeline node, eliminating runtime key lookup failures across downstream workflow components. By evaluating _MODE_ADJUSTMENTS, the plan balances resource consumption; for instance, running the advanced mode under an economy profile selectively elevates write_chapters from low to medium because advanced architectural synthesis requires deeper rationalization than standard tutorial prose.

    resolve_thinking_level()

    Visibility: Public
    Signature: def resolve_thinking_level(shared: dict, node_key: str) -> str | None:

    Description: Resolves the operational thinking level for an individual LLM execution site during graph node execution. It inspects the shared pipeline state dictionary for an active thinking_plan. If a plan exists and contains node_key, its mapped value is returned. If no plan is found or the key is absent, it falls back to the legacy or global thinking_level entry within shared. If neither is configured, it returns None.

    Parameters: * shared (dict): The global or per-stage shared state dictionary passed across execution nodes. * node_key (str): The unique pipeline node identifier defined in NODE_KEYS.

    Returns: * str | None: The assigned thinking level string (e.g., "medium"), or None if model defaults should apply.

    Raises: * This function does not raise exceptions internally.

    Example: 

    def resolve_thinking_level(shared: dict, node_key: str) -> str | None:
    """Thinking level for one LLM call site. Falls back to the global level when no plan exists."""
    plan = shared.get("thinking_plan")
    if plan and node_key in plan:
        return plan[node_key]
    return shared.get("thinking_level")

    This helper acts as the point of integration between graph nodes in nodes.py and the centralized inference entry point call_llm.py. By supporting an automatic fallback to shared.get("thinking_level"), it maintains backwards compatibility with invocations or test suites that do not initialize full profile plans.

    describe_plan()

    Visibility: Public
    Signature: def describe_plan(plan: dict, mode: str | None = None) -> str:

    Description: Formats a compact, single-line string representation of a thinking plan suitable for startup telemetry, console headers, and execution audit logging. It restricts output to the subset of nodes that actively execute under the specified mode, filtering via MODE_NODES. If mode is unspecified or unknown, it outputs all NODE_KEYS. Nodes mapped to None or empty strings are rendered as "default".

    Parameters: * plan (dict[str, str | None]): The active thinking plan mapping node keys to levels. * mode (str | None, optional): The active pipeline mode name used to filter relevant nodes. Defaults to None.

    Returns: * str: A comma-separated string of key=level assignments (e.g., "filter_files=low, write_chapters=medium").

    Raises: * This function does not raise exceptions internally.

    Example: 

    def describe_plan(plan: dict, mode: str | None = None) -> str:
    """Compact one-line rendering for the startup config display (only nodes that run in `mode`)."""
    keys = MODE_NODES.get(mode, NODE_KEYS)
    return ", ".join(f"{key}={plan.get(key) or 'default'}" for key in keys)

    By filtering irrelevant nodes based on the operating mode, describe_plan() prevents misleading log output. For example, during an api-reference run, abstract synthesis nodes (map_abstractions, identify_abstractions) are omitted from the summary line since that mode follows a deterministic 1:1 file routing architecture.

    PROFILED_PROVIDERS tuple[str, ...] ("ANTHROPIC", "GEMINI", "OPENROUTER")

    Internal Schemas

    While the module does not declare custom Python classes or dataclasses, it relies on structured schema conventions for its inputs and outputs:

    ThinkingPlan

    The dictionary generated by build_thinking_plan() and stored in shared["thinking_plan"]. * Type: dict[str, str | None] * Key: Any string present in NODE_KEYS. * Value: A string from THINKING_LEVELS (e.g., "low", "medium", "high"), or None if reasoning is disabled or uses default behavior.

    OverridesTuple

    The return value schema of parse_overrides(). * Type: tuple[dict[str, str], list[str]] * Index 0 (overrides): dict[str, str] mapping valid node keys to valid thinking levels. * Index 1 (invalid): list[str] containing unparseable or unrecognized argument strings.

    Error Handling

    The utils/thinking.py module operates as a pure configuration and arithmetic utility layer, avoiding hard exceptions in favor of defensive validation and fallback cascades:

    1. Non-Throwing Input Partitioning: In parse_overrides(), malformed strings (e.g., missing = delimiters), invalid node names, or unsupported effort levels do not raise ValueError or KeyError. Instead, the function isolates offending inputs into an invalid list while successfully extracting valid pairs. This prevents startup crashes and provides actionable diagnostics to upstream callers.
    2. Nearest-Neighbor Arithmetic Fallback: In clamp_level(), when an upstream model configuration does not support a requested effort tier, the module calculates the minimum distance on the canonical index scale rather than failing. If the target level is completely unrecognized or the supported collection is empty, it returns None safely.
    3. Safe Dictionary Defaults: In build_thinking_plan(), unmapped profile names default cleanly to an all-None plan equivalent to "off". In resolve_thinking_level(), missing keys in the state dictionary fall back to the global level, and finally to None, ensuring that an incomplete context dictionary never raises an unhandled exception during LLM dispatch.
