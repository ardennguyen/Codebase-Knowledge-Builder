    thinking.py

    Source: utils/thinking.py

    Technical Overview

    utils/thinking.py serves as the reasoning effort orchestration and budget planning engine for the codebase knowledge generation pipeline. Large language model (LLM) providers expose disparate configuration interfaces for extended reasoning—Anthropic Claude utilizes discrete effort allocations (low, medium, high), Google Gemini relies on integer token budgets or model-specific level enumerations, and OpenRouter passes effort directives through catalog-defined metadata. This module abstracts these provider-specific reasoning protocols into a normalized, provider-neutral scale (minimal, low, medium, high, xhigh, max) and maps distinct reasoning budgets to individual pipeline execution stages (referred to as "nodes").

    The module computes a comprehensive execution plan (thinking_plan) mapping every LLM call site (NODE_KEYS) to a target thinking effort level. The resolution logic enforces a strict three-tier precedence hierarchy: explicit per-node command-line overrides (--thinking-override NODE=LEVEL) supersede a global pipeline-wide level setting (--thinking-level LEVEL), which in turn supersedes curated profile presets (--thinking-profile PROFILE). Preconfigured profiles (economy, balanced, quality, max) assign calibrated reasoning effort based on the computational complexity of each stage—allocating maximum reasoning to structural synthesis tasks (such as whole-codebase abstraction discovery and reduction) while constraining mechanical tasks (such as file classification or UI string translation) to minimal or low effort.

    At runtime, downstream workflow nodes retrieve their assigned reasoning budget using resolve_thinking_level against the shared pipeline state. When dispatching inference requests, provider-specific adapters invoke clamp_level to project the normalized project level onto the subset of levels natively supported by the target LLM. If a requested effort level is unsupported by a model, clamp_level deterministically selects the nearest available tier along the ordinal effort scale, resolving equidistant ties toward lower computational effort to prevent unexpected cost inflation.

    Public API

    THINKING_LEVELS

    Visibility: Public

    Signature: THINKING_LEVELS = ("minimal", "low", "medium", "high", "xhigh", "max")

    Description: Immutable tuple defining the complete, ordered effort continuum supported across the system. Positions within the tuple dictate relative computational intensity, which clamp_level() utilizes to compute distance and resolve nearest-match substitutions. The minimal tier is reserved for select OpenRouter models and is omitted from standard project profiles.

    # Definition in utils/thinking.py
THINKING_LEVELS = ("minimal", "low", "medium", "high", "xhigh", "max")

    The scale provides an ordinal foundation for distance comparisons. When algorithms compute metric distance between unsupported and supported model configurations, indices within THINKING_LEVELS establish the exact coordinate space.

    THINKING_PROFILES

    Visibility: Public

    Signature: THINKING_PROFILES = ("auto", "off", "economy", "balanced", "quality", "max")

    Description: Immutable tuple listing valid configuration profile names accepted via the command-line interface. Profiles range from completely unmanaged model defaults (off), through cost-optimized tiers (economy, balanced, quality), up to unconstrained reasoning allocations (max).

    # Definition in utils/thinking.py
THINKING_PROFILES = ("auto", "off", "economy", "balanced", "quality", "max")

    The default profile auto dynamically resolves at startup to either balanced or off depending on the active provider's compatibility with per-model reasoning configurations.

    PROFILED_PROVIDERS

    Visibility: Public

    Signature: PROFILED_PROVIDERS = ("ANTHROPIC", "GEMINI", "OPENROUTER")

    Description: Identifies inference providers whose contemporary models support granular per-request reasoning effort parameters. Used by resolve_profile_name() to decide whether the auto profile should activate managed thinking profiles or revert to vendor defaults.

    # Providers whose thinking controls are mapped per model (auto → balanced).
PROFILED_PROVIDERS = ("ANTHROPIC", "GEMINI", "OPENROUTER")

    For models under Anthropic, Google Gemini, and OpenRouter, reasoning effort serves as the primary cost and quality control lever. For generic endpoints (such as local Ollama instances or standard OpenAI-compatible gateways), thinking controls are unmapped by default.

    resolve_profile_name()

    Visibility: Public

    Signature: def resolve_profile_name(profile: str | None, provider: str | None) -> str:

    Description: Resolves dynamic or omitted profile names into concrete profile identifiers. Specifically evaluates the auto profile keyword against the target LLM provider: providers listed in PROFILED_PROVIDERS receive the balanced profile, whereas all other providers fall back to off (deferring to native backend model defaults).

    Parameters:

    • profile (str | None): The raw profile string supplied by user configuration or CLI arguments. Defaults to "auto" if None or empty.
    • provider (str | None): Canonical provider name (e.g., "ANTHROPIC", "GEMINI", "OPENROUTER", "OLLAMA").

    Returns:

    • str: Resolved profile name ("balanced", "off", or the normalized lowercase profile string).

    Raises:

    • None directly.

    Example:

    # Implementation from utils/thinking.py
def resolve_profile_name(profile: str | None, provider: str | None) -> str:
    """Resolve `auto` to a concrete profile for the active provider."""
    profile = (profile or "auto").lower()
    if profile == "auto":
        return "balanced" if provider in PROFILED_PROVIDERS else "off"
    return profile

    The function guarantees safe string operations by forcing inputs to lowercase and providing "auto" as a fallback for missing values. When evaluated against modern providers capable of extended deliberation, it activates the balanced profile automatically. For uncalibrated or self-hosted backends where manual effort settings might cause payload validation rejections, it resolves to "off".

    clamp_level()

    Visibility: Public

    Signature: def clamp_level(level: str, supported) -> str | None:

    Description: Maps a target normalized thinking level to the nearest level supported by a specific model backend. If the requested level is directly supported, it returns unchanged. If unsupported, the function filters THINKING_LEVELS to find all levels valid for the target model, measures the absolute distance in ordinal space, and selects the closest supported tier. In the event of an equidistant tie between higher and lower tiers, the algorithm selects the lower index to mitigate unexpected token consumption and cost.

    Parameters:

    • level (str): Target thinking level name (e.g., "medium", "xhigh").
    • supported (Iterable[str]): Collection, set, or sequence of level names supported by the active model configuration.

    Returns:

    • str | None: The exact level if supported; otherwise the nearest supported level on the THINKING_LEVELS scale. Returns None if the target level is not recognized or if supported contains no elements present on THINKING_LEVELS.

    Raises:

    • None directly.

    Example:

    # Implementation from utils/thinking.py
def clamp_level(level: str, supported) -> str | None:
    """Return `level` if the model supports it, else the nearest supported level on
    THINKING_LEVELS (ties → lower). None when nothing on the scale is supported."""
    if level in supported:
        return level
    ranked = [lvl for lvl in THINKING_LEVELS if lvl in supported]
    if not ranked or level not in THINKING_LEVELS:
        return None
    target = THINKING_LEVELS.index(level)
    return min(ranked, key=lambda lvl: (abs(THINKING_LEVELS.index(lvl) - target), THINKING_LEVELS.index(lvl)))

    The algorithm constructs ranked, a list preserving the canonical ordering of THINKING_LEVELS while filtering out unsupported levels. It computes target by locating level in THINKING_LEVELS. The min() evaluation uses a 2-tuple key: (abs(index - target), index). The primary sort key minimizes metric distance, while the secondary sort key breaks ties by choosing the smallest index (lower computational effort).

    parse_overrides()

    Visibility: Public

    Signature: def parse_overrides(values: list[str] | None) -> tuple[dict, list[str]]:

    Description: Parses and validates raw command-line override arguments formatted as NODE=LEVEL. Strips whitespace, forces lowercase normalization, and verifies that the node identifier exists in NODE_KEYS and the level exists in THINKING_LEVELS. Returns a dictionary of valid overrides alongside a list of malformed or invalid declarations.

    Parameters:

    • values (list[str] | None): List of string parameters passed via CLI arguments (e.g., ["write_chapters=high", "extract_facts=low"]).

    Returns:

    • tuple[dict, list[str]]: A 2-tuple containing:
      1. overrides (dict[str, str]): Mapping of valid node keys to validated thinking level strings.
      2. invalid (list[str]): List of input strings that failed delimiter, node key, or level validation.

    Raises:

    • None directly.

    Example:

    # Implementation from utils/thinking.py
def parse_overrides(values: list[str] | None) -> tuple[dict, list[str]]:
    """Parse NODE=LEVEL strings. Returns (overrides, invalid_values)."""
    overrides, invalid = {}, []
    for value in values or []:
        node, sep, level = value.partition("=")
        node, level = node.strip().lower(), level.strip().lower()
        if not sep or node not in NODE_KEYS or level not in THINKING_LEVELS:
            invalid.append(value)
        else:
            overrides[node] = level
    return overrides, invalid

    The function utilizes str.partition("=") to separate key-value pairs without raising exceptions on missing delimiters. Inputs lacking an = separator, targeting unrecognized nodes, or referencing invalid effort names are accumulated into invalid for upstream reporting, while well-formed entries populate the overrides dictionary.

    build_thinking_plan()

    Visibility: Public

    Signature: def build_thinking_plan(profile: str, mode: str, global_level: str | None, overrides: dict) -> dict:

    Description: Assembles the complete mapping of every node in NODE_KEYS to its resolved thinking level string or None. Implements the system's precedence model: explicit overrides take highest precedence; global levels take secondary precedence; profile matrices (modified by mode adjustments) take tertiary precedence; and unresolved or "off" profiles set all nodes to None to enable provider default behavior.

    Parameters:

    • profile (str): Resolved profile name ("economy", "balanced", "quality", "max", or "off"). Must not be "auto".
    • mode (str): Active pipeline execution mode ("tutorial", "advanced", "sdk", or "api-reference").
    • global_level (str | None): Optional override setting all nodes to an identical level.
    • overrides (dict[str, str]): Node-specific override dictionary returned from parse_overrides().

    Returns:

    • dict[str, str | None]: A complete plan dictionary mapping every key in NODE_KEYS to a level string or None.

    Raises:

    • None directly.

    Example:

    # Implementation from utils/thinking.py
def build_thinking_plan(profile: str, mode: str, global_level: str | None, overrides: dict) -> dict:
    """Return {node_key: level | None} for every NODE key.

    Precedence: overrides > global_level > profile table (+ mode adjustments).
    `profile` must already be resolved (see resolve_profile_name).
    """
    if global_level:
        plan = dict.fromkeys(NODE_KEYS, global_level.lower())
    elif profile in _PROFILES:
        plan = dict(_PROFILES[profile])
        plan.update(_MODE_ADJUSTMENTS.get(profile, {}).get(mode, {}))
    else:  # "off": every node uses the model's default thinking behavior
        plan = dict.fromkeys(NODE_KEYS)
    plan.update(overrides)
    return plan

    The plan synthesis proceeds through structured cascading branches. If global_level is set, all node keys are initialized to that value. If omitted and profile exists in _PROFILES, a shallow copy of the profile dictionary is loaded and updated with mode-specific adjustments from _MODE_ADJUSTMENTS. Otherwise, if the profile is "off", all keys are initialized with None. Finally, plan.update(overrides) is applied, ensuring node-specific CLI parameters overwrite baseline settings.

    resolve_thinking_level()

    Visibility: Public

    Signature: def resolve_thinking_level(shared: dict, node_key: str) -> str | None:

    Description: Retrieves the resolved thinking level for a specific pipeline node at LLM call execution time. Inspects the thinking_plan dictionary stored within the application's shared runtime state; if absent or if the key is missing from the plan, it gracefully falls back to the legacy thinking_level attribute in the shared state.

    Parameters:

    • shared (dict): The central shared context dictionary passed across pipeline nodes.
    • node_key (str): The unique identifier for the calling node (must align with NODE_KEYS).

    Returns:

    • str | None: The designated thinking level string (e.g., "high"), or None if unconfigured or defaulting to model parameters.

    Raises:

    • None directly.

    Example:

    # Implementation from utils/thinking.py
def resolve_thinking_level(shared: dict, node_key: str) -> str | None:
    """Thinking level for one LLM call site. Falls back to the global level when no plan exists."""
    plan = shared.get("thinking_plan")
    if plan and node_key in plan:
        return plan[node_key]
    return shared.get("thinking_level")

    This helper guarantees backward compatibility during transitions between global thinking configurations and node-specific thinking flows. Downstream modules do not need to parse CLI flags or profile configurations directly; they provide their node key to retrieve their assigned budget.

    describe_plan()

    Visibility: Public

    Signature: def describe_plan(plan: dict, mode: str | None = None) -> str:

    Description: Formats an active thinking plan into a compact, single-line comma-delimited string for startup logging and operational audit displays. Restricts rendering to the node keys relevant to the specified execution mode.

    Parameters:

    • plan (dict[str, str | None]): The compiled thinking plan mapping node keys to levels.
    • mode (str | None): The active pipeline mode used to filter displayed nodes via MODE_NODES. If omitted or unrecognized, all NODE_KEYS are rendered.

    Returns:

    • str: Comma-delimited key-value string (e.g., "filter_files=low, extract_facts=low, write_chapters=medium"). Unset or None levels are rendered as "default".

    Raises:

    • None directly.

    Example:

    # Implementation from utils/thinking.py
def describe_plan(plan: dict, mode: str | None = None) -> str:
    """Compact one-line rendering for the startup config display (only nodes that run in `mode`)."""
    keys = MODE_NODES.get(mode, NODE_KEYS)
    return ", ".join(f"{key}={plan.get(key) or 'default'}" for key in keys)

    The function interrogates MODE_NODES using the provided mode. By omitting irrelevant nodes (such as omitting heuristic analysis nodes in api-reference mode), it prevents log clutter and clarifies active inference parameters during system startup.

    _MODE_ADJUSTMENTS

    Visibility: Private

    Signature: _MODE_ADJUSTMENTS = { "economy": {"advanced": {"write_chapters": "medium"}}, }

    Description: Internal nested dictionary specifying mode-dependent overrides applied over baseline profiles. Compensates for documentation modes that demand higher reasoning capabilities even when executing under constrained profiles.

    # Mode-specific adjustments on top of the base profile. advanced chapters carry design-
# rationale analysis and there are at most max_abstraction_num of them, so economy keeps
# them at medium instead of low.
_MODE_ADJUSTMENTS = {
    "economy": {"advanced": {"write_chapters": "medium"}},
}

    Under the economy profile, baseline chapter writing is capped at "low". However, because advanced mode produces technical deep-dives detailing architectural design rationale and operates over a bounded number of abstractions, _MODE_ADJUSTMENTS raises write_chapters to "medium".

    Error Handling

    utils/thinking.py implements deterministic, non-throwing defensive validation patterns across all functions. Rather than raising runtime exceptions on malformed user inputs, functions sanitize values, collect diagnostic records, or fall back to safe default behaviors:

    • Override Syntax Validation: In parse_overrides(), candidate strings are partitioned around =. Any string lacking an = character, naming an unrecognized node, or designating an effort level outside THINKING_LEVELS is collected into the invalid return list. Execution proceeds without terminating the process, allowing callers to log warnings or exit cleanly.
    • Effort Level Clamping: In clamp_level(), if a requested level is absent from the target model's supported set, the function calculates absolute distance along THINKING_LEVELS. Equidistant ties resolve toward lower computational cost (min(ranked, key=lambda lvl: (abs(...), index))). If the requested level is completely unrecognized or supported has no overlap with THINKING_LEVELS, the function returns None rather than raising a ValueError or KeyError.
    • Missing Plan Fallbacks: In resolve_thinking_level(), if shared lacks a thinking_plan key or the target node_key is not present within the plan, the function falls back to retrieving shared.get("thinking_level"). If neither exists, it safely returns None, allowing inference adapters to fall back to native model defaults.
    • Profile Resolution Fallback: In resolve_profile_name(), empty or None inputs default to "auto". For providers not registered in PROFILED_PROVIDERS, "auto" gracefully degrades to "off", preventing uncalibrated providers from receiving unexpected reasoning configuration payloads.
