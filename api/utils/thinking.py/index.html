    thinking.py

    Source: utils/thinking.py

    Following the prompt serialization and template loading mechanisms detailed in prompts.py, the thinking.py module governs cognitive resource allocation and reasoning effort budgets across all Large Language Model (LLM) interaction points. Where prompts.py ensures structural integrity of inputs and outputs, thinking.py regulates the computational depth and latency profile of the inference requests dispatched across the pipeline.

    Technical Overview

    utils/thinking.py implements the per-node thinking effort resolution subsystem, referred to internally as "thinking flows." Modern reasoning LLMs—such as Anthropic Claude 3.7 Sonnet, Google Gemini 2.5 / 3.x, and reasoning models served through OpenRouter—support variable reasoning parameters (such as thinking_budget, thinking_level, or reasoning_effort). Because different compilation phases within Codebase-Knowledge-Builder require radically different reasoning depth, applying a uniform reasoning level across the entire execution graph results in excessive API latency, token exhaustion, or degraded architectural synthesis. The module solves this optimization challenge by mapping individual pipeline call sites to an ordered cognitive effort scale.

    The architecture operates on a three-tier hierarchy of precedence resolved once during application bootstrap in main.py: 1. Per-node Overrides (--thinking-override NODE=LEVEL): Explicit granular overrides assigned to specific call sites via command-line flags. 2. Global Effort Level (--thinking-level LEVEL): A uniform override applied across every node in the pipeline. 3. Preset Profiles (--thinking-profile PROFILE): Predefined effort allocation tables (economy, balanced, quality, max, off) that assign calibrated effort levels based on node sensitivity, modified dynamically by execution mode (tutorial, advanced, sdk, api-reference).

    The module standardizes effort along an ordered canonical scale: minimal, low, medium, high, xhigh, and max. Reasoning-heavy structural discovery phases (such as identify_abstractions and reduce_abstractions) receive high-tier allocations, whereas mechanical tasks (such as filter_files or translate_strings) are assigned minimal or low effort. Provider drivers (llm_anthropic.py, llm_gemini.py, and llm_openrouter.py) translate canonical project levels into provider-specific parameters at dispatch time using nearest-neighbor fallback resolution.

    Public API

    resolve_profile_name()

    Visibility: Public
    Signature: def resolve_profile_name(profile: str | None, provider: str | None) -> str:

    Description: Resolves the operational profile identifier against the active model provider. When an explicit profile name (such as "economy", "balanced", "quality", or "max") is provided, the function normalizes the string to lowercase and returns it. If the profile is omitted or specified as "auto", the function evaluates whether the target provider is an explicitly profiled ecosystem (ANTHROPIC, GEMINI, or OPENROUTER). In those ecosystems, current foundation models reason by default and per-node calibration is a vital cost-control mechanism, causing "auto" to resolve to "balanced". For generic or local endpoints (such as Ollama or OpenAI-compatible hosts), "auto" defaults to "off", preserving model-native behavior.

    Parameters: * profile (str | None): The requested profile name passed via configuration or CLI flags. Defaults to "auto" if None. * provider (str | None): The uppercase identifier of the target inference provider (e.g., "ANTHROPIC", "GEMINI", "OPENROUTER", "OLLAMA").

    Returns: * str: The normalized, concrete profile identifier ("balanced", "off", or the explicitly supplied profile).

    Raises: * This function does not raise exceptions; unexpected or unmapped profile names pass through normalized.

    Example: 

    def resolve_profile_name(profile: str | None, provider: str | None) -> str:
    """Resolve `auto` to a concrete profile for the active provider."""
    profile = (profile or "auto").lower()
    if profile == "auto":
        return "balanced" if provider in PROFILED_PROVIDERS else "off"
    return profile

    The implementation performs a single-pass fallback check. By decoupling provider identification from CLI argument ingestion, it enables upstream initialization routines to establish operational profiles before driver instantiation. Providers outside PROFILED_PROVIDERS default to "off", preventing downstream payload injectors from sending unsupported reasoning keys to third-party OpenAI-compatible REST endpoints.

    clamp_level()

    Visibility: Public
    Signature: def clamp_level(level: str, supported) -> str | None:

    Description: Normalizes an abstract project reasoning level to an explicit level supported by a specific model target. The function searches the target model's supported capabilities against the canonical THINKING_LEVELS tuple. If the exact level is directly supported, it returns unchanged. If the requested level is unsupported, the function identifies all overlapping supported levels and computes the nearest neighbor on the THINKING_LEVELS index scale. In the event of an equidistant tie between two supported levels, the algorithm deterministically selects the lower effort tier, safeguarding token budgets. If the model supports no recognized levels, or if the input level is not present in THINKING_LEVELS, it returns None.

    Parameters: * level (str): The requested reasoning level string (e.g., "high", "xhigh", "minimal"). * supported (Iterable[str]): A collection or container (such as a set, list, or tuple) containing the thinking levels officially supported by the active model or provider catalog.

    Returns: * str | None: The exact level, the closest supported level ranked along the scale (ties breaking toward lower effort), or None if no valid level can be resolved.

    Raises: * This function does not raise exceptions.

    Example: 

    def clamp_level(level: str, supported) -> str | None:
    """Return `level` if the model supports it, else the nearest supported level on
    THINKING_LEVELS (ties → lower). None when nothing on the scale is supported."""
    if level in supported:
        return level
    ranked = [lvl for lvl in THINKING_LEVELS if lvl in supported]
    if not ranked or level not in THINKING_LEVELS:
        return None
    target = THINKING_LEVELS.index(level)
    return min(ranked, key=lambda lvl: (abs(THINKING_LEVELS.index(lvl) - target), THINKING_LEVELS.index(lvl)))

    The clamping logic uses an absolute index distance metric paired with the index value as a secondary sorting key: (abs(THINKING_LEVELS.index(lvl) - target), THINKING_LEVELS.index(lvl)). This tuple comparison guarantees that if a requested level (e.g., index 2) is flanked symmetrically by supported levels at index 1 and index 3, the secondary element breaks the tie by choosing index 1. This prevents vendor drivers such as llm_gemini.py or llm_openrouter.py from failing request schema validation when models only advertise a subset of reasoning modes (e.g., only "low" and "high").

    parse_overrides()

    Visibility: Public
    Signature: def parse_overrides(values: list[str] | None) -> tuple[dict, list[str]]:

    Description: Parses and validates raw command-line override parameters passed via --thinking-override flags. The function processes a list of key-value assignment strings formatted as NODE=LEVEL. Each entry is split at the first delimiter, stripped of surrounding whitespace, and normalized to lowercase. It verifies that the parsed node name exists within NODE_KEYS and that the assigned level exists within THINKING_LEVELS. Valid entries are aggregated into an overrides dictionary, while malformed strings or unknown tokens are collected into an invalid values list for consolidated error reporting by the CLI runner.

    Parameters: * values (list[str] | None): A list of command-line override strings, typically sourced from sys.argv via argparse. Accepts None gracefully.

    Returns: * tuple[dict[str, str], list[str]]: A 2-tuple containing: 1. overrides: A dictionary mapping valid node keys (str) to valid thinking levels (str). 2. invalid: A list of original string values (str) that failed delimiter parsing, contained invalid node names, or specified unrecognized levels.

    Raises: * This function does not raise exceptions directly; syntax and schema validation errors are returned as structured data.

    Example: 

    def parse_overrides(values: list[str] | None) -> tuple[dict, list[str]]:
    """Parse NODE=LEVEL strings. Returns (overrides, invalid_values)."""
    overrides, invalid = {}, []
    for value in values or []:
        node, sep, level = value.partition("=")
        node, level = node.strip().lower(), level.strip().lower()
        if not sep or node not in NODE_KEYS or level not in THINKING_LEVELS:
            invalid.append(value)
        else:
            overrides[node] = level
    return overrides, invalid

    The implementation relies on str.partition("=") rather than str.split("=") to guarantee safe single-split execution without throwing ValueError on missing delimiters. The guard clause validates three critical conditions: presence of the separator, membership of the node in NODE_KEYS, and validity of the assigned level in THINKING_LEVELS. By returning invalid values rather than halting execution, the function allows main.py to report every syntax error in a single terminal diagnostic emission before execution begins.

    build_thinking_plan()

    Visibility: Public
    Signature: def build_thinking_plan(profile: str, mode: str, global_level: str | None, overrides: dict) -> dict:

    Description: Synthesizes the master thinking execution plan mapping every known node key in NODE_KEYS to a resolved thinking level or None. The construction enforces a strict precedence hierarchy: CLI overrides override global level overrides, which in turn override baseline profile allocations. When a global_level is defined, every node key is initialized to that uniform level. When no global level is specified, the plan initializes from _PROFILES using the resolved profile name and applies mode-specific adjustments from _MODE_ADJUSTMENTS. If the profile is "off", every node is initialized to None, directing inference drivers to omit explicit reasoning payloads and accept vendor defaults. Finally, all keys present in the overrides dictionary are merged into the plan, taking ultimate precedence.

    Parameters: * profile (str): The pre-resolved profile name (e.g., "balanced", "economy", "quality", "max", "off"). * mode (str): The operational documentation mode ("tutorial", "advanced", "sdk", "api-reference"). * global_level (str | None): An optional uniform thinking level assigned across all pipeline nodes via --thinking-level. * overrides (dict[str, str]): A validated dictionary of per-node overrides returned by parse_overrides().

    Returns: * dict[str, str | None]: A complete mapping of every string key in NODE_KEYS to its assigned thinking level (str) or None.

    Raises: * This function does not raise exceptions directly.

    Example: 

    def build_thinking_plan(profile: str, mode: str, global_level: str | None, overrides: dict) -> dict:
    """Return {node_key: level | None} for every NODE key.

    Precedence: overrides > global_level > profile table (+ mode adjustments).
    `profile` must already be resolved (see resolve_profile_name).
    """
    if global_level:
        plan = dict.fromkeys(NODE_KEYS, global_level.lower())
    elif profile in _PROFILES:
        plan = dict(_PROFILES[profile])
        plan.update(_MODE_ADJUSTMENTS.get(profile, {}).get(mode, {}))
    else:  # "off": every node uses the model's default thinking behavior
        plan = dict.fromkeys(NODE_KEYS)
    plan.update(overrides)
    return plan

    This function ensures that the resulting plan dictionary is fully populated across all known NODE_KEYS. When global_level is set, profile definitions and mode adjustments are bypassed entirely. When relying on profiles, _MODE_ADJUSTMENTS handles task nuances—such as elevating chapter writing in "advanced" mode under the "economy" profile from "low" to "medium" to accommodate architectural trade-off synthesis. Merging overrides at the final step ensures explicit CLI instructions cannot be overwritten by mode or profile heuristics.

    resolve_thinking_level()

    Visibility: Public
    Signature: def resolve_thinking_level(shared: dict, node_key: str) -> str | None:

    Description: Resolves the runtime thinking level for a specific LLM execution site during graph node execution. It inspects the pipeline state dictionary (shared) for a compiled "thinking_plan" dictionary. If the plan exists and contains node_key, its assigned level is returned. If no plan is present or the key is absent, the function falls back defensively to the top-level "thinking_level" key stored in the shared state. If neither exists, it returns None.

    Parameters: * shared (dict): The central shared context dictionary passed across execution nodes in flow.py and nodes.py. * node_key (str): The unique string identifier of the active execution node (must match an entry in NODE_KEYS).

    Returns: * str | None: The resolved thinking level string (e.g., "medium", "high"), or None if the node should execute using model defaults.

    Raises: * This function does not raise exceptions.

    Example: 

    def resolve_thinking_level(shared: dict, node_key: str) -> str | None:
    """Thinking level for one LLM call site. Falls back to the global level when no plan exists."""
    plan = shared.get("thinking_plan")
    if plan and node_key in plan:
        return plan[node_key]
    return shared.get("thinking_level")

    This helper abstracts the pipeline state lookup across all call sites in nodes.py. Graph nodes invoke this function immediately prior to dispatching prompts to call_llm.py. Because the returned string is vendor-agnostic, downstream dispatchers remain decoupled from the workflow state schema, delegating final parameter mapping to provider drivers.

    describe_plan()

    Visibility: Public
    Signature: def describe_plan(plan: dict, mode: str | None = None) -> str:

    Description: Generates a compact, single-line human-readable summary of a thinking plan for terminal startup telemetry and diagnostic logging. It restricts output exclusively to nodes relevant to the active operational mode (using MODE_NODES), preventing terminal clutter from unused pipeline phases. If a node maps to None or an empty value, it renders as "default".

    Parameters: * plan (dict[str, str | None]): The compiled thinking plan mapping node keys to levels. * mode (str | None): The operational documentation mode ("tutorial", "advanced", "sdk", "api-reference"). If omitted or invalid, formatting falls back to evaluating all keys in NODE_KEYS.

    Returns: * str: A comma-separated string of key=level assignments (e.g., "filter_files=low, write_chapters=high, chapter_summary=low").

    Raises: * This function does not raise exceptions.

    Example: 

    def describe_plan(plan: dict, mode: str | None = None) -> str:
    """Compact one-line rendering for the startup config display (only nodes that run in `mode`)."""
    keys = MODE_NODES.get(mode, NODE_KEYS)
    return ", ".join(f"{key}={plan.get(key) or 'default'}" for key in keys)

    The helper filters execution nodes by consulting MODE_NODES.get(mode, NODE_KEYS). In "api-reference" mode, for instance, structural discovery nodes like map_abstractions and reduce_abstractions are omitted from startup logs since the deterministic 1:1 file mapper bypasses those workflow steps. The fallback expression plan.get(key) or 'default' ensures unconfigured or "off" nodes are legibly labeled in CLI startup banners.

    Internal Helpers

    The thinking.py module defines no private helper functions or nested closures. All algorithmic operations are exposed directly through the public API functions documented above. Internal state is maintained through module-scoped constant collections (_ANALYSIS_NODES, _PROFILES, and _MODE_ADJUSTMENTS) that isolate configuration tables from external mutation.

    Error Handling

    The module employs defensive normalization and graceful degradation rather than raising runtime exceptions:

    • Safe Delimiter Splitting: parse_overrides() uses str.partition("=") to separate arguments without risking ValueError on strings lacking an = separator. It verifies each token against NODE_KEYS and THINKING_LEVELS before accepting it into the plan, collecting malformed entries into an invalid list so callers can emit descriptive terminal diagnostics.
    • Nearest-Neighbor Fallback: clamp_level() guards against API rejection when a model lacks support for an assigned level. Rather than throwing an error or failing payload validation, it uses distance minimization across THINKING_LEVELS indices to select the closest available level. Equidistant ties break toward the lower level to prevent unexpected billing spikes.
    • Defensive Property Access: resolve_thinking_level() uses dict.get() across nested dictionaries, falling back gracefully to the global thinking_level or None if the thinking plan is uninitialized.
    • Safe Profile Fallback: resolve_profile_name() treats None as "auto", defaulting unrecognized providers to "off" to prevent sending invalid parameters to unsupported REST endpoints.
