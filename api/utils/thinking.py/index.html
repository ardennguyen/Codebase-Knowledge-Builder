    thinking.py

    Source: utils/thinking.py

    Technical Overview

    The utils/thinking.py module establishes the centralized reasoning effort resolution engine—termed "thinking flows"—for the Codebase-Knowledge-Builder pipeline. Across contemporary reasoning models (including Anthropic Claude 3.7/Opus, Google Gemini 2.5/3.x, and various OpenRouter models), explicit thinking parameters serve as the primary lever balancing token expenditure against synthesis quality. Rather than hardcoding reasoning levels inside disparate generation steps, this module assigns a unique node key to every Large Language Model (LLM) interaction point and resolves an execution-wide dictionary mapping each node to a calibrated effort level.

    The module manages configuration precedence across CLI flags, provider capabilities, and execution modes. When orchestrating pipeline initialization, it resolves profile settings (--thinking-profile), global overrides (--thinking-level), and surgical per-node overrides (--thinking-override NODE=LEVEL). For providers that support fine-grained thinking controls (ANTHROPIC, GEMINI, and OPENROUTER), the default auto profile activates a balanced tier (balanced), whereas unmapped providers (such as local Ollama or OpenAI-compatible proxies) default to disabled thinking (off). Furthermore, the module handles operational mode nuances—such as boosting chapter writing effort in advanced mode to accommodate architectural design rationale—and provides nearest-neighbor clamping routines to reconcile abstract effort requests with discrete provider limits.

    Public API

    THINKING_LEVELS

    Visibility: Public

    Signature: THINKING_LEVELS = ("minimal", "low", "medium", "high", "xhigh", "max")

    Description: An ordered tuple defining the project's canonical effort scale. Represents an increasing gradient of token expenditure and reasoning depth. The minimal level exists primarily for models exposed via OpenRouter that support an ultra-low reasoning boundary, though standard built-in profiles operate within the low to max spectrum.

    THINKING_LEVELS = ("minimal", "low", "medium", "high", "xhigh", "max")

    The THINKING_LEVELS constant acts as the standard reference scale across all pipeline modules. It provides the index coordinates used by clamp_level when calculating relative distances between requested levels and provider-supported feature sets. Because it is ordered strictly from lowest to highest effort, index differences directly reflect relative reasoning distance.

    THINKING_PROFILES

    Visibility: Public

    Signature: THINKING_PROFILES = ("auto", "off", "economy", "balanced", "quality", "max")

    Description: An immutable tuple enumerating the valid configuration profile names accepted from CLI parameters or environment flags.

    THINKING_PROFILES = ("auto", "off", "economy", "balanced", "quality", "max")

    This tuple defines the allowed user options for the --thinking-profile flag. The entries correspond to curated strategies: auto dynamically evaluates the provider; off suppresses thinking parameters; economy minimizes tokens across mechanical steps; balanced provides standard production trade-offs; quality elevates reasoning across synthesis phases; and max allocates the highest supported effort across all analytical nodes.

    "advanced": (*_ANALYSIS_NODES, "write_chapters", "chapter_summary", "translate_strings"),

    PROFILED_PROVIDERS

    Visibility: Public

    Signature: PROFILED_PROVIDERS = ("ANTHROPIC", "GEMINI", "OPENROUTER")

    Description: A tuple containing the uppercase identifiers of model providers whose SDKs or APIs support granular reasoning effort levels.

    PROFILED_PROVIDERS = ("ANTHROPIC", "GEMINI", "OPENROUTER")

    This tuple is evaluated during preflight configuration resolution. When a user runs with --thinking-profile auto, providers in this set activate the balanced profile, whereas providers not in this list fall back to off to prevent sending unsupported reasoning parameters to incompatible API endpoints.

    resolve_profile_name()

    Visibility: Public

    Signature: def resolve_profile_name(profile: str | None, provider: str | None) -> str:

    Description: Resolves the dynamic auto profile keyword into a concrete profile name based on provider capabilities, while passing through explicit profile names unchanged.

    Parameters:

    • profile (str | None): The requested profile name (e.g., from CLI args). Defaults to "auto" if empty or None.
    • provider (str | None): The normalized uppercase model provider name (e.g., "ANTHROPIC", "GEMINI").

    Returns:

    • str: The resolved profile name ("balanced", "off", "economy", "quality", or "max").

    Raises:

    • None: This function does not explicitly raise any exceptions.

    Example:

    def resolve_profile_name(profile: str | None, provider: str | None) -> str:
    """Resolve `auto` to a concrete profile for the active provider."""
    profile = (profile or "auto").lower()
    if profile == "auto":
        return "balanced" if provider in PROFILED_PROVIDERS else "off"
    return profile

    The function normalizes inputs by lowercasing the profile string and defaulting absent configurations to "auto". For "auto", it queries PROFILED_PROVIDERS; if the active provider supports explicit per-model thinking, it resolves to "balanced". If the provider does not support fine-grained controls, it returns "off". Any explicit profile passed by the caller is returned directly.

    clamp_level()

    Visibility: Public

    Signature: def clamp_level(level: str, supported) -> str | None:

    Description: Evaluates a requested thinking level against an iterable of supported levels exposed by a model or provider. Returns the level directly if supported, or computes the nearest neighbor along the THINKING_LEVELS scale, resolving distance ties in favor of the lower level.

    Parameters:

    • level (str): The requested abstract thinking level.
    • supported (iterable of str): A collection, set, or sequence of levels supported by the target model or driver.

    Returns:

    • str | None: The exact or nearest supported level, or None if the input level is not in THINKING_LEVELS or no supported levels match the scale.

    Raises:

    • None: This function does not explicitly raise any exceptions.

    Example:

    def clamp_level(level: str, supported) -> str | None:
    """Return `level` if the model supports it, else the nearest supported level on
    THINKING_LEVELS (ties → lower). None when nothing on the scale is supported."""
    if level in supported:
        return level
    ranked = [lvl for lvl in THINKING_LEVELS if lvl in supported]
    if not ranked or level not in THINKING_LEVELS:
        return None
    target = THINKING_LEVELS.index(level)
    return min(ranked, key=lambda lvl: (abs(THINKING_LEVELS.index(lvl) - target), THINKING_LEVELS.index(lvl)))

    This clamping algorithm prevents generation crashes when models expose constrained reasoning tiers (for example, models supporting only low and high). It filters THINKING_LEVELS to find all candidates present in supported. If the target is absent, it computes a composite sort key (distance, index). The second tuple element ensures that if a level is equidistant between two supported levels, the lower-indexed (less expensive) level is selected.

    parse_overrides()

    Visibility: Public

    Signature: def parse_overrides(values: list[str] | None) -> tuple[dict, list[str]]:

    Description: Parses and validates raw NODE=LEVEL CLI override expressions into a dictionary of valid overrides and a list of malformed or unrecognized expressions.

    Parameters:

    • values (list[str] | None): A list of raw string arguments passed via --thinking-override.

    Returns:

    • tuple[dict, list[str]]: A 2-tuple containing:
      • overrides (dict[str, str]): Mapping of valid node keys to their overridden thinking levels.
      • invalid (list[str]): List of input strings that failed delimiter, node key, or thinking level validation.

    Raises:

    • None: This function does not explicitly raise any exceptions.

    Example:

    def parse_overrides(values: list[str] | None) -> tuple[dict, list[str]]:
    """Parse NODE=LEVEL strings. Returns (overrides, invalid_values)."""
    overrides, invalid = {}, []
    for value in values or []:
        node, sep, level = value.partition("=")
        node, level = node.strip().lower(), level.strip().lower()
        if not sep or node not in NODE_KEYS or level not in THINKING_LEVELS:
            invalid.append(value)
        else:
            overrides[node] = level
    return overrides, invalid

    The function iterates over the input strings, partitioning each on the = delimiter. It sanitizes both tokens by stripping whitespace and converting to lowercase. An item is categorized as invalid if the delimiter is missing, if the node key does not exist in NODE_KEYS, or if the requested level is absent from THINKING_LEVELS. Valid pairs are collected into overrides, and unrecognized entries are retained in invalid for diagnostic logging.

    build_thinking_plan()

    Visibility: Public

    Signature: def build_thinking_plan(profile: str, mode: str, global_level: str | None, overrides: dict) -> dict:

    Description: Assembles the complete thinking plan dictionary mapping every registered NODE_KEYS item to an effort level or None. Enforces hierarchical precedence across global levels, profile tables, mode adjustments, and per-node overrides.

    Parameters:

    • profile (str): The resolved profile name (must not be "auto").
    • mode (str): The active pipeline execution mode ("tutorial", "advanced", "sdk", or "api-reference").
    • global_level (str | None): Global thinking level override (--thinking-level), if specified.
    • overrides (dict): Per-node override mapping produced by parse_overrides().

    Returns:

    • dict: A dictionary mapping every node key in NODE_KEYS to a thinking level string or None.

    Raises:

    • None: This function does not explicitly raise any exceptions.

    Example:

    def build_thinking_plan(profile: str, mode: str, global_level: str | None, overrides: dict) -> dict:
    """Return {node_key: level | None} for every NODE key.

    Precedence: overrides > global_level > profile table (+ mode adjustments).
    `profile` must already be resolved (see resolve_profile_name).
    """
    if global_level:
        plan = dict.fromkeys(NODE_KEYS, global_level.lower())
    elif profile in _PROFILES:
        plan = dict(_PROFILES[profile])
        plan.update(_MODE_ADJUSTMENTS.get(profile, {}).get(mode, {}))
    else:  # "off": every node uses the model's default thinking behavior
        plan = dict.fromkeys(NODE_KEYS)
    plan.update(overrides)
    return plan

    The construction follows a strict hierarchy. If global_level is provided, every node key is initialized to that uniform level. Otherwise, if the profile exists in _PROFILES, the plan loads the baseline node allocations and applies any mode-specific delta from _MODE_ADJUSTMENTS. If the profile is "off" or unrecognized, all nodes are initialized to None (instructing models to use native defaults). Finally, any explicit per-node entries in overrides overwrite existing values, ensuring surgical overrides take absolute precedence.

    resolve_thinking_level()

    Visibility: Public

    Signature: def resolve_thinking_level(shared: dict, node_key: str) -> str | None:

    Description: Retrieves the configured thinking effort level for an active pipeline node from the shared execution dictionary.

    Parameters:

    • shared (dict): The global or workflow-level shared state dictionary.
    • node_key (str): The identifier of the calling node (from NODE_KEYS).

    Returns:

    • str | None: The resolved effort level for the node, or None if unconfigured or disabled.

    Raises:

    • None: This function does not explicitly raise any exceptions.

    Example:

    def resolve_thinking_level(shared: dict, node_key: str) -> str | None:
    """Thinking level for one LLM call site. Falls back to the global level when no plan exists."""
    plan = shared.get("thinking_plan")
    if plan and node_key in plan:
        return plan[node_key]
    return shared.get("thinking_level")

    This helper abstracts plan lookup for individual pipeline nodes. It inspects the thinking_plan mapping stored within shared. If a plan is present and contains the target node_key, it returns the assigned level. If no plan is found or the key is omitted, it falls back to the top-level thinking_level attribute in shared, returning None if no reasoning configuration exists.

    describe_plan()

    Visibility: Public

    Signature: def describe_plan(plan: dict, mode: str | None = None) -> str:

    Description: Formats an active thinking plan into a compact, comma-separated key-value string suitable for startup console emissions and diagnostic logs, filtering output to include only nodes relevant to the current mode.

    Parameters:

    • plan (dict): The thinking plan dictionary mapping node keys to levels.
    • mode (str | None): The active execution mode used to filter displayed nodes via MODE_NODES. Defaults to displaying all NODE_KEYS if None or omitted.

    Returns:

    • str: A formatted string such as "filter_files=low, extract_facts=low, write_chapters=medium".

    Raises:

    • None: This function does not explicitly raise any exceptions.

    Example:

    def describe_plan(plan: dict, mode: str | None = None) -> str:
    """Compact one-line rendering for the startup config display (only nodes that run in `mode`)."""
    keys = MODE_NODES.get(mode, NODE_KEYS)
    return ", ".join(f"{key}={plan.get(key) or 'default'}" for key in keys)

    The function identifies the relevant nodes by querying MODE_NODES with the provided mode, falling back to NODE_KEYS when mode is unlisted or unspecified. It then iterates over those keys, formatting each as key=level. If a node's level is None, it substitutes the label 'default' to indicate that the model's native reasoning behavior applies.

    Error Handling

    The module implements defensive parsing and fail-safe validation strategies to prevent configuration errors from halting pipeline execution:

    • Non-Crashing Override Accumulation: In parse_overrides(), malformed CLI strings (such as missing = delimiters, unknown node keys, or unsupported levels) do not raise exceptions. Instead, they are collected into an invalid list and returned to the caller, allowing main.py to log descriptive warnings while applying all valid overrides.
    • Safe Nearest-Neighbor Clamping: The clamp_level() function gracefully handles model constraints without raising errors. If an unsupported thinking level is requested, it calculates relative index distances against THINKING_LEVELS and falls back to the nearest supported level. If the target level is completely unrecognized or the model supports no levels on the scale, it safely returns None.
    • Safe State Lookup: Functions querying state dictionaries (resolve_thinking_level, build_thinking_plan, and describe_plan) use .get() with explicit defaults. Missing keys or uninitialized plans fall back to None or 'default', ensuring execution continues using the model's native settings.
    • String Normalization: All user-supplied strings (profile names, node keys, and effort levels) are sanitized via .strip().lower() before comparison, preventing failures caused by inconsistent casing or whitespace in environment variables and CLI flags.
