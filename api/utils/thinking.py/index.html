    thinking.py

    Source: utils/thinking.py

    Following prompt templating and response extraction in prompts.py, the pipeline must determine the cognitive reasoning depth allocated to each Large Language Model (LLM) invocation. The utils/thinking.py module defines the centralized configuration, profile hierarchy, and runtime resolution engine for per-node thinking effort—collectively referred to as "thinking flows." Modern reasoning-capable models (such as the Anthropic Claude 3.7/Sonnet/Opus families, Google Gemini 2.5/3.x series, and reasoning models served through OpenRouter) treat reasoning tokens as a primary lever for balancing generation quality, inference latency, and operational expenditure. This module establishes a provider-neutral abstraction over provider-specific reasoning controls, enabling granular or profile-based tuning across each distinct workflow step.

    The module operates as a deterministic rules engine. During application initialization in main.py, CLI flags specifying execution modes, global effort levels, named profiles, and explicit per-node overrides are resolved into an immutable dictionary mapping every pipeline stage to a discrete effort level. At runtime, workflow nodes orchestrated by nodes.py and flow.py query this configuration through resolve_thinking_level(), before transport adapters such as llm_anthropic.py, llm_gemini.py, and llm_openrouter.py normalize or clamp the abstract effort level against provider-specific capabilities using clamp_level().

    Technical Overview

    The primary responsibility of utils/thinking.py is eliminating hardcoded reasoning budgets from individual pipeline nodes, providing instead an adaptable matrix governed by operational profiles (economy, balanced, quality, and max). Because different tasks within the codebase documentation pipeline have radically divergent cognitive demands, a static reasoning setting across the entire execution flow causes severe inefficiencies. For example, structural file filtering (filter_files) and per-file fact verification (extract_facts) are deterministic extraction tasks where excess reasoning effort increases latency without improving output accuracy. Conversely, whole-codebase architectural discovery (identify_abstractions) and iterative synthesis (reduce_abstractions) require deep chains of thought to uncover non-obvious relationships across disparate modules.

    To decouple high-level pipeline orchestration from backend vendor specifications, the module standardizes thinking effort onto an ordered six-point scale: minimal, low, medium, high, xhigh, and max. Each provider maps this scale to its own proprietary controls: - Anthropic: Maps levels to output_config.effort, clamping minimal up to low when adaptive thinking is active, or mapping directly to structured budgets. - Google Gemini: Maps levels to categorical thinking_level configurations on Gemini 3.x architectures, or converts levels into numeric thinking_budget integer limits on Gemini 2.5 models. - OpenRouter: Matches abstract levels against the upstream catalog's supported_efforts array inside the model's reasoning payload parameters. - Ollama / Local Endpoints: Maps levels to low, medium, or high, or disables thinking altogether when the underlying runtime does not support reasoning parsing.

    The module implements a strict priority cascade when compiling a run's thinking plan: 1. Explicit Per-Node Overrides (--thinking-override NODE=LEVEL): Highest priority; sets an exact effort for a single pipeline stage without altering any other node. 2. Global Effort Override (--thinking-level LEVEL): Second priority; sets every node in the pipeline to a single uniform level. 3. Operational Profiles (--thinking-profile PROFILE): Third priority; uses pre-calibrated baseline tables tuned for cost/quality tradeoffs, supplemented by contextual mode adjustments (such as bumping chapter generation from low to medium in advanced mode). 4. Model Defaults (off): Fallback priority; all nodes resolve to None, indicating that the underlying model's default thinking behavior should be utilized without explicit intervention.

    Public API

    resolve_profile_name()

    Visibility: Public
    Signature: def resolve_profile_name(profile: str | None, provider: str | None) -> str:

    Description: Resolves the user-supplied profile configuration string into a concrete, actionable profile identifier. When an explicit profile (such as economy, balanced, quality, or max) is passed, the function normalizes the string to lowercase and returns it unchanged. When profile is empty, None, or set to "auto", the function evaluates the active provider. Providers belonging to PROFILED_PROVIDERS (ANTHROPIC, GEMINI, OPENROUTER) default their modern model tiers to active thinking, making explicit per-node effort management essential for quality and cost control; thus, "auto" resolves to "balanced" for these providers. For unprofiled providers (such as OLLAMA or local OpenAI-compatible gateways), "auto" safely resolves to "off", allowing the target host to run without extraneous reasoning parameters.

    Parameters: * profile (str | None): The CLI argument or configuration value specifying the requested profile name (e.g., "auto", "balanced", "economy"). * provider (str | None): The normalized string identifier of the active LLM backend provider (e.g., "ANTHROPIC", "GEMINI").

    Returns: * str: The resolved, lowercase profile name ("balanced", "off", or the normalized explicit profile string).

    Raises: * No exceptions are raised internally; missing or empty inputs default safely to "auto".

    Example: 

    # Actual implementation from utils/thinking.py
def resolve_profile_name(profile: str | None, provider: str | None) -> str:
    """Resolve `auto` to a concrete profile for the active provider."""
    profile = (profile or "auto").lower()
    if profile == "auto":
        return "balanced" if provider in PROFILED_PROVIDERS else "off"
    return profile

    The function handles string case discrepancies defensively by applying .lower() to the extracted or defaulted profile value. Because profile can be passed as None when CLI flags are omitted, the (profile or "auto") idiom ensures that None or empty strings cleanly fall back to "auto". The provider check utilizes constant-time membership testing against the immutable PROFILED_PROVIDERS tuple.

    clamp_level()

    Visibility: Public
    Signature: def clamp_level(level: str, supported) -> str | None:

    Description: Maps an abstract thinking level to the closest valid level supported by a specific LLM model or provider catalog. When the requested level is directly present in the supported collection, it is returned immediately. If the level is unsupported, the function filters THINKING_LEVELS down to the subset present in supported, computes the absolute distance between the target level's position and each candidate's position on the canonical scale, and returns the candidate with the smallest distance. In the event of an equidistant tie between two candidates, the key sorts by the candidate's canonical index, deterministically choosing the lower (more conservative / cost-effective) effort level. If the requested level is not a recognized member of THINKING_LEVELS, or if the model supports no levels on the scale, the function returns None.

    Phase 1: Exact Match Evaluation

        if level in supported:
        return level
    The function first executes an $O(1)$ or $O(N)$ containment check against the supported collection. If the target provider or model natively accepts level without modification, execution short-circuits immediately, bypassing any distance metric calculations.

    Phase 2: Candidate Ranking and Scale Validation

        ranked = [lvl for lvl in THINKING_LEVELS if lvl in supported]
    if not ranked or level not in THINKING_LEVELS:
        return None
    If an exact match fails, the function compiles an ordered list of all levels simultaneously defined in THINKING_LEVELS and present in the model's supported set. If the intersection is empty (indicating the model exposes a non-standard vocabulary or does not support adjustable thinking), or if the incoming level is invalid, the function safely aborts by returning None.

    Phase 3: Distance Metric Calculation and Tie-Breaking

        target = THINKING_LEVELS.index(level)
    return min(ranked, key=lambda lvl: (abs(THINKING_LEVELS.index(lvl) - target), THINKING_LEVELS.index(lvl)))
    The final phase computes the index distance between each supported level and the target on the ordered scale. The minimization key produces a 2-tuple: (distance_from_target, absolute_scale_index). If two supported levels are equally distant from the target (e.g., target is medium at index 2, with supported levels low at index 1 and high at index 3, both having distance 1), the second tuple element breaks the tie in favor of the smaller index (low). This enforces a defensive engineering policy: when forced to approximate, the system favors lower cost and lower latency over excessive token consumption.

    Parameters: * level (str): The desired thinking level string to clamp (e.g., "xhigh", "minimal"). * supported (Iterable[str]): A collection (list, set, or tuple) containing the thinking level identifiers supported by the target model or provider.

    Returns: * str | None: The exact level if supported, the nearest supported level favoring the lower option on ties, or None if clamping is impossible.

    Raises: * No exceptions are raised internally.

    Example: 

    # Actual implementation from utils/thinking.py
def clamp_level(level: str, supported) -> str | None:
    """Return `level` if the model supports it, else the nearest supported level on
    THINKING_LEVELS (ties → lower). None when nothing on the scale is supported."""
    if level in supported:
        return level
    ranked = [lvl for lvl in THINKING_LEVELS if lvl in supported]
    if not ranked or level not in THINKING_LEVELS:
        return None
    target = THINKING_LEVELS.index(level)
    return min(ranked, key=lambda lvl: (abs(THINKING_LEVELS.index(lvl) - target), THINKING_LEVELS.index(lvl)))

    parse_overrides()

    Visibility: Public
    Signature: def parse_overrides(values: list[str] | None) -> tuple[dict, list[str]]:

    Description: Parses raw command-line override arguments into a validated dictionary of node-to-level assignments and a list of invalid entries. Each input item is expected in the format NODE=LEVEL. The function partitions each string on the first = delimiter, trims whitespace, and converts both tokens to lowercase. It validates that the node identifier exists in NODE_KEYS and the level exists in THINKING_LEVELS. Valid pairs are inserted into the overrides dictionary, while malformed strings, unknown node names, or unapproved effort levels are appended to invalid_values for diagnostic logging and warning emissions upstream.

    Parameters: * values (list[str] | None): A list of raw string inputs passed via the CLI (e.g., ["write_chapters=high", "extract_facts=low"]), or None if the flag was not supplied.

    Returns: * tuple[dict, list[str]]: A 2-tuple containing: 1. overrides (dict[str, str]): A mapping of validated node keys to their target thinking levels. 2. invalid (list[str]): A list of original raw strings that failed syntax or schema validation.

    Raises: * No exceptions are raised internally; errors are collected and returned within the second tuple element.

    Example: 

    # Actual implementation from utils/thinking.py
def parse_overrides(values: list[str] | None) -> tuple[dict, list[str]]:
    """Parse NODE=LEVEL strings. Returns (overrides, invalid_values)."""
    overrides, invalid = {}, []
    for value in values or []:
        node, sep, level = value.partition("=")
        node, level = node.strip().lower(), level.strip().lower()
        if not sep or node not in NODE_KEYS or level not in THINKING_LEVELS:
            invalid.append(value)
        else:
            overrides[node] = level
    return overrides, invalid

    The function uses str.partition("=") instead of str.split("=") to guarantee a safe 3-tuple unpacking even when delimiter characters are missing or duplicated. Calling .strip().lower() on both partitions ensures that user typos involving trailing spaces or uppercase text (e.g., " Write_Chapters = HIGH ") do not cause spurious validation failures. The values or [] idiom gracefully shields the loop from iterating over None.

    build_thinking_plan()

    Visibility: Public
    Signature: def build_thinking_plan(profile: str, mode: str, global_level: str | None, overrides: dict) -> dict:

    Description: Assembles the complete execution plan mapping every registered NODE_KEYS entry to a concrete thinking level or None. The construction adheres strictly to the system's precedence hierarchy: 1. If global_level is provided, it supersedes profile definitions, initializing all nodes to the lowercased global level. 2. Otherwise, if profile matches an entry in _PROFILES, the plan copies the profile's baseline node table and applies any mode-specific adjustments defined in _MODE_ADJUSTMENTS for the active mode. 3. If profile is "off" or unrecognized, every node in NODE_KEYS is mapped to None (deferring thinking settings to provider model defaults). 4. Finally, all key-value pairs in overrides are updated into the plan dictionary, overwriting any previous assignments with highest priority.

    Parameters: * profile (str): The resolved profile name, typically obtained from resolve_profile_name() (e.g., "balanced", "economy", "off"). * mode (str): The active documentation generation mode (e.g., "tutorial", "advanced", "sdk", "api-reference"). * global_level (str | None): An optional global effort level specified by the user via --thinking-level (e.g., "high"), or None. * overrides (dict[str, str]): A dictionary of node-specific level overrides obtained from parse_overrides().

    Returns: * dict[str, str | None]: A complete thinking plan mapping every string key in NODE_KEYS to a thinking level string or None.

    Raises: * No exceptions are raised internally.

    Example: 

    # Actual implementation from utils/thinking.py
def build_thinking_plan(profile: str, mode: str, global_level: str | None, overrides: dict) -> dict:
    """Return {node_key: level | None} for every NODE key.

    Precedence: overrides > global_level > profile table (+ mode adjustments).
    `profile` must already be resolved (see resolve_profile_name).
    """
    if global_level:
        plan = dict.fromkeys(NODE_KEYS, global_level.lower())
    elif profile in _PROFILES:
        plan = dict(_PROFILES[profile])
        plan.update(_MODE_ADJUSTMENTS.get(profile, {}).get(mode, {}))
    else:  # "off": every node uses the model's default thinking behavior
        plan = dict.fromkeys(NODE_KEYS)
    plan.update(overrides)
    return plan

    The function guarantees that every identifier in NODE_KEYS is present as a key in the returned dictionary. When using dict.fromkeys(NODE_KEYS), keys default to None if no secondary argument is passed, perfectly representing the "off" state. When updating mode adjustments via _MODE_ADJUSTMENTS.get(profile, {}).get(mode, {}), chained .get() invocations ensure that missing profiles or unadjusted modes fall back cleanly to empty dictionaries without raising KeyError.

    resolve_thinking_level()

    Visibility: Public
    Signature: def resolve_thinking_level(shared: dict, node_key: str) -> str | None:

    Description: Resolves the effective thinking level for a specific LLM call site from the shared workflow state dictionary. It first inspects the shared dictionary for a compiled "thinking_plan" mapping. If the plan exists and contains node_key, its assigned level is returned. If no plan is present or the key is missing from the plan, the function falls back to retrieving the global "thinking_level" scalar from shared. If neither is configured, it returns None.

    Parameters: * shared (dict): The global or workflow-level shared state dictionary passed across pipeline nodes. * node_key (str): The unique identifier of the calling node (e.g., "extract_facts", "write_chapters").

    Returns: * str | None: The resolved thinking level for the specified node, or None if model defaults should apply.

    Raises: * No exceptions are raised internally.

    Example: 

    # Actual implementation from utils/thinking.py
def resolve_thinking_level(shared: dict, node_key: str) -> str | None:
    """Thinking level for one LLM call site. Falls back to the global level when no plan exists."""
    plan = shared.get("thinking_plan")
    if plan and node_key in plan:
        return plan[node_key]
    return shared.get("thinking_level")

    This helper is invoked across node execution boundaries in nodes.py and prompt dispatchers in call_llm.py. By checking node_key in plan rather than evaluating the truthiness of plan.get(node_key), it correctly handles plan entries whose value is explicitly set to None.

    describe_plan()

    Visibility: Public
    Signature: def describe_plan(plan: dict, mode: str | None = None) -> str:

    Description: Serializes a thinking plan into a compact, human-readable, one-line string representation suitable for terminal startup banners and configuration telemetry. If a mode is provided and recognized in MODE_NODES, the output is filtered to display only the nodes relevant to that mode's execution path. If mode is omitted or unlisted, all NODE_KEYS are displayed. Any node mapped to None or an empty value is rendered with the label 'default'.

    Parameters: * plan (dict): The compiled thinking plan dictionary mapping node keys to levels. * mode (str | None, optional): The active execution mode (e.g., "tutorial", "api-reference"). Defaults to None.

    Returns: * str: A comma-delimited string of node=level assignments (e.g., "filter_files=low, extract_facts=low, write_chapters=medium").

    Raises: * No exceptions are raised internally.

    Example: 

    # Actual implementation from utils/thinking.py
def describe_plan(plan: dict, mode: str | None = None) -> str:
    """Compact one-line rendering for the startup config display (only nodes that run in `mode`)."""
    keys = MODE_NODES.get(mode, NODE_KEYS)
    return ", ".join(f"{key}={plan.get(key) or 'default'}" for key in keys)

    The function queries MODE_NODES with a default fallback to NODE_KEYS, ensuring that pipeline modes omitting specific analysis stages (such as api-reference bypassing abstraction identification) do not clutter diagnostic logs with irrelevant node statuses. The expression plan.get(key) or 'default' guarantees that None values are translated into readable text.

    Data Structures

    The module relies on structured tuples and dictionaries to govern node keys, execution modes, effort scales, and operational profiles.

    THINKING_LEVELS

    An ordered tuple of string literals representing the system-wide reasoning effort scale.

    THINKING_LEVELS = ("minimal", "low", "medium", "high", "xhigh", "max")
    Index Level Typical Token / Cognitive Profile Primary Use Case
    0 "minimal" Minimal token budget (supported on select OpenRouter models). Ultra-fast heuristic checks; never assigned by standard profiles.
    1 "low" Low reasoning budget (~1,024 reasoning tokens). Mechanical transformations, file filtering, localized fact extraction.
    2 "medium" Moderate reasoning budget (~2,048–4,096 tokens). Standard chapter drafting, relationship analysis, module grouping.
    3 "high" High reasoning budget (~8,192 tokens). Whole-codebase abstraction discovery, complex synthesis.
    4 "xhigh" Extended reasoning budget (~16,384 tokens). Deep multi-abstraction relationship mapping under the max profile.
    5 "max" Provider context ceiling limit. Maximum reasoning depth for critical synthesis under the max profile.

    THINKING_PROFILES

    A tuple defining the valid profile names accepted by --thinking-profile.

    THINKING_PROFILES = ("auto", "off", "economy", "balanced", "quality", "max")
    Profile Strategy Description Cost / Latency Tier
    "auto" Dynamically resolves to "balanced" for profiled providers, and "off" for unprofiled endpoints. Variable
    "off" Disables explicit reasoning parameters; every node runs with model-default behavior. Baseline
    "economy" Minimizes reasoning token usage across all nodes (capped at medium for abstraction synthesis). Lowest Cost
    "balanced" Allocates high effort to abstraction identification/reduction, and medium or low elsewhere. Standard / Recommended
    "quality" Elevates chapter generation and analysis nodes to high effort. Higher Quality & Cost
    "max" Allocates xhigh and max effort to core abstraction and synthesis stages. Maximum Effort

    _MODE_ADJUSTMENTS

    A nested dictionary specifying mode-specific overrides that overlay on top of the base profile tables.

    _MODE_ADJUSTMENTS = {
    "economy": {"advanced": {"write_chapters": "medium"}},
}

    In economy profile, chapter writing defaults to low. However, because advanced mode chapters require extensive design-rationale analysis and are capped at a smaller maximum chapter count, _MODE_ADJUSTMENTS raises write_chapters to medium specifically when mode == "advanced".

    PROFILED_PROVIDERS

    A tuple containing provider names whose reasoning capabilities are explicitly configured per model in this project.

    PROFILED_PROVIDERS = ("ANTHROPIC", "GEMINI", "OPENROUTER")

    When --thinking-profile auto is selected, providers within this set resolve to "balanced". All other providers resolve to "off".

    A complete dictionary where every key in NODE_KEYS is mapped to an effort level ("minimal", "low", "medium", "high", "xhigh", "max") or None (representing model default behavior).

    Error Handling

    The module implements defensive, non-terminating error recovery patterns to ensure CLI configuration issues do not cause unhandled runtime crashes during pipeline initialization:

    1. Non-Raising CLI Parsing (parse_overrides): Instead of raising ValueError or KeyError upon encountering malformed input strings, parse_overrides() separates valid definitions from invalid entries. It verifies delimiter presence (sep), node validity (node in NODE_KEYS), and level validity (level in THINKING_LEVELS). Unrecognized items are gathered into the invalid list, allowing the caller in main.py to log formatted warnings to the user via utils.output before cleanly exiting.

    2. Graceful Clamping Fallbacks (clamp_level): When an upstream provider adapter invokes clamp_level() with a level outside its supported set, the function does not raise an IndexError or ValueError. If the requested level is not in THINKING_LEVELS, or if the model's supported collection contains no recognizable levels, it gracefully returns None. When clamping among valid options, it uses absolute index delta minimization with lower-bound tie-breaking to guarantee a deterministic result.

    3. Safe Dictionary Retrieval (resolve_thinking_level and build_thinking_plan): When querying workflow state dictionaries, resolve_thinking_level() uses .get("thinking_plan") and explicitly verifies node_key in plan. This avoids KeyError exceptions if nodes are added dynamically or if state dictionaries are initialized partially. Similarly, build_thinking_plan() guards against missing mode configurations by chaining .get() lookups with empty dictionary fallbacks: _MODE_ADJUSTMENTS.get(profile, {}).get(mode, {}).

    4. Case and Whitespace Normalization: All user-supplied string inputs (profile names, node keys, and effort levels) are sanitized using .strip().lower(). This ensures resilience against casing discrepancies and accidental whitespace in configuration files or CLI flags.
