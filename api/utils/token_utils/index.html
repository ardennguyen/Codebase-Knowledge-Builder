    utils.token_utils

    Source File: utils/token_utils.py

    Technical Overview

    The utils.token_utils module provides token measurement, estimation, and diagnostic logging utilities for LLM prompts across the pipeline. It manages a lazily initialized singleton tiktoken encoding model (cl100k_base) with a graceful character-heuristic fallback mechanism (len(text) // 4) if tokenizer initialization fails or if the environment lacks complete tokenizer resources.

    Additionally, this module provides structured logging and ANSI-colored terminal analytics via log_token_estimation, giving real-time visibility into prompt token counts, prompt capacity utilization against configured maximums, and itemized breakdowns of dynamic prompt sections.

    • Definition: _encoding = None
    • Description: Module-level singleton variable storing the cached cl100k_base tokenizer encoding object. It remains None until initialized on first access via _get_encoding().

    Module-Level Functions

    _get_encoding()

    Visibility: Private (Internal helper)
    Signature: def _get_encoding() -> tiktoken.Encoding | None:

    Description:
    Implements a lazy-loading singleton pattern for the tiktoken tokenizer encoding. It checks the module-scoped _encoding variable, attempting to instantiate the standard OpenAI cl100k_base BPE tokenizer if not already loaded. If an exception occurs during initialization (e.g., missing tokenizer dictionary files or network/environment restrictions), the exception is suppressed and _encoding is set to None, ensuring that downstream token counting degrades safely to heuristic estimation without crashing the calling node.

    Parameters:
    * None

    Returns:
    * tiktoken.Encoding | None: The initialized cl100k_base encoding object if available; otherwise None.

    Raises:
    * None (all internal exceptions from tiktoken.get_encoding are caught internally).

    Example: 

    def _get_encoding():
    global _encoding
    if _encoding is None:
        try:
            _encoding = tiktoken.get_encoding("cl100k_base")
        except Exception:
            _encoding = None
    return _encoding

    The function relies on global state mutation (global _encoding) to guarantee that the BPE vocabulary table is loaded at most once during the process lifecycle. The broad except Exception clause guarantees fault tolerance in offline or resource-constrained environments where binary token assets cannot be verified or downloaded. Once resolved, subsequent invocations bypass the initialization block entirely and return the cached reference.

    count_tokens()

    Visibility: Public
    Signature: def count_tokens(text: str) -> int:

    Description:
    Calculates the number of tokens in a provided string. It first performs a fast check for empty or falsy strings, returning 0 immediately. If text is present, it retrieves the encoding instance from _get_encoding(). When an encoding object is active, it encodes the string using byte-pair encoding and returns the exact token list length. If the encoding object is unavailable, it calculates an integer division approximation (len(text) // 4), matching the standard four-characters-per-token heuristic for English text.

    Parameters:
    * text (str): The raw text string or prompt content whose tokens need to be calculated.

    Returns:
    * int: The exact or estimated token count. Returns 0 if text is empty or None.

    Raises:
    * None

    Example: 

    def count_tokens(text: str) -> int:
    """Count tokens using tiktoken, with fallback to chars/4."""
    if not text:
        return 0
    enc = _get_encoding()
    if enc:
        return len(enc.encode(text))
    return len(text) // 4

    This function acts as the unified token measurement interface for the application. By centralizing token calculation, prompt builders across utils.prompts and node executors in nodes can determine payload sizes prior to making network requests. The fallback calculation len(text) // 4 ensures pipeline continuity in development or testing environments where tiktoken native bindings or vocabularies might not be fully configured.

    log_token_estimation()

    Visibility: Public
    Signature: def log_token_estimation(node_name: str, prompt_content: str, max_tokens: int, token_usage: dict | None = None) -> None:

    Description:
    Measures prompt size, calculates capacity consumption relative to the configured context window limit, builds sub-component usage breakdowns, and emits formatted messages to both the standard console output and the structured file logger. Console output uses yellow ANSI escape sequences (\033[93m...\033[0m) for high visibility during live executions, while file logs write standardized NODE EXEC pipe-delimited log lines through llm_logger.

    Parameters:
    * node_name (str): The name or identifier of the execution node invoking the LLM (e.g., node names defined in flow or nodes). * prompt_content (str): The full text string of the assembled prompt to be evaluated. * max_tokens (int): The maximum token capacity allocated for the model or node context. * token_usage (dict | None, optional): A key-value mapping of sub-component names to their respective token counts (e.g., {"system_prompt": 120, "context": 1500}). Defaults to None.

    Returns:
    * None

    Raises:
    * None

    Example: 

    def log_token_estimation(node_name: str, prompt_content: str, max_tokens: int,
                         token_usage: dict | None = None) -> None:
    token_count = count_tokens(prompt_content)
    percentage = (token_count / max_tokens) * 100 if max_tokens else 0

    # Build token usage string if provided
    usage_str = ""
    if token_usage:
        parts = []
        for label, value in token_usage.items():
            pct = (value / token_count * 100) if token_count else 0
            parts.append(f"{label}={value:,} ({pct:.0f}%)")
        usage_str = " | " + " | ".join(parts)

    # Console output (yellow) with token usage
    print(f"\033[93m[Token Analytics] {node_name}: {token_count:,} / {max_tokens:,} tokens ({percentage:.1f}% capacity){usage_str}\033[0m")

    # File log with node context and token usage
    logger.info(f"NODE EXEC | node={node_name} | prompt_tokens={token_count:,} / {max_tokens:,} ({percentage:.1f}% capacity){usage_str}")

    The function computes the global token count of prompt_content using count_tokens(). It then computes the overall context consumption ratio percentage, guarding against division by zero when max_tokens is set to 0. If an optional token_usage dictionary is supplied, it iterates over each sub-section metric, formatting individual counts with comma separators and relative percentages against the total prompt token count. Finally, it formats dual outputs: an ANSI-colored string directly written to stdout via print(), and a structured record sent to logger.info().
