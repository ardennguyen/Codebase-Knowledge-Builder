    utils.token_utils

    utils/token_utils.py

    The utils.token_utils module provides token counting, estimation, and execution logging utilities for the Codebase-Knowledge-Builder pipeline. It is responsible for calculating token footprints across execution nodes, guarding against context-window saturation, and reporting capacity utilization to both console outputs and log files.

    Technical Overview

    Language model operations in Codebase-Knowledge-Builder require monitoring prompt sizes against strict model context constraints. utils.token_utils encapsulates the token calculation logic using OpenAI's tiktoken tokenizer (cl100k_base encoding) while providing a heuristic character-ratio fallback mechanism when the tokenizer is unavailable.

    The module implements a lazy-initialized singleton pattern for the tokenizer instance to minimize memory overhead and startup latency. Furthermore, it integrates with the shared logging infrastructure configured in utils.call_llm to emit formatted console telemetry (with ANSI terminal colors) and structured log entries detailing prompt capacities and token distributions per graph node.

    Module-Level Variables

    logger

    • Type: logging.Logger
    • Description: Reference to the shared "llm_logger" instance initialized across the application (primarily configured in utils.call_llm). Used for persistent operational and diagnostic logging.

    _encoding

    • Type: Optional[tiktoken.Encoding]
    • Description: Module-level global singleton holding the cached tiktoken encoding instance. Initialized to None and lazily instantiated upon the first invocation of _get_encoding().

    Module-Level Functions

    _get_encoding()

    Visibility: Private Signature: def _get_encoding()

    Description: Retrieves or lazily instantiates the module-level singleton tiktoken encoding instance configured for the "cl100k_base" tokenizer family. If the encoding has not yet been initialized, it attempts to load it from tiktoken. If an exception occurs (such as missing tokenizer data files, network issues downloading vocabulary assets, or underlying runtime failures), the function catches the exception and maintains _encoding as None, allowing downstream token calculation to degrade gracefully to a heuristic character-based count.

    def _get_encoding():
    global _encoding
    if _encoding is None:
        try:
            _encoding = tiktoken.get_encoding("cl100k_base")
        except Exception:
            _encoding = None
    return _encoding

    The singleton pattern avoids the computational cost of reloading the BPE tokenizer dictionary on every token counting operation. By catching all broad Exception instances, the system guarantees uninterrupted execution even in offline or constrained environments where tiktoken resource downloads might fail.

    Parameters: * None.

    Returns: * Optional[tiktoken.Encoding]: The initialized tiktoken.Encoding instance if successfully resolved; otherwise None.

    Raises: * No exceptions are raised; internal errors during initialization are suppressed to enable fallback operation.

    Example: 

    # Internal usage within count_tokens()
enc = _get_encoding()
if enc:
    return len(enc.encode(text))
return len(text) // 4

    count_tokens()

    Visibility: Public Signature: def count_tokens(text: str) -> int:

    Description: Calculates the total token count of a provided text string. It first performs a truthiness check on the input string to short-circuit empty or None inputs to 0. It then queries _get_encoding() for the active tiktoken encoding object. If present, it tokenizes the text using enc.encode(text) and measures the length of the resulting token array. If the tokenizer is unavailable, it calculates an approximation based on the standard empirical heuristic of 4 characters per token (len(text) // 4).

    def count_tokens(text: str) -> int:
    """Count tokens using tiktoken, with fallback to chars/4."""
    if not text:
        return 0
    enc = _get_encoding()
    if enc:
        return len(enc.encode(text))
    return len(text) // 4

    This dual-mode counting strategy ensures strict accuracy when tiktoken is operational while preventing execution failure if tokenizer dependencies are missing or misconfigured. The integer division // 4 provides an integer token estimate suitable for context budgeting calculations.

    Parameters: * text (str): The raw text or prompt content whose tokens are to be counted.

    Returns: * int: Total number of tokens computed by tiktoken or estimated via heuristic division.

    Raises: * No exceptions are raised directly.

    Example: 

    # Internal invocation from log_token_estimation()
token_count = count_tokens(prompt_content)

    log_token_estimation()

    Visibility: Public Signature: def log_token_estimation(node_name: str, prompt_content: str, max_tokens: int, token_usage: dict = None) -> None:

    Description: Computes token statistics for a specific workflow node's prompt and emits detailed diagnostic analytics to both standard console output and the shared application logger. The function determines the token count using count_tokens() and computes the consumption percentage against the provided max_tokens context limit. If a structured token_usage breakdown dictionary is supplied, it parses each key-value pair, calculates the individual component percentage relative to token_count, and builds a composite summary string.

    def log_token_estimation(node_name: str, prompt_content: str, max_tokens: int,
                         token_usage: dict = None) -> None:
    token_count = count_tokens(prompt_content)
    percentage = (token_count / max_tokens) * 100 if max_tokens else 0

    # Build token usage string if provided
    usage_str = ""
    if token_usage:
        parts = []
        for label, value in token_usage.items():
            pct = (value / token_count * 100) if token_count else 0
            parts.append(f"{label}={value:,} ({pct:.0f}%)")
        usage_str = " | " + " | ".join(parts)

    # Console output (yellow) with token usage
    print(f"\033[93m[Token Analytics] {node_name}: {token_count:,} / {max_tokens:,} tokens ({percentage:.1f}% capacity){usage_str}\033[0m")

    # File log with node context and token usage
    logger.info(f"NODE EXEC | node={node_name} | prompt_tokens={token_count:,} / {max_tokens:,} ({percentage:.1f}% capacity){usage_str}")

    The function handles edge cases where max_tokens or token_count are zero by zero-guarding percentage computations. Console output is formatted using ANSI escape sequences (\033[93m and \033[0m) to render analytics in yellow for visibility during interactive CLI execution, while logger.info() writes a machine-parsable execution record tagged with NODE EXEC.

    Parameters: * node_name (str): The name or identifier of the pipeline node triggering the estimation (e.g., "summary", "architecture"). * prompt_content (str): The full text of the prompt being dispatched to the LLM. * max_tokens (int): The maximum context window or budget configured for the target model or node. * token_usage (dict, optional): A key-value mapping of prompt sub-components (e.g., {"system": 500, "files": 12000}) to their respective token counts. Defaults to None.

    Returns: * None

    Raises: * No exceptions are raised directly.

    Example:
