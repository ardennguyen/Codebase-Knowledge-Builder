    utils.token_utils

    File Path: utils/token_utils.py

    Following the file crawling and repository fetching utilities documented in utils.crawl_local_files and utils.crawl_github_files, the utils.token_utils module provides token counting, estimation, and capacity logging functionality for the Codebase-Knowledge-Builder pipeline.

    Technical Overview

    The utils.token_utils module tracks and logs token consumption across the execution lifecycle of individual nodes. Because large language models (LLMs) operate under strict context window constraints, monitoring the estimated token size of generated prompts relative to a model's maximum context capacity is critical to prevent prompt truncation, unexpected API rejections, and out-of-memory runtime failures.

    The module integrates with: 1. tiktoken: Uses OpenAI's cl100k_base byte pair encoding (BPE) tokenizer to provide accurate token estimates for code and text prompts. 2. Character-Count Fallback: Implements a rule-of-thumb fallback calculation (len(prompt_content) // 4) if tiktoken fails or is unavailable. 3. Centralized Logging: Attaches directly to the "llm_logger" instance configured by utils.call_llm to record token metrics to per-run disk logs while printing ANSI-formatted analytics directly to the terminal stdout stream.

    Architectural Workflow

    The diagram below illustrates how log_token_estimation calculates token usage and dispatches metrics to both stdout and disk-based logs:

    flowchart TD
    A[Node Invocation: log_token_estimation] --> B[Try tiktoken: cl100k_base]
    B -- Success --> C[Exact Token Count: len enc.encode]
    B -- Exception --> D[Fallback Approximation: len // 4]

    C --> E[Calculate Context Percentage: tokens / max_tokens * 100]
    D --> E

    E --> F[Print Yellow ANSI Analytics to Terminal stdout]
    E --> G[Log Structured Message via llm_logger to File]

    Module-Level Variables

    logger

    • Type: logging.Logger
    • Value: logging.getLogger("llm_logger")
    • Description: Module-level logger retrieved from Python's standard logging hierarchy. It shares the same logger instance initialized and configured by configure_logging() in utils.call_llm, ensuring that token consumption entries are written to the current session's timestamped execution log file.

    Module-Level Functions

    log_token_estimation()

    Visibility: Public
    Signature: def log_token_estimation(node_name: str, prompt_content: str, max_tokens: int) -> None:

    Description:
    Calculates the estimated token count of a given prompt string, computes the percentage of the model's total context window capacity that the prompt occupies, and outputs this analysis to both the console (in ANSI yellow) and the application log file.

    The function attempts to tokenize prompt_content using tiktoken with the "cl100k_base" encoding scheme. If an exception is raised during tokenization (e.g., encountering unrecognized characters or initialization issues), it falls back to an approximate ratio of 4 characters per token (len(prompt_content) // 4).

    It calculates the percentage of the context limit used: $$\text{percentage} = \left(\frac{\text{token_count}}{\text{max_tokens}}\right) \times 100$$ If max_tokens is 0 or None, it evaluates to 0.

    Finally, it formats and outputs: - A colored terminal line: \033[93m[Token Analytics] {node_name}: {token_count:,} / {max_tokens:,} tokens ({percentage:.1f}% capacity)\033[0m - A structured logging record through llm_logger: NODE EXEC | node={node_name} | estimated_tokens={token_count:,} / {max_tokens:,} ({percentage:.1f}% capacity)

    Core Implementation:

    def log_token_estimation(node_name: str, prompt_content: str, max_tokens: int) -> None:
    try:
        encoding = tiktoken.get_encoding("cl100k_base")
        token_count = len(encoding.encode(prompt_content))
    except Exception:
        # Fallback approximation
        token_count = len(prompt_content) // 4

    percentage = (token_count / max_tokens) * 100 if max_tokens else 0

    # Console output (yellow)
    print(f"\033[93m[Token Analytics] {node_name}: {token_count:,} / {max_tokens:,} tokens ({percentage:.1f}% capacity)\033[0m")

    # File log with node context
    logger.info(f"NODE EXEC | node={node_name} | estimated_tokens={token_count:,} / {max_tokens:,} ({percentage:.1f}% capacity)")

    Parameters: * node_name (str): The name of the executing pipeline node (e.g., "IdentifyAbstractions", "DeterministicFileMapper"). * prompt_content (str): The complete raw prompt text to be analyzed. * max_tokens (int): The maximum context window size configured for the target LLM.

    Returns: * None

    Raises: * None (all exceptions encountered during token encoding are handled internally by falling back to character approximation).

    Example: 

    # From DeterministicFileMapper.exec() in nodes.py
log_token_estimation(self.__class__.__name__, prompt, max_tokens)


    # From IdentifyAbstractions.exec() in nodes.py
log_token_estimation(self.__class__.__name__, prompt, max_tokens)
