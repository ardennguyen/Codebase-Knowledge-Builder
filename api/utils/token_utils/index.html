    utils.token_utils

    File Path: utils/token_utils.py

    Overview

    The utils.token_utils module provides tokenization, token counting, and telemetry estimation utilities for the Codebase-Knowledge-Builder pipeline. Because large language models impose strict input context window limits and cost constraints, accurate token estimation is necessary before executing graph operations and LLM prompts.

    This module encapsulates lazy-loaded tiktoken encoding using a singleton pattern. When available, it leverages the cl100k_base BPE (Byte-Pair Encoding) tokenizer used by modern OpenAI architectures. If tiktoken is unavailable or encounters initialization issues, it gracefully falls back to a 4-character-per-token heuristic (len(text) // 4). Additionally, the module exposes structured logging utilities that output colorized console alerts and stream metrics into the shared llm_logger.

    Module-Level Functions

    _get_encoding()

    Visibility: Private / Internal Helper
    Signature: def _get_encoding()

    Description:
    Initializes and retrieves the global tiktoken BPE tokenizer instance. It uses the "cl100k_base" encoding specification. If the encoding object has not been loaded yet, it attempts instantiation within a try-except block; any failure resets or retains _encoding as None. This guarantees that tokenizer setup failures do not crash the pipeline and allow downstream fallback execution.

    def _get_encoding():
    global _encoding
    if _encoding is None:
        try:
            _encoding = tiktoken.get_encoding("cl100k_base")
        except Exception:
            _encoding = None
    return _encoding

    _get_encoding manages the lifecycle of the tokenizer singleton across thread calls and node executions. By deferring tokenizer creation until the first token count is requested, application startup time is minimized. In containerized or sandboxed environments where tokenizer binary assets or network caches might be restricted, the broad except Exception ensures continuous operation by returning None instead of propagating uncaught exceptions.

    Parameters: * None.

    Returns: * tiktoken.Encoding | None: The loaded cl100k_base encoding object if available, otherwise None.

    Raises: * No exceptions are raised; errors during tiktoken.get_encoding are swallowed and set _encoding to None.

    Example: 

    # Internal usage inside utils/token_utils.py:
enc = _get_encoding()
if enc:
    return len(enc.encode(text))
return len(text) // 4

    count_tokens()

    Visibility: Public
    Signature: def count_tokens(text: str) -> int:

    Description:
    Calculates the exact or estimated token count for a given string. If text is empty or falsy, it immediately returns 0. When the tiktoken encoding instance is successfully retrieved via _get_encoding(), it performs exact BPE tokenization (len(enc.encode(text))). If the tokenizer is unavailable, it applies a fast integer division heuristic based on character length (len(text) // 4).

    def count_tokens(text: str) -> int:
    """Count tokens using tiktoken, with fallback to chars/4."""
    if not text:
        return 0
    enc = _get_encoding()
    if enc:
        return len(enc.encode(text))
    return len(text) // 4

    This function is the primary token estimation workhorse across the framework. It handles boundary cases such as "" or None by immediately returning zero before calling the tokenizer. When exact tokenization is active, enc.encode(text) generates integer token IDs whose count matches the actual context window consumption of OpenAI models. The integer division len(text) // 4 provides an industry-standard approximation for English text and source code when runtime constraints prevent loading the standard tokenizer table.

    Parameters: * text (str): The string payload or prompt segment whose tokens are to be counted.

    Returns: * int: Total number of tokens computed via BPE encoding or character division approximation.

    Raises: * No exceptions are raised directly.

    Example: 

    # Extracted from log_token_estimation implementation in utils/token_utils.py:
token_count = count_tokens(prompt_content)
percentage = (token_count / max_tokens) * 100 if max_tokens else 0

    log_token_estimation()

    Visibility: Public
    Signature: def log_token_estimation(node_name: str, prompt_content: str, max_tokens: int, token_usage: dict | None = None) -> None:

    Description:
    Calculates the token footprint of prompt_content using count_tokens(), determines the percentage against the provided max_tokens context ceiling, and outputs formatted metrics to both stdout and the shared logger. If a breakdown dictionary token_usage is supplied, it calculates the percentage of the total prompt each category occupies and appends it to the log output.

    def log_token_estimation(node_name: str, prompt_content: str, max_tokens: int, token_usage: dict | None = None) -> None:
    token_count = count_tokens(prompt_content)
    percentage = (token_count / max_tokens) * 100 if max_tokens else 0

    # Build token usage string if provided
    usage_str = ""
    if token_usage:
        parts = []
        for label, value in token_usage.items():
            pct = (value / token_count * 100) if token_count else 0
            parts.append(f"{label}={value:,} ({pct:.0f}%)")
        usage_str = " | " + " | ".join(parts)

    # Console output (yellow) with token usage
    print(f"\033[93m[Token Analytics] {node_name}: {token_count:,} / {max_tokens:,} tokens ({percentage:.1f}% capacity){usage_str}\033[0m")

    # File log with node context and token usage
    logger.info(f"NODE EXEC | node={node_name} | prompt_tokens={token_count:,} / {max_tokens:,} ({percentage:.1f}% capacity){usage_str}")

    log_token_estimation provides real-time observability into the context utilization of each execution node in the knowledge-building pipeline. Terminal output is formatted with ANSI yellow escape codes (\033[93m ... \033[0m) to ensure token budget warnings stand out during execution runs. The structured message is simultaneously logged to logger.info("llm_logger") with prefix NODE EXEC, supporting external parsing and offline token budget auditing. If max_tokens is passed as 0, zero-division is guarded against, assigning percentage = 0.

    Parameters: * node_name (str): Identifier of the execution node invoking the token check (e.g., "build_skeleton"). * prompt_content (str): Full prompt text to evaluate. * max_tokens (int): Maximum context window capacity allocated for the node. * token_usage (dict | None, optional): Mapping of sub-component labels to their respective token counts (e.g., {"system_prompt": 120, "context": 4500}). Defaults to None.

    Returns: * None

    Raises: * No exceptions are raised directly.

    Example: 

    # Core implementation showing console and file log outputs:
token_count = count_tokens(prompt_content)
percentage = (token_count / max_tokens) * 100 if max_tokens else 0

print(f"\033[93m[Token Analytics] {node_name}: {token_count:,} / {max_tokens:,} tokens ({percentage:.1f}% capacity){usage_str}\033[0m")
logger.info(f"NODE EXEC | node={node_name} | prompt_tokens={token_count:,} / {max_tokens:,} ({percentage:.1f}% capacity){usage_str}")
