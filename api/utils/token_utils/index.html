    utils.token_utils

    Source File: utils/token_utils.py

    Overview

    The utils.token_utils module provides token calculation, estimation, and logging utilities across the Codebase-Knowledge-Builder pipeline. Because Large Language Model (LLM) context windows are constrained by strict input token thresholds, node executions must monitor prompt sizes and log token consumption metrics before dispatching payloads to downstream LLM APIs.

    This module encapsulates: 1. Lazy Singleton Encoding Initialization: Dynamically loads and caches the cl100k_base BPE (Byte-Pair Encoding) model from tiktoken upon first invocation. 2. Graceful Token Counting & Heuristic Fallbacks: Accurately counts tokens via tiktoken.encode() and falls back to a character-ratio heuristic (len(text) // 4) if tiktoken is unavailable or encounters initialization failures. 3. Structured Token Analytics Logging: Computes prompt capacity utilization percentages and breakdown metrics per node execution, emitting formatted ANSI-colored diagnostics to stdout and structured log entries to the shared llm_logger.

    _encoding

    • Type: Optional[tiktoken.Encoding]
    • Visibility: Private
    • Value: None
    • Description: Singleton cache variable holding the initialized cl100k_base tiktoken tokenizer instance. Initialized on demand by _get_encoding() to avoid import-time overhead.

    Module-Level Functions

    _get_encoding()

    Visibility: Private
    Signature: def _get_encoding() -> Optional[tiktoken.Encoding]:

    Description: Retrieves or lazily instantiates the module-level singleton _encoding instance. It attempts to load the standard OpenAI cl100k_base tokenizer schema via tiktoken.get_encoding("cl100k_base"). If tiktoken raises any exception (e.g., missing network access for first-time vocabulary downloads, unsupported platform dependencies, or corrupt vocabulary cache files), the exception is swallowed and _encoding remains None. This design ensures that token counting never crashes the pipeline.

    Parameters: * None

    Returns: * Optional[tiktoken.Encoding]: The initialized tiktoken encoding instance, or None if initialization failed.

    Raises: * No exceptions are propagated; all internal Exception instances during retrieval are caught and handled.

    Example: 

    def _get_encoding():
    global _encoding
    if _encoding is None:
        try:
            _encoding = tiktoken.get_encoding("cl100k_base")
        except Exception:
            _encoding = None
    return _encoding

    _get_encoding manages the global tokenizer cache lifecycle through lazy instantiation. By isolating the tiktoken.get_encoding call inside a guarded try/except block, the function provides an operational guarantee that network or runtime issues within the tokenizer library do not halt execution. Subsequent calls re-use the resolved _encoding reference without re-executing tokenizer parsing routines.

    count_tokens()

    Visibility: Public
    Signature: def count_tokens(text: str) -> int:

    Description: Calculates the total number of BPE tokens in a provided text string. If the input text is empty or falsy, it immediately returns 0. When the cl100k_base tokenizer is available via _get_encoding(), the function returns the exact token length from len(enc.encode(text)). If the tokenizer is unavailable (for example, if initialization failed), it falls back to the deterministic character approximation formula len(text) // 4, standard for English and code-heavy LLM contexts.

    Parameters: * text (str): The raw text or prompt content whose tokens need to be calculated.

    Returns: * int: Total token count (either exact BPE token length or heuristic estimate).

    Raises: * None.

    Example: 

    def count_tokens(text: str) -> int:
    """Count tokens using tiktoken, with fallback to chars/4."""
    if not text:
        return 0
    enc = _get_encoding()
    if enc:
        return len(enc.encode(text))
    return len(text) // 4

    The function handles edge cases where text is passed as an empty string, None, or whitespace by returning 0 immediately. When processing source code or structured node prompts, enc.encode(text) accurately accounts for indentation tokens, special syntax symbols, and vocabulary splits. The fallback len(text) // 4 ensures downstream nodes can still monitor rough capacity limits in restricted environments where external dependencies fail.

    log_token_estimation()

    Visibility: Public
    Signature: def log_token_estimation(node_name: str, prompt_content: str, max_tokens: int, token_usage: dict = None) -> None:

    Description: Performs token usage analysis for an execution step and emits formatted diagnostics to both stdout and logger. It calculates the prompt token count using count_tokens(prompt_content) and derives the percentage of context capacity utilized (token_count / max_tokens * 100). If an optional token_usage breakdown dictionary is supplied, it calculates relative percentages for each sub-component (e.g., file contents, system instructions, metadata).

    The formatted output is emitted to the console using ANSI yellow escape codes (\033[93m...\033[0m) for visibility during interactive runs, and simultaneously written to the "llm_logger" handler via logger.info().

    Parameters: * node_name (str): Identifier of the executing workflow node (e.g., "node_file_summary"). * prompt_content (str): Complete text payload intended for the model prompt. * max_tokens (int): Upper bound limit of tokens allowed for the target model or node context. * token_usage (dict, optional): Mapping of descriptive labels to individual token count integers representing prompt components. Defaults to None.

    Returns: * None

    Raises: * None.

    Example: 

    def log_token_estimation(node_name: str, prompt_content: str, max_tokens: int,
                         token_usage: dict = None) -> None:
    token_count = count_tokens(prompt_content)
    percentage = (token_count / max_tokens) * 100 if max_tokens else 0

    # Build token usage string if provided
    usage_str = ""
    if token_usage:
        parts = []
        for label, value in token_usage.items():
            pct = (value / token_count * 100) if token_count else 0
            parts.append(f"{label}={value:,} ({pct:.0f}%)")
        usage_str = " | " + " | ".join(parts)

    # Console output (yellow) with token usage
    print(f"\033[93m[Token Analytics] {node_name}: {token_count:,} / {max_tokens:,} tokens ({percentage:.1f}% capacity){usage_str}\033[0m")

    # File log with node context and token usage
    logger.info(f"NODE EXEC | node={node_name} | prompt_tokens={token_count:,} / {max_tokens:,} ({percentage:.1f}% capacity){usage_str}")

    log_token_estimation provides real-time monitoring of token budget consumption before LLM API invocation. It safely guards against division-by-zero errors when max_tokens or token_count are zero. The optional token_usage parameter allows nodes to pass sub-breakdowns (such as individual source files or dependency context), which are formatted into percentage-of-total strings and appended to both the terminal output and structured file log records.
