    utils.token_utils

    utils/token_utils.py

    Overview

    The utils.token_utils module provides utility functions for estimating, counting, and logging token usage across prompts and LLM pipeline operations. It is responsible for tracking token consumption within the Codebase-Knowledge-Builder system to ensure prompts stay within model context limits and to provide execution-time observability.

    The module encapsulates the tiktoken library using a lazy-loaded singleton pattern targeting the cl100k_base encoding (the standard tokenizer for OpenAI models such as GPT-4 and GPT-3.5-Turbo). If the tokenizer fails to initialize or encounters unexpected environments, it provides an automatic character-based fallback mechanism (heuristic of 4 characters per token). Furthermore, it provides formatted analytics logging to both the standard output (with ANSI color highlighting) and the shared application logger (llm_logger).

    Module-Level Variables

    logger

    • Type: logging.Logger
    • Description: A shared logger instance retrieved via logging.getLogger("llm_logger"). It channels token estimation and node execution telemetry to the unified logging system initialized across LLM utilities.

    _encoding

    • Type: tiktoken.Encoding | None
    • Description: Internal module-level singleton cache for the tiktoken encoding object. It remains None until first requested by _get_encoding(), preventing unnecessary overhead during startup.

    Module-Level Functions

    _get_encoding()

    Visibility: Private (Internal Helper)
    Signature: def _get_encoding() -> tiktoken.Encoding | None:

    Description:
    Lazily resolves and caches the cl100k_base tokenizer encoding instance from tiktoken. When invoked for the first time, it attempts to load the encoding schema and assign it to the global _encoding variable. If an exception occurs (for example, missing tokenizer data files or network retrieval issues in specific sandboxed environments), the exception is caught, and _encoding is set to None, allowing downstream token counters to degrade gracefully to heuristic estimation.

    Parameters:
    * None.

    Returns:
    * tiktoken.Encoding | None: The loaded tiktoken encoding singleton if successfully initialized; otherwise None.

    Raises:
    * No exceptions are raised. All initialization exceptions are caught internally.

    Example: 

    def _get_encoding():
    global _encoding
    if _encoding is None:
        try:
            _encoding = tiktoken.get_encoding("cl100k_base")
        except Exception:
            _encoding = None
    return _encoding

    The function manages the state of the global singleton variable _encoding. By wrapping the instantiation inside a generic try...except block, it guarantees that any operational or initialization failure within tiktoken does not crash the caller. Subsequent calls bypass initialization and return the cached reference directly.

    count_tokens()

    Visibility: Public
    Signature: def count_tokens(text: str) -> int:

    Description:
    Calculates the exact or estimated token count for a given string. If the input string is empty or evaluates to a falsy value, the function immediately returns 0. When text is provided, it retrieves the encoding instance via _get_encoding(). If the tokenizer is active, it encodes the string with disallowed_special=() (which disables special token parsing errors and treats all text verbatim) and returns the length of the resulting token list. If the tokenizer is unavailable, it calculates the token count using the standard heuristic len(text) // 4.

    Parameters:
    * text (str): The raw text content to evaluate.

    Returns:
    * int: Total number of tokens counted or estimated.

    Raises:
    * No exceptions are raised directly.

    Example: 

    def count_tokens(text: str) -> int:
    """Count tokens using tiktoken, with fallback to chars/4."""
    if not text:
        return 0
    enc = _get_encoding()
    if enc:
        return len(enc.encode(text, disallowed_special=()))
    return len(text) // 4

    The disallowed_special=() argument passed to enc.encode() is critical for codebase analysis pipelines. Source code frequently contains reserved substrings, prompt delimiters, or control characters that could otherwise trigger tiktoken special token validation exceptions. If encoding fails or is uninitialized, integer division by 4 provides an approximation aligned with standard English/code token density.

    log_token_estimation()

    Visibility: Public
    Signature: def log_token_estimation(node_name: str, prompt_content: str, max_tokens: int, token_usage: dict | None = None) -> None:

    Description:
    Calculates the token consumption of a prompt, calculates the percentage of context window capacity utilized against max_tokens, and logs the analytics to both the terminal (via ANSI yellow formatting) and the application file log (logger.info). It also supports an optional breakdown dictionary (token_usage) mapping section names to token counts, computing the relative percentage contribution of each subsection against the total calculated prompt tokens.

    Parameters:
    * node_name (str): The identifier or name of the execution node/step invoking the LLM (e.g., "SynthesizeArchitecture"). * prompt_content (str): The complete compiled prompt string passed to the model. * max_tokens (int): The maximum context window or budget allocated for this operation. * token_usage (dict | None, optional): A key-value mapping of sub-component names to their individual token counts for granular usage profiling. Defaults to None.

    Returns:
    * None

    Raises:
    * No exceptions are raised directly. Zero-division guards are included for cases where max_tokens or token_count is 0.

    Example: 

    def log_token_estimation(node_name: str, prompt_content: str, max_tokens: int, token_usage: dict | None = None) -> None:
    token_count = count_tokens(prompt_content)
    percentage = (token_count / max_tokens) * 100 if max_tokens else 0

    # Build token usage string if provided
    usage_str = ""
    if token_usage:
        parts = []
        for label, value in token_usage.items():
            pct = (value / token_count * 100) if token_count else 0
            parts.append(f"{label}={value:,} ({pct:.0f}%)")
        usage_str = " | " + " | ".join(parts)

    # Console output (yellow) with token usage
    print(f"\033[93m[Token Analytics] {node_name}: {token_count:,} / {max_tokens:,} tokens ({percentage:.1f}% capacity){usage_str}\033[0m")

    # File log with node context and token usage
    logger.info(f"NODE EXEC | node={node_name} | prompt_tokens={token_count:,} / {max_tokens:,} ({percentage:.1f}% capacity){usage_str}")

    This function performs formatted metric reporting. It evaluates count_tokens(prompt_content) to get the primary baseline, then constructs optional metric slices if token_usage is supplied. Output is routed to print() wrapped in ANSI escape sequences (\033[93m and \033[0m) for real-time developer visibility, and written to logger.info() under the structured prefix NODE EXEC | node=... for downstream log aggregation.
