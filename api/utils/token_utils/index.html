    utils.token_utils

    Source: utils/token_utils.py

    Technical reference and implementation documentation for utils.token_utils. This module provides token counting, encoding management, and formatted diagnostic reporting for LLM (Large Language Model) prompt capacity and node execution tracking in the Codebase-Knowledge-Builder pipeline.

    Technical Overview

    The utils.token_utils module acts as a utility layer for calculating and visualizing token utilization across prompt assembly and graph execution nodes. It interacts with OpenAI's tiktoken library using the cl100k_base BPE (Byte Pair Encoding) tokenizer while implementing defensive fallback mechanisms for environments where tiktoken fails to initialize or encounters non-standard inputs.

    Key Capabilities

    1. Lazy-Loaded Singleton Tokenizer: Encapsulates tiktoken.get_encoding("cl100k_base") in an internal singleton loader (_get_encoding) to avoid redundant initialization overhead during workflow execution.
    2. Resilient Token Estimation: Provides a token counter (count_tokens) that disables special token validation restrictions (disallowed_special=()) and defaults to a 4-characters-per-token heuristic (len(text) // 4) upon tokenizer failure or missing dependencies.
    3. Structured Analytics and Logging: Delivers standard terminal reporting with ANSI color highlights and single-line structured logging (log_token_estimation) targeted at downstream log parsers and the shared llm_logger.

    Module-Level Functions

    _get_encoding()

    Visibility: Private / Internal Helper
    Signature: def _get_encoding() -> tiktoken.Encoding | None:

    Description:
    Initializes and retrieves the global tiktoken BPE tokenizer instance. It uses lazy initialization so that the tokenizer is loaded only upon the first token calculation request. If tiktoken.get_encoding raises an exception (e.g., missing tokenizer models or network/filesystem issues loading encodings), the function catches the error, maintains _encoding as None, and returns None safely.

    Parameters:
    * None.

    Returns:
    * tiktoken.Encoding | None: The loaded cl100k_base encoding object, or None if initialization failed.

    Raises:
    * None internally (catches all standard exceptions during tokenizer instantiation).

    Example: 

    def _get_encoding():
    global _encoding
    if _encoding is None:
        try:
            _encoding = tiktoken.get_encoding("cl100k_base")
        except Exception:
            _encoding = None
    return _encoding

    _get_encoding manages the lifecycle of the tokenizer instance by maintaining a module-level global reference. By wrapping the external library call in a generic try...except block, the system ensures that unexpected failures in tiktoken do not crash the pipeline; instead, downstream consumers fall back gracefully to character-based heuristic estimation.

    count_tokens()

    Visibility: Public
    Signature: def count_tokens(text: str) -> int:

    Description:
    Calculates the exact or estimated token count for a given text string. If an encoding instance is available via _get_encoding(), it encodes the string using cl100k_base while bypassing special token validation errors by setting disallowed_special=(). If the tokenizer is unavailable or fails to initialize, it falls back to estimating the count using the standard character ratio heuristic of 4 characters per token (len(text) // 4).

    Parameters: * text (str): The raw text or prompt content to be measured.

    Returns: * int: Total number of tokens, or estimated token count. Returns 0 if text is empty or falsy.

    Raises: * None.

    Example: 

    def count_tokens(text: str) -> int:
    """Count tokens using tiktoken, with fallback to chars/4."""
    if not text:
        return 0
    enc = _get_encoding()
    if enc:
        return len(enc.encode(text, disallowed_special=()))
    return len(text) // 4

    The function handles edge cases where text might contain raw tokens that resemble control sequences (e.g., <|endoftext|>). By supplying disallowed_special=(), it instructs tiktoken to treat all special tokens as standard text literals rather than raising an error. If text is an empty string, the function returns immediately without incurring encoding overhead.

    log_token_estimation()

    Visibility: Public
    Signature: def log_token_estimation(node_name: str, prompt_content: str, max_tokens: int, token_usage: dict | None = None) -> None:

    Description:
    Performs diagnostic calculations and produces multi-channel logging for token consumption against a designated capacity limit (max_tokens). The function generates two distinct log outputs: 1. Interactive Console Output: Uses ANSI escape sequences (\033[93m yellow color) with multi-line tabbed alignment to print token breakdowns by component. 2. Structured Log File Output: Emits a single-line, pipe-delimited log entry through logger.info designed for log aggregators and parsing scripts.

    Parameters: * node_name (str): Identifier of the executing workflow node or pipeline component. * prompt_content (str): The complete compiled prompt string passed to the LLM. * max_tokens (int): Maximum context window or token limit allocated for the node. * token_usage (dict | None, optional): A dictionary mapping sub-component labels (e.g., "system_prompt", "context") to their specific token counts. Defaults to None.

    Returns: * None

    Raises: * None.

    Example: 

    def log_token_estimation(node_name: str, prompt_content: str, max_tokens: int, token_usage: dict | None = None) -> None:
    token_count = count_tokens(prompt_content)
    percentage = (token_count / max_tokens) * 100 if max_tokens else 0

    # Build token usage string if provided
    usage_str = ""
    usage_log_str = ""
    if token_usage:
        # Find the longest label for alignment
        max_label_len = max(len(label) for label in token_usage)
        lines = []
        log_parts = []
        for label, value in token_usage.items():
            pct = (value / token_count * 100) if token_count else 0
            padded_label = label.ljust(max_label_len)
            lines.append(f"\t{padded_label} : {value:,} ({pct:.0f}%)")
            log_parts.append(f"{label}={value:,} ({pct:.0f}%)")
        usage_str = "\n" + "\n".join(lines)
        usage_log_str = " | " + " | ".join(log_parts)

    # Console output (yellow) with token usage on separate lines
    print(f"\033[93m[Token Analytics] {node_name}: {token_count:,} / {max_tokens:,} tokens ({percentage:.1f}% capacity){usage_str}\033[0m")

    # File log stays single-line for parseability
    logger.info(f"NODE EXEC | node={node_name} | prompt_tokens={token_count:,} / {max_tokens:,} ({percentage:.1f}% capacity){usage_log_str}")

    log_token_estimation calculates the total token count of the prompt via count_tokens and computes capacity utilization relative to max_tokens (protecting against zero division if max_tokens is 0). If sub-component usage details are provided in token_usage, the function calculates the relative percentage of each part against token_count and aligns keys dynamically using ljust. The final console output provides visual feedback for developers, while the structured logger record preserves parseable metrics for auditability.
