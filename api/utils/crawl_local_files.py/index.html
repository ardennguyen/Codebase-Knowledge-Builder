    crawl_local_files.py

    Source: utils/crawl_local_files.py

    Technical Overview

    The crawl_local_files.py module serves as the local filesystem ingestion engine for the Codebase-Knowledge-Builder pipeline. While remote codebase ingestion is delegated to crawl_github_files.py, crawl_local_files.py provides an in-memory extraction pipeline tailored for local directories. It navigates directory trees, applies hierarchical ignore rules, prunes unwanted directory branches early, enforces file size thresholds, decodes text files across heterogeneous character encodings, and streams real-time telemetry back to the user interface.

    Operating directly on the host operating system's virtual file system (VFS), the crawler standardizes file representations across platforms by normalizing path separators and handling character encoding quirks (such as UTF-8 Byte Order Marks). It abstracts away low-level filesystem traversal complexities, returning an ingestion payload structure compatible with downstream analysis modules.

    Key Capabilities and Operational Characteristics

    1. Cascading Hierarchical .gitignore Resolution: The crawler dynamically loads root-level and nested .gitignore files encountered at any directory depth during traversal. It creates isolated pathspec.PathSpec evaluation scopes bound to their originating directory trees, preserving Git's contextual inheritance and override semantics.
    2. Early Subtree Pruning: During directory traversal via os.walk, the module modifies directory collections in-place. If a directory matches ignore rules or exclusion globs, it is pruned immediately, preventing unnecessary recursive traversal into large subtrees such as node_modules, .git, or build artifact directories.
    3. Multi-Stage File Filtering Pipeline: Individual files are evaluated against a strict sequence of filters: scoped .gitignore rule matching, user-defined exclude_patterns, user-defined include_patterns, and filesystem byte size limits (max_file_size).
    4. Resilient Text Ingestion and Encoding Fallback: Files are read using utf-8-sig decoding to automatically strip UTF-8 BOM headers. If decoding fails due to UnicodeDecodeError or ValueError (indicating binary or corrupted assets), the crawler logs the file as skipped without terminating the crawl.
    5. Real-Time Structured Telemetry: Telemetry and progress indicators are emitted through utils.output (emit and get), tracking processed counts, exclusions, file size ceiling violations, and binary skips.

    Module-Level Functions

    _load_gitignore()

    Visibility: Private (_)
    Signature: def _load_gitignore(gitignore_path: str) -> pathspec.PathSpec | None

    Description:
    Attempts to open, read, and compile a .gitignore file located at gitignore_path into an immutable pathspec.PathSpec object using the standard Git wildmatch pattern syntax (gitwildmatch).

    Under the hood, the function opens the target file using the utf-8-sig encoding, which automatically detects and removes any leading UTF-8 Byte Order Marks (BOMs) that might otherwise corrupt pattern parsing on Windows systems. If the file cannot be accessed due to filesystem permissions, OS-level locks, missing files, or corrupt encodings, the function swallows the exception and returns None, ensuring that an unreadable ignore file does not halt the crawling pipeline.

    Parameters: * gitignore_path (str): Absolute or relative filesystem path to the .gitignore file.

    Returns: * pathspec.PathSpec | None: A compiled PathSpec pattern matcher instance if successfully loaded and parsed; otherwise None.

    Raises: * None: All internal exceptions (e.g., IOError, OSError, UnicodeDecodeError) are caught and handled by returning None.

    Example: 

    def _load_gitignore(gitignore_path):
    """Load a .gitignore file and return a PathSpec, or None on failure."""
    try:
        with open(gitignore_path, encoding="utf-8-sig") as f:
            return pathspec.PathSpec.from_lines("gitwildmatch", f.readlines())
    except Exception:
        return None

    The function reads the entire contents of the .gitignore file into a list of strings using f.readlines(). It delegates parsing to pathspec.PathSpec.from_lines("gitwildmatch", ...), which parses comment lines (#), negation markers (!), directory path indicators (/), and glob wildcards (*, **, ?). The resulting PathSpec instance encapsulates the parsed pattern logic, ready for path matching operations.

    _matches_any_gitignore()

    Visibility: Private (_)
    Signature: def _matches_any_gitignore(gitignore_specs: dict[str, pathspec.PathSpec], abs_path: str, is_dir: bool = False) -> bool

    Description:
    Determines whether a given absolute path matches any active .gitignore specification within an arbitrary directory hierarchy. The function maintains Git's directory-scoped matching rules, ensuring that a .gitignore spec only applies to files and directories located within its own subtree.

    The function iterates over the gitignore_specs dictionary (mapping abs_dir_path to its compiled pathspec.PathSpec). For each spec, it computes the relative path of abs_path against abs_dir_path using os.path.relpath. If the relative path starts with .., the target file or directory is outside the scope of that .gitignore and is skipped.

    For targets within scope, Windows backslashes (\) are converted to standard POSIX forward slashes (/). If is_dir is True, a trailing slash (/) is enforced, which allows gitwildmatch to evaluate directory-specific rules (such as build/ matching directories but not files named build). The function returns True upon the first matching spec.

    Parameters: * gitignore_specs (dict[str, pathspec.PathSpec]): Mapping of absolute directory paths to their respective compiled PathSpec pattern instances. * abs_path (str): The absolute path of the candidate file or directory to check. * is_dir (bool, optional): Flag indicating whether abs_path refers to a directory (True) or a file (False). Defaults to False.

    Returns: * bool: True if abs_path matches any active .gitignore rule within its hierarchy; otherwise False.

    Raises: * None: Operates deterministically over in-memory strings and path specs without raising exceptions.

    Example: 

    def _matches_any_gitignore(gitignore_specs, abs_path, is_dir=False):
    """Check if a path matches ANY loaded .gitignore spec.

    Each spec is checked with the path relative to its own .gitignore directory.
    For directories, a trailing '/' is appended for proper gitignore matching.

    Args:
        gitignore_specs: dict of {abs_dir_path: pathspec.PathSpec}
        abs_path: absolute path of the file or directory to check
        is_dir: True if checking a directory
    Returns:
        True if the path matches any gitignore rule
    """
    for gi_dir, spec in gitignore_specs.items():
        rel = os.path.relpath(abs_path, gi_dir)
        # Skip if the path is not under this gitignore's scope
        if rel.startswith(".."):
            continue
        match_path = rel.replace("\\", "/")
        if is_dir:
            match_path = match_path.rstrip("/") + "/"
        if spec.match_file(match_path):
            return True
    return False

    This method implements Git's hierarchical scoping mechanics. By evaluating rel.startswith(".."), it prevents higher-level specs from evaluating upward and ensures that sibling or parent directories do not misapply child .gitignore rules. The directory trailing slash normalization (match_path.rstrip("/") + "/") ensures compatibility with the gitwildmatch standard, where patterns like dist/ specifically require a trailing slash to identify directories.

    crawl_local_files()

    Visibility: Public
    Signature: def crawl_local_files(directory: str, include_patterns: set[str] | None = None, exclude_patterns: set[str] | None = None, max_file_size: int | None = None, use_relative_paths: bool = True) -> dict[str, dict[str, str]]

    Description:
    Executes a filtered traversal of a local filesystem directory, returning an in-memory dictionary of relative file paths mapped to their text contents. It provides a standardized data contract equivalent to remote crawlers such as crawl_github_files.py.

    The crawling lifecycle proceeds through distinct phases: 1. Validation & Initialization: Validates that directory exists and is a directory. Pre-loads the root .gitignore if present and initializes telemetry counters. 2. Directory-Level Pruning: Dynamically loads any nested .gitignore files encountered during os.walk. Evaluates directories against ignore specs and exclude_patterns, modifying the dirs list in-place to prune subtrees immediately. 3. File-Level Filtering: Evaluates each file against .gitignore specs, exclude_patterns, include_patterns, and max_file_size. 4. Content Extraction: Opens qualifying files with utf-8-sig decoding. Skips binary or unreadable files upon encountering UnicodeDecodeError or ValueError. 5. Telemetry Reporting: Emits crawl metrics (processed, excluded, size limit exceeded, non-text) via utils.output.emit.

    Parameters: * directory (str): Target local filesystem path to crawl. * include_patterns (set[str] | None, optional): Set of glob patterns (e.g., {"*.py", "*.ts"}) that files must match to be included. If None or empty, all non-excluded files are accepted. * exclude_patterns (set[str] | None, optional): Set of glob patterns (e.g., {"tests/*", "*.lock"}) to exclude from traversal. * max_file_size (int | None, optional): Maximum allowed file size in bytes. Files exceeding this ceiling are skipped. If None, no size ceiling is enforced. * use_relative_paths (bool, optional): Whether to use paths relative to directory as keys in the returned dictionary (True), or absolute system paths (False). Defaults to True.

    Returns: * dict[str, dict[str, str]]: A dictionary payload containing a "files" dictionary mapping file paths to their decoded string contents: 

    {
    "files": {
        "src/main.py": "import os\n...",
        "README.md": "# Documentation\n..."
    }
}

    Raises: * ValueError: Raised if directory does not exist or is not a valid directory.

    The function begins with defensive validation via os.path.isdir(). It initializes tracking counters and lists for telemetry reporting. Before beginning directory traversal, it checks for a root .gitignore, loading it into gitignore_specs indexed by the absolute path of the root directory. Reason strings for telemetry are resolved up-front via get() to prevent repeated dictionary lookups during deep tree traversals.

    Implementation Walkthrough: Directory Branch Pruning

        # --- Single-pass: walk, filter, and process inline ---
    for root, dirs, files in os.walk(directory):
        abs_root = os.path.abspath(root)

        # Check for nested .gitignore in current directory (skip root, already loaded)
        if abs_root != os.path.abspath(directory):
            nested_gi = os.path.join(root, ".gitignore")
            if os.path.exists(nested_gi):
                spec = _load_gitignore(nested_gi)
                if spec:
                    gitignore_specs[abs_root] = spec

        # --- Directory filtering ---
        excluded_dirs = set()
        for d in sorted(dirs):
            abs_d = os.path.join(abs_root, d)
            dirpath_rel = os.path.relpath(abs_d, directory)

            reason = None
            if _matches_any_gitignore(gitignore_specs, abs_d, is_dir=True):
                reason = reason_gitignore
            elif exclude_patterns:
                for pattern in exclude_patterns:
                    dir_pattern = pattern.removesuffix("/*")
                    if fnmatch.fnmatch(dirpath_rel, dir_pattern) or fnmatch.fnmatch(d, dir_pattern):
                        reason = reason_excluded
                        break

            if reason:
                excluded_dirs.add(d)
                entry_num += 1
                count_excluded += 1
                emit("CRAWL_DIR_EXCLUDED", num=entry_num, path=dirpath_rel, reason=reason)

        for d in dirs.copy():
            if d in excluded_dirs:
                dirs.remove(d)

        # Sort remaining dirs for consistent traversal order
        dirs.sort()

    This block performs in-place directory pruning during os.walk. For each traversed directory, it discovers any nested .gitignore files and registers them within gitignore_specs. It then iterates through the child directory names (dirs), checking each against loaded .gitignore specs and user-defined exclude_patterns (normalizing wildcard suffixes like /*).

    Directories marked for exclusion are pruned in-place by removing them from dirs via dirs.remove(d). This prevents os.walk from descending into those subtrees on subsequent iterations. The remaining directories are sorted to guarantee deterministic, reproducible traversal orders across different operating systems.

    Implementation Walkthrough: File Filtering and Text Extraction

            # --- File processing (inline, sorted) ---
        for filename in sorted(files):
            filepath = os.path.join(root, filename)
            abs_filepath = os.path.abspath(filepath)
            relpath = os.path.relpath(filepath, directory) if use_relative_paths else filepath
            entry_num += 1

            # Check gitignore (all levels)
            if _matches_any_gitignore(gitignore_specs, abs_filepath):
                count_excluded += 1
                emit("CRAWL_FILE_GITIGNORE", num=entry_num, path=relpath)
                continue

            # Check exclude patterns
            excluded = False
            if exclude_patterns:
                for pattern in exclude_patterns:
                    if fnmatch.fnmatch(relpath, pattern):
                        excluded = True
                        break
            if excluded:
                count_excluded += 1
                emit("CRAWL_FILE_EXCLUDED", num=entry_num, path=relpath)
                continue

            # Check include patterns
            if include_patterns:
                matched = False
                for pattern in include_patterns:
                    if fnmatch.fnmatch(relpath, pattern):
                        matched = True
                        break
                if not matched:
                    count_excluded += 1
                    emit("CRAWL_FILE_NOT_INCLUDED", num=entry_num, path=relpath)
                    continue

            # Check size limit
            if max_file_size and os.path.getsize(filepath) > max_file_size:
                count_size_limit += 1
                skipped_size_limit.append(relpath)
                size_kb = os.path.getsize(filepath) / 1024
                emit("CRAWL_FILE_SIZE_LIMIT", num=entry_num, path=relpath, size=f"{size_kb:.0f}")
                continue

            # Try to read as text
            try:
                with open(filepath, encoding="utf-8-sig") as f:
                    content = f.read()
                files_dict[relpath] = content
                count_processed += 1
                emit("CRAWL_FILE_PROCESSED", num=entry_num, path=relpath)
            except (UnicodeDecodeError, ValueError):
                count_non_text += 1
                skipped_non_text.append(relpath)
                emit("CRAWL_FILE_NOT_TEXT", num=entry_num, path=relpath)
            except Exception as e:
                count_non_text += 1
                skipped_non_text.append(relpath)
                emit("CRAWL_FILE_ERROR", num=entry_num, path=relpath, error=e)

    File evaluation proceeds through a sequence of guard conditions. Candidate files are checked against _matches_any_gitignore(), then against glob expressions in exclude_patterns, and then against include_patterns. Files exceeding max_file_size are skipped and tracked in skipped_size_limit.

    Qualifying files are read into memory using open(filepath, encoding="utf-8-sig"). If reading fails due to a UnicodeDecodeError or ValueError, the file is identified as binary or unreadable and recorded in skipped_non_text. Any unexpected filesystem errors (e.g., race-condition permission changes) are caught, emitted as CRAWL_FILE_ERROR, and skipped without crashing the traversal loop.

    Implementation Walkthrough: Summary Telemetry and Return

        # --- Summary ---

    Error Handling and Edge Cases

    Scenario / Condition Handling Mechanism Pipeline Impact
    Non-Existent Target Path os.path.isdir() check raises ValueError immediately. Traversal is aborted before any filesystem operations occur.
    Malformed / Unreadable .gitignore Handled in _load_gitignore() via try...except Exception, which catches the error and returns None. The unreadable ignore file is skipped; traversal continues without applying those specific rules.
    Windows Path Separators (\) Normalized in _matches_any_gitignore() via .replace("\\", "/"). Ensures consistent glob matching against POSIX-based .gitignore specifications across platforms.
    Directory Ignores with Trailing Slash _matches_any_gitignore() appends / when is_dir=True. Complies with gitwildmatch specifications (e.g., build/ matches directories but not files named build).
    Out-of-Scope Nested Ignore Rules Handled via rel.startswith("..") check in _matches_any_gitignore(). Prevents nested .gitignore files from matching paths outside their parent directory tree.
    Binary and Compiled Files Handled in open() block by catching (UnicodeDecodeError, ValueError). The file is skipped, recorded in skipped_non_text, and traversal continues.
    Files Exceeding max_file_size Checked via os.path.getsize(filepath) > max_file_size before opening. Content is not read into memory, preventing memory spikes and token window overflow.
    Filesystem Race Conditions Handled via generic except Exception as e block wrapping file reads. Emits CRAWL_FILE_ERROR with the exception details and continues traversal.

    Performance Characteristics and Resource Management

    1. Memory Complexity: The memory footprint scales with the aggregate size of all ingested text file contents stored in files_dict. Files excluded by pattern or size limits are never read into memory, keeping heap allocation proportional only to valid source files.
    2. I/O Complexity and Subtree Pruning: Modifying the dirs list in-place during os.walk avoids traversing into excluded directory trees entirely (such as .git or node_modules). This eliminates unnecessary stat and read system calls on large subtrees.
    3. Regex and Pattern Caching: pathspec.PathSpec compiles wildmatch expressions into regular expressions upon initialization. Because .gitignore files are parsed once per directory and retained in gitignore_specs, pattern matching operations run efficiently against pre-compiled expressions.
