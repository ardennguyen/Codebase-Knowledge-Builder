    output.py

    Source: utils/output.py

    Following the persistent documentation generation and rendering workflows established in utils/mkdocs.py, utils/output.py provides the foundational operational observability, localized terminal presentation, and structured file logging subsystem for the entire codebase.

    Technical Overview

    The utils/output.py module serves as the centralized communications bridge and presentation gateway across all stages of the documentation pipeline. It decouples core pipeline logic from standard I/O streams, terminal escape styling, and language localization concerns. By formalizing every user-facing message into an external declarative string registry (utils/strings.csv), the module eliminates hardcoded console text and ensures complete internationalization (i18n) across heterogeneous runtime environments.

    Architecturally, the subsystem establishes a dual-destination dispatch pattern that coordinates between ANSI-colored terminal streams (sys.stdout) and persistent, timestamped file-based loggers (logging.FileHandler). To support localized operation without human translation overhead, the module embeds an automated runtime self-localization loop: when configured with a non-English language, it detects untranslated or missing keys in the CSV registry, compiles an ad-hoc translation prompt, queries an external Large Language Model via utils/call_llm.py, and persists the resulting translations back into disk storage with UTF-8 BOM encoding.

    Public API

    init()

    Visibility: Public
    Signature: def init(language="english", use_cache=True, thinking_level=None, debug=False) -> None:

    Description: Initializes the global state of the output subsystem. It resolves the absolute file path of utils/strings.csv, normalizes the user's requested language identifier for column lookups and display names, configures caching and debug flags, loads all static string mappings into memory, and executes automated runtime translation checks for non-English executions. This function must be executed in main.py prior to calling any message emission functions.

    Parameters: * language (str): Target language name (e.g., "english", "Vietnamese"). Case-insensitive; internally normalized to lowercase for column retrieval and capitalized for terminal logs. Defaults to "english". * use_cache (bool): Directs whether automated translation LLM requests should consult and populate the persistent cache managed by utils/call_llm.py. Defaults to True. * thinking_level (str | None): Reasoning effort level passed down to the model provider during translation requests. Defaults to None. * debug (bool): Global debug toggle controlling the suppression or pass-through of debug-gated messages (DBOTH, DSTDOUT, DEBUG). Defaults to False.

    Returns: * None

    Raises: * No exceptions raised directly. File resolution or network exceptions occurring during automated translation are caught, reported, and handled with safe fallback mechanics.

    Example: 

    # Initializing output system with custom language and debug logging
init(language="vietnamese", use_cache=True, thinking_level="low", debug=True)

    The core implementation configures module globals and orchestrates string loading followed by translation:

    def init(language="english", use_cache=True, thinking_level=None, debug=False):
    """Initialize the output system: load strings.csv, set language, auto-translate missing.

    Must be called from main() after parsing CLI arguments but before any emit() calls.

    Args:
        language: Target language name (e.g., "Vietnamese").
        use_cache: Whether LLM caching is enabled (passed to translation calls).
        thinking_level: LLM thinking level (passed to translation calls).
    """
    global _language, _lang_col, _csv_path, _use_cache, _thinking_level, _debug
    _language = language.capitalize()
    _lang_col = language.lower()
    _csv_path = os.path.join(os.path.dirname(os.path.abspath(__file__)), "strings.csv")
    _use_cache = use_cache
    _thinking_level = thinking_level
    _debug = debug
    _load_strings()
    _auto_translate()

    The initialization procedure establishes process-wide singletons within the module namespace. By calculating _csv_path using os.path.abspath(__file__), the system avoids relative path resolution errors when the root execution directory varies across invocations. The dual assignment of _language (via .capitalize()) and _lang_col (via .lower()) ensures that human-readable console banners display proper nouns (e.g., "Vietnamese") while maintaining case-insensitive column queries against the underlying CSV header row.

    emit()

    Visibility: Public
    Signature: def emit(key: str, suffix: str = "", **kwargs: object) -> None:

    Description: Dispatches a localized, styled message to terminal standard output and/or the active file logger based on a symbolic key registered in strings.csv. It retrieves the string template, safely interpolates dynamic keyword arguments via _format_safe(), appends an optional unformatted suffix (e.g., token counters), applies destination and debug filtering rules, wraps the terminal message in ANSI escape codes, and executes logging.

    Parameters: * key (str): The unique identifier matching a STRING_KEY record in strings.csv (e.g., "LLM_CALL_WRITE_CHAPTER"). * suffix (str): Optional plain text appended directly to the formatted text without undergoing template variable substitution. Defaults to "". * **kwargs (object): Arbitrary named parameters matching the {placeholder} tokens declared within the registered message template.

    Returns: * None

    Raises: * No exceptions raised. If an unregistered key is supplied, the method defensively prints a formatted notice [UNKNOWN STRING: {key}] to standard output to prevent application termination while avoiding silent information loss.

    Example: 

    # Emitting a chapter write event with dynamic parameters and token suffix
emit("LLM_CALL_WRITE_CHAPTER", chapter_num=1, name="flow")

    The implementation routes messages according to destinations, debug flags, and color maps:

    def emit(key, suffix="", **kwargs):
    """Emit a translatable string to stdout and/or log file.

    Args:
        key: String key from strings.csv (e.g., "LLM_CALL_WRITE_CHAPTER").
        suffix: Optional extra text appended after the main message (e.g., token breakdown).
        **kwargs: Variables to substitute into the string template.
    """
    entry = _strings.get(key)
    if not entry:
        # Fallback for unknown keys — print raw so nothing is silently lost
        print(f"[UNKNOWN STRING: {key}]")
        return

    text = _format_safe(entry["text"], kwargs)
    if suffix:
        text = text + suffix

    level = entry["level"]
    dest = entry["dest"]

    # D-prefixed destinations (DBOTH, DSTDOUT): debug-gated console output.
    # Without --debug, suppress console but always log. Preserves original color from LEVEL.
    if dest.startswith("D"):
        if _debug:
            dest = dest[1:]  # DBOTH → BOTH, DSTDOUT → STDOUT
        else:
            dest = "LOG"

    color = COLORS.get(level, "")
    reset = RESET if color else ""

    if dest in ("BOTH", "STDOUT"):
        print(f"{color}{text}{reset}")
    if dest in ("BOTH", "LOG"):
        _logger.log(LOG_LEVELS.get(level, logging.INFO), text)

    The function incorporates specialized routing logic for D-prefixed destination specifiers (DBOTH and DSTDOUT). When encountered, the system evaluates the state of _debug. If the pipeline is not running with debug flags enabled, dest is re-routed strictly to "LOG", which silences terminal output while guaranteeing that diagnostic records remain intact within the physical log file. If _debug is enabled, the leading character is stripped (dest = dest[1:]), allowing the message to print to the console while preserving its original severity color mapping defined in COLORS.

    emit_raw()

    Visibility: Public
    Signature: def emit_raw(level: str, text: str, dest: str = "BOTH") -> None:

    Description: Dispatches unmanaged, dynamic, or structurally arbitrary text to the console and/or logger using explicit severity styling. Unlike emit(), this function does not perform lookups against strings.csv and does not apply {placeholder} substitutions. It is designed for variable multi-line payloads, AST crawl summaries, progress bars, and transient tabular diagnostics.

    Parameters: * level (str): The severity level string governing ANSI color codes and Python logging priorities (e.g., "PROGRESS", "SUCCESS", "WARNING", "ERROR", "INFO", "DEBUG", "FILE_WRITE"). * text (str): The fully formatted string content to emit. * dest (str): Target destination stream. Accepts "BOTH", "STDOUT", or "LOG". Defaults to "BOTH".

    Returns: * None

    Raises: * No exceptions raised. Unmapped severity strings fall back to plain uncolored text and default logging.INFO priority.

    Example: 

    # Emitting ad-hoc status information
emit_raw("WARNING", "Custom warning message regarding external API rate limits")
emit_raw("DEBUG", "Skipping binary file during AST walk", dest="LOG")

    The implementation controls ad-hoc console printing and logger dispatch:

    def emit_raw(level, text, dest="BOTH"):
    """Emit a pre-formatted string with explicit level styling.

    Use for dynamic/structural output that doesn't come from strings.csv
    (e.g., numbered file lists, batch details, crawl summary tables).
    """
    # DEBUG-level: suppress console unless --debug is active
    if level == "DEBUG" and not _debug:
        dest = "LOG"

    color = COLORS.get(level, "")
    reset = RESET if color else ""

    if dest in ("BOTH", "STDOUT"):
        print(f"{color}{text}{reset}")
    if dest in ("BOTH", "LOG"):
        _logger.log(LOG_LEVELS.get(level, logging.INFO), text)

    emit_raw() enforces an implicit debug gate when level == "DEBUG". Even if a caller specifies dest="BOTH" or dest="STDOUT", the destination is mutated to "LOG" unless _debug evaluates to True. This prevents verbose crawl traces, chunk distributions, and sub-tree skips from polluting standard execution views while retaining complete fidelity within diagnostic trace files.

    Description: Retrieves a translated string template directly from the in-memory cache, executes variable substitution using provided keyword arguments, and returns the resulting string without emitting anything to terminal streams or log files. This function is designed for generating Markdown content, document headers, navigation labels, and UI strings managed by utils/mkdocs.py.

    Raises: * No exceptions raised. Template interpolation errors are suppressed by _format_safe().

    Example: 

    # Retrieving UI headers for documentation landing pages
tutorial_header = get("UI_TUTORIAL")
index_title = get("UI_INDEX_TITLE", project="Codebase-Knowledge-Builder")

    The implementation resolves the raw template from memory:

    def get(key, **kwargs):
    """Get a translated string without printing or logging.

    Use for UI strings embedded in generated markdown (index.md headings, etc.).
    Returns the raw translated text with variable substitution applied.
    """
    entry = _strings.get(key)
    if not entry:
        return key  # Fallback: return the key itself
    return _format_safe(entry["text"], kwargs)

    The return fallback mechanism ensures downstream document generation nodes never encounter NoneType errors or empty strings when an unexpected translation key is referenced. By returning key verbatim upon lookup misses, the system allows missing configuration references to remain visible directly in generated documentation markdown as obvious diagnostic placeholders.

    configure_logging()

    Visibility: Public
    Signature: def configure_logging(project_name: str = "project", mode: str = "tutorial") -> str:

    Description: Configures dedicated file-based logging for the running process instance. It resolves the output directory (respecting the LOG_DIR environment variable), sanitizes project and execution mode names to eliminate illegal filesystem characters, constructs a unique timestamped filename, flushes existing handlers on _logger, binds a new logging.FileHandler using UTF-8 encoding, and writes initial execution metadata blocks.

    Parameters: * project_name (str): The name of the target repository or codebase under analysis. Defaults to "project". * mode (str): The current pipeline execution mode (e.g., "tutorial", "api-reference", "quickstart"). Defaults to "tutorial".

    Returns: * str: The absolute or normalized filesystem path of the initialized log file.

    Raises: * OSError: If the log directory cannot be created due to filesystem permissions.

    Example: 

    # Initializing run logging from CLI arguments
log_path = configure_logging(project_name="my-org/backend-api", mode="api-reference")
# Resulting log file: logs/my_org_backend_api_api_reference_20250520_143000.log

    The implementation performs path generation, handler registration, and header output:

    def configure_logging(project_name="project", mode="tutorial"):
    """Configure file-based logging for this run.

    Creates a new log file per invocation:
        logs/{project_name}_{mode}_{YYYYMMDD_HHmmss}.log

    Must be called from main() after parsing CLI arguments.
    """
    from datetime import datetime

    log_directory = os.getenv("LOG_DIR", "logs")
    os.makedirs(log_directory, exist_ok=True)

    safe_project = "".join(c if c.isalnum() or c in "-_." else "_" for c in project_name)
    safe_mode = mode.replace("-", "_")
    timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
    log_file = os.path.join(log_directory, f"{safe_project}_{safe_mode}_{timestamp}.log")

    # Remove any existing handlers (e.g., NullHandler) and add the file handler
    _logger.handlers.clear()
    file_handler = logging.FileHandler(log_file, encoding="utf-8")
    file_handler.setFormatter(logging.Formatter("%(asctime)s - %(levelname)s - %(message)s"))
    _logger.addHandler(file_handler)

    # Log run metadata at the start of every log file
    _logger.info(f"{'=' * 80}")
    _logger.info(f"RUN STARTED | project={project_name} | mode={mode} | timestamp={timestamp}")
    _logger.info(f"Log file: {log_file}")
    _logger.info(f"{'=' * 80}")

    return log_file

    Filename sanitization is enforced via a character whitelist: c if c.isalnum() or c in "-_." else "_". This protects Unix and Windows filesystems against invalid characters when repository identifiers contain forward slashes, spaces, or protocol prefixes (e.g., git@github.com:owner/repo.git). By calling _logger.handlers.clear(), the function prevents duplicate log lines from accumulating across iterative unit test invocations or multiple orchestrator runs within the same Python process.

    Internal Helpers

    _format_safe()

    Visibility: Private
    Signature: def _format_safe(template: str, kwargs: dict) -> str:

    Description: Executes string interpolation using Python's standard str.format(**kwargs) protocol while defensively intercepting formatting exceptions. If placeholders within template fail to resolve against keys in kwargs, or if indices are malformed, the raw unformatted template is returned without raising an exception.

    Parameters: * template (str): The source format string containing {placeholder} variables. * kwargs (dict): The mapping of keyword arguments intended for interpolation.

    Returns: * str: The successfully interpolated string, or the unaltered template if an interpolation error occurs.

    Raises: * No exceptions raised internally (KeyError, IndexError, and ValueError are intercepted).

    Example: 

    # Internal call site from emit()
text = _format_safe("Processing chapter {chapter_num}: {name}", {"chapter_num": 1, "name": "Architecture"})
# Fallback on missing keys
fallback_text = _format_safe("Processing chapter {chapter_num}: {name}", {"chapter_num": 1})
# Returns: "Processing chapter {chapter_num}: {name}"

    The underlying implementation relies on a basic guarded block:

    def _format_safe(template, kwargs):
    """Apply .format(**kwargs) with graceful fallback on missing keys."""
    try:
        return template.format(**kwargs)
    except (KeyError, IndexError, ValueError):
        return template

    This helper insulates the application from crashes caused by mismatched placeholder syntax in dynamic LLM-generated translation outputs. If an external model inadvertently translates or drops a variable placeholder (e.g., changing {chapter_num} to {so_chuong}), subsequent emit() operations safely degrade to emitting the raw text rather than terminating pipeline execution with an unhandled KeyError.

    _load_strings()

    Visibility: Private
    Signature: def _load_strings() -> None:

    Description: Parses strings.csv from disk and populates the module's private _strings registry. It parses CSV headers using csv.DictReader configured with utf-8-sig encoding to handle UTF-8 Byte Order Marks (BOM). For every row, it extracts the key, output styling level, dispatch destination, and target language text. If the target language column does not exist or contains an empty string, it falls back to reading the english column.

    Parameters: * None. Operates directly on the module-level state variables _csv_path, _lang_col, _language, and _strings.

    Returns: * None

    Raises: * OSError: If the file path points to an unreadable device, though the function verifies os.path.exists(_csv_path) prior to opening.

    Example: 

    # Executed within init() or after _write_translations_to_csv()
_load_strings()

    The file loading loop processes the CSV records into memory:

    def _load_strings():
    """Load all strings from strings.csv."""
    global _strings
    _strings = {}

    if not _csv_path or not os.path.exists(_csv_path):
        return

    translated_count = 0
    total_count = 0

    with open(_csv_path, encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        for row in reader:
            key = row.get("STRING_KEY", "").strip()
            if not key or key.startswith("#"):
                continue

            level = row.get("LEVEL", "INFO").strip()
            dest = row.get("DEST", "BOTH").strip()

            # Priority: language column → English fallback
            text = row.get(_lang_col, "").strip()
            if text:
                translated_count += 1
            else:
                text = row.get("english", "").strip()

            total_count += 1
            _strings[key] = {"text": text, "level": level, "dest": dest}

    if _lang_col != "english" and translated_count == total_count:
        emit_raw("SUCCESS", f"[i18n] {_language} — loaded {translated_count} strings from CSV")

    The parser ignores empty lines and comments (key.startswith("#")). It tallies translation completeness via translated_count against total_count. If a non-English language is fully localized, it issues an immediate SUCCESS confirmation banner via emit_raw().

    _auto_translate()

    Visibility: Private
    Signature: def _auto_translate() -> None:

    Description: Performs dynamic, batch runtime translation for any strings lacking translations in the active target language column. It inspects the CSV file to compile an inventory of missing keys, constructs a structured prompt referencing prompts/common/translate_strings.md, dispatches the request to utils/call_llm.py, extracts the resulting JSON dictionary via regular expressions, persists the new translations back into strings.csv, and reloads the in-memory string registry.

    Parameters: * None. Reads _lang_col, _language, _csv_path, _use_cache, and _thinking_level.

    Returns: * None

    Raises: * Catches all exceptions internally (Exception), logging a warning and falling back to English.

    Phase 1: Missing Strings Discovery

    The function scans strings.csv to identify whether the target language column exists and aggregates missing entries:

        if _lang_col == "english":
        return

    if not _csv_path or not os.path.exists(_csv_path):
        return

    # Collect strings that have no translation in the target language column
    missing = {}
    is_new_column = False
    with open(_csv_path, encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        fieldnames = list(reader.fieldnames)
        is_new_column = _lang_col not in fieldnames
        for row in reader:
            key = row.get("STRING_KEY", "").strip()
            if not key or key.startswith("#"):
                continue
            # Check if the language column exists and has a value
            lang_text = row.get(_lang_col, "").strip() if _lang_col in fieldnames else ""
            if lang_text:
                continue  # Already translated

            english_text = row.get("english", "").strip()
            if english_text:
                missing[key] = english_text

    if not missing:
        return

    During discovery, the function evaluates reader.fieldnames against _lang_col. If the language has never been used before, is_new_column evaluates to True. The crawler aggregates all non-empty english entries corresponding to unpopulated target language cells into a missing dictionary keyed by STRING_KEY.

    Phase 2: LLM Translation Dispatch and Parsing

    The system loads the translation prompt template, formats the payload as JSON, and invokes the inference provider:

        # Report what we found
    if is_new_column:
        emit_raw("PROGRESS", f"[i18n] New language '{_language}' — adding column to strings.csv")
    emit_raw("PROGRESS", f"[i18n] {len(missing)} strings need translation to {_language}")

    # Batch translate via LLM
    try:
        from utils.call_llm import call_llm

        entries_json = json.dumps(missing, ensure_ascii=False, indent=2)

        # Load prompt template from prompts/common/translate_strings.md
        prompt_path = os.path.join(
            os.path.dirname(os.path.dirname(os.path.abspath(__file__))),
            "prompts",
            "common",
            "translate_strings.md",
        )
        with open(prompt_path, encoding="utf-8") as pf:
            prompt_template = pf.read()
        prompt = prompt_template.format(language=_language, entries=entries_json)

        emit_raw("PROGRESS", f"[i18n] Calling LLM to translate {len(missing)} strings...")
        response = call_llm(prompt, use_cache=_use_cache, thinking_level=_thinking_level)

        # Extract JSON from response
        json_match = re.search(r"\{[^{}]*(?:\{[^{}]*\}[^{}]*)*\}", response, re.DOTALL)
        if json_match:
            translations = json.loads(json_match.group())
            translated_count = len(translations)

            # Write translations back into strings.csv
            _write_translations_to_csv(translations)
            emit_raw("SUCCESS", f"[i18n] Translated {translated_count}/{len(missing)} strings — saved to strings.csv")

            # Reload strings from the updated CSV so all translations are active
            _load_strings()
        else:
            emit_raw("WARNING", "[i18n] LLM response did not contain valid JSON — falling back to English")

    except Exception as e:
        emit_raw("WARNING", f"[i18n] Translation failed: {e} — falling back to English")

    The LLM query uses call_llm() imported dynamically from utils/call_llm.py to avoid circular import dependencies at module load time. The prompt template instructs the model to return a strict JSON dictionary mapping each STRING_KEY to its translated equivalent while keeping format placeholders intact. A nested regular expression (r"\{[^{}]*(?:\{[^{}]*\}[^{}]*)*\}") extracts the JSON block even if the model prefixes or suffixes its response with Markdown fences or explanatory text.

    _write_translations_to_csv()

    Visibility: Private

    Description: Persists newly translated key-value pairs back into strings.csv. If the target language column does not already exist in the CSV header, it appends the new column. It reads all existing rows, mutates rows matching keys present in translations, and rewrites the entire file using utf-8-sig encoding with newline="" to ensure consistent formatting across operating systems and Excel environments.

    Parameters: * translations (dict[str, str]): A dictionary mapping STRING_KEY strings to their corresponding localized translations.

    Returns: * None

    Raises: * OSError: If write permissions are restricted on the target CSV file.

    Example: 

    # Internal invocation from _auto_translate()
_write_translations_to_csv({
    "LLM_CALL_WRITE_CHAPTER": "Đang gọi LLM để viết chương {chapter_num}: {name}...",
    "UI_TUTORIAL": "Hướng dẫn chi tiết"
})

    The file mutation pattern handles column updates and row persistence:

    def _write_translations_to_csv(translations):
    """Write LLM translations back into strings.csv, persisting them for future runs.

    If the target language column doesn't exist, it is added to the CSV.
    """
    rows = []
    fieldnames = None

    with open(_csv_path, encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        fieldnames = list(reader.fieldnames)
        # Add language column if it doesn't exist
        if _lang_col not in fieldnames:
            fieldnames.append(_lang_col)
        for row in reader:
            key = row.get("STRING_KEY", "").strip()
            if key in translations:
                row[_lang_col] = translations[key]
            rows.append(row)

    # Write with BOM so Excel opens as UTF-8 without extra import steps
    with open(_csv_path, "w", encoding="utf-8-sig", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=fieldnames)
        writer.writeheader()
        writer.writerows(rows)

    The CSV rewrite process updates the file atomically by reading all rows into memory, applying translation updates to matching keys, and writing the full dataset back out. Opening with utf-8-sig ensures that modern spreadsheet editors like Microsoft Excel automatically detect UTF-8 encoding without requiring manual CSV import wizard steps.

    Data Structures

    strings.csv Record Schema

    The persistent localization registry stored at utils/strings.csv follows a tabular schema where each record defines a discrete user-facing message, its visual severity styling, its stream routing rules, and localized text across supported languages.

    Field Type Description Example Values
    STRING_KEY str Unique primary key identifying the message across code call sites. Lines starting with # are treated as comments. "LLM_CALL_WRITE_CHAPTER", "UI_TUTORIAL"
    LEVEL str Severity classification mapping to ANSI terminal escape colors and Python logging priorities. "PROGRESS", "SUCCESS", "WARNING", "ERROR", "INFO", "DEBUG", "FILE_WRITE"
    DEST str Output destination policy controlling routing to standard output, file logging, or both. "BOTH", "STDOUT", "LOG", "DBOTH", "DSTDOUT"
    english str Baseline English text template containing optional {placeholder} tokens for interpolation. "Generating chapter {chapter_num}: {name}..."
    <lang_col> str Dynamic column added per target language containing localized translation templates. "Đang tạo chương {chapter_num}: {name}..."

    In-Memory String Registry Cache (_strings)

    The private module-level dictionary _strings holds normalized message configurations parsed from strings.csv during _load_strings().

    Field Type Description
    text str The localized format template string (falling back to English if untranslated).
    level str Severity level string used to resolve colors from COLORS and logging priorities from LOG_LEVELS.
    dest str Output destination flag ("BOTH", "STDOUT", "LOG", "DBOTH", "DSTDOUT"). 
    # Internal shape of _strings entry
{
    "LLM_CALL_WRITE_CHAPTER": {
        "text": "Writing chapter {chapter_num}: {name}...",
        "level": "PROGRESS",
        "dest": "BOTH"
    }
}

    Color Palette Mapping (COLORS)

    The module defines a static mapping between logical severity levels and ANSI color escape sequences.

    Level Identifier ANSI Sequence Display Appearance Intended Operational Semantics
    "PROGRESS" \033[96m Cyan Active LLM queries, multi-file crawl batches, phase milestones.
    "SUCCESS" \033[92m Green Task completions, cache hits, successful artifact writes.
    "WARNING" \033[93m Yellow Token budget alerts, fallback triggers, rate limit warnings.
    "ERROR" \033[91m Red Pipeline failures, unrecoverable API errors, fatal terminations.
    "INFO" "" Standard Terminal Text Informational labels, configuration values, run metadata.
    "DEBUG" \033[90m Dark Gray Skipped files, raw AST metrics, detailed execution traces.
    "FILE_WRITE" "" Standard Terminal Text Indented file write notices (" - Wrote {path}").
    "UI" "" N/A Reserved for Markdown artifacts; never directly printed to console.

    Python Logging Severity Mapping (LOG_LEVELS)

    Translates application-level severity specifiers to standard library logging priorities:

    Level Identifier Python Logger Level Value
    "PROGRESS" logging.INFO 20
    "SUCCESS" logging.INFO 20
    "WARNING" logging.WARNING 30
    "ERROR" logging.ERROR 40
    "INFO" logging.INFO 20
    "DEBUG" logging.DEBUG 10
    "FILE_WRITE" logging.DEBUG 10

    Destination Routing Codes (DEST)

    The DEST column in strings.csv and the dest parameter in emit_raw() govern stream delivery:

    Destination Code Terminal Output (sys.stdout) Disk Logger (logging.FileHandler) Gating Condition
    "BOTH" Yes (ANSI colored) Yes (Plain text) Always active.
    "STDOUT" Yes (ANSI colored) No Always active.
    "LOG" No Yes (Plain text) Always active.
    "DBOTH" Yes (ANSI colored) Yes (Plain text) Gated: Suppressed from stdout unless --debug is specified. Always logged.
    "DSTDOUT" Yes (ANSI colored) No Gated: Suppressed completely unless --debug is specified.

    Error Handling

    Template Variable Substitution Failures

    During template interpolation in _format_safe(), user-supplied arguments may fail to match placeholder tokens defined within strings.csv. This commonly occurs when an LLM auto-translation inadvertently alters placeholder syntax (e.g., modifying {count} to {total}). The helper intercepts KeyError, IndexError, and ValueError, returning the raw template string instead of throwing an exception:

    try:
    return template.format(**kwargs)
except (KeyError, IndexError, ValueError):
    return template

    Missing Registry Key Lookups

    When emit(key) encounters an unrecognized string key, it catches the lookup miss through dictionary inspection:

    entry = _strings.get(key)
if not entry:
    print(f"[UNKNOWN STRING: {key}]")
    return

    This ensures that typos in string keys do not cause fatal runtime crashes, while immediately exposing missing keys in the terminal output for developers to see.

    Automated Translation Fault Tolerance

    Dynamic localization in _auto_translate() is wrapped in a broad exception handler:

    try:
    # LLM translation dispatch, JSON parsing, and disk writes
    ...
except Exception as e:
    emit_raw("WARNING", f"[i18n] Translation failed: {e} — falling back to English")

    If the network connection drops, API credentials fail, or the external model returns invalid JSON, the exception is intercepted. The system issues a WARNING and continues execution using baseline English strings, ensuring that localization issues never disrupt core documentation generation.
