    output.py

    Source: utils/output.py

    Following the generation and layout orchestration of static documentation structures in mkdocs.py, the output.py module serves as the centralized messaging, formatting, logging, and internationalization bridge across the Codebase-Knowledge-Builder architecture. While downstream nodes and utilities compile complex data pipelines, output.py standardizes how system events, diagnostic traces, and user-facing notifications are presented on standard output and recorded within persistent log files.

    Technical Overview

    The output.py module establishes a unified telemetry and logging subsystem designed to decouple console presentation logic from computational pipeline stages. It governs all terminal output by applying semantic ANSI color styling, enforcing selective stream routing, and handling dynamic string localization. Rather than scattering unformatted print() statements across crawler routines or model invocation pipelines, all components interface with output.py to dispatch structured event keys or pre-formatted operational text. This architecture guarantees that console feeds remain clean and readable, while comprehensive execution details are systematically preserved in isolated log files for post-mortem analysis.

    Central to the design of the module is its dynamic localization mechanism, which loads string templates from an external catalog (utils/strings.csv). Messages support variable interpolation through keyword arguments, allowing templates to remain cleanly separated from runtime parameters. If target language strings are missing during initialization, the module interfaces with i18n.py to dynamically translate absent keys via language model inference and update the CSV catalog in-place. Furthermore, the module introduces a fine-grained destination routing model: messages can be directed strictly to the console (STDOUT), written solely to disk (LOG), or broadcast to both (BOTH). It incorporates debug gating mechanisms (DBOTH, DSTDOUT, and the DEBUG level) that automatically suppress verbose diagnostic chatter from standard output unless the user explicitly enables debug mode, ensuring operational logs capture raw context without cluttering the interactive terminal.

    Public API

    init()

    Visibility: Public
    Signature: def init(language="english", use_cache=True, thinking_level=None, debug=False) -> None:

    Description: Initializes the output subsystem by setting runtime language preferences, locating the CSV string catalog, loading in-memory string entries, and orchestrating automated translation for missing keys. It must be called by the application entry point (main.py) immediately following CLI argument parsing and before any messaging functions are invoked.

    Global State Configuration

        global _language, _lang_col, _csv_path, _use_cache, _thinking_level, _debug
    _language = language.capitalize()
    _lang_col = language.lower()
    _csv_path = os.path.join(os.path.dirname(os.path.abspath(__file__)), "strings.csv")
    _use_cache = use_cache
    _thinking_level = thinking_level
    _debug = debug
    This phase populates module-level variables governing display formatting, column lookup keys, and operational flags. The _language attribute stores a capitalized representation used in diagnostic logs, while _lang_col holds the lowercase identifier used for CSV header matching. The absolute file path to strings.csv is constructed dynamically relative to the module's filesystem directory to guarantee resolution regardless of current working directories.

    Catalog Loading and Translation Sync

        _load_strings()
    _auto_translate()
    Once the filesystem paths and runtime parameters are bound to the global scope, _load_strings() reads all string definitions from disk into memory. Immediately following the initial catalog load, _auto_translate() executes to detect if the target language is missing translations for any keys; if discrepancies exist, it bridges to i18n.py to generate them via LLM inference and reloads the catalog.

    Parameters: * language (str): Target language name (e.g., "english", "vietnamese"). Defaults to "english". * use_cache (bool): Flag indicating whether LLM response caching is enabled during dynamic translation. Defaults to True. * thinking_level (Optional[str]): Reasoning effort level allocated to downstream translation requests ("low", "medium", "high", or None). Defaults to None. * debug (bool): Flag indicating whether debug messages and D-prefixed destination outputs should appear in the console. Defaults to False.

    Returns: * None

    Raises: * Does not raise exceptions directly; non-fatal file access or translation errors are caught and handled within internal delegators.

    Example: 

    from utils.output import init as init_output

# Initialize output system with Vietnamese language support and debug logging
init_output(language="vietnamese", use_cache=True, thinking_level="low", debug=True)

    emit()

    Visibility: Public
    Signature: def emit(key, suffix="", **kwargs) -> None:

    Description: Emits a localized string looked up from strings.csv to the console and/or persistent log file based on its configured metadata. It performs safe placeholder interpolation, applies ANSI terminal colors corresponding to the message level, and handles debug-gated console suppression.

    Key Lookup and Variable Interpolation

        entry = _strings.get(key)
    if not entry:
        # Fallback for unknown keys — print raw so nothing is silently lost
        print(f"[UNKNOWN STRING: {key}]")
        return

    text = _format_safe(entry["text"], kwargs)
    if suffix:
        text = text + suffix

    level = entry["level"]
    dest = entry["dest"]
    The routine searches the in-memory _strings catalog using the supplied key. If the key is not present, it prints a diagnostic fallback ([UNKNOWN STRING: ...]) to stdout to prevent silent telemetry omission. If resolved, it executes variable interpolation using _format_safe(), appends an optional text suffix (such as execution timing or token usage profiles), and extracts the target severity level and output dest.

    Debug Gating and Channel Resolution

        # D-prefixed destinations (DBOTH, DSTDOUT): debug-gated console output.
    # Without --debug, suppress console but always log. Preserves original color from LEVEL.
    if dest.startswith("D"):
        if _debug:
            dest = dest[1:]  # DBOTH → BOTH, DSTDOUT → STDOUT
        else:
            dest = "LOG"

    color = COLORS.get(level, "")
    reset = RESET if color else ""
    This phase checks whether the destination string begins with the prefix D (e.g., DBOTH, DSTDOUT), which designates that console presentation is conditional. If _debug is enabled, the prefix is stripped, restoring destination routing to BOTH or STDOUT. If debug mode is inactive, the destination is redirected to LOG, preventing terminal clutter while preserving the full diagnostic event in persistent logs. ANSI escape sequences are retrieved from COLORS based on the message level.

    Standard Output and File Dispatch

        if dest in ("BOTH", "STDOUT"):
        print(f"{color}{text}{reset}")
    if dest in ("BOTH", "LOG"):
        _write_log(level, text)
    In the final phase, the formatted message is dispatched to the designated streams. If dest matches "BOTH" or "STDOUT", the text is wrapped in the resolved ANSI escape codes and printed to standard output. If dest matches "BOTH" or "LOG", the uncolored text and its severity level are forwarded to _write_log() for persistent disk storage.

    Parameters: * key (str): Catalog identifier defined in strings.csv (e.g., "LLM_CALL_WRITE_CHAPTER"). * suffix (str): Optional string appended directly to the end of the formatted message. Defaults to "". * **kwargs (Any): Keyword arguments matching template placeholders (e.g., {chapter_num}, {path}) within the catalog text.

    Returns: * None

    Raises: * Does not raise exceptions; variable interpolation errors are caught within _format_safe().

    Example: 

    from utils.output import emit

# Emit localized step execution notice with variable substitution
emit("LLM_CALL_WRITE_CHAPTER", chapter_num=1, name="flow")

    emit_raw()

    Visibility: Public
    Signature: def emit_raw(level, text, dest="BOTH") -> None:

    Description: Emits an ad-hoc, pre-formatted string to the console and/or persistent log file without consulting the strings.csv catalog. It is intended for dynamic structural elements, batch listings, crawl summary tables, and external telemetry callbacks.

        # DEBUG-level: suppress console unless --debug is active
    if level == "DEBUG" and not _debug:
        dest = "LOG"

    color = COLORS.get(level, "")
    reset = RESET if color else ""

    if dest in ("BOTH", "STDOUT"):
        print(f"{color}{text}{reset}")
    if dest in ("BOTH", "LOG"):
        _write_log(level, text)
    The implementation evaluates the provided severity level. If the level is set to "DEBUG" and global debug mode (_debug) is disabled, the destination route is constrained to "LOG" to suppress terminal chatter. It retrieves the ANSI escape sequence corresponding to level from the COLORS dictionary and wraps the text accordingly when printing to standard output. Finally, if the resolved destination includes "LOG", it delegates the uncolored string to _write_log().

    Parameters: * level (str): Severity classification determining ANSI color formatting ("PROGRESS", "SUCCESS", "WARNING", "ERROR", "INFO", "DEBUG"). * text (str): Raw string content to output. * dest (str): Target routing channel ("BOTH", "STDOUT", or "LOG"). Defaults to "BOTH".

    Returns: * None

    Raises: * Does not raise exceptions.

    Example: 

    from utils.output import emit_raw

# Print pre-formatted warning directly to stdout and log
emit_raw("WARNING", "Custom validation failed for module path: utils/cache.py")

    get()

    Visibility: Public
    Signature: def get(key, **kwargs) -> str:

    Description: Retrieves a translated string template from the catalog and applies variable interpolation without writing to stdout or the log file. This is utilized by downstream generators (such as mkdocs.py) to inject localized labels and headings directly into generated Markdown documents.

        entry = _strings.get(key)
    if not entry:
        return key  # Fallback: return the key itself

    The function looks up key in the global _strings catalog. If the key cannot be found, it gracefully degrades by returning the raw key string. When found, it passes the associated text and variable keyword arguments to _format_safe() to substitute all placeholders and returns the resulting string.

    Parameters: * key (str): Catalog key identifier from strings.csv. * **kwargs (Any): Variable placeholder values to substitute into the template.

    Returns: * str: Localized and interpolated string content, or key if the identifier is absent from the catalog.

    Raises: * Does not raise exceptions.

    Example: 

    from utils.output import get

# Retrieve localized section header for documentation index
tutorial_header = get("UI_TUTORIAL")

    configure_logging()

    Visibility: Public
    Signature: def configure_logging(project_name="project", mode="tutorial") -> str:

    Description: Establishes a dedicated, timestamped file logging stream for the active execution run. It resolves directory storage paths, creates log folders on demand, sanitizes naming parameters, opens an append-mode file handle, and writes an initial execution metadata header.

    Directory Setup and Path Sanitization

        global _log_file

    log_directory = os.getenv("LOG_DIR", "logs")
    os.makedirs(log_directory, exist_ok=True)

    safe_project = "".join(c if c.isalnum() or c in "-_." else "_" for c in project_name)
    safe_mode = mode.replace("-", "_")
    timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
    log_path = os.path.join(log_directory, f"{safe_project}_{safe_mode}_{timestamp}.log")
    This phase determines the target log directory by inspecting the LOG_DIR environment variable, defaulting to "logs" if unset, and creates the directory structure if it does not already exist. To prevent filesystem errors, project_name is filtered to retain only alphanumeric characters and safe punctuation (-, _, .), replacing all other characters with underscores. The operating mode has hyphens normalized to underscores. A file path is then constructed incorporating the project name, execution mode, and current timestamp formatted as YYYYMMDD_HHmmss.

    File Handle Initialization and Header Logging

        # Close any existing log file
    if _log_file is not None:
        _log_file.close()

    _log_file = open(log_path, "a", encoding="utf-8")  # noqa: SIM115

    # Log run metadata at the start of every log file
    sep = "=" * 80
    emit_raw("INFO", sep, dest="LOG")
    emit_raw("INFO", f"RUN STARTED | project={project_name} | mode={mode} | timestamp={timestamp}", dest="LOG")
    emit_raw("INFO", f"Log file: {log_path}", dest="LOG")

    return log_path
    If an open log file handle already exists in the global _log_file variable, it is flushed and closed to prevent descriptor leaks. A new file handle is opened in append mode with explicit utf-8 encoding. The function then dispatches initialization metadata—including an 80-character boundary separator, runtime project properties, execution mode, timestamp, and destination path—directly to the log file via emit_raw(..., dest="LOG"), returning the log path to the caller.

    Parameters: * project_name (str): Identifier of the codebase being analyzed, used to prefix the log filename. Defaults to "project". * mode (str): Execution pipeline mode (e.g., "tutorial", "api-reference"). Defaults to "tutorial".

    Returns: * str: Absolute or relative path to the newly created log file.

    Raises: * OSError: If the log directory cannot be created or permissions prevent opening the log file.

    Example: 

    from utils.output import configure_logging

# Configure logging for repository analysis run
log_file_path = configure_logging(project_name="my_repo", mode="tutorial")

    Internal Helpers

    _write_log()

    Visibility: Private
    Signature: def _write_log(level: str, text: str) -> None:

    Description: Formats and appends a single timestamped log entry to the active log file, ensuring immediate buffer synchronization with the filesystem.

        if _log_file is None:
        return

    ts = datetime.now().strftime("%Y-%m-%d %H:%M:%S,%f")[:-3]
    _log_file.write(f"{ts} - {level} - {text}\n")
    _log_file.flush()
    The helper verifies that _log_file is initialized; if None, the function exits immediately as a no-op. If active, it generates a high-resolution timestamp formatted as YYYY-MM-DD HH:MM:SS,mmm by truncating the microsecond portion to three decimal places. It writes the entry in the standard format {ts} - {level} - {text}\n and immediately invokes .flush() to ensure log persistence even in the event of unexpected process termination.

    Parameters: * level (str): Severity level string (e.g., "INFO", "WARNING", "ERROR"). * text (str): Unformatted plain text message content without ANSI escapes.

    Returns: * None

    Raises: * OSError: If an I/O failure occurs while writing to or flushing the file handle.

    Example: 

    # Internal invocation from emit() or emit_raw()
_write_log("ERROR", "Failed to connect to inference endpoint")

    _format_safe()

    Visibility: Private
    Signature: def _format_safe(template: str, kwargs: dict) -> str:

    Description: Safely interpolates keyword arguments into a template string, catching formatting exceptions to prevent missing or invalid placeholder keys from crashing execution.

        try:
        return template.format(**kwargs)
    except (KeyError, IndexError, ValueError):
        return template
    The helper wraps Python's standard str.format() invocation in a defensive try...except block. If callers provide arguments with mismatched identifiers, unsupplied template variables, or malformed formatting sequences, it intercepts KeyError, IndexError, and ValueError, silently aborting the substitution and returning the unformatted template string.

    Parameters: * template (str): Target string containing {placeholder} variables. * kwargs (dict): Dictionary of keyword arguments to interpolate.

    Returns: * str: Successfully interpolated string, or the raw template if an interpolation exception occurred.

    Raises: * Does not raise exceptions.

    Example: 

    # Internal template formatting
formatted = _format_safe("Processing chapter {num}: {title}", {"num": 1, "title": "Overview"})

    _load_strings()

    Visibility: Private
    Signature: def _load_strings() -> None:

    Description: Reads strings.csv from the filesystem and populates the in-memory _strings catalog, resolving language-specific columns with fallback to English defaults.

    CSV Stream Initialization

        global _strings
    _strings = {}

    if not _csv_path or not os.path.exists(_csv_path):
        return

    translated_count = 0
    total_count = 0
    This phase resets the global _strings dictionary to an empty state. It validates that _csv_path has been defined and that the file physically exists on the disk; if the file is missing, the method aborts gracefully, allowing subsequent emit calls to fall back to unformatted raw key printing. Local tracking counters are initialized to monitor translation coverage.

    Record Parsing and Fallback Resolution

        with open(_csv_path, encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        for row in reader:
            key = row.get("STRING_KEY", "").strip()
            if not key or key.startswith("#"):
                continue

            level = row.get("LEVEL", "INFO").strip()
            dest = row.get("DEST", "BOTH").strip()

            # Priority: language column → English fallback
            text = row.get(_lang_col, "").strip()
            if text:
                translated_count += 1
            else:
                text = row.get("english", "").strip()

            total_count += 1
            _strings[key] = {"text": text, "level": level, "dest": dest}
    The file is opened using utf-8-sig encoding to automatically handle Byte Order Marks (BOM). Utilizing csv.DictReader, each row is inspected for a non-empty STRING_KEY that does not start with a comment prefix (#). The helper extracts the LEVEL and DEST fields with sensible defaults ("INFO" and "BOTH"). It resolves the target message text by prioritizing the column matching _lang_col; if the language column is empty or missing, it falls back to the "english" column. The record is then stored in _strings.

    Telemetry Reporting

        if _lang_col != "english" and translated_count == total_count:
        emit_raw("SUCCESS", f"[i18n] {_language} — loaded {translated_count} strings from CSV")
    Following record parsing, the helper evaluates whether a non-English language was configured. If the count of localized strings matches the total non-commented rows in the catalog, it dispatches an informational success event via emit_raw(), notifying the operator that full translation coverage was loaded from the CSV.

    Parameters: * None

    Returns: * None

    Raises: * OSError: If the CSV exists but cannot be read due to filesystem permission issues.

    Example: 

    # Internal invocation during init() or after translation sync
_load_strings()

    Data Structures

    In-Memory String Entry Record

    The internal dictionary stored within _strings[key] adheres to the following structural contract:

    Field Type Description
    text str Localized message template containing optional {placeholder} tokens.
    level str Message severity category governing ANSI colorization ("PROGRESS", "SUCCESS", etc.).
    dest str Target output stream ("BOTH", "STDOUT", "LOG", "DBOTH", "DSTDOUT", "UI").

    Example In-Memory Instance: 

    {
    "text": "Writing chapter {chapter_num}: {name}...",
    "level": "PROGRESS",
    "dest": "BOTH"
}

    Catalog CSV Storage Schema (strings.csv)

    The persistent tabular schema stored within utils/strings.csv dictates application localization properties:

    Column Type Description Example
    STRING_KEY str Unique uppercase identifier used for lookups. "LLM_CALL_WRITE_CHAPTER"
    LEVEL str Severity mapping to COLORS. "PROGRESS"
    DEST str Output stream destination channel. "BOTH"
    english str Canonical baseline English message template. "Writing chapter {chapter_num}: {name}..."
    <language> str Dynamic target language columns (e.g., vietnamese). "Đang viết chương {chapter_num}: {name}..."

    Terminal ANSI Color Map (COLORS)

    The module defines a static dictionary mapping semantic message levels to 16-color ANSI escape sequences:

    Level Key Escape Code Terminal Display Style
    "PROGRESS" \033[96m Bright Cyan — Active steps, ongoing inference calls.
    "SUCCESS" \033[92m Bright Green — Step completions, cache hits.
    "WARNING" \033[93m Bright Yellow — Non-fatal warnings, threshold capacity alerts.
    "ERROR" \033[91m Bright Red — Operation failures, caught exceptions.
    "INFO" "" Default Terminal Color — Structural counts, labels, metadata.
    "DEBUG" \033[90m Dark Gray — Granular file crawl exclusions, diagnostic info.
    "FILE_WRITE" "" Default Terminal Color — Disk artifact generation notices.
    "UI" "" Default Terminal Color — Strings designated strictly for Markdown.

    Destination Routing Protocol

    The routing of text messages is governed by the dest property configured in the catalog or passed to emit_raw:

    Destination Value Standard Output (Console) Persistent Log File Debug Gating Logic
    "STDOUT" Yes (ANSI colored) No None.
    "LOG" No Yes (Plain text) None.
    "BOTH" Yes (ANSI colored) Yes (Plain text) None.
    "DSTDOUT" Conditional No Suppressed unless --debug is active.
    "DBOTH" Conditional Yes (Plain text) Console suppressed unless --debug is active; always logged.
    "UI" No No Never printed or logged; retrieved solely via get().

    Log Record Output Schema

    Entries appended to physical log files via _write_log() adhere to the following deterministic format:

    YYYY-MM-DD HH:MM:SS,mmm - LEVEL - MESSAGE_CONTENT
    Component Format / Type Description
    Timestamp YYYY-MM-DD HH:MM:SS,mmm High-resolution wall-clock timestamp with millisecond precision.
    Level str Operational severity level (INFO, PROGRESS, WARNING, ERROR, etc.).
    Message str Sanitized message content stripped of ANSI escape sequences.

    Example Raw Log Output: 

    2025-02-15 10:14:22,104 - INFO - ================================================================================
2025-02-15 10:14:22,105 - INFO - RUN STARTED | project=my_repo | mode=tutorial | timestamp=20250215_101422
2025-02-15 10:14:22,105 - INFO - Log file: logs/my_repo_tutorial_20250215_101422.log
2025-02-15 10:14:23,450 - PROGRESS - Writing chapter 1: architecture...
2025-02-15 10:14:28,812 - SUCCESS - Completed chapter 1 in 5.36s

    Error Handling

    Safe Variable Substitution

    String templates in strings.csv rely on standard Python string formatting expressions ({name}, {path}). Runtime mismatches between provided keyword arguments and expected template variables could trigger uncaught exceptions. The _format_safe() function guards every format call:

        try:
        return template.format(**kwargs)
    except (KeyError, IndexError, ValueError):
        return template
    If an unmapped key or mismatched token index is encountered, the exception is swallowed and the raw template is preserved, guaranteeing that the logging framework never causes catastrophic application halts.

    Key Resolution Degradation

    When emit() or get() is invoked with a key that does not exist in strings.csv, the module provides defensive fallbacks: * In emit(), missing keys bypass formatting and print [UNKNOWN STRING: {key}] to console stdout, ensuring missing catalog definitions are immediately obvious to developers without throwing an uncaught KeyError. * In get(), missing keys cause the function to return the literal key string directly, permitting Markdown synthesis pipelines to proceed with fallback headers.

    CSV Absence and File IO Resilience

    During _load_strings(), the existence of strings.csv is explicitly verified via os.path.exists(). If the file is missing (such as during minimal testing or headless utility execution), _strings remains an empty dictionary, and the application degrades gracefully to raw key outputs without crashing.

    Stream Flushing and Process Safety

    The persistent logging subsystem enforces operational durability by calling _log_file.flush() immediately after every line write. This prevents data loss in operating system write buffers should the host application crash, encounter a SIGINT, or trigger an unhandled exception in an upstream inference pipeline.

    Circular Import Isolation

    Because output.py is the fundamental telemetry utility used across all modules (including call_llm.py), importing i18n.py at module level would cause circular dependencies, as i18n.py requires call_llm.py and output.emit_raw. The module isolates this dependency by deferring the import of auto_translate to the internal body of _auto_translate().
