    output.py

    Source: utils/output.py

    Following the static-site generation and artifact serialization services documented in utils/mkdocs.py, the utils/output.py module provides the foundational telemetry, console formatting, and logging infrastructure utilized across the entire project. While mkdocs.py converts processed abstractions into persistent web documentation, output.py drives the interactive user experience, diagnostic logging, and localized CLI messaging for every stage of pipeline execution.

    Technical Overview

    The output.py module acts as the centralized console presentation and filesystem logging subsystem for the Codebase-Knowledge-Builder engine. It provides a structured mechanism to emit operational updates, warnings, errors, progress indicators, and debug traces across standard output (sys.stdout) and persistent run-specific log files. Terminal output is stylized using standard ANSI escape sequences mapped to semantic logging levels (PROGRESS, SUCCESS, WARNING, ERROR, INFO, DEBUG, and FILE_WRITE).

    A core architectural capability of the module is its dynamic internationalization (i18n) layer. Instead of hardcoding user-facing strings into pipeline routines, message templates are maintained in an external comma-separated values database (utils/strings.csv). Upon initialization, output.py loads strings for the requested target language, falling back gracefully to English if specific translations are absent. When untranslated keys are encountered in non-English execution modes, the module interfaces with utils/i18n.py to trigger automated LLM translations and persist the updated catalog back to disk.

    The module also handles cross-platform stream encoding issues. On non-interactive or redirected Windows environments (such as CI/CD runners or background processes), standard output and error streams frequently default to legacy ANSI code pages (e.g., cp1252), resulting in UnicodeEncodeError exceptions when rendering multi-byte UTF-8 character sets. output.py proactively detects non-TTY streams and reconfigures them to standard UTF-8 with character replacement fallback strategies.

    emit()

    Visibility: Public
    Signature: def emit(key: str, suffix: str = "", **kwargs: object) -> None

    Description: Emits a localized, template-driven message to configured output sinks (standard output, disk log file, or both). The function queries the loaded string registry using the provided key. If found, it interpolates dynamic variables supplied in kwargs, appends any optional suffix, applies ANSI color coding according to the entry's severity level, and routes the message according to its destination policy. If the key is not present in the catalog, a fallback notification is printed to standard output to prevent silent telemetry loss.

    Parameters: * key (str): Symbolic identifier defined in utils/strings.csv (e.g., "LLM_CALL_WRITE_CHAPTER"). * suffix (str): Optional plain text string appended to the formatted template output (e.g., token usage breakdowns). Defaults to "". * **kwargs (object): Arbitrary keyword arguments used for variable substitution within {placeholder} tokens in the template.

    Returns: * None

    Raises: * No exceptions raised; formatting errors and missing keys are handled gracefully.

    Example: 

    # Real usage from utils/output.py docstring:
emit("LLM_CALL_WRITE_CHAPTER", chapter_num=1, name="flow")

    Implementation logic: 

    def emit(key, suffix="", **kwargs):
    entry = _strings.get(key)
    if not entry:
        # Fallback for unknown keys — print raw so nothing is silently lost
        print(f"[UNKNOWN STRING: {key}]")
        return

    text = _format_safe(entry["text"], kwargs)
    if suffix:
        text = text + suffix

    level = entry["level"]
    dest = entry["dest"]

    # D-prefixed destinations (DBOTH, DSTDOUT): debug-gated console output.
    # Without --debug, suppress console but always log. Preserves original color from LEVEL.
    if dest.startswith("D"):
        if _debug:
            dest = dest[1:]  # DBOTH → BOTH, DSTDOUT → STDOUT
        else:
            dest = "LOG"

    color = COLORS.get(level, "")
    reset = RESET if color else ""

    if dest in ("BOTH", "STDOUT"):
        print(f"{color}{text}{reset}")
    if dest in ("BOTH", "LOG"):
        _write_log(level, text)
    The dispatch mechanism evaluates whether the resolved destination incorporates a debug gate (prefixed with "D", such as "DBOTH" or "DSTDOUT"). When running without the --debug flag active, these destinations are rewritten to "LOG", suppressing terminal chatter while guaranteeing complete audit traces on disk. If the message destination includes terminal targets ("BOTH" or "STDOUT"), standard ANSI color prefixes and reset terminators are wrapped around the text before passing to Python's built-in print.

    emit_raw()

    Visibility: Public
    Signature: def emit_raw(level: str, text: str, dest: str = "BOTH") -> None

    Description: Renders and logs dynamic or structural text directly without consulting the localization catalog. This is the primary output function for un-templated content generated at runtime, such as file tree visualizations, markdown diffs, batch processing summaries, and horizontal dividing rules. It formats the output with appropriate ANSI color codes corresponding to the specified level and directs output to the selected destination sinks.

    Parameters: * level (str): Severity or semantic styling identifier (e.g., "PROGRESS", "SUCCESS", "WARNING", "ERROR", "INFO", "DEBUG"). * text (str): Pre-formatted string payload to output. * dest (str): Output target routing specifier. Accepts "BOTH", "STDOUT", or "LOG". Defaults to "BOTH".

    Returns: * None

    Raises: * No exceptions raised.

    Example: 

    # Real usage from utils/output.py docstring:
emit_raw("WARNING", "Custom message")

    Implementation logic: 

    def emit_raw(level, text, dest="BOTH"):
    # DEBUG-level: suppress console unless --debug is active
    if level == "DEBUG" and not _debug:
        dest = "LOG"

    color = COLORS.get(level, "")
    reset = RESET if color else ""

    if dest in ("BOTH", "STDOUT"):
        print(f"{color}{text}{reset}")
    if dest in ("BOTH", "LOG"):
        _write_log(level, text)
    emit_raw enforces an explicit safeguard for DEBUG-level records: if --debug is not enabled in the runtime configuration, the destination is automatically coerced to "LOG". Color styling is resolved dynamically via dictionary lookup against COLORS. If the resolved color string is non-empty, a trailing ANSI reset sequence (\033[0m) is appended to prevent terminal color leakage.

    configure_logging()

    Visibility: Public
    Signature: def configure_logging(project_name: str = "project", mode: str = "tutorial") -> str

    Description: Configures and initializes disk-based audit logging for the current pipeline run. The function ensures the target log directory exists, sanitizes the project and mode identifiers to create safe filenames, closes any previously active log file handle, and creates a timestamped log file. It also writes standard execution metadata headers into the log file.

    Parameters: * project_name (str): Name of the repository or project under analysis. Defaults to "project". * mode (str): Active operational mode of the pipeline (e.g., "tutorial", "api-reference"). Defaults to "tutorial".

    Returns: * str: The absolute or normalized relative path to the newly opened log file (e.g., "logs/my_project_tutorial_20250101_120000.log").

    Raises: * OSError: If the directory specified by LOG_DIR cannot be created or file creation fails due to filesystem permissions.

    Example: 

    # Configuring logging in main.py startup:
log_path = configure_logging(project_name="Codebase-Knowledge-Builder", mode="tutorial")

    Implementation logic: 

    def configure_logging(project_name="project", mode="tutorial"):
    global _log_file

    log_directory = os.getenv("LOG_DIR", "logs")
    os.makedirs(log_directory, exist_ok=True)

    safe_project = "".join(c if c.isalnum() or c in "-_." else "_" for c in project_name)
    safe_mode = mode.replace("-", "_")
    timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
    log_path = os.path.join(log_directory, f"{safe_project}_{safe_mode}_{timestamp}.log")

    # Close any existing log file
    if _log_file is not None:
        _log_file.close()

    _log_file = open(log_path, "a", encoding="utf-8")  # noqa: SIM115

    # Log run metadata at the start of every log file
    sep = "=" * 80
    emit_raw("INFO", sep, dest="LOG")
    emit_raw("INFO", f"RUN STARTED | project={project_name} | mode={mode} | timestamp={timestamp}", dest="LOG")
    emit_raw("INFO", f"Log file: {log_path}", dest="LOG")

    return log_path
    Filename generation sanitizes input strings by replacing any non-alphanumeric character (excluding hyphens, underscores, and dots) with an underscore. The log stream is opened in append mode with explicit UTF-8 encoding. Immediately following initialization, standard audit metadata—including run mode, project name, timestamp, and delimiter bars—is written directly to the file stream via emit_raw(..., dest="LOG").

    Internal Helpers

    _write_log()

    Visibility: Private
    Signature: def _write_log(level: str, text: str) -> None

    Description: Formats and writes a timestamped record to the active disk log file. If file-based logging has not been initialized via configure_logging(), the operation silently terminates without error. Written lines are formatted with microsecond precision truncated to milliseconds and flushed immediately to prevent buffer loss during system crashes.

    Parameters: * level (str): Semantic severity string associated with the log record. * text (str): Formatted log message payload.

    Returns: * None

    Raises: * OSError: If writing to the file descriptor fails at the operating system level.

    Example: 

    # Internal call site within emit():
_write_log(level, text)

    Implementation logic: 

    def _write_log(level, text):
    if _log_file is None:
        return

    ts = datetime.now().strftime("%Y-%m-%d %H:%M:%S,%f")[:-3]
    _log_file.write(f"{ts} - {level} - {text}\n")
    _log_file.flush()
    Timestamps are formatted according to the standard ISO-like structure YYYY-MM-DD HH:MM:SS,mmm by slicing the last three characters off the microsecond string. Calling _log_file.flush() after every write operation guarantees that log entries are synchronized to the underlying storage device immediately, protecting execution traces against sudden process termination.

    _ensure_utf8_streams()

    Visibility: Private
    Signature: def _ensure_utf8_streams() -> None

    Description: Inspects standard output (sys.stdout) and standard error (sys.stderr) streams to identify non-UTF-8 encodings when running in non-interactive (piped or redirected) environments. On operating systems such as Windows, redirected streams often default to legacy code pages (e.g., cp1252), which fail to encode localized text (such as Vietnamese or CJK characters) and raise UnicodeEncodeError. This function reconfigures active streams to use UTF-8 with character replacement on failure.

    Parameters: * None

    Returns: * None

    Raises: * No exceptions raised.

    Example: 

    # Invoked internally during subsystem startup:
_ensure_utf8_streams()

    Implementation logic: 

    def _ensure_utf8_streams():
    for stream in (sys.stdout, sys.stderr):
        encoding = (getattr(stream, "encoding", "") or "").lower().replace("-", "")
        if hasattr(stream, "reconfigure") and encoding != "utf8" and not stream.isatty():
            stream.reconfigure(encoding="utf-8", errors="replace")
    The routine loops over both standard output and error descriptors. It normalizes the reported stream encoding string by stripping hyphens and converting to lowercase. If Python's stream reconfiguration interface (reconfigure) is supported, the stream encoding is not already UTF-8, and isatty() evaluates to False (indicating redirected output), it calls stream.reconfigure(encoding="utf-8", errors="replace") to prevent runtime encoding failures.

    _load_strings()

    Visibility: Private
    Signature: def _load_strings() -> None

    Description: Parses utils/strings.csv using csv.DictReader and populates the in-memory string catalog _strings. The parser strips whitespace, skips comments (lines starting with #) and empty keys, and resolves the target language string with fallback to English. It also tracks the total count of loaded keys versus translated keys for localization diagnostics.

    Parameters: * None

    Returns: * None

    Raises: * OSError: If the CSV file cannot be opened due to filesystem permission constraints.

    Example: 

    # Invoked internally during init() and after auto-translation:
_load_strings()

    Implementation logic: 

    def _load_strings():
    global _strings
    _strings = {}

    if not _csv_path or not os.path.exists(_csv_path):
        return

    translated_count = 0
    total_count = 0

    with open(_csv_path, encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        for row in reader:
            key = row.get("STRING_KEY", "").strip()
            if not key or key.startswith("#"):
                continue

            level = row.get("LEVEL", "INFO").strip()
            dest = row.get("DEST", "BOTH").strip()

            # Priority: language column → English fallback
            text = row.get(_lang_col, "").strip()
            if text:
                translated_count += 1
            else:
                text = row.get("english", "").strip()

            total_count += 1
            _strings[key] = {"text": text, "level": level, "dest": dest}

    if _lang_col != "english" and translated_count == total_count:
        emit_raw("SUCCESS", f"[i18n] {_language} — loaded {translated_count} strings from CSV")
    The routine opens the CSV catalog utilizing utf-8-sig encoding, ensuring that Byte Order Marks (BOM) inserted by external editing tools (such as Microsoft Excel) are stripped cleanly. For each row, the helper resolves the active message string by first inspecting the configured language column (_lang_col); if empty, it falls back to the baseline "english" column. When a non-English catalog is completely translated, a success notification is emitted to standard output.

    def _auto_translate():

    Data Structures

    ANSI Color Palette (COLORS)

    The module maintains a mapping of semantic message classifications to terminal ANSI escape sequences.

    Level Identifier Escape Sequence Target Display Color Semantic Usage Context
    "PROGRESS" "\033[96m" Cyan LLM API requests, active processing steps
    "SUCCESS" "\033[92m" Green Step completions, cache hits, successful exports
    "WARNING" "\033[93m" Yellow Rate warnings, truncation events, non-fatal errors
    "ERROR" "\033[91m" Red Execution failures, critical model refusals
    "INFO" "" Default Terminal Color Configuration parameters, file counts, standard labels
    "DEBUG" "\033[90m" Gray Skipped files, diagnostic token dumps
    "FILE_WRITE" "" Default Terminal Color File generation confirmations (- Wrote {path})
    "UI" "" Default Terminal Color Reserved for markdown documentation rendering

    In-Memory String Entry (_strings Value Schema)

    When strings.csv is parsed, each valid record is stored in the _strings dictionary using its STRING_KEY as the lookup key.

    Field Name Type Description
    text str Message template string with optional {placeholder} tokens for parameter interpolation.
    level str Semantic severity identifier mapping into COLORS (e.g., "PROGRESS", "INFO").
    dest str Routing sink specifier: "BOTH", "STDOUT", "LOG", "DBOTH", or "DSTDOUT". 
    # Sample in-memory catalog entry:
{
    "LLM_CALL_WRITE_CHAPTER": {
        "text": "[LLM] Writing Chapter {chapter_num}: {name}...",
        "level": "PROGRESS",
        "dest": "BOTH",
    }
}

    Localization File Schema (strings.csv)

    The tabular CSV structure maintained on disk defining system-wide localized strings.

    Column Header Required Description
    STRING_KEY Yes Unique string identifier (e.g., "LLM_CALL_WRITE_CHAPTER", "UI_TUTORIAL"). Lines starting with # are ignored as comments.
    LEVEL Yes Semantic logging level specifying the ANSI color mapping (INFO, PROGRESS, WARNING, ERROR, DEBUG, FILE_WRITE, UI).
    DEST Yes Output destination routing (BOTH, STDOUT, LOG, DBOTH, DSTDOUT).
    english Yes Baseline canonical English translation and formatting template.
    <lang_col> No Dynamic columns representing additional target languages (e.g., vietnamese, japanese).

    Module Runtime State

    The internal runtime configuration state maintained across the lifecycle of the process.

    Variable Name Type Initial Value Description

    _language str "English" Display-formatted target language name (e.g., "Vietnamese").

    Message STRING The plain text message payload (ANSI color codes are excluded).

    Error Handling

    String Formatting Fault Isolation

    Variable substitution in user-facing strings is handled through _format_safe(). If a template defines invalid format tokens, references positional indices that are missing, or encounters mismatched dictionary keys, the resulting KeyError, IndexError, or ValueError is caught. Instead of propagating an unhandled exception that would crash an in-flight documentation build, _format_safe() returns the raw template string.

    Missing Catalog Keys

    If an emit(key) call requests a key that does not exist in strings.csv, output.py avoids raising a KeyError. It prints [UNKNOWN STRING: {key}] directly to sys.stdout. Similarly, get(key) returns the raw key string. This approach ensures missing translation keys do not abort execution while surfacing clear visual notices to developers.

    Non-Interactive Windows Encoding Safeguards

    On Windows environments, non-TTY redirected streams (e.g., standard output redirected to a file or piped to another process) default to legacy ANSI code pages (such as Windows-1252). Emitting multi-byte UTF-8 characters under these conditions raises a terminal UnicodeEncodeError. _ensure_utf8_streams() detects non-TTY streams and reconfigures them using stream.reconfigure(encoding="utf-8", errors="replace"). This ensures Unicode characters can be output safely, replacing un-encodable bytes with replacement characters rather than terminating the process.

    File Handle Lifecycle and Teardown

    To prevent file descriptor leaks and lost disk writes, configure_logging() explicitly closes any previously active log handle before opening a new one. The shutdown() function is designed to be invoked within finally blocks at the entry point of the application (main.py), ensuring that buffered output lines are flushed to disk even in the event of unexpected pipeline terminations.
