    output.py

    Source: utils/output.py

    Following the static exclusion definitions established in exclude_patterns.py, the output.py module provides the centralized output, console telemetry, multi-channel event logging, and dynamic internationalization (i18n) infrastructure for the Codebase-Knowledge-Builder architecture. It serves as the unified interface through which all workflow components communicate operational state, progress telemetry, warnings, and error diagnostics to human operators via styled terminal output and persistent file-based logs.

    The module manages string localization via a dynamic dictionary backed by an external CSV store (utils/strings.csv). When non-English execution modes are requested, output.py integrates directly with the LLM inference pipeline in call_llm.py to automatically translate missing localized strings on demand, persisting new translations back to disk for subsequent runs.

    Architecture and Execution Flows

    The output system operates as a hybrid console renderer and structured logging sink. It exposes methods for template-based internationalized message dispatching (emit), unformatted styled output (emit_raw), and non-logging UI string extraction (get).

    Module Constants and Global State

    The module defines global state variables and static mapping dictionaries that govern console colorization, Python logging severity mappings, active language selection, and in-memory string caching.

    COLORS

    • Type: dict[str, str]
    • Description: Maps symbolic message levels to ANSI escape color codes for standard output terminal styling:
    • "PROGRESS": "\033[96m" (Cyan) — Used for active execution phases, crawler milestones, and LLM inference calls.
    • "SUCCESS": "\033[92m" (Green) — Used for completions, cache hits, and generated document writes.
    • "WARNING": "\033[93m" (Yellow) — Used for non-fatal execution anomalies, context capacity alerts, and retry notices.
    • "ERROR": "\033[91m" (Red) — Used for system failures, network timeouts, and unrecoverable pipeline exceptions.
    • "INFO": "" (Plain terminal default) — Used for baseline parameters, run configurations, and counts.
    • "DEBUG": "\033[90m" (Gray) — Used for excluded file notifications, verbose telemetry, and AST node parsing dumps.
    • "FILE_WRITE": "" (Plain) — Reserved for document creation lines (e.g., " - Wrote {path}").
    • "UI": "" (N/A) — Reserved for markdown document generation headers; never directly printed to stdout.

    RESET

    • Type: str
    • Value: "\033[0m"
    • Description: ANSI escape sequence used to reset terminal color formatting back to default after printing a colored message segment.

    LOG_LEVELS

    • Type: dict[str, int]
    • Description: Maps symbolic message severity levels to native Python logging module levels:
    • "PROGRESS" $\rightarrow$ logging.INFO
    • "SUCCESS" $\rightarrow$ logging.INFO
    • "WARNING" $\rightarrow$ logging.WARNING
    • "ERROR" $\rightarrow$ logging.ERROR
    • "INFO" $\rightarrow$ logging.INFO
    • "DEBUG" $\rightarrow$ logging.DEBUG
    • "FILE_WRITE" $\rightarrow$ logging.DEBUG

    Internal State Variables

    • _strings (dict): Module-level lookup table storing loaded translation entries. Structured as {key: {"text": str, "level": str, "dest": str}}.
    • _language (str): Capitalized display name of the active target language (e.g., "English", "Vietnamese").
    • _lang_col (str): Lowercase column name matching the header row inside strings.csv (e.g., "english", "vietnamese").
    • _logger (logging.Logger): Dedicated logger instance named "llm_logger". Initialized as a root utility logger and configured by configure_logging().
    • _csv_path (str | None): Absolute filesystem path resolving to utils/strings.csv.
    • _use_cache (bool): Global boolean indicating whether LLM caching is active during auto-translation inference cycles.
    • _thinking_level (str | int | None): Reasoning effort level passed downstream to call_llm.py when executing auto-translation prompts.

    Module-Level Functions

    init()

    Visibility: Public
    Signature: def init(language="english", use_cache=True, thinking_level=None) -> None:

    Description:
    Initializes the output utility subsystem. It resolves the absolute path to utils/strings.csv, sets the module-level target language configurations, stores inference runtime flags (use_cache, thinking_level), loads all translation records into memory via _load_strings(), and triggers on-demand translation for missing localization entries via _auto_translate(). This function must be executed in the initialization phase of main.py prior to executing any string emissions.

    Parameters: * language (str, optional): Target localization language name (e.g., "english", "vietnamese"). Defaults to "english". * use_cache (bool, optional): Boolean flag dictating whether LLM prompt responses during translation should be cached on disk. Defaults to True. * thinking_level (str | int | None, optional): Reasoning effort parameter configured for the translation model call. Defaults to None.

    Returns: * None

    Raises: * No exceptions are raised directly; underlying file or translation errors degrade gracefully to English fallbacks with warning emissions.

    Example: 

    # Sourced from utils/output.py implementation
def init(language="english", use_cache=True, thinking_level=None):
    global _language, _lang_col, _csv_path, _use_cache, _thinking_level
    _language = language.capitalize()
    _lang_col = language.lower()
    _csv_path = os.path.join(os.path.dirname(os.path.abspath(__file__)), "strings.csv")
    _use_cache = use_cache
    _thinking_level = thinking_level
    _load_strings()
    _auto_translate()

    The init() function establishes the runtime state required for all downstream logging and terminal output. By computing _csv_path relative to __file__, it guarantees correct file resolution regardless of the current working directory from which the CLI is executed. The transition to _load_strings() populates the memory cache immediately, while _auto_translate() ensures that any missing keys in non-English modes are synthesized before subsequent workflow nodes attempt to look them up.

    emit()

    Visibility: Public
    Signature: def emit(key: str, suffix: str = "", **kwargs) -> None:

    Description:
    Emits an internationalized, template-interpolated string identified by key to standard console output and/or the file logger. It looks up the translation record from the internal _strings table, performs safe keyword placeholder substitution via _format_safe(), appends an optional unformatted suffix, resolves ANSI color styling according to the string's configured level, and routes the formatted text to the configured destination ("STDOUT", "LOG", or "BOTH"). If key is missing from the translation catalog, a raw fallback notice ([UNKNOWN STRING: {key}]) is printed to stdout to ensure telemetry is never silently dropped.

    Parameters: * key (str): Unique string identifier defined in strings.csv (e.g., "LLM_CALL_WRITE_CHAPTER"). * suffix (str, optional): Unformatted trailing text appended to the interpolated message (e.g., execution durations or token breakdown statistics). Defaults to "". * **kwargs (Any): Arbitrary keyword arguments substituted into the {placeholder} variables defined within the localized string template.

    Returns: * None

    Raises: * No exceptions raised. Key lookup failures and format exceptions degrade safely to stdout fallback messages or unformatted raw strings.

    Example: 

    # Sourced from utils/output.py implementation
def emit(key, suffix="", **kwargs):
    entry = _strings.get(key)
    if not entry:
        # Fallback for unknown keys — print raw so nothing is silently lost
        print(f"[UNKNOWN STRING: {key}]")
        return

    text = _format_safe(entry["text"], kwargs)
    if suffix:
        text = text + suffix

    level = entry["level"]
    dest = entry["dest"]
    color = COLORS.get(level, "")
    reset = RESET if color else ""

    if dest in ("BOTH", "STDOUT"):
        print(f"{color}{text}{reset}")
    if dest in ("BOTH", "LOG"):
        _logger.log(LOG_LEVELS.get(level, logging.INFO), text)

    The emit() function serves as the standard telemetry dispatch point for all orchestrators, including flow.py and nodes.py. Destination checking evaluates the string's dest attribute loaded from CSV: messages marked STDOUT bypass the file logger, messages marked LOG bypass terminal output, and messages marked BOTH are dispatched simultaneously to both sinks. The terminal stream receives ANSI color-coded text wrapped in RESET escapes, whereas the file logger receives clean, unescaped text to maintain log readability.

    emit_raw()

    Visibility: Public
    Signature: def emit_raw(level: str, text: str, dest: str = "BOTH") -> None:

    Description:
    Dispatches dynamic, pre-formatted, or structurally arbitrary strings directly to standard output and the file logger without performing a template lookup in strings.csv. This is used for dynamically generated data that cannot be statically enumerated in a localization CSV, such as numbered file listing trees, batch progress breakdowns, crawl summary tables, and raw LLM error alerts.

    Parameters: * level (str): Symbolic severity level (e.g., "PROGRESS", "SUCCESS", "WARNING", "ERROR", "INFO", "DEBUG", "FILE_WRITE") determining ANSI color styling and Python log level mapping. * text (str): Pre-formatted string payload to output. * dest (str, optional): Target dispatch destination. Valid options are "BOTH", "STDOUT", or "LOG". Defaults to "BOTH".

    Returns: * None

    Raises: * No exceptions raised.

    Example: 

    # Sourced from utils/output.py implementation
def emit_raw(level, text, dest="BOTH"):
    color = COLORS.get(level, "")
    reset = RESET if color else ""

    if dest in ("BOTH", "STDOUT"):
        print(f"{color}{text}{reset}")
    if dest in ("BOTH", "LOG"):
        _logger.log(LOG_LEVELS.get(level, logging.INFO), text)

    emit_raw() provides a bypass for the i18n lookup engine while retaining unified ANSI color-coding and file logging synchronization. Crawlers such as crawl_github_files.py and crawl_local_files.py invoke this function to stream discovered file paths, size warnings, and API rate limit pauses directly to the operator console while ensuring that all output is mirrored to the active session log file.

    get()

    Visibility: Public
    Signature: def get(key: str, **kwargs) -> str:

    Description:
    Retrieves an internationalized string with keyword variable substitution applied, without printing to standard output or writing to the logger. This function is designed for generating markdown documentation content, synthesizing table-of-contents headings, and creating section labels inside generated artifacts (such as index.md and chapter documentation). If the specified key is not present in _strings, the key string itself is returned as a safe fallback.

    Parameters: * key (str): Unique string identifier defined in strings.csv (e.g., "UI_TUTORIAL", "UI_OVERVIEW"). * **kwargs (Any): Named variables to interpolate into the resolved template string.

    Returns: * str: Localized and interpolated string ready for embedding into documentation.

    Raises: * No exceptions raised.

    Example: 

    # Sourced from utils/output.py implementation
def get(key, **kwargs):
    entry = _strings.get(key)
    if not entry:
        return key  # Fallback: return the key itself
    return _format_safe(entry["text"], kwargs)

    get() is utilized within document generation nodes (e.g., in nodes.py) where localized structural headings and markdown UI labels are written into the final repository knowledge base. Because entries designated for UI documentation often have their level set to "UI" in strings.csv, get() extracts the clean text without triggering console side-effects or contaminating execution logs.

    configure_logging()

    Visibility: Public
    Signature: def configure_logging(project_name: str = "project", mode: str = "tutorial") -> str:

    Description:
    Initializes and binds a persistent, timestamped file handler to the module-level _logger ("llm_logger"). It resolves the target logging directory from the LOG_DIR environment variable (defaulting to logs/), ensures the target directory exists on disk, sanitizes project_name and mode into filesystem-safe strings, and constructs a filename adhering to the pattern logs/{safe_project}_{safe_mode}_{YYYYMMDD_HHmmss}.log. Any pre-existing handlers bound to _logger (such as default NullHandler instances) are purged before attaching a UTF-8 encoded logging.FileHandler. The function writes a structured initialization banner containing execution metadata before returning the resolved log path.

    Parameters: * project_name (str, optional): Identifier of the target repository or codebase being indexed. Defaults to "project". * mode (str, optional): Active synthesis mode (e.g., "tutorial", "deep-dive", "quickstart"). Defaults to "tutorial".

    Returns: * str: Absolute or relative filesystem path to the initialized .log file.

    Raises: * OSError: If log directory creation or file handle allocation fails due to disk permission constraints.

    Example: 

    # Sourced from utils/output.py implementation
def configure_logging(project_name="project", mode="tutorial"):
    from datetime import datetime

    log_directory = os.getenv("LOG_DIR", "logs")
    os.makedirs(log_directory, exist_ok=True)

    safe_project = "".join(c if c.isalnum() or c in "-_." else "_" for c in project_name)
    safe_mode = mode.replace("-", "_")
    timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
    log_file = os.path.join(log_directory, f"{safe_project}_{safe_mode}_{timestamp}.log")

    # Remove any existing handlers (e.g., NullHandler) and add the file handler
    _logger.handlers.clear()
    file_handler = logging.FileHandler(log_file, encoding="utf-8")
    file_handler.setFormatter(logging.Formatter("%(asctime)s - %(levelname)s - %(message)s"))
    _logger.addHandler(file_handler)

    # Log run metadata at the start of every log file
    _logger.info(f"{'=' * 80}")
    _logger.info(f"RUN STARTED | project={project_name} | mode={mode} | timestamp={timestamp}")
    _logger.info(f"Log file: {log_file}")
    _logger.info(f"{'=' * 80}")

    return log_file

    configure_logging() coordinates execution session traceability. It cleanses input project names using character-filtering comprehensions that replace non-alphanumeric characters (excluding -, _, and .) with underscores, preventing invalid path generation across Windows and POSIX filesystems. By establishing a dedicated log file per run and resetting existing handlers via _logger.handlers.clear(), it prevents duplicate log message propagation when multiple pipeline runs execute within the same process.

    _format_safe()

    Visibility: Private
    Signature: def _format_safe(template: str, kwargs: dict) -> str:

    Description:
    Applies standard Python string format interpolation (str.format(**kwargs)) against a template string while catching formatting-related exceptions. If a template references a placeholder key not supplied in kwargs, or if an indexing or type conversion error occurs during interpolation, the function catches KeyError, IndexError, and ValueError and returns the unformatted template verbatim rather than crashing the pipeline.

    Parameters: * template (str): String containing optional {key} substitution placeholders. * kwargs (dict): Dictionary of keyword arguments to interpolate into the template.

    Returns: * str: The successfully formatted string, or the original template string if formatting fails.

    Raises: * No exceptions raised; all format syntax and parameter mismatch exceptions are intercepted internally.

    Example: 

    # Sourced from utils/output.py implementation
def _format_safe(template, kwargs):
    """Apply .format(**kwargs) with graceful fallback on missing keys."""
    try:
        return template.format(**kwargs)
    except (KeyError, IndexError, ValueError):
        return template

    _format_safe() provides defensive boundary protection against runtime formatting errors. In complex multi-language environments, translations generated by LLMs may occasionally distort placeholder brackets (e.g., outputting {0} or omitting a variable name). By intercepting (KeyError, IndexError, ValueError), this helper ensures that downstream display calls never raise unhandled exceptions due to malformed localization strings.

    _load_strings()

    Visibility: Private
    Signature: def _load_strings() -> None:

    Description:
    Reads and parses the localization catalog from utils/strings.csv into the internal _strings dictionary cache. The file is opened with utf-8-sig encoding to handle UTF-8 Byte Order Marks transparently. The parser skips blank lines and comment rows prefixed with #. For each valid row, it extracts STRING_KEY, LEVEL (defaulting to INFO), DEST (defaulting to BOTH), and the localized string text. The text extraction prioritizes the target language column (_lang_col); if the target column is missing or empty, it falls back to the "english" column. When all strings for a non-English language are successfully loaded, a success notification is dispatched via emit_raw().

    Parameters: * None

    Returns: * None

    Raises: * FileNotFoundError / PermissionError: Handled gracefully by returning early if _csv_path does not exist on disk.

    Example: 

    # Sourced from utils/output.py implementation
def _load_strings():
    global _strings
    _strings = {}

    if not _csv_path or not os.path.exists(_csv_path):
        return

    translated_count = 0
    total_count = 0

    with open(_csv_path, encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        for row in reader:
            key = row.get("STRING_KEY", "").strip()
            if not key or key.startswith("#"):
                continue

            level = row.get("LEVEL", "INFO").strip()
            dest = row.get("DEST", "BOTH").strip()

            # Priority: language column → English fallback
            text = row.get(_lang_col, "").strip()
            if text:
                translated_count += 1
            else:
                text = row.get("english", "").strip()

            total_count += 1
            _strings[key] = {"text": text, "level": level, "dest": dest}
// ...

    _load_strings() populates the lookup dictionary that powers both emit() and get(). By utilizing csv.DictReader, it accesses columns dynamically via field names. The fallback mechanism guarantees that the application remains fully functional even if a translation file is only partially localized, ensuring that unlocalized strings default to English rather than causing execution errors.

    _auto_translate()

    Visibility: Private
    Signature: def _auto_translate() -> None:

    Description:
    Scans strings.csv for strings missing translations in the active target language column (_lang_col). If missing entries are detected, it constructs a batch JSON payload mapping string keys to their English reference texts. It loads the translation prompt template from prompts/common/translate_strings.md, formats the prompt with the target language and JSON payload, and calls the LLM inference client via call_llm.py. The function uses regular expressions to extract the JSON response object from the LLM output, writes the newly synthesized translations back to disk via _write_translations_to_csv(), and invokes _load_strings() to refresh the active memory cache.

    Parameters: * None

    Returns: * None

    Raises: * Intercepts all generic Exception instances during LLM communication, file reading, or JSON decoding, emitting a WARNING and falling back to English strings.

    Example: 

    # Sourced from utils/output.py implementation
def _auto_translate():
    if _lang_col == "english":
        return

    if not _csv_path or not os.path.exists(_csv_path):
        return

    # Collect strings that have no translation in the target language column
    missing = {}
    is_new_column = False
    with open(_csv_path, encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        fieldnames = list(reader.fieldnames)
        is_new_column = _lang_col not in fieldnames
        for row in reader:
            key = row.get("STRING_KEY", "").strip()
            if not key or key.startswith("#"):
                continue
            lang_text = row.get(_lang_col, "").strip() if _lang_col in fieldnames else ""
            if lang_text:
                continue

            english_text = row.get("english", "").strip()
            if english_text:
                missing[key] = english_text

    if not missing:
        return
// ...

    _auto_translate() provides automated internationalization. If a user runs the system with --language Vietnamese or --language Japanese and new keys have been added to the codebase in English, this function identifies the missing keys, batches them into a single inference request, and updates the local CSV file automatically. The dynamic import from utils.call_llm import call_llm inside the function body avoids circular import dependencies at module load time.

    _write_translations_to_csv()

    Visibility: Private
    Signature: def _write_translations_to_csv(translations: dict[str, str]) -> None:

    Description:
    Persists newly translated string key-value pairs back to utils/strings.csv. It reads the entire CSV file into memory, checks if the target language column header (_lang_col) exists in fieldnames (appending it if missing), updates each matching row with the new translation, and writes the entire dataset back to disk. The output file is written with utf-8-sig encoding to ensure compatibility with Microsoft Excel and other CSV editors that rely on a Byte Order Mark for UTF-8 detection.

    Parameters: * translations (dict[str, str]): Dictionary mapping STRING_KEY strings to their newly translated text values.

    Returns: * None

    Raises: * OSError: If writing to _csv_path fails due to filesystem permission issues.

    Example: 

    # Sourced from utils/output.py implementation
def _write_translations_to_csv(translations):
    rows = []
    fieldnames = None

    with open(_csv_path, encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        fieldnames = list(reader.fieldnames)
        # Add language column if it doesn't exist
        if _lang_col not in fieldnames:
            fieldnames.append(_lang_col)
        for row in reader:
            key = row.get("STRING_KEY", "").strip()
            if key in translations:
                row[_lang_col] = translations[key]
            rows.append(row)

    # Write with BOM so Excel opens as UTF-8 without extra import steps
    with open(_csv_path, "w", encoding="utf-8-sig", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=fieldnames)
        writer.writeheader()
        writer.writerows(rows)

    _write_translations_to_csv() handles schema migration and persistence for translation data. When a new language is requested, the function dynamically alters the CSV column structure by appending _lang_col to fieldnames and populating the corresponding cells. By writing back to disk using csv.DictWriter with newline="", it maintains consistent line endings across operating systems.

    Error Handling and Edge Cases

    Scenario Subroutine Handling Strategy
    Missing Translation Key emit() Prints [UNKNOWN STRING: {key}] directly to stdout; does not throw KeyError.
    Missing Translation Key get() Returns the raw key string back to the caller for safe rendering.
    Template Variable Mismatch _format_safe() Catches (KeyError, IndexError, ValueError) and returns the unformatted template verbatim.
    Missing strings.csv File _load_strings() Returns immediately without populating _strings; subsequent emit() calls fall back to unknown key handling.
    New Language Column _auto_translate() Detects missing header in fieldnames, requests LLM translations, and expands CSV columns dynamically.
    Malformed LLM Translation Output _auto_translate() Employs regex pattern matching to extract JSON; if no valid JSON structure is found, emits a WARNING and falls back to English.
    Translation Network/API Failure _auto_translate() Wraps inference invocation in a broad try...except Exception block, reporting the failure via emit_raw("WARNING", ...) and falling back to English.
    Invalid Characters in Project Name configure_logging() Replaces non-alphanumeric characters with underscores using isalnum() filtering to ensure safe log filenames.
