    output.py

    Source: utils/output.py

    Technical Overview

    The utils/output.py module provides a centralized, internationalized output and logging subsystem for the Codebase-Knowledge-Builder architecture. It orchestrates user-facing diagnostic output across interactive terminal streams (sys.stdout, sys.stderr) and persistent timestamped disk logs (logs/*.log). The module decouples runtime reporting from hardcoded English strings by loading message templates, output verbosity levels, and routing destinations dynamically from utils/strings.csv. It supports runtime variable interpolation, ANSI color formatting, debug-gated stream routing, and automatic multi-language backfilling via asynchronous LLM translation calls.

    To ensure deterministic execution across heterogeneous runtime environments, the module implements proactive stream encoding normalization, reconfiguring non-interactive Windows standard output streams to UTF-8 to prevent character encoding exceptions during multi-language processing. Prior to log file initialization, early pipeline events—such as authentication preflights, configuration checks, and translation updates—are intercepted and retained in an in-memory ring buffer (_pending_log). Once the active log file is configured, this buffer is atomically flushed to disk.

    Public API

    COLORS

    Visibility: Public Signature: COLORS = { ... }

    Description: Module-level mapping linking discrete operational logging levels (PROGRESS, SUCCESS, WARNING, ERROR, INFO, DEBUG, FILE_WRITE, UI) to standard ANSI 16-color escape sequences.

    COLORS = {
    "PROGRESS": "\033[96m",  # Cyan — LLM calls, active steps
    "SUCCESS": "\033[92m",  # Green — completions, cache hits
    "WARNING": "\033[93m",  # Yellow — warnings, capacity alerts
    "ERROR": "\033[91m",  # Red — errors, failures
    "INFO": "",  # Plain — config, counts, labels
    "DEBUG": "\033[90m",  # Gray — skipped files, debug
    "FILE_WRITE": "",  # Plain — "  - Wrote {path}" messages
    "UI": "",  # N/A — used in generated docs, never printed
}

    The COLORS dictionary defines visual hierarchy across terminal outputs. Active operational steps and LLM dispatches use high-intensity cyan, while success indicators and cache reconciliations are colored green. Warning and error conditions trigger yellow and red highlights respectively. Informational labels, documentation writes, and UI markdown strings remain uncolored to maintain clean piping.

    RESET

    Visibility: Public Signature: RESET = "\033[0m"

    Description: The standard ANSI reset sequence used to terminate active terminal color formatting and return standard output streams to default terminal styling.

    RESET = "\033[0m"

    This constant is conditionally concatenated to the end of colored log messages whenever COLORS.get(level) yields a non-empty string. It guarantees that subsequent console output retains default terminal styling across interactive shells.

    PENDING_LOG_MAX_LINES

    Visibility: Public Signature: PENDING_LOG_MAX_LINES = 5_000

    Description: The maximum upper boundary for the in-memory log buffer (_pending_log) before physical log file instantiation.

    PENDING_LOG_MAX_LINES = 5_000

    PENDING_LOG_MAX_LINES defines a bounded memory guard preventing unbounded growth of unpersisted log messages during pre-execution phases. When pipeline initialization runs without active disk file handlers, oldest lines are dropped using FIFO eviction once this threshold is crossed.

    def init(language="english", use_cache=True, thinking_level=None, debug=False, auto_translate=True):
    """Initialize the output system: load strings.csv, set language, auto-translate missing.

    Must be called from main() after parsing CLI arguments but before any emit() calls.

    Args:
        language: Target language name (e.g., "Vietnamese").
        use_cache: Whether LLM caching is enabled (passed to translation calls).
        thinking_level: LLM thinking level (passed to translation calls).
        auto_translate: Translate missing strings now. main() passes False and calls
            translate_missing_strings() after argument validation and the LLM auth preflight,
            because translation is itself an LLM call.
    """
    global _language, _lang_col, _csv_path, _use_cache, _thinking_level, _debug
    _language = language.capitalize()
    _lang_col = language.lower()
    _csv_path = os.path.join(os.path.dirname(os.path.abspath(__file__)), "strings.csv")
    _use_cache = use_cache
    _thinking_level = thinking_level
    _debug = debug
    _ensure_utf8_streams()
    _load_strings()
    if auto_translate:
        _auto_translate()

    The initialization routine configures the global module state. It normalizes language identifiers into capitalized presentation labels (_language) and lowercase column headers (_lang_col). It computes the absolute path to strings.csv, saves LLM translation parameters, invokes UTF-8 terminal encoding verification, and parses the CSV into memory. If auto_translate is set to True, it initiates translation of missing localized strings before returning control to the caller.

    emit()

    Visibility: Public Signature: def emit(key, suffix="", **kwargs):

    Description: Retrieves a localized template by key from the in-memory translation table, interpolates runtime keyword variables, applies ANSI color styling, and dispatches formatted output to designated targets (terminal, log file, or both).

    Parameters: * key (str): Unique string identifier corresponding to a STRING_KEY in strings.csv. * suffix (str): Optional string appended to the formatted template text prior to terminal emission or file logging. Defaults to "". * **kwargs (Any): Keyword substitutions mapped to placeholders within the message template.

    Returns: * None

    Raises: * None. Unrecognized keys trigger a defensive console fallback message without interrupting program flow.

    Example: 

    # Usage from source code docstring
emit("LLM_CALL_WRITE_CHAPTER", chapter_num=1, name="flow")


    def emit(key, suffix="", **kwargs):
    """Emit a translatable string to stdout and/or log file.

    Args:
        key: String key from strings.csv (e.g., "LLM_CALL_WRITE_CHAPTER").
        suffix: Optional extra text appended after the main message (e.g., token breakdown).
        **kwargs: Variables to substitute into the string template.
    """
    entry = _strings.get(key)
    if not entry:
        # Fallback for unknown keys — print raw so nothing is silently lost
        print(f"[UNKNOWN STRING: {key}]")
        return

    text = _format_safe(entry["text"], kwargs)
    if suffix:
        text = text + suffix

    level = entry["level"]
    dest = entry["dest"]

    # D-prefixed destinations (DBOTH, DSTDOUT): debug-gated console output.
    # Without --debug, suppress console but always log. Preserves original color from LEVEL.
    if dest.startswith("D"):
        if _debug:
            dest = dest[1:]  # DBOTH → BOTH, DSTDOUT → STDOUT
        else:
            dest = "LOG"

    color = COLORS.get(level, "")
    reset = RESET if color else ""

    if dest in ("BOTH", "STDOUT"):
        print(f"{color}{text}{reset}")
    if dest in ("BOTH", "LOG"):
        _write_log(level, text)

    The emit function coordinates message retrieval, formatting, and routing. When an unknown key is encountered, it logs an [UNKNOWN STRING: {key}] notice to sys.stdout and exits cleanly. For valid entries, dynamic parameters are interpolated using _format_safe, and the optional suffix is appended. Destinations with a D prefix (DBOTH, DSTDOUT) are evaluated against _debug: if debugging is disabled, console output is suppressed and the destination becomes LOG. Finally, messages routed to BOTH or STDOUT are printed with ANSI styling, while destinations matching BOTH or LOG are passed to _write_log.

    def emit_raw(level, text, dest="BOTH"):
    """Emit a pre-formatted string with explicit level styling.

    Use for dynamic/structural output that doesn't come from strings.csv
    (e.g., numbered file lists, batch details, crawl summary tables).
    """
    # DEBUG-level: suppress console unless --debug is active
    if level == "DEBUG" and not _debug:
        dest = "LOG"

    color = COLORS.get(level, "")
    reset = RESET if color else ""

    if dest in ("BOTH", "STDOUT"):
        print(f"{color}{text}{reset}")
    if dest in ("BOTH", "LOG"):
        _write_log(level, text)

    emit_raw outputs dynamic and structural payloads that cannot be defined as static templates in strings.csv, such as file trees, batch tables, and crawling summaries. It checks if the specified level is "DEBUG": when debugging is disabled, console dispatch is silenced by forcing dest = "LOG". The text is styled using the ANSI escape codes mapped in COLORS and routed to the requested targets.

    def configure_logging(project_name="project", mode="tutorial"):
    """Configure file-based logging for this run.

    Creates a new log file per invocation:
        logs/{project_name}_{mode}_{YYYYMMDD_HHmmss}.log

    Must be called from main() after parsing CLI arguments.
    """
    global _log_file

    log_directory = os.getenv("LOG_DIR", "logs")
    os.makedirs(log_directory, exist_ok=True)

    safe_project = "".join(c if c.isalnum() or c in "-_." else "_" for c in project_name)
    safe_mode = mode.replace("-", "_")
    timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
    log_path = os.path.join(log_directory, f"{safe_project}_{safe_mode}_{timestamp}.log")

    # Close any existing log file
    if _log_file is not None:
        _log_file.close()

    _log_file = open(log_path, "a", encoding="utf-8")  # noqa: SIM115

    # Log run metadata at the start of every log file
    sep = "=" * 80
    emit_raw("INFO", sep, dest="LOG")
    emit_raw("INFO", f"RUN STARTED | project={project_name} | mode={mode} | timestamp={timestamp}", dest="LOG")
    emit_raw("INFO", f"Log file: {log_path}", dest="LOG")
    if _pending_log:
        _log_file.write("".join(_pending_log))
        _log_file.flush()
        _pending_log.clear()

    return log_path

    configure_logging initializes the file-based logging system. It resolves the output directory using the LOG_DIR environment variable (defaulting to "logs") and creates the directory if needed. Project and mode strings are sanitized to prevent invalid path characters, and a timestamped filename is generated. Any open log handles are closed before opening the new file with UTF-8 encoding. Initial header metadata is written directly to the log, and any pre-configuration messages stored in _pending_log are written to disk and flushed, clearing the buffer.

    def _write_log(level, text):
    """Write a timestamped line to the log file (buffered until configure_logging opens it)."""
    ts = datetime.now().strftime("%Y-%m-%d %H:%M:%S,%f")[:-3]
    line = f"{ts} - {level} - {text}\n"
    if _log_file is None:
        _pending_log.append(line)
        if len(_pending_log) > PENDING_LOG_MAX_LINES:
            del _pending_log[0]
        return
    _log_file.write(line)
    _log_file.flush()

    _write_log handles file logging operations. It formats log entries with a millisecond timestamp (YYYY-MM-DD HH:MM:SS,mmm), the logging level, and the message text. If _log_file is uninitialized, the entry is appended to _pending_log. When _pending_log exceeds PENDING_LOG_MAX_LINES (5,000 entries), the oldest entry is removed via FIFO eviction. Once _log_file is active, entries are written directly to disk and flushed immediately.

    Parameters: * None

    Raises: * None.

    # Internal invocation within init()

    def _ensure_utf8_streams():
    """Write UTF-8 when stdout/stderr are piped or redirected.

    On Windows a redirected stream uses the ANSI code page (e.g. cp1252) and any
    non-English CLI string (Vietnamese, CJK, ...) raises UnicodeEncodeError. Interactive
    consoles already use UTF-8 (PEP 528), so only non-TTY streams are reconfigured.
    """
    for stream in (sys.stdout, sys.stderr):
        encoding = (getattr(stream, "encoding", "") or "").lower().replace("-", "")
        if hasattr(stream, "reconfigure") and encoding != "utf8" and not stream.isatty():
            stream.reconfigure(encoding="utf-8", errors="replace")

    _ensure_utf8_streams guards against stream encoding failures when output is piped or redirected on platforms like Windows, where non-interactive streams may default to legacy ANSI code pages (such as cp1252). It iterates over sys.stdout and sys.stderr, inspecting their declared encodings. If a stream is not a TTY terminal and its encoding is not UTF-8, it calls reconfigure(encoding="utf-8", errors="replace") to prevent UnicodeEncodeError exceptions when outputting localized or non-ASCII characters.

    Description: Interpolates keyword variables into a template string, returning the raw template unmodified if substitution fails due to mismatched or missing keys.

    Parameters: * template (str): Template string containing {placeholder} variables. * kwargs (dict): Dictionary of keyword arguments to substitute.

    def _format_safe(template, kwargs):
    """Apply .format(**kwargs) with graceful fallback on missing keys."""
    try:
        return template.format(**kwargs)
    except (KeyError, IndexError, ValueError):
        return template

    _format_safe wraps Python's standard str.format() in a fail-soft boundary. If the template contains malformed brace patterns or references keys not present in kwargs, it catches KeyError, IndexError, and ValueError and returns the unformatted template string. This prevents formatting errors from interrupting pipeline execution.

    Description: Parses strings.csv into the internal _strings cache, selecting localized column values when available and falling back to English defaults.

    Parameters: * None

    Returns: * None

    Example: 

    # Invoked during init() and after auto-translation updates

    def _load_strings():
    """Load all strings from strings.csv."""
    global _strings
    _strings = {}

    if not _csv_path or not os.path.exists(_csv_path):
        return

    translated_count = 0
    total_count = 0

    with open(_csv_path, encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        for row in reader:
            key = row.get("STRING_KEY", "").strip()
            if not key or key.startswith("#"):
                continue

            level = row.get("LEVEL", "INFO").strip()
            dest = row.get("DEST", "BOTH").strip()

            # Priority: language column → English fallback
            text = row.get(_lang_col, "").strip()
            if text:
                translated_count += 1
            else:
                text = row.get("english", "").strip()

            total_count += 1
            _strings[key] = {"text": text, "level": level, "dest": dest}

    if _lang_col != "english" and translated_count == total_count:
        emit_raw("SUCCESS", f"[i18n] {_language} — loaded {translated_count} strings from CSV")

    _load_strings reads strings.csv using the utf-8-sig encoding to handle optional Byte Order Marks. It iterates over the CSV rows using csv.DictReader, skipping blank lines and comments prefixed with #. For each entry, it parses LEVEL and DEST, then checks the column for the active language (_lang_col); if empty, it falls back to the "english" column. The parsed record is stored in _strings. When a non-English language is fully translated, it emits a SUCCESS message confirming that all strings were loaded.

    def _auto_translate():
    """Auto-translate missing strings via LLM and write back into strings.csv."""
    from utils.i18n import auto_translate

    if auto_translate(_lang_col, _language, _csv_path, _use_cache, _thinking_level):
        # Reload strings from the updated CSV so all translations are active
        _load_strings()

    _auto_translate handles missing string translations. To avoid circular imports between output.py and call_llm.py, it imports auto_translate locally within the function body. It passes the current language identifiers, CSV filesystem path, caching preferences, and reasoning effort configuration. If auto_translate returns True (indicating that new translations were written to disk), _auto_translate invokes _load_strings() to refresh the in-memory cache with the new translations.

    Data Structures

    In-Memory String Entry Shape

    Represents the structural value schema stored for each key inside the _strings dictionary:

    Field Type Description Example
    text str The localized or fallback English string template, with optional {name} format tokens. "Writing chapter {chapter_num}: {name}..."
    level str Operational logging severity level matching keys in COLORS. "PROGRESS"
    dest str Destination identifier determining whether output routes to terminal, log file, or both. "BOTH"

    strings.csv Record Layout

    Defines the schema expected when parsing entries from utils/strings.csv:

    Column Presence Description
    STRING_KEY Mandatory Unique programmatic string identifier queried by emit() and get(). Rows starting with # are treated as comments.
    LEVEL Mandatory Logging severity tier (PROGRESS, SUCCESS, WARNING, ERROR, INFO, DEBUG, FILE_WRITE, UI).
    DEST Mandatory Target routing channel (BOTH, STDOUT, LOG, DBOTH, DSTDOUT, UI).
    english Mandatory The canonical English fallback text template.
    <lang_col> Dynamic One or more dynamic language columns (e.g., vietnamese, japanese) matched against _lang_col.

    Destination Routing Codes

    Routing behavior for strings emitted via emit and emit_raw:

    Destination Code Console Output (STDOUT) File Logging (LOG) Debug Behavior
    BOTH Yes Yes Unconditionally active
    STDOUT Yes No Unconditionally active
    LOG No Yes Unconditionally active
    DBOTH Conditional Yes Emits to BOTH if --debug is active; otherwise routes to LOG only
    DSTDOUT Conditional No Emits to STDOUT if --debug is active; otherwise discarded
    UI No No Never printed or logged; reserved for get() calls in markdown documents

    Error Handling

    • Missing Translation Template Keys: If emit(key) is invoked with an unknown identifier, it avoids raising KeyError by printing a fallback message ([UNKNOWN STRING: {key}]) directly to sys.stdout. Similarly, get(key) returns the un-interpolated key string itself.
    • Variable Interpolation Errors: In _format_safe, string template substitution catches KeyError, IndexError, and ValueError. If placeholders do not match the provided keyword arguments, the unformatted template is returned intact rather than raising an exception.
    • Redirected Stream Encoding Collisions: On Windows systems, non-TTY streams (such as redirected files or pipes) can cause UnicodeEncodeError when emitting non-ASCII characters. The private helper _ensure_utf8_streams inspects sys.stdout and sys.stderr and reconfigures them to utf-8 with replacement error handling (errors="replace").
    • Early Run Buffer Eviction: Log messages generated before configure_logging() initializes a file handle are stored in _pending_log. If this list exceeds PENDING_LOG_MAX_LINES (5,000 lines), the oldest lines are dropped using FIFO eviction to prevent unbounded memory growth.
    • Path Sanitization in File Logging: In configure_logging, the project_name parameter is sanitized by filtering out any characters that are not alphanumeric, hyphens, underscores, or periods. The mode parameter replaces hyphens with underscores, ensuring the generated log filename is safe across operating systems.
    • Circular Import Defense: The _auto_translate() function uses a local deferred import (from utils.i18n import auto_translate) to avoid circular import cycles between output.py, i18n.py, and upstream LLM dispatch modules.
