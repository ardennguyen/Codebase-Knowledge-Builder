    output.py

    Source: utils/output.py

    Following the repository hygiene rules established in exclude_patterns.py to prune unwanted files during repository traversal, utils/output.py provides the central presentation and diagnostic logging layer for the entire application. It decouples core pipeline logic from terminal display styling, log serialization, and user-facing internationalization (i18n).

    Technical Overview

    utils/output.py acts as the single source of truth for all command-line interface (CLI) rendering, formatted file logging, and localized message resolution across the knowledge base generation pipeline. It unifies terminal feedback with persistent execution logs by intercepting status events, token metrics, and operational warnings. The module routes them through destination dispatch rules (STDOUT, LOG, or BOTH), ANSI color formatting maps, and standard Python logging levels.

    The subsystem reads user-facing copy from an external CSV catalog (utils/strings.csv), enabling multi-language support. String entries in the catalog support dynamic parameter injection using standard brace-enclosed tokens. If a configured language contains missing string keys, the module invokes an LLM translation workflow through call_llm.py to translate missing strings in batch mode. It then updates strings.csv on disk with UTF-8 BOM encoding and refreshes the internal memory cache.

    Architecturally, the module employs a Singleton-style module-level state pattern. Global variables maintain the active localized dictionary (_strings), active language target, file logger instance, and runtime cache flags. Downstream modules invoke lightweight procedural entry points (emit, emit_raw, get) without maintaining their own formatters, ANSI escape constants, or log handlers.

    def init(language="english", use_cache=True, thinking_level=None):
    """Initialize the output system: load strings.csv, set language, auto-translate missing.

    Must be called from main() after parsing CLI arguments but before any emit() calls.

    Args:
        language: Target language name (e.g., "Vietnamese").
        use_cache: Whether LLM caching is enabled (passed to translation calls).
        thinking_level: LLM thinking level (passed to translation calls).
    """
    global _language, _lang_col, _csv_path, _use_cache, _thinking_level
    _language = language.capitalize()
    _lang_col = language.lower()
    _csv_path = os.path.join(os.path.dirname(os.path.abspath(__file__)), "strings.csv")
    _use_cache = use_cache
    _thinking_level = thinking_level
    _load_strings()
    _auto_translate()

    The function normalizes the input language into two representations: an uppercase title (_language) for terminal display messages and a lowercase identifier (_lang_col) matching the column headers of strings.csv. It computes the absolute path to strings.csv relative to the current script file. Once internal references are populated, it invokes _load_strings() to populate the string dictionary in memory. If the configured language requires localization tokens that do not yet exist, it calls _auto_translate() to fetch translations before returning control to the caller.

    Parameters: * language (str, optional): Target language for all user-facing output (e.g., "english", "vietnamese").     emit()

    Visibility: Public
    Signature: def emit(key: str, suffix: str = "", **kwargs: Any) -> None:

    Description:
    Emits a localized message catalog entry to the terminal (stdout), the persistent run log file, or both, based on the string's configuration.

    def emit(key, suffix="", **kwargs):
    """Emit a translatable string to stdout and/or log file.

    Args:
        key: String key from strings.csv (e.g., "LLM_CALL_WRITE_CHAPTER").
        suffix: Optional extra text appended after the main message (e.g., token breakdown).
        **kwargs: Variables to substitute into the string template.
    """
    entry = _strings.get(key)
    if not entry:
        # Fallback for unknown keys — print raw so nothing is silently lost
        print(f"[UNKNOWN STRING: {key}]")
        return

    text = _format_safe(entry["text"], kwargs)
    if suffix:
        text = text + suffix

    level = entry["level"]
    dest = entry["dest"]
    color = COLORS.get(level, "")
    reset = RESET if color else ""

    if dest in ("BOTH", "STDOUT"):
        print(f"{color}{text}{reset}")
    if dest in ("BOTH", "LOG"):
        _logger.log(LOG_LEVELS.get(level, logging.INFO), text)

    The function searches the _strings table for the specified key. If the key is not defined, it prints an unformatted warning [UNKNOWN STRING: {key}] directly to stdout to avoid silent failures. If found, it interpolates dynamic variables using _format_safe() and appends any optional suffix. It resolves the terminal color from COLORS using the entry's level field and inspects the dest attribute. Based on whether dest is BOTH, STDOUT, or LOG, it writes the formatted string to standard output, logs it through _logger.log(), or sends it to both.

    Parameters: * key (str): The unique identifier matching a STRING_KEY in strings.csv (e.g., "LLM_CALL_WRITE_CHAPTER"). * suffix (str, optional): Raw text appended to the formatted string, typically used for token metrics or execution times. Defaults to "". * **kwargs (Any): Arbitrary key-value pairs matching {placeholder} tags defined in the target string template.

    Returns: * None

    Raises: * No exceptions are raised.

    configure_logging()

    Visibility: Public
    Signature: def configure_logging(project_name: str = "project", mode: str = "tutorial") -> str:

    Description:
    Sets up run-specific, file-based logging. It creates a dedicated .log file on disk, attaches a custom logging.FileHandler to the internal llm_logger instance, and writes execution metadata headers.

    def configure_logging(project_name="project", mode="tutorial"):
    """Configure file-based logging for this run.

    Creates a new log file per invocation:
        logs/{project_name}_{mode}_{YYYYMMDD_HHmmss}.log

    Must be called from main() after parsing CLI arguments.
    """
    from datetime import datetime

    log_directory = os.getenv("LOG_DIR", "logs")
    os.makedirs(log_directory, exist_ok=True)

    safe_project = "".join(c if c.isalnum() or c in "-_." else "_" for c in project_name)
    safe_mode = mode.replace("-", "_")
    timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
    log_file = os.path.join(log_directory, f"{safe_project}_{safe_mode}_{timestamp}.log")

    # Remove any existing handlers (e.g., NullHandler) and add the file handler
    _logger.handlers.clear()
    file_handler = logging.FileHandler(log_file, encoding="utf-8")
    file_handler.setFormatter(logging.Formatter("%(asctime)s - %(levelname)s - %(message)s"))
    _logger.addHandler(file_handler)

    # Log run metadata at the start of every log file
    _logger.info(f"{'=' * 80}")
    _logger.info(f"RUN STARTED | project={project_name} | mode={mode} | timestamp={timestamp}")
    _logger.info(f"Log file: {log_file}")
    _logger.info(f"{'=' * 80}")

    return log_file

    The function reads the log directory from the LOG_DIR environment variable (defaulting to "logs") and creates it on disk via os.makedirs(..., exist_ok=True). It sanitizes project_name by replacing non-alphanumeric characters (outside of -, _, .) with underscores, replaces hyphens in mode with underscores, and generates a timestamp formatted as %Y%m%d_%H%M%S.

    To prevent duplicate logs from previous runs or placeholder handlers (such as the NullHandler registered by call_llm.py), it clears all active handlers from _logger. It then instantiates a logging.FileHandler targeting the generated path using UTF-8 encoding and applies the format string "%(asctime)s - %(levelname)s - %(message)s". Finally, it writes an 80-character delimiter banner containing the run metadata and returns the log file path.

    Parameters: * project_name (str, optional): Identifier for the active codebase being processed. Defaults to "project". * mode (str, optional): Execution pipeline mode (e.g., "tutorial" or "api"). Defaults to "tutorial".

    Returns: * str: The relative or absolute filesystem path to the newly created .log file.

    Raises: * OSError: If the log directory cannot be created due to filesystem permissions. * IOError: If the target log file cannot be opened for writing.

    Example:

    Signature: def _format_safe(template: str, kwargs: dict) -> str:

    Description:
    Applies Python's native str.format() substitution using a dictionary of variables, falling back to the raw template if formatting fails.

    def _format_safe(template, kwargs):
    """Apply .format(**kwargs) with graceful fallback on missing keys."""
    try:
        return template.format(**kwargs)
    except (KeyError, IndexError, ValueError):
        return template

This prevents formatting errors from interrupting pipeline execution.

    _load_strings()

    Visibility: Private
    Signature: def _load_strings() -> None:

    Description:
    Parses utils/strings.csv into memory and populates the global _strings lookup dictionary for the active language.

    def _load_strings():
    """Load all strings from strings.csv."""
    global _strings
    _strings = {}

    if not _csv_path or not os.path.exists(_csv_path):
        return

    translated_count = 0
    total_count = 0

    with open(_csv_path, encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        for row in reader:
            key = row.get("STRING_KEY", "").strip()
            if not key or key.startswith("#"):
                continue

            level = row.get("LEVEL", "INFO").strip()
            dest = row.get("DEST", "BOTH").strip()

            # Priority: language column → English fallback
            text = row.get(_lang_col, "").strip()
            if text:
                translated_count += 1
            else:
                text = row.get("english", "").strip()

            total_count += 1
            _strings[key] = {"text": text, "level": level, "dest": dest}

    if _lang_col != "english" and translated_count == total_count:
        emit_raw("SUCCESS", f"[i18n] {_language} — loaded {translated_count} strings from CSV")

    The function verifies that _csv_path is defined and points to an existing file, exiting early if the file is missing. It opens the CSV file using the utf-8-sig codec to strip Byte Order Marks (BOM) that may be added by spreadsheet editors like Microsoft Excel. It iterates over the records using csv.DictReader, skipping blank lines and comment rows prefixed with #.

    For each valid row, it extracts the LEVEL and DEST directives, defaulting to "INFO" and "BOTH" if omitted. It checks the column for the configured language (_lang_col). If a translation exists in that column, it increments translated_count and uses that text; otherwise, it falls back to the "english" column. It stores the resolved text, severity level, and destination routing in _strings[key]. If every string in a non-English catalog has a translation, it emits a SUCCESS message confirming the catalog is fully loaded.

    Parameters: * None

    Returns: * None

    Raises: * OSError: If the file exists but cannot be read due to filesystem permissions. * csv.Error: If the file contains malformed CSV syntax.

    Example:

    _auto_translate()

    Visibility: Private
    Signature: def _auto_translate() -> None:

    Description:
    Finds missing string translations for the active language, batches them into an LLM translation prompt, and updates strings.csv.

    Due to the distinct steps involved—detecting missing strings, calling the LLM, and parsing the response—the function's implementation is broken down across three sequential phases:

    Phase 1: Detection of Missing Translations

    def _auto_translate():
    """Auto-translate missing strings via LLM and write back into strings.csv."""
    if _lang_col == "english":
        return

    if not _csv_path or not os.path.exists(_csv_path):
        return

    # Collect strings that have no translation in the target language column
    missing = {}
    is_new_column = False
    with open(_csv_path, encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        fieldnames = list(reader.fieldnames)
        is_new_column = _lang_col not in fieldnames
        for row in reader:
            key = row.get("STRING_KEY", "").strip()
            if not key or key.startswith("#"):
                continue
            # Check if the language column exists and has a value
            lang_text = row.get(_lang_col, "").strip() if _lang_col in fieldnames else ""
            if lang_text:
                continue  # Already translated

            english_text = row.get("english", "").strip()
            if english_text:
                missing[key] = english_text

    if not missing:
        return

    # Report what we found
    if is_new_column:
        emit_raw("PROGRESS", f"[i18n] New language '{_language}' — adding column to strings.csv")
    emit_raw("PROGRESS", f"[i18n] {len(missing)} strings need translation to {_language}")

    Phase 1 exits early if the target language is "english" or if the CSV file cannot be located on disk. It inspects the CSV header row (reader.fieldnames) to determine whether the target language column (_lang_col) exists. It then iterates through all rows to find keys that lack a translation in _lang_col but have a valid value in the "english" column. These missing keys and their English source strings are collected into the missing dictionary. If no strings require translation, the function exits without performing inference. If untranslated entries are found, it emits progress notifications indicating whether a new column is being created and how many strings require translation.

    Phase 2: LLM Inference Request Dispatch

        # Batch translate via LLM

        from utils.call_llm import call_llm

        entries_json = json.dumps(missing, ensure_ascii=False, indent=2)

            "common",

            prompt_template = pf.read()
        prompt = prompt_template.format(language=_language, entries=entries_json)

        emit_raw("PROGRESS", f"[i18n] Calling LLM to translate {len(missing)} strings...")
        response = call_llm(prompt, use_cache=_use_cache, thinking_level=_thinking_level)

    In Phase 2, the function serializes the missing dictionary into a formatted JSON string using UTF-8 preservation (ensure_ascii=False). It resolves the filesystem path to the translation prompt template at prompts/common/translate_strings.md, reads the template contents, and interpolates the target language name and JSON entries. It then dynamically imports and calls call_llm() from call_llm.py, passing the populated prompt, cache configuration (_use_cache), and reasoning budget (_thinking_level).

    Phase 3: Extraction, Persistence, and State Refresh

            # Extract JSON from response
        json_match = re.search(r"\{[^{}]*(?:\{[^{}]*\}[^{}]*)*\}", response, re.DOTALL)
        if json_match:
            translations = json.loads(json_match.group())

            _load_strings()

    Phase 3 uses a regular expression with the re.DOTALL flag (r"\{[^{}]*(?:\{[^{}]*\}[^{}]*)*\}") to extract the JSON dictionary from the model's response, bypassing any Markdown code fencing or conversational text. It deserializes the JSON string into a Python dictionary. If JSON extraction succeeds, it calls _write_translations_to_csv() to write the updated translations to disk and emits a confirmation message. It then calls _load_strings() to refresh the internal lookup table with the new translations. If the regex match fails or an unhandled exception occurs during inference or file I/O, it emits a WARNING and falls back to the default English strings.

    _write_translations_to_csv()

    Visibility: Private
    Signature: def _write_translations_to_csv(translations: dict[str, str]) -> None:

    Description:
    Writes translated strings into strings.csv, adding the target language column header if it does not already exist.

    def _write_translations_to_csv(translations):
    """Write LLM translations back into strings.csv, persisting them for future runs.

    If the target language column doesn't exist, it is added to the CSV.
    """
    rows = []
    fieldnames = None

    with open(_csv_path, encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        fieldnames = list(reader.fieldnames)
        # Add language column if it doesn't exist
        if _lang_col not in fieldnames:
            fieldnames.append(_lang_col)
        for row in reader:
            key = row.get("STRING_KEY", "").strip()
            if key in translations:
                row[_lang_col] = translations[key]
            rows.append(row)

    # Write with BOM so Excel opens as UTF-8 without extra import steps
    with open(_csv_path, "w", encoding="utf-8-sig", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=fieldnames)
        writer.writeheader()
        writer.writerows(rows)

    The function reads the entire strings.csv file into memory using csv.DictReader. It inspects the header field names, appending _lang_col if the language column is new. As it iterates over the rows, it checks whether each STRING_KEY is present in the translations dictionary; if a match is found, it updates row[_lang_col] with the translated text.

    Once all rows are processed, it re-opens _csv_path in write mode ("w"). It sets newline="" to prevent blank lines on Windows platforms and uses the utf-8-sig encoding so spreadsheet applications like Excel can open the file without UTF-8 import issues. Finally, it uses csv.DictWriter to write out the updated column headers and data rows.

    Parameters: * translations (dict[str, str]): Key-value pairs mapping STRING_KEY names to their translated string values.

    Returns: * None

    Raises: * OSError: If the file cannot be opened for reading or writing due to file system locks or permission errors. * csv.Error: If an error occurs during CSV serialization.

    Example:

    Data Structures

    The module relies on several data structures, including terminal color codes, logging severity maps, in-memory string catalogs, and on-disk CSV schemas.

    ANSI Color Mapping (COLORS)

    COLORS maps message severity strings to ANSI escape sequences for terminal output.

    COLORS = {
    "PROGRESS": "\033[96m",  # Cyan — LLM calls, active steps
    "SUCCESS": "\033[92m",  # Green — completions, cache hits
    "WARNING": "\033[93m",  # Yellow — warnings, capacity alerts
    "ERROR": "\033[91m",  # Red — errors, failures

    Key Error Handling Patterns

    1. Template Substitution Fallback (_format_safe):
      If parameter substitution fails with a KeyError, IndexError, or ValueError, the helper catches the error and returns the original template string. This prevents unhandled exceptions if dynamic tags are omitted or misnamed.
    2. Missing Localization Keys:
      If emit() encounters an unknown key, it prints [UNKNOWN STRING: {key}] directly to stdout so the missing token is clearly visible in the terminal without interrupting execution. Similarly, get() returns the raw key string, ensuring generated Markdown documents still display a legible identifier.
    3. CSV Parsing Resiliency:
      _load_strings() skips empty rows and lines prefixed with #, allowing developers to organize strings.csv with comments and section dividers. Opening the file with encoding="utf-8-sig" automatically removes any UTF-8 Byte Order Marks added by external tools.
    4. Auto-Translation Graceful Degradation:
      In _auto_translate(), the entire translation block—including LLM invocation, regex extraction, JSON parsing, and CSV updates—is wrapped in a try...except Exception block. If the LLM returns invalid JSON or the network request fails, the module emits a warning and continues execution using the English fallback strings.
    5. Logging Handler Isolation:
      In configure_logging(), invoking _logger.handlers.clear() before attaching a new logging.FileHandler prevents duplicate entries from being written if configure_logging() is called multiple times.
