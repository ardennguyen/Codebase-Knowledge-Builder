    facts.py

    Source: utils/facts.py

    Technical Overview

    The utils/facts.py module implements a language-agnostic static verification and symbol-resolution engine for extracted codebase facts within the Codebase-Knowledge-Builder pipeline. Upstream extraction prompts prompt Large Language Models (LLMs) to identify declarations, imported dependencies, configuration keys, and error-handling conditions accompanied by verbatim source code quotes. Rather than constructing a full language-specific Abstract Syntax Tree (AST), facts.py treats source code as a structured text corpus with lexical boundaries. It guarantees factual fidelity by accepting claims only when their quoted evidence can be located in the source file via exact line matches, squashed multi-line joins, or ordered identifier token sequences.

    Architecturally, the module operates across two distinct phases: per-file verification and cross-module resolution. In the per-file phase, verify_file_claims() utilizes SourceIndex to locate symbols, configuration accessors, errors, and dependency candidates, recording exact 1-based line spans and extracting contextual source excerpts while pruning fabricated or unlocatable claims. In the cross-module phase, ModuleTable and verify_dependencies() construct repository-wide namespace tables, ingest build manifest metadata (e.g., Cargo, npm, Go modules, Maven), resolve relative and aliased module imports, and enforce the "evidence rule" to ensure that an imported target is genuinely named or bound within the referencing source.

    The module publishes its verified results to disk via save_facts() into an atomic, schema-validated JSON document (facts.json). Downstream verification components—most notably utils.chapter_check—consume this artifact to cross-check markdown documentation chapters, guaranteeing that every documented API signature, error condition, and cross-file reference matches the repository's ground truth.

    Description: Splits source code into lines matching the line-numbering conventions of standard code editors and GitHub. It accounts for CRLF, CR, and LF line breaks while ensuring that a trailing empty string generated by a terminal newline is omitted.

    Parameters: * content (str): Raw multi-line string content from a source file.

    Returns: * list[str]: A list of discrete lines without newline characters.

    Raises: * None.

    SourceIndex.locate()

    Visibility: Public Signature: def locate(self, quote, start: int = 0, end: int | None = None) -> list[tuple[int, int, str]]:

    Description: Locates a claimed quote within a bounded range of lines using a 3-tier matching cascade: exact collapsed line matching, whitespace-squashed multi-line joined matching, and ordered identifier token sequence matching.

    Parameters: * quote (Any): The substring or quote to locate in the source text. * start (int, default=0): 0-based start line boundary for the search. * end (int | None, default=None): 0-based end line boundary for the search.

    Returns: * list[tuple[int, int, str]]: A list of matches formatted as (first_line, last_line, how), where how is "exact", "joined", or "tokens". Returns an empty list if unlocatable.

    Raises: * None.

    Example: 

    matches = index.locate(evidence)
if not matches:
    rejected.append({"kind": "dependency", "target": target, "evidence": evidence, "reason": "evidence not in source"})
    continue
first, last, how = matches[0]
    The location algorithm executes in three strict tiers. First, it searches collapsed_text using str.find and maps character offsets to line numbers using bisect_right; any match found on this tier is categorized as "exact". If no match occurs, it executes a "joined" search on squashed_text, permitting the quote to span up to _WINDOW lines (or the quote's own line count) while stripping all whitespace. If joined matching fails, it evaluates the quote's identifier tokens using _words_in_order anchored to the least frequent word via the inverted index word_lines.

    Raises: * None.

    Example:

    verify_file_claims()

    Visibility: Public Signature: def verify_file_claims(claims: dict, content: str) -> dict:

    Description: Validates all raw LLM claims for a single source file against its text content. It coordinates symbol scoping, dependency location, configuration accessor ranking, and error role classification.

    Phase 1: Symbol Verification and Scoping

        index = SourceIndex(content)
    result = {key: [] for key in CLAIM_KEYS}

    claimed += len(symbols)
    kept, symbol_rejects = _verify_symbols(symbols, index)
    result["symbols"] = kept
    rejected += symbol_rejects
    The function initializes a SourceIndex and accounts for malformed or unparsed LLM items directly as rejected records. It delegates symbol validation to _verify_symbols(), which scopes nested declarations to their parents and calculates line boundaries.

    Phase 2: Dependency Location

        for item in _claim_list(claims, "dependencies"):
        claimed += 1
        target, evidence = _as_text(item.get("target")).strip(), _as_text(item.get("evidence"))
        matches = index.locate(evidence) if target else []
        if not matches:
            rejected.append({"kind": "dependency", "target": target, "evidence": evidence, "reason": "evidence not in source"})
            continue

        text, truncated = index.excerpt(first, last, evidence)
        entry = {"target": target, "line": first + 1, **_end(first, last), "evidence": text, "match": how}
        result["dependencies"].append({**entry, "truncated": True} if truncated else entry)
    Dependencies are checked to confirm that their quoted evidence exists in the file. Validated dependency claims record line numbers and excerpts; target-to-module resolution is deferred to verify_dependencies().

    Phase 3: Configuration and Error Classification

        for key in ("config", "errors"):
        for item in _claim_list(claims, key):
            claimed += 1
            name, evidence = _as_text(item.get("name")).strip(), _as_text(item.get("evidence"))
            matches = []
            for first, last, how in index.locate(evidence) if name else []:
                if _names_in(index.text(first, last), name):
                    matches.append((first, last, how, False))
                    continue
                end = _call_span(index, first, last)
                if end > last and _names_in(index.text(first, end), name):
                    matches.append((first, end, how, True))
            if not matches:
                rejected.append({"kind": key, "name": name, "evidence": evidence, "reason": "name/evidence not in source"})
                continue
            roles = {m: _error_role(index, m[0], m[1], name) for m in matches} if key == "errors" else {}
            matches.sort(key=lambda m: (_ROLE_RANK.get(roles.get(m), 0), _name_rank(index.text(m[0], m[1]), name), m[3]))
            first, last, how, extended = matches[0]
            text, truncated = index.excerpt(first, last, evidence)
            if extended and not _names_in(text, name):
                text, truncated = index.excerpt(first, last, name)
            entry = {"name": name, "line": first + 1, **_end(first, last), "evidence": text, "match": how}
            if key == "config":
                entry["kind"] = _as_text(item.get("kind")).strip() or "config"
            else:
                entry["role"] = roles[matches[0]]
            result[key].append({**entry, "truncated": True} if truncated else entry)
    Config and error facts expand matches across multi-line invocations using _call_span(). If multiple candidate locations match, matches are sorted by role priority (raised beats mentioned, which beats caught), naming prominence (code beats whole string, which beats prose), and span tightness.

    Phase 4: Deduplication and Normalization

        for key, fields in (("symbols", ("parent", "name")), ("dependencies", ("target",)), ("config", ("name",)), ("errors", ("name",))):
        seen, unique = set(), []
        for entry in result[key]:
            marker = (*(entry.get(field) for field in fields), entry["line"])
            if marker not in seen:
                seen.add(marker)
                unique.append(entry)
        if key in ("config", "errors"):

            kept_spans = []

                if not any(other["name"] == entry["name"] and low <= other["line"] <= high for other in kept_spans):

            unique = [entry for entry in unique if any(entry is other for other in kept_spans)]
        claimed -= len(result[key]) - len(unique)
        result[key] = unique
    result["rejected"] = rejected
    result["claimed"] = claimed
    result["found"] = claimed - len(rejected)
    return result
    Duplicate extractions are deduplicated on identity fields and line positions. When configuration or error keys appear both as standalone calls and within larger enclosing expressions, the narrower source span is preferred.

    Visibility: Public Signature: def code_view(lines: list[str]) -> list[str]:

    Description: Produces a normalized view of source code lines where docstrings, block strings, and comments are blanked out while preserving exact line counts and character line positions.

    Parameters: * lines (list[str]): List of source code lines.

    Returns: * list[str]: Masked source code lines with comments and block strings converted to empty space.

    declaration_like()

    Visibility: Public Signature: def declaration_like(line: str) -> bool:

    Description: Heuristically determines whether a source code line appears to declare a symbol (such as a function, class, constant, interface, or struct) across diverse programming languages.

    Parameters: * line (str): Single stripped or unstripped source line.

    Returns: * bool: True if the line matches structural declaration patterns, otherwise False.

    enclosing_blocks()

    Visibility: Public Signature: def enclosing_blocks(lines: list[str]) -> list[str | None]:

    Description: Determines the structural category of the enclosing block for each line in a source file by tracking indentation changes.

    Parameters: * lines (list[str]): List of source code lines.

    Returns: * list[str | None]: Parallel list where each element indicates the enclosing block category ("function", "container", or None).

    Raises: * None.

    Error Handling

    The module employs defensive, fail-soft error handling patterns designed to keep verification running across imperfect LLM extractions and varied repository structures:

    • Atomic File Replacement: save_facts() writes data to a .tmp sibling file before calling os.replace. This prevents half-written or corrupted JSON artifacts from persisting if the process is terminated mid-write.
    • Tolerant Deserialization: load_facts() catches both OSError and ValueError (which includes json.JSONDecodeError). If reading fails or the schema version does not match FACTS_SCHEMA, it returns an empty dictionary, allowing the pipeline to re-extract facts smoothly.
    • Subprocess Isolation: source_commit() executes git rev-parse HEAD inside a try...except (OSError, subprocess.SubprocessError) block with a 10-second timeout. If Git is not installed, the directory is not a Git repository, or the command times out, it returns None rather than raising an unhandled exception.
    • Malformed LLM Output Tolerance: All extraction helpers (_as_text(), _claim_list(), verify_file_claims(), verify_manifest_claims()) validate data types before accessing dictionary keys. Non-dictionary items in arrays are filtered out, and unparsed YAML/JSON markers are captured as "unparsed" rejections, ensuring that schema-checking continues even when LLM output is malformed.
    • Safe Character Decoding: Text operations use Unicode NFC normalization via unicodedata.normalize("NFC", ...). The module avoids standard str.splitlines() in split_lines() to prevent non-standard Unicode boundary characters (such as form feeds or vertical tabs) from desynchronizing line counts with GitHub and code editors.
