    token_utils.py

    Source: utils/token_utils.py

    Technical Overview

    The utils/token_utils.py module provides the centralized token counting, prompt budgeting, and dynamic tokenizer calibration engine for the Codebase-Knowledge-Builder architecture. Operating between high-level orchestration nodes (such as indexing, abstraction mapping, and chapter synthesis) and downstream LLM provider client adapters (Anthropic Claude, Google Gemini, OpenRouter, and generic OpenAI-compatible endpoints), the module solves the critical challenge of context window management. Because different language model families employ disparate, proprietary Byte-Pair Encoding (BPE) vocabularies, raw token counts derived from standard open-source tokenizers do not map 1:1 to provider billing and context ceilings. This module bridges that divide by pairing local token estimation with empirical feedback loops that observe actual provider billing telemetry and recalibrate multipliers dynamically at runtime.

    The module implements a two-tier counting architecture. The baseline tier computes raw token counts using the OpenAI cl100k_base BPE encoding via the tiktoken library. To minimize latency across repetitive prompts—such as multi-stage analysis loops where prompts are evaluated across multiple subsystem boundaries—raw counts are cached in an in-memory, thread-safe Least Recently Used (LRU) memoization table keyed by content length and hash. If the tiktoken native library or vocabulary fails to initialize (for example, in air-gapped environments or constrained execution environments where vocabulary downloads fail), the engine automatically falls back to an emergency conservative byte-ratio estimator (-len(text.encode("utf-8")) // 3). This fallback purposefully over-counts source code rather than under-counting multilingual text, preventing context exhaustion during subsequent LLM invocations.

    The upper tier of the module applies an adaptive multiplier (token_ratio()) to scale raw BPE counts to the active provider and model architecture. It initializes with static per-family prior ratios loaded from utils.llm_config.get_token_ratio, which are then continuously refined through online updates via observe_prompt_tokens. To prevent catastrophic prompt overflow, the calibration mechanism uses an asymmetric update policy: ratios scale upward quickly using an Exponential Moving Average (EMA) to account for token bloat, but require substantial empirical evidence (at least 3 samples and 150,000 raw tokens) before lowering. Learned calibration parameters are atomically persisted to llm_token_calibration.json, ensuring subsequent workflow runs start fully calibrated.

    Public API

    MIN_OUTPUT_RESERVE

    Visibility: Public
    Signature: MIN_OUTPUT_RESERVE = 8_192

    Description: The minimum output token reservation ceiling applied to providers that do not explicitly report or size their maximum generation tokens (such as Ollama or generic OpenAI-compatible completion endpoints).

    MAX_OUTPUT_RESERVE

    Visibility: Public
    Signature: MAX_OUTPUT_RESERVE = 64_000

    Description: The maximum upper clamp applied to dynamic 5% output token reservations on unconfigured providers, preventing excessive allocation away from the prompt input window.

    ESTIMATE_RESERVE_UNCALIBRATED

    Visibility: Public
    Signature: ESTIMATE_RESERVE_UNCALIBRATED = 0.05

    Description: The fraction of the model context window (5%) reserved to absorb tokenizer estimation variance when the active model's token ratio has not yet been calibrated against empirical usage.

    ESTIMATE_RESERVE_CALIBRATED

    Visibility: Public
    Signature: ESTIMATE_RESERVE_CALIBRATED = 0.02

    Description: The reduced fraction of the model context window (2%) reserved for estimation variance once the active model ratio has accumulated sufficient empirical telemetry to be marked calibrated.

    MEMO_MAX_ENTRIES

    Visibility: Public
    Signature: MEMO_MAX_ENTRIES = 4_096

    Description: The maximum capacity of the in-memory Least Recently Used (OrderedDict) cache storing raw BPE token counts.

    MEMO_MIN_CHARS

    Visibility: Public
    Signature: MEMO_MIN_CHARS = 256

    Description: The minimum character length threshold required for a string to be eligible for memoization in the raw token count cache; strings shorter than this are re-encoded directly.

    TOKEN_CALIBRATION_FILE

    Visibility: Public
    Signature: TOKEN_CALIBRATION_FILE = "llm_token_calibration.json"

    Description: The standard filesystem path where learned token calibration ratios and empirical sample counts are persisted.

    CALIBRATION_MIN_RAW

    Visibility: Public
    Signature: CALIBRATION_MIN_RAW = 2_000

    Description: The minimum number of raw BPE tokens a request prompt must contain before it is admitted into the empirical ratio calibration loop. Below this threshold, fixed per-request system framing tokens skew the observed ratio.

    CALIBRATION_EMA_WEIGHT

    Visibility: Public
    Signature: CALIBRATION_EMA_WEIGHT = 0.35

    Description: The baseline smoothing factor ($\alpha$) used in the Exponential Moving Average calculation when updating calibrated token ratios with new empirical samples.

    CALIBRATION_FULL_WEIGHT_RAW

    Visibility: Public
    Signature: CALIBRATION_FULL_WEIGHT_RAW = 50_000

    Description: The token volume threshold at which a single observation receives full weight in the calibration formula. Samples smaller than this threshold receive proportionally scaled fractional weights.

    CALIBRATION_HEADROOM

    Visibility: Public
    Signature: CALIBRATION_HEADROOM = 1.03

    Description: A safety multiplier (3% headroom) applied to the learned Exponential Moving Average ratio before clamping, ensuring conservative estimates that avoid context boundary exhaustion.

    CALIBRATION_MIN_SAMPLES_TO_LOWER

    Visibility: Public
    Signature: CALIBRATION_MIN_SAMPLES_TO_LOWER = 3

    Description: The minimum number of empirical observations required before the calibration system allows an effective token ratio to decrease below its static prior.

    CALIBRATION_MIN_RAW_TO_LOWER

    Visibility: Public
    Signature: CALIBRATION_MIN_RAW_TO_LOWER = 3 * CALIBRATION_FULL_WEIGHT_RAW

    Description: The cumulative raw token volume threshold (150,000 raw tokens) required before the calibration system is permitted to lower the effective ratio below the static baseline.

    CALIBRATION_RANGE

    Visibility: Public
    Signature: CALIBRATION_RANGE = (0.75, 1.5)

    Description: The allowable bounding interval (low, high) as multiples of the static prior ratio within which the learned ratio must remain.

    CALIBRATION_PRIOR_DRIFT

    Visibility: Public
    Signature: CALIBRATION_PRIOR_DRIFT = 0.02

    Description: The relative tolerance threshold (2%) beyond which a cached calibration entry is marked invalid due to changes in the static prior configuration or underlying model target.

    OBSERVED_RATIO_BOUNDS

    Visibility: Public
    Signature: OBSERVED_RATIO_BOUNDS = (0.5, 3.0)

    Description: The acceptable absolute bounds for observed request-to-raw token ratios. Observations falling outside this range are discarded as anomalies (such as in-transit search augmentation).

    CALIBRATION_COUNTER

    Visibility: Public
    Signature: CALIBRATION_COUNTER = "cl100k_base"

    Description: The identifier of the baseline tokenizer encoding against which all raw token measurements and calibration entries are recorded.

    resolve_max_tokens()

    Visibility: Public
    Signature: def resolve_max_tokens(shared):

    Description: Resolves the effective context length ceiling for the running pipeline. It checks the pipeline's shared dictionary store for an explicit override key "max_tokens". If not present, it calls resolve_llm_settings() to determine the current provider, model identifier, API endpoint, and authentication credentials, and delegates to get_model_context_length() to retrieve the context window ceiling. The resolved context limit is logged via diagnostic telemetry.

    Parameters: * shared (dict): The shared execution dictionary containing pipeline state and configuration overrides.

    Returns: * int: The context length limit in tokens.

    Raises: * None. Exceptions raised during downstream model resolution are handled by get_model_context_length.

    Example: 

    max_tokens = resolve_max_tokens(shared)
token_budget = input_token_budget(max_tokens, thinking_level="high")


    def resolve_max_tokens(shared):
    """Resolve max_tokens from shared store or auto-detect from the active provider."""
    max_tokens = shared.get("max_tokens")
    if max_tokens is not None:
        return max_tokens
    _, model_name, endpoint, api_key = resolve_llm_settings()
    max_tokens_val = get_model_context_length(endpoint, model_name, api_key)
    emit_raw("DEBUG", f"resolve_max_tokens | resolved max_tokens={max_tokens_val:,}", dest="LOG")
    return max_tokens_val

    The function provides lazy resolution of the context limit, ensuring that models initialized via environment variables or CLI flags have their context ceilings properly registered before token budgeting begins. By caching the value in the caller's shared dictionary after the first resolution, the pipeline avoids redundant network discovery round-trips.

    input_token_budget()

    Visibility: Public
    Signature: def input_token_budget(max_tokens: int, thinking_level: str | None = None) -> int:

    Description: Calculates the maximum number of input tokens (measured in calibrated count_tokens() units) that can be safely dispatched in a prompt while leaving sufficient headroom for the model's generation output, reasoning traces, flat safety margins, and estimation variance. For unified window providers (Anthropic Claude, OpenRouter), it reserves the planned output buffer defined by context_output_reserve(thinking_level) plus CONTEXT_MARGIN. For separate window architectures (Google Gemini), only the margin is subtracted. For unconfigured endpoints (Ollama), it reserves 5% of the context window clamped between MIN_OUTPUT_RESERVE and MAX_OUTPUT_RESERVE. Finally, it reserves an additional estimation margin (2% if calibrated, 5% if uncalibrated) and enforces a floor of at least half the total context window (max_tokens // 2).

    Parameters: * max_tokens (int): Total context length of the active model. * thinking_level (str | None, optional): The reasoning effort tier assigned to the invocation (e.g., "low", "medium", "high"), which scales the output headroom reservation. Defaults to None.

    Returns: * int: The maximum allowable prompt token count.

    Raises: * None.

    Example: 

    budget = input_token_budget(max_tokens=200_000, thinking_level="high")
if count_tokens(prompt) > budget:
    prompt = truncate_prompt(prompt, budget)


    def input_token_budget(max_tokens: int, thinking_level: str | None = None) -> int:
    planned = context_output_reserve(thinking_level)
    if planned is not None:
        reserve = planned + CONTEXT_MARGIN
    else:
        reserve = min(max(int(max_tokens * 0.05), MIN_OUTPUT_RESERVE), MAX_OUTPUT_RESERVE)
    reserve += int(max_tokens * (ESTIMATE_RESERVE_CALIBRATED if ratio_is_calibrated() else ESTIMATE_RESERVE_UNCALIBRATED))
    return max(max_tokens - reserve, max_tokens // 2)

    The calculation guarantees that generation buffers are dynamically adapted to reasoning depth. When extended thinking is enabled, output token reservations expand, compressing the allowable input budget. The estimation reserve deduction dynamically contracts from 5% to 2% once the ratio calibration engine confirms empirical stability, safely freeing context space for source code ingestion.

    count_tokens_raw()

    Visibility: Public
    Signature: def count_tokens_raw(text: str) -> int:

    Description: Computes the uncalibrated raw BPE token count of a given string using the cl100k_base encoding. If the string length is below MEMO_MIN_CHARS, it directly encodes the text without cache interaction. For longer strings, it constructs a cache key tuple (len(text), hash(text)) and queries the internal LRU cache _memo. On cache hits, it returns the stored integer count immediately; on misses, it computes the count via _encode_count, populates _memo, and returns the result.

    Parameters: * text (str): The input string to measure.

    Returns: * int: Raw token count according to cl100k_base. Returns 0 if text is empty or evaluate to boolean False.

    Raises: * None. Encoding failures trigger the internal UTF-8 byte fallback within _encode_count.

    Example: 

    raw_count = count_tokens_raw("def hello_world(): return True")


    def count_tokens_raw(text: str) -> int:
    """tiktoken cl100k_base token count (no model calibration). Memoized by content."""
    if not text:
        return 0
    if len(text) < MEMO_MIN_CHARS:
        return _encode_count(text)
    key = (len(text), hash(text))
    cached = _memo_get(key)
    if cached is not None:
        return cached
    count = _encode_count(text)
    _memo_put(key, count)
    return count

    This function forms the deterministic base for all token estimation operations. Relying on Python's built-in string hash caching (str objects store their computed hash code internally after first access), the (len(text), hash(text)) lookup operates in $O(1)$ time without keeping entire prompt texts in memory.

    count_tokens_raw_many()

    Visibility: Public
    Signature: def count_tokens_raw_many(texts: list[str]) -> list[int]:

    Description: High-throughput batch token counter for multiple strings. It scans the input list, satisfying hits from the memo cache while gathering uncached strings into a pending queue. If tiktoken is loaded, it executes multithreaded native batch encoding via enc.encode_ordinary_batch, distributing workload across up to 8 threads (bounded by os.cpu_count()). If tiktoken is unavailable, it processes pending items with _fallback_count. Uncached entries that meet the MEMO_MIN_CHARS threshold are added back into _memo.

    Parameters: * texts (list[str]): A list of input strings to encode.

    Returns: * list[int]: An ordered list of integer token counts matching the indices of the input texts.

    Raises: * None.

    Example: 

    counts = count_tokens_raw_many([file_content_1, file_content_2, file_content_3])


    def count_tokens_raw_many(texts: list[str]) -> list[int]:
    """Raw counts for many texts; the uncached ones are batch-encoded on several threads."""
    counts = [0] * len(texts)
    pending = []
    for i, text in enumerate(texts):
        if not text:
            continue
        key = (len(text), hash(text)) if len(text) >= MEMO_MIN_CHARS else None
        cached = _memo_get(key) if key else None
        if cached is not None:
            counts[i] = cached
        else:
            pending.append((i, text, key))
    enc = _get_encoding()
    if pending and enc is not None:
        encoded = enc.encode_ordinary_batch([text for _, text, _ in pending], num_threads=min(8, os.cpu_count() or 1))
        results = [len(tokens) for tokens in encoded]
    else:
        results = [_fallback_count(text) for _, text, _ in pending]
    for (i, _text, key), count in zip(pending, results, strict=True):
        counts[i] = count
        if key:
            _memo_put(key, count)
    return counts

    By decoupling cache checks from batch execution, the function eliminates Python Global Interpreter Lock (GIL) contention during large-scale repository indexing. Pre-populating results from the memo table avoids submitting previously evaluated files to the multithreaded Rust BPE batch encoder.

    token_ratio()

    Visibility: Public
    Signature: def token_ratio() -> float:

    Description: Resolves the active scaling ratio mapping raw cl100k_base counts to the active provider and model tokenizer. It retrieves the active provider and model key tuple via _active_key(), loads the static prior ratio via _static_ratio(), loads persistent empirical entries via _load_calibration(), and evaluates the effective ratio via _effective().

    Parameters: * None.

    Returns: * float: The effective token ratio multiplier (e.g., 1.55).

    Raises: * None.

    Example: 

    current_ratio = token_ratio()
estimated_tokens = int(raw_tokens * current_ratio)


    def token_ratio() -> float:
    """Multiplier from raw tiktoken counts to the active model's tokenizer (static prior, calibrated)."""
    provider, _model, key = _active_key()
    return _effective(_static_ratio(provider, key), _load_calibration().get(key))

    This method is the primary mathematical scalar utilized by high-level estimation routines. Because it reconciles static baseline priors with persistent empirical calibration on each call, changes to the running environment or model target are reflected across the pipeline immediately.

    ratio_is_calibrated()

    Visibility: Public
    Signature: def ratio_is_calibrated() -> bool:

    Description: Determines whether the active provider and model configuration has accumulated sufficient empirical observation data to be classified as calibrated. It evaluates the loaded calibration record against _can_lower, requiring that at least CALIBRATION_MIN_SAMPLES_TO_LOWER requests and CALIBRATION_MIN_RAW_TO_LOWER raw tokens have been logged without invalidating static drift boundaries.

    Parameters: * None.

    Returns: * bool: True if calibration criteria are met; False otherwise.

    Raises: * None.

    Example: 

    if ratio_is_calibrated():
    reserve_pct = ESTIMATE_RESERVE_CALIBRATED
else:
    reserve_pct = ESTIMATE_RESERVE_UNCALIBRATED


    def ratio_is_calibrated() -> bool:
    """True once enough real usage (samples and measured text) has been observed for the active
    provider+model, in this or earlier runs."""
    provider, _model, key = _active_key()
    entry = _valid_entry(_static_ratio(provider, key), _load_calibration().get(key))
    return bool(entry) and _can_lower(entry)

    This function gates context window headroom reservation. By verifying that a model has demonstrated empirical stability across multiple large calls, the pipeline safely transitions from a 5% conservative safety margin to an optimized 2% margin.

    describe_token_ratio()

    Visibility: Public
    Signature: def describe_token_ratio() -> str:

    Description: Generates a human-readable diagnostic description of the active token ratio for display during application startup and telemetry reporting. If the active model has no empirical calibration records, it returns a localized static status message (e.g., "1.55 (static)"). If calibrated records are present, it formats a status string containing the effective ratio, the total sample count, and the underlying static prior.

    Parameters: * None.

    Returns: * str: Localized diagnostic string describing the ratio state.

    Raises: * None.

    Example: 

    ratio_desc = describe_token_ratio()
emit("STARTUP_STATUS", ratio_info=ratio_desc)


    def describe_token_ratio() -> str:
    """'1.55 (static)' or '1.61 (calibrated from 12 calls; static 1.55)' for the startup display."""
    provider, _model, key = _active_key()
    static = _static_ratio(provider, key)
    entry = _valid_entry(static, _load_calibration().get(key))
    effective = _effective(static, entry)
    if not entry:
        return get("CFG_TOKEN_RATIO_STATIC", ratio=f"{static:.2f}")
    return get("CFG_TOKEN_RATIO_CALIBRATED", ratio=f"{effective:.2f}", samples=entry["n"], static=f"{static:.2f}")

    The method interfaces with utils.output.get to resolve localized UI templates (CFG_TOKEN_RATIO_STATIC and CFG_TOKEN_RATIO_CALIBRATED). This provides visibility into whether prompt packing calculations are operating on static estimates or empirically calibrated values.

    observe_prompt_tokens()

    Visibility: Public
    Signature: def observe_prompt_tokens(provider: str, model: str, raw_tokens: int, billed_tokens: int, served_model: str | None = None) -> None:

    Description: Ingests actual provider-reported prompt usage from an API response and updates the calibration state for the corresponding provider and model. The update process executes in three distinct phases: validation, EMA calculation, and persistence.

    Parameters: * provider (str): Provider identifier (e.g., "ANTHROPIC", "GEMINI", "OPENROUTER"). * model (str): Requested model name. * raw_tokens (int): BPE token count measured locally via count_tokens_raw. * billed_tokens (int): Total prompt tokens billed by the upstream provider. * served_model (str | None, optional): The concrete model that generated the completion. Defaults to None.

    Raises: * None. File write errors are caught and logged as warnings.

    Phase 1: Input Validation and Outlier Guarding

        if not calibration_enabled() or raw_tokens < CALIBRATION_MIN_RAW or billed_tokens <= 0:
        return
    if _get_encoding() is None:
        return
    model_id = _model_id(provider, model)
    served = _model_id(provider, served_model or "")
    if served and not (served.startswith(model_id) or model_id.startswith(served)):
        return
    if provider == "OPENROUTER" and ":online" in model_id:
        return
    ratio = billed_tokens / raw_tokens
    if not OBSERVED_RATIO_BOUNDS[0] <= ratio <= OBSERVED_RATIO_BOUNDS[1]:
        return
    This phase discards invalid or distorting inputs. It skips updates if calibration is disabled, if raw_tokens is under CALIBRATION_MIN_RAW (where fixed framing tokens distort ratios), or if _get_encoding() is unavailable. It also rejects calls where server-side fallbacks rerouted the request to a different model family, drops OpenRouter web-search routes (:online) due to dynamic search injection, and filters out ratios outside OBSERVED_RATIO_BOUNDS (0.5 to 3.0).

        key = _key(provider, model)
    static = _static_ratio(provider, key)
    weight = min(raw_tokens / CALIBRATION_FULL_WEIGHT_RAW, 1.0)
    with _calibration_lock:
        calibration = _load_calibration()
        entry = _valid_entry(static, calibration.get(key))
        before = _effective(static, entry)
        if entry is None:

        seen = entry.get("w", 0.0)

        else:

            entry["ema"] = (1 - alpha) * entry["ema"] + alpha * ratio

        entry["n"] += 1
        entry["raw"] += raw_tokens
        entry["prior"] = static
        after = _effective(static, entry)

The entry metrics (w, n, raw, prior) are updated, and the record is written to disk via _save_calibration().

    def format_cost(usage: dict) -> str:

    return entry["n"] >= CALIBRATION_MIN_SAMPLES_TO_LOWER and entry["raw"] >= CALIBRATION_MIN_RAW_TO_LOWER

    This asymmetric threshold implements a fail-safe against premature optimization: overestimating prompt size merely causes earlier chunk batching, whereas underestimating prompt size risks catastrophic context window exhaustion.

    _effective()

    Visibility: Private
    Signature: def _effective(static: float, entry: dict | None) -> float:

    Description: Calculates the final effective token ratio from the static prior and an optional calibration record. Clamps the learned ratio within CALIBRATION_RANGE (0.75× to 1.5× of static prior) with CALIBRATION_HEADROOM (3% buffer). If _can_lower() returns false, the result is bounded below by the static prior.

    Parameters: * static (float): The static baseline prior ratio. * entry (dict | None): The calibrated entry record.

    Returns: * float: The final effective ratio to apply to raw token counts.

    Raises: * None.

    Example: 

    final_ratio = _effective(static_ratio, calibration_entry)


    def _effective(static: float, entry: dict | None) -> float:
    entry = _valid_entry(static, entry)
    if not entry:
        return static
    low, high = CALIBRATION_RANGE
    learned = min(max(entry["ema"] * CALIBRATION_HEADROOM, static * low), static * high)
    return learned if _can_lower(entry) else max(static, learned)

    This function combines the safety mechanisms of the calibration engine into a single multiplier: bounding adjustments within a fixed envelope around the baseline, applying a safety headroom factor, and gating downward adjustments behind sample thresholds.

    Error Handling

    • Tokenizer Asset Loading Failures: If the tiktoken library fails to load the cl100k_base BPE vocabulary (e.g., due to network timeouts or missing local caches in air-gapped systems), _get_encoding() catches the exception, sets _encoding_failed = True, and emits WARN_TIKTOKEN_UNAVAILABLE. All subsequent token counting automatically routes through _fallback_count(), which computes a conservative UTF-8 byte estimate (bytes / 3) without raising exceptions.
    • Calibration File Invalidation and Schema Mismatch: During _load_calibration(), if TOKEN_CALIBRATION_FILE is missing, execution proceeds silently. If the file contains invalid JSON, raises OSError, or references an incompatible baseline counter (counter != CALIBRATION_COUNTER), a ValueError is caught, a diagnostic warning is logged via emit_raw, and the engine initializes with an empty calibration registry.
    • Drift Detection and Model Aliasing: When evaluating stored calibration records in _valid_entry(), entries are invalidated if the recorded baseline prior differs from the active static prior by more than CALIBRATION_PRIOR_DRIFT (2%). This prevents stale calibration data from persisting across model migrations or configuration updates.
    • Outlier Observation Filtering: In observe_prompt_tokens(), observations are discarded if the prompt contains fewer than CALIBRATION_MIN_RAW (2,000) raw tokens, if the observed ratio falls outside OBSERVED_RATIO_BOUNDS (0.5 to 3.0), or if the response was served by an alternate model family via server-side fallback.
    • Atomic File Writes: _save_calibration() writes JSON data to an intermediate file (llm_token_calibration.json.tmp) and swaps it into place using os.replace(). This prevents file corruption if the process is terminated mid-write.
