    token_utils.py

    Source: utils/token_utils.py

    Following the prompt template construction and layout compilation provided in prompts.py, the token_utils.py module provides the centralized token counting, context window utilization analysis, and execution budget telemetry engine for the Codebase-Knowledge-Builder pipeline.

    Large Language Model (LLM) inference nodes require precise accounting of prompt volumes to prevent context window overflow, plan model degradation fallbacks, and track operational costs. This module provides a fast, offline tokenization layer built on OpenAI's tiktoken library with heuristic fallbacks, alongside dual-channel diagnostic logging that bifurcates human-readable console alerts and machine-parseable log files.

    Architecture & Integration

    The module acts as a critical intermediary between codebase ingestion, prompt assembly, and LLM invocation. Pipeline nodes in nodes.py assemble arbitrary source code trees into prompts via prompts.py, pass the resulting payloads to token_utils.py to evaluate token sizing against model thresholds discovered by call_llm.py, and format console and log events through output.py.

    Module-Level Attributes

    logger

    • Type: logging.Logger
    • Value: logging.getLogger("llm_logger")
    • Description: A shared, named logger instance aligned with the inference logger defined in call_llm.py. It records structured single-line execution records for parsing and diagnostic audits without polluting stdout streams.

    _encoding

    • Type: tiktoken.core.Encoding | None
    • Initial Value: None
    • Description: A module-level singleton cache holding the lazily initialized cl100k_base Byte Pair Encoding (BPE) tokenizer instance. If tiktoken encounters initialization errors or missing local assets, this variable remains None to trigger heuristic character-based token approximation.

    Module-Level Functions

    _get_encoding()

    Visibility: Private (Internal Helper)
    Signature: def _get_encoding() -> tiktoken.core.Encoding | None:

    def _get_encoding():
    global _encoding
    if _encoding is None:
        try:
            _encoding = tiktoken.get_encoding("cl100k_base")
        except Exception:
            _encoding = None
    return _encoding

    Description:
    Implements a thread-safe-compatible lazy singleton pattern for the tiktoken BPE tokenizer. Rather than loading the heavy cl100k_base vocabulary table during module import, _get_encoding() defers initialization until the first call to count_tokens().

    The function traps all potential initialization exceptions—such as network lookup errors when retrieving BPE data files, missing vocabulary caches, or environment corruption—swallowing the exception and setting the global _encoding pointer to None. This guarantees that failure in the third-party tokenization binary does not crash the host application.

    Parameters:
    * None.

    Returns:
    * tiktoken.core.Encoding | None: The initialized cl100k_base tokenizer object if successful; otherwise None.

    Raises:
    * None. All exceptions raised by tiktoken.get_encoding are caught internally.

    Example: 

    # Internal retrieval within utils/token_utils.py
enc = _get_encoding()
if enc:
    token_count = len(enc.encode("Sample source code", disallowed_special=()))

    count_tokens()

    Visibility: Public
    Signature: def count_tokens(text: str) -> int:

    def count_tokens(text: str) -> int:
    """Count tokens using tiktoken, with fallback to chars/4."""
    if not text:
        return 0
    enc = _get_encoding()
    if enc:
        return len(enc.encode(text, disallowed_special=()))
    return len(text) // 4

    Description:
    Calculates the exact or estimated token count of a given input string. If text is empty or evaluates to a falsy value, the function immediately short-circuits and returns 0. When a valid tokenizer is returned by _get_encoding(), the text is encoded using Byte Pair Encoding.

    Crucially, the tokenizer sets disallowed_special=(), disabling tiktoken's default behavior of raising a ValueError when encountering special control strings (e.g., <|endoftext|>, <|fim_prefix|>). This setting is mandatory for repository analysis pipelines because raw source code files, documentation strings, and markdown templates frequently contain tokens that resemble LLM control sequences. If _get_encoding() returns None, the function falls back to integer division of total characters by 4 (len(text) // 4), which represents the standard empirical ratio for English prose and C-family source code.

    Parameters:
    * text (str): The raw text or source code payload to measure.

    Returns:
    * int: The total token count calculated via BPE encoding or the fallback character heuristic.

    Raises:
    * None.

    Example: 

    # Sizing raw file contents during repository traversal
from utils.token_utils import count_tokens

file_content = "def calculate_sum(a: int, b: int) -> int:\n    return a + b"
tokens = count_tokens(file_content)
assert tokens > 0

    log_token_estimation()

    Visibility: Public
    Signature: def log_token_estimation(node_name: str, prompt_content: str, max_tokens: int, token_usage: dict | None = None) -> None:

    def log_token_estimation(node_name: str, prompt_content: str, max_tokens: int, token_usage: dict | None = None) -> None:
    token_count = count_tokens(prompt_content)
    percentage = (token_count / max_tokens) * 100 if max_tokens else 0

    # Build token usage breakdown suffix for stdout display
    suffix = ""
    usage_log_str = ""
    if token_usage:
        max_label_len = max(len(label) for label in token_usage)
        lines = []
        log_parts = []
        for label, value in token_usage.items():
            pct = (value / token_count * 100) if token_count else 0
            padded_label = label.ljust(max_label_len)
            lines.append(f"\t{padded_label} : {value:,} ({pct:.0f}%)")
            log_parts.append(f"{label}={value:,} ({pct:.0f}%)")
        suffix = "\n" + "\n".join(lines)
        usage_log_str = " | " + " | ".join(log_parts)

    # Console output via emit (styled by CSV LEVEL=WARNING → yellow)
    emit(
        "TOKEN_ANALYTICS",
        suffix=suffix,
        node_name=node_name,
        token_count=f"{token_count:,}",
        max_tokens=f"{max_tokens:,}",
        percentage=f"{percentage:.1f}",
    )

    # File log stays single-line for parseability (structured, not translatable)
    logger.info(f"NODE EXEC | node={node_name} | prompt_tokens={token_count:,} / {max_tokens:,} ({percentage:.1f}% capacity){usage_log_str}")

    Description:
    Executes comprehensive token budget accounting for an execution node in the pipeline and routes the metrics across console and file logging channels.

    The function first resolves the prompt's total token count by invoking count_tokens(prompt_content). It computes the context window utilization percentage against max_tokens (handling division-by-zero safely by verifying max_tokens truthiness). If a token_usage breakdown mapping is provided (e.g., separating system instructions, repository file context, and prior chapter summaries), the function computes proportional allocations, aligns labels using str.ljust(), and formats two discrete representations: 1. Console Suffix (suffix): A multi-line, tab-indented block designed for interactive CLI visualization. 2. Structured Log Suffix (usage_log_str): A pipe-delimited single-line string optimized for programmatic log parsers.

    The console output is dispatched through utils.output.emit() using the localization key "TOKEN_ANALYTICS", which applies ANSI styling according to level configurations in utils/strings.csv. Simultaneously, a single-line audit record is written directly to logger.info().

    Parameters:
    * node_name (str): The name or identifier of the calling pipeline node (e.g., "CHAPTER_ANALYSIS", "ARCHITECTURE_MAP"). * prompt_content (str): The full text of the rendered prompt payload to be evaluated. * max_tokens (int): The maximum input context window size supported by the active LLM backend. * token_usage (dict | None, optional): An optional dictionary mapping descriptive segment names (str) to their individual token counts (int). Defaults to None.

    Returns:
    * None

    Raises:
    * None.

    Example: 

    # Sizing an assembled node prompt before LLM dispatch
from utils.token_utils import log_token_estimation

system_tokens = 450
context_tokens = 12500
full_prompt = "...assembled prompt text..."

log_token_estimation(
    node_name="GENERATE_MODULE_DOCS",
    prompt_content=full_prompt,
    max_tokens=32768,
    token_usage={
        "System Prompt": system_tokens,
        "Source Code Context": context_tokens
    }
)

    Token Calculation Heuristics & Edge Cases

    Scenario Behavior / Formula Handling Rationale
    prompt_content = "" (Empty Input) Returns 0 immediately via early return guard. Prevents unnecessary tokenizer invocations and zero-division errors during metric formatting.
    tiktoken library unavailable or throws error Falls back to len(text) // 4. Guarantees non-blocking pipeline execution even in stripped container environments or offline air-gapped systems.
    Source code contains special tokens (<|endoftext|>) Encoded as regular text via disallowed_special=(). Prevents runtime ValueError crashes caused by token injection or raw code examples demonstrating LLM special syntax.
    max_tokens = 0 Percentage computed as 0. Protects against ZeroDivisionError when model limits are dynamically uninitialized or omitted.
    Granular token_usage dictionary supplied Computes dynamic string padding via max(len(k)) and individual percentage fractions. Aligns variable-length label names in terminal tabular views while maintaining single-line logs for file persistence.
