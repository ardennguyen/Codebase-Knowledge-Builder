    token_utils.py

    Source: utils/token_utils.py

    Technical Overview

    The utils/token_utils.py module serves as the centralized token estimation, context headroom budgeting, and dynamic ratio calibration engine for the Codebase Knowledge Builder pipeline. Foundation models from disparate providers (such as Anthropic Claude, Google Gemini, and OpenRouter-hosted models) utilize proprietary Byte-Pair Encoding (BPE) or SentencePiece tokenizers with distinct vocabularies. Because downloading and executing vendor-specific tokenizers locally introduces operational overhead and dependency instability, this module adopts OpenAI's cl100k_base encoding (via tiktoken) as a universal baseline and bridges discrepancies through empirical token ratio calibration.

    To reconcile the baseline cl100k_base counts with actual provider tokenization, the module implements an asymmetric, sample-weighted online calibration loop. It initializes each model with a static ratio prior resolved from utils.llm_config. As pipeline steps complete LLM requests, observe_prompt_tokens compares the locally measured raw tokens against the provider's billed usage. The calibration system adjusts the effective ratio upwards aggressively to avoid context overflow errors, while lowering it conservatively only when backed by substantial empirical sample sizes and token volumes. These calibrated multipliers are persisted atomically across runs in llm_token_calibration.json.

    Beyond ratio estimation, the module calculates prompt sizing boundaries via input_token_budget. It guarantees that prompt payloads leave sufficient headroom for planned model output generations, thinking/reasoning token allocations, fixed provider margins, and dynamic estimation error reserves (scaling from 5% down to 2% once calibrated). High-throughput raw token counting is accelerated via a thread-safe, bounded Least Recently Used (LRU) content cache indexed by text length and Python string object hashes, alongside parallelized multi-threaded batch tokenization for large document arrays.

    Public API

    MIN_OUTPUT_RESERVE

    Visibility: Public

    Signature: MIN_OUTPUT_RESERVE = 8_192

    Description: The minimum token allocation reserved for model output generation when interacting with providers that do not explicitly report or size output allowances (such as Ollama or uncataloged OpenRouter endpoints).

    MAX_OUTPUT_RESERVE

    Visibility: Public

    Signature: MAX_OUTPUT_RESERVE = 64_000

    Description: The maximum upper clamp applied to dynamic 5% output reservations on providers lacking explicit output configuration schemas.

    ESTIMATE_RESERVE_UNCALIBRATED

    Visibility: Public

    Signature: ESTIMATE_RESERVE_UNCALIBRATED = 0.05

    Description: The proportion of the total context window (5%) held in reserve to absorb estimation discrepancies between tiktoken's cl100k_base and target tokenizers when the active model operates without empirical calibration.

    ESTIMATE_RESERVE_CALIBRATED

    Visibility: Public

    Signature: ESTIMATE_RESERVE_CALIBRATED = 0.02

    Description: The reduced safety reserve proportion (2%) allocated for estimation variance once a model's token ratio has been reliably calibrated from observed provider usage.

    MEMO_MAX_ENTRIES

    Visibility: Public

    Signature: MEMO_MAX_ENTRIES = 4_096

    Description: Maximum capacity boundary for the in-memory string token count memoization cache (_memo), maintained under LRU eviction policies.

    MEMO_MIN_CHARS

    Visibility: Public

    Signature: MEMO_MIN_CHARS = 256

    Description: String length threshold below which token memoization is bypassed; strings shorter than 256 characters are cheaper to tokenize directly than to track in the memo structure.

    TOKEN_CALIBRATION_FILE

    Visibility: Public

    Signature: TOKEN_CALIBRATION_FILE = "llm_token_calibration.json"

    Description: The persistent JSON datastore filename where learned per-model tokenizer ratios, sample counts, and EMA weights are stored.

    CALIBRATION_MIN_RAW

    Visibility: Public

    Signature: CALIBRATION_MIN_RAW = 2_000 # below this, fixed per-request framing tokens distort the ratio

    Description: Minimum raw token count required for an observed completion to be factored into ratio calibration, filtering out small requests where provider request framing distorts measurements.

    CALIBRATION_EMA_WEIGHT

    Visibility: Public

    Signature: CALIBRATION_EMA_WEIGHT = 0.35

    Description: Smoothing factor ($\alpha$) utilized in the Exponential Moving Average calculation for model token ratio updates once a full sample weight has accumulated.

    CALIBRATION_FULL_WEIGHT_RAW

    Visibility: Public

    Signature: CALIBRATION_FULL_WEIGHT_RAW = 50_000 # a sample this large gets the full EMA weight

    Description: The raw token volume benchmark that constitutes a fully weighted observation sample; requests of this size receive 100% of the nominal EMA weight.

    CALIBRATION_HEADROOM

    Visibility: Public

    Signature: CALIBRATION_HEADROOM = 1.03

    Description: Multiplier applied to the learned ratio to maintain a 3% conservative buffer, prioritizing context window protection over aggressive packing.

    CALIBRATION_MIN_SAMPLES_TO_LOWER

    Visibility: Public

    Signature: CALIBRATION_MIN_SAMPLES_TO_LOWER = 3

    Description: The minimum discrete request sample count required before the system permits lowering an effective token ratio below its static prior.

    CALIBRATION_MIN_RAW_TO_LOWER

    Visibility: Public

    Signature: CALIBRATION_MIN_RAW_TO_LOWER = 3 * CALIBRATION_FULL_WEIGHT_RAW

    Description: The cumulative measured token volume (150,000 raw tokens) required before the system permits reducing an effective ratio below the static prior.

    CALIBRATION_RANGE

    Visibility: Public

    Signature: CALIBRATION_RANGE = (0.75, 1.5) # learned ratio stays within these multiples of the static prior

    Description: The admissible dynamic envelope for a learned ratio, restricting deviations to between 75% and 150% of the statically declared prior.

    CALIBRATION_PRIOR_DRIFT

    Visibility: Public

    Signature: CALIBRATION_PRIOR_DRIFT = 0.02 # a saved entry learned against a different static prior is stale

    Description: The maximum tolerance for divergence between a saved entry's static prior and the active runtime prior before the cached entry is invalidated as stale.

    OBSERVED_RATIO_BOUNDS

    Visibility: Public

    Signature: OBSERVED_RATIO_BOUNDS = (0.5, 3.0) # samples outside are ignored (e.g. a prompt rewritten in transit)

    Description: Outlier rejection boundaries; individual observations outside the $[0.5, 3.0]$ ratio range are discarded to protect against prompts modified in transit.

    CALIBRATION_COUNTER

    Visibility: Public

    Signature: CALIBRATION_COUNTER = "cl100k_base" # raw counts the saved ratios are relative to

    Description: Identifies the base reference tokenizer against which all saved calibration entries are indexed.

    Parameters:

    Returns:

    • int: The resolved context window token capacity.

    Raises:

    • Does not raise exceptions directly; network or configuration errors from resolve_llm_settings() or get_model_context_length() may bubble up.

    Example:

    # Extracted from utils/token_utils.py:47-55
def resolve_max_tokens(shared):
    """Resolve max_tokens from shared store or auto-detect from the active provider."""
    max_tokens = shared.get("max_tokens")
    if max_tokens is not None:
        return max_tokens
    _, model_name, endpoint, api_key = resolve_llm_settings()
    max_tokens_val = get_model_context_length(endpoint, model_name, api_key)
    emit_raw("DEBUG", f"resolve_max_tokens | resolved max_tokens={max_tokens_val:,}", dest="LOG")

    input_token_budget()

    Visibility: Public

    Signature: def input_token_budget(max_tokens: int, thinking_level: str | None = None) -> int:

    Description: Computes the maximum safe prompt size (in calibrated token units) that fits within the given context window while guaranteeing adequate headroom for model responses, reasoning tokens, and estimation variance.

    Phase 1: Output Reserve and Margin Allocation

        planned = context_output_reserve(thinking_level)
    if planned is not None:
        reserve = planned + CONTEXT_MARGIN
    else:
        reserve = min(max(int(max_tokens * 0.05), MIN_OUTPUT_RESERVE), MAX_OUTPUT_RESERVE)

    The function queries context_output_reserve to determine the token budget required by the provider for the specified thinking tier, appending the static CONTEXT_MARGIN. For providers without explicit output sizing schemas, it reserves 5% of max_tokens, clamping the allocation between MIN_OUTPUT_RESERVE (8,192 tokens) and MAX_OUTPUT_RESERVE (64,000 tokens).

    Phase 2: Dynamic Estimation Reserve Allocation and Floor Enforcement

        reserve += int(max_tokens * (ESTIMATE_RESERVE_CALIBRATED if ratio_is_calibrated() else ESTIMATE_RESERVE_UNCALIBRATED))
    return max(max_tokens - reserve, max_tokens // 2)

    The total reserve is expanded by an estimation error factor: 2% (ESTIMATE_RESERVE_CALIBRATED) if the active model's token ratio has been verified against historical usage, or 5% (ESTIMATE_RESERVE_UNCALIBRATED) otherwise. Finally, the function deducts the cumulative reserve from max_tokens and applies a hard floor of max_tokens // 2, ensuring that prompt allocations never collapse below half the context window even under severe reservation constraints.

    Parameters:

    • max_tokens (int): Total context window capacity for the target model.
    • thinking_level (str | None, optional): The active reasoning effort tier (e.g., "low", "medium", "high"), used to look up thinking token reserves. Defaults to None.

    Returns:

    • int: The maximum allowed prompt token capacity.

    Raises:

    • Does not raise exceptions internally.

    Example:

    # Invocation pattern from codebase pipeline nodes
budget = input_token_budget(max_tokens=128_000, thinking_level="high")

    count_tokens_raw()

    Visibility: Public

    Signature: def count_tokens_raw(text: str) -> int:

    Description: Calculates the raw, uncalibrated token count for a text string using tiktoken's cl100k_base encoding. Strings shorter than MEMO_MIN_CHARS (256 characters) are encoded directly without caching overhead. For larger strings, it computes a lookup key tuple (len(text), hash(text)) and checks the thread-safe _memo cache before executing BPE encoding.

    Parameters:

    • text (str): The raw text string to count.

    Returns:

    • int: The token count measured against cl100k_base (or the UTF-8 fallback approximation).

    Raises:

    • Does not raise exceptions; encoding loading errors are trapped and degrade to byte-level estimation.

    Example:

    # Extracted from utils/token_utils.py:131-143
def count_tokens_raw(text: str) -> int:
    """tiktoken cl100k_base token count (no model calibration). Memoized by content."""
    if not text:
        return 0
    if len(text) < MEMO_MIN_CHARS:
        return _encode_count(text)
    key = (len(text), hash(text))
    cached = _memo_get(key)
    if cached is not None:
        return cached
    count = _encode_count(text)
    _memo_put(key, count)
    return count

    The function handles empty strings early by returning zero. When strings meet the size threshold, it queries _memo_get using a composite key of length and precomputed string hash; on cache misses, it computes the token count via _encode_count and updates the cache via _memo_put.

    count_tokens_raw_many()

    Visibility: Public

    Signature: def count_tokens_raw_many(texts: list[str]) -> list[int]:

    Description: Computes raw token counts for an iterable of text strings, utilizing the memoization cache for known entries and multi-threaded parallel batch encoding for uncached entries.

    Phase 1: Cache Inspection and Batch Assembly

        counts = [0] * len(texts)
    pending = []
    for i, text in enumerate(texts):
        if not text:
            continue
        key = (len(text), hash(text)) if len(text) >= MEMO_MIN_CHARS else None
        cached = _memo_get(key) if key else None
        if cached is not None:
            counts[i] = cached
        else:
            pending.append((i, text, key))

    An output array pre-populated with zeros is instantiated alongside a pending list. Each string is inspected; empty strings remain zero, qualifying cached strings are resolved immediately via _memo_get, and cache misses (or short strings) are queued into pending along with their original index and memo key.

    Phase 2: Multi-Threaded Batch Encoding and Fallback

        enc = _get_encoding()
    if pending and enc is not None:
        encoded = enc.encode_ordinary_batch([text for _, text, _ in pending], num_threads=min(8, os.cpu_count() or 1))
        results = [len(tokens) for tokens in encoded]
    else:
        results = [_fallback_count(text) for _, text, _ in pending]

    If uncached strings exist and tiktoken is operational, the function dispatches them to enc.encode_ordinary_batch, capping thread concurrency to $\min(8, \text{cpu_count})$. If the tokenizer failed to load, it processes each pending item sequentially through _fallback_count.

    Phase 3: Cache Storage and Result Synthesis

        for (i, _text, key), count in zip(pending, results, strict=True):
        counts[i] = count
        if key:
            _memo_put(key, count)
    return counts

    The resulting token lengths are mapped back to their original ordinal slots in counts. For any item possessing a valid cache key, _memo_put records the result in the LRU cache.

    Parameters:

    • texts (list[str]): A sequence of text strings to tokenize.

    Returns:

    • list[int]: Parallel list of raw token counts corresponding to the input texts.

    Raises:

    • Does not raise exceptions internally.

    Example:

    # Invocation pattern for processing repository files in batch
file_contents = ["def alpha(): pass", "def beta(): pass"]
raw_counts = count_tokens_raw_many(file_contents)

    observe_prompt_tokens()

    Visibility: Public

    Signature: def observe_prompt_tokens(provider: str, model: str, raw_tokens: int, billed_tokens: int, served_model: str | None = None) -> None:

    Description: Ingests actual provider-reported prompt token counts from completed LLM calls into the online calibration system, recalculating the model's tokenizer multiplier.

    Phase 1: Pre-condition Validation and Outlier Filtering

        if not calibration_enabled() or raw_tokens < CALIBRATION_MIN_RAW or billed_tokens <= 0:
        return
    if _get_encoding() is None:
        return
    model_id = _model_id(provider, model)
    served = _model_id(provider, served_model or "")
    if served and not (served.startswith(model_id) or model_id.startswith(served)):
        return
    if provider == "OPENROUTER" and ":online" in model_id:
        return
    ratio = billed_tokens / raw_tokens
    if not OBSERVED_RATIO_BOUNDS[0] <= ratio <= OBSERVED_RATIO_BOUNDS[1]:
        return

    The observation is ignored if calibration is disabled, if raw_tokens falls below CALIBRATION_MIN_RAW (2,000 tokens), or if billed_tokens is non-positive. It discards observations where tiktoken failed to load, where the serving model diverged due to server-side fallbacks, where OpenRouter web-search (:online) injected unmeasured tokens, or where the observed ratio falls outside $[0.5, 3.0]$.

    Phase 2: Metric Computation and Weighted EMA Update

        key = _key(provider, model)
    static = _static_ratio(provider, key)
    weight = min(raw_tokens / CALIBRATION_FULL_WEIGHT_RAW, 1.0)
    with _calibration_lock:
        calibration = _load_calibration()
        entry = _valid_entry(static, calibration.get(key))
        before = _effective(static, entry)
        if entry is None:
            entry = calibration[key] = {"ema": ratio, "n": 0, "raw": 0, "w": 0.0}
        seen = entry.get("w", 0.0)
        if seen < 1.0:
            entry["ema"] = (entry["ema"] * seen + ratio * weight) / (seen + weight)
        else:
            alpha = CALIBRATION_EMA_WEIGHT * weight
            entry["ema"] = (1 - alpha) * entry["ema"] + alpha * ratio
        entry["w"] = seen + weight
        entry["n"] += 1
        entry["raw"] += raw_tokens
        entry["prior"] = static
        after = _effective(static, entry)
        _save_calibration()

    Under thread lock, the function computes observation weight proportional to CALIBRATION_FULL_WEIGHT_RAW.     learned = min(max(entry["ema"] * CALIBRATION_HEADROOM, static * low), static * high)
    return learned if _can_lower(entry) else max(static, learned)

    The function ensures the effective ratio remains bounded and asymmetric, returning the static baseline whenever the entry is absent or invalid.

    Data Structures

    Calibration Datastore Schema (llm_token_calibration.json)

    Persistent root JSON document generated by _save_calibration and read by _load_calibration.

    Field Type Description
    version int Datastore schema version identifier (always 1).
    counter str Reference baseline tokenizer identifier (always "cl100k_base").
    entries dict[str, dict] Map of composite provider/model keys to calibration records.

  "version": 1,
  "counter": "cl100k_base",
  "entries": {
    "ANTHROPIC|claude-3-7-sonnet-20250219": {
      "ema": 1.224,
      "n": 14,
      "prior": 1.25,
      "raw": 245000,
      "w": 4.9
    }
  }
}

    Calibration Record Schema

    In-memory dictionary tracked per model in _calibration and stored under entries in llm_token_calibration.json.

    Field Type Description
    ema float Exponential moving average (or weighted mean) of observed token ratios.
    n int Total count of observed request samples meeting calibration criteria.
    raw int Cumulative sum of raw cl100k_base prompt tokens across all observed calls.
    w float Cumulative observation weight units accumulated by the entry.
    prior float Optional snapshot of the static baseline ratio when the entry was updated.

    Memo Cache Key Schema

    Composite lookup tuple utilized within the thread-safe LRU cache _memo.

    Element Type Description
    [0] int Character length of the input string (len(text)).
    [1] int Native Python integer hash of the input string (hash(text)).

    Step Usage Breakdown Schema

    Standardized usage accounting dictionary ingested by emit_step_usage and format_cost.

    Field Type Description
    calls int Total count of LLM API requests executed in this step.
    cache_hits int Number of calls served from local response cache.
    input int Billed prompt tokens reported by the provider.
    estimated_input int Pre-request estimated prompt tokens computed by count_tokens.
    output int Billed output completion tokens reported by the provider.
    thinking int Output tokens consumed by reasoning / internal thoughts.
    cost float Total monetary expense in USD incurred during this step.
    unpriced_calls int Number of requests executed without known pricing metrics.

    Error Handling

    The module employs defensive, non-terminating fallback patterns to maintain pipeline continuity during tokenizer or filesystem anomalies:

    1. tiktoken Initialization Fallback: When tiktoken.get_encoding("cl100k_base") raises network or environment exceptions during runtime bootstrapping, _get_encoding() traps the error, logs a localized WARN_TIKTOKEN_UNAVAILABLE warning once, and toggles _encoding_failed = True. All subsequent token counting operations degrade gracefully to _fallback_count(), which computes ceiling division of UTF-8 byte lengths by 3 (len(text.encode('utf-8', 'surrogatepass')) // 3). This mathematical ceiling ensures prompts never underestimate token requirements.
    2. Calibration Datastore Resilience: During _load_calibration(), missing calibration files (FileNotFoundError) are handled cleanly without logging. Schema corruption, invalid types, or I/O failures (OSError, ValueError, TypeError, AttributeError) are caught, logging a warning to file logs while continuing execution with an empty in-memory store. Additionally, if the datastore's counter attribute does not match CALIBRATION_COUNTER, a ValueError is raised internally to bypass stale ratios derived from divergent tokenizers.
    3. Atomic File Persistence: Serialization of calibration data in _save_calibration() is performed by writing to a temporary file ({TOKEN_CALIBRATION_FILE}.tmp) followed by an atomic os.replace operation. This prevents datastore corruption if the process terminates abruptly during serialization. File writing exceptions (OSError) are trapped and logged via emit_raw.
    4. Outlier and Boundary Filtering: In observe_prompt_tokens(), potential calibration anomalies—such as requests below 2,000 raw tokens, ratios outside $[0.5, 3.0]$, web-augmented OpenRouter searches (:online), or tokenizer shifts from server-side fallbacks—are filtered before modifying the running Exponential Moving Average.
