    token_utils.py

    Source: utils/token_utils.py

    Following the reasoning effort management and profile planning implemented in thinking.py, the token_utils.py module provides the mathematical and heuristic engine for calculating token volumes, establishing input context budgets, and dynamically calibrating token ratios across heterogeneous model families.

    Technical Overview

    The token_utils.py module is the centralized token management authority in Codebase-Knowledge-Builder. Because downstream inference relies on models with fundamentally different tokenization schemes (such as Anthropic Claude, Google Gemini, and diverse OpenRouter targets) while the pipeline standardizes its local counting on OpenAI's cl100k_base Byte-Pair Encoding (BPE), token calculations require continuous translation. The module bridges this gap by maintaining a static family prior (llm_config.get_token_ratio()) that is adaptively corrected at runtime using real provider-reported billing figures.

    To eliminate redundant BPE tokenization passes across pipeline nodes, logging decorators, gateway callers, and provider transports, token_utils.py incorporates an in-memory, thread-safe Least Recently Used (LRU) content cache. Strings exceeding MEMO_MIN_CHARS (256 characters) are indexed by a compound key consisting of text length and internal Python string hash, rendering repetitive prompt inspections instantaneous ($O(1)$) with zero string duplication in memory. When tiktoken fails to load (such as in offline or restricted environments), the module activates a conservative, deterministic fallback counter based on UTF-8 byte length divided by three.

    Beyond raw counting, the module orchestrates online calibration and context budget resolution. During pipeline execution, provider responses pass their billed prompt tokens back into observe_prompt_tokens(). Prompts meeting rigorous gating criteria are integrated into an Exponential Moving Average (EMA) or size-weighted mean, adjusting the active token ratio and persisting state to llm_token_calibration.json. The module uses these calibrated ratios in input_token_budget() to reserve strict margins for reasoning generation tokens, flat communication overhead, and tokenizer variance, guaranteeing that prompt generation will not induce context window overflow.

    input_token_budget()

    Visibility: Public Signature: def input_token_budget(max_tokens: int, thinking_level: str | None = None) -> int:

    Description: Calculates the maximum safe prompt size (in units of count_tokens()) that can be dispatched to the active provider without risking context truncation. For unified-window models (such as Anthropic and OpenRouter), it subtracts the output budget required for the specified reasoning level alongside CONTEXT_MARGIN. For separate-window architectures (such as Google Gemini), only the safety margin is subtracted. It scales the estimation uncertainty reserve down from 5% to 2% once token calibration achieves confidence, while clamping the final budget to never drop below half of max_tokens.

    Parameters: * max_tokens (int): The total context window ceiling of the model. * thinking_level (str | None, optional): The reasoning effort level requested for the prompt (e.g., "low", "high"), defaults to None.

    Returns: * int: The maximum allowed input token count for the candidate prompt.

    Raises: * None.

    Example: 

    planned = context_output_reserve(thinking_level)
if planned is not None:
    reserve = planned + CONTEXT_MARGIN
else:
    reserve = min(max(int(max_tokens * 0.05), MIN_OUTPUT_RESERVE), MAX_OUTPUT_RESERVE)
reserve += int(max_tokens * (ESTIMATE_RESERVE_CALIBRATED if ratio_is_calibrated() else ESTIMATE_RESERVE_UNCALIBRATED))
return max(max_tokens - reserve, max_tokens // 2)

    count_tokens_raw()

    Visibility: Public Signature: def count_tokens_raw(text: str) -> int:

    Description: Computes the uncalibrated BPE token count for an arbitrary string using the OpenAI cl100k_base encoding. Strings shorter than MEMO_MIN_CHARS (256 characters) are encoded directly without memo overhead. Larger strings are resolved against the internal LRU cache _memo using (len(text), hash(text)) as the lookup key to avoid repeated encoding passes.

    Parameters: * text (str): The raw string content to be tokenized.

    Returns: * int: The raw token count computed via cl100k_base or the byte-fallback counter.

    Raises: * None.

    Example: 

    if not text:
    return 0
if len(text) < MEMO_MIN_CHARS:
    return _encode_count(text)
key = (len(text), hash(text))
cached = _memo_get(key)
if cached is not None:
    return cached
count = _encode_count(text)
_memo_put(key, count)
return count

    count_tokens_raw_many()

    Visibility: Public Signature: def count_tokens_raw_many(texts: list[str]) -> list[int]:

    Description: Processes a list of strings in bulk, separating cached entries from uncached items. Uncached strings are dispatched to encode_ordinary_batch() over a multithreaded pool (up to 8 worker threads) or evaluated sequentially with the fallback counter if tiktoken is unavailable. The resulting counts are backfilled into _memo and returned in the input sequence.

    Phase 1: Cache Inspection and Pending Queue Assembly

    counts = [0] * len(texts)
pending = []
for i, text in enumerate(texts):
    if not text:
        continue
    key = (len(text), hash(text)) if len(text) >= MEMO_MIN_CHARS else None
    cached = _memo_get(key) if key else None
    if cached is not None:
        counts[i] = cached
    else:
        pending.append((i, text, key))
    The initial phase pre-allocates an output list of zeroes and iterates through the input texts. Texts meeting the length threshold are queried against the memo table; hits are immediately written to the output array at their original index, while cache misses and short strings are appended to pending.

    Phase 2: Multithreaded Batch Encoding and Fallback

    enc = _get_encoding()
if pending and enc is not None:
    encoded = enc.encode_ordinary_batch([text for _, text, _ in pending], num_threads=min(8, os.cpu_count() or 1))
    results = [len(tokens) for tokens in encoded]
else:
    results = [_fallback_count(text) for _, text, _ in pending]
    If the pending queue contains items and _get_encoding() successfully loaded the cl100k_base tokenizer, the batch is passed to encode_ordinary_batch. Concurrency scales up to 8 threads or the host CPU count. If encoding failed, each pending string falls back to the UTF-8 byte estimate.

    Phase 3: Cache Ingestion and Array Reassembly

    for (i, _text, key), count in zip(pending, results, strict=True):
    counts[i] = count
    if key:
        _memo_put(key, count)
return counts
    The final phase synchronizes results with pending tasks. It writes each token count into its target index in the counts array and commits candidate entries to the LRU memo table using _memo_put().

    Parameters: * texts (list[str]): A sequence of raw text strings to count.

    Returns: * list[int]: A list of integer token counts aligned with the input order.

    Raises: * None.

    Example: 

    counts = count_tokens_raw_many(["import os", "def test(): pass"])

    observe_prompt_tokens()

    Visibility: Public Signature: def observe_prompt_tokens(provider: str, model: str, raw_tokens: int, billed_tokens: int, served_model: str | None = None) -> None:

    Description: Ingests actual prompt usage reported by an LLM provider to calibrate future estimation ratios. The observation goes through rigorous filtering, size-weighted aggregation, and Exponential Moving Average updates before being persisted to disk.

    Phase 1: Validation and Guard Filtering

    if not calibration_enabled() or raw_tokens < CALIBRATION_MIN_RAW or billed_tokens <= 0:
    return
if _get_encoding() is None:
    return
model_id = _model_id(provider, model)
served = _model_id(provider, served_model or "")
if served and not (served.startswith(model_id) or model_id.startswith(served)):
    return
if provider == "OPENROUTER" and ":online" in model_id:
    return
ratio = billed_tokens / raw_tokens
if not OBSERVED_RATIO_BOUNDS[0] <= ratio <= OBSERVED_RATIO_BOUNDS[1]:
    return
    Observations are discarded if calibration is disabled, if prompt size is under CALIBRATION_MIN_RAW (where fixed framing tokens distort ratios), if tiktoken failed, if a server-side model fallback altered the target tokenizer, if OpenRouter :online injected external search results, or if the resulting ratio falls outside the boundary [0.5, 3.0].

    Phase 2: Statistical Weighting and Ratio Calculation

    key = _key(provider, model)
static = _static_ratio(provider, key)
weight = min(raw_tokens / CALIBRATION_FULL_WEIGHT_RAW, 1.0)
    The observation computes a proportional weight capped at 1.0. Samples containing CALIBRATION_FULL_WEIGHT_RAW (50,000) or more tokens achieve full weight, preventing tiny requests from distorting learned trends.

    Phase 3: EMA State Update and Atomic Serialization

    with _calibration_lock:
    calibration = _load_calibration()
    entry = _valid_entry(static, calibration.get(key))
    before = _effective(static, entry)
    if entry is None:
        entry = calibration[key] = {"ema": ratio, "n": 0, "raw": 0, "w": 0.0}
    seen = entry.get("w", 0.0)
    if seen < 1.0:
        entry["ema"] = (entry["ema"] * seen + ratio * weight) / (seen + weight)
    else:
        alpha = CALIBRATION_EMA_WEIGHT * weight
        entry["ema"] = (1 - alpha) * entry["ema"] + alpha * ratio
    entry["w"] = seen + weight
    entry["n"] += 1
    entry["raw"] += raw_tokens
    entry["prior"] = static
    after = _effective(static, entry)
    _save_calibration()
    Under lock, if cumulative weight is below 1.0, the entry maintains a size-weighted mean. Once past 1.0, updates transition to an Exponential Moving Average using alpha = 0.35 * weight. The record updates its sample count, total raw token count, and baseline prior before committing atomically to disk via _save_calibration().

    Phase 4: Telemetry Logging and Notification

    emit_raw(
    "DEBUG",
    f"TOKEN RATIO | key={key} | observed={ratio:.3f} | ema={entry['ema']:.3f} | samples={entry['n']} | effective {before:.3f} -> {after:.3f}",
    dest="LOG",
)
if abs(after - before) / before >= 0.02:
    emit("TOKEN_RATIO_UPDATED", model=model, before=f"{before:.2f}", after=f"{after:.2f}", observed=f"{ratio:.2f}", samples=entry["n"])
    Emits detailed calibration telemetry to the persistent log file. If the effective ratio shifts by 2% or more relative to its prior state, an event notification (TOKEN_RATIO_UPDATED) is broadcast to the console.

    Parameters: * provider (str): Identifier of the LLM provider (e.g., "GEMINI", "ANTHROPIC"). * model (str): Target model name. * raw_tokens (int): Uncalibrated token count calculated via count_tokens_raw(). * billed_tokens (int): Actual prompt token count reported in the API response metadata. * served_model (str | None, optional): Actual model variant executing the call if redirected by server-side routing, defaults to None.

    Returns: * None.

    Raises: * None.

    Example: 

    observe_prompt_tokens(
    provider="ANTHROPIC",
    model="claude-3-7-sonnet-20250219",
    raw_tokens=15420,
    billed_tokens=18200,
    served_model=None
)

    Error Handling

    Defensive Encoding Fallback

    If the tiktoken library fails to load or cannot download its BPE dictionary files (common in air-gapped or network-restricted environments), _get_encoding() traps the exception and marks _encoding_failed = True. The module immediately falls back to _fallback_count(), which computes ceil(len(bytes) / 3). This calculation is intentionally conservative: it over-estimates Latin/code text to guarantee that non-English languages (like Vietnamese, which often consumes ~2.5 characters per token) do not exceed context window limits.

    Calibration Drift Protection

    Model aliases (especially on aggregators like OpenRouter) can silently retarget to newer models with distinct tokenizers, and configuration files can be updated to specify different static token priors. To prevent stale calibration records from poisoning execution, _valid_entry() inspects the recorded prior field. If the difference between the recorded prior and current static prior exceeds CALIBRATION_PRIOR_DRIFT (2%), the historical calibration entry is automatically invalidated and discarded.

    Atomic State Serialization

    To prevent JSON file corruption from process interrupts or unexpected terminations during file writes, _save_calibration() follows an atomic write pattern. Data is serialized first to a temporary file (llm_token_calibration.json.tmp) and then committed to disk via os.replace(), guaranteeing an atomic POSIX filesystem swap. Any OS-level write errors are captured, logged to LOG destinations via emit_raw(), and suppressed without halting the pipeline.
