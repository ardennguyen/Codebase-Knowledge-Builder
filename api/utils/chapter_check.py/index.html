    chapter_check.py

    Source: utils/chapter_check.py

    Technical Overview

    The utils/chapter_check.py module provides deterministic, rule-based verification for generated documentation chapters across the codebase. Operating strictly without LLM invocations, it executes static inspection over Markdown pages and reports discrepancies without modifying files on disk. Its primary responsibility is quality assurance: validating that generated documentation adheres to structural constraints, maintains valid navigation links, provides syntax-valid Mermaid diagrams, leaves no code fences open, and faithfully documents verified source code facts extracted by utils.facts.

    The verification engine operates at two distinct tiers. The first tier applies universal syntactic checks to every Markdown page, including MkDocs link resolution against the generated file tree, fence balance tracking, and AST-level lexical validation of Mermaid diagram definitions. The second tier activates for pages associated with verified facts extracted from source code (e.g., API references). It validates factual alignment by identifying omitted symbols, detecting signature divergence (such as parameter additions, renamings, or unauthorized embellishments like hallucinated type annotations), flagging fabricated type names in section headings, and comparing See Also links against verified module dependency graphs.

    All findings are aggregated at runtime into an uncommitted inspection report (chapter_check.json) and emitted via utils.output as human-readable warnings and CLI summary telemetry.

    parse_page()

    Visibility: Public
    Signature: def parse_page(markdown: str) -> dict:

    Description: Parses raw Markdown content into structured segments consisting of prose lines, code blocks, section headings, and unclosed code fence markers. Line numbers are recorded using 1-based indexing. Fenced code blocks opened by backticks (`) or tildes (~) are matched against equivalent closers requiring an equal or greater character count and a maximum relative indentation depth of three spaces. If a fence remains unclosed at EOF, it is treated as prose by the parser (mirroring MkDocs parsing semantics), and its opening line number is recorded in unclosed.

    Parameters: * markdown (str): The raw text content of a Markdown file.

    Returns: * dict: Dictionary with keys "prose" (list[tuple[int, str]]), "blocks" (list[dict]), "headings" (list[tuple[int, int, str]]), and "unclosed" (list[int]).

    Raises: * None.

    Example: 

    parsed = parse_page(markdown)
report = {
    "page": page,
    "module": module,
    "broken_links": broken_links(page, parsed, exists),
    "diagram_problems": diagram_problems(parsed),
    "unclosed_fences": [{"line": line} for line in parsed["unclosed"]],
}


    def parse_page(markdown: str) -> dict:
    lines = markdown.split("\n")
    prose, blocks, headings, unclosed = [], [], [], []
    number = 0
    while number < len(lines):
        line = lines[number]
        opener = _FENCE_RE.match(line)
        if opener:
            indent, fence = len(opener.group(1)), opener.group(2)
            for end in range(number + 1, len(lines)):
                closer = _FENCE_RE.match(lines[end])
                if (
                    closer
                    and closer.group(2)[0] == fence[0]
                    and len(closer.group(2)) >= len(fence)
                    and not closer.group(3)
                    and len(closer.group(1)) <= indent + 3
                ):
                    blocks.append({"lang": opener.group(3).lower(), "start": number + 1, "text": "\n".join(lines[number + 1 : end])})
                    number = end + 1
                    break
            else:
                unclosed.append(number + 1)
                prose.append((number + 1, line))
                number += 1
            continue
        prose.append((number + 1, line))
        heading = _HEADING_RE.match(line)
        if heading:
            headings.append((number + 1, len(heading.group(1)), heading.group(2)))
        number += 1
    return {"prose": prose, "blocks": blocks, "headings": headings, "unclosed": unclosed}

    The function reads the document line-by-line while tracking fence transitions. When a fence opener is encountered via _FENCE_RE, it scans forward to find an matching closing sequence matching the opener delimiter character and meeting standard CommonMark indentation restrictions. If a valid closing delimiter is found, the inner block is isolated into blocks with its detected programming language (converted to lowercase) and starting line offset; otherwise, the opener is recorded into unclosed and reclassified as standard prose. All non-block lines are checked against _HEADING_RE to track heading depth and title text.

    Visibility: Public
    Signature: def resolve_link(page: str, target: str) -> str | None:

    Description: Converts a page-relative target path into a normalized site-relative path based on the hosting Markdown page's directory location. Query parameters and anchor hashes are stripped, and URL percent-encoding (such as %20) is decoded. Returns None for external URI schemes (http:, https:, mailto:), root-relative targets, or internal same-page hash anchors.

    Parameters: * page (str): Site-relative path of the source Markdown document (e.g., utils/call_llm.py.md). * target (str): Target link URI as written in the Markdown source.

    Returns: * str | None: The normalized site-relative path, or None if the target is external or an anchor.

    Raises: * None.

    Example: 

    resolved = resolve_link("utils/chapter_check.py.md", "facts.py.md#missing-symbols")
# resolved == "utils/facts.py.md"


    def resolve_link(page: str, target: str) -> str | None:
    if re.match(r"^[a-zA-Z][\w+.-]*:", target) or target.startswith(("#", "/")):
        return None
    path = unquote(target.split("#", 1)[0].split("?", 1)[0])
    return posixpath.normpath(posixpath.join(posixpath.dirname(page), path)) if path else None

    This helper handles path normalization using POSIX path semantics regardless of the host OS. By using posixpath.join and posixpath.normpath, it accurately resolves relative parent directory steps (e.g., ../nodes.md) against the directory of the current chapter page. Absolute file paths and URIs containing schemes are filtered out upfront by checking for leading slashes or URI prefix regex patterns.

    def broken_links(page: str, parsed: dict, exists) -> list[dict]:
    problems = []
    for number, target in _links(parsed["prose"]):
        resolved = resolve_link(page, target)
        if resolved is not None and not exists(resolved):
            problems.append({"line": number, "target": target})
    return problems

    The function iterates over the outputs of _links(parsed["prose"]), which extracts URIs from Markdown link expressions, image syntax, HTML anchor href attributes, and link reference definitions. Targets that resolve to valid internal site paths via resolve_link are queried against the provided exists callback. Any target returning False is recorded alongside its 1-based source line number.

    mermaid_problems()

    Visibility: Public
    Signature: def mermaid_problems(source: str) -> list[dict]:

    Description: Audits Mermaid diagram code blocks for common syntax errors that cause client-side rendering failures. It validates frontmatter demarcation, ensures diagram type declarations exist within the supported _MERMAID_TYPES, and evaluates flowchart bodies for unescaped code operators (>>), unquoted bracket shapes within labels, unbalanced quotes, and mismatched brackets.

    Phase 1: Frontmatter Stripping & Diagram Type Detection

    def mermaid_problems(source: str) -> list[dict]:
    lines = source.split("\n")
    body = [(number, line) for number, line in enumerate(lines, start=1) if line.strip() and not line.strip().startswith("%%")]
    if body and body[0][1].strip() == "---":  # frontmatter (title / config) before the diagram type
        closing = next((i for i, (_n, line) in enumerate(body[1:], start=1) if line.strip() == "---"), None)
        body = body[closing + 1 :] if closing is not None else []
    if not body:
        return []
    first = body[0][1].strip().split()[0].rstrip(":")
    if first not in _MERMAID_TYPES:
        return [{"line": body[0][0], "problem": "type"}]
    if not first.startswith(("flowchart", "graph")):
        return []
    # ...

    In this initial phase, the function strips out comment lines starting with %% and handles Mermaid frontmatter delimited by ---. Once YAML frontmatter is discarded, the first token is evaluated against _MERMAID_TYPES. If the type is unrecognized, a type error is raised. If the diagram is not a flowchart or graph, detailed syntax verification is bypassed since other diagram families employ distinct lexing rules.

    Phase 2: Flowchart Syntax Verification

        # ...
    markdown_strings = '"`' in source  # "`multi-line markdown labels`" span lines: quote and bracket counts do not apply
    problems = []
    for number, line in body[1:]:
        if line.count('"') % 2 and not markdown_strings:
            problems.append({"line": number, "problem": "quotes"})
            continue
        code = re.sub(r'"[^"]*"', '""', line)
        code = re.sub(r"\|[^|]*\|", "||", code)  # edge labels: A -->|label| B
        code = re.sub(r"\w>[^\]]*\]", "x", code)  # the asymmetric shape: id>label]
        unlabelled = re.sub(r"\[[^\]]*\]|\([^)]*\)|\{[^}]*\}", "", code)  # `>>` inside a label is text
        if re.search(r"(?<![-=.])>>", unlabelled):
            problems.append({"line": number, "problem": "arrow"})
        elif re.search(r"\w\[(?![(\[/\\])[^\]\"]*[(\[{]", code):  # A[run(x)] — not the shapes A[(db)], A[[sub]], A[/p/]
            problems.append({"line": number, "problem": "label"})
        elif not markdown_strings and any(code.count(o) != code.count(c) for o, c in ("[]", "()", "{}")):
            problems.append({"line": number, "problem": "brackets"})
    return problems

    The second phase iterates through flowchart lines and evaluates balanced quoting and structure. Unless multi-line markdown strings ("`) are present, lines with odd quotation mark counts are flagged with a quotes problem. The parser strips string literals, pipe-delimited edge labels, and asymmetric shape definitions before searching for invalid bare code operators (>>), illegal bracket combinations inside node labels (A[run(x)] instead of A["run(x)"]), and unbalanced structural parentheses or braces (brackets).

    Parameters: * source (str): Raw string content of the Mermaid diagram block.

    Returns: * list[dict]: List of problem records with keys "line" (int) and "problem" (str). Problem kinds include "type", "quotes", "arrow", "label", and "brackets".

    Raises: * None.

    Example: 

    problems = mermaid_problems("flowchart TD\n    A >> B")
# problems == [{"line": 2, "problem": "arrow"}]

    Parameters: * parsed (dict): Dictionary produced by parse_page().

    def diagram_problems(parsed: dict) -> list[dict]:
    diagrams = [block for block in parsed["blocks"] if block["lang"] == "mermaid"]
    return [
        {"diagram": number, "line": block["start"] + problem["line"], "problem": problem["problem"]}
        for number, block in enumerate(diagrams, start=1)
        for problem in mermaid_problems(block["text"])
    ]

    This function filters parsed["blocks"] for items with lang == "mermaid". For each diagram found, it invokes mermaid_problems and offsets the returned problem line by block["start"], ensuring that downstream logging and reporting point directly to the exact Markdown file line.

    missing_symbols()

    Visibility: Public
    Signature: def missing_symbols(parsed: dict, symbols: list[dict]) -> list[dict]:

    Description: Cross-references verified symbols extracted from the codebase against the prose and code text of a page. Any symbol whose short identifier is never referenced in either prose or non-Mermaid code is identified as missing from the documentation.

    Parameters: * parsed (dict): The parsed representation of the page. * symbols (list[dict]): List of verified symbol dictionaries, typically containing name, kind, parent, and line.

    Returns: * list[dict]: List of symbol dictionaries that were not mentioned anywhere on the page.

    Raises: * None.

    Example: 

    symbols = facts.get("symbols", [])
omissions = missing_symbols(parsed, symbols)


    def missing_symbols(parsed: dict, symbols: list[dict]) -> list[dict]:
    text = _page_text(parsed)
    words = set(re.findall(r"\w+", text)) | {word.lstrip("$") for word in re.findall(r"\$\w+", text)}
    words |= set(re.findall(r"[A-Za-z_$][A-Za-z0-9_$]*", text))  # an identifier glued to CJK prose: 调用run_flow函数
    missing = []
    for symbol in symbols:
        name = str(symbol.get("name", "")).split(".")[-1].lstrip("$")
        if name and not (name in words or _names_in(text, name)):
            missing.append({k: symbol.get(k) for k in ("name", "kind", "parent", "line")})
    return missing

    The function extracts all textual content excluding Mermaid diagrams using _page_text(). It constructs a word token cache, taking into account dollar-prefixed identifiers (PHP/Perl/shell variables) and identifiers adjacent to CJK multibyte characters. Each verified symbol is stripped of its qualified parent prefix and checked against the token set and via _names_in(text, name) from utils.facts. Unmatched symbols are returned.

    signature_issues()

    Visibility: Public
    Signature: def signature_issues(parsed: dict, source: str, symbols: list[dict]) -> tuple[list[dict], list[dict]]:

    Description: Validates explicitly labelled signatures in the documentation against original source code text and verified AST symbols. Detects two classes of anomalies: signature mismatches (parameters added, removed, renamed, or reordered) and signature embellishments (valid parameters that have had unauthorized types, defaults, or annotations added that do not exist in the source code).

    Parameters: * parsed (dict): The parsed representation of the Markdown page. * source (str): Raw source code of the underlying file being documented. * symbols (list[dict]): Verified symbol definitions from facts.json.

    Returns: * tuple[list[dict], list[dict]]: A 2-tuple (mismatches, embellished) containing dictionaries with problem details and line numbers.

    Raises: * None.

    Example: 

    mismatches, embellished = signature_issues(parsed, source, symbols)


    def signature_issues(parsed: dict, source: str, symbols: list[dict]) -> tuple[list[dict], list[dict]]:
    flat_source = _collapse(source)
    by_name = {}
    for symbol in symbols:
        by_name.setdefault(str(symbol.get("name", "")).split(".")[-1], []).append(_head(str(symbol.get("signature", ""))))
    mismatches, embellished = [], []
    for number, text in _signatures(parsed):
        if _collapse(text).rstrip(":{; ") in flat_source:
            continue
        name = _declared_name(text)
        candidates = by_name.get(name[0]) if name else None
        if not candidates:
            continue
        verdicts = [_compare(_head(text), candidate) for candidate in candidates]
        if "same" in verdicts:
            continue
        if "embellished" in verdicts:
            embellished.append({"line": number, "signature": text})
        else:
            mismatches.append({"line": number, "signature": text, "source": _collapse(candidates[0])[:200]})
    return mismatches, embellished

    The function maps all verified symbols by their short name. It scans the page for signature declarations using _signatures(). If a signature matches the source code verbatim (normalizing whitespace via _collapse), it is considered valid. If it does not match verbatim, the function extracts parameter tokens using _head() and compares them against verified candidates using _compare(). If any candidate matches with added tokens (such as added type hints), it is marked as embellished. If structural differences exist, it is recorded in mismatches.

    unknown_type_names()

    Visibility: Public
    Signature: def unknown_type_names(parsed: dict, known_words: set) -> list[dict]:

    Description: Audits section headings for type-like PascalCase identifiers embedded in inline code spans (e.g., ###FactClaim``) that do not appear in any source file across the repository. This detects hallucinated type definitions or invented record classes.

    Parameters: * parsed (dict): Parsed page dictionary containing headings. * known_words (set): All valid identifier word tokens extracted across all crawled source code files.

    Returns: * list[dict]: List of issue records with keys "line" (int) and "name" (str).

    Raises: * None.

    Example: 

    hallucinated = unknown_type_names(parsed, prep_res.get("known_words", set()))


    def unknown_type_names(parsed: dict, known_words: set) -> list[dict]:
    if not known_words:
        return []
    found = []
    for number, _level, text in parsed["headings"]:
        spans = " ".join(match.group(2) for match in _CODE_SPAN_RE.finditer(text))
        names = sorted(set(re.findall(r"[A-Za-z_][A-Za-z0-9_]*", spans)))  # ASCII: a name glued to CJK text still counts
        found.extend({"line": number, "name": word} for word in names if _TYPE_NAME_RE.match(word) and word not in known_words)
    return found

    The helper searches all heading lines for inline code spans via _CODE_SPAN_RE. It extracts ASCII tokens and matches them against _TYPE_NAME_RE (which matches PascalCase identifiers with both uppercase and lowercase letters). Any identifier matching this type pattern that cannot be found in known_words is flagged as an unknown type name.

    see_also_issues()

    Visibility: Public
    Signature: def see_also_issues(page: str, parsed: dict, module: str, module_by_page: dict, facts: dict) -> tuple[list, list]:

    Description: Compares links in the chapter's "See Also" section against verified dependency facts. Detects two issues: links to unrelated modules (files that have no import relationship in either direction), and missing dependencies (verified imported modules that are documented in the site but omitted from "See Also").

    Parameters: * page (str): Site-relative path of the current chapter page. * parsed (dict): Parsed page dictionary. * module (str): Original source file path corresponding to this page. * module_by_page (dict): Mapping of site-relative page paths to their original source file paths. * facts (dict): Verified facts dictionary containing depends_on and used_by entries.

    Returns: * tuple[list, list]: A 2-tuple (unrelated, missing): * unrelated: list[dict] containing "line" and "module". * missing: list[dict] containing "module".

    Raises: * None.

    Example: 

    unrelated, missing = see_also_issues(page, parsed, module, module_by_page, facts)


    def see_also_issues(page: str, parsed: dict, module: str, module_by_page: dict, facts: dict) -> tuple[list, list]:
    depends = {edge["module"] for edge in facts.get("depends_on", [])} & set(module_by_page.values())  # only documented ones can be linked
    related = depends | set(facts.get("used_by", []))
    linked = {}
    pages = set(module_by_page)
    section = _see_also_section(parsed, pages, page)
    for number, target in _links(section):
        resolved = resolve_link(page, target)
        target_module = module_by_page.get(resolved) if resolved else None
        if target_module and target_module != module:
            linked.setdefault(target_module, number)
    unrelated = [{"line": number, "module": target} for target, number in sorted(linked.items(), key=lambda item: item[1]) if target not in related]
    missing = [{"module": target} for target in sorted(depends - set(linked))]
    return unrelated, missing

    The function computes the intersection between verified module dependencies and active documentation chapters. It locates the "See Also" section using _see_also_section(), extracts all relative links, and resolves them to their target modules. It then flags linked modules that share no verified dependency or usage relationship (unrelated) and verified dependencies that were never linked (missing).

    check_chapter()

    def _declaration_shaped(text: str) -> bool:
    text = _strip_decorators(text).strip()
    first = (_words(text) or [""])[0]
    name = _declared_name(text)
    if not name or first in _NOT_DECLARATION:
        return False
    if first in _DECLARATION_START:
        return True
    if first in ("constructor", "init") and re.search(r"\(\s*[\w$]+\s*:", text):
        return True  # constructor(size: string), init(name: Int) — typed, unlike a call init(language="x")
    before = text[: name[1]].rstrip()
    before = before[: len(before) - len(name[0])] if before.endswith(name[0]) else before
    if before.endswith((".", "->")) or "=" in before:
        return False
    if before.endswith("::") and not _words(before.rstrip(":").rsplit(None, 1)[0] if " " in before.strip() else ""):
        return False  # A::b(…) with no type before it is a call; `void A::b(` is a definition
    head = _head(text).rstrip()
    return len(_words(before)) >= 1 or head.endswith(("{", ":", ";"))

For untyped languages, it inspects the prefix preceding the name to reject receiver method invocations (obj.method(), ptr->method()) while accepting C/C++ style declarations (int size()) and trailing body openers ({, :, ;).

    Returns: * list[tuple[int, str]]: List of (line_number, signature_text) tuples.

    def _signatures(parsed: dict) -> list[tuple[int, str]]:
    found = []
    prose = dict(parsed["prose"])
    for number, line in parsed["prose"]:
        found.extend((number, match.group(2).strip()) for match in _LABELLED_CODE_RE.finditer(line) if _declaration_shaped(match.group(2)))
    for block in parsed["blocks"]:
        label = prose.get(block["start"] - 1, "").strip()
        if block["lang"] == "mermaid" or not (_BLOCK_LABEL_RE.match(label) and re.search(r"[:\uff1a]", label)):
            continue
        head = _head(block["text"])
        if _declaration_shaped(head):
            found.append((block["start"] + 1, head.strip()))
    return found

    The function checks two patterns: inline code spans directly following a bold label matching _LABELLED_CODE_RE, and fenced code blocks that immediately follow a standalone bold label line (e.g., **Implementation**:). In both cases, candidates must pass _declaration_shaped() to be included.

    Visibility: Private
    Signature: def _params(head: str) -> tuple[list[list[str]], bool] | None:

    Description: Parses a declaration header to extract its parameter token lists and determine whether the parameter list is closed.

    Parameters: * head (str): Declaration signature header.

    Returns: * tuple[list[list[str]], bool] | None: (param_tokens, is_closed) or None.

    Raises: * None.

    Example: 

    page, source = _params(page_head), _params(source_head)


    def _params(head: str) -> tuple[list[list[str]], bool] | None:
    name = _declared_name(head)
    if not name:
        return None
    params, current, depth = [], "", 0
    text = head[name[1] + 1 :]
    for position, char in enumerate(text):
        pair = text[max(0, position - 1) : position + 1]
        if char in "([{" or (char == "<" and pair != "<="):
            depth += 1
        elif char in ")]}" or (char == ">" and pair not in ("->", "=>", ">=")):
            if depth == 0 and char == ")":
                params.append(current)
                return [_PARAM_TOKEN_RE.findall(p) for p in params if p.strip()], True
            depth -= 1
        elif char == "," and depth == 0:
            params.append(current)
            current = ""
            continue
        current += char
    params.append(current)
    return [_PARAM_TOKEN_RE.findall(p) for p in params if p.strip()], False

    The function navigates past the opening parenthesis and splits comma-separated arguments while tracking nesting depth across parentheses, brackets, braces, and generics (<...>). Each parameter segment is tokenized using _PARAM_TOKEN_RE. If the parameter list terminates with a matching closing parenthesis, is_closed is True; if it cuts off prematurely, is_closed is False.

    _compare()

    Visibility: Private
    Signature: def _compare(page_head: str, source_head: str) -> str:

    Description: Evaluates structural equivalence between a documented signature and a source signature candidate.

    Parameters: * page_head (str): Documented signature header. * source_head (str): Verified signature header from source code.

    Returns: * str: One of "same", "embellished", or "mismatch".

    Raises: * None.

    Example: 

    verdicts = [_compare(_head(text), candidate) for candidate in candidates]


    def _compare(page_head: str, source_head: str) -> str:
    have, wanted = _PARAM_TOKEN_RE.findall(page_head), _PARAM_TOKEN_RE.findall(source_head)
    if have == wanted:
        return "same"
    page, source = _params(page_head), _params(source_head)
    if page is None or source is None:
        return "embellished" if _is_subsequence(wanted, have) else "mismatch"
    (page_params, _page_closed), (source_params, source_closed) = page, source
    if not source_closed:  # a cut-short verified signature: its complete parameters are a prefix
        source_params = source_params[:-1]
        if len(page_params) < len(source_params):
            return "mismatch"
        page_params = page_params[: len(source_params)]
    elif len(page_params) != len(source_params):
        return "mismatch"
    if not all(_is_subsequence(want, got) for want, got in zip(source_params, page_params, strict=True)):
        return "mismatch"
    # the parameters hold; a return type the source writes must still be there (only added tokens are harmless)
    return "embellished" if not source_closed or _is_subsequence(wanted, have) else "mismatch"

    The comparison checks for exact token equivalence first ("same"). If tokens differ, parameters are extracted via _params(). Parameter counts must align (handling cut-off signatures where the verified parameters form a prefix). If each source parameter's tokens form a subsequence within the documented parameter's tokens, the parameters match. If return types or annotations were added, the verdict is "embellished"; if parameters were added, removed, renamed, or reordered, the verdict is "mismatch".

    def _see_also_section(parsed: dict, pages: set, page: str) -> list[tuple[int, str]]:
    starts = [number for number, level, _text in parsed["headings"] if level == 2]
    if not starts:
        return []
    sections = [
        [(number, line) for number, line in parsed["prose"] if start < number < end and USED_BY_MARKER not in line]
        for start, end in zip(starts, [*starts[1:], float("inf")], strict=True)
    ]
    for section in reversed(sections):
        if any(resolve_link(page, target) in pages for _number, target in _links(section)):
            return section
    return sections[-1]

    Because section titles may be translated across languages, the function identifies the "See Also" section positionally. It partitions page prose into slices between level-2 headings (##). Scanning in reverse, it selects the last level-2 section that contains relative links resolving to valid chapter pages, filtering out auto-generated USED_BY_MARKER lines.

    Error Handling

    The module implements a deterministic, fail-soft verification architecture designed never to halt pipeline execution unexpectedly:

    • Non-Mutating Verification: Operations are strictly read-only; source code and Markdown documentation files are never modified in place.
    • Tolerant Lexing: Unclosed code fences do not cause parsing exceptions. Instead, the opening fence line is appended to unclosed, and remaining lines are parsed as standard prose.
    • Heuristic Robustness: If a declaration or signature cannot be definitively identified by _declared_name or _params, the comparison safely defaults to subsequence checks or marks the candidate as skipped rather than raising parsing errors.
    • Selective Diagram Parsing: Unknown non-flowchart diagrams (e.g., Gantt, Journey, GitGraph) pass diagram validation gracefully because flowchart-specific syntax rules do not apply to them.
    • Resilient Fact Checking: If upstream fact extraction fails or produces empty claim sets (facts.get("claims") is None), the entire fact-based validation phase is skipped for that chapter, ensuring baseline checks (links and diagrams) continue unimpeded.
