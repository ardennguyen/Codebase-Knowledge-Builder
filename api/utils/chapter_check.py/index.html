    chapter_check.py

    Source: utils/chapter_check.py

    Technical Overview

    utils/chapter_check.py provides deterministic quality assurance and linting for generated Markdown chapters. Operating without Large Language Model (LLM) calls, it inspects written documentation pages strictly through regular expressions, AST/token analysis, and pipeline-accurate rendering tests. The module functions as a verification gate at the end of the documentation build pipeline, outputting a consolidated diagnostic report to chapter_check.json and emitting structured telemetry via utils.output.emit.

    The verification architecture operates across three distinct evaluation layers. First, structural checks analyze CommonMark syntax compliance across every page, identifying unclosed code fences, broken internal hyperlinks, and syntactic defects in Mermaid diagram blocks that would cause client-side rendering crashes. Second, markup fidelity checks evaluate site renderer compatibility by injecting non-rendering Unicode Private Use Area (PUA) markers into Markdown construct boundaries, rendering the marked text through the MkDocs renderer, and comparing the resulting HTML tag hierarchies against CommonMark baseline expectations. Third, factual conformance checks validate the content of API reference pages against verified source facts, detecting omitted symbols, mutated signatures, nonexistent type names in headings, and broken or superfluous cross-references.

    parse_page()

    Visibility: Public

    Signature: def parse_page(markdown: str) -> dict:

    Description: Parses raw Markdown text into structured components without executing external rendering engines. It reads the source line-by-line following GitHub CommonMark conventions to identify code fences, separating fenced blocks from prose and cataloging all headings along with their nesting levels. Any code block opener that remains unclosed at the end of the document is reclassified as prose, and its line number is tracked in the unclosed list.

    Parameters:

    • markdown (str): The raw Markdown text content of a documentation chapter.

    Returns:

    • dict: A dictionary containing parsed page structures:
      • "prose": List of (line_number, text) tuples for lines outside code blocks.
      • "blocks": List of dictionary records for closed code blocks (lang, start, end, text).
      • "headings": List of (line_number, level, text) tuples for Markdown headings.
      • "unclosed": List of 1-based line numbers for unclosed opening code fences.

    Example:

    lines = markdown.split("\n")
prose, blocks, headings, unclosed = [], [], [], []
number = 0
while number < len(lines):
    line = lines[number]
    opener = _FENCE_RE.match(line)
    if opener and opener.group(2)[0] == "`" and "`" in line[opener.end(2) :]:  # ```mermaid``` in prose: inline code
        opener = None
    if opener:
        indent, fence = len(opener.group(1)), opener.group(2)
        for end in range(number + 1, len(lines)):
            closer = _FENCE_RE.match(lines[end])
            if (
                closer
                and closer.group(2)[0] == fence[0]
                and len(closer.group(2)) >= len(fence)
                and not lines[end][closer.end(2) :].strip()
                and len(closer.group(1)) <= indent + 3
            ):
                blocks.append({"lang": opener.group(3).lower(), "start": number + 1, "end": end + 1, "text": "\n".join(lines[number + 1 : end])})
                number = end + 1
                break
        else:
            unclosed.append(number + 1)
            prose.append((number + 1, line))
            number += 1
        continue
    prose.append((number + 1, line))
    heading = _HEADING_RE.match(line)
    if heading:
        headings.append((number + 1, len(heading.group(1)), heading.group(2)))
    number += 1

    The parsing loop uses _FENCE_RE to distinguish valid code fence delimiters (triple backticks or tildes). It explicitly guards against inline code spans such as ```mermaid``` appearing in prose. When a fence opener is encountered, the inner loop searches ahead for a matching closer with identical or greater delimiter length and an indentation within 3 spaces of the opener; if found, the intermediate text is recorded as a code block. If the inner search reaches the end of the file without finding a matching delimiter, the opening line is appended to unclosed and treated as prose.

    resolve_link()

    Visibility: Public

    Signature: def resolve_link(page: str, target: str) -> str | None:

    Description: Resolves a relative Markdown link target against the site-relative path of the source page, returning a normalized POSIX path. Protocol links (https:, mailto:), root-relative links starting with /, and in-page anchor links starting with # are ignored, returning None. URL query strings and fragment identifiers are stripped, and percent-encoded escapes are decoded.

    Parameters:

    • page (str): The site-relative file path of the page containing the link (e.g., "api/index.md").
    • target (str): The raw hyperlink target attribute extracted from the Markdown link.

    Returns:

    • str | None: The normalized site-relative path to the target file, or None if the target is external or an anchor.

    Example:

    if re.match(r"^[a-zA-Z][\w+.-]*:", target) or target.startswith(("#", "/")):
    return None
path = unquote(target.split("#", 1)[0].split("?", 1)[0])
return posixpath.normpath(posixpath.join(posixpath.dirname(page), path)) if path else None

    The function first checks the target against a URI scheme regex and leading # or / prefixes, immediately returning None for external or non-relative references. For candidate relative paths, query strings and anchors are discarded using string splits, and urllib.parse.unquote resolves any URL-encoded characters. The resulting path is joined with the source page's directory name using posixpath.join and normalized with posixpath.normpath.

    mermaid_problems()

    Visibility: Public

    Signature: def mermaid_problems(source: str) -> list[dict]:

    Description: Evaluates the syntax of a Mermaid diagram block to detect conditions that cause client-side rendering crashes. It validates frontmatter headers, checks diagram type declarations against supported Mermaid diagram types, and applies conservative syntax rules to flowcharts and graph diagrams to catch invalid arrow operators, unescaped brackets in labels, and unbalanced delimiters.

    Parameters:

    • source (str): The raw text content of the Mermaid diagram block.

    Returns:

    • list[dict]: A list of dictionaries with "line" (int, 1-based offset within the block) and "problem" (str), where problem is one of "type", "arrow", "quotes", "brackets", or "label".

    Phase 1: Header and Diagram Type Validation

    lines = source.split("\n")
body = [(number, line) for number, line in enumerate(lines, start=1) if line.strip() and not line.strip().startswith("%%")]
if body and body[0][1].strip() == "---":  # frontmatter (title / config) before the diagram type
    closing = next((i for i, (_n, line) in enumerate(body[1:], start=1) if line.strip() == "---"), None)
    body = body[closing + 1 :] if closing is not None else []
if not body:
    return []
first = body[0][1].strip().split()[0].rstrip(":")
if first not in _MERMAID_TYPES:
    return [{"line": body[0][0], "problem": "type"}]
if not first.startswith(("flowchart", "graph")):
    return []

    The function filters out empty lines and comments (%%), then checks for YAML-style frontmatter demarcated by triple dashes (---). The first active line after frontmatter is inspected to verify that its leading token belongs to _MERMAID_TYPES. If the type is unrecognized, a "type" error is reported immediately; if the diagram type is valid but not a flowchart or graph, detailed syntax scanning is skipped.

    Phase 2: Flowchart and Graph Syntax Scanning

    markdown_strings = '"`' in source  # "`multi-line markdown labels`" span lines: quote and bracket counts do not apply
problems = []
for number, line in body[1:]:
    if line.count('"') % 2 and not markdown_strings:
        problems.append({"line": number, "problem": "quotes"})
        continue
    code = re.sub(r'"[^"]*"', '""', line)
    code = re.sub(r"\|[^|]*\|", "||", code)  # edge labels: A -->|label| B
    code = re.sub(r"\w>[^\]]*\]", "x", code)  # the asymmetric shape: id>label]
    unlabelled = re.sub(r"\[[^\]]*\]|\([^)]*\)|\{[^}]*\}", "", code)  # `>>` inside a label is text
    if re.search(r"(?<![-=.])>>", unlabelled):
        problems.append({"line": number, "problem": "arrow"})
    elif re.search(r"\w\[(?![(\[/\\])[^\]\"]*[(\[{]", code):  # A[run(x)] — not the shapes A[(db)], A[[sub]], A[/p/]
        problems.append({"line": number, "problem": "label"})
    elif not markdown_strings and any(code.count(o) != code.count(c) for o, c in ("[]", "()", "{}")):
        problems.append({"line": number, "problem": "brackets"})
return problems

    For flowchart diagrams, lines are evaluated sequentially unless Markdown strings (indicated by " + `) are present. The scanner identifies odd quotation mark counts as "quotes", sanitizes label text and edge labels using regular expressions, and checks for unsupported code operators such as raw >> arrows. It also detects nested parentheses or brackets inside standard square brackets that violate Mermaid label syntax unless enclosed in quotation marks.

    markup_verdicts()

    Visibility: Public

    Signature: def markup_verdicts(markdown: str, parsed: dict, render) -> tuple[list[tuple[str, tuple, bool | None]], int]:

    Description: Compares the CommonMark reading of a document against the output of the site's renderer. It injects tracking markers into intended block elements, renders the document to HTML, and determines whether each element rendered in its intended structural context. This function provides strict verification for markup repair routines such as utils.mkdocs.repair_markup.

    Parameters:

    • markdown (str): The raw Markdown text of the page.
    • parsed (dict): The parsed page dictionary produced by parse_page.
    • render (Callable[[str], str]): A rendering function mapping Markdown text to HTML.

    Returns:

    • tuple[list[tuple[str, tuple, bool | None]], int]: A tuple consisting of:
      • List of verdicts as (kind, reading, ok), where kind is the element type, reading is a normalized tuple of expected properties, and ok is True, False, or None (if the marker was swallowed by raw HTML).
      • int: Total number of rendered code blocks.

    Example:

    _lines, marks, found, code_blocks = _rendered_marks(markdown, parsed, render)
verdicts = []
for number, (_index, kind, expect) in enumerate(marks):
    reading = tuple(sorted((key, value) for key, value in expect.items() if key not in ("opener", "cut")))
    where = found.get(number)
    verdicts.append((kind, reading, None if where is None else _mark_ok(kind, expect, where)))
return verdicts, code_blocks

    The function calls _rendered_marks to generate intended element markers and collect their rendered HTML positions from _MarkContexts. Each mark expectation is converted into an order-independent tuple of properties, omitting line-specific keys (opener, cut). The mark's rendered context is evaluated using _mark_ok, yielding an exact verdict for every structural element.

    markup_problems()

    Visibility: Public

    Signature: def markup_problems(markdown: str, parsed: dict, render) -> dict:

    Description: Identifies structural Markdown defects where the site renderer parses content differently than intended under CommonMark rules. It evaluates list items rendered as plain text, flattened nested lists, merged adjacent lists of different types, split lists caused by indented content, tables parsed as raw text, and unclosed or swallowed code blocks.

    Parameters:

    • markdown (str): The raw Markdown text of the page.
    • parsed (dict): The parsed page structure from parse_page.
    • render (Callable[[str], str]): The Markdown-to-HTML rendering function.

    Returns:

    • dict: A dictionary mapping each markup error category from _MARKUP_KINDS to a list of finding records:
      • "lists_as_text": [{"line": int, "items": int}]
      • "lists_flattened": [{"line": int, "items": int}]
      • "lists_merged": [{"line": int, "items": int}]
      • "lists_split": [{"line": int}]
      • "tables_as_text": [{"line": int}]
      • "code_blocks_not_rendered": [{"line": int, "opener": str}]

    Phase 1: Mark Placement and Code Block Ownership Mapping

    lines, marks, found, _code_blocks = _rendered_marks(markdown, parsed, render)
owners = {}  # rendered code block -> [(mark, opener)] of the fenced blocks whose first code line it shows
for number, (_index, kind, expect) in enumerate(marks):
    if kind == "code" and found.get(number) and found[number]["code"]:
        owners.setdefault(found[number]["code"], []).append((number, expect["opener"]))
problems = {kind: [] for kind in _MARKUP_KINDS}
blamed = set()  # fenced blocks already reported

def blame(opener: int) -> None:
    if opener not in blamed:
        blamed.add(opener)
        problems["code_blocks_not_rendered"].append({"line": opener, "opener": lines[opener - 1].strip()[:80]})

    _rendered_marks places invisible Unicode markers at every structural construct and executes the site renderer. The resulting found contexts are inspected to establish code block ownership: for each "code" mark that landed inside a rendered code element (<pre> or Mermaid div), the mark and its opening line are indexed by rendered block ID. The blame helper records code fence failures and prevents redundant reporting of cascaded unclosed blocks.

    Phase 2: Structural Verification and Element Classification

    split_since_item, run, item_listed, last_block = False, None, True, None  # run: list items being folded
for number, (index, kind, expect) in enumerate(marks):
    where = found.get(number)
    if where is None:  # the mark vanished (raw HTML, a comment): nothing to compare
        continue
    if kind != "code" and where["code"]:
        opened = [opener for mark, opener in owners.get(where["code"], []) if mark < number]
        if opened:
            blame(opened[-1])
        run = None
        continue
    problem = None
    if kind == "after":
        continue
    if kind == "item":
        if not where["li"] or where["marker"]:
            problem = "lists_as_text"
        elif where["depth"] < expect["depth"]:
            problem = "lists_flattened"
        elif where["list"] != ("ol" if expect["numbered"] else "ul"):
            problem = "lists_merged"
        elif ("start" in expect or expect.get("continues")) and where["number"] == 1 and not split_since_item:
            problem = "lists_split"
        split_since_item, item_listed = False, where["li"] and not where["marker"]
    elif kind == "content":  # outside the list, or in a shallower item than its own
        problem = "lists_split" if item_listed and (not where["li"] or where["depth"] < expect["depth"]) else None
    elif kind == "table":
        if not where["th"]:
            problem = "tables_as_text"
        elif expect["item"] and item_listed and (not where["li"] or where["depth"] < expect["depth"]):
            problem = "lists_split"
    else:
        knock_on, last_block = last_block in blamed, expect["opener"]
        if not where["code"]:
            if not knock_on:  # else its opening fence was taken as the closer of the block before, reported
                blame(expect["opener"])
            run = None
            continue
        if expect["item"] and item_listed and (not where["li"] or where["depth"] < expect["depth"]):
            problem = "lists_split"

    The loop iterates through every placed marker. If a non-code construct was swallowed into a rendered code block (where["code"]), the preceding fence opener is blamed for leaving its block unclosed. List items (kind == "item") are checked to confirm they generated an <li> tag without visible marker characters, achieved the expected nesting depth, matched the ordered/unordered list type, and maintained numbering continuity. Tables and item continuation paragraphs ("content") are checked to verify they were not broken out into sibling blocks or rendered as plain text.

    Phase 3: Consecutive Error Aggregation

        if problem is None:
        run = None
        continue
    if problem == "lists_split" and kind != "item":
        split_since_item = True
    if problem in _LIST_RUNS and run and run[0] == problem:

        if all(between) or not any(between):  # the same list, tight or loose
            run[1]["items"] += 1
            run = (problem, run[1], index)
            continue

    if problem in _LIST_RUNS:

    Returns:

    • bool: True if shaped like a declaration; otherwise False.

    Example:

    text = _strip_decorators(text).strip()
first = (_words(text) or [""])[0]
name = _declared_name(text)
if not name or first in _NOT_DECLARATION:
    return False
if first in _DECLARATION_START:
    return True
if first in ("constructor", "init") and re.search(r"\(\s*[\w$]+\s*:", text):
    return True  # constructor(size: string), init(name: Int) — typed, unlike a call init(language="x")
before = text[: name[1]].rstrip()
before = before[: len(before) - len(name[0])] if before.endswith(name[0]) else before
if before.endswith((".", "->")) or "=" in before:
    return False
if before.endswith("::") and not _words(before.rstrip(":").rsplit(None, 1)[0] if " " in before.strip() else ""):
    return False  # A::b(…) with no type before it is a call; `void A::b(` is a definition
head = _head(text).rstrip()
return len(_words(before)) >= 1 or head.endswith(("{", ":", ";"))

    The function filters out statements starting with non-declaration keywords (if, return, await). It accepts tokens starting with _DECLARATION_START keywords (def, func, class) or typed constructors, rejects member calls (object.method(), ptr->call()), and checks for preceding return types or trailing block openers ({, :, ;).

    _params()

    Visibility: Private

    Signature: def _params(head: str) -> tuple[list[list[str]], bool] | None:

    Description: Parses a declaration header's parameter list into tokenized parameter segments, tracking whether the parameter list reaches a closing parenthesis.

    Parameters:

    • head (str): Declaration header string.

    Returns:

    • tuple[list[list[str]], bool] | None: (tokenized_parameters, is_closed) or None if no parameter list is found.

    Example:

    name = _declared_name(head)
if not name:
    return None
params, current, depth = [], "", 0
text = head[name[1] + 1 :]
for position, char in enumerate(text):
    pair = text[max(0, position - 1) : position + 1]
    if char in "([{" or (char == "<" and pair != "<="):
        depth += 1
    elif char in ")]}" or (char == ">" and pair not in ("->", "=>", ">=")):
        if depth == 0 and char == ")":
            params.append(current)
            return [_PARAM_TOKEN_RE.findall(p) for p in params if p.strip()], True
        depth -= 1
    elif char == "," and depth == 0:
        params.append(current)
        current = ""
        continue
    current += char
params.append(current)
return [_PARAM_TOKEN_RE.findall(p) for p in params if p.strip()], False

    The function locates the opening parenthesis using _declared_name and iterates through the parameter list, maintaining bracket nesting depth while ignoring comparison operators. Parameters delimited by commas at depth 0 are split into strings and tokenized with _PARAM_TOKEN_RE. The return value indicates whether the parameter list was properly closed.

    _compare()

    Visibility: Private

    Signature: def _compare(page_head: str, source_head: str) -> str:

    Description: Compares a documented signature header against a verified source code signature header, returning a verdict of "same", "embellished", or "mismatch".

    Parameters:

    • page_head (str): Documented declaration header.
    • source_head (str): Verified source code declaration header.

    Returns:

    • str: One of "same", "embellished", or "mismatch".

    Example:

    have, wanted = _PARAM_TOKEN_RE.findall(page_head), _PARAM_TOKEN_RE.findall(source_head)
if have == wanted:
    return "same"
page, source = _params(page_head), _params(source_head)
if page is None or source is None:
    return "embellished" if _is_subsequence(wanted, have) else "mismatch"
(page_params, _page_closed), (source_params, source_closed) = page, source
if not source_closed:  # a cut-short verified signature: its complete parameters are a prefix
    source_params = source_params[:-1]
    if len(page_params) < len(source_params):
        return "mismatch"
    page_params = page_params[: len(source_params)]
elif len(page_params) != len(source_params):
    return "mismatch"
if not all(_is_subsequence(want, got) for want, got in zip(source_params, page_params, strict=True)):
    return "mismatch"
return "embellished" if not source_closed or _is_subsequence(wanted, have) else "mismatch"

    If the token streams of both signatures match identically, the function returns "same". Otherwise, parameter lists are parsed via _params. If parameter counts differ or any parameter token list fails the subsequence check (_is_subsequence), it returns "mismatch". If all source parameter tokens are preserved in order, the function returns "embellished".

    Error Handling

    chapter_check.py implements a passive reporting strategy: it never raises custom exceptions, modifies source documents, or interrupts pipeline execution. Error handling is structured around the following defensive conventions:

    • Missing Verified Facts Handling: When evaluating factual conformance, check_chapter inspects facts.get("claims"). If claims is None (indicating that fact extraction failed or is unavailable for that file), factual conformance checks are skipped entirely, and only structural CommonMark and Mermaid syntax checks are executed.
    • Cascading Code Fence Blame Prevention: An unclosed code fence will swallow subsequent Markdown text and cause following code fences to be parsed as closers. To prevent reporting every swallowed element, markup_problems maintains a blamed set. Once an opening fence is blamed for an unclosed block, subsequent knock-on effects referencing that block are suppressed.
    • Malformed or Truncated Signatures: When tokenizing parameter lists, _params detects unclosed signatures (e.g., multi-line signatures cut short in facts extraction) by returning a boolean is_closed flag. _compare accounts for unclosed signatures by comparing only the complete parameter prefix.
    • Private Use Area Marker Isolation: To ensure that injected tracking markers (...) do not collide with content in user documents, _rendered_marks explicitly strips existing occurrences of  and  prior to marker insertion.
