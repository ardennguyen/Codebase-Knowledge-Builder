    chapter_check.py

    Source: utils/chapter_check.py

    Technical Overview

    The utils/chapter_check.py module is a deterministic, offline static-analysis and verification engine designed to audit generated documentation chapters. Operating entirely without LLM inference, it acts as an automated quality gate that inspects generated Markdown pages against structural, syntactical, factual, and renderer-specific rules before publication. Pages are never mutated; instead, the module performs non-destructive read passes and outputs diagnostic telemetry along with an aggregated JSON report (chapter_check.json).

    The verification pipeline operates across three primary layers: 1. Syntactical and Structural Auditing: It parses Markdown text conforming to CommonMark rules to isolate prose, headings, and code fences. It checks for broken relative links (resolving URL escapes, cross-page targets, and anchors), detects malformed or unclosed code blocks, and performs syntax analysis on Mermaid diagram blocks to catch fatal layout errors (unsupported diagram types, invalid code operators like >>, unbalanced quotes, and unescaped brackets in node labels). 2. Renderer Discrepancy Detection: Documentation generators (specifically Python-Markdown under MkDocs) apply stricter parsing rules than standard GitHub CommonMark. Lists without preceding blank lines, improperly indented sublists, tables missing blank line buffers, and code blocks with invalid fence delimiters can render as broken inline text. By injecting non-rendering Unicode private-use markers ( / ) and feeding the rendered HTML through a streaming HTMLParser (_MarkContexts), the module verifies whether structural elements rendered into expected tags (<li>, <th>, <pre>) or degraded into plain text. 3. Deterministic Factual Validation: For API-reference chapters possessing verified code facts (extracted via utils.facts), the module verifies that documented symbols exist in the source, validates declared signatures token-by-token (distinguishing benign embellishments from fatal parameter mismatches), flags fabricated CamelCase type names that appear nowhere in the scanned repository, and ensures the "See Also" section includes verified module dependencies while excluding unrelated files.

    parse_page()

    Visibility: Public

    Signature: def parse_page(markdown: str) -> dict:

    Description: Parses raw Markdown text according to CommonMark block conventions, isolating fenced code blocks (delimited by matching sequences of three or more backticks or tildes) from prose lines and headings. Line numbers are normalized to 1-based indices. If a fenced block is left open at the end of the file, it is classified as unclosed; its contents are restored to prose, and its opening line is recorded in the unclosed list.

    Parameters:

    • markdown (str): The raw Markdown source of the documentation page.

    Returns:

    • dict: A dictionary containing parsed block entities:
      • "prose": List of (line_number, text) tuples.
      • "blocks": List of code block dicts ({"lang": str, "start": int, "end": int, "text": str}).
      • "headings": List of (line_number, level, text) tuples.
      • "unclosed": List of integer line numbers representing unclosed fences.

    Example:

    parsed = parse_page(markdown)

    The parsing algorithm tracks opening fence character types (` or ~), indentation depth, and length, ensuring that inline code containing triple backticks (e.g. ```mermaid```) within prose is not misinterpreted as a block opener. It scans lines sequentially, tracking heading levels from #{1,6} tokens while ignoring code contents.

    resolve_link()

    Visibility: Public

    Signature: def resolve_link(page: str, target: str) -> str | None:

    Description: Resolves a relative Markdown link target against the current page path, converting it into a normalized site-relative path. It ignores external URI schemes (e.g., https:, mailto:), root-relative paths starting with /, and local page anchor fragments starting with #. Query parameters and anchor hashes are stripped, and URL percent-encoded entities (such as %20) are decoded using urllib.parse.unquote.

    Parameters:

    • page (str): The site-relative file path of the page containing the link (e.g., docs/api/core.md).
    • target (str): The raw link target string extracted from Markdown link syntax or an HTML anchor tag.

    Returns:

    • str | None: The resolved, normalized POSIX relative path, or None if the target is external, root-relative, or an anchor.

    Example:

    resolved = resolve_link(page, target)
if resolved is not None and not exists(resolved):
    problems.append({"line": number, "target": target})

    The function utilizes posixpath.join(posixpath.dirname(page), path) followed by posixpath.normpath to handle relative path navigations such as ../ and ./. Empty target paths evaluate to None.

    missing_symbols()

    Visibility: Public

    Signature: def missing_symbols(parsed: dict, symbols: list[dict]) -> list[dict]:

    Description: Cross-references verified symbols extracted from the codebase against the documentation page's prose and code blocks (excluding Mermaid diagrams). A symbol is considered missing if its leaf name (the segment following the final period, stripped of leading $) does not appear as an independent word token or verbatim identifier in the page text.

    Parameters:

    • parsed (dict): The parsed page structure returned by parse_page().
    • symbols (list[dict]): A collection of verified symbol dictionaries extracted from utils/facts.py.

    Returns:

    • list[dict]: Dictionaries representing verified symbols omitted from the page, containing "name", "kind", "parent", and "line".

    Example:

    def missing_symbols(parsed: dict, symbols: list[dict]) -> list[dict]:
    """Verified symbols whose name the page never writes (prose or code), matched like facts.py matches
    names: word tokens, and verbatim for names with punctuation (``valid?``, ``operator==``)."""
    text = _page_text(parsed)
    words = set(re.findall(r"\w+", text)) | {word.lstrip("$") for word in re.findall(r"\$\w+", text)}
    words |= set(re.findall(r"[A-Za-z_$][A-Za-z0-9_$]*", text))  # an identifier glued to CJK prose: 调用run_flow函数
    missing = []
    for symbol in symbols:
        name = str(symbol.get("name", "")).split(".")[-1].lstrip("$")
        if name and not (name in words or _names_in(text, name)):
            missing.append({k: symbol.get(k) for k in ("name", "kind", "parent", "line")})
    return missing

    The function extracts all word tokens, including identifiers adjacent to CJK characters. It evaluates punctuation-heavy symbol names (such as Ruby predicates or C++ operator overloads) using _names_in from utils.facts.

    signature_issues()

    Visibility: Public

    Signature: def signature_issues(parsed: dict, source: str, symbols: list[dict]) -> tuple[list[dict], list[dict]]:

    Description: Compares declared function, method, and constructor signatures in the documentation against verified source declarations. Signatures are identified via labelled code patterns (e.g., **Signature**: \...``) or code blocks directly following bold label lines. If a signature does not match the source text verbatim, it is parsed into tokens and compared against verified candidates: * Embellished: The parameter names, sequence, and modifiers match the source, but additional type annotations or return types were added. * Mismatch: Parameters were added, removed, reordered, or renamed, or default values/variadic indicators were altered.

    Parameters:

    • parsed (dict): The parsed page structure returned by parse_page().
    • source (str): The complete source code of the underlying source module.
    • symbols (list[dict]): The verified symbol definitions for the module.

    Returns:

    • tuple[list[dict], list[dict]]: A tuple containing (mismatches, embellished).

    Example:

    mismatches, embellished = signature_issues(parsed, source, symbols)

    def signature_issues(parsed: dict, source: str, symbols: list[dict]) -> tuple[list[dict], list[dict]]:
    flat_source = _collapse(source)
    by_name = {}
    for symbol in symbols:
        by_name.setdefault(str(symbol.get("name", "")).split(".")[-1], []).append(_head(str(symbol.get("signature", ""))))
    mismatches, embellished = [], []
    for number, text in _signatures(parsed):
        if _collapse(text).rstrip(":{; ") in flat_source:
            continue
        name = _declared_name(text)
        candidates = by_name.get(name[0]) if name else None
        if not candidates:
            continue
        verdicts = [_compare(_head(text), candidate) for candidate in candidates]
        if "same" in verdicts:
            continue
        if "embellished" in verdicts:
            embellished.append({"line": number, "signature": text})
        else:
            mismatches.append({"line": number, "signature": text, "source": _collapse(candidates[0])[:200]})
    return mismatches, embellished

    The function strips decorators, annotations, and comments before comparing parameter token subsequences via _compare(). Verbatim matches bypass token analysis entirely.

    unknown_type_names()

    Visibility: Public

    Signature: def unknown_type_names(parsed: dict, known_words: set) -> list[dict]:

    Description: Scans inline code spans within Markdown headings for PascalCase / CamelCase identifiers (e.g., ###FactClaim``) that do not appear in any crawled file in the repository. This detects instances where documentation authors invent formal class or type names for unstructured data shapes (such as raw dictionaries or tuples).

    Parameters:

    • parsed (dict): The parsed page structure returned by parse_page().
    • known_words (set): The set of all word tokens extracted from all crawled source files.

    Returns:

    • list[dict]: A list of findings containing "line" and "name".

    Example:

    def unknown_type_names(parsed: dict, known_words: set) -> list[dict]:
    """Type-like names written as code in headings (``### `FactClaim` ``, ``### Stream result (`StreamResult`)``)
    that occur in no crawled file: the writer named a dict or tuple shape as if it were a declared type. Names
    starting with an acronym count (``LLMConfigTuple``); brand names in heading prose do not."""
    if not known_words:
        return []
    found = []
    for number, _level, text in parsed["headings"]:
        spans = " ".join(match.group(2) for match in _CODE_SPAN_RE.finditer(text))
        names = sorted(set(re.findall(r"[A-Za-z_][A-Za-z0-9_]*", spans)))  # ASCII: a name glued to CJK text still counts
        found.extend({"line": number, "name": word} for word in names if _TYPE_NAME_RE.match(word) and word not in known_words)
    return found

    The regular expression _TYPE_NAME_RE targets type-like names (beginning with uppercase letters, containing mixed capitalization or uppercase acronym prefixes) while ignoring normal prose outside inline code spans.

    depends = {edge["module"] for edge in facts.get("depends_on", [])} & set(module_by_page.values())  # only documented ones can be linked
    related = depends | set(facts.get("used_by", []))
    linked = {}
    pages = set(module_by_page)
    section = _see_also_section(parsed, pages, page)
    for number, target in _links(section):
        resolved = resolve_link(page, target)
        target_module = module_by_page.get(resolved) if resolved else None
        if target_module and target_module != module:
            linked.setdefault(target_module, number)
    unrelated = [{"line": number, "module": target} for target, number in sorted(linked.items(), key=lambda item: item[1]) if target not in related]
    missing = [{"module": target} for target in sorted(depends - set(linked))]
    return unrelated, missing

    Error Handling

    The module implements a non-terminating, fault-tolerant inspection strategy. Rather than raising exceptions and halting documentation builds, all validation routines catch malformed states and append descriptive records to findings lists:

    • Unclosed Code Fences: When parse_page() encounters an opening backtick or tilde fence that is never closed, it records the opener's line number in unclosed and restores all subsequent lines to prose. This prevents downstream prose and link checkers from silently dropping remainder text.
    • Resilient Link Parsing: Malformed URI escapes in resolve_link() are safely decoded via urllib.parse.unquote. Unresolvable external URIs, protocol schemes, and anchor fragments return None and are skipped without error.
    • HTML Parser Safety: _MarkContexts inherits from Python's standard html.parser.HTMLParser with convert_charrefs=True. Unknown tags and mismatched closing tags are tolerated without raising parse exceptions.
    • Missing Facts Handling: When facts dictionaries are absent or their extraction failed (facts.get("claims") is None), check_chapter() skips factual checks without throwing errors, returning only syntax and link reports.
    • Mermaid Syntax Tolerance: mermaid_problems() ignores empty lines, frontmatter metadata, and comments. Diagram parsing errors are captured as structured issue records rather than propagating runtime failures.
