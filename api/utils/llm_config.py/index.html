    llm_config.py

    Source: utils/llm_config.py

    Technical Overview

    Building upon the runtime ledger, refusal tracking, and truncated response abstractions established in utils/llm_common.py, utils/llm_config.py serves as the centralized configuration, credential preflight, and model parameter resolution engine for the codebase analysis pipeline. Originally extracted from call_llm.py to eliminate circular import dependencies with token_utils.py, this module acts as the authoritative single source of truth for runtime provider selection, model catalog limits, context window calculations, token estimation scaling, and thinking effort budgets.

    The architecture isolates upstream pipeline orchestrators from vendor-specific configuration schemas across Anthropic, Google Gemini, OpenRouter, and generic OpenAI-compatible gateways. It models complex model-family behaviors: dynamic reasoning effort translation, token ratio compensation for tiktoken undercounting across various Claude and Gemini tokenizers, Vertex AI regional endpoint routing, and OpenRouter dynamic catalog introspection with transient failure circuit-breaking.

    Additionally, the module implements fail-fast credential preflights for all supported providers prior to executing intensive repository crawls or planning nodes. For Anthropic, it performs multi-tier authentication resolution across environment API keys, auth tokens, Workload Identity Federation attributes, native ant auth CLI status scraping with credential masking, and cached filesystem OAuth tokens. For Gemini, it enforces minimum Google GenAI SDK version thresholds (>= 1.56.0) to avoid runtime Pydantic validation failures when handling structured thinking configurations, while intercepting deprecated preview identifiers.

    Visibility: Public
    Signature: def anthropic_output_cap() -> int | None:

    Description: Resolves the user-configured ceiling for Anthropic token generations from the environment variable ANTHROPIC_MAX_OUTPUT_TOKENS. The value is parsed as a positive integer; if unset, non-numeric, or non-positive, it returns None.

    Parameters: * None.

    Returns: * int | None: The parsed positive token limit, or None if not specified.

    Raises: * None.

    Example: 

    # Sizing prompt budget in token_utils.py or planned output
cap = anthropic_output_cap()

    budget = min(budget, cap)


    def anthropic_output_cap() -> int | None:
    """ANTHROPIC_MAX_OUTPUT_TOKENS as an int, or None when unset/invalid."""
    return _env_int("ANTHROPIC_MAX_OUTPUT_TOKENS")
    The helper invokes _env_int against ANTHROPIC_MAX_OUTPUT_TOKENS. It sanitizes input whitespace, ensures pure digit composition, and enforces strict positivity, shielding downstream budgeting formulas from syntax crashes.

    anthropic_output_budget()

    Visibility: Public
    Signature: def anthropic_output_budget(thinking_level: str | None) -> int:

    Description: Calculates the target output token allocation for an Anthropic adaptive thinking model given an abstract reasoning level. It retrieves baseline requirements from ANTHROPIC_MAX_TOKENS_BY_EFFORT and bounds the result using anthropic_output_cap() if an environment override is configured.

    Parameters: * thinking_level (str | None): The requested reasoning effort tier ("low", "medium", "high", "xhigh", "max", "minimal", or None).

    Returns: * int: Safe maximum token count to allocate for the request.

    Raises: * None.

    Example: 

    planned = anthropic_output_budget("high")
# Output: 64000 (or capped by ANTHROPIC_MAX_OUTPUT_TOKENS)


    def anthropic_output_budget(thinking_level: str | None) -> int:
    """Per-effort table value capped by ANTHROPIC_MAX_OUTPUT_TOKENS (adaptive models)."""
    level = thinking_level.lower() if thinking_level else None
    budget = ANTHROPIC_MAX_TOKENS_BY_EFFORT.get(level, ANTHROPIC_MAX_TOKENS_BY_EFFORT[None])
    cap = anthropic_output_cap()
    return min(budget, cap) if cap else budget
    The implementation lower-cases the input string to match normalized keys in ANTHROPIC_MAX_TOKENS_BY_EFFORT. If thinking_level is absent or unmapped, it defaults to the None key entry (64_000 tokens). Finally, anthropic_output_cap() restricts the value to prevent cost overruns when constrained by administrator environments.

    anthropic_effort()

    Visibility: Public
    Signature: def anthropic_effort(model: str, level: str | None) -> str | None:

    Description: Normalizes an abstract reasoning tier into a valid Claude output_config.effort parameter compatible with the target model. It translates "minimal" to "low", validates membership within ANTHROPIC_EFFORT_LEVELS, and downgrades "xhigh" to "high" on legacy Claude 4.6 architectures.

    Parameters: * model (str): The target Claude model name. * level (str | None): The abstract reasoning level string.

    Returns: * str | None: The vendor-compliant effort string, or None if thinking is disabled or unmapped.

    Raises: * None.

    Example: 

    effort = anthropic_effort("claude-sonnet-4-6", "xhigh")
# Returns: "high"


    def anthropic_effort(model: str, level: str | None) -> str | None:
    """Thinking level → effort the model accepts: minimal → low, xhigh → high on the 4.6 family,
    unknown values → None (model default)."""
    if not level:
        return None
    level = level.lower()
    if level == "minimal":
        level = "low"
    if level not in ANTHROPIC_EFFORT_LEVELS:
        return None
    if level == "xhigh" and (model or "").lower().startswith(ANTHROPIC_NO_XHIGH_PREFIXES):
        return "high"
    return level
    This function protects API requests from runtime rejections caused by incompatible effort parameters. Models such as claude-opus-4-6 and claude-sonnet-4-6 reject the xhigh tier introduced in newer versions with an HTTP 400 error. The helper maps incoming requests down to "high" while ignoring casing differences.

    anthropic_planned_output()

    Visibility: Public
    Signature: def anthropic_planned_output(model: str, thinking_level: str | None) -> int:

    Description: Determines the output token headroom that must be reserved for an Anthropic request before checking model and context boundaries.     def _installed_version(dist: str) -> tuple[int, ...] | None:
    from importlib import metadata

    try:
        raw = metadata.version(dist)
    except metadata.PackageNotFoundError:
        return None
    parts = []
    for piece in raw.split(".")[:3]:
        digits = re.match(r"\d+", piece)
        parts.append(int(digits.group()) if digits else 0)
    return tuple(parts)

    Error Handling

    Catalog Fetch Failures and Circuit Breaking

    openrouter_catalog() handles network disruptions gracefully: * Catches all exceptions during requests.get() and JSON parsing. * Records failure timestamps in _openrouter_last_failure. * Activates a 60-second cooldown (_OPENROUTER_RETRY_COOLDOWN) during which subsequent requests immediately return None to prevent repeated network delays. * Emits diagnostic warnings once per run via warn_once(), avoiding log pollution.

    Token Ratio Validation and Boundary Clamping

    _ratio_from_env() safeguards token calculations against invalid configuration values: * Catches ValueError when environment variables contain non-numeric strings. * Validates parsed floats with math.isfinite() to reject NaN and Infinity. * Clamps values to TOKEN_RATIO_BOUNDS (0.5 to 3.0), ensuring prompt budgeting calculations remain stable.

    SDK Gating and Version Auditing

    Preflight checks validate dependencies before execution begins: * check_anthropic_auth() verifies the anthropic library is installed without importing it directly, emitting ERROR_ANTHROPIC_SDK_MISSING and returning False if absent. * check_gemini_config() validates that google-genai meets the GEMINI_MIN_SDK threshold (>= 1.56.0). Outdated installations return False and emit ERROR_GEMINI_SDK_OUTDATED to prevent runtime Pydantic validation failures.

    Non-Fatal Authentication Diagnostics

    Preflight functions return boolean status flags instead of raising unhandled exceptions: * If authentication checks fail, the system emits descriptive setup guidance (including OS-specific installation instructions via _emit_auth_help()) and returns False. * Downstream callers (main.py) can then exit cleanly with exit code 1 before executing resource-intensive operations like codebase crawling.

    Credential Masking in Diagnostic Logging

    To prevent credential exposure in logs: * _redact() processes CLI output with _TOKEN_PATTERN, replacing strings like sk-ant-oat01-EXA... with sk-ant-***. * Vertex AI error messages are truncated to 200 characters to prevent exposing sensitive internal tracebacks.
