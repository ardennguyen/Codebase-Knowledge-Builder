    llm_config.py

    Source: utils/llm_config.py

    Following the centralized accounting and ledger mechanisms established in llm_common.py, llm_config.py acts as the foundational model configuration, credential preflight, and context-length resolution engine. It resolves circular dependencies across the codebase by serving as the decoupled single source of truth for runtime provider settings, budget calculations, and model parameter adaptation.

    Technical Overview

    The llm_config.py module establishes the configuration baseline and operational constraints for all Large Language Model (LLM) interactions across the system. Historically coupled within the invocation pipeline, this component was extracted from call_llm.py to break an architectural circular dependency between model dispatching and token budgeting in token_utils.py. By centralizing configuration parsing, environment resolution, and provider inspection into a standalone utility, both orchestration modules and downstream transport harnesses can query runtime parameters without initiating circular imports or eager SDK instantiations.

    The module provides deterministic resolution mechanisms across four distinct provider domains: Google Gemini (both AI Studio and Vertex AI endpoints), Anthropic Claude (supporting direct API keys, authentication tokens, Workload Identity Federation, and native ant auth CLI sessions), OpenRouter (with real-time catalog lookups and routing suffix normalization), and generic OpenAI-compatible custom endpoints. In addition to credentials, llm_config.py standardizes provider-specific thinking regimes, token sizing multipliers (bridging discrepancies between cl100k_base tiktoken estimates and native model tokenizers), and output limits.

    The preflight validation pipeline implemented by this module intercepts configuration deficiencies before resource-intensive repository crawling or multi-phase graph workflows begin. It inspects local Python environment dependencies (such as ensuring google-genai meets minimum semantic version thresholds), probes active CLI authentication states via subprocess wrappers, queries remote provider model catalogs with automatic failure cooldowns, and cross-references requested models against retirement or deprecation matrices.

    Public API

    anthropic_output_cap()

    Visibility: Public
    Signature: def anthropic_output_cap() -> int | None:

    Description: Retrieves the hard ceiling on output tokens for Anthropic Claude models configured via environment variables. It inspects ANTHROPIC_MAX_OUTPUT_TOKENS and validates that the value is composed strictly of digits representing a positive integer. If the variable is unset, empty, non-numeric, or less than or equal to zero, the function returns None.

    Parameters: * None

    Returns: * int | None: The parsed positive token limit if set and valid; otherwise None.

    Example: 

    def anthropic_output_cap() -> int | None:
    """ANTHROPIC_MAX_OUTPUT_TOKENS as an int, or None when unset/invalid."""
    return _env_int("ANTHROPIC_MAX_OUTPUT_TOKENS")

    The function provides an operational upper bound override for downstream budgeting calculations. By delegating parsing to the internal helper _env_int, it guarantees defensive sanitization against empty strings or malformed user configurations. Upstream planners use this return value to clamp planned output budgets to prevent accidental over-generation.

    anthropic_output_budget()

    Visibility: Public
    Signature: def anthropic_output_budget(thinking_level: str | None) -> int:

    Description: Resolves the planned output token allocation for adaptive Claude models based on the specified reasoning level. It queries ANTHROPIC_MAX_TOKENS_BY_EFFORT using the normalized lowercase level, falling back to the default None key (64,000 tokens) if omitted or unmatched. If an environment cap is returned by anthropic_output_cap(), the budget is clamped to the minimum of the table value and the cap.

    Parameters: * thinking_level (str | None): The requested reasoning intensity (e.g., "low", "medium", "high", "max").

    Returns: * int: The maximum token count planned for generation including reasoning tokens.

    Example: 

    def anthropic_output_budget(thinking_level: str | None) -> int:
    """Per-effort table value capped by ANTHROPIC_MAX_OUTPUT_TOKENS (adaptive models)."""
    level = thinking_level.lower() if thinking_level else None
    budget = ANTHROPIC_MAX_TOKENS_BY_EFFORT.get(level, ANTHROPIC_MAX_TOKENS_BY_EFFORT[None])
    cap = anthropic_output_cap()
    return min(budget, cap) if cap else budget

    This budget calculation accounts for Anthropic's unified token accounting, where thinking tokens and response tokens consume the same output allocation. If thinking_level is set to "xhigh" or "max", the lookup extracts allocations up to 128,000 tokens while respecting any administrator-defined ANTHROPIC_MAX_OUTPUT_TOKENS environment constraints.

    anthropic_effort()

    Visibility: Public
    Signature: def anthropic_effort(model: str, level: str | None) -> str | None:

    Description: Normalizes and maps user-specified thinking levels to effort strings supported natively by the Anthropic Messages API. It handles family-specific constraints, such as converting "minimal" to "low", rejecting unsupported levels by returning None, and downgrading "xhigh" to "high" on legacy Claude 4.6 family models that predate extended effort tiers.

    Parameters: * model (str): The target Claude model identifier or path. * level (str | None): The requested thinking level name.

    Returns: * str | None: A valid Anthropic effort string ("low", "medium", "high", "xhigh", "max"), or None if thinking should fall back to model defaults.

    Example: 

    def anthropic_effort(model: str, level: str | None) -> str | None:
    """Thinking level → effort the model accepts: minimal → low, xhigh → high on the 4.6 family,
    unknown values → None (model default)."""
    if not level:
        return None
    level = level.lower()
    if level == "minimal":
        level = "low"
    if level not in ANTHROPIC_EFFORT_LEVELS:
        return None
    if level == "xhigh" and (model or "").lower().startswith(ANTHROPIC_NO_XHIGH_PREFIXES):
        return "high"
    return level

    This normalization step ensures schema compliance before request payloads are serialized. Models starting with prefixes in ANTHROPIC_NO_XHIGH_PREFIXES (such as claude-opus-4-6 and claude-sonnet-4-6) trigger HTTP 400 validation errors if dispatched with output_config.effort="xhigh". The conditional logic gracefully scales down the effort tier, preserving pipeline execution continuity.

    anthropic_planned_output()

    Visibility: Public
    Signature: def anthropic_planned_output(model: str, thinking_level: str | None) -> int:

    Description: Computes the baseline output token allocation that the Anthropic request will plan for prior to applying model or context window limits. For adaptive reasoning models, it queries anthropic_output_budget(). For pre-adaptive legacy architectures (such as Haiku 4.5), it computes the sum of the level's budget_tokens and a fixed reply buffer (ANTHROPIC_BUDGET_REPLY_TOKENS, default 16,000), subsequently clamping against anthropic_output_cap().

    Parameters: * model (str): The target Claude model identifier. * thinking_level (str | None): The requested thinking intensity level.

    Returns: * int: The total planned token budget allocated for generation.

    Example: 

    def anthropic_planned_output(model: str, thinking_level: str | None) -> int:
    """Claude max_tokens the request will plan for (before the model/context ceiling): the per-effort
    table on adaptive models, budget_tokens + 16K on pre-adaptive ones (Haiku 4.5), capped by
    ANTHROPIC_MAX_OUTPUT_TOKENS. Shared by llm_anthropic and token_utils.input_token_budget."""
    effort = anthropic_effort(model, thinking_level)
    if (model or "").lower().startswith(ANTHROPIC_ADAPTIVE_PREFIXES):
        return anthropic_output_budget(effort)
    planned = ANTHROPIC_BUDGET_BY_LEVEL.get(effort, 0) + ANTHROPIC_BUDGET_REPLY_TOKENS
    cap = anthropic_output_cap()
    return min(planned, cap) if cap else planned

    This dual-branch calculation provides accurate token reservations for both modern adaptive thinking engines and legacy explicit budget implementations. In pre-adaptive architectures, specifying thinking requires providing an explicit numeric budget; the reply tokens must be added to this budget to prevent the response text from being truncated when reasoning finishes.

    gemini_thinking_mode()

    Visibility: Public
    Signature: def gemini_thinking_mode(model: str) -> tuple[str, object]:

    Description: Determines the thinking configuration schema supported by a specific Google Gemini model identifier. It evaluates model name prefixes against registered capability tables to return a mode descriptor tag paired with its parameter constraints: categorical levels for Gemini 3.x, numeric budget boundaries for Gemini 2.5, or a disabled state for non-reasoning variants.

    Parameters: * model (str): The Gemini model name or path.

    Returns: * tuple[str, object]: A tuple indicating ("level", allowed_levels) for Gemini 3.x, ("budget", (min, max, can_disable)) for Gemini 2.5, or ("none", None) for non-thinking models.

    Example: 

    def gemini_thinking_mode(model: str) -> tuple[str, object]:
    """('level', allowed_levels) for Gemini 3.x, ('budget', (min, max, can_disable)) for 2.5,
    ('none', None) for models without a thinking control the project maps."""
    name = gemini_model_id(model)
    for prefix, low, high, can_disable in GEMINI_BUDGET_RANGES:
        if name.startswith(prefix):
            return "budget", (low, high, can_disable)
    if not name.startswith("gemini-") or name.startswith(("gemini-1", "gemini-2")):
        return "none", None  # 1.x / 2.0, other 2.5 variants (image, live, TTS) and non-Gemini ids
    for prefix, levels in GEMINI_THINKING_LEVELS:
        if name.startswith(prefix):
            return "level", levels
    # Other 3.x ids, '-latest' aliases (gemini-flash-latest, gemini-pro-latest) and newer families:
    # the level set every documented 3.x model accepts (a model that rejects it is handled at runtime).
    return "level", GEMINI_3_DEFAULT_LEVELS

    The Google GenAI SDK enforces strict separation between reasoning mechanisms: passing thinking_level alongside thinking_budget results in an HTTP 400 error, as does sending categorical levels to Gemini 2.x models. This function enables transport adapters in llm_gemini.py to dynamically construct valid SDK configuration payloads.

    gemini_model_id()

    Visibility: Public
    Signature: def gemini_model_id(model: str) -> str:

    Description: Strips Google resource collection prefixes and whitespace from a model string, isolating the bare model identifier. It extracts the tail element following the final / character and converts the resulting string to lowercase.

    Parameters: * model (str): The raw model name or resource URI (e.g., "models/gemini-3.8-flash" or "publishers/google/models/gemini-3.8-flash").

    Returns: * str: The sanitized, lowercased model identifier (e.g., "gemini-3.8-flash").

    Example: 

    def gemini_model_id(model: str) -> str:
    """'models/gemini-3.8-flash' / 'publishers/google/models/gemini-3.8-flash' → 'gemini-3.8-flash'."""
    return (model or "").strip().lower().rsplit("/", 1)[-1]

    This normalization handles variations across Google AI Studio and Google Cloud Vertex AI naming conventions. AI Studio natively expects models/ prefixed identifiers, while Vertex AI uses hierarchical publisher paths. Stripping these namespaces simplifies internal prefix lookups.

    gemini_vertex_locations()

    Visibility: Public
    Signature: def gemini_vertex_locations(model: str) -> tuple | None:

    Description: Identifies the valid Google Cloud Vertex AI geographic regions serving a specified Gemini 3.x model family. It walks through GEMINI_VERTEX_LOCATIONS using longest-prefix matching, returning a tuple of supported location identifiers, None if the model is available across all regional endpoints, or GEMINI_3_VERTEX_LOCATIONS for unlisted Gemini 3.x variants.

    Parameters: * model (str): The target model name or path.

    Returns: * tuple | None: A tuple of valid region strings (e.g., ("global", "us")), or None if all regions are allowed.

    Example: 

    def gemini_vertex_locations(model: str) -> tuple | None:
    """Vertex AI locations that serve a Gemini 3.x model (None = any, including regional endpoints)."""
    name = gemini_model_id(model)
    for prefix, locations in GEMINI_VERTEX_LOCATIONS:
        if name.startswith(prefix):
            return locations
    return GEMINI_3_VERTEX_LOCATIONS if name.startswith("gemini-3") else None

    Vertex AI serves Gemini 3.x models primarily from centralized or multi-region scopes (global, us, eu) rather than individual legacy zonal regions like us-central1. This function powers preflight warnings when an incompatible region is selected in GEMINI_LOCATION.

    gemini_output_budget()

    Visibility: Public
    Signature: def gemini_output_budget(thinking_level: str | None, output_limit: int | None = None) -> int:

    Description: Resolves the planned output token allocation for Gemini models. It selects a baseline from GEMINI_OUTPUT_TOKENS_BY_EFFORT, clamps the value against the model's physical output ceiling (falling back to GEMINI_DEFAULT_LIMITS[1], which is 65,536 tokens), and applies any environment override configured in GEMINI_MAX_OUTPUT_TOKENS.

    Parameters: * thinking_level (str | None): The requested thinking effort level. * output_limit (int | None): The physical output token limit reported by the model metadata.

    Returns: * int: The planned maximum output token budget.

    Example: 

    def gemini_output_budget(thinking_level: str | None, output_limit: int | None = None) -> int:
    """Planned Gemini max_output_tokens: per-level table, capped by the model output limit and
    GEMINI_MAX_OUTPUT_TOKENS. Shared by llm_gemini (request) and token_utils (prompt budget)."""
    level = thinking_level.lower() if thinking_level else None
    budget = GEMINI_OUTPUT_TOKENS_BY_EFFORT.get(level, GEMINI_OUTPUT_TOKENS_BY_EFFORT[None])
    budget = min(budget, output_limit or GEMINI_DEFAULT_LIMITS[1])
    cap = _env_int("GEMINI_MAX_OUTPUT_TOKENS")
    return min(budget, cap) if cap else budget

    Gemini models feature separate input and output token pools rather than a single unified context window. This function ensures that downstream prompt packagers in token_utils.py do not over-reserve input tokens while guaranteeing that max_output_tokens passed to the Google GenAI SDK does not exceed the model's 65,536 limit.

    openrouter_output_budget()

    Visibility: Public
    Signature: def openrouter_output_budget(model: str, thinking_level: str | None) -> int | None:

    Description: Calculates the planned output token budget for models routed through OpenRouter. It queries the OpenRouter model catalog to identify top_provider.max_completion_tokens. If found, it clamps the per-effort allocation from OUTPUT_TOKENS_BY_EFFORT against the provider cap (or a default 32,000 threshold) and applies OPENROUTER_MAX_OUTPUT_TOKENS. If the model is not present in the catalog, it returns the environment cap directly, allowing callers to omit explicit token parameters.

    Parameters: * model (str): The OpenRouter model slug (e.g., "anthropic/claude-3.5-sonnet"). * thinking_level (str | None): The requested reasoning effort tier.

    Returns: * int | None: The calculated output token ceiling, or None if the model cannot be sized via catalog data.

    Example: 

    def openrouter_output_budget(model: str, thinking_level: str | None) -> int | None:
    """Planned OpenRouter max_tokens: shared per-effort table, capped by the catalog's
    top_provider.max_completion_tokens and OPENROUTER_MAX_OUTPUT_TOKENS. None when the model is not
    in the catalog (unknown limits, e.g. a non-OpenRouter proxy): max_tokens is then omitted."""
    info = openrouter_model_info(model)
    if info is None:
        return _env_int("OPENROUTER_MAX_OUTPUT_TOKENS")
    level = thinking_level.lower() if thinking_level else None
    budget = OUTPUT_TOKENS_BY_EFFORT.get(level, OUTPUT_TOKENS_BY_EFFORT[None])
    model_cap = (info.get("top_provider") or {}).get("max_completion_tokens")
    budget = min(budget, model_cap) if model_cap else min(budget, 32_000)
    cap = _env_int("OPENROUTER_MAX_OUTPUT_TOKENS")
    return min(budget, cap) if cap else budget

    OpenRouter hosts hundreds of upstream providers with varying completion limits. By dynamically querying catalog specifications, this function avoids sending invalid max_tokens values that exceed provider capabilities while still sizing prompt packing budgets appropriately.

    context_output_reserve()

    Visibility: Public
    Signature: def context_output_reserve(thinking_level: str | None) -> int | None:

    Description: Determines the number of output tokens that must be subtracted from the total context window to reserve generation space for the active provider. For Anthropic and OpenRouter, where prompt and generation share a combined window, it returns the planned max tokens. For Gemini, which enforces independent input and output token pools, it returns 0. For unconfigured providers, it returns None, signaling callers to apply a generic safety margin.

    Parameters: * thinking_level (str | None): The active reasoning effort level.

    Returns: * int | None: The number of tokens to reserve from the context window, 0 if pools are disjoint, or None for default handling.

    Example: 

    def context_output_reserve(thinking_level: str | None) -> int | None:
    """Output tokens that share the context window with the prompt, for the active provider.
    ANTHROPIC / OPENROUTER: the planned max_tokens (thinking included). GEMINI: 0 — Gemini's input and
    output limits are separate. None: the provider does not size output (5% reserve in token_utils)."""
    provider, model, _, _ = resolve_llm_settings()
    if provider == "ANTHROPIC":
        return anthropic_planned_output(model, thinking_level)
    if provider == "GEMINI":
        return 0
    if provider == "OPENROUTER":
        return openrouter_output_budget(model, thinking_level)
    return None

    This calculation directly informs prompt packing algorithms in token_utils.py. If a model shares context between input and output, failing to subtract the planned output budget from the prompt budget will lead to context window overflow during generation.

    get_llm_provider()

    Visibility: Public
    Signature: def get_llm_provider() -> str | None:

    Description: Determines the active LLM provider from the environment. An explicit LLM_PROVIDER environment variable takes highest precedence. If unset, it inspects Gemini-specific credentials (GEMINI_PROJECT_ID or GEMINI_API_KEY) and defaults to "GEMINI". Anthropic is intentionally never auto-selected without an explicit LLM_PROVIDER declaration to prevent accidental billing when generic development tools export ANTHROPIC_API_KEY.

    Parameters: * None

    Returns: * str | None: The uppercase provider identifier ("GEMINI", "ANTHROPIC", "OPENROUTER", or a custom name), or None if unresolvable.

    Example: 

    def get_llm_provider() -> str | None:
    """Determine the LLM provider from environment variables.

    Explicit LLM_PROVIDER wins; otherwise Gemini credentials select GEMINI (legacy default).
    ANTHROPIC is never auto-selected: ANTHROPIC_API_KEY is often exported globally for other
    tools (e.g. Claude Code), and a silent switch to a paid Claude run would be surprising.
    """
    provider = os.getenv("LLM_PROVIDER")
    if provider:
        return provider.strip().upper()
    if os.getenv("GEMINI_PROJECT_ID") or os.getenv("GEMINI_API_KEY"):
        return "GEMINI"
    return None

    The resolution logic prevents unintended costs associated with ambient environment configurations. Because tools like Claude Code and Cursor regularly export ANTHROPIC_API_KEY globally, treating that key as an implicit opt-in could silently incur Anthropic API charges without the developer's explicit intent.

    Visibility: Public
    Signature: def gemini_location() -> str:

    Description: Retrieves and normalizes the configured Google Cloud Vertex AI geographic location from GEMINI_LOCATION, falling back to DEFAULT_GEMINI_LOCATION ("global"). The string is converted to lowercase to match the case-sensitive endpoint routing required by the google-genai SDK.

    Parameters: * None

    Returns: * str: The lowercased Vertex AI location identifier.

    Example: 

    def gemini_location() -> str:
    """GEMINI_LOCATION lower-cased: google-genai matches 'global' / 'us' / 'eu' case-sensitively."""
    return (os.getenv("GEMINI_LOCATION") or DEFAULT_GEMINI_LOCATION).strip().lower()

    Normalizing this value is essential for Vertex AI SDK stability. Regional routing in google-genai expects lowercase strings ("global", "us", "eu"); variations in casing can cause endpoint lookup failures.

    openrouter_base_url()

    Visibility: Public
    Signature: def openrouter_base_url() -> str:

    Description: Resolves and formats the base URL for OpenRouter API interactions. It retrieves OPENROUTER_BASE_URL (defaulting to DEFAULT_OPENROUTER_BASE_URL), strips surrounding whitespace and trailing slashes, and removes any trailing /v1 suffix to standardize OpenAI SDK path construction.

    Parameters: * None

    Returns: * str: The sanitized OpenRouter base URL without a trailing slash or /v1 path component.

    Example: 

    def openrouter_base_url() -> str:
    """OPENROUTER_BASE_URL without a trailing '/' or '/v1' (OpenAI SDK style); paths add '/v1/...'."""
    base = (os.getenv("OPENROUTER_BASE_URL") or DEFAULT_OPENROUTER_BASE_URL).strip().rstrip("/")
    return base.removesuffix("/v1")

    OpenAI-compatible client libraries vary in whether they expect base URLs with or without /v1. Stripping this suffix ensures downstream URL builders can safely append /v1/chat/completions or /v1/models without producing invalid paths like /v1/v1/....

    is_openrouter_host()

    Visibility: Public
    Signature: def is_openrouter_host() -> bool:

    Signature: def _normalize_claude_id(model_name: str) -> str:

    Description: Normalizes heterogeneous Claude identifiers (including cloud gateway IDs from OpenRouter or AWS Bedrock and inverted version-first aliases) into a canonical, family-first string format.

    Parameters: * model_name (str): The raw model name or cloud path.

    Returns: * str: The normalized family-first identifier (e.g., "claude-opus-4-7").

    Example: 

    def _normalize_claude_id(model_name: str) -> str:
    """Gateway/cloud IDs → bare family-first Claude ID: 'anthropic/claude-opus-4.7',
    'bedrock/us.anthropic.claude-opus-4-7-v1:0' and the version-first alias

    _ratio_from_env()

    Visibility: Private
    Signature: def _ratio_from_env(name: str, default: float) -> float:

    Description: Parses a floating-point multiplier from an environment variable and clamps it to the inclusive interval defined by TOKEN_RATIO_BOUNDS (0.5 to 3.0). If the value cannot be parsed as a float or is non-finite (NaN or Inf), the provided fallback is used.

    Parameters: * name (str): The environment variable name. * default (float): The default fallback multiplier.

    Returns: * float: The validated and clamped float ratio.

    Example: 

    def _ratio_from_env(name: str, default: float) -> float:
    """Float env ratio clamped to TOKEN_RATIO_BOUNDS; unparsable / non-finite values use the default."""
    try:
        ratio = float(os.getenv(name, default))
    except ValueError:
        ratio = default
    if not math.isfinite(ratio):
        ratio = default
    low, high = TOKEN_RATIO_BOUNDS
    return min(max(ratio, low), high)

    Clamping the ratio prevents misconfigured environment variables from skewing token budget calculations. An extreme token multiplier could cause the pipeline to under-fill prompts or risk context window overflows during generation.

    Error Handling

    Preflight Failure Interception

    The module implements a fail-fast strategy via check_llm_auth(), validating configurations before execution begins: * Missing or Outdated Dependencies: check_gemini_config() validates that google-genai is installed and meets the GEMINI_MIN_SDK threshold (>= 1.56.0). Earlier versions reject thinking_level with Pydantic validation errors. If outdated or missing, execution is halted with clear upgrade instructions. * Anthropic Authentication Discovery: check_anthropic_auth() evaluates credentials across four tiers (API key, auth token, Workload Identity Federation, and ant auth CLI sessions). If no credentials exist, platform-specific setup commands (npm install -g @anthropic-ai/claude-code or native package managers) are displayed, returning False to prevent downstream request retries. * Model Retirement Enforcement: Models listed in GEMINI_RETIRED_MODELS are evaluated against their retirement policy. If a model has been shut down without an automatic alias on AI Studio (such as gemini-3.1-flash-lite-preview), preflight emits ERROR_GEMINI_MODEL_RETIRED and halts execution.

    Network Resilience & Failure Cooldown

    To prevent catalog queries from introducing latency during startup: * Catalog Failure Cooldown: In openrouter_catalog(), failed HTTP requests update _openrouter_last_failure. Subsequent calls within _OPENROUTER_RETRY_COOLDOWN (60 seconds) return None immediately without making repeated network calls. * Single Warning Emission: Diagnostic alerts use llm_common.warn_once("openrouter_catalog_unavailable") to prevent log noise across repeated catalog lookups.

    Defensive Parsing and Sanitization

    All environment extraction helpers defend against malformed inputs: * Integer Conversions: _env_int() requires strings to consist entirely of digits and resolve to values > 0. Empty or invalid values return None rather than raising ValueError. * Float Clamping: _ratio_from_env() catches ValueError exceptions and checks math.isfinite(), clamping multipliers to TOKEN_RATIO_BOUNDS ([0.5, 3.0]). * Subprocess Guarding: In check_anthropic_auth(), the subprocess.run(["ant", "auth", "status"]) invocation is wrapped in a try-except handling OSError and subprocess.SubprocessError, ensuring missing binaries or process timeouts do not crash the pipeline.
