    llm_config.py

    Source: utils/llm_config.py

    Technical Overview

    Building on the telemetry, token accounting, and refusal-handling mechanisms established in utils/llm_common.py, llm_config.py acts as the single source of truth for Large Language Model configuration, provider routing, context-window management, and credential preflight verification. It was extracted from call_llm.py to decouple the core dispatch engine from tokenizer token-counting utilities (token_utils.py), eliminating what was previously a cyclic dependency. Modules across the pipeline—including main.py, token_utils.py, and provider adapters—rely on this module to determine active endpoints, authentication parameters, thinking budgets, and context window limits.

    The module provides deterministic resolution across three supported provider backends: Google Gemini (both Vertex AI enterprise multi-region endpoints and Google AI Studio REST endpoints), Anthropic Claude (supporting direct API keys, auth tokens, Workload Identity Federation, and ant auth login OAuth profiles), and OpenRouter (incorporating an automated dynamic model catalog cache with exponential retry cooldowns). It normalizes disparate vendor naming conventions into unified model families, maps abstract reasoning effort tiers (minimal, low, medium, high, xhigh, max) into vendor-specific API structures, and enforces output token caps.

    Furthermore, llm_config.py executes early, fail-fast credential preflights prior to pipeline execution. Rather than allowing authentication failures to manifest mid-run after extensive crawling and analysis stages have completed, the preflight routines validate SDK installations, verify environment variables or OAuth credential profiles, inspect minimum client library versions, and verify access against provider metadata services.

    # utils/llm_config.py: lines 131-136
def anthropic_output_budget(thinking_level: str | None) -> int:
    """Per-effort table value capped by ANTHROPIC_MAX_OUTPUT_TOKENS (adaptive models)."""
    level = thinking_level.lower() if thinking_level else None
    budget = ANTHROPIC_MAX_TOKENS_BY_EFFORT.get(level, ANTHROPIC_MAX_TOKENS_BY_EFFORT[None])

    # utils/llm_config.py: lines 139-151
def anthropic_effort(model: str, level: str | None) -> str | None:
    """Thinking level → effort the model accepts: minimal → low, xhigh → high on the 4.6 family,
    unknown values → None (model default)."""
    if not level:
        return None
    level = level.lower()
    if level == "minimal":
        level = "low"
    if level not in ANTHROPIC_EFFORT_LEVELS:
        return None
    if level == "xhigh" and (model or "").lower().startswith(ANTHROPIC_NO_XHIGH_PREFIXES):
        return "high"
    return level

    The function normalizes input casing before evaluating membership against ANTHROPIC_EFFORT_LEVELS. If the model identifier begins with any prefix in ANTHROPIC_NO_XHIGH_PREFIXES (such as claude-opus-4-6 or claude-sonnet-4-6), requesting "xhigh" is automatically remapped to "high" to prevent HTTP 400 validation failures. Unrecognized levels evaluate to None, directing the downstream caller to rely on the model's server-side default.

    # utils/llm_config.py: lines 154-163
def anthropic_planned_output(model: str, thinking_level: str | None) -> int:
    """Claude max_tokens the request will plan for (before the model/context ceiling): the per-effort
    table on adaptive models, budget_tokens + 16K on pre-adaptive ones (Haiku 4.5), capped by
    ANTHROPIC_MAX_OUTPUT_TOKENS. Shared by llm_anthropic and token_utils.input_token_budget."""
    effort = anthropic_effort(model, thinking_level)
    if (model or "").lower().startswith(ANTHROPIC_ADAPTIVE_PREFIXES):
        return anthropic_output_budget(effort)
    planned = ANTHROPIC_BUDGET_BY_LEVEL.get(effort, 0) + ANTHROPIC_BUDGET_REPLY_TOKENS
    cap = anthropic_output_cap()
    return min(planned, cap) if cap else planned

    The routine evaluates whether model begins with any prefix listed in ANTHROPIC_ADAPTIVE_PREFIXES. For adaptive models, it delegates token allocation to anthropic_output_budget(). For pre-adaptive architectures, it looks up the explicit thinking budget in ANTHROPIC_BUDGET_BY_LEVEL (defaulting to 0) and adds ANTHROPIC_BUDGET_REPLY_TOKENS (16,000 tokens), clamping the result to ANTHROPIC_MAX_OUTPUT_TOKENS if defined.

    # utils/llm_config.py: lines 166-180
def gemini_thinking_mode(model: str) -> tuple[str, object]:
    """('level', allowed_levels) for Gemini 3.x, ('budget', (min, max, can_disable)) for 2.5,
    ('none', None) for models without a thinking control the project maps."""
    name = gemini_model_id(model)
    for prefix, low, high, can_disable in GEMINI_BUDGET_RANGES:
        if name.startswith(prefix):
            return "budget", (low, high, can_disable)
    if not name.startswith("gemini-") or name.startswith(("gemini-1", "gemini-2")):
        return "none", None  # 1.x / 2.0, other 2.5 variants (image, live, TTS) and non-Gemini ids
    for prefix, levels in GEMINI_THINKING_LEVELS:
        if name.startswith(prefix):
            return "level", levels
    # Other 3.x ids, '-latest' aliases (gemini-flash-latest, gemini-pro-latest) and newer families:
    # the level set every documented 3.x model accepts (a model that rejects it is handled at runtime).
    return "level", GEMINI_3_DEFAULT_LEVELS

    The function extracts the bare model name using gemini_model_id() and iterates over GEMINI_BUDGET_RANGES to identify legacy Gemini 2.5 models requiring ThinkingConfig.thinking_budget. Non-Gemini IDs and older generations (1.x, 2.0) return ("none", None). For modern Gemini 3.x models, it checks GEMINI_THINKING_LEVELS by prefix, defaulting unknown 3.x variants and aliases to GEMINI_3_DEFAULT_LEVELS.

    # utils/llm_config.py: lines 197-204
def gemini_output_budget(thinking_level: str | None, output_limit: int | None = None) -> int:
    """Planned Gemini max_output_tokens: per-level table, capped by the model output limit and
    GEMINI_MAX_OUTPUT_TOKENS. Shared by llm_gemini (request) and token_utils (prompt budget)."""

    # utils/llm_config.py: lines 207-219
def openrouter_output_budget(model: str, thinking_level: str | None) -> int | None:
    """Planned OpenRouter max_tokens: shared per-effort table, capped by the catalog's
    top_provider.max_completion_tokens and OPENROUTER_MAX_OUTPUT_TOKENS. None when the model is not
    in the catalog (unknown limits, e.g. a non-OpenRouter proxy): max_tokens is then omitted."""
    info = openrouter_model_info(model)
    if info is None:
        return _env_int("OPENROUTER_MAX_OUTPUT_TOKENS")
    level = thinking_level.lower() if thinking_level else None
    budget = OUTPUT_TOKENS_BY_EFFORT.get(level, OUTPUT_TOKENS_BY_EFFORT[None])
    model_cap = (info.get("top_provider") or {}).get("max_completion_tokens")
    budget = min(budget, model_cap) if model_cap else min(budget, 32_000)
    cap = _env_int("OPENROUTER_MAX_OUTPUT_TOKENS")
    return min(budget, cap) if cap else budget

    The function checks openrouter_model_info() for metadata. If metadata is unavailable, it returns OPENROUTER_MAX_OUTPUT_TOKENS (which may be None). When catalog metadata is present, it looks up the effort tier in OUTPUT_TOKENS_BY_EFFORT, bounds the budget by top_provider.max_completion_tokens (or 32,000 if omitted), and applies OPENROUTER_MAX_OUTPUT_TOKENS as an upper limit.

    Parameters:

    • thinking_level (str | None): Desired reasoning effort level.

    Returns:

    Example:

    # utils/llm_config.py: lines 222-233
def context_output_reserve(thinking_level: str | None) -> int | None:
    """Output tokens that share the context window with the prompt, for the active provider.
    ANTHROPIC / OPENROUTER: the planned max_tokens (thinking included). GEMINI: 0 — Gemini's input and
    output limits are separate. None: the provider does not size output (5% reserve in token_utils)."""
    provider, model, _, _ = resolve_llm_settings()
    if provider == "ANTHROPIC":
        return anthropic_planned_output(model, thinking_level)
    if provider == "GEMINI":
        return 0
    if provider == "OPENROUTER":
        return openrouter_output_budget(model, thinking_level)
    return None

    This method calls resolve_llm_settings() to inspect the runtime provider. For Anthropic and OpenRouter, output generation directly consumes capacity from the shared model context window, requiring explicit deduction via anthropic_planned_output() or openrouter_output_budget(). For Gemini, input and output limits do not share a context budget, so the function returns 0. If the provider is unrecognized, returning None prompts token_utils to apply a generic fallback reserve of 5%.

    Parameters:

    None.

    Returns:

    Raises:

    Example:

    # utils/llm_config.py: lines 236-248
def get_llm_provider() -> str | None:
    """Determine the LLM provider from environment variables.

    Explicit LLM_PROVIDER wins; otherwise Gemini credentials select GEMINI (legacy default).
    ANTHROPIC is never auto-selected: ANTHROPIC_API_KEY is often exported globally for other
    tools (e.g. Claude Code), and a silent switch to a paid Claude run would be surprising.
    """
    provider = os.getenv("LLM_PROVIDER")
    if provider:
        return provider.strip().upper()
    if os.getenv("GEMINI_PROJECT_ID") or os.getenv("GEMINI_API_KEY"):
        return "GEMINI"
    return None

    The function reads LLM_PROVIDER and strips and uppercases its value. If omitted, it inspects GEMINI_PROJECT_ID or GEMINI_API_KEY. As documented in the code, ANTHROPIC is never auto-selected without an explicit LLM_PROVIDER=ANTHROPIC declaration, preventing accidental billing if developer environments have ambient Claude API keys configured for other tools.

    """The model catalog, or None when it could not be fetched (yet). Every failed fetch is announced:
    ``CATALOG_RETRY`` (fetched again when next needed, after the doubling cooldown) or, for a permanent failure,
    ``CATALOG_GAVE_UP``; a fetch that succeeds after failures says so (``CATALOG_LOADED``)."""

def openrouter_model_info(model_id: str) -> dict | None:
    """Catalog entry for a model id: exact id, canonical_slug, routing-suffix variant
    (':nitro', ':floor', ...), dated canonical slug (e.g. 'anthropic/claude-4.6-opus' →

    if _env_set("ANTHROPIC_API_KEY"):
        emit("ANTHROPIC_AUTH_OK", source="ANTHROPIC_API_KEY")
        return True
    if _env_set("ANTHROPIC_AUTH_TOKEN"):
        emit("ANTHROPIC_AUTH_OK", source="ANTHROPIC_AUTH_TOKEN")
        return True
    if all(_env_set(v) for v in _FEDERATION_VARS) and (_env_set("ANTHROPIC_IDENTITY_TOKEN_FILE") or _env_set("ANTHROPIC_IDENTITY_TOKEN")):
        emit("ANTHROPIC_AUTH_OK", source="Workload Identity Federation")
        return True

    # No key: the SDK falls back to an `ant auth login` profile. Verify one is active.
    ant = shutil.which("ant")
    if not ant:
        stored = sorted(glob.glob(os.path.join(_anthropic_config_dir(), "credentials", "*.json")))
        if stored:
            emit("WARN_ANTHROPIC_ANT_MISSING_LOGIN_FOUND", path=stored[0])
            return True
        emit("ERROR_ANTHROPIC_NO_CREDENTIALS")
        _emit_auth_help(ant_installed=False)
        return False

    # Run with the same environment the SDK will see; empty key variables are dropped so the
    # CLI reports the profile the SDK will actually use (the SDK treats empty as unset).
    env = {k: v for k, v in os.environ.items() if not (k in ("ANTHROPIC_API_KEY", "ANTHROPIC_AUTH_TOKEN") and not v.strip())}
    try:
        result = subprocess.run([ant, "auth", "status"], capture_output=True, text=True, encoding="utf-8", errors="replace", timeout=30, env=env)
    except (OSError, subprocess.SubprocessError) as e:
        emit("WARN_ANTHROPIC_AUTH_UNVERIFIED", error=str(e))
        return True

    output = f"{result.stdout}\n{result.stderr}"
    credential, workspace = parse_ant_auth_status(output)
    emit_raw("DEBUG", f"ant auth status | exit={result.returncode}\n{_redact(output).strip()}", dest="LOG")
    if not credential:
        emit("ERROR_ANTHROPIC_NOT_LOGGED_IN")
        details = _redact(output).strip()
        if details:
            emit_raw("INFO", "\n".join(f"    {line}" for line in details.splitlines()))
        _emit_auth_help(ant_installed=True)
        return False

    source = _ui("AUTH_SOURCE_ANT_LOGIN", credential=credential)
    if workspace:
        source += f" | {_ui('AUTH_SOURCE_WORKSPACE', workspace=workspace)}"
    emit("ANTHROPIC_AUTH_OK", source=source)
    return True

    This preflight routine runs through several authentication checks:

    1. Validates whether the anthropic Python SDK is installed via _anthropic_sdk_installed().
    2. Inspects ANTHROPIC_API_KEY and ANTHROPIC_AUTH_TOKEN.
    3. Verifies Workload Identity Federation variables (_FEDERATION_VARS alongside ANTHROPIC_IDENTITY_TOKEN or its file counterpart).
    4. If explicit tokens are missing, it looks for the ant CLI tool on PATH. If missing, it checks for stored JSON profile files in _anthropic_config_dir().
    5. If ant is found, it runs ant auth status in a 30-second subprocess. It parses active credentials via parse_ant_auth_status(), logging redacted diagnostics and printing setup guidance via _emit_auth_help() if authentication is incomplete.

    Error Handling

    Rather than raising unhandled exceptions during execution, llm_config.py uses defensive validation and preflight checks to emit diagnostic events and return status indicators.

    Fail-Fast Preflight Verification

    check_llm_auth(), check_anthropic_auth(), and check_gemini_config() run before pipeline execution to catch authentication and configuration problems early:

    • Missing SDK packages (e.g., google-genai or anthropic) emit descriptive error events (ERROR_ANTHROPIC_SDK_MISSING, ERROR_GEMINI_SDK_MISSING) and return False.
    • Outdated libraries (such as google-genai versions below (1, 56, 0)) emit ERROR_GEMINI_SDK_OUTDATED and return False, preventing runtime validation errors when configuring thinking levels.
    • Deprecated Gemini preview models trigger WARN_GEMINI_MODEL_RETIRED on AI Studio or hard-fail with ERROR_GEMINI_MODEL_RETIRED on Vertex AI.
    • Missing API keys or invalid CLI login states trigger setup help via _emit_auth_help() and emit notifications like ERROR_ANTHROPIC_NOT_LOGGED_IN or ERROR_GEMINI_NO_CREDENTIALS.

    OpenRouter Catalog Resiliency and Backoff

    The OpenRouter catalog fetcher in openrouter_catalog() handles network and endpoint failures with adaptive retry logic:

    • Transient Network Failures: Connection timeouts, HTTP 408, HTTP 429, or 5xx server errors trigger an exponential cooldown (_catalog_cooldown()) that starts at 60 seconds and doubles up to 900 seconds. Failures emit CATALOG_RETRY, allowing subsequent calls to retry after the cooldown expires.
    • Permanent Endpoint Failures: Non-retryable HTTP 4xx errors (excluding 408/429) or JSON payloads missing the required data list set _openrouter_gave_up = True and emit CATALOG_GAVE_UP. This halts further catalog requests for the remainder of the run.
    • One-Time Warnings: Missing catalog data emits WARN_OPENROUTER_CATALOG_UNAVAILABLE only once per run via warn_once(), avoiding log spam while the system falls back to safe offline defaults.

    Subprocess and Environment Fault Tolerance

    • Anthropic CLI Parsing: check_anthropic_auth() executes ant auth status within a 30-second timeout guard. OSError and subprocess.SubprocessError exceptions are trapped to emit WARN_ANTHROPIC_AUTH_UNVERIFIED, allowing execution to continue if stored credential files exist.
    • Token Redaction: _redact() masks tokens matching _TOKEN_PATTERN (sk-ant-*) before writing command output to debug logs, preventing secret leaks.
    • Numeric Parsing: _env_int() and _ratio_from_env() handle unparsable, non-numeric, or non-finite environment variables by falling back to safe defaults and clamping ratios within TOKEN_RATIO_BOUNDS.
