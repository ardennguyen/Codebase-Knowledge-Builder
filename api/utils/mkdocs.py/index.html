    mkdocs.py

    Source: utils/mkdocs.py

    Technical Overview

    The utils/mkdocs.py module is the centralized documentation synthesis, static site configuration, and navigation generation subsystem in Codebase-Knowledge-Builder. It consolidates output pipeline mechanics previously distributed across workflow nodes, providing end-to-end transformation of raw generated chapter content into fully configured MkDocs Material documentation suites or standalone multi-chapter Markdown bundles. The module handles configuration building (mkdocs.yml), JavaScript asset generation for Mermaid diagrams, LLM-driven architectural module grouping, dependency graph generation, cross-chapter link normalization, deterministic dependency provenance tagging, and render-verified CommonMark markup repair.

    Architecturally, the module sits downstream of chapter generation and verification passes. When invoked in api-reference mode, it uses deterministic source facts extracted by utils/facts.py alongside LLM clustering to arrange modules into domain-driven architectural sections. It computes dependency fan-in metrics to identify shared structural hubs, generating responsive Mermaid diagrams for high-level module architecture and granular dependency interactions. For content integrity, the file implements a verification-guarded markup repair engine that re-indents nested lists and inserts missing blank lines ahead of tables and lists, verifying through an in-memory MkDocs Markdown renderer instance that no visible prose or fenced code blocks are mutated.

    Public API

    yaml_str()

    Visibility: Public

    Signature: def yaml_str(value) -> str:

    Description: Quotes and serializes a Python scalar value into a valid YAML double-quoted string literal using JSON encoding (json.dumps). This ensures that labels, navigation titles, and section names containing colons, quotes, leading @ symbols, or brackets can be safely embedded into hand-crafted YAML documents like mkdocs.yml without syntax corruption.

    Parameters:

    • value (Any): The scalar value to stringify, strip, and quote.

    Returns:

    • str: A JSON-encoded, double-quoted string literal safe for inclusion in YAML files.

    Example:

    # From utils/mkdocs.py: Hand-crafting safe navigation strings
home_line = f"  - {yaml_str(get('UI_HOME'))}: index.md\n" if include_home else ""
lines.append(f"{pad}- {yaml_str(section['name'])}:")

    The function executes json.dumps(str(value).strip(), ensure_ascii=False). Because JSON string literals conform strictly to YAML scalar double-quote specifications, characters that would otherwise trigger YAML syntax errors (such as : or #) are safely escaped.

    build_mkdocs_config()

    Visibility: Public

    Signature: def build_mkdocs_config(site_name: str, nav_yaml: str, include_home: bool = True, lang_code: str = "") -> str:

    Description: Generates the complete mkdocs.yml configuration specification for MkDocs Material sites. Configures theme settings, search, interactive Mermaid rendering via pymdownx.superfences using a custom mermaid-raw div class, pan/zoom plugin support, code syntax highlighting, copy-to-clipboard buttons, palette toggle controls (light/dark mode), and hierarchical navigation trees.

    Parameters:

    • site_name (str): The project name and documentation title to display in the header.
    • nav_yaml (str): Pre-formatted YAML navigation block generated by navigation routines.
    • include_home (bool): Whether to insert an explicit Home (docs/index.md) entry at the top of navigation. Defaults to True.
    • lang_code (str): Optional ISO 639-1 language code string (e.g., "vi", "zh", "ja") for MkDocs Material UI localization. Defaults to "".

    Returns:

    • str: The complete raw YAML text ready to be written to mkdocs.yml.

    Example:

    mkdocs_config = build_mkdocs_config(
    site_title,
    nav_snippet,
    include_home=True,
    lang_code=lang_code,
)
with open(mkdocs_filepath, "w", encoding="utf-8") as f:
    f.write(mkdocs_config)

    The function splits nav_yaml to strip the root nav: declaration before indenting the navigation body. It configures pymdownx.superfences with a custom fence formatter mapping mermaid to the mermaid-raw HTML class, ensuring MkDocs Material's built-in color schemes do not override native Mermaid styling. It also configures the panzoom plugin to target .mermaid-raw while explicitly excluding .mermaid to prevent double-wrapping containers.

    split_frontmatter()

    Visibility: Public

    Signature: def split_frontmatter(text: str) -> tuple[str, bool]:

    Description: Strips leading YAML frontmatter blocks from Markdown source text according to MkDocs metadata parsing rules. Validates that the delimited block parses as a valid YAML mapping (dict) before stripping; horizontal rules (---) that do not constitute valid YAML mappings are retained as content.

    Parameters:

    • text (str): Raw Markdown string.

    Returns:

    • tuple[str, bool]: A tuple containing (body_text, found_flag).

    Example:

    match = _FRONTMATTER_RE.match(text)
if match:
    try:
        if isinstance(yaml.safe_load(match.group(1)), dict):
            return text[match.end() :].strip(), True
    except Exception:
        pass
return text, False

    The method matches against _FRONTMATTER_RE. If yaml.safe_load fails with YAMLError or ValueError (such as impossible dates), the exception is suppressed and the text is returned unmodified.

    clip_sentences()

    Visibility: Public

    Signature: def clip_sentences(text: str, limit: int) -> str:

    Description: Collapses irregular whitespace and extracts whole grammatical sentences from text up to a specified character limit. Preserves abbreviations, supports CJK sentence boundary delimiters, truncates gracefully at word boundaries if the first sentence exceeds the limit, and closes open Markdown inline backticks.

    Parameters:

    • text (str): Source prose text.
    • limit (int): Maximum allowed character length.

    Returns:

    • str: Truncated, whitespace-normalized sentence string ending cleanly or with an ellipsis (…).

    Example:

    # Extract up to 400 characters of clean sentence text
cleaned_desc = clip_sentences(raw_description, 400)

    The function uses regex _SENTENCE_END_RE while evaluating tokens against _ABBREVIATIONS via _ends_with_abbreviation. If no complete sentence fits within limit, it splits at the last word boundary, counts backticks, appends a balancing backtick if odd (clipped.count("") % 2`), and terminates with an ellipsis.

    table_cell_text()

    Visibility: Public

    Signature: def table_cell_text(text: str) -> str:

    Description: Escapes pipe characters (|) with backslashes (\|) so the string can be safely embedded in Markdown table cells, while keeping pipes inside inline code spans (...) unescaped.

    Parameters:

    • text (str): Text intended for insertion into a table column.

    Returns:

    • str: Escaped string safe for Markdown table parsing.

    Example:

    parts, position = [], 0
for match in _CODE_SPAN_RE.finditer(text):
    parts.append(text[position : match.start()].replace("|", "\\|"))
    parts.append(match.group(0))
    position = match.end()
parts.append(text[position:].replace("|", "\\|"))
return "".join(parts)

    Uses _CODE_SPAN_RE to iterate over code spans, escaping pipes only in text segments located between matches.

    module_name_lookup()

    Visibility: Public

    Signature: def module_name_lookup(chapter_files: list) -> dict:

    Description: Builds a name resolution dictionary that maps alternative module identifiers (such as original file paths, exact module names, and unique basenames) to canonical module_name values.

    Parameters:

    • chapter_files (list): List of chapter file dictionaries.

    Returns:

    • dict[str, str]: Mapping of identifier aliases to authoritative module names.

    Example:

    lookup = {}
basename_counts = Counter(os.path.basename(cf.get("original_path") or cf["module_name"]) for cf in chapter_files)
for cf in chapter_files:
    name = cf["module_name"]
    lookup[name] = name
    if cf.get("original_path"):
        lookup.setdefault(cf["original_path"], name)
    basename = os.path.basename(cf.get("original_path") or name)
    if basename_counts[basename] == 1:
        lookup.setdefault(basename, name)
return lookup

    Identifies unique basenames across all modules. If a basename occurs only once, it is added to the dictionary to map LLM-shortened names back to their canonical modules.

    build_module_graph()

    Visibility: Public

    Signature: def build_module_graph(sections: list, dependencies: dict, chapter_files: list) -> tuple[str, int]:

    Description: Constructs a comprehensive Mermaid module dependency diagram for api/index.md. Generates a flowchart subgraph for each top-level section and individual nodes for each module. Central architectural hub modules (modules used by at least max(5, total // 4) other modules) have their incoming edges detached to prevent diagram tangling, and are instead annotated with usage counts and highlighted using the entryNode class.

    Parameters:

    • sections (list): Hierarchical section grouping list.
    • dependencies (dict): Map of source module names to lists of target module names.
    • chapter_files (list): List of all chapter metadata dictionaries.

    Returns:

    • tuple[str, int]: A 2-tuple containing:
      1. Mermaid diagram source string (or empty string if dependencies are empty or module count exceeds 80).
      2. Integer hub threshold value (0 if no hubs were identified).

    Example:

    module_graph, hub_threshold = build_module_graph(sections, dependencies, chapter_files)
if module_graph:
    index_lines += [f"## {get('UI_MODULE_DEPENDENCIES')}", "", "```mermaid", module_graph, "```", ""]

    If len(chapter_files) > _MODULE_GRAPH_MAX_MODULES (80), the function returns ("", 0) because full-system Mermaid rendering becomes unreadable. Edge connections directed into hub nodes are omitted from the diagram (if target not in hubs) to eliminate arrow clutter.

    Visibility: Public

    Signature: def build_hub_fan_ins(sections: list, dependencies: dict, chapter_files: list, threshold: int) -> list[tuple[str, str]]:

    Description: Generates dedicated, isolated Mermaid fan-in diagrams for modules identified as shared architectural hubs by build_module_graph. Creates a separate small diagram for each hub, grouping its consumer modules by section and displaying directed arrows annotated with consumer counts.

    Parameters:

    • sections (list): Section grouping tree.
    • dependencies (dict): Module dependency mappings.
    • chapter_files (list): List of chapter file objects.
    • threshold (int): Usage threshold used to qualify a module as a hub.

    Returns:

    • list[tuple[str, str]]: List of (hub_module_name, mermaid_diagram_source) tuples sorted in descending order of consumer count.

    Example:

    for hub, fan_in in build_hub_fan_ins(sections, dependencies, chapter_files, hub_threshold):

    For each qualifying hub, the function inverts the dependency graph to find all consumers, groups those consumers by their parent navigation section, and draws arrows from the consumer section boxes to the central hub node with link labels showing user counts (-->|count| H).

    Error Handling

    The module implements defensive error handling patterns across parsing, network requests, and static site generation:

    1. LLM Grouping Retries: request_grouping wraps calls to call_llm in a retry loop with a maximum of GROUPING_ATTEMPTS (3) attempts and a GROUPING_WAIT delay (20 seconds). Non-retryable LLMRefusalError exceptions break the retry loop and re-raise immediately, while retryable refusals and timeout exceptions trigger backoff and telemetry events. If all attempts fail, the function raises the underlying exception, allowing write_mkdocs_output to catch it and fall back to directory_sections.
    2. Empty Section Pruning: Empty sections parsed from LLM responses are pruned by prune_sections. If no valid sections remain after pruning, request_grouping raises a localized ValueError(get("GROUP_NO_SECTIONS")).
    3. Renderer Fault Tolerance: site_renderer wraps Markdown parser initialization in a broad exception handler. If dependencies or extensions are missing, it emits a CHAPTER_CHECK_NO_RENDERER telemetry event and returns None, allowing the pipeline to proceed without markup verification.
    4. Render-Guarded Markup Repair: repair_markup tests candidate fixes against an in-memory MkDocs renderer, discarding any repair that alters visible text characters (_visible), changes code blocks (_code_blocks), or shifts CommonMark block assignments (markup_verdicts).
    5. Frontmatter Validation: split_frontmatter catches yaml.YAMLError and ValueError exceptions when parsing frontmatter blocks, ensuring that Markdown documents opening with horizontal rules (---) are not corrupted.
