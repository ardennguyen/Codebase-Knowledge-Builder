    mkdocs.py

    Source: utils/mkdocs.py

    Following the structural repository traversal and selective content retrieval orchestrated by files.py, the pipeline synthesizes generated documentation artifacts into publication-ready static sites. The utils/mkdocs.py module serves as the final rendering and serialization engine for the documentation pipeline, consolidating site configuration, recursive navigation grouping, index page synthesis, client-side diagram orchestration, and cross-chapter hyperlink normalization.

    Technical Overview

    The utils/mkdocs.py module decouples documentation generation from specific output formats by managing the disk serialization and layout formatting for both MkDocs Material static sites and standalone Markdown bundles. Originally refactored from scattered static routines across nodes.py and utils/prompts.py, this component standardizes the creation of the mkdocs.yml specification, handles deep hierarchical navigation trees, and generates automated index matrices.

    The module provides two distinct output pathways: 1. MkDocs Material Pipeline (write_mkdocs_output): Configures a complete documentation site featuring dark/light palettes, search plugins, interactive Panzoom pan/zoom controls, custom Mermaid diagram DOM un-wrapping, automated redirect landing pages (docs/index.md), rich API index matrices (docs/api/index.md), and deterministic relative link normalization. 2. Standalone Markdown Pipeline (write_standalone_output): Assembles decoupled Markdown files alongside an aggregated single-file document (full_content.md) complete with anchor-based tables of contents for portability.

    For complex API reference documentation exceeding five modules, the module dynamically interfaces with call_llm.py to synthesize logical module groupings using domain reasoning, while falling back to structural filesystem hierarchies or flat navigation lists if inference fails or thresholds are unmet.

    Public API

    build_mkdocs_config()

    Visibility: Public
    Signature: def build_mkdocs_config(site_name: str, nav_yaml: str, include_home: bool = True, lang_code: str = "") -> str:

    Description: Programmatically constructs the text content of a complete mkdocs.yml configuration targeting the mkdocs-material theme. It configures code block copy buttons, search indexing, deep navigation indexes, light/slate dark mode toggles, and syntax highlighting via pymdownx.highlight and pymdownx.inlinehilite. To prevent Material's internal styling from clashing with custom Mermaid rendering, it binds Mermaid code blocks to the .mermaid-raw CSS class via pymdownx.superfences custom fences and configures the panzoom plugin to target .mermaid-raw selectors.

    Parameters: * site_name (str): Title of the documentation site displayed in the MkDocs header and metadata. * nav_yaml (str): Raw navigation YAML string (typically generated by build_grouped_nav or provided in prep_res). * include_home (bool, optional): Whether to inject a - Home: index.md navigation entry. Defaults to True. * lang_code (str, optional): Two-letter ISO language code (e.g., "vi", "zh", "ja") for UI localization. Defaults to "".

    Returns: * str: Fully formatted, ready-to-write mkdocs.yml configuration string.

    Raises: * This function does not raise internal exceptions; string interpolation operations are fully deterministic.

    Example: 

    def build_mkdocs_config(site_name: str, nav_yaml: str, include_home: bool = True, lang_code: str = "") -> str:
    # Extract nav items from nav_snippet (strip the "nav:" header line)
    nav_lines = nav_yaml.split("\n")
    nav_body = "\n".join(nav_lines[1:]) if nav_lines else ""

    # Conditional Home nav entry (CI has root index.md, local mkdocs doesn't)
    home_line = "  - Home: index.md\n" if include_home else ""

    # Optional Material theme language (e.g. "vi", "zh", "ja", "ko")
    lang_line = f"  language: {lang_code}\n" if lang_code else ""

    return (
        f"site_name: '{site_name}'\n"
        f"theme:\n"
        f"  name: material\n"
        f"{lang_line}"
        f"  features:\n"
        f"    - content.code.copy\n"
        f"    - navigation.indexes\n"
        f"  palette:\n"
        f"    - scheme: default\n"
        f"      toggle:\n"
        f"        icon: material/brightness-7\n"
        f"        name: Switch to dark mode\n"
        f"    - scheme: slate\n"
        f"      toggle:\n"
        f"        icon: material/brightness-4\n"
        f"        name: Switch to light mode\n"
        f"plugins:\n"
        f"  - search\n"
        f"  - panzoom:\n"
        f"      include_selectors:\n"
        f"        - '.mermaid-raw'\n"
        f"markdown_extensions:\n"
        f"  - pymdownx.highlight:\n"
        f"      anchor_linenums: true\n"
        f"      use_pygments: true\n"
        f"  - pymdownx.superfences:\n"
        f"      custom_fences:\n"
        f"        - name: mermaid\n"
        f"          class: mermaid-raw\n"
        f"          format: !!python/name:pymdownx.superfences.fence_code_format\n"
        f"  - pymdownx.inlinehilite\n"
        f"extra_javascript:\n"
        f"  - https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.min.js\n"
        f"  - javascripts/mermaid-init.js\n"
        f"nav:\n"
        f"{home_line}"
        f"{nav_body}\n"
    )

    The function handles string decomposition by splitting the input nav_yaml across newline boundaries and stripping the initial top-level nav: declaration, allowing the navigation tree to be nested cleanly under the root configuration. It selectively injects language attributes and home entry directives based on incoming flags, ensuring that local executions and continuous integration environments configure their respective landing hierarchies correctly. The returned YAML payload integrates CDN-hosted Mermaid runtime assets alongside local initialization hooks to ensure that diagrams render reliably upon DOM load.

    build_mermaid_init_js()

    Visibility: Public
    Signature: def build_mermaid_init_js() -> str:

    Description: Accessor function returning the embedded JavaScript script string (MERMAID_INIT_JS) required to bridge MkDocs Material, PyMdown Extensions, and Mermaid.js.

    Parameters: * None.

    Returns: * str: The complete client-side JavaScript source code string.

    Raises: * No exceptions are raised.

    Example: 

    def build_mermaid_init_js() -> str:
    """Return the JavaScript snippet that initializes Mermaid diagrams."""
    return MERMAID_INIT_JS

    The underlying script resolves a specific markup incompatibility between PyMdown SuperFences and Mermaid v11. Because SuperFences outputs <pre class="mermaid-raw"><code>...</code></pre>, the initialization script queries all matching preformatted tags, extracts the inner text from the nested <code> element, hoists that content directly into the <pre> container, and purges the child element before triggering mermaid.run(). This unwrapping prevents Mermaid syntax evaluation errors while maintaining strict diagram styling isolation from MkDocs CSS overrides.

    build_grouped_nav()

    Visibility: Public
    Signature: def build_grouped_nav(sections: list, chapter_files: list, indent: int = 4) -> list[str]:

    Description: Recursively constructs formatted YAML navigation lines from an arbitrary-depth section grouping tree (derived from LLM clustering). For each section, it evaluates nested sub-sections under the children key and matches module leaf nodes against the chapter_files collection via module_name. It groups files within each section by their originating subdirectory (original_path), nesting non-root files within directory-specific sub-layers while keeping repository root files flat.

    Parameters: * sections (list): A list of dictionaries representing logical sections, optionally containing nested children and modules lists. * chapter_files (list): List of chapter dictionaries containing metadata (module_name, filename, original_path). * indent (int, optional): Number of leading indentation spaces to apply to generated YAML lines. Defaults to 4.

    Returns: * list[str]: An ordered collection of indented YAML lines representing the navigation tree.

    Raises: * No explicit exceptions raised; missing module references in chapter_files are safely skipped via fallback iterators.

    Example: 

    def build_grouped_nav(sections: list, chapter_files: list, indent: int = 4) -> list[str]:
    emit_raw("DEBUG", f"build_grouped_nav | building nav for {len(sections)} sections", dest="LOG")
    from collections import defaultdict

    lines = []
    pad = " " * indent
    for section in sections:
        lines.append(f"{pad}- {section['name']}:")
        if "children" in section:
            lines.extend(build_grouped_nav(section["children"], chapter_files, indent + 2))

        # Collect matched modules with directory info
        matched = []
        for mod_name in section.get("modules", []):
            match = next((cf for cf in chapter_files if cf["module_name"] == mod_name), None)
            if match:
                dir_path = os.path.dirname(match.get("original_path", "")) or ""
                matched.append((dir_path, mod_name, match))

        # Group by directory
        dir_groups = defaultdict(list)
        for dir_path, mod_name, match in matched:
            dir_groups[dir_path].append((mod_name, match))

        # Emit dir sub-layers for non-root dirs, flat for root files
        has_non_root = any(d for d in dir_groups)
        if has_non_root:
            for dir_path in sorted(dir_groups.keys()):
                if dir_path:
                    # Non-root: add directory sub-layer with bare module names
                    lines.append(f"{pad}  - {dir_path}:")
                    for mod_name, match in dir_groups[dir_path]:
                        lines.append(f"{pad}    - '{mod_name}': 'api/{match['filename']}'")
                else:
                    # Root files: flat (no sub-layer)
                    for mod_name, match in dir_groups[dir_path]:
                        lines.append(f"{pad}  - '{mod_name}': 'api/{match['filename']}'")
        else:
            # All root files → flat list
            for _dir_path, mod_name, match in matched:
                lines.append(f"{pad}  - '{mod_name}': 'api/{match['filename']}'")

    return lines

    The algorithm navigates the grouping tree by applying indentation proportional to the recursion depth (indent + 2 for nested sub-sections). To avoid chaotic menu layouts when many files share a logical category, it extracts the parent directory path via os.path.dirname on each file's original_path. By organizing items through a defaultdict(list), the method injects intermediate structural folders only when non-root files are present, emitting bare module names scoped cleanly within their parent folder paths.

    collect_all_modules()

    Visibility: Public
    Signature: def collect_all_modules(sections: list) -> set:

    Description: Recursively traverses a hierarchical section dictionary tree to extract and aggregate all referenced module_name strings into a unified set. Used primarily for post-grouping validation to identify orphaned modules dropped during LLM synthesis.

    Parameters: * sections (list): List of section dictionaries that may contain modules (list of strings) and children (nested section lists).

    Returns: * set: Unordered set containing every string module name present across the entire hierarchy.

    Raises: * No exceptions raised.

    Example: 

    def collect_all_modules(sections: list) -> set:
    """Recursively collect all module names referenced in a sections tree."""
    result = set()
    for section in sections:
        result.update(section.get("modules", []))
        if "children" in section:
            result.update(collect_all_modules(section["children"]))
    return result

    This helper implements a classic tree traversal pattern, accumulating module identifiers at each level using set.update() before descending into any nested structures within section["children"]. The resulting collection provides a complete list of all clustered modules, enabling callers to run set-difference operations against original input files to detect omissions.

    write_mkdocs_output()

    Visibility: Public
    Signature: def write_mkdocs_output(output_path, prep_res, chapter_files):

    Description: Main orchestrator for generating static MkDocs documentation. It resolves navigation hierarchies (leveraging LLM clustering when appropriate), writes configuration files, builds landing and redirect pages, executes deterministic cross-chapter link normalization, and serializes final Markdown chapters to disk.

    Parameters: * output_path (str): Base output directory where the documentation hierarchy and mkdocs.yml will be created. * prep_res (dict): Pipeline metadata dictionary containing project configuration, navigation snippets, mode settings, translation keys, and prompt inputs. * chapter_files (list[dict]): Ordered list of generated chapter payloads, including filenames, module names, summaries, and Markdown text.

    Returns: * None

    Raises: * OSError / IOError: Raised if the target filesystem directories cannot be created or file write operations fail.

    Phase 1: Output Directory Initialization & Mode Setup

    The function initializes directory structures, creates docs/api, and sets localized site branding based on pipeline operational modes:

        project_name = prep_res["project_name"]
    mode = prep_res["mode"]
    api_docs_path = os.path.join(output_path, "docs", "api")
    os.makedirs(api_docs_path, exist_ok=True)

    mode_labels = {
        "tutorial": get("UI_MODE_TUTORIAL"),
        "advanced": get("UI_MODE_ADVANCED"),
        "sdk": get("UI_MODE_SDK"),
        "api-reference": get("UI_MODE_API_REF"),
    }
    site_title = f"{project_name} — {mode_labels.get(mode, 'Documentation')}"
    emit("COMBINE_FORMAT_MKDOCS", mode=mode_labels.get(mode, "Documentation"))
    emit("COMBINE_CHAPTER_COUNT", count=len(chapter_files))

    This initialization phase ensures that the target filesystem path docs/api exists prior to disk operations. It maps the internal execution mode string to localized UI strings via get(), dynamically configuring the primary site title used in page headers and browser tab labels.

    Phase 2: LLM-Assisted Nav Grouping & Hierarchy Resolution

    When operating in api-reference mode with more than five chapters, the function invokes an LLM to cluster flat module listings into functional architectural sections:

        sections = None
    emit_raw("DEBUG", f"NAV GROUPING CHECK | mode={mode} | module_count={len(chapter_files)} | threshold=6", dest="LOG")
    if mode == "api-reference" and len(chapter_files) > 5:
        try:
            chapter_summaries = prep_res.get("chapter_summaries", [])
            module_entries = []
            for i, cf in enumerate(chapter_files):
                summary = chapter_summaries[i] if i < len(chapter_summaries) and chapter_summaries[i] else cf["description"]
                module_entries.append(f"- {cf['module_name']}: {summary}")
            module_list = "\n".join(module_entries)

            # Load grouping prompt template
            prompt_path = os.path.join(os.path.dirname(os.path.dirname(os.path.abspath(__file__))), "prompts", "common", "group_modules.md")
            with open(prompt_path, encoding="utf-8-sig") as f:
                group_template = f.read()

            language = prep_res.get("language", "english")
            language_note = f"Section names MUST be in {language}." if language.lower() != "english" else ""

            group_prompt = group_template.format(
                project_name=project_name,
                module_count=len(chapter_files),
                module_list=module_list,
                directory_tree=prep_res.get("directory_tree", "N/A"),
                language_note=language_note,
            )

            emit("LLM_CALL_GROUPING", count=len(chapter_files))

            log_token_estimation("NavGrouping", group_prompt, prep_res.get("max_tokens", 100000))
            group_response = call_llm(group_prompt, use_cache=prep_res.get("use_cache", True), thinking_level=prep_res.get("thinking_level"))
            parsed = parse_yaml_response(group_response)
            sections = parsed.get("sections", parsed) if isinstance(parsed, dict) else None

            if sections:
                # Validate: ensure all modules are covered
                grouped_modules = collect_all_modules(sections)
                ungrouped = [cf["module_name"] for cf in chapter_files if cf["module_name"] not in grouped_modules]
                if ungrouped:
                    sections.append({"name": get("UI_OTHER"), "modules": ungrouped})

                nav_lines = build_grouped_nav(sections, chapter_files, indent=4)
                nav_lines.insert(0, "    - api/index.md")
                nav_label = mode_labels.get(mode, "Documentation")
                nav_snippet = f"nav:\n  - {nav_label}:\n" + "\n".join(nav_lines)
                emit("DONE_GROUPING", count=len(sections))
            else:
                emit("GROUP_EMPTY_FALLBACK")
                nav_snippet = prep_res["nav_snippet"]

        except Exception as e:
            emit("GROUP_ERROR_FALLBACK", error=e)
            emit_raw("ERROR", f"LLM grouping failed: {e}\n{traceback.format_exc()}", dest="LOG")
            nav_snippet = prep_res["nav_snippet"]
            sections = None
    else:
        nav_snippet = prep_res["nav_snippet"]

    This phase compiles chapter summaries, module paths, and directory layout strings into an LLM prompt using group_modules.md. The prompt is dispatched through call_llm() with token tracking handled by token_utils.py. The resulting YAML is parsed with parse_yaml_response. If the LLM omits modules, the method groups the missing files under an Other section via get("UI_OTHER"). If the LLM call fails or raises an exception, the pipeline falls back gracefully to prep_res["nav_snippet"].

        # --- Generate mkdocs.yml ---
    lang_code_map = {

        "portuguese": "pt",

    language = prep_res.get("language", "english")
    lang_code = lang_code_map.get(language.lower(), "")

    # --- Generate javascripts/mermaid-init.js ---

    The system maps the user's language name to an ISO 639-1 code, configuring MkDocs Material localization settings such as search indexes and UI labels. It then generates mkdocs.yml using build_mkdocs_config() and writes mermaid-init.js to ensure interactive diagrams render correctly in the browser.

    Phase 4: Landing Pages & Navigation Manifest Generation

    Constructs the top-level HTML redirect and the main API index landing page:

        # --- Generate docs/index.md — homepage redirect to api/ ---
    mode_label = mode_labels.get(mode, "Documentation")
    home_index_path = os.path.join(output_path, "docs", "index.md")
    home_content = f'# {project_name}\n\n<meta http-equiv="refresh" content="0; url=api/">\n\n[→ {mode_label}](api/index.md)\n'
    with open(home_index_path, "w", encoding="utf-8") as f:
        f.write(home_content)
    emit("FILE_WROTE", path=home_index_path)

    # --- Generate docs/api/index.md — section landing page ---
    if sections:
        chapter_index_label = get("UI_CHAPTER_INDEX")
        chapters_label = get("UI_CHAPTERS")
        index_lines = [
            f"# {project_name} — {mode_label}",
            "",
            f"{mode_label} — **{project_name}** — **{len(chapter_files)}** {chapters_label}.",
            "",
            f"## {chapter_index_label}",
            "",
        ]
        build_index_sections(index_lines, sections, chapter_files)
        index_content = "\n".join(index_lines)
    else:
        # Build a rich flat index with module listing table
        chapter_summaries = prep_res.get("chapter_summaries", [])
        chapter_index_label = get("UI_CHAPTER_INDEX")
        chapters_label = get("UI_CHAPTERS")
        th_chapter = get("UI_TH_CHAPTER")
        th_description = get("UI_TH_DESCRIPTION")
        index_lines = [
            f"# {project_name} — {mode_label}",
            "",
            f"{mode_label} — **{project_name}** — **{len(chapter_files)}** {chapters_label}.",
            "",
            f"## {chapter_index_label}",
            "",
            f"| {th_chapter} | {th_description} |",
            "|---------|-------------|",
        ]
        for i, cf in enumerate(chapter_files):
            dir_path = os.path.dirname(cf.get("original_path", "")) or ""
            display = f"{dir_path}/{cf['module_name']}" if dir_path else cf["module_name"]
            summary = chapter_summaries[i] if i < len(chapter_summaries) and chapter_summaries[i] else cf["description"]
            # Truncate and sanitize for table cell (replace pipes and newlines)
            summary = summary.replace("|", "—").replace("\n", " ").strip()
            if len(summary) > 200:
                summary = summary[:197] + "..."
            index_lines.append(f"| [{display}]({cf['filename']}) | {summary} |")
        index_lines.append("")
        index_content = "\n".join(index_lines)
    api_index_filepath = os.path.join(api_docs_path, "index.md")
    with open(api_index_filepath, "w", encoding="utf-8") as f:
        f.write(index_content)
    emit("FILE_WROTE", path=api_index_filepath)

    # --- Write nav_snippet.yml ---
    nav_filepath = os.path.join(output_path, "docs", "nav_snippet.yml")
    with open(nav_filepath, "w", encoding="utf-8") as f:
        f.write(nav_snippet)
    emit("FILE_WROTE", path=nav_filepath)

    The site creates a root landing page at docs/index.md with an HTTP <meta> refresh tag pointing to api/. For the main section page at docs/api/index.md, it renders either hierarchical markdown tables via build_index_sections() (when sections are defined) or a flat Markdown table. In the flat fallback, summary descriptions are cleaned by stripping line breaks, replacing Markdown pipe characters with em dashes (—), and truncating strings to 200 characters to prevent broken table formatting.

    Phase 5: Deterministic Link Normalization and Serialization

    Repairs cross-chapter links across the documentation and writes out the final chapter files:

        # --- Normalize cross-chapter links ---
    normalize_chapter_links(chapter_files)

    # --- Write chapter files ---
    for chapter_info in chapter_files:
        chapter_filepath = os.path.join(api_docs_path, chapter_info["filename"])
        os.makedirs(os.path.dirname(chapter_filepath), exist_ok=True)
        with open(chapter_filepath, "w", encoding="utf-8") as f:
            f.write(chapter_info["content"])
        emit("FILE_WROTE", path=chapter_filepath)

    This final phase runs normalize_chapter_links() to adjust markdown links between chapters based on their final directory locations. The modified chapters are then written out to disk under docs/api/, creating any nested subdirectories on demand.

    write_standalone_output()

    Visibility: Public
    Signature: def write_standalone_output(output_path, prep_res, chapter_files, ui):

    Description: Serializes documentation when --mkdocs output is disabled. Writes independent Markdown chapters, generates a root index.md, and compiles a combined full_content.md document containing anchor-based navigation links.

    Parameters: * output_path (str): Destination directory path where standalone Markdown files are saved. * prep_res (dict): Metadata dictionary providing index_content. * chapter_files (list[dict]): Collection of chapter dictionaries containing filename and content. * ui (dict): Localized UI dictionary providing terms such as toc and chapter.

    Returns: * None

    Raises: * OSError / IOError: Raised if directory creation or file operations fail.

    Phase 1: Index and Chapter Writing

    Writes the main landing page and serializes each chapter file:

        index_content = prep_res["index_content"]
    emit("COMBINE_FORMAT_STANDALONE")
    emit("COMBINE_CHAPTER_COUNT", count=len(chapter_files))

    # Write index.md
    index_filepath = os.path.join(output_path, "index.md")
    with open(index_filepath, "w", encoding="utf-8") as f:
        f.write(index_content)
    emit("FILE_WROTE", path=index_filepath)

    # Write chapter files
    for chapter_info in chapter_files:
        chapter_filepath = os.path.join(output_path, chapter_info["filename"])
        with open(chapter_filepath, "w", encoding="utf-8") as f:
            f.write(chapter_info["content"])
        emit("FILE_WROTE", path=chapter_filepath)

    This initial phase writes index.md directly into the target root directory using the pre-rendered index_content payload from prep_res. Each chapter dictionary is then written to its relative file path, ensuring all individual chapter files are persisted to disk.

    Phase 2: Combined Document Assembly (full_content.md)

    Merges all chapters into a single concatenated file with anchor tags and a Table of Contents:

        # Create full_content.md
    toc_lines = [f"# {ui['toc']}\n"]
    full_content_lines = []

    for i, chapter_info in enumerate(chapter_files):
        content = chapter_info["content"]
        title_line = content.split("\n", 1)[0]
        if title_line.startswith("# "):
            title = title_line[2:].strip()
        else:
            title = f"{ui['chapter']} {i + 1}"

        toc_lines.append(f"- [{title}](#chapter-{i + 1})")
        full_content_lines.append(f'<a id="chapter-{i + 1}"></a>\n')
        full_content_lines.append(content)
        full_content_lines.append("\n---\n")

    full_content = "\n".join(toc_lines) + "\n\n" + "\n".join(full_content_lines)
    full_content_filepath = os.path.join(output_path, "full_content.md")
    with open(full_content_filepath, "w", encoding="utf-8") as f:
        f.write(full_content)
    emit("FILE_WROTE", path=full_content_filepath)

    The function generates a Table of Contents by extracting top-level # headings from each chapter's content or falling back to a default Chapter {N} label. Each chapter is wrapped with an explicit HTML anchor (<a id="chapter-N"></a>) and separated by horizontal rules (---), assembling the entire documentation set into a single portable file (full_content.md).

    Internal Helpers

    build_index_sections()

    Visibility: Internal
    Signature: def build_index_sections(lines, sections, chapter_files, level=3):

    Description: Recursively constructs Markdown index tables for grouped sections. For each section, it outputs a Markdown header scaled by level, writes a table mapping chapters to their descriptions, and descends into any nested children sections.

    Parameters: * lines (list[str]): Accumulator list of Markdown strings appended in place. * sections (list[dict]): Hierarchical list of section definitions. * chapter_files (list[dict]): Available chapter metadata items. * level (int, optional): Markdown heading depth (###, ####, etc.). Defaults to 3.

    Returns: * None (mutates lines in-place).

    Raises: * No exceptions raised.

    Example: 

    def build_index_sections(lines, sections, chapter_files, level=3):
    heading = "#" * level
    for section in sections:
        lines.append(f"{heading} {section['name']}")
        lines.append("")
        if section.get("modules"):
            lines.append(f"| {get('UI_TH_CHAPTER')} | {get('UI_TH_DESCRIPTION')} |")
            lines.append("|---------|-------------|")
            for mod_name in section["modules"]:
                match = next((cf for cf in chapter_files if cf["module_name"] == mod_name), None)
                if match:
                    display = mod_name
                    # Use description, but if it's the generic mapper description, extract from content
                    desc = match["description"]
                    if desc.startswith("Internal API reference"):
                        content_lines = match["content"].strip().split("\n")
                        for cl in content_lines:
                            cs = cl.strip()
                            if cs and not cs.startswith(("---", "#", "```", "title:", "sidebar_position:")):
                                desc = cs[:120]
                                break
                    lines.append(f"| [{display}]({match['filename']}) | {desc} |")
            lines.append("")
        for child in section.get("children", []):
            build_index_sections(lines, [child], chapter_files, level + 1)

    This helper handles fallback description extraction. If a module's description field contains a generic string such as "Internal API reference", it parses the raw Markdown content to find the first meaningful text line that is not a heading, frontmatter block, or code fence, truncating it to 120 characters for clean table formatting.

    normalize_chapter_links()

    Visibility: Internal
    Signature: def normalize_chapter_links(chapter_files):

    Description: Normalizes cross-chapter Markdown links across all generated files. Resolves relative link paths between chapters in different directories based on their target filenames.

    Parameters: * chapter_files (list[dict]): Chapter file dictionaries containing filename and content. Mutated in-place.

    Returns: * None (mutates chapter_files items in-place).

    Raises: * No exceptions raised.

    Phase 1: Canonical Path Lookup & Ambiguity Resolution

    Builds a filename lookup table and identifies potential collisions across directories:

        # Build lookup: various path forms → canonical filename
    filename_lookup = {}
    ambiguous_basenames = set()
    for cf in chapter_files:
        fname = cf["filename"]  # e.g. "CoreService/AccountingService.cs.md"
        filename_lookup[fname] = fname
        basename = fname.rsplit("/", 1)[-1]
        if basename in filename_lookup and filename_lookup[basename] != fname:
            ambiguous_basenames.add(basename)
        else:
            filename_lookup[basename] = fname

    # Remove ambiguous basenames (same name in different dirs)
    for ab in ambiguous_basenames:
        filename_lookup.pop(ab, None)

    The method registers both full relative paths (CoreService/AccountingService.cs.md) and simple base names (AccountingService.cs.md) in a lookup table. If identical file names appear across multiple directories, those entries are flagged as ambiguous and removed from the base lookup, preventing incorrect link rewriting.

    Phase 2: In-place Link Substitution & Relative Directory Re-computation

    Parses Markdown links with regular expressions, calculates corrected relative paths using os.path.relpath, and preserves URI anchors:

        link_pattern = re.compile(r"\[([^\]]*)\]\(([^)#]+\.md)(#[^)]*)?\)")
    fixed_count = 0

    for cf in chapter_files:
        current_dir = os.path.dirname(cf["filename"])  # e.g. "CoreService"

        def fix_link(match, _dir=current_dir):
            nonlocal fixed_count
            text, target, anchor = match.group(1), match.group(2), match.group(3) or ""
            if target.startswith(("http://", "https://")):
                return match.group(0)
            # Try resolving the target as-is (LLM copied verbatim from index)
            canonical = filename_lookup.get(target)
            if not canonical:
                # Try resolving relative to current dir
                resolved = os.path.normpath(os.path.join(_dir, target)).replace("\\", "/")
                canonical = filename_lookup.get(resolved)
            if canonical:
                correct_rel = os.path.relpath(canonical, _dir).replace("\\", "/") if _dir else canonical
                if correct_rel != target:
                    fixed_count += 1
                return f"[{text}]({correct_rel}{anchor})"
            return match.group(0)  # Unknown target — leave as-is

        cf["content"] = link_pattern.sub(fix_link, cf["content"])

    if fixed_count:
        emit_raw("DEBUG", f"LINK NORMALIZATION | fixed {fixed_count} cross-chapter links", dest="LOG")

    The inner replacement closure fix_link matches Markdown links ending in .md and ignores external HTTP/HTTPS URLs. It resolves targets against the lookup table, normalizes paths across Windows and POSIX systems with .replace("\\", "/"), and calculates the relative path from the current chapter's directory using os.path.relpath(). Any original URI hash anchors (#anchor) are preserved.

    MERMAID_INIT_JS

    Visibility: Internal Constant
    Signature: MERMAID_INIT_JS: str

    Description: JavaScript snippet embedded into generated MkDocs sites (docs/javascripts/mermaid-init.js) to handle Mermaid diagram rendering and client-side initialization.

    // Mermaid initialization for MkDocs Material.
//
// Material for MkDocs targets .mermaid class for its own color overrides.
// By using .mermaid-raw, diagrams render with Mermaid's default theme:
// yellow subgraph backgrounds, lavender nodes, clean rectangles.
//
// pymdownx.superfences fence_code_format wraps content as:
//   <pre class="mermaid-raw"><code>flowchart TD ...</code></pre>
// Mermaid expects the diagram text directly in the target element,
// so we unwrap the <code> child before calling mermaid.run().
(function() {
  function initMermaid() {
    if (typeof mermaid === 'undefined') return;
    try {
      // Unwrap: move <code> text content up to <pre> and remove <code>
      document.querySelectorAll('pre.mermaid-raw > code').forEach(function(code) {
        var pre = code.parentElement;
        pre.textContent = code.textContent;
      });
      mermaid.initialize({
        startOnLoad: false,
        theme: 'default',
        securityLevel: 'loose'
      });
      mermaid.run({ querySelector: '.mermaid-raw' }).catch(function(err) {
        console.warn('Mermaid render error:', err);
      });
    } catch (e) {
      console.warn('Mermaid init error:', e);
    }
  }
  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', initMermaid);
  } else {
    initMermaid();
  }
})();

    This client-side script initializes once the DOM is ready (DOMContentLoaded). It pulls code content out of nested <code> tags, configures Mermaid with startOnLoad: false, theme: 'default', and securityLevel: 'loose', and renders diagrams matching .mermaid-raw. Any rendering or initialization errors are caught and logged to the browser console without breaking page execution.

    Error Handling

    The module implements defensive strategies to handle LLM parsing failures, malformed input trees, and cross-chapter link resolution:

    1. LLM Section Grouping Fallback: In write_mkdocs_output, the LLM grouping call is wrapped in a broad try...except Exception block. If network calls fail, token budgets are exceeded, or the model outputs malformed YAML, the exception is caught, logged with traceback.format_exc(), and the pipeline falls back to prep_res["nav_snippet"].

    2. Orphaned Module Recovery: When LLM-generated section groupings omit input files, write_mkdocs_output uses collect_all_modules() to identify missing entries. Any orphaned modules are appended to a fallback section titled get("UI_OTHER"), ensuring all generated documentation chapters remain reachable in site navigation.

    3. Ambiguous Filename Collision Handling: In normalize_chapter_links, repositories containing identically named files across different directories (e.g., pkg_a/index.py.md and pkg_b/index.py.md) are tracked in ambiguous_basenames. Colliding entries are excluded from base name lookups, preventing the normalizer from rewriting links to incorrect relative destinations.

    4. Client-Side Mermaid Fail-Safe: The embedded JavaScript in MERMAID_INIT_JS wraps diagram unwrapping and rendering logic in nested try...catch blocks and handles asynchronous errors via .catch(). This isolates diagram rendering failures and prevents unhandled exceptions from breaking other page functionality.
