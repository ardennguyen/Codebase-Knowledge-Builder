    mkdocs.py

    Source: utils/mkdocs.py

    Following the OpenRouter client implementation in llm_openrouter.py, which serves as an inference transport driver, utils/mkdocs.py acts as the document compilation and static-site generation engine of the repository. It consolidates all structural formatting, configuration synthesis, cross-chapter link normalization, and filesystem emission routines required to serialize abstract syntax trees and LLM-drafted documentation into navigable static documentation websites or standalone Markdown bundles.

    Technical Overview

    The utils/mkdocs.py module orchestrates the final serialization phase of the synthesis pipeline. When downstream synthesis nodes complete chapter drafting and module mapping, this module transforms raw markdown text, metadata dictionaries, and hierarchical relationship structures into a fully functional MkDocs Material documentation site or an integrated standalone Markdown distribution. It handles site configuration generation, navigation tree layout, responsive diagram initialization, landing page synthesis, and cross-document hyperlink resolution.

    A primary technical challenge resolved by this module is cross-chapter link consistency. Because LLMs synthesize chapter documentation independently, relative markdown links generated between files often contain invalid directory offsets or assume a flat hierarchy. The module implements a two-pass deterministic link normalizer that maps base filenames and paths to canonical output locations, disambiguates colliding basenames across nested directories, and rewrites markdown hyperlinks using exact filesystem relative offsets. Furthermore, for large codebases documented in API reference mode, the module provides automated navigation grouping: when module counts exceed configurable thresholds, it dispatches prompts to an LLM to categorize files logically, falls back gracefully to directory structures upon failure, and auto-sub-groups subdirectories deterministically.

    Additionally, utils/mkdocs.py bridges the visual rendering gap between MkDocs Material and Mermaid diagrams. By default, the Material theme overrides Mermaid styles, altering diagram geometries and contrast. This module generates a specialized javascripts/mermaid-init.js bootstrap script paired with custom superfences configurations (mermaid-raw) that strips intermediate wrapping elements rendered by pymdownx.superfences and invokes the native Mermaid rendering engine with interactive Panzoom support.

    yaml_str()

    Visibility: Public
    Signature: def yaml_str(value) -> str:

    Description: Safely quotes and escapes scalar values (such as navigation labels, chapter titles, and filesystem paths) for insertion into hand-built YAML configuration blocks and Markdown frontmatter. Under the hood, the function delegates serialization to json.dumps(str(value).strip(), ensure_ascii=False). Because valid JSON string literals conform strictly to YAML double-quoted scalar grammar, this strategy guarantees that arbitrary strings containing reserved YAML control characters (such as colons :, brackets [], braces {}, quotes ', leading dashes -, or @ symbols) will not corrupt configuration syntax.

    Parameters: * value (Any): The scalar object or string to be escaped.

    Returns: * str: A valid, double-quoted, escaped YAML string representation.

    Example: 

    # Escaping arbitrary module labels and directory paths for YAML navigation lines
lines.append(f"{pad}  - {yaml_str(dir_path)}:")
for mod_name, match in dir_groups[dir_path]:
    lines.append(f"{pad}    - {yaml_str(mod_name)}: {yaml_str('api/' + match['filename'])}")


    def yaml_str(value) -> str:
    """Quote a scalar for hand-built YAML (nav labels, section names, titles).

    JSON string literals are valid YAML double-quoted scalars, so names containing
    apostrophes, colons, brackets or a leading @ never break mkdocs.yml or frontmatter.
    """
    return json.dumps(str(value).strip(), ensure_ascii=False)
    The implementation converts input values to strings, trims surrounding whitespace, and serializes them using json.dumps. The flag ensure_ascii=False is enforced so that Unicode characters (such as Asian logograms, accented Cyrillic, or Latin script diacritics) remain unescaped, ensuring readability in generated configuration files while remaining fully compliant with YAML parsers.

    build_mermaid_init_js()

    Visibility: Public
    Signature: def build_mermaid_init_js() -> str:

    Description: Returns the runtime JavaScript source code that initializes the Mermaid client library within MkDocs Material. The returned script coordinates lifecycle execution during DOMContentLoaded, bypasses Material's default Mermaid stylesheet overrides, unwraps the nested HTML structure generated by pymdownx.superfences, and executes client-side rendering.

    Returns: * str: Complete JavaScript script buffer conforming to browser execution standards.

    Example:

    f.write(build_mermaid_init_js())


    MERMAID_INIT_JS = """\
// Mermaid initialization for MkDocs Material.
//
// Material for MkDocs targets .mermaid class for its own color overrides.
// By using .mermaid-raw, diagrams render with Mermaid's default theme:
// yellow subgraph backgrounds, lavender nodes, clean rectangles.
//
// pymdownx.superfences fence_code_format wraps content as:
//   <pre class="mermaid-raw"><code>flowchart TD ...</code></pre>
// Mermaid expects the diagram text directly in the target element,
// so we unwrap the <code> child before calling mermaid.run().
(function() {
  function initMermaid() {
    if (typeof mermaid === 'undefined') return;
    try {
      // Unwrap: move <code> text content up to <pre> and remove <code>
      document.querySelectorAll('pre.mermaid-raw > code').forEach(function(code) {
        var pre = code.parentElement;
        pre.textContent = code.textContent;
      });
      mermaid.initialize({
        startOnLoad: false,
        theme: 'default',
        securityLevel: 'loose'
      });
      mermaid.run({ querySelector: '.mermaid-raw' }).catch(function(err) {
        console.warn('Mermaid render error:', err);
      });
    } catch (e) {
      console.warn('Mermaid init error:', e);
    }
  }
  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', initMermaid);
  } else {
    initMermaid();
  }
})();
"""


def build_mermaid_init_js() -> str:
    """Return the JavaScript snippet that initializes Mermaid diagrams."""
    return MERMAID_INIT_JS
    The client script operates within an Immediately Invoked Function Expression (IIFE) to avoid polluting global window namespaces. Because pymdownx.superfences wraps custom fence blocks inside <pre class="mermaid-raw"><code>...</code></pre>, standard Mermaid parsing fails because it expects raw diagram definitions directly inside the target container. The script resolves this by traversing document.querySelectorAll('pre.mermaid-raw > code'), assigning the inner text content of each <code> block directly to its parent <pre> node, clearing the intermediate element, and then executing mermaid.run({ querySelector: '.mermaid-raw' }).

    normalize_chapter_links()

    Visibility: Public
    Signature: def normalize_chapter_links(chapter_files: list[dict]) -> None:

    Description: Executes deterministic, in-place link normalization across all generated markdown chapter contents. It inspects all internal cross-chapter hyperlinks ([anchor](target.md)), verifies whether targets point to valid chapter paths or simple file names, and replaces them with mathematically precise relative filesystem paths computed from the referencing file's directory to the target file's directory.

    Parameters: * chapter_files (list[dict]): Mutable list of chapter file dictionaries, where each item must contain at least "filename" and "content".

    Phase 1: Canonical Filename Lookup and Ambiguity Resolution

        # Build lookup: various path forms → canonical filename
    filename_lookup = {}
    ambiguous_basenames = set()
    for cf in chapter_files:
        fname = cf["filename"]  # e.g. "CoreService/AccountingService.cs.md"
        filename_lookup[fname] = fname
        basename = fname.rsplit("/", 1)[-1]
        if basename in filename_lookup and filename_lookup[basename] != fname:
            ambiguous_basenames.add(basename)
        else:
            filename_lookup[basename] = fname

    # Remove ambiguous basenames (same name in different dirs)
    for ab in ambiguous_basenames:
        filename_lookup.pop(ab, None)
    The first phase builds an index mapping both fully qualified relative filenames (e.g., services/auth.py.md) and plain basenames (e.g., auth.py.md) to canonical filenames. To guard against incorrect path rewrites in monorepos or multi-tiered directories containing identical filenames across distinct folders (e.g., api/v1/user.py.md vs. api/v2/user.py.md), collisions are tracked inside ambiguous_basenames. Any basename detected in more than one distinct subpath is permanently removed from the lookup table, requiring subsequent matches to resolve against fully qualified paths.

    Phase 2: Regex Matching and Relative Target Resolution

        link_pattern = re.compile(r"\[([^\]]*)\]\(([^)#]+\.md)(#[^)]*)?\)")
    fixed_count = 0

    for cf in chapter_files:
        current_dir = os.path.dirname(cf["filename"])  # e.g. "CoreService"

        def fix_link(match, _dir=current_dir):
            nonlocal fixed_count
            text, target, anchor = match.group(1), match.group(2), match.group(3) or ""
            if target.startswith(("http://", "https://")):
                return match.group(0)
            # Try resolving the target as-is (LLM copied verbatim from index)
            canonical = filename_lookup.get(target)
            if not canonical:
                # Try resolving relative to current dir
                resolved = os.path.normpath(os.path.join(_dir, target)).replace("\\", "/")
                canonical = filename_lookup.get(resolved)
            if canonical:
                correct_rel = os.path.relpath(canonical, _dir).replace("\\", "/") if _dir else canonical
                if correct_rel != target:
                    fixed_count += 1
                return f"[{text}]({correct_rel}{anchor})"
            return match.group(0)  # Unknown target — leave as-is

        cf["content"] = link_pattern.sub(fix_link, cf["content"])

    if fixed_count:
        emit_raw("DEBUG", f"LINK NORMALIZATION | fixed {fixed_count} cross-chapter links", dest="LOG")
    The second phase iterates through each chapter file, determining its enclosing directory via os.path.dirname(cf["filename"]). It compiles a regular expression r"\[([^\]]*)\]\(([^)#]+\.md)(#[^)]*)?\)" to capture link text, .md link targets, and optional anchor tags. An inline closure, fix_link, bypasses HTTP/HTTPS URIs, resolves targets either directly or against current_dir via os.path.normpath, recalculates the relative traversal path using os.path.relpath, and normalizes path separators to forward slashes (/). If a target matches a canonical path and differs from the source link, the replacement is applied and the fix counter is incremented.

    write_mkdocs_output()

    Visibility: Public

    Description: The primary orchestration driver for exporting generated documentation into an MkDocs static site structure. It handles automated LLM navigation grouping (for API reference modes with large module counts), synthesizes mkdocs.yml, writes client-side Mermaid initialization assets, builds landing pages (docs/index.md and docs/api/index.md), persists navigation snippets, normalizes cross-document hyperlinks, and writes chapter Markdown files into disk subdirectories.

        project_name = prep_res["project_name"]

    Phase 2: LLM-Assisted Navigation Grouping

        # --- LLM-Assisted Nav Grouping (api-reference only, 6+ modules) ---
    sections = None
    emit_raw("DEBUG", f"NAV GROUPING CHECK | mode={mode} | module_count={len(chapter_files)} | threshold=6", dest="LOG")
    if mode == "api-reference" and len(chapter_files) > 5:
        try:
            chapter_summaries = prep_res.get("chapter_summaries", [])
            module_entries = []
            for i, cf in enumerate(chapter_files):
                summary = chapter_summaries[i] if i < len(chapter_summaries) and chapter_summaries[i] else cf["description"]
                module_entries.append(f"- {cf['module_name']}: {summary}")
            module_list = "\n".join(module_entries)

            # Load grouping prompt template
            prompt_path = os.path.join(os.path.dirname(os.path.dirname(os.path.abspath(__file__))), "prompts", "common", "group_modules.md")
            with open(prompt_path, encoding="utf-8-sig") as f:
                group_template = f.read()

            language = prep_res.get("language", "english")
            language_note = f"Section names MUST be in {language}." if language.lower() != "english" else ""

            group_prompt = group_template.format(
                project_name=project_name,
                module_count=len(chapter_files),
                module_list=module_list,
                directory_tree=prep_res.get("directory_tree", "N/A"),
                language_note=language_note,
            )

            emit("LLM_CALL_GROUPING", count=len(chapter_files))

            log_token_estimation("NavGrouping", group_prompt, prep_res.get("max_tokens", 100000))
            group_response = call_llm(group_prompt, use_cache=prep_res.get("use_cache", True), thinking_level=prep_res.get("thinking_level"))
            parsed = parse_yaml_response(group_response)
            sections = parsed.get("sections", parsed) if isinstance(parsed, dict) else None

            if sections:
                # Validate: ensure all modules are covered
                grouped_modules = collect_all_modules(sections)
                ungrouped = [cf["module_name"] for cf in chapter_files if cf["module_name"] not in grouped_modules]
                if ungrouped:
                    sections.append({"name": get("UI_OTHER"), "modules": ungrouped})

                nav_lines = build_grouped_nav(sections, chapter_files, indent=4)
                nav_lines.insert(0, "    - api/index.md")
                nav_label = mode_labels.get(mode, "Documentation")
                nav_snippet = f"nav:\n  - {nav_label}:\n" + "\n".join(nav_lines)
                emit("DONE_GROUPING", count=len(sections))
            else:
                emit("GROUP_EMPTY_FALLBACK")
                nav_snippet = prep_res["nav_snippet"]

        except Exception as e:
            emit("GROUP_ERROR_FALLBACK", error=e)
            emit_raw("ERROR", f"LLM grouping failed: {e}\n{traceback.format_exc()}", dest="LOG")
            nav_snippet = prep_res["nav_snippet"]
            sections = None
    else:
        nav_snippet = prep_res["nav_snippet"]
    When running in api-reference mode with more than 5 modules, flat navigation becomes unwieldy. The system constructs an LLM prompt injecting module summaries and directory structures from prompts/common/group_modules.md. The model response is parsed via parse_yaml_response. A completeness check ensures no modules were dropped: any unassigned modules are collected into an Other (UI_OTHER) section. If parsing fails, exceptions are caught and the pipeline falls back to prep_res["nav_snippet"].

    The pipeline maps full language names to 2-letter ISO codes via lang_code_map to configure the Material theme UI. It writes mkdocs.yml directly into output_path, initializes the docs/javascripts/ directory, and writes mermaid-init.js.

    Phase 4: Index Landing Pages and Nav Snippet Serialization

        # --- Generate docs/index.md — homepage redirect to api/ ---
    mode_label = mode_labels.get(mode, "Documentation")
    home_index_path = os.path.join(output_path, "docs", "index.md")
    home_content = f'# {project_name}\n\n<meta http-equiv="refresh" content="0; url=api/">\n\n[→ {mode_label}](api/index.md)\n'

    emit("FILE_WROTE", path=home_index_path)

    # --- Generate docs/api/index.md — section landing page ---
    if sections:

            f"# {project_name} — {mode_label}",
            "",

        # Build a rich flat index with module listing table
        chapter_summaries = prep_res.get("chapter_summaries", [])
        chapter_index_label = get("UI_CHAPTER_INDEX")
        chapters_label = get("UI_CHAPTERS")
        th_chapter = get("UI_TH_CHAPTER")
        th_description = get("UI_TH_DESCRIPTION")
        index_lines = [
            f"# {project_name} — {mode_label}",
            "",
            f"{mode_label} — **{project_name}** — **{len(chapter_files)}** {chapters_label}.",
            "",
            f"## {chapter_index_label}",
            "",
            f"| {th_chapter} | {th_description} |",
            "|---------|-------------|",
        ]
        for i, cf in enumerate(chapter_files):
            dir_path = os.path.dirname(cf.get("original_path", "")) or ""
            display = f"{dir_path}/{cf['module_name']}" if dir_path else cf["module_name"]
            summary = chapter_summaries[i] if i < len(chapter_summaries) and chapter_summaries[i] else cf["description"]
            # Truncate and sanitize for table cell (replace pipes and newlines)
            summary = summary.replace("|", "—").replace("\n", " ").strip()
            if len(summary) > 200:
                summary = summary[:197] + "..."
            index_lines.append(f"| [{display}]({cf['filename']}) | {summary} |")
        index_lines.append("")
        index_content = "\n".join(index_lines)
    api_index_filepath = os.path.join(api_docs_path, "index.md")
    with open(api_index_filepath, "w", encoding="utf-8") as f:
        f.write(index_content)
    emit("FILE_WROTE", path=api_index_filepath)

    # --- Write nav_snippet.yml ---
    nav_filepath = os.path.join(output_path, "docs", "nav_snippet.yml")
    with open(nav_filepath, "w", encoding="utf-8") as f:
        f.write(nav_snippet)
    emit("FILE_WROTE", path=nav_filepath)
    Phase 4 creates two landing pages: docs/index.md acts as a root redirect containing <meta http-equiv="refresh" content="0; url=api/">, and docs/api/index.md serves as the primary navigation index. If grouping sections exist, build_index_sections renders hierarchical tables; otherwise, a flat table is emitted, sanitizing descriptions by stripping linebreaks, replacing table delimiter pipes (| with —), and truncating entries exceeding 200 characters.

    Phase 5: Link Normalization and Chapter Persistence

        # --- Normalize cross-chapter links ---
    normalize_chapter_links(chapter_files)

    # --- Write chapter files ---
    for chapter_info in chapter_files:
        chapter_filepath = os.path.join(api_docs_path, chapter_info["filename"])
        os.makedirs(os.path.dirname(chapter_filepath), exist_ok=True)
        with open(chapter_filepath, "w", encoding="utf-8") as f:
            f.write(chapter_info["content"])
        emit("FILE_WROTE", path=chapter_filepath)
    In the final phase, normalize_chapter_links() rewrites broken or unaligned relative hyperlinks across all chapter buffers. Once links are normalized, the files are written to their respective subdirectories within docs/api/, using os.makedirs(..., exist_ok=True) to handle arbitrary folder depths.

    Description: Emits generated documentation in standalone (non-MkDocs) format. This creates individual Markdown files in the output directory, outputs a top-level index.md, and compiles an all-in-one full_content.md file containing an anchored table of contents linked to every chapter for offline reading and monolithic viewing.

    Parameters: * output_path (str): Target output directory. * prep_res (dict): Context dictionary containing index_content. * chapter_files (list[dict]): Collection of synthesized chapter records. * ui (dict): Localized UI label mapping containing at least "toc" and "chapter".

    Example: 

    # Standalone mode export invoked from CombineTutorial
write_standalone_output(
    output_path=output_dir,
    prep_res=preparation_state,
    chapter_files=chapters,
    ui={"toc": "Table of Contents", "chapter": "Chapter"}

    def write_standalone_output(output_path, prep_res, chapter_files, ui):
    """Write standalone (non-MkDocs) output: index.md, chapters, full_content.md."""
    index_content = prep_res["index_content"]
    emit("COMBINE_FORMAT_STANDALONE")
    emit("COMBINE_CHAPTER_COUNT", count=len(chapter_files))

    # Write index.md
    index_filepath = os.path.join(output_path, "index.md")
    with open(index_filepath, "w", encoding="utf-8") as f:
        f.write(index_content)
    emit("FILE_WROTE", path=index_filepath)

    # Write chapter files
    for chapter_info in chapter_files:
        chapter_filepath = os.path.join(output_path, chapter_info["filename"])
        with open(chapter_filepath, "w", encoding="utf-8") as f:
            f.write(chapter_info["content"])
        emit("FILE_WROTE", path=chapter_filepath)

    # Create full_content.md
    toc_lines = [f"# {ui['toc']}\n"]
    full_content_lines = []

    for i, chapter_info in enumerate(chapter_files):
        content = chapter_info["content"]
        title_line = content.split("\n", 1)[0]
        if title_line.startswith("# "):
            title = title_line[2:].strip()
        else:
            title = f"{ui['chapter']} {i + 1}"

        toc_lines.append(f"- [{title}](#chapter-{i + 1})")
        full_content_lines.append(f'<a id="chapter-{i + 1}"></a>\n')
        full_content_lines.append(content)
        full_content_lines.append("\n---\n")

    full_content = "\n".join(toc_lines) + "\n\n" + "\n".join(full_content_lines)
    full_content_filepath = os.path.join(output_path, "full_content.md")
    with open(full_content_filepath, "w", encoding="utf-8") as f:
        f.write(full_content)
    emit("FILE_WROTE", path=full_content_filepath)
    The function extracts the pre-built index_content from prep_res and writes it to index.md. It then writes each chapter file to output_path. Finally, it constructs full_content.md by parsing the first line of each chapter to extract its # title (falling back to a generic numbered title if missing), creating a table of contents list with Markdown anchor links, and concatenating all chapters separated by <a id="chapter-N"></a> anchors and horizontal divider rules (---).

    Internal Helpers

    build_grouped_nav()

    Visibility: Private
    Signature: def build_grouped_nav(sections: list[dict], chapter_files: list[dict], indent: int = 4) -> list[str]:

    Description: Recursively constructs lines of YAML navigation entries based on an LLM-derived hierarchical section tree. It handles arbitrary nesting depth through the children key. Within each leaf section, modules are matched against chapter_files by module_name. Modules residing in subdirectories are auto-sub-grouped by directory path without extra LLM calls, while root files remain flat.

    Parameters: * sections (list[dict]): Hierarchical tree of section dictionaries. * chapter_files (list[dict]): Available chapter records to match against. * indent (int): Indentation spaces to prepend to YAML lines (defaults to 4).

    Returns: * list[str]: Indented YAML lines representing the navigation tree.

    def build_grouped_nav(sections: list, chapter_files: list, indent: int = 4) -> list[str]:
    emit_raw("DEBUG", f"build_grouped_nav | building nav for {len(sections)} sections", dest="LOG")

    lines = []
    pad = " " * indent
    for section in sections:
        lines.append(f"{pad}- {yaml_str(section['name'])}:")
        if "children" in section:
            lines.extend(build_grouped_nav(section["children"], chapter_files, indent + 2))

        # Collect matched modules with directory info
        matched = []
        for mod_name in section.get("modules", []):
            match = next((cf for cf in chapter_files if cf["module_name"] == mod_name), None)
            if match:
                dir_path = os.path.dirname(match.get("original_path", "")) or ""
                matched.append((dir_path, mod_name, match))

        # Group by directory
        dir_groups = defaultdict(list)
        for dir_path, mod_name, match in matched:
            dir_groups[dir_path].append((mod_name, match))

        # Emit dir sub-layers for non-root dirs, flat for root files
        has_non_root = any(d for d in dir_groups)
        if has_non_root:
            for dir_path in sorted(dir_groups.keys()):
                if dir_path:
                    # Non-root: add directory sub-layer with bare module names
                    lines.append(f"{pad}  - {yaml_str(dir_path)}:")
                    for mod_name, match in dir_groups[dir_path]:
                        lines.append(f"{pad}    - {yaml_str(mod_name)}: {yaml_str('api/' + match['filename'])}")
                else:
                    # Root files: flat (no sub-layer)
                    for mod_name, match in dir_groups[dir_path]:
                        lines.append(f"{pad}  - {yaml_str(mod_name)}: {yaml_str('api/' + match['filename'])}")
        else:
            # All root files → flat list
            for _dir_path, mod_name, match in matched:
                lines.append(f"{pad}  - {yaml_str(mod_name)}: {yaml_str('api/' + match['filename'])}")

    return lines
    The helper formats indentation using pad = " " * indent and recursively processes nested sub-sections by passing indent + 2. It resolves module paths via defaultdict(list), checking if any module belongs to a non-root folder. If subdirectories are present, it injects a directory subsection header (- "dir_path":) with indented leaf entries pointing to api/{filename}. If all modules are top-level, it emits a flat list of module links.

    collect_all_modules()

    Visibility: Private
    Signature: def collect_all_modules(sections: list[dict]) -> set[str]:

    Description: Recursively traverses a hierarchical section tree, collecting every referenced module name into a flat Python set. This provides $O(1)$ membership testing to verify whether an LLM navigation plan has omitted any generated documentation chapters.

    Parameters: * sections (list[dict]): The section tree structure containing modules lists and optional children lists.

    Returns: * set[str]: Set of all unique module names present across the tree.

    def collect_all_modules(sections: list) -> set:
    """Recursively collect all module names referenced in a sections tree."""
    result = set()
    for section in sections:
        result.update(section.get("modules", []))
        if "children" in section:
            result.update(collect_all_modules(section["children"]))
    return result
    The function initializes an empty set result and iterates over each section node. It performs an in-place update with section.get("modules", []), checks for the existence of children, and recursively invokes itself to traverse child branches. The consolidated set is returned to the caller to identify missing chapters.

    build_index_sections()

    Visibility: Private
    Signature: def build_index_sections(lines: list[str], sections: list[dict], chapter_files: list[dict], level: int = 3) -> None:

    Description: Recursively constructs the Markdown text of the index landing page (docs/api/index.md) from the section tree. For each section, it emits a Markdown heading scaled to the nesting depth ("#" * level), followed by a two-column Markdown table listing chapters and their descriptions.

    Parameters: * lines (list[str]): Mutable accumulator list where Markdown lines are appended. * sections (list[dict]): Hierarchical tree of section definitions. * chapter_files (list[dict]): Collection of chapter objects for resolving metadata. * level (int): Markdown heading level for section titles (defaults to 3, e.g. ###).

    def build_index_sections(lines, sections, chapter_files, level=3):
    """Recursively build index.md sections with module tables."""
    heading = "#" * level
    for section in sections:
        lines.append(f"{heading} {section['name']}")
        lines.append("")
        if section.get("modules"):
            lines.append(f"| {get('UI_TH_CHAPTER')} | {get('UI_TH_DESCRIPTION')} |")
            lines.append("|---------|-------------|")
            for mod_name in section["modules"]:
                match = next((cf for cf in chapter_files if cf["module_name"] == mod_name), None)
                if match:
                    display = mod_name
                    # Use description, but if it's the generic mapper description, extract from content
                    desc = match["description"]
                    if desc.startswith("Internal API reference"):
                        content_lines = match["content"].strip().split("\n")
                        for cl in content_lines:
                            cs = cl.strip()
                            if cs and not cs.startswith(("---", "#", "```", "title:", "sidebar_position:")):
                                desc = cs[:120]
                                break
                    lines.append(f"| [{display}]({match['filename']}) | {desc} |")
            lines.append("")
        for child in section.get("children", []):
            build_index_sections(lines, [child], chapter_files, level + 1)
    For each module in a section, this helper resolves its display entry and description. If the description is a placeholder starting with "Internal API reference", it parses the module's actual markdown content, finds the first non-header, non-frontmatter, non-fence text line, and extracts the first 120 characters as an excerpt. It then recurses through section.get("children", []), incrementing level + 1 to maintain header hierarchy in Markdown.

    Error Handling

    LLM Grouping Failures and Graceful Degradation

    The automated grouping phase in write_mkdocs_output encapsulates network and parsing operations in an isolated try...except Exception block:

    except Exception as e:
    emit("GROUP_ERROR_FALLBACK", error=e)
    emit_raw("ERROR", f"LLM grouping failed: {e}\n{traceback.format_exc()}", dest="LOG")
    nav_snippet = prep_res["nav_snippet"]
    sections = None
    If the LLM call times out, encounters rate limits, refuses the prompt, or outputs malformed YAML that fails in parse_yaml_response, the system captures the full exception traceback to diagnostics via emit_raw. It then emits a UI event (GROUP_ERROR_FALLBACK), resets sections = None, and falls back to prep_res["nav_snippet"].

    Ambiguous Cross-Chapter Link Resolution

    When normalizing cross-chapter links in normalize_chapter_links(), files in different directories may share the same basename (such as models.py.md in different services). The resolution engine detects collisions early:

    basename = fname.rsplit("/", 1)[-1]
if basename in filename_lookup and filename_lookup[basename] != fname:
    ambiguous_basenames.add(basename)
else:
    filename_lookup[basename] = fname

# Remove ambiguous basenames (same name in different dirs)
for ab in ambiguous_basenames:
    filename_lookup.pop(ab, None)
    By removing colliding basenames from filename_lookup, ambiguous links are left unchanged rather than misdirected to arbitrary chapters.
