    mkdocs.py

    Source: utils/mkdocs.py

    Technical Overview

    The utils/mkdocs.py module serves as the primary publication engine and static site generator adapter for the Codebase-Knowledge-Builder pipeline. It consolidates all logic required to transform generated chapter contents, structural AST facts, and codebase relationships into fully functional, navigable static documentation sites. The module manages configuration generation for Material for MkDocs (mkdocs.yml), custom JavaScript diagram initialization, dynamic navigation tree generation, cross-chapter link normalization, deterministic "Used by" dependency linking, and file generation for both MkDocs-based and standalone multi-markdown distributions.

    At the core of the module's architecture is a multi-stage publication pipeline that supports multiple documentation modalities (tutorial, advanced, sdk, and api-reference). For large api-reference document sets (6+ modules), it coordinates with language models via prompt templates (prompts/common/group_modules.md) to synthesize high-level architectural categories, human-readable section groupings, and module summaries. Crucially, the module cross-references inferred architectural relationships against ground-truth facts extracted by utils/facts.py (surfaced through prep_res["module_facts"]), guaranteeing that cross-module arrows and structural dependency graphs reflect verified source code relationships.

    The component enforces deterministic filesystem operations and non-destructive rendering policies. It applies automated link-rewriting rules to ensure relative links resolve accurately regardless of directory depth, implements inode-based file pruning to remove stale markdown artifacts without race conditions or case-sensitivity collisions on host operating systems, and isolates Mermaid diagram styling from Material theme overrides through a dedicated JavaScript bridge.

    Public API

    yaml_str()

    Visibility: Public
    Signature: def yaml_str(value) -> str:

    Description: Serializes and quotes any scalar value into a valid YAML double-quoted string literal. It delegates internally to json.dumps(..., ensure_ascii=False) after stripping leading and trailing whitespace. Because all valid JSON string literals constitute valid YAML double-quoted scalars, this helper guarantees that section names, navigation labels, and document titles containing colons, square brackets, leading @ characters, quotes, or CJK characters will not corrupt the generated mkdocs.yml or markdown frontmatter mappings.

    Parameters: * value (Any): The scalar object, string, or identifier to convert into a YAML-safe string representation.

    Returns: * str: A double-quoted string literal safe for inclusion in YAML configurations.

    Example: 

    home_line = f"  - {yaml_str(get('UI_HOME'))}: index.md\n" if include_home else ""

    build_mkdocs_config()

    Visibility: Public
    Signature: def build_mkdocs_config(site_name: str, nav_yaml: str, include_home: bool = True, lang_code: str = "") -> str:

    Description: Assembles the complete textual contents of a mkdocs.yml configuration file tailored for Material for MkDocs. The generated configuration configures syntax highlighting via pymdownx.highlight and pymdownx.inlinehilite, and registers a custom mermaid-raw div-based fence handler under pymdownx.superfences to circumvent Material's native diagram color overrides. It integrates the panzoom plugin configured specifically for .mermaid-raw selectors to provide interactive pan and zoom capabilities for wide architectural diagrams. Furthermore, it sets up light/slate color palette toggles, code copy buttons, search plugins, and localized theme language configurations.

    Parameters: * site_name (str): The project name and documentation title displayed in the site header. * nav_yaml (str): Raw YAML string representing the navigation tree (typically starting with or containing a nav: hierarchy). * include_home (bool): Whether to inject a top-level root home navigation item linking to index.md. Defaults to True. * lang_code (str): Optional ISO language code (e.g., "vi", "zh", "ja") for UI localization. Defaults to "".

    Returns: * str: The complete, ready-to-write mkdocs.yml configuration string.

    Example: 

    mkdocs_config = build_mkdocs_config(site_title, nav_snippet, include_home=True, lang_code=lang_code)
mkdocs_filepath = os.path.join(output_path, "mkdocs.yml")
with open(mkdocs_filepath, "w", encoding="utf-8") as f:
    f.write(mkdocs_config)

    MERMAID_INIT_JS

    Visibility: Public
    Signature: MERMAID_INIT_JS = """..."""

    Description: A constant multi-line JavaScript string containing an Immediately Invoked Function Expression (IIFE). It initializes the Mermaid rendering engine on <div class="mermaid-raw"> elements while bypassing Material for MkDocs' default CSS color overrides. The script injects dynamic CSS rules to ensure diagrams display against a light background card when the user switches Material to the dark (slate) scheme, avoiding contrast issues with default Mermaid dark-gray edge lines. It attaches to the DOMContentLoaded lifecycle event or executes immediately if the document has already finished loading.

    build_chapter_filenames()

    Visibility: Public
    Signature: def build_chapter_filenames(chapter_order: list, abstractions: list, is_mkdocs: bool) -> dict:

    Description: Computes deterministic, unique file paths for each abstraction in the chapter generation sequence. When running in MkDocs mode (is_mkdocs=True), it attempts to mirror the codebase's original repository hierarchy using the abstraction's original_path metadata, falling back to a sanitized name if absent. In standalone markdown mode, filenames receive a zero-padded sequential index prefix (NN_sanitized_name.md). To prevent file collisions, the function performs case-insensitive tracking, automatically appending numerical suffixes (_2.md, _3.md) upon detecting conflicting filenames or collisions with directory root pages (README.md or index.md).

    Parameters: * chapter_order (list): Ordered list of integer abstraction indices representing the publication order. * abstractions (list): List of abstraction metadata dictionaries containing name and optional original_path keys. * is_mkdocs (bool): Flag indicating whether MkDocs path conventions or standalone numbered prefixes should be applied.

    Returns: * dict: A dictionary mapping positional indices (int) from chapter_order to relative destination filenames (str).

    Example: 

    filenames = build_chapter_filenames(chapter_order, abstractions, is_mkdocs=True)
# filenames: {0: "core/engine.py.md", 1: "utils/config.py.md"}

    split_frontmatter()

    Visibility: Public
    Signature: def split_frontmatter(text: str) -> tuple[str, bool]:

    Description: Parses leading YAML frontmatter out of raw markdown text, replicating the frontmatter parsing rules used by MkDocs. It searches for opening --- fences followed by closing --- or ... fences using the precompiled _FRONTMATTER_RE. It attempts to parse the enclosed block as a YAML mapping using yaml.safe_load. If the block parses successfully as a Python dict, the frontmatter block is stripped, returning the clean document body and a boolean True. If YAML parsing fails or if the block is not a mapping, the text remains unstripped to prevent destroying legitimate opening horizontal rules.

    Parameters: * text (str): Raw markdown string potentially containing leading frontmatter.

    Returns: * tuple[str, bool]: A 2-tuple (body, found) where body is the stripped text (or original text if absent) and found indicates whether valid frontmatter was detected and removed.

    Example: 

    body, has_frontmatter = split_frontmatter(raw_markdown)

    strip_summary_header()

    Visibility: Public
    Signature: def strip_summary_header(summary: str) -> str:

    Description: Removes standardized title headers that the WriteChapters pipeline node prepends to chapter summaries (such as <Chapter> N — name:). It partitions the summary string on the first newline and evaluates the leading line against _SUMMARY_HEADER_RE. If a match occurs, it strips the leading line and returns the remainder; otherwise, the original summary is returned cleanly stripped.

    Parameters: * summary (str): The raw chapter summary text emitted by LLM workers.

    Returns: * str: The summary text with the chapter header line removed.

    Example: 

    clean_summary = strip_summary_header("Chapter 1 — Engine:\nThis module drives...")

    clip_sentences()

    Visibility: Public
    Signature: def clip_sentences(text: str, limit: int) -> str:

    Description: Truncates arbitrary prose to fit within a specified character length while preserving whole sentences and valid Markdown syntax. Whitespace is collapsed into single spaces. The function iterates over detected sentence boundaries via _sentences(), assembling sentences until adding another would exceed limit. If even the first sentence exceeds limit, the text is cut at the last word boundary before the threshold (or at the character limit for non-spaced CJK text), dangling punctuation is stripped, unclosed code spans (backticks) are balanced, and an ellipsis (…) is appended.

    Parameters: * text (str): Prose text to be bounded. * limit (int): Maximum permitted character count.

    Returns: * str: Cleanly bounded text guaranteed not to break code spans or terminate mid-word.

    Example: 

    short_desc = clip_sentences("The engine handles routing. It caches requests.", 30)
# Returns: "The engine handles routing."

    table_cell_text()

    Visibility: Public
    Signature: def table_cell_text(text: str) -> str:

    Description: Sanitizes arbitrary text for safe insertion into Markdown table cells by escaping pipe characters (| to \|). To prevent invalidating code syntax within documentation tables, the function uses _CODE_SPAN_RE to find all inline code spans, escaping pipes strictly in the prose segments between code spans while leaving pipes inside backticks untouched (e.g., str | None remains intact).

    Parameters: * text (str): Markdown text destined for a table cell.

    Returns: * str: Text with unescaped table delimiters neutralized outside code spans.

    Example: 

    cell = table_cell_text("Returns `dict | None` | status code")
# Returns: "Returns `dict | None` \| status code"

    summary_description()

    Visibility: Public
    Signature: def summary_description(summary: str, limit: int = 300) -> str:

    Description: Extracts a concise, single-paragraph module description from a multi-point chapter summary to populate index table cells. Standard chapter summaries consist of four structured points (e.g., Scope & Responsibility, Key Technical Elements). This function strips headers, identifies the boundary between points (1) and (2) using _POINT_PAREN_RE or _POINT_PLAIN_RE, strips preamble lines and inline point labels via _SUMMARY_LABEL_RE, bounds the resulting text using clip_sentences(..., limit), and sanitizes table syntax via table_cell_text().

    Parameters: * summary (str): Raw multi-point summary text. * limit (int): Maximum length ceiling for the output description. Defaults to 300.

    Returns: * str: A sanitized, single-sentence or bounded-paragraph description suitable for Markdown tables.

    Example: 

    desc = summary_description(cf["description"], limit=300)

    md_link_text()

    Visibility: Public
    Signature: def md_link_text(text: str) -> str:

    Description: Escapes Markdown metacharacters (\, `, *, _, [, ], |) within module names and titles using _MD_ESCAPE_RE. This guarantees that programming filenames such as __init__.py or [id].tsx render literally inside Markdown link labels without triggering unwanted italics, bolding, or premature bracket terminations.

    Parameters: * text (str): Raw link text or filename.

    Returns: * str: Escaped string safe for Markdown link labels.

    Example: 

    link = f"[{md_link_text('__init__.py')}](utils/__init__.py.md)"
# Yields: [\\_\\_init\\_\\_.py](utils/__init__.py.md)

    module_name_lookup()

    Visibility: Public
    Signature: def module_name_lookup(chapter_files: list) -> dict:

    Description: Constructs a comprehensive lookup dictionary that resolves varied module identifier representations to their canonical module_name. It registers the primary module_name, the full original_path (if present), and the unqualified basename (provided the basename occurs exactly once across all chapter files). This mapping enables flexible name resolution when processing LLM grouping responses, which may refer to modules using basenames, repository paths, or canonical names.

    Parameters: * chapter_files (list): List of chapter dictionaries containing module_name and optional original_path.

    Returns: * dict: Lookup table mapping string aliases to canonical module names.

    Example: 

    lookup = module_name_lookup(chapter_files)
canonical = lookup.get("mkdocs.py")  # Returns "utils/mkdocs.py"

    grouping_extras()

    Visibility: Public
    Signature: def grouping_extras(parsed, chapter_files: list) -> tuple[dict, dict]:

    Description: Extracts and validates supplemental descriptions and dependencies payloads returned by the prompts/common/group_modules.md LLM prompt. It utilizes module_name_lookup() to map heterogeneous model-generated module keys to verified project modules. The function discards invalid entries, self-referential dependencies, non-string descriptions, and duplicate relationships.     descriptions, dependencies = grouping_extras(parsed_llm_json, chapter_files)

    build_section_map()

    Visibility: Public
    Signature: def build_section_map(sections: list, dependencies: dict, max_listed: int = 8) -> tuple[str, bool, bool]:

    Description: Generates Mermaid flowchart source code (flowchart TD) for the high-level architecture overview rendered on docs/api/index.md. Each top-level navigation section is rendered as a single rectangular node summarizing its member modules (listing up to max_listed modules, appending a localized "... N more" string if exceeded). Directional arrows (S0 --> S1) are drawn when any module in section S0 depends on a module in S1. Sections that receive incoming dependencies from two or more distinct sections are identified as architectural hubs and highlighted using _ENTRY_NODE_CLASSDEF.

    Parameters: * sections (list): Hierarchical section groupings. * dependencies (dict): Module dependency mapping. * max_listed (int): Maximum number of module names to list inside each section's node. Defaults to 8.

    Returns: * tuple[str, bool, bool]: A 3-tuple (source, has_arrows, has_hubs) where source is the Mermaid flowchart string, has_arrows indicates if any edges were generated, and has_hubs indicates if hub styling was applied.

    Example: 

    section_map, map_has_arrows, map_has_hubs = build_section_map(sections, dependencies)
if section_map:
    index_lines += ["```mermaid", section_map, "```"]

    build_module_graph()

    Visibility: Public
    Signature: def build_module_graph(sections: list, dependencies: dict, chapter_files: list) -> tuple[str, int]:

    Description: Constructs Mermaid source code (flowchart LR) for a granular, module-level dependency diagram. Top-level sections are rendered as Mermaid subgraph clusters enclosing individual module nodes. Hub modules—defined as modules consumed by at least max(5, total_modules // 4) other modules (such as logging utilities or configuration singletons)—have their incoming arrows suppressed to prevent visual clutter; instead, they receive _ENTRY_NODE_CLASSDEF styling and an annotated label stating "used by N modules". If total module count exceeds _MODULE_GRAPH_MAX_MODULES (80) or if dependencies are empty, graph generation is bypassed.

    Parameters: * sections (list): Hierarchical section tree. * dependencies (dict): Module dependency mappings. * chapter_files (list): Master list of chapter dictionaries.

    Returns: * tuple[str, int]: A 2-tuple (source, hub_threshold) where source is the Mermaid string (or empty string if skipped) and hub_threshold is the integer count cutoff applied for hubs.

    Example: 

    module_graph, hub_threshold = build_module_graph(sections, dependencies, chapter_files)

    Example: 

    nav_lines = build_grouped_nav(sections, chapter_files, indent=4)
nav_lines.insert(0, "    - api/index.md")

    SECTION_ROLES

    Visibility: Public
    Signature: SECTION_ROLES = ("types", "setup", "core", "support", "operational")

    Description: Constant tuple defining the canonical architectural reading order for navigation sections. Emulates progressive codebase learning: foundation data structures (types), initialization routines (setup), central business logic (core), utility helpers (support), and runtime cross-cutting operations (operational).

    Returns: * list: New list of section dictionaries ordered by reading role and directory grouping.

    Example:

    build_index_sections()

    Visibility: Public
    Signature: def build_index_sections(lines, sections, chapter_files, level=3, summaries=None, descriptions=None):

    Description: Recursively constructs Markdown section headings and module summary tables for docs/api/index.md. For each module listed in a section, it outputs a table row with an escaped link (md_link_text) and an associated description. It resolves descriptions hierarchically: prioritizing the grouping reply's concise description (descriptions), falling back to an extracted summary description (summary_description) if the default description is generic, and defaulting to match["description"].

    Parameters: * lines (list): Mutable list of markdown string lines to which output is appended. * sections (list): Nested section definitions to render. * chapter_files (list): List of chapter definitions. * level (int): Markdown heading level (number of # characters).     Description: Generator function that splits input text into individual sentences using _SENTENCE_END_RE.     def _sentences(text: str):
    """Yield the sentences of *text*; an abbreviation such as "e.g." or "vs." does not end one."""
    start = 0
    for match in _SENTENCE_END_RE.finditer(text):
        piece = text[start : match.start()]
        if not piece or _ends_with_abbreviation(piece):
            continue
        yield piece
        start = match.end()
    if text[start:]:
        yield text[start:]

    The generator inspects text chunks sliced between consecutive punctuation boundaries. If a chunk ends with an entry from _ABBREVIATIONS, the iterator skips yielding and extends the current span to the next match. This mechanism prevents fractured sentences in generated documentation summaries and table descriptions.

    _ends_with_abbreviation()

    Visibility: Private

    Description: Evaluates whether a candidate string segment terminates with a recognized whole-word abbreviation from _ABBREVIATIONS.

    def _ends_with_abbreviation(piece: str) -> bool:
    """True when *piece* ends with a whole-word abbreviation ("… e.g." but not "… piano.")."""
    lower = piece.lower()
    for abbreviation in _ABBREVIATIONS:
        if lower.endswith(abbreviation):
            before = lower[: -len(abbreviation)][-1:]
            if not before or not before.isalnum():
                return True
    return False

    The helper performs lower-case prefix testing on the final characters of piece. When an abbreviation match is found, it inspects the preceding character to verify that it is non-alphanumeric or the start of the string, preventing false positives (e.g., verifying that a word ending in "no." is an abbreviation rather than "piano.").

    _section_members()

    Visibility: Private
    Signature: def _section_members(sections: list) -> list[tuple[str, list]]:

    Description: Flattens a nested section hierarchy into a list of tuples containing the top-level section name and a list of all descendant module names.

    def _section_members(sections: list) -> list[tuple[str, list]]:
    """``[(top-level section name, [module_name, ...])]``, children folded into their top-level section;
    a module listed in several sections belongs to the first."""
    owned = set()

    def modules_of(section):
        found = list(section.get("modules", []))
        for child in section.get("children", []):
            found += modules_of(child)
        return found

    groups = []
    for section in sections:
        members = []
        for name in modules_of(section):
            if name not in owned:
                owned.add(name)
                members.append(name)
        groups.append((section["name"], members))
    return groups

    This helper recursively folds child sections into their respective parent sections while enforcing a strict single-ownership rule via the owned set. If a module appears multiple times across different groupings, it is assigned exclusively to the first section that claimed it.

    def _mermaid_label(text) -> str:
    """Text for a quoted Mermaid label, with Mermaid's special characters as entity codes."""
    text = " ".join(str(text).split())
    for char, code in (("#", "#35;"), ('"', "#quot;"), ("`", "#96;"), ("<", "#lt;"), (">", "#gt;")):
        text = text.replace(char, code)
    return text

    Mermaid diagrams break when labels contain unescaped quotes, angle brackets, backticks, or hash symbols.     _page_link()

    def _page_link(page: str, target: str, filenames: set) -> str:
    """Link target from chapter *page* to chapter *target*, page-relative; ``./``-pinned when the relative path
    is also another chapter's root-relative path; in ``<…>`` when it holds spaces or parentheses."""
    directory = posixpath.dirname(page)
    relative = posixpath.relpath(target, directory) if directory else target
    if directory and relative in filenames and relative != target:
        relative = f"./{relative}"
    return f"<{relative}>" if re.search(r"[\s()]", relative) else relative

    The function computes the POSIX relative path from the originating directory to the target. If the relative path conflicts with another chapter's root-relative path, it prepends ./ to disambiguate the reference. If the final path contains spaces or parentheses, it encloses the target in angle brackets (<...>) per CommonMark specifications.

    The module implements defensive, fail-soft error handling across all filesystem, YAML, and LLM boundaries:

    • YAML Frontmatter Tolerance: split_frontmatter() wraps yaml.safe_load in a broad except Exception: block. If a document opens with a horizontal rule (---) that contains invalid YAML syntax or illegal date representations (e.g., 2024-02-30), the parsing error is ignored and the full markdown body is preserved intact.
    • LLM Grouping Failure Recovery: write_mkdocs_output() surrounds LLM prompt generation, API calls, and JSON parsing in a try...except Exception as e: block. If token limits are exceeded, JSON is malformed, or network failures occur, the module emits GROUP_ERROR_FALLBACK, logs a full traceback, and reverts to the deterministic flat navigation tree (prep_res["nav_snippet"]).
    • Empty Section Pruning: prune_sections() filters out sections that have no matching modules or children. This prevents emitting empty YAML navigation items (- "Section Name":), which causes MkDocs build validation to crash with Expected nav to be a list, got None.
    • Inode-Based Collision Defense: When pruning stale markdown pages in prune_stale_pages(), file identification uses (stat.st_dev, stat.st_ino) instead of string matching. On case-insensitive filesystems (macOS and Windows), renaming files with different casing will not cause active files to be mistakenly unlinked.
    • Unclosed Code Block Recovery: In add_used_by_lines(), if an upstream LLM response was truncated mid-generation leaving a code block unclosed, the helper detects the unclosed fence via parse_page(), extracts the opening delimiter (``` or ~~~), and appends the closing delimiter before injecting the "Used by:" line. This prevents the injected dependency text from being swallowed inside a code block.
    • Mermaid Syntax Defense: _mermaid_label() systematically encodes special characters (#, ", `, <, >) into entity codes, preventing malformed Mermaid syntax from crashing client-side browser rendering.
