    mkdocs.py

    Source: utils/mkdocs.py

    Following the inference configuration and token budget resolution provided by llm_config.py, the mkdocs.py module operates as the final artifact generation and document layout engine within the Codebase-Knowledge-Builder architecture. It consolidates site configuration generation, navigation tree synthesis, landing page formatting, cross-chapter relative hyperlink normalization, and physical file persistence for MkDocs documentation sites and standalone Markdown outputs.

    Technical Overview

    utils/mkdocs.py serves as the centralized output generation layer, decoupling markdown structuring and site layout logic from workflow execution nodes. The module receives synthesized chapter documents, section summaries, and repository metadata from upstream processing stages (principally CombineTutorial in nodes.py). It transforms these in-memory data structures into either a complete Material for MkDocs static documentation project or a self-contained, standalone Markdown directory structure.

    When operating in MkDocs mode, the module configures theme behaviors, code syntax highlighting, search facilities, and interactive diagram extensions. Notably, it resolves theme conflicts with Mermaid diagrams by establishing a custom .mermaid-raw CSS class fence paired with an unwrapping runtime script (mermaid-init.js), bypassing default Material color overrides to preserve native Mermaid palettes. For extensive reference suites (api-reference mode with more than five chapters), the module orchestrates an LLM-assisted grouping workflow using call_llm.py and prompts.py to generate hierarchical thematic navigation trees, falling back cleanly to deterministic directory-based navigation if grouping fails.

    Finally, the module enforces structural integrity across generated documents through a deterministic post-processing pass (normalize_chapter_links). Because language models frequently output absolute or inconsistent cross-chapter links, this pass maps all target references to verified canonical filenames and calculates exact relative POSIX paths between output subdirectories.

    Visibility: Public Signature: def build_mkdocs_config(site_name: str, nav_yaml: str, include_home: bool = True, lang_code: str = "") -> str:

    Description: Constructs the complete string contents of an mkdocs.yml configuration file configured for Material for MkDocs.     Raises: * None.

    def build_mkdocs_config(site_name: str, nav_yaml: str, include_home: bool = True, lang_code: str = "") -> str:
    # Extract nav items from nav_snippet (strip the "nav:" header line)
    nav_lines = nav_yaml.split("\n")
    nav_body = "\n".join(nav_lines[1:]) if nav_lines else ""

    # Conditional Home nav entry (CI has root index.md, local mkdocs doesn't)
    home_line = "  - Home: index.md\n" if include_home else ""

    # Optional Material theme language (e.g. "vi", "zh", "ja", "ko")
    lang_line = f"  language: {lang_code}\n" if lang_code else ""

    return (
        f"site_name: '{site_name}'\n"
        f"theme:\n"
        f"  name: material\n"
        f"{lang_line}"
        f"  features:\n"
        f"    - content.code.copy\n"
        f"    - navigation.indexes\n"
        f"  palette:\n"
        f"    - scheme: default\n"
        f"      toggle:\n"
        f"        icon: material/brightness-7\n"
        f"        name: Switch to dark mode\n"
        f"    - scheme: slate\n"
        f"      toggle:\n"
        f"        icon: material/brightness-4\n"
        f"        name: Switch to light mode\n"
        f"plugins:\n"
        f"  - search\n"
        f"  - panzoom:\n"
        f"      include_selectors:\n"
        f"        - '.mermaid-raw'\n"
        f"markdown_extensions:\n"
        f"  - pymdownx.highlight:\n"
        f"      anchor_linenums: true\n"
        f"      use_pygments: true\n"
        f"  - pymdownx.superfences:\n"
        f"      custom_fences:\n"
        f"        - name: mermaid\n"
        f"          class: mermaid-raw\n"
        f"          format: !!python/name:pymdownx.superfences.fence_code_format\n"
        f"  - pymdownx.inlinehilite\n"
        f"extra_javascript:\n"
        f"  - https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.min.js\n"
        f"  - javascripts/mermaid-init.js\n"
        f"nav:\n"
        f"{home_line}"
        f"{nav_body}\n"
    )

    The function processes the incoming nav_yaml by stripping its top-level nav: declaration so that child navigation nodes can be nested properly underneath optional root links such as Home: index.md. It injects pymdownx.superfences custom fences to assign the class mermaid-raw to Mermaid diagrams, bypassing Material's standard .mermaid styles that override flowchart colors. Furthermore, it adds the panzoom plugin and external JavaScript assets (mermaid.min.js and local mermaid-init.js) to provide diagram pan/zoom interactions.

    This function acts as a clean accessor for the module-level MERMAID_INIT_JS script template. The returned script attaches to the DOM DOMContentLoaded lifecycle event (or executes immediately if the document has already loaded), unwraps <pre class="mermaid-raw"><code> DOM hierarchies produced by pymdownx.superfences into raw text nodes expected by the Mermaid parser, and runs mermaid.initialize with 'default' theming and 'loose' security levels.

    normalize_chapter_links()

    Visibility: Public Signature: def normalize_chapter_links(chapter_files: list[dict]) -> None:

    Description: Deterministically post-processes Markdown contents across all chapter dictionaries in place to validate and fix cross-chapter links ([text](target.md)). It resolves target filenames against an indexed catalog of valid chapter paths, eliminating broken links caused by inconsistent directory depths or model hallucination.

    Parameters: * chapter_files (list[dict]): A list of chapter dictionaries containing "filename" and "content" keys. Modified in place.

    Returns: * None: Mutates the "content" key of dictionaries in chapter_files.

    Raises: * None.

    Example: 

    # Extracted from write_mkdocs_output execution path in utils/mkdocs.py
normalize_chapter_links(chapter_files)
for chapter_info in chapter_files:
    chapter_filepath = os.path.join(api_docs_path, chapter_info["filename"])
    # ... writes normalized content to disk

    Phase 1: Filename and Basename Lookup Mapping

        # Build lookup: various path forms → canonical filename
    filename_lookup = {}
    ambiguous_basenames = set()
    for cf in chapter_files:
        fname = cf["filename"]  # e.g. "CoreService/AccountingService.cs.md"
        filename_lookup[fname] = fname
        basename = fname.rsplit("/", 1)[-1]
        if basename in filename_lookup and filename_lookup[basename] != fname:
            ambiguous_basenames.add(basename)
        else:
            filename_lookup[basename] = fname

    The algorithm iterates through every chapter to construct filename_lookup. To maximize matching flexibility, it maps both the canonical relative path (e.g., services/auth.py.md) and the trailing basename (e.g., auth.py.md) to the canonical path. When two distinct files share identical basenames across different directories, the basename key is flagged in ambiguous_basenames to prevent misdirected link rewriting.

    Phase 2: Ambiguity Pruning and Link Substitution Closure

        # Remove ambiguous basenames (same name in different dirs)
    for ab in ambiguous_basenames:
        filename_lookup.pop(ab, None)

    link_pattern = re.compile(r"\[([^\]]*)\]\(([^)#]+\.md)(#[^)]*)?\)")
    fixed_count = 0

    for cf in chapter_files:
        current_dir = os.path.dirname(cf["filename"])  # e.g. "CoreService"

        def fix_link(match, _dir=current_dir):
            nonlocal fixed_count
            text, target, anchor = match.group(1), match.group(2), match.group(3) or ""
            if target.startswith(("http://", "https://")):
                return match.group(0)
            # Try resolving the target as-is (LLM copied verbatim from index)
            canonical = filename_lookup.get(target)
            if not canonical:
                # Try resolving relative to current dir
                resolved = os.path.normpath(os.path.join(_dir, target)).replace("\\", "/")
                canonical = filename_lookup.get(resolved)
            if canonical:
                correct_rel = os.path.relpath(canonical, _dir).replace("\\", "/") if _dir else canonical
                if correct_rel != target:
                    fixed_count += 1
                return f"[{text}]({correct_rel}{anchor})"
            return match.group(0)  # Unknown target — leave as-is

        cf["content"] = link_pattern.sub(fix_link, cf["content"])

    if fixed_count:
        emit_raw("DEBUG", f"LINK NORMALIZATION | fixed {fixed_count} cross-chapter links", dest="LOG")

    After ambiguous basenames are purged from the lookup index, the function compiles a regular expression targeting Markdown hyperlinks ending in .md with optional anchor fragments (#[^)]*). For each chapter, it scans the text using the nested helper fix_link. External HTTP/HTTPS links are ignored, while candidate file links are resolved against the lookup dictionary either verbatim or relative to current_dir. Valid targets are converted to exact relative paths using os.path.relpath, and all backslashes are replaced with POSIX forward slashes.

    write_mkdocs_output()

    Visibility: Public Signature: def write_mkdocs_output(output_path: str, prep_res: dict, chapter_files: list[dict]) -> None:

    Description: Orchestrates the generation of an entire MkDocs Material documentation site. It evaluates whether navigation grouping should be executed via LLM, generates mkdocs.yml, emits the Mermaid initialization runtime script, constructs root landing redirects and section index pages, normalizes relative cross-chapter hyperlinks, and serializes all chapter files to disk.

    Parameters: * output_path (str): Root destination directory on the filesystem where MkDocs artifacts will be written. * prep_res (dict): Upstream preparation dictionary containing project settings, mode descriptors, language preferences, directory trees, and base navigation structures. * chapter_files (list[dict]): Collection of chapter dictionaries containing filenames, module names, summaries, and Markdown bodies.

    Returns: * None: Writes files directly to disk and emits status events.

    Raises: * Exception: LLM grouping exceptions are caught internally and fall back to flat navigation; unhandled filesystem I/O exceptions propagate to the caller.

    Example: 

    # Extracted from CombineTutorial execution in nodes.py
from utils.mkdocs import write_mkdocs_output

write_mkdocs_output(
    output_path=context["output_dir"],
    prep_res=preparation_metadata,
    chapter_files=synthesized_chapters
)

    Phase 1: Initialization and Telemetry

        project_name = prep_res["project_name"]
    mode = prep_res["mode"]
    api_docs_path = os.path.join(output_path, "docs", "api")
    os.makedirs(api_docs_path, exist_ok=True)

    mode_labels = {
        "tutorial": get("UI_MODE_TUTORIAL"),
        "advanced": get("UI_MODE_ADVANCED"),
        "sdk": get("UI_MODE_SDK"),
        "api-reference": get("UI_MODE_API_REF"),
    }
    site_title = f"{project_name} — {mode_labels.get(mode, 'Documentation')}"
    emit("COMBINE_FORMAT_MKDOCS", mode=mode_labels.get(mode, "Documentation"))
    emit("COMBINE_CHAPTER_COUNT", count=len(chapter_files))

    The phase initializes output paths, ensuring docs/api exists on disk. It maps the active execution mode string to localized display labels via output.get(), constructs the overall documentation site title, and logs startup telemetry reporting the target mode and total chapter count.

    Phase 2: LLM-Assisted Navigation Grouping and Fallback

        # --- LLM-Assisted Nav Grouping (api-reference only, 6+ modules) ---
    sections = None
    emit_raw("DEBUG", f"NAV GROUPING CHECK | mode={mode} | module_count={len(chapter_files)} | threshold=6", dest="LOG")
    if mode == "api-reference" and len(chapter_files) > 5:
        try:
            chapter_summaries = prep_res.get("chapter_summaries", [])
            module_entries = []
            for i, cf in enumerate(chapter_files):
                summary = chapter_summaries[i] if i < len(chapter_summaries) and chapter_summaries[i] else cf["description"]
                module_entries.append(f"- {cf['module_name']}: {summary}")
            module_list = "\n".join(module_entries)

            # Load grouping prompt template
            prompt_path = os.path.join(os.path.dirname(os.path.dirname(os.path.abspath(__file__))), "prompts", "common", "group_modules.md")
            with open(prompt_path, encoding="utf-8-sig") as f:
                group_template = f.read()

            language = prep_res.get("language", "english")
            language_note = f"Section names MUST be in {language}." if language.lower() != "english" else ""

            group_prompt = group_template.format(
                project_name=project_name,
                module_count=len(chapter_files),
                module_list=module_list,
                directory_tree=prep_res.get("directory_tree", "N/A"),
                language_note=language_note,
            )

            emit("LLM_CALL_GROUPING", count=len(chapter_files))

            log_token_estimation("NavGrouping", group_prompt, prep_res.get("max_tokens", 100000))
            group_response = call_llm(group_prompt, use_cache=prep_res.get("use_cache", True), thinking_level=prep_res.get("thinking_level"))
            parsed = parse_yaml_response(group_response)
            sections = parsed.get("sections", parsed) if isinstance(parsed, dict) else None

            if sections:
                # Validate: ensure all modules are covered
                grouped_modules = collect_all_modules(sections)
                ungrouped = [cf["module_name"] for cf in chapter_files if cf["module_name"] not in grouped_modules]
                if ungrouped:
                    sections.append({"name": get("UI_OTHER"), "modules": ungrouped})

                nav_lines = build_grouped_nav(sections, chapter_files, indent=4)
                nav_lines.insert(0, "    - api/index.md")
                nav_label = mode_labels.get(mode, "Documentation")
                nav_snippet = f"nav:\n  - {nav_label}:\n" + "\n".join(nav_lines)
                emit("DONE_GROUPING", count=len(sections))
            else:
                emit("GROUP_EMPTY_FALLBACK")
                nav_snippet = prep_res["nav_snippet"]

        except Exception as e:
            emit("GROUP_ERROR_FALLBACK", error=e)
            emit_raw("ERROR", f"LLM grouping failed: {e}\n{traceback.format_exc()}", dest="LOG")
            nav_snippet = prep_res["nav_snippet"]
            sections = None
    else:
        nav_snippet = prep_res["nav_snippet"]

    When building an api-reference with more than five modules, flat navigation becomes unwieldy. The function compiles module descriptions and directory structures into prompts/common/group_modules.md and invokes call_llm() to cluster modules into thematic categories. The response is parsed with parse_yaml_response(). If parsing fails or an exception occurs, the system logs the failure and falls back to prep_res["nav_snippet"]. If sections are successfully produced, the code verifies coverage with collect_all_modules(), appends any orphan modules under an "Other" category, prepends api/index.md, and serializes the grouped navigation tree.

    This phase maps natural language designations (e.g., "vietnamese", "japanese") to two-letter ISO language codes required by MkDocs Material. It invokes build_mkdocs_config() to assemble the configuration file and writes it to mkdocs.yml. It then creates the docs/javascripts/ directory and writes the custom Mermaid unwrap script (mermaid-init.js) to ensure diagram styling renders reliably.

    Phase 4: Landing Pages and Section Indexes

        # --- Generate docs/index.md — homepage redirect to api/ ---
    mode_label = mode_labels.get(mode, "Documentation")
    home_index_path = os.path.join(output_path, "docs", "index.md")
    home_content = f'# {project_name}\n\n<meta http-equiv="refresh" content="0; url=api/">\n\n[→ {mode_label}](api/index.md)\n'
    with open(home_index_path, "w", encoding="utf-8") as f:
        f.write(home_content)
    emit("FILE_WROTE", path=home_index_path)

    # --- Generate docs/api/index.md — section landing page ---
    if sections:
        chapter_index_label = get("UI_CHAPTER_INDEX")
        chapters_label = get("UI_CHAPTERS")
        index_lines = [
            f"# {project_name} — {mode_label}",
            "",
            f"{mode_label} — **{project_name}** — **{len(chapter_files)}** {chapters_label}.",
            "",
            f"## {chapter_index_label}",
            "",
        ]
        build_index_sections(index_lines, sections, chapter_files)
        index_content = "\n".join(index_lines)
    else:
        # Build a rich flat index with module listing table
        chapter_summaries = prep_res.get("chapter_summaries", [])
        chapter_index_label = get("UI_CHAPTER_INDEX")
        chapters_label = get("UI_CHAPTERS")
        th_chapter = get("UI_TH_CHAPTER")
        th_description = get("UI_TH_DESCRIPTION")
        index_lines = [
            f"# {project_name} — {mode_label}",
            "",
            f"{mode_label} — **{project_name}** — **{len(chapter_files)}** {chapters_label}.",
            "",
            f"## {chapter_index_label}",
            "",
            f"| {th_chapter} | {th_description} |",
            "|---------|-------------|",
        ]
        for i, cf in enumerate(chapter_files):
            dir_path = os.path.dirname(cf.get("original_path", "")) or ""
            display = f"{dir_path}/{cf['module_name']}" if dir_path else cf["module_name"]
            summary = chapter_summaries[i] if i < len(chapter_summaries) and chapter_summaries[i] else cf["description"]
            # Truncate and sanitize for table cell (replace pipes and newlines)
            summary = summary.replace("|", "—").replace("\n", " ").strip()
            if len(summary) > 200:
                summary = summary[:197] + "..."
            index_lines.append(f"| [{display}]({cf['filename']}) | {summary} |")
        index_lines.append("")
        index_content = "\n".join(index_lines)
    api_index_filepath = os.path.join(api_docs_path, "index.md")
    with open(api_index_filepath, "w", encoding="utf-8") as f:
        f.write(index_content)
    emit("FILE_WROTE", path=api_index_filepath)

    The phase emits a root landing page at docs/index.md containing an HTML meta-refresh redirect (<meta http-equiv="refresh" content="0; url=api/">) and a fallback Markdown hyperlink pointing directly to the generated API index. It then constructs docs/api/index.md: if hierarchical sections were derived, it delegates table generation to build_index_sections(); otherwise, it builds a tabular module inventory, sanitizing pipes and newlines and truncating descriptions beyond 200 characters to preserve Markdown table formatting.

    Phase 5: Link Normalization and Chapter Persistence

        # --- Write nav_snippet.yml ---
    nav_filepath = os.path.join(output_path, "docs", "nav_snippet.yml")
    with open(nav_filepath, "w", encoding="utf-8") as f:
        f.write(nav_snippet)
    emit("FILE_WROTE", path=nav_filepath)

    # --- Normalize cross-chapter links ---
    normalize_chapter_links(chapter_files)

    # --- Write chapter files ---
    for chapter_info in chapter_files:

        for dir_path, mod_name, match in matched:

        # Emit dir sub-layers for non-root dirs, flat for root files

    Modules within a section are grouped by their directory paths via defaultdict(list).     def collect_all_modules(sections: list) -> set:
    """Recursively collect all module names referenced in a sections tree."""
    result = set()
    for section in sections:
        result.update(section.get("modules", []))
        if "children" in section:
            result.update(collect_all_modules(section["children"]))
    return result

    This helper performs a depth-first traversal across arbitrary nesting depths in the section structure.     def build_index_sections(lines, sections, chapter_files, level=3):
    """Recursively build index.md sections with module tables."""
    heading = "#" * level
    for section in sections:
        lines.append(f"{heading} {section['name']}")
        lines.append("")
        if section.get("modules"):
            lines.append(f"| {get('UI_TH_CHAPTER')} | {get('UI_TH_DESCRIPTION')} |")
            lines.append("|---------|-------------|")
            for mod_name in section["modules"]:
                match = next((cf for cf in chapter_files if cf["module_name"] == mod_name), None)
                if match:
                    display = mod_name
                    # Use description, but if it's the generic mapper description, extract from content
                    desc = match["description"]
                    if desc.startswith("Internal API reference"):
                        content_lines = match["content"].strip().split("\n")
                        for cl in content_lines:
                            cs = cl.strip()
                            if cs and not cs.startswith(("---", "#", "```", "title:", "sidebar_position:")):
                                desc = cs[:120]
                                break
                    lines.append(f"| [{display}]({match['filename']}) | {desc} |")
            lines.append("")
        for child in section.get("children", []):
            build_index_sections(lines, [child], chapter_files, level + 1)

    The helper formats each section title with a dynamic Markdown heading level (# multiplied by level).     Visibility: Private (nested closure inside normalize_chapter_links) Signature: def fix_link(match: re.Match, _dir: str = current_dir) -> str:

    Parameters: * match (re.Match): Regex match object containing the link text (group 1), target file path (group 2), and optional anchor fragment (group 3). * _dir (str, optional): The directory of the chapter file currently being rewritten. Defaults to current_dir bound in the outer scope.

    Returns: * str: The original link string if unresolvable/external, or the rewritten Markdown link with an updated relative path.

    Raises: * None.

    Example: 

    # Extracted from normalize_chapter_links in utils/mkdocs.py

            def fix_link(match, _dir=current_dir):
            nonlocal fixed_count
            text, target, anchor = match.group(1), match.group(2), match.group(3) or ""
            if target.startswith(("http://", "https://")):
                return match.group(0)
            # Try resolving the target as-is (LLM copied verbatim from index)
            canonical = filename_lookup.get(target)
            if not canonical:
                # Try resolving relative to current dir
                resolved = os.path.normpath(os.path.join(_dir, target)).replace("\\", "/")
                canonical = filename_lookup.get(resolved)
            if canonical:
                correct_rel = os.path.relpath(canonical, _dir).replace("\\", "/") if _dir else canonical
                if correct_rel != target:
                    fixed_count += 1
                return f"[{text}]({correct_rel}{anchor})"
            return match.group(0)  # Unknown target — leave as-is

    The closure extracts link text, target file, and anchor fragments. External links starting with http:// or https:// are returned unmodified. For internal links, it looks up target in filename_lookup. If an immediate match is not found, it normalizes target relative to the current chapter's directory (_dir). If a canonical path is resolved, os.path.relpath() calculates the relative path from _dir to the target file. If the resolved path differs from the original target, it increments fixed_count and returns the corrected Markdown link.

    MERMAID_INIT_JS

    Type: str A JavaScript template string written to docs/javascripts/mermaid-init.js. It runs in client browsers to unwrap pymdownx.superfences code elements and initialize the Mermaid diagram runtime.

    // Mermaid initialization for MkDocs Material.
//
// Material for MkDocs targets .mermaid class for its own color overrides.
// By using .mermaid-raw, diagrams render with Mermaid's default theme:
// yellow subgraph backgrounds, lavender nodes, clean rectangles.
//
// pymdownx.superfences fence_code_format wraps content as:
//   <pre class="mermaid-raw"><code>flowchart TD ...</code></pre>
// Mermaid expects the diagram text directly in the target element,
// so we unwrap the <code> child before calling mermaid.run().
(function() {
  function initMermaid() {
    if (typeof mermaid === 'undefined') return;
    try {
      // Unwrap: move <code> text content up to <pre> and remove <code>
      document.querySelectorAll('pre.mermaid-raw > code').forEach(function(code) {
        var pre = code.parentElement;
        pre.textContent = code.textContent;
      });
      mermaid.initialize({
        startOnLoad: false,
        theme: 'default',
        securityLevel: 'loose'
      });
      mermaid.run({ querySelector: '.mermaid-raw' }).catch(function(err) {
        console.warn('Mermaid render error:', err);
      });
    } catch (e) {
      console.warn('Mermaid init error:', e);
    }
  }
  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', initMermaid);
  } else {
    initMermaid();
  }
})();

    Error Handling

    LLM Grouping Failures and Graceful Fallback

    In write_mkdocs_output(), dynamic module clustering is wrapped in an explicit try...except Exception as e boundary. If the LLM call times out, encounters token exhaustion, returns malformed syntax, or fails during YAML parsing: 1. The exception and traceback are logged via emit_raw("ERROR", ..., dest="LOG"). 2. A localized telemetry event GROUP_ERROR_FALLBACK is dispatched. 3. The module sets sections = None and falls back to the deterministic navigation snippet pre-computed in prep_res["nav_snippet"]. 4. Site generation continues without interrupting pipeline execution.

    Module Coverage Validation and Orphan Recovery

    If the LLM generates a valid YAML section tree but omits certain modules: 1. collect_all_modules(sections) aggregates all referenced module names. 2. The list of omitted modules (ungrouped) is identified by comparing against chapter_files. 3. If ungrouped is non-empty, a synthetic section is appended to sections: 

    sections.append({"name": get("UI_OTHER"), "modules": ungrouped})
    4. This guarantees that all generated chapter files remain accessible in the navigation tree and index table.

    Ambiguous Basename Collisions in Link Normalization

    During normalize_chapter_links(), repositories containing identical filenames across different directories (e.g., pkg_a/utils.py.md and pkg_b/utils.py.md) present ambiguous resolution targets. The function tracks duplicate basenames in an ambiguous_basenames set: 

    if basename in filename_lookup and filename_lookup[basename] != fname:
    ambiguous_basenames.add(basename)
    All entries in ambiguous_basenames are deleted from filename_lookup. Consequently, bare links to colliding basenames are preserved as-is rather than rewritten to an incorrect directory target.

    Client-Side Mermaid Initialization Defense

    In MERMAID_INIT_JS, diagram initialization is wrapped in both synchronous try/catch blocks and asynchronous .catch(function(err) {...}) promise rejections. If an invalid Mermaid diagram fails to render, the error is logged to console.warn without throwing uncaught exceptions that could interrupt surrounding MkDocs JavaScript features (such as search or theme switching).
