    mkdocs.py

    Source: utils/mkdocs.py

    Technical Overview

    The utils/mkdocs.py module serves as the primary publishing, site generation, and link-normalization engine for the Codebase-Knowledge-Builder pipeline. Consolidating logic previously divided between workflow nodes and prompt construction helpers, it orchestrates the transformation of generated documentation chapters into a fully functional, deployable MkDocs Material static site or a standalone Markdown collection. The module builds site configuration files (mkdocs.yml), injects specialized interactive assets (such as panzoom-enabled Mermaid runtime scripts), formats index landing pages with visual architecture and dependency diagrams, and validates the integrity of all emitted pages.

    Architecturally, the module bridges LLM-synthesized narrative documentation with deterministic static analysis facts. In the api-reference documentation mode, it queries language models to derive hierarchical module groupings and domain roles, while grounding module-level dependencies directly against source-verified AST facts produced by utils.facts. It synthesizes two distinct Mermaid diagrams on the index page: a high-level subsystem architecture map and an interconnected module graph that flags high-fan-in architectural hubs. Furthermore, the module enforces structural stability across generated documentation through a series of deterministic post-processing routines: resolving cross-chapter link targets to relative POSIX paths, appending verified importer references ("Used by"), and purging obsolete documentation artifacts across compilation runs.

    Public API

    yaml_str()

    Visibility: Public

    Signature: def yaml_str(value) -> str:

    Description: Serializes and escapes an arbitrary Python scalar into a valid YAML double-quoted string literal using JSON encoding semantics. Because JSON string literals conform directly to YAML scalar syntax, this helper guarantees that section names, titles, and navigation labels containing special characters (such as colons, brackets, apostrophes, or leading @ symbols) do not break mkdocs.yml structure.

    Parameters:

    • value (Any): The scalar value, string, or number to be serialized into hand-built YAML syntax.

    Returns:

    • str: A valid, JSON-encoded and double-quoted YAML scalar string with leading and trailing whitespace stripped.

    Example:

    from utils.mkdocs import yaml_str

label = yaml_str("Core: Internal Services & Auth")
# Evaluates to: '"Core: Internal Services & Auth"'

    build_mkdocs_config()

    Visibility: Public

    Signature: def build_mkdocs_config(site_name: str, nav_yaml: str, include_home: bool = True, lang_code: str = "") -> str:

    Description: Compiles a complete mkdocs.yml configuration string optimized for MkDocs Material. The generated configuration enables code-copy buttons, instant navigation indices, Pygments syntax highlighting, and Mermaid diagram integration via a specialized .mermaid-raw CSS class that bypasses default theme color overrides. It integrates the panzoom plugin for interactive diagram exploration and allows localization of search and user interface components via an optional language code.

    Parameters:

    • site_name (str): The primary site title displayed in the navigation header.
    • nav_yaml (str): Hand-crafted or generated YAML navigation lines (typically generated by build_grouped_nav).
    • include_home (bool): Whether to prepend a root home entry linking to index.md. Defaults to True.
    • lang_code (str): Optional two-letter ISO language code (e.g., "vi", "zh", "fr") to localize Material UI strings. Defaults to "".

    Returns:

    • str: A complete, formatted mkdocs.yml configuration string.

    Example:

    mkdocs_config = build_mkdocs_config(
    site_name="My Project",
    nav_yaml="nav:\n  - Overview: index.md\n",
    include_home=True,
    lang_code="en",
)

    MERMAID_INIT_JS

    Visibility: Public

    Signature: MERMAID_INIT_JS = """..."""

    Description: A JavaScript snippet string embedded into javascripts/mermaid-init.js. It overrides MkDocs Material's default Mermaid coloring by initializing Mermaid with the "default" theme on <div class="mermaid-raw"> containers. It dynamically appends a stylesheet ensuring diagrams in dark mode ([data-md-color-scheme="slate"]) render on a light background card for edge contrast, and catches diagram rendering anomalies gracefully without halting browser thread execution.

    build_chapter_filenames()

    Visibility: Public

    Signature: def build_chapter_filenames(chapter_order: list, abstractions: list, is_mkdocs: bool) -> dict:

    Description: Establishes a deterministic mapping from chapter sequence indices to target Markdown filenames. For MkDocs compilation, if an abstraction provides an original_path, it mirrors that relative POSIX path; otherwise, it sanitizes the abstraction name into an alphanumeric slug. For standalone output, it prefixes the slug with a zero-padded index (01_name.md). It maintains an internal collision set (treating readme.md as equivalent to directory index.md) and appends numeric suffixes (_2.md, _3.md) when names collide case-insensitively.

    Parameters:

    • chapter_order (list): List of integer abstraction indices representing the desired reading sequence.
    • abstractions (list): Master collection of abstraction metadata dictionaries extracted from the codebase.
    • is_mkdocs (bool): Flag indicating whether output targets an MkDocs directory structure (True) or a flat standalone directory (False).

    Returns:

    • dict[int, str]: Mapping of chapter position index to relative Markdown filename.

    Example:

    filenames = build_chapter_filenames(
    chapter_order=[0, 1],
    abstractions=[
        {"name": "App Core", "original_path": "src/core.py"},
        {"name": "Utils", "original_path": "src/utils.py"},
    ],
    is_mkdocs=True,
)
# Result: {0: 'src/core.py.md', 1: 'src/utils.py.md'}

    split_frontmatter()

    Visibility: Public

    Signature: def split_frontmatter(text: str) -> tuple[str, bool]:

    Description: Strips leading YAML frontmatter blocks from a Markdown string matching MkDocs' native metadata parser semantics. The block must begin at line zero with ---, terminate with --- or ..., and parse as a valid YAML mapping. If the block fails YAML validation or does not parse as a mapping, the text is preserved untouched to avoid truncating Markdown files that open with a horizontal rule.

    Parameters:

    • text (str): The raw Markdown text to evaluate.

    Returns:

    • tuple[str, bool]: A 2-tuple containing (body_text, found_flag), where found_flag indicates whether a valid frontmatter mapping was extracted and removed.

    Example:

    content, has_fm = split_frontmatter("---\ntitle: Home\n---\n# Content")
# content == "# Content", has_fm is True

    clip_sentences()

    Visibility: Public

    Signature: def clip_sentences(text: str, limit: int) -> str:

    Description: Truncates prose to whole sentences without exceeding a maximum character limit. Handles both Latin punctuation boundaries and CJK sentence terminators without spacing. If even the first sentence exceeds the character limit, the text is cut at a word boundary (or exact character index for languages without spaces), trailing punctuation is trimmed, open backtick code spans are defensively closed, and an ellipsis (…) is appended.

    Parameters:

    • text (str): Prose content to truncate.
    • limit (int): Maximum allowed character length.

    Returns:

    • str: Formatted, sentence-bounded string guaranteed not to exceed limit (unless truncated with an ellipsis suffix).

    Example:

    clipped = clip_sentences("First sentence. Second sentence.", limit=20)
# clipped == "First sentence."

    table_cell_text()

    Visibility: Public

    Signature: def table_cell_text(text: str) -> str:

    Description: Prepares raw text for safe inclusion within a Markdown table cell by escaping vertical bar characters (| to \|). The helper parses inline code spans (...) using regular expressions and preserves literal pipes located inside code spans, allowing types such as str | None to render unescaped.

    Parameters:

    • text (str): The raw text to escape.

    Returns:

    • str: The sanitized text with table cell delimiters escaped outside of inline code spans.

    Example:

    cell = table_cell_text("Returns str | None | union")
# Returns: "Returns str \\| None \\| union"
cell_code = table_cell_text("Returns `str | None` | union")
# Returns: "Returns `str | None` \\| union"

    summary_description()

    Visibility: Public

    Signature: def summary_description(summary: str, limit: int = 300) -> str:

    Description: Extracts a concise module description from a multi-point structured chapter summary for use in index tables. It isolates the primary "Component Scope & Responsibility" section (point 1), discards preamble chatter (such as "Here is a structured technical brief..."), strips numeric and bold heading markers, truncates the text to whole sentences within limit characters via clip_sentences, and escapes pipe delimiters via table_cell_text.

    Parameters:

    • summary (str): The raw multi-point chapter summary text.
    • limit (int): Maximum character ceiling for the description. Defaults to 300.

    Returns:

    • str: A sanitized, single-paragraph description suitable for Markdown table cells.

    Example:

    desc = summary_description("### (1) Component Scope & Responsibility\nHandles auth.", limit=100)
# desc == "Handles auth."

    build_module_graph()

    Visibility: Public

    Signature: def build_module_graph(sections: list, dependencies: dict, chapter_files: list) -> tuple[str, int]:

    Description: Constructs a detailed Mermaid module dependency graph (flowchart LR) for api/index.md. Modules are partitioned into subgraphs corresponding to their top-level navigation sections. High-fan-in hub modules—modules depended upon by at least max(5, total_modules // 4) other files—are highlighted with the entryNode styling class, labeled with an incoming dependency count (used by N modules), and have incoming arrows pruned to avoid diagram sprawl. Returns an empty diagram if total modules exceed _MODULE_GRAPH_MAX_MODULES (80) or if dependencies are empty.

    Parameters:

    • sections (list): Navigation section tree defining module grouping.
    • dependencies (dict): Module dependency dictionary ({source: [targets]}).
    • chapter_files (list): Complete list of chapter descriptors.

    Returns:

    • tuple[str, int]: A 2-tuple containing:
      1. mermaid_source (str): Fenced diagram source string, or "" if skipped.
      2. hub_threshold (int): The numerical fan-in threshold required for hub status (0 if no hubs exist).

    Example:

    graph_src, hub_thresh = build_module_graph(sections, dependencies, chapter_files)

    normalize_chapter_links()

    Visibility: Public

    Signature: def normalize_chapter_links(chapter_files):

    Description: Post-processing routine that scans all Markdown content across chapter_files and rewrites cross-chapter Markdown links ([text](target.md)). It constructs a lookup table of canonical paths and bare basenames, determines the relative directory distance between the current chapter and the link target, and updates link URLs to POSIX-compliant relative paths. Pins relative links with ./ if they collide with another chapter's root path, while leaving external HTTP/HTTPS links unmodified.

    Parameters:

    • chapter_files (list): List of chapter dictionaries whose content strings are updated in place.

    Returns:

    • None: Mutates chapter content in place.

    Example:

    # In utils/mkdocs.py:
def normalize_chapter_links(chapter_files):
    filenames = [cf["filename"] for cf in chapter_files]
    filename_lookup = {fname: fname for fname in filenames}
    basename_counts = Counter(fname.rsplit("/", 1)[-1] for fname in filenames)
    for fname in filenames:
        basename = fname.rsplit("/", 1)[-1]
        if basename_counts[basename] == 1 and basename not in filename_lookup:
            filename_lookup[basename] = fname

    link_pattern = re.compile(r"\[([^\]]*)\]\(([^)#]+\.md)(#[^)]*)?\)")
    fixed_count = 0

    for cf in chapter_files:
        current_dir = os.path.dirname(cf["filename"])

        def fix_link(match, _dir=current_dir):
            nonlocal fixed_count
            text, target, anchor = match.group(1), match.group(2), match.group(3) or ""
            if target.startswith(("http://", "https://")):
                return match.group(0)
            canonical = filename_lookup.get(target)
            if not canonical:
                resolved = os.path.normpath(os.path.join(_dir, target)).replace("\\", "/")
                canonical = filename_lookup.get(resolved)
            if canonical:
                correct_rel = os.path.relpath(canonical, _dir).replace("\\", "/") if _dir else canonical
                if _dir and filename_lookup.get(correct_rel, canonical) != canonical:
                    correct_rel = f"./{correct_rel}"
                if correct_rel != target:
                    fixed_count += 1
                return f"[{text}]({correct_rel}{anchor})"
            return match.group(0)

        cf["content"] = link_pattern.sub(fix_link, cf["content"])

    The function iterates over each chapter file, determining its enclosing directory depth. When a match for a Markdown link pattern is identified, it extracts the destination target and resolves it against the canonical filename registry. If the relative path calculated from the source chapter to the destination differs from the author's original link text, the link is rewritten and a debug telemetry counter is incremented.

    Signature: def _ends_with_abbreviation(piece: str) -> bool:

    Description: Evaluates whether a text fragment terminates with a recognized abbreviation from _ABBREVIATIONS. Ensures that word boundaries match (e.g., matching ... e.g. but not a word ending in those letters like piano.).

    Parameters:

    • piece (str): Text fragment ending with a period.

    # In utils/mkdocs.py:
def _ends_with_abbreviation(piece: str) -> bool:
    lower = piece.lower()
    for abbreviation in _ABBREVIATIONS:
        if lower.endswith(abbreviation):
            before = lower[: -len(abbreviation)][-1:]
            if not before or not before.isalnum():

    return False

    owned = set()

        found = list(section.get("modules", []))
        for child in section.get("children", []):
            found += modules_of(child)
        return found

    Error Handling

    The module implements defensive programming patterns to prevent build failures during site generation:

    • LLM Grouping Resilience: The grouping pipeline in write_mkdocs_output wraps the call_llm invocation and response parsing in a top-level try/except block. If the LLM call times out, returns malformed JSON, or fails validation, an error event is logged and the pipeline falls back gracefully to prep_res["nav_snippet"] and a flat index table.
    • Frontmatter Parsing Safety: In split_frontmatter, YAML parsing errors (YAMLError, ValueError) triggered by invalid syntax or out-of-range dates are caught. The function safely returns the original text intact with a False flag, preventing content loss.
    • Markdown Renderer Availability: In site_renderer, missing markdown libraries or extension configuration errors are intercepted and logged via emit("CHAPTER_CHECK_NO_RENDERER"), returning None so downstream audits can handle the missing renderer without raising unhandled exceptions.
    • Navigation Tree Validation: In prune_sections, unrecognized module names and sections left empty after filtering are pruned. This prevents emitting empty YAML navigation keys (- "Name":), which causes mkdocs build to terminate with a schema error.
    • Unclosed Markdown Blocks: In add_used_by_lines, chapters ending in unclosed code fences are detected using parse_page. A matching closing fence is inserted before appending the "Used by" line, preventing the reference from being swallowed into a code block.
    • Inode-Based File Pruning: In prune_stale_pages, existing files are matched using filesystem device and inode numbers (st_dev, st_ino) rather than string path matching. This prevents case-only file renames on case-insensitive filesystems from leaving behind orphaned pages that MkDocs would otherwise include in the site search index.
