    call_llm.py

    Source: utils/call_llm.py

    Technical Overview

    utils/call_llm.py serves as the primary inference gateway and orchestration module for all Large Language Model (LLM) communications within the Codebase-Knowledge-Builder repository. It provides a unified entry point, call_llm(), which abstracts provider-specific connection protocols, client implementations, request and response normalizations, and authentication subtleties. Downstream workflow nodes invoke this unified function without needing direct coupling to the underlying vendor interfaces, whether interacting with Anthropic Claude, Google Gemini, OpenRouter, or self-hosted OpenAI-compatible endpoints such as Ollama.

    The architecture emphasizes cost-efficiency, operational idempotency, and fine-grained observability. Disk caching is implemented through an in-memory singleton backed by a JSON file (llm_cache_v2.json). Cached entries are keyed by a SHA-256 hash combining the provider, model, thinking level, and prompt text. Cache updates use atomic filesystem operations (writing to a temporary file before renaming) to ensure process interruptions never leave corrupt or truncated states on disk. Additionally, the module integrates with a ledger system defined in utils/llm_common.py that intercepts unretryable provider refusals (preventing redundant billed retries on subsequent node cycles) and tracks token consumption, reasoning tokens, cache read rates, and monetary costs.

    The execution lifecycle of a language model invocation through this module proceeds through cache lookup, refusal ledger validation, provider-specific routing, token usage recording, and cache serialization:

    Public API

    cache_file

    Visibility: Public

    Signature: cache_file = "llm_cache_v2.json"

    Description: The active on-disk filename where the v2 LLM response cache is serialized and stored in JSON format. Responses stored in this file are scoped to individual SHA-256 digests calculated across provider names, model IDs, thinking levels, and the prompt text.

    LEGACY_CACHE_FILE

    Visibility: Public

    Signature: LEGACY_CACHE_FILE = "llm_cache.json"

    Description: The legacy v1 cache file path. Pre-v2 caches keyed responses purely on prompt content without scoping to provider or model parameters. This file is no longer read or written by the runtime, but its presence is checked at startup so users can be alerted to clean up obsolete disk usage.

    load_cache()

    Visibility: Public

    Signature: def load_cache():

    Description: Loads the disk cache into the in-memory singleton _cache. If the in-memory dictionary is already populated, it returns immediately without disk access. If the file is not found, an empty dictionary is initialized. If decoding fails due to an invalid JSON structure or an operating system error, an alert is emitted via utils.output and an empty cache is returned to prevent blocking operations.

    Parameters:

    None.

    Returns:

    • dict: The global cache dictionary mapping hashed cache keys to string completions.

    Raises:

    None internally; all FileNotFoundError, json.JSONDecodeError, and OSError exceptions are caught and handled defensively.

    Example:

    cache = load_cache()
if key in cache:
    cached_response = cache[key]
    emit("CACHE_HIT", chars=f"{len(cached_response):,}")
    record_estimate(step, prompt_tokens, cache_hit=True)

    The function checks the module-level _cache variable and deserializes the JSON cache file upon first call. If a corrupted file is encountered, warnings are dispatched through the centralized event-emitting system while ensuring runtime execution continues uninterrupted with a clean, in-memory dictionary.

    save_cache()

    Visibility: Public

    Signature: def save_cache(cache):

    Description: Synchronizes the current in-memory cache to the filesystem. To prevent data corruption from ungraceful process terminations, the function employs atomic file replacement: it dumps the JSON payload into a temporary file named llm_cache_v2.json.tmp and executes os.replace to atomically overwrite the destination cache file.

    Parameters:

    • cache (dict): The dictionary of cache keys and string responses to persist.

    Returns:

    • None

    Raises:

    None internally; caught OSError and TypeError events trigger an error emit rather than crashing the pipeline.

    Example:

    if use_cache and response_text and not getattr(response_text, "truncated", False):
    cache = load_cache()
    cache[key] = response_text
    save_cache(cache)
    emit_raw("DEBUG", "CACHE WRITE | saved response to cache", dest="LOG")

    This write strategy guarantees that even if a pipeline run is cancelled or terminated mid-write, the existing cache file remains intact. Any failure in serializing or writing to the disk results in a warning log event (WARN_CACHE_SAVE_FAIL), keeping the process alive.

    Parameters:

    None.

    Returns:

    • None

    Raises:

    None internally; OSError exceptions triggered during os.path.getsize are silently ignored.

    Example:

    from utils.llm_config import check_llm_auth

    call_llm()

    Visibility: Public

    Signature: def call_llm(prompt: str, use_cache: bool = True, thinking_level: str | None = None, step: str | None = None) -> str:

    Description: The central public dispatch interface used throughout the codebase to submit a prompt to the configured LLM provider. It resolves the active provider configuration, inspects local caches, checks for previous refusal records, delegates execution to provider subroutines, captures telemetry and usage deltas, and updates the cache.

    Phase 1: Parameter Normalization and Telemetry Initialization

        step = step or "other"
    provider, model, _, _ = resolve_llm_settings()
    prompt_tokens = count_tokens(prompt)  # memoized: the node already counted this prompt

    emit_raw("DEBUG", f"{'=' * 80}", dest="LOG")
    emit_raw(
        "DEBUG",
        f"LLM CALL START | provider={provider} | model={model} | thinking={thinking_level} | cache={'enabled' if use_cache else 'disabled'} | prompt_tokens={prompt_tokens:,}",
        dest="LOG",
    )
    emit_raw("DEBUG", f"PROMPT:\n{prompt}", dest="LOG")

    The routine defaults the node execution step to "other" if unspecified. It resolves the active provider and model via resolve_llm_settings(), calculates prompt token metrics using memoized estimation utilities, and logs structured debug entries.

    Phase 2: Cache Inspection

        # Check cache if enabled
    key = _cache_key(prompt, provider, model, thinking_level)
    if use_cache:
        cache = load_cache()
        if key in cache:
            cached_response = cache[key]
            emit("CACHE_HIT", chars=f"{len(cached_response):,}")
            record_estimate(step, prompt_tokens, cache_hit=True)
            emit("LLM_CALL_CACHED", step=step, estimate=f"{prompt_tokens:,}")
            emit_raw("DEBUG", f"RESPONSE (cached):\n{cached_response}", dest="LOG")
            emit_raw("DEBUG", "LLM CALL END | result=cache_hit", dest="LOG")
            return cached_response
        emit("CACHE_MISS")

    When caching is requested (use_cache=True), the function derives the SHA-256 hash key across the prompt and runtime settings. Upon a cache hit, token estimation metrics are updated, telemetry events are emitted, and the cached response string is returned immediately, bypassing external network overhead.

    Phase 3: Prior Refusal Verification

        # A request the provider already declined this run is declined again: do not re-send it on
    # node retries (rate limits, billed partial output). The node retry still sees the error.
    refusal_key = request_key(provider, model, thinking_level, prompt)
    refused = previous_refusal(refusal_key)
    if refused is not None:
        emit_raw("DEBUG", "LLM CALL END | result=refused_before (not re-sent)", dest="LOG")
        raise refused

    Before dispatching expensive or blocked API calls, the function evaluates whether an identical prompt and parameter combination was previously rejected during this pipeline execution. If an unretryable refusal is on record, the stored exception is re-raised immediately to prevent wasted billing and repeated rate-limit violations.

    Phase 4: Provider Dispatch and Ledger Tracking

        # Make the actual LLM call
    start_time = time.time()
    emit_raw("DEBUG", f"API CALL | sending request to {provider}...", dest="LOG")

    # Usage of this call = ledger delta for the provider: it includes every billed request the call
    # made (Anthropic truncation retry, resend after fallbacks were disabled), even when it raises.
    before = usage_snapshot(provider)
    returned = False
    try:
        with usage_step(step):
            if provider == "GEMINI":
                response_text = _call_llm_gemini(prompt, thinking_level=thinking_level)
            elif provider == "ANTHROPIC":
                response_text = _call_llm_anthropic(prompt, thinking_level=thinking_level)
            elif provider == "OPENROUTER":
                response_text = _call_llm_openrouter(prompt, thinking_level=thinking_level)
            else:  # generic method using a URL that is OpenAI compatible API (Ollama, ...)
                response_text = _call_llm_provider(prompt, thinking_level=thinking_level)
        returned = True
    except LLMRefusalError as e:
        if not e.retryable:
            remember_refusal(refusal_key, e)
        raise
    finally:
        call_usage = usage_delta(before, usage_snapshot(provider))
        measured = call_usage["calls"] - call_usage["unmeasured_calls"]
        if measured:
            record_estimate(step, prompt_tokens * measured)
            _emit_call_usage(step, prompt_tokens, call_usage, measured)
        elif returned:  # answered, but the provider reported no usage
            emit("LLM_CALL_USAGE_MISSING", step=step, estimate=f"{prompt_tokens:,}")

    The function captures a baseline usage snapshot from the ledger and routes the prompt within a usage_step context manager to the appropriate provider handler. If an LLMRefusalError occurs and is marked non-retryable, it is recorded in the refusal registry. The finally block computes the ledger delta to ensure that token metrics and request costs are accounted for, even if underlying operations fail.

    Phase 5: Response Finalization and Atomic Cache Write

        elapsed = time.time() - start_time
    emit_raw("DEBUG", f"API CALL COMPLETE | elapsed={elapsed:.1f}s | response_chars={len(response_text):,}", dest="LOG")
    emit_raw("DEBUG", f"RESPONSE:\n{response_text}", dest="LOG")

    # Update cache if enabled. Empty and truncated responses (llm_common.TruncatedResponse)
    # are never cached — they would be replayed on every later run.
    if use_cache and response_text and not getattr(response_text, "truncated", False):
        cache = load_cache()
        cache[key] = response_text
        save_cache(cache)
        emit_raw("DEBUG", "CACHE WRITE | saved response to cache", dest="LOG")

    emit_raw("DEBUG", f"LLM CALL END | result=success | elapsed={elapsed:.1f}s", dest="LOG")
    return response_text

    Elapsed time and completed responses are written to debug logs. If caching is enabled and the response text is non-empty and not flagged as truncated (via TruncatedResponse), the new output is written to the cache and flushed atomically to disk.

    Parameters:

    • prompt (str): The complete prompt text to submit to the model.
    • use_cache (bool, optional): Whether to inspect or populate the response cache. Defaults to True.
    • thinking_level (str | None, optional): Model-specific reasoning budget or level (e.g., "low", "medium", "high"). Defaults to None.
    • step (str | None, optional): Name of the executing workflow node, mapped against NODE_KEYS for token ledger attribution. Defaults to None.

    Returns:

    • str: The text generated by the model.

    Raises:

    • LLMRefusalError: Re-raised or newly raised if the provider rejects the prompt or content filtering blocks completion.
    • ValueError: Raised if the provider configuration is missing required environment variables or returns malformed JSON.
    • RuntimeError: Raised if the provider API response is missing completion choices.
    • Exception: Raised on network failures, timeouts, or unexpected API errors.

    Example:

    test_prompt = "Hello, how are you?"

emit("SELFTEST_LLM_CALL")
response1 = call_llm(test_prompt, use_cache=False)
emit("SELFTEST_LLM_RESPONSE", response=response1)

    _cache_key()

    Visibility: Private

    Signature: def _cache_key(prompt: str, provider: str, model: str, thinking_level: str | None) -> str:

    Description: Constructs an immutable SHA-256 hash identifying an LLM invocation. Scopes the hash to the provider name, model identifier, normalized thinking level, and prompt body to prevent cache cross-contamination across differing configurations.

    Parameters:

    • prompt (str): The prompt string.
    • provider (str): The provider identifier (e.g., "ANTHROPIC", "GEMINI", "OLLAMA").
    • model (str): The specific model name.
    • thinking_level (str | None): The assigned reasoning effort level, or None.

    Returns:

    • str: The hexadecimal SHA-256 digest string representing the cache entry.

    Raises:

    None.

    Example:

    def _cache_key(prompt: str, provider: str, model: str, thinking_level: str | None) -> str:
    scope = f"{provider}|{model}|{(thinking_level or 'default').lower()}\n"
    return hashlib.sha256((scope + prompt).encode("utf-8")).hexdigest()

    The function builds a scoping prefix incorporating provider, model, and thinking level parameters followed by a newline, appends the prompt text, encodes the concatenated string to UTF-8, and calculates the SHA-256 digest. This prevents identical prompts run against different models or reasoning budgets from colliding.

    _call_llm_provider()

    Visibility: Private

    Signature: def _call_llm_provider(prompt: str, thinking_level: str | None = None) -> str:

    Description: Dispatches chat completion calls to generic OpenAI-compatible HTTP endpoints (used primarily for local engines such as Ollama). It parses environment configurations, configures HTTP headers, applies reasoning effort parameters, validates HTTP responses, parses usage metrics, and returns the completion content.

    Phase 1: Environment Resolution and Validation

        # Read the provider from environment variable
    provider = get_llm_provider()
    if not provider:
        raise ValueError("LLM_PROVIDER environment variable is required")

    # Construct the names of the other environment variables
    model_var = f"{provider}_MODEL"
    base_url_var = f"{provider}_BASE_URL"
    api_key_var = f"{provider}_API_KEY"

    # Read the provider-specific variables
    model = os.environ.get(model_var)
    base_url = os.environ.get(base_url_var)
    api_key = os.environ.get(api_key_var, "")  # API key is optional, default to empty string

    # Validate required variables
    if not model:
        raise ValueError(f"{model_var} environment variable is required")
    if not base_url:
        raise ValueError(f"{base_url_var} environment variable is required")

    # Append the endpoint to the base URL
    url = f"{base_url.rstrip('/')}/v1/chat/completions"

    The method resolves provider configuration via get_llm_provider(), dynamically references provider-specific environment variables (<PROVIDER>_MODEL, <PROVIDER>_BASE_URL, and <PROVIDER>_API_KEY), validates their existence, and constructs the target /v1/chat/completions endpoint URL.

    Phase 2: Payload Construction and Sampling Adjustment

        # Configure headers and payload based on provider
    headers = {
        "Content-Type": "application/json",
    }
    if api_key:  # Only add Authorization header if API key is provided
        headers["Authorization"] = f"Bearer {api_key}"

    payload = {
        "model": model,
        "messages": [{"role": "user", "content": prompt}],
        "temperature": 0.7,
    }

    if provider == "OLLAMA" and thinking_level:
        # Ollama reasoning models accept low/medium/high; xhigh/max clamp to high.
        # Some Ollama SDKs / API versions look for `think`, others look for standard `reasoning_effort`
        effort = _clamp_level(thinking_level.lower(), ["low", "medium", "high"]) or "medium"
        payload["think"] = effort
        payload["reasoning_effort"] = effort
        payload["temperature"] = 1.0

    if rejects_sampling_params(model):
        # Claude Opus 4.7+ / Opus 5.x / Sonnet 5 / Fable reject sampling parameters (400).
        payload.pop("temperature", None)

    The payload is initialized with the target model, user message, and default temperature (0.7). If the provider is "OLLAMA" and thinking levels are configured, the effort is clamped to valid boundaries (low, medium, high) and assigned to both think and reasoning_effort keys. If the model rejects sampling parameters (evaluated by rejects_sampling_params), the temperature parameter is stripped.

    Phase 3: Request Dispatch and Response Extraction

        try:
        response = requests.post(url, headers=headers, json=payload, timeout=(10, 300))
        response.raise_for_status()  # HTTP status first: an HTML 502 page must not look like a JSON bug
        try:
            response_json = response.json()
        except (ValueError, requests.exceptions.JSONDecodeError):
            from utils.output import emit

            emit(
                "WARN_INVALID_JSON",
                status_code=response.status_code,
                preview=response.text[:200].strip(),
            )
            raise ValueError(f"Provider returned invalid JSON. Status Code: {response.status_code}") from None

        # Defensive check: API may return 200 with error/rate-limit payload missing 'choices'
        if "choices" not in response_json or not response_json["choices"]:
            error_detail = response_json.get("error", response_json)
            from utils.output import emit

            emit("WARN_API_NO_CHOICES", detail=str(error_detail))
            raise RuntimeError(f"API response missing 'choices' key. Response: {error_detail}")
        # ...

    The HTTP POST request is submitted with a connect timeout of 10 seconds and a read timeout of 300 seconds. HTTP errors trigger status verification before JSON decoding to prevent masking gateway errors. The parsed JSON structure is checked for completion choices.

    Phase 4: Usage Recording and Truncation Checks

            # ...
        usage = response_json.get("usage") or {}
        from utils.llm_common import record_usage
        from utils.token_utils import count_tokens_raw, observe_prompt_tokens

        prompt_tokens = usage.get("prompt_tokens") or 0
        record_usage(
            provider,
            model,
            input_tokens=prompt_tokens,
            output_tokens=usage.get("completion_tokens") or 0,
            thinking_tokens=(usage.get("completion_tokens_details") or {}).get("reasoning_tokens") or 0,
            cache_read=(usage.get("prompt_tokens_details") or {}).get("cached_tokens") or 0,
            cost=None,
            measured=bool(usage),
        )
        if usage:
            observe_prompt_tokens(provider, model, count_tokens_raw(prompt), prompt_tokens)
        choice = response_json["choices"][0]
        text = (choice.get("message") or {}).get("content") or ""
        if choice.get("finish_reason") == "length":
            from utils.llm_common import TruncatedResponse

            return TruncatedResponse(text)
        return text
    except requests.exceptions.HTTPError as e:
        error_message = f"HTTP error occurred: {e}"
        try:
            error_details = response.json().get("error", "No additional details")
            error_message += f" (Details: {error_details})"
        except Exception:
            pass
        raise Exception(error_message) from e
    except requests.exceptions.ConnectionError as e:
        raise Exception(f"Failed to connect to {provider} API. Check your network connection.") from e
    except requests.exceptions.Timeout as e:
        raise Exception(f"Request to {provider} API timed out.") from e
    except requests.exceptions.RequestException as e:
        raise Exception(f"An error occurred while making the request to {provider}: {e}") from e
    except ValueError as e:
        raise Exception(f"Failed to parse response as JSON from {provider}. The server might have returned an invalid response.") from e

    Token consumption metrics (prompt, completion, reasoning, and cached tokens) are extracted and recorded in the common ledger via record_usage(). If the completion was terminated due to token length limits (finish_reason == "length"), the response text is returned wrapped in a TruncatedResponse object. Exception handlers catch HTTP errors, connection drops, and timeouts, converting them into standardized exceptions.

    Parameters:

    • prompt (str): The prompt string.
    • thinking_level (str | None, optional): Reasoning effort level. Defaults to None.

    Returns:

    • str: The completion text, or an instance of TruncatedResponse if terminated early.

    Raises:

    • ValueError: Missing environment settings or non-JSON HTTP responses.
    • RuntimeError: Successful HTTP responses that lack the choices attribute.
    • Exception: Network timeouts, connection drops, or HTTP status failures.

    _emit_call_usage()

    Visibility: Private

    Signature: def _emit_call_usage(step: str, estimate: int, usage: dict, measured: int) -> None:

    Description: Formats and emits a single-line console telemetry summary for an LLM call. Calculates percentage deviations between estimated prompt tokens and actual billed input tokens, incorporates output and reasoning metrics, logs cached token counts, and formats overall estimated monetary cost.

    Parameters:

    • step (str): The pipeline step name associated with the execution.
    • estimate (int): The estimated prompt token count calculated prior to network dispatch.
    • usage (dict): The dictionary of usage metrics returned by the ledger delta.
    • measured (int): The count of completed requests that reported valid usage metrics.

    Returns:

    • None

    Raises:

    None.

    Example:

    def _emit_call_usage(step: str, estimate: int, usage: dict, measured: int) -> None:
    """One console line per LLM call: billed input vs the estimate, output (thinking), cached, cost.
    `measured` = requests with provider-reported usage (the deviation is per measured request)."""
    from utils.output import emit, get
    from utils.token_utils import format_cost

    per_request = usage["input"] / measured
    deviation = f"{(per_request - estimate) / estimate:+.0%}" if estimate else get("CFG_VALUE_UNKNOWN")
    emit(
        "LLM_CALL_USAGE",
        step=step,
        input=f"{usage['input']:,}",
        estimate=f"{estimate:,}",
        deviation=deviation,
        requests=get("LLM_CALL_REQUESTS", count=measured) if measured > 1 else "",
        output=f"{usage['output']:,}",
        thinking=f"{usage['thinking']:,}",
        cached=f"{usage['cache_read']:,}",
        cost=format_cost(usage),
    )

    The helper determines input consumption per request, computes the variance against initial estimates, and emits the LLM_CALL_USAGE event with formatted token counts and costs.

    Error Handling

    The module implements defensive error handling across filesystem operations, network transport, response serialization, and provider-specific error states:

    • Filesystem & Cache Resiliency: If llm_cache_v2.json is missing, load_cache() treats it as an empty cache without failing. If corrupted or unreadable, json.JSONDecodeError and OSError exceptions are caught, an alert event is logged, and an empty dictionary is returned. Cache writes are committed to a temporary file (.tmp) before atomic replacement via os.replace to prevent corrupted files if interrupted.
    • Network & Gateway Faults: In _call_llm_provider(), network requests are bounded by timeouts ((10, 300)). Specific exceptions (requests.exceptions.HTTPError, ConnectionError, Timeout, and RequestException) are caught and re-raised as standardized Exception types containing diagnostic details.
    • Malformed Provider Outputs: If an HTTP 200 response contains non-JSON text or HTML (such as error pages from reverse proxies), the JSON parser failure raises a ValueError with a response preview. If the response JSON lacks the expected choices array, a RuntimeError is raised.
    • Truncated Completions: When a provider stops generation early due to token limits (finish_reason == "length"), the completion is wrapped in a TruncatedResponse. These responses are explicitly excluded from disk caching so subsequent pipeline executions retry the query rather than replaying truncated text.
    • Non-Retryable Refusal Memory: When an LLMRefusalError is caught during provider execution, its retryable status is evaluated. If non-retryable, the refusal is recorded in a run-scoped registry (remember_refusal). Subsequent attempts with the same parameters are aborted early via previous_refusal, avoiding redundant billing.
    • Missing Optional Dependencies: Provider delegators (_call_llm_anthropic, _call_llm_gemini) catch ImportError exceptions when external SDKs (anthropic, google-genai) are not installed, providing explicit installation instructions.
