    call_llm.py

    Source: utils/call_llm.py

    Technical Overview

    Following the package-level initialization documented in init.py, which establishes the modular namespace for the utility suite, call_llm.py acts as the primary inference orchestration interface for all pipeline nodes. It decouples the upstream pipeline workflows—such as topological synthesis nodes in nodes.py and state machines in flow.py—from concrete model providers. The module provides a unified execution facade that coordinates request routing, model configuration resolution, prompt token counting, disk-backed caching, refusal interception, and telemetry reporting.

    At its core, call_llm.py implements a persistent two-tier caching mechanism and a refusal memorization pattern. Prompts, provider types, model identifiers, and requested thinking budgets are hashed using SHA-256 to create deterministic cache keys. Responses are cached in-memory and committed to an atomic disk file (llm_cache_v2.json) using a temporary file replacement pattern to prevent corruption during unexpected process termination. The module also integrates refusal interception: when a model issues a non-retryable refusal, the request signature is memorized in-memory, preventing redundant API billing and repetitive HTTP transactions across node retry loops.

    The engine dispatches requests to backend-specific adapter drivers based on the active provider configuration. Dedicated internal handlers wrap official SDK integrations for Google Gemini (llm_gemini.py), Anthropic (llm_anthropic.py), and OpenRouter (llm_openrouter.py). For local deployments or self-hosted reasoning models (such as Ollama or generic OpenAI-compatible reverse proxies), call_llm.py features a native HTTP client implementation using requests. This client dynamically adjusts sampling parameters, handles reasoning effort tokens (think / reasoning_effort), tracks token usage metadata, and identifies length-based output truncations.

    Public API

    call_llm()

    Visibility: Public Signature: def call_llm(prompt: str, use_cache: bool = True, thinking_level: str | None = None) -> str:

    Description: Main orchestrator function for Large Language Model invocations. Resolves active provider settings, computes token metrics, queries the disk-backed cache singleton, evaluates prior model refusals, dispatches prompts to target backend drivers, measures elapsed execution time, and conditionally updates the cache.

    Parameters: * prompt (str): The complete formatted prompt text sent to the downstream model. * use_cache (bool, optional): Flag indicating whether to check existing entries in llm_cache_v2.json and persist new successful responses. Defaults to True. * thinking_level (str | None, optional): Model-agnostic reasoning effort level (e.g., "low", "medium", "high", "max"). Defaults to None.

    Returns: * str: The textual response generated by the provider or loaded from cache. If the response was truncated due to output length limits, an instance of TruncatedResponse (a str subclass) is returned.

    Raises: * LLMRefusalError: When a provider refuses to answer the prompt or triggers safety thresholds. * ValueError: If required environment variables are absent, or invalid JSON is returned. * RuntimeError: If an API response lacks expected choice payloads. * Exception: Propagated from downstream HTTP or provider SDK driver failures.

    Phase 1: Settings Resolution and Prompt Telemetry

        from utils.output import emit, emit_raw
    from utils.token_utils import count_tokens

    provider, model, _, _ = resolve_llm_settings()
    prompt_tokens = count_tokens(prompt)

    emit_raw("DEBUG", f"{'=' * 80}", dest="LOG")
    emit_raw(
        "DEBUG",
        f"LLM CALL START | provider={provider} | model={model} | thinking={thinking_level} | cache={'enabled' if use_cache else 'disabled'} | prompt_tokens={prompt_tokens:,}",
        dest="LOG",
    )
    emit_raw("DEBUG", f"PROMPT:\n{prompt}", dest="LOG")
    This phase reads global configuration parameters by calling resolve_llm_settings() from llm_config.py. It calculates prompt token consumption using count_tokens() from token_utils.py to provide visibility into payload sizing. Diagnostic metadata—including model identifier, provider name, thinking levels, and complete prompt contents—are written directly to logger channels via emit_raw() from output.py.

    Phase 2: Cache Evaluation and Short-Circuiting

        # Check cache if enabled
    key = _cache_key(prompt, provider, model, thinking_level)
    if use_cache:
        cache = load_cache()
        if key in cache:
            cached_response = cache[key]
            emit("CACHE_HIT", chars=f"{len(cached_response):,}")
            emit_raw("DEBUG", f"RESPONSE (cached):\n{cached_response}", dest="LOG")
            emit_raw("DEBUG", "LLM CALL END | result=cache_hit", dest="LOG")
            return cached_response
        emit("CACHE_MISS")
    When caching is enabled, the execution pipeline generates a unique SHA-256 key matching the prompt and runtime scope. It invokes load_cache() to access the global cache map. If a match is found, the system records a CACHE_HIT event, writes debug logs containing character count metrics, and immediately returns the cached output string, bypassing API calls and network overhead.

    Phase 3: Refusal Interception

        # A request the provider already declined this run is declined again: do not re-send it on
    # node retries (rate limits, billed partial output). The node retry still sees the error.
    refusal_key = request_key(provider, model, thinking_level, prompt)
    refused = previous_refusal(refusal_key)
    if refused is not None:
        emit_raw("DEBUG", "LLM CALL END | result=refused_before (not re-sent)", dest="LOG")
        raise refused
    Before initiating remote network calls, call_llm() queries previous_refusal() using a deterministic refusal key generated by request_key() from llm_common.py. If this specific prompt and model combination resulted in a non-retryable refusal earlier in the session, the memorized LLMRefusalError is immediately re-raised. This prevents cascading retries in nodes.py from generating repeated billable errors for permanently declined prompts.

    Phase 4: Dynamic Provider Dispatch and Refusal Recording

        # Make the actual LLM call
    start_time = time.time()
    emit_raw("DEBUG", f"API CALL | sending request to {provider}...", dest="LOG")

    try:
        if provider == "GEMINI":
            response_text = _call_llm_gemini(prompt, thinking_level=thinking_level)
        elif provider == "ANTHROPIC":
            response_text = _call_llm_anthropic(prompt, thinking_level=thinking_level)
        elif provider == "OPENROUTER":
            response_text = _call_llm_openrouter(prompt, thinking_level=thinking_level)
        else:  # generic method using a URL that is OpenAI compatible API (Ollama, ...)
            response_text = _call_llm_provider(prompt, thinking_level=thinking_level)
    except LLMRefusalError as e:
        if not e.retryable:
            remember_refusal(refusal_key, e)
        raise
    The router directs the call to dedicated adapters depending on the provider string: _call_llm_gemini for Google Gemini, _call_llm_anthropic for Anthropic Claude, _call_llm_openrouter for OpenRouter, or fallback to _call_llm_provider for generic OpenAI-compatible HTTP endpoints. The dispatch block captures LLMRefusalError exceptions. If the exception's retryable property is False, it calls remember_refusal() to cache the failure in memory before propagating the exception up the execution stack.

    Phase 5: Cache Persistence and Response Return

        elapsed = time.time() - start_time
    emit_raw("DEBUG", f"API CALL COMPLETE | elapsed={elapsed:.1f}s | response_chars={len(response_text):,}", dest="LOG")
    emit_raw("DEBUG", f"RESPONSE:\n{response_text}", dest="LOG")

    # Update cache if enabled. Empty and truncated responses (llm_common.TruncatedResponse)
    # are never cached — they would be replayed on every later run.
    if use_cache and response_text and not getattr(response_text, "truncated", False):
        cache = load_cache()
        cache[key] = response_text
        save_cache(cache)
        emit_raw("DEBUG", "CACHE WRITE | saved response to cache", dest="LOG")

    emit_raw("DEBUG", f"LLM CALL END | result=success | elapsed={elapsed:.1f}s", dest="LOG")
    return response_text
    Following a successful API invocation, elapsed execution time is calculated and logged alongside character counts. The system determines whether the response can be cached: empty responses and truncated outputs (getattr(response_text, "truncated", False)) are excluded to avoid caching incomplete text. Valid completions are committed to disk via save_cache(), and the final string or TruncatedResponse object is returned to the caller.

    load_cache()

    Visibility: Public Signature: def load_cache() -> dict:

    Description: Accesses and returns the process-wide in-memory cache dictionary singleton. On initial access, it deserializes cache data from llm_cache_v2.json. If the file does not exist or contains invalid JSON data, it emits an alert and falls back to an empty dictionary, ensuring file corruption does not interrupt pipeline runs.

    Parameters: None.

    Returns: * dict: A key-value dictionary mapping SHA-256 prompt-scope hashes to generated text responses.

    Raises: No exceptions are raised; file missing and syntax errors are handled internally and logged.

    Example: 

    # Implementation pattern from utils/call_llm.py
def load_cache():
    global _cache
    if _cache is not None:
        return _cache
    try:
        with open(cache_file, encoding="utf-8") as f:
            _cache = json.load(f)
        from utils.output import emit

        emit("CACHE_LOADED", count=f"{len(_cache):,}", file=cache_file)
    except FileNotFoundError:
        _cache = {}
    except (json.JSONDecodeError, OSError) as e:
        from utils.output import emit, emit_raw

        emit("WARN_CACHE_LOAD_FAIL")
        emit_raw("WARNING", f"Cache load error: {e}", dest="LOG")
        _cache = {}
    return _cache
    load_cache uses the global _cache variable to avoid re-parsing large JSON files on repeated calls. When the cache file is read for the first time, it reports successful loading along with the entry count via emit("CACHE_LOADED", ...). If an OSError or JSONDecodeError occurs, it emits WARN_CACHE_LOAD_FAIL, outputs the error detail to the application log, and initializes _cache as an empty dictionary.

    save_cache()

    Visibility: Public Signature: def save_cache(cache: dict) -> None:

    Description: Persists the updated cache dictionary to disk atomically. Serializes the dictionary to a temporary staging file (llm_cache_v2.json.tmp) before renaming it over the destination target (llm_cache_v2.json). This ensures that process aborts, OS interrupts, or power failures cannot leave behind truncated or corrupt cache files.

    Parameters: * cache (dict): The full cache dictionary to serialize to disk.

    Returns: * None

    Raises: No exceptions are raised; I/O and serialization errors are caught and logged via telemetry utilities.

    Example: 

    # Implementation pattern from utils/call_llm.py
def save_cache(cache):
    global _cache
    _cache = cache
    # Write to a temp file and atomically replace, so an interrupted run never leaves a truncated cache.
    tmp_path = f"{cache_file}.tmp"
    try:
        with open(tmp_path, "w", encoding="utf-8") as f:
            json.dump(cache, f)
        os.replace(tmp_path, cache_file)
    except (OSError, TypeError) as e:
        from utils.output import emit, emit_raw

        emit("WARN_CACHE_SAVE_FAIL")
        emit_raw("WARNING", f"Cache save error: {e}", dest="LOG")
    save_cache updates the in-memory singleton _cache and initiates atomic file replacement. The write target is derived by appending .tmp to cache_file. Once json.dump finishes writing the temporary file, os.replace() provides atomic replacement on POSIX and Windows systems. If writing fails due to disk quotas, file permissions, or serialization type errors, the function catches (OSError, TypeError), logs the failure, and prevents process crashes.

    Internal Helpers

    _cache_key()

    Visibility: Private Signature: def _cache_key(prompt: str, provider: str, model: str, thinking_level: str | None) -> str:

    Description: Generates a deterministic SHA-256 hash identifying a cached completion. Incorporates the provider name, model identifier, normalized thinking budget, and the complete prompt text into the hashing scope.

    Parameters: * prompt (str): The exact input prompt text. * provider (str): The name of the LLM provider (e.g., "GEMINI", "ANTHROPIC"). * model (str): The specific model identifier string. * thinking_level (str | None): The requested reasoning level or None.

    Returns: * str: A 64-character hexadecimal SHA-256 digest string.

    Example: 

    # Implementation from utils/call_llm.py
def _cache_key(prompt: str, provider: str, model: str, thinking_level: str | None) -> str:
    scope = f"{provider}|{model}|{(thinking_level or 'default').lower()}\n"
    return hashlib.sha256((scope + prompt).encode("utf-8")).hexdigest()
    _cache_key standardizes the cache scope by building a prefix formatted as {provider}|{model}|{thinking_level}\n. If thinking_level is absent, it defaults to "default". By concatenating this scope prefix with the raw UTF-8 prompt bytes and running SHA-256 hashing, cache entries are strictly segregated across different models, providers, and reasoning budgets.

    _call_llm_provider()

    Visibility: Private Signature: def _call_llm_provider(prompt: str, thinking_level: str | None = None) -> str:

    Description: Low-level HTTP communication driver for OpenAI-compatible REST endpoints, including local Ollama installations and self-hosted inference servers. It resolves endpoint URLs, sets headers, shapes JSON payloads, tunes reasoning parameters, posts requests via requests, parses token usage, and handles truncated completions.

    Parameters: * prompt (str): The raw prompt to pass in the messages array. * thinking_level (str | None, optional): Desired reasoning effort configuration. Defaults to None.

    Returns: * str: The completion text extracted from choices[0].message.content. If finish_reason == "length", returns an instance of TruncatedResponse.

    Raises: * ValueError: If required environment variables (<provider>_MODEL, <provider>_BASE_URL) are missing, or if the server returns non-JSON payloads. * RuntimeError: If the HTTP 200 response JSON omits the mandatory choices list. * Exception: For connection drops, timeouts, or HTTP status error codes.

    Phase 1: Environment Configuration and Endpoint Resolution

        # Read the provider from environment variable
    provider = get_llm_provider()
    if not provider:
        raise ValueError("LLM_PROVIDER environment variable is required")

    # Construct the names of the other environment variables
    model_var = f"{provider}_MODEL"
    base_url_var = f"{provider}_BASE_URL"
    api_key_var = f"{provider}_API_KEY"

    # Read the provider-specific variables
    model = os.environ.get(model_var)
    base_url = os.environ.get(base_url_var)
    api_key = os.environ.get(api_key_var, "")  # API key is optional, default to empty string

    # Validate required variables
    if not model:
        raise ValueError(f"{model_var} environment variable is required")
    if not base_url:
        raise ValueError(f"{base_url_var} environment variable is required")

    # Append the endpoint to the base URL
    url = f"{base_url.rstrip('/')}/v1/chat/completions"
    This phase retrieves configuration from environment variables based on the active provider prefix. It uses get_llm_provider() from llm_config.py to determine the provider key (e.g., OLLAMA). It verifies that both <provider>_MODEL and <provider>_BASE_URL are defined in the environment, stripping trailing slashes from the base URL and appending the standard /v1/chat/completions endpoint path.

    Phase 2: Payload Construction and Reasoning Adaptation

        # Configure headers and payload based on provider
    headers = {
        "Content-Type": "application/json",
    }
    if api_key:  # Only add Authorization header if API key is provided
        headers["Authorization"] = f"Bearer {api_key}"

    payload = {
        "model": model,
        "messages": [{"role": "user", "content": prompt}],
        "temperature": 0.7,
    }

    if provider == "OLLAMA" and thinking_level:
        # Ollama reasoning models accept low/medium/high; xhigh/max clamp to high.
        # Some Ollama SDKs / API versions look for `think`, others look for standard `reasoning_effort`
        effort = _clamp_level(thinking_level.lower(), ["low", "medium", "high"]) or "medium"
        payload["think"] = effort
        payload["reasoning_effort"] = effort
        payload["temperature"] = 1.0

    if rejects_sampling_params(model):
        # Claude Opus 4.7+ / Opus 5.x / Sonnet 5 / Fable reject sampling parameters (400).
        payload.pop("temperature", None)
    The request headers and payload are prepared for transmission. If an API key is available, an Authorization: Bearer <key> header is attached. For Ollama reasoning models, the requested thinking level is clamped to allowed values (low, medium, high) using _clamp_level from thinking.py, and populated into both think and reasoning_effort fields while resetting temperature to 1.0. If rejects_sampling_params(model) evaluates to true (e.g., newer Claude models), the temperature parameter is stripped entirely to prevent 400 Bad Request errors.

    Phase 3: HTTP Transmission and Error Interception

        try:
        response = requests.post(url, headers=headers, json=payload, timeout=(10, 300))
        response.raise_for_status()  # HTTP status first: an HTML 502 page must not look like a JSON bug
        try:
            response_json = response.json()
        except (ValueError, requests.exceptions.JSONDecodeError):
            from utils.output import emit

            emit(
                "WARN_INVALID_JSON",
                status_code=response.status_code,
                preview=response.text[:200].strip(),
            )
            raise ValueError(f"Provider returned invalid JSON. Status Code: {response.status_code}") from None
        # ...
    except requests.exceptions.HTTPError as e:
        error_message = f"HTTP error occurred: {e}"
        try:
            error_details = response.json().get("error", "No additional details")
            error_message += f" (Details: {error_details})"
        except Exception:
            pass
        raise Exception(error_message) from e
    except requests.exceptions.ConnectionError as e:
        raise Exception(f"Failed to connect to {provider} API. Check your network connection.") from e
    except requests.exceptions.Timeout as e:
        raise Exception(f"Request to {provider} API timed out.") from e
    except requests.exceptions.RequestException as e:
        raise Exception(f"An error occurred while making the request to {provider}: {e}") from e
    except ValueError as e:
        raise Exception(f"Failed to parse response as JSON from {provider}. The server might have returned an invalid response.") from e
    The HTTP payload is dispatched using requests.post with a connect timeout of 10 seconds and a read timeout of 300 seconds. Status codes are checked using response.raise_for_status(). The parser verifies that the returned body is valid JSON; if parsing fails (for example, receiving an HTML error page from a proxy), a WARN_INVALID_JSON warning is logged and a clean ValueError is raised. Dedicated exception blocks wrap transport errors (ConnectionError, Timeout, HTTPError) into actionable exceptions that include server error payloads where available.

    Phase 4: JSON Parsing, Usage Accounting, and Truncation Handling

            # Defensive check: API may return 200 with error/rate-limit payload missing 'choices'
        if "choices" not in response_json or not response_json["choices"]:
            error_detail = response_json.get("error", response_json)
            from utils.output import emit

            emit("WARN_API_NO_CHOICES", detail=str(error_detail))
            raise RuntimeError(f"API response missing 'choices' key. Response: {error_detail}")

        usage = response_json.get("usage") or {}
        from utils.llm_common import record_usage

        record_usage(provider, model, input_tokens=usage.get("prompt_tokens") or 0, output_tokens=usage.get("completion_tokens") or 0, cost=None)
        choice = response_json["choices"][0]
        text = (choice.get("message") or {}).get("content") or ""
        if choice.get("finish_reason") == "length":
            from utils.llm_common import TruncatedResponse

            return TruncatedResponse(text)
        return text
    This phase handles the parsed JSON structure. It ensures the response contains a non-empty choices list; if missing, it logs WARN_API_NO_CHOICES and raises a RuntimeError. Token usage metrics (prompt_tokens, completion_tokens) are recorded globally via record_usage() from llm_common.py. Finally, it inspects finish_reason: if execution stopped due to length limits (finish_reason == "length"), the generated string is returned wrapped in a TruncatedResponse instance, signaling upstream callers that output generation was truncated.

    _call_llm_openrouter()

    Visibility: Private Signature: def _call_llm_openrouter(prompt: str, thinking_level: str | None = None) -> str:

    Description: Dispatches inference requests to OpenRouter's unified endpoint by delegating directly to call_openrouter() in llm_openrouter.py.

    Parameters: * prompt (str): Input text prompt. * thinking_level (str | None, optional): Reasoning configuration passed to the OpenRouter adapter. Defaults to None.

    Returns: * str: Model completion output text.

    Example: 

    # Implementation from utils/call_llm.py
def _call_llm_openrouter(prompt: str, thinking_level: str | None = None) -> str:

    Error Handling

    call_llm.py uses specific error handling strategies across multiple layers, including network calls, JSON deserialization, model refusals, and disk I/O:

    • Model Refusal Caching & Short-Circuiting: When a provider rejects a prompt (e.g., safety violations or content policy triggers), downstream adapters raise an LLMRefusalError (defined in llm_common.py). call_llm() intercepts this exception: 

      except LLMRefusalError as e:
    if not e.retryable:
        remember_refusal(refusal_key, e)
    raise
      If e.retryable is false, remember_refusal() records the refusal key in memory. On subsequent retries within the same process run, previous_refusal(refusal_key) catches the failure and re-raises the error before any network request is sent.

    • Cache Read/Write Resilience: In load_cache(), missing cache files (FileNotFoundError) are handled by initializing a clean dictionary without logging warnings. Syntax or OS read errors (json.JSONDecodeError, OSError) emit WARN_CACHE_LOAD_FAIL warnings and fall back to an empty dictionary, ensuring cache corruption does not crash the application. In save_cache(), file writes target .tmp files first, and any OSError or TypeError triggers a WARN_CACHE_SAVE_FAIL event rather than terminating execution.

    • Truncated Response Caching Exclusion: Incomplete responses caused by model token limits are wrapped in TruncatedResponse instances. In call_llm(), responses with getattr(response_text, "truncated", False) == True or empty bodies are explicitly excluded from cache writes. This ensures truncated output is not saved to disk and replayed on subsequent runs.

    • HTTP Transport and Response Validation: In _call_llm_provider(), network requests are guarded against transport and protocol errors. Non-200 HTTP responses raise requests.exceptions.HTTPError via raise_for_status(), capturing upstream API error details where available. Malformed JSON payloads trigger WARN_INVALID_JSON and raise clean ValueError exceptions. Missing choices arrays in 200 OK responses (e.g., provider-level rate-limit envelopes) emit WARN_API_NO_CHOICES and raise explicit RuntimeError instances.
