    call_llm.py

    Source: utils/call_llm.py

    Technical Overview

    utils/call_llm.py serves as the centralized LLM dispatch gateway and persistent caching layer for the Codebase-Knowledge-Builder pipeline. It abstracts multi-provider API interactions behind a unified function interface (call_llm), allowing the indexing and documentation pipelines to query models across Anthropic, Google Gemini, OpenRouter, and generic OpenAI-compatible REST endpoints (such as local Ollama instances) without coupling calling nodes to vendor-specific SDK semantics. The module manages environment initialization, authentication resolution, request routing, usage ledger tracking, and output validation across all LLM operations.

    A core responsibility of this module is local response caching via an in-memory singleton backed by an on-disk JSON document (llm_cache_v2.json). Cache entries are keyed by a SHA-256 digest computed across the active provider, model name, normalized reasoning/thinking effort level, and prompt content. This scoped hashing prevents collisions across models and parameter configurations while removing raw prompt text from disk storage. Disk synchronization employs an atomic write-and-replace strategy using a .tmp file swap to prevent corruption during interrupted runs. Furthermore, caching guards prevent saving empty responses or truncated text resulting from output token limits (TruncatedResponse), ensuring that incomplete generations are never permanently recorded.

    The module also implements execution telemetry and defensive request handling. Before dispatching remote requests, it interrogates an execution-wide ledger to detect prior unrecoverable errors (LLMRefusalError); previously refused requests are aborted immediately to prevent redundant quota consumption during node-level retry loops. During live calls, the module tracks execution duration, token estimation, prompt token alignment, thinking/reasoning token breakdowns, and ledger deltas. Real-time usage and financial estimates are emitted to diagnostic and console outputs per pipeline execution step.

    def load_cache():

    if _cache is not None:
        return _cache

    save_cache()

    Visibility: Public
    Signature: def save_cache(cache):

    Description: Persists the provided cache dictionary to disk atomically. It updates the internal global _cache reference, serializes the JSON structure into an adjacent temporary file (llm_cache_v2.json.tmp), and executes an atomic replacement via os.replace. This atomic file swap ensures that interrupting the process mid-write does not leave a truncated or corrupted cache file on disk.

    Parameters: * cache (dict): The full cache dictionary mapping cache keys to LLM response strings.

    Returns: * None

    Raises: * No exceptions are raised directly; OSError and TypeError exceptions are caught, triggering diagnostic warnings through utils.output.emit.

    Example: 

    cache = load_cache()
cache[key] = response_text
save_cache(cache)


    def save_cache(cache):
    global _cache
    _cache = cache
    # Write to a temp file and atomically replace, so an interrupted run never leaves a truncated cache.
    tmp_path = f"{cache_file}.tmp"
    try:
        with open(tmp_path, "w", encoding="utf-8") as f:
            json.dump(cache, f)
        os.replace(tmp_path, cache_file)
    except (OSError, TypeError) as e:
        from utils.output import emit, emit_raw

        emit("WARN_CACHE_SAVE_FAIL")
        emit_raw("WARNING", f"Cache save error: {e}", dest="LOG")

    The function assigns cache to the global _cache pointer and writes the serialized dictionary into tmp_path. Upon successful file closure, os.replace atomically updates cache_file. If an I/O failure or serialization error occurs during this process, the failure is caught, and WARN_CACHE_SAVE_FAIL is emitted to prevent terminating active pipeline execution.

    except OSError:
        return

    call_llm()

    Visibility: Public
    Signature: def call_llm(prompt: str, use_cache: bool = True, thinking_level: str | None = None, step: str | None = None) -> str:

    Description: Dispatches a single prompt string to the currently configured LLM provider, providing persistent disk caching, token tracking, retry-refusal detection, and provider routing. The function serves as the central API entry point for all generation tasks in the system.

    Parameters: * prompt (str): The raw text prompt to transmit to the language model. * use_cache (bool, optional): Flag indicating whether to query and write to the local cache. Defaults to True. * thinking_level (str | None, optional): Desired reasoning effort or budget (e.g., 'low', 'medium', 'high'). Defaults to None. * step (str | None, optional): Pipeline execution step identifier corresponding to NODE_KEYS in utils/thinking.py for telemetry attribution. Defaults to None (mapped internally to 'other').

    Returns: * str: The completion text generated by the model or retrieved from cache. If truncated, an instance of TruncatedResponse (a str subclass) is returned.

    Raises: * LLMRefusalError: If the provider rejects the request with an unrecoverable refusal or if the request was previously refused during the same run. * ValueError: If required environment variables are missing or provider configurations are invalid. * RuntimeError: If an API response payload lacks expected completion structures. * ImportError: If provider-specific client libraries (anthropic, google-genai) are missing. * Exception: If communication with the remote provider encounters fatal HTTP, timeout, or transport errors.

    Example:

response = call_llm(
    prompt="Explain the architecture of this project.",
    use_cache=True,
    thinking_level="high",
    step="draft_chapters",
)

        returned = True
    except LLMRefusalError as e:

            remember_refusal(refusal_key, e)
        raise

    The function captures a timestamp and takes a snapshot of the provider's token consumption ledger via usage_snapshot. It wraps provider execution within a usage_step context manager to attribute usage accurately. Based on the resolved provider string ("GEMINI", "ANTHROPIC", "OPENROUTER", or generic fallback), it routes the call to the corresponding specialized helper. If an LLMRefusalError is raised and marked as non-retryable, the exception is stored in memory via remember_refusal before being re-raised.

It computes call_usage by comparing ledger snapshots taken before and after execution via usage_delta. If measured calls exist, it attributes input estimates and calls _emit_call_usage to print console statistics.     The final phase evaluates whether the result qualifies for caching. Empty strings and responses tagged with truncated=True (indicating that the model ran out of output tokens before completing) are excluded from the cache to prevent persisting partial generations. Valid responses are added to the cache dictionary and persisted to disk via save_cache.

    Internal Helpers

    _cache

    Visibility: Private
    Signature: _cache = None

    Description: Internal module-level cache singleton holding the in-memory representation of llm_cache_v2.json. Initialized to None, it is loaded lazily on the first invocation of load_cache or call_llm.

    _cache_key()

    Visibility: Private
    Signature: def _cache_key(prompt: str, provider: str, model: str, thinking_level: str | None) -> str:

    Description: Constructs a deterministic SHA-256 hexadecimal digest that uniquely identifies a generation request. The digest scopes the prompt to its operational configuration: provider, model name, and lowercased reasoning level (defaulting to "default" if None). Scoping prevents cache collisions when switching between models, providers, or reasoning levels.

    Parameters: * prompt (str): The raw prompt string. * provider (str): Name of the active LLM provider (e.g., 'GEMINI', 'ANTHROPIC', 'OLLAMA'). * model (str): Specific model identifier (e.g., 'claude-sonnet-5'). * thinking_level (str | None): Desired reasoning effort level.

    Returns: * str: A 64-character hexadecimal SHA-256 string.

    Raises: * No exceptions are raised directly.

    Example: 

    key = _cache_key(prompt, provider, model, thinking_level)


    def _cache_key(prompt: str, provider: str, model: str, thinking_level: str | None) -> str:
    scope = f"{provider}|{model}|{(thinking_level or 'default').lower()}\n"
    return hashlib.sha256((scope + prompt).encode("utf-8")).hexdigest()

    The helper formats the prefix scope string by joining the provider name, model identifier, and normalized thinking level, delimited by pipe characters and terminated with a newline. It appends the raw prompt text, encodes the concatenated string to UTF-8, and computes the SHA-256 digest via Python's standard hashlib library.

            observe_prompt_tokens(provider, model, count_tokens_raw(prompt), prompt_tokens)
        choice = response_json["choices"][0]
        text = (choice.get("message") or {}).get("content") or ""
        if choice.get("finish_reason") == "length":
            from utils.llm_common import TruncatedResponse

            return TruncatedResponse(text)
        return text

    The function validates that choices is present and non-empty in the returned JSON, guarding against HTTP 200 responses that carry embedded rate-limit or quota error bodies. It extracts token usage details (prompt tokens, completion tokens, reasoning tokens, and cache hits) and logs them to the ledger using record_usage and observe_prompt_tokens. It extracts the generated message content from choices[0]. If finish_reason is "length", the text is wrapped in a TruncatedResponse object so callers can detect output exhaustion.

    def _emit_call_usage(step: str, estimate: int, usage: dict, measured: int) -> None:
    """One console line per LLM call: billed input vs the estimate, output (thinking), cached, cost.
    `measured` = requests with provider-reported usage (the deviation is per measured request)."""
    from utils.output import emit, get
    from utils.token_utils import format_cost

    per_request = usage["input"] / measured
    deviation = f"{(per_request - estimate) / estimate:+.0%}" if estimate else get("CFG_VALUE_UNKNOWN")
    emit(
        "LLM_CALL_USAGE",
        step=step,
        input=f"{usage['input']:,}",
        estimate=f"{estimate:,}",
        deviation=deviation,
        requests=get("LLM_CALL_REQUESTS", count=measured) if measured > 1 else "",
        output=f"{usage['output']:,}",
        thinking=f"{usage['thinking']:,}",
        cached=f"{usage['cache_read']:,}",
        cost=format_cost(usage),
    )

    The helper calculates average per-request input tokens by dividing usage["input"] by measured. It calculates percentage deviation between estimated prompt tokens and billed input tokens. Finally, it triggers an LLM_CALL_USAGE event via utils.output.emit, formatting integer values with comma separators and appending formatted financial metrics calculated by format_cost.

    Error Handling

    utils/call_llm.py enforces structured defensive programming patterns to handle network volatility, provider rate limits, model refusals, and local cache I/O errors:

    • Non-Retryable Refusal Suppression: When a provider rejects an operation due to policy, context overflows, or unsupported parameters, an LLMRefusalError is raised. If e.retryable is False, the error is recorded via remember_refusal using a request hash. Subsequent retries during the same run fail immediately at Phase 2 of call_llm, preventing repeated remote calls.
    • Network & HTTP Error Normalization: In _call_llm_provider, raw requests.exceptions (HTTPError, ConnectionError, Timeout, RequestException) are caught and wrapped in informative Exception instances. Before parsing JSON payloads, response.raise_for_status() is called to intercept HTML error pages (e.g., 502/504 gateway timeouts) and prevent misleading JSON decoding errors.
    • Defensive JSON Payload Validation: Generic endpoints returning HTTP 200 may still include error bodies or omit completion results. If the deserialized JSON lacks the choices attribute or contains an empty choice list, the module emits a WARN_API_NO_CHOICES warning and raises a RuntimeError.
    • Atomic Cache Persistence: Cache writes in save_cache are performed via an intermediary .tmp file and replaced using os.replace. If a serialization or filesystem error (OSError, TypeError) occurs, a WARN_CACHE_SAVE_FAIL event is emitted without interrupting execution.
    • Truncation Protection: Responses marked with finish_reason == "length" return as TruncatedResponse instances. The caching logic inspects getattr(response_text, "truncated", False) and skips writing them to disk, preventing permanent caching of incomplete code or chapter drafts.
