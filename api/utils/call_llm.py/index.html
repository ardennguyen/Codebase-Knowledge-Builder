    call_llm.py

    Source: utils/call_llm.py

    Technical Overview

    The call_llm.py module serves as the primary inference gateway for the Codebase-Knowledge-Builder framework. It abstracts multi-provider Large Language Model (LLM) communications behind a unified interface, decoupling pipeline execution stages from underlying inference protocol details. The module supports direct integrations with Google Gemini (via both Google GenAI Client and Vertex AI) as well as OpenAI-compatible REST endpoints, specifically accommodating providers such as OpenRouter and local Ollama instances.

    In addition to standard request routing, the module encapsulates caching and reasoning effort orchestration. Prompt-response cycles are optionally memoized to a persistent JSON-backed cache file (llm_cache.json), supported by an in-memory singleton that prevents redundant filesystem reads across multiple pipeline tasks. When reasoning-capable models are targeted, call_llm.py parses and translates thinking effort levels (low, medium, high) into provider-native configuration constructs, including Gemini thinking token budgets and OpenRouter/Ollama reasoning parameter payloads.

    Public API

    call_llm()

    Visibility: Public
    Signature: def call_llm(prompt: str, use_cache: bool = True, thinking_level: str | None = None) -> str:

    Description:
    Executes an inference call using the resolved active provider, providing token auditing, timing metrics, and optional persistent caching. Under the hood, this function manages four distinct logical phases: inspecting execution parameters, querying the in-memory/disk cache, dynamically routing execution to either the native Gemini client or the OpenAI-compatible HTTP wrapper, and committing newly generated responses back to the cache store.

    Phase 1: Token Profiling and Execution Logging

        from utils.output import emit, emit_raw
    from utils.token_utils import count_tokens

    provider = get_llm_provider()
    model = os.environ.get(f"{provider}_MODEL", os.environ.get("GEMINI_MODEL", "unknown"))
    prompt_tokens = count_tokens(prompt)

    emit_raw("DEBUG", f"{'=' * 80}", dest="LOG")
    emit_raw(
        "DEBUG",
        f"LLM CALL START | provider={provider} | model={model} | thinking={thinking_level} | cache={'enabled' if use_cache else 'disabled'} | prompt_tokens={prompt_tokens:,}",
        dest="LOG",
    )
    emit_raw("DEBUG", f"PROMPT:\n{prompt}", dest="LOG")
    This phase identifies the target provider using get_llm_provider() imported from utils/llm_config.py and extracts the active model identifier from the corresponding environment variable. The raw prompt token consumption is calculated using count_tokens() from utils/token_utils.py. Detailed operational metadata—including model name, reasoning mode, cache settings, and full prompt contents—is emitted to the log destination using emit_raw() from utils/output.py.

    Phase 2: Cache Evaluation and Hit Return

        # Check cache if enabled
    if use_cache:
        cache = load_cache()
        if prompt in cache:
            cached_response = cache[prompt]
            emit("CACHE_HIT", chars=f"{len(cached_response):,}")
            emit_raw("DEBUG", f"RESPONSE (cached):\n{cached_response}", dest="LOG")
            emit_raw("DEBUG", "LLM CALL END | result=cache_hit", dest="LOG")
            return cached_response
        emit("CACHE_MISS")
    When caching is enabled, the function calls load_cache() to obtain the cache dictionary. If an exact match for the raw prompt string exists within the cache keys, the function short-circuits execution immediately. It emits a CACHE_HIT event indicating character count, logs the complete cached text, and returns the response without dispatching any network operations. If the prompt does not exist in the store, a CACHE_MISS notification is emitted.

    Phase 3: Execution Dispatch and Latency Tracking

        # Make the actual LLM call
    start_time = time.time()
    emit_raw("DEBUG", f"API CALL | sending request to {provider}...", dest="LOG")

    if provider == "GEMINI":
        response_text = _call_llm_gemini(prompt, thinking_level=thinking_level)
    else:  # generic method using a URL that is OpenAI compatible API (Ollama, ...)
        response_text = _call_llm_provider(prompt, thinking_level=thinking_level)

    elapsed = time.time() - start_time
    emit_raw("DEBUG", f"API CALL COMPLETE | elapsed={elapsed:.1f}s | response_chars={len(response_text):,}", dest="LOG")
    emit_raw("DEBUG", f"RESPONSE:\n{response_text}", dest="LOG")
    If execution proceeds past cache lookup, high-precision timing begins via time.time(). Depending on the provider resolved from the environment, execution branches to _call_llm_gemini() for Google's native SDK or _call_llm_provider() for OpenAI-compatible HTTP providers like OpenRouter and Ollama. Upon completion, total elapsed wall-clock time and response string lengths are calculated and logged alongside the raw output.

    Phase 4: Cache Update and Return

        # Update cache if enabled
    if use_cache:
        cache = load_cache()
        cache[prompt] = response_text
        save_cache(cache)
        emit_raw("DEBUG", "CACHE WRITE | saved response to cache", dest="LOG")

    emit_raw("DEBUG", f"LLM CALL END | result=success | elapsed={elapsed:.1f}s", dest="LOG")
    return response_text
    Following a successful API call, if use_cache is set to True, the returned text is associated with the original prompt in the cache dictionary. The modified structure is written to disk via save_cache(), persisting the state across subsequent process runs. Finally, an operational completion event is logged, and the generated text is returned to the caller.

    Parameters: * prompt (str): The complete input prompt text submitted for inference. * use_cache (bool): Flag determining whether to query and write to the local memoization cache (llm_cache.json). Defaults to True. * thinking_level (str | None): Optional reasoning depth identifier ("low", "medium", "high"). Defaults to None.

    Returns: * str: The textual response generated by the resolved model.

    Raises: * ValueError: If required environment variables are absent, if the provider returns invalid JSON, or if the response lacks valid output structures. * Exception: Wrapped connection errors, timeouts, or HTTP failures returned during network communication.

    Example: 

    if __name__ == "__main__":
    from utils.output import emit

    test_prompt = "Hello, how are you?"

    emit("SELFTEST_LLM_CALL")
    response1 = call_llm(test_prompt, use_cache=False)
    emit("SELFTEST_LLM_RESPONSE", response=response1)

    load_cache()

    Visibility: Public
    Signature: def load_cache() -> dict:

    Description:
    Retrieves the memoization dictionary from the module-level singleton variable _cache, populating it from disk on initial invocation. By caching the parsed dictionary in memory, subsequent invocations avoid reparsing potentially massive JSON files on every inference step. If the cache file does not exist, contains corrupted JSON, or cannot be accessed due to OS permissions, the error is logged and an empty dictionary is initialized.

    def load_cache():
    global _cache
    if _cache is not None:
        return _cache
    try:
        with open(cache_file) as f:
            _cache = json.load(f)
        from utils.output import emit

        emit("CACHE_LOADED", count=f"{len(_cache):,}", file=cache_file)
    except (FileNotFoundError, json.JSONDecodeError, OSError) as e:
        from utils.output import emit, emit_raw

        emit("WARN_CACHE_LOAD_FAIL")
        emit_raw("WARNING", f"Cache load error: {e}", dest="LOG")
        _cache = {}
    return _cache
    The implementation uses a global reference _cache to store the loaded dictionary. If _cache already holds an object, it is returned immediately without filesystem I/O. If not yet initialized, it reads from cache_file (llm_cache.json) and parses it using json.load. On success, it emits CACHE_LOADED with the count of cached items. If disk reading encounters FileNotFoundError, json.JSONDecodeError, or OSError, it falls back to an empty dictionary {} while notifying through emit() and emit_raw().

    Parameters:
    None.

    Returns: * dict: In-memory dictionary containing prompt-to-response key-value mappings.

    Raises:
    None directly. Filesystem and parsing exceptions are intercepted and handled with fallbacks.

    Example: 

    # Extracted from call_llm() implementation
if use_cache:
    cache = load_cache()
    if prompt in cache:
        cached_response = cache[prompt]

    save_cache()

    Visibility: Public
    Signature: def save_cache(cache: dict) -> None:

    Description:
    Persists the current in-memory cache dictionary to disk at the path defined by cache_file (llm_cache.json), while updating the internal singleton pointer. Serializes the entire dictionary structure into JSON format. If disk writing fails due to permission restrictions, missing storage mounts, or un-serializable objects, the function traps the exception and emits diagnostic warnings without interrupting pipeline flow.

    def save_cache(cache):
    global _cache
    _cache = cache
    try:
        with open(cache_file, "w") as f:
            json.dump(cache, f)
    except (OSError, TypeError) as e:
        from utils.output import emit, emit_raw

        emit("WARN_CACHE_SAVE_FAIL")
        emit_raw("WARNING", f"Cache save error: {e}", dest="LOG")
    The function takes the modified cache mapping, reassigns the module-level _cache reference, and opens cache_file for writing. It uses json.dump() to serialize the dictionary to disk. Any OSError (e.g., read-only filesystem, disk full) or TypeError (e.g., unhashable or non-serializable payload) is caught to prevent unhandled exceptions from terminating long-running pipeline batches. Failures trigger emission of WARN_CACHE_SAVE_FAIL alongside raw log traces.

    Parameters: * cache (dict): The dictionary of prompts and responses to be persisted.

    Returns: * None

    Raises:
    None directly. Traps OSError and TypeError.

    Example: 

    # Extracted from call_llm() implementation
if use_cache:
    cache = load_cache()
    cache[prompt] = response_text
    save_cache(cache)
    emit_raw("DEBUG", "CACHE WRITE | saved response to cache", dest="LOG")

    Internal Helpers

    _call_llm_provider()

    Visibility: Private
    Signature: def _call_llm_provider(prompt: str, thinking_level: str | None = None) -> str:

    Description:
    Constructs and dispatches standard HTTP requests targeting OpenAI-compatible completions endpoints (such as OpenRouter or Ollama). It parses provider-specific environment variables, injects reasoning configurations, posts JSON payloads with defensive timeouts, and validates response schema structures.

    Phase 1: Environment Configuration and Validation

        # Read the provider from environment variable
    provider = os.environ.get("LLM_PROVIDER")
    if not provider:
        raise ValueError("LLM_PROVIDER environment variable is required")

    # Construct the names of the other environment variables
    model_var = f"{provider}_MODEL"
    base_url_var = f"{provider}_BASE_URL"
    api_key_var = f"{provider}_API_KEY"

    # Read the provider-specific variables
    model = os.environ.get(model_var)
    base_url = os.environ.get(base_url_var)
    api_key = os.environ.get(api_key_var, "")  # API key is optional, default to empty string

    # Validate required variables
    if not model:
        raise ValueError(f"{model_var} environment variable is required")
    if not base_url:
        raise ValueError(f"{base_url_var} environment variable is required")

    # Append the endpoint to the base URL
    url = f"{base_url.rstrip('/')}/v1/chat/completions"
    This phase retrieves the provider designation from LLM_PROVIDER and constructs dynamic variable keys for model, base URL, and API key. It strictly validates that both the model identifier and base URL are present, raising a ValueError if either is missing. It formats the target endpoint by stripping trailing slashes from the base URL and appending /v1/chat/completions.

    Phase 2: Reasoning and Payload Construction

        # Configure headers and payload based on provider
    headers = {
        "Content-Type": "application/json",
    }
    if api_key:  # Only add Authorization header if API key is provided
        headers["Authorization"] = f"Bearer {api_key}"

    payload = {
        "model": model,
        "messages": [{"role": "user", "content": prompt}],
        "temperature": 0.7,
    }

    if provider == "OPENROUTER" and thinking_level:
        model_info = _get_openrouter_model_info(model)
        if model_info and "reasoning" in model_info:
            supported_efforts = model_info["reasoning"].get("supported_efforts", [])
            if thinking_level.lower() in supported_efforts:
                payload["reasoning"] = {"effort": thinking_level.lower()}
                payload["temperature"] = 1.0  # Required for many reasoning models
            else:
                from utils.output import emit

                emit("WARN_THINKING_LEVEL_INVALID", level=thinking_level, model=model, supported=str(supported_efforts))
        else:
            from utils.output import emit

            emit("WARN_THINKING_NOT_SUPPORTED", model=model)

    elif provider == "OLLAMA" and thinking_level:
        # Some Ollama SDKs / API versions look for `think`, others look for standard `reasoning_effort`
        payload["think"] = thinking_level.lower()
        payload["reasoning_effort"] = thinking_level.lower()
        payload["temperature"] = 1.0
    This phase builds the standard JSON payload and HTTP headers. If an API key is available, an Authorization: Bearer <token> header is added. When thinking_level is requested for OpenRouter, the helper queries _get_openrouter_model_info() from utils/llm_config.py to verify whether the model advertises reasoning effort support, setting payload["reasoning"] = {"effort": ...} and raising temperature to 1.0 when verified. For Ollama, both think and reasoning_effort payload fields are populated to ensure compatibility across disparate Ollama runtime releases.

    Phase 3: HTTP Request Execution and Response Validation

        try:
        response = requests.post(url, headers=headers, json=payload, timeout=(10, 300))
        try:
            response_json = response.json()  # Log the response
        except (ValueError, requests.exceptions.JSONDecodeError):
            from utils.output import emit

            emit(
                "WARN_INVALID_JSON",
                status_code=response.status_code,
                preview=response.text[:200].strip(),
            )
            raise ValueError(f"Provider returned invalid JSON. Status Code: {response.status_code}") from None
        response.raise_for_status()

        # Defensive check: API may return 200 with error/rate-limit payload missing 'choices'
        if "choices" not in response_json or not response_json["choices"]:
            error_detail = response_json.get("error", response_json)
            from utils.output import emit

            emit("WARN_API_NO_CHOICES", detail=str(error_detail))
            raise ValueError(f"API response missing 'choices' key. Response: {error_detail}")

        return response_json["choices"][0]["message"]["content"]
    The HTTP request is executed via requests.post() with a connect timeout of 10 seconds and read timeout of 300 seconds. The returned body is parsed into JSON, raising a detailed ValueError if the content fails JSON decoding. The helper invokes response.raise_for_status() to flag 4xx and 5xx HTTP codes. Crucially, a defensive check is performed to catch rate limits or provider-level errors that return HTTP 200 without a choices array, extracting and raising the nested error before accessing response_json["choices"][0]["message"]["content"].

    Phase 4: Network and Protocol Exception Translation

        except requests.exceptions.HTTPError as e:
        error_message = f"HTTP error occurred: {e}"
        try:
            error_details = response.json().get("error", "No additional details")
            error_message += f" (Details: {error_details})"
        except Exception:
            pass
        raise Exception(error_message) from e
    except requests.exceptions.ConnectionError as e:
        raise Exception(f"Failed to connect to {provider} API. Check your network connection.") from e
    except requests.exceptions.Timeout as e:
        raise Exception(f"Request to {provider} API timed out.") from e
    except requests.exceptions.RequestException as e:
        raise Exception(f"An error occurred while making the request to {provider}: {e}") from e
    except ValueError as e:
        raise Exception(f"Failed to parse response as JSON from {provider}. The server might have returned an invalid response.") from e
    Any lower-level exceptions occurring within the communication lifecycle are intercepted and transformed into descriptive pipeline-level exceptions. HTTP errors attempt to extract and append structured error payloads from the server response. Explicit handlers distinguish between socket connection failures, request timeouts, general request exceptions, and payload parsing errors, ensuring root causes are contextualized with the provider's identity.

    Parameters: * prompt (str): Raw prompt string sent to the chat completions API. * thinking_level (str | None): Optional reasoning effort configuration string.

    Returns: * str: Text content generated in message.content within the first completion choice.

    Raises: * ValueError: If required environment variables are unset or response JSON lacks expected keys. * Exception: Normalized exception wrapping underlying requests errors.

    Example: 

    # Real usage extracted from call_llm()
if provider == "GEMINI":
    response_text = _call_llm_gemini(prompt, thinking_level=thinking_level)
else:  # generic method using a URL that is OpenAI compatible API (Ollama, ...)
    response_text = _call_llm_provider(prompt, thinking_level=thinking_level)

    _call_llm_gemini()

    Visibility: Private
    Signature: def _call_llm_gemini(prompt: str, thinking_level: str | None = None) -> str:

    Description:
    Executes inference against Google Gemini models using the modern google.genai SDK. Discovers credentials dynamically to support both Vertex AI enterprise environments and Google AI Studio API key access, configures reasoning budgets, and strips non-text artifacts from multi-part response structures.

    Phase 1: Authentication and Client Initialization

        if os.getenv("GEMINI_PROJECT_ID"):
        client = genai.Client(vertexai=True, project=os.getenv("GEMINI_PROJECT_ID"), location=os.getenv("GEMINI_LOCATION", "us-central1"))
    elif os.getenv("GEMINI_API_KEY"):
        client = genai.Client(api_key=os.getenv("GEMINI_API_KEY"))
    else:
        raise ValueError("Either GEMINI_PROJECT_ID or GEMINI_API_KEY must be set in the environment")
    model = os.getenv("GEMINI_MODEL", "gemini-3.7-flash")

    kwargs = {"model": model, "contents": [prompt]}
    This phase handles authentication resolution. If GEMINI_PROJECT_ID is present, the SDK client is initialized in Vertex AI mode with region fallback to us-central1. Otherwise, if GEMINI_API_KEY is present, standard API key authentication is selected. If neither is available, a ValueError is raised. The target model defaults to gemini-3.7-flash if GEMINI_MODEL is omitted, and the parameter dictionary kwargs is constructed.

    Phase 2: Thinking Budget and Generation Configuration

        if thinking_level:
        # Map string levels to budgets for the installed SDK version
        budget_map = {"low": 1024, "medium": 4096, "high": 8192}
        budget = budget_map.get(thinking_level.lower(), 4096)
        from utils.output import emit_raw

        emit_raw("DEBUG", f"Gemini thinking config | budget={budget}", dest="LOG")
        thinking_config = types.ThinkingConfig(include_thoughts=True, thinking_budget=budget)
        kwargs["config"] = types.GenerateContentConfig(thinking_config=thinking_config)
    When thinking_level is specified, string identifiers are converted into concrete integer token budgets using an internal mapping: low maps to 1024, medium to 4096, and high to 8192 tokens (defaulting to 4096 for unrecognized strings). A types.ThinkingConfig instance is created with include_thoughts=True and assigned to types.GenerateContentConfig, which is injected into the call's keyword arguments.

    Phase 3: Content Generation and Candidate Parsing

        response = client.models.generate_content(**kwargs)

    response_text = ""
    # Extract only text parts to avoid "non-text parts: ['thought_signature']" warnings
    if response.candidates and response.candidates[0].content.parts:
        text_parts = [part.text for part in response.candidates[0].content.parts if part.text is not None]
        response_text = "".join(text_parts)

    if not response_text:
        from utils.output import emit_raw

        emit_raw("WARNING", "Gemini response contained no text parts", dest="LOG")

    return response_text
    The client dispatches the generation request via client.models.generate_content(**kwargs). To prevent runtime warnings when the model returns reasoning candidates containing non-text elements (such as thought_signature), the response parsing explicitly filters for content parts where part.text is not None. The resulting text parts are joined into a single coherent output string. If no text parts are detected, a warning is logged.

    Parameters: * prompt (str): Input prompt string for Gemini inference. * thinking_level (str | None): Reasoning depth level ("low", "medium", "high").

    Returns: * str: Extracted response text from candidate parts.

    Raises: * ValueError: When neither GEMINI_PROJECT_ID nor GEMINI_API_KEY can be found in the active environment. * genai.errors.APIError: If the Google GenAI backend rejects the request or encounters internal errors.

    Example: 

    # Real usage extracted from call_llm()
if provider == "GEMINI":
    response_text = _call_llm_gemini(prompt, thinking_level=thinking_level)

    Data Structures

    CacheStore

    The memoization store is represented internally as a flat Python dictionary and serialized as a single JSON object in llm_cache.json.

    Field / Key Type Description
    [prompt: str] str The exact prompt string acts as the lookup key. The value contains the raw response text generated by the model. 
    {
  "Hello, how are you?": "Hello! I'm doing well, thank you. How can I help you today?"
}

    OpenAICompatibleChatPayload

    The data structure transmitted via HTTP POST to /v1/chat/completions endpoints by _call_llm_provider().

    Field Type Description
    model str Name or identifier of the target model (e.g., "deepseek/deepseek-r1").
    messages list[dict[str, str]] List of chat message objects containing role and content.
    temperature float Generation temperature. Defaults to 0.7; adjusted to 1.0 when reasoning is enabled.
    reasoning dict[str, str] (Optional) Used for OpenRouter reasoning models. Contains key effort with values "low", "medium", or "high".
    think str (Optional) Injected for Ollama instances supporting the think parameter.
    reasoning_effort str (Optional) Injected for Ollama instances conforming to standard reasoning parameters. 
    {
  "model": "deepseek/deepseek-r1",
  "messages": [
    {
      "role": "user",
      "content": "Analyze codebase architecture"
    }
  ],
  "temperature": 1.0,
  "reasoning": {
    "effort": "high"
  }
}

    OpenRouterModelInfo

    The schema of model capability metadata queried via _get_openrouter_model_info() from utils/llm_config.py when evaluating reasoning capability.

    Field Type Description
    reasoning dict Object declaring model reasoning features. Contains supported_efforts.
    reasoning.supported_efforts list[str] List of supported reasoning tiers, such as ["low", "medium", "high"]. 
    {
    "reasoning": {
        "supported_efforts": ["low", "medium", "high"]
    }
}

    GeminiGenerationConfig

    Configuration objects instantiated from the Google GenAI SDK during _call_llm_gemini() execution.

    Object / Field Type Description
    types.ThinkingConfig Class Manages reasoning effort settings for Gemini 2.5/3.7 models.
    ThinkingConfig.include_thoughts bool Set to True to allow reasoning steps alongside generated output.
    ThinkingConfig.thinking_budget int Maximum token ceiling for reasoning: 1024 (low), 4096 (medium), or 8192 (high).
    types.GenerateContentConfig Class Root generation configuration wrapping thinking_config.

    ProviderEnvironmentConfiguration

    Defines the required environment variables expected by the provider resolution subsystems.

    Variable Name Required By Description Example Value
    LLM_PROVIDER All non-Gemini calls Defines active provider ("OPENROUTER", "OLLAMA"). "OPENROUTER"
    GEMINI_API_KEY Gemini (AI Studio) API secret for standard Google AI Studio access. "AIzaSy..."
    GEMINI_PROJECT_ID Gemini (Vertex AI) GCP project identifier triggering Vertex AI mode. "my-gcp-project"

    Error Handling

    The module implements layered fault-tolerance patterns designed to keep documentation generation pipelines operational despite transient networking failures, malformed remote payloads, or localized cache corruption:

    • Graceful Cache Degradation: In load_cache(), failures caused by missing files (FileNotFoundError), corrupt JSON (json.JSONDecodeError), or OS-level access issues (OSError) do not raise exceptions to the caller. Instead, the module logs a warning via emit("WARN_CACHE_LOAD_FAIL") and falls back to an empty dictionary {}. Similarly, save_cache() catches OSError and TypeError, preventing disk serialization issues from crashing active pipeline jobs.
    • Missing Provider Credentials Validation: Before any network operation is attempted, _call_llm_provider() and _call_llm_gemini() validate environment variables. If required settings (such as LLM_PROVIDER, <provider>_MODEL, or Gemini authentication keys) are missing, a descriptive ValueError is raised immediately.
    • Defensive HTTP Response Parsing: Providers returning status code 200 with non-JSON bodies or missing choices blocks (a pattern observed during upstream rate-limiting or provider error states) are caught. _call_llm_provider() explicitly verifies the existence and non-emptiness of response_json["choices"], raising a ValueError with embedded diagnostic details if the structure is invalid.
    • Network Exception Normalization: requests.exceptions.HTTPError, requests.exceptions.ConnectionError, and requests.exceptions.Timeout are caught and re-raised as standardized Exception instances with actionable troubleshooting advice (e.g., checking network connections or inspecting server error details).
    • Gemini Multi-Part Safety: To avoid runtime warnings when reasoning models include non-text artifacts (such as thought_signature), _call_llm_gemini() filters candidate parts via part.text is not None, ensuring only valid strings are concatenated.
