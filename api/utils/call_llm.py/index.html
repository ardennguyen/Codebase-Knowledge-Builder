    call_llm.py

    Source: utils/call_llm.py

    Technical Overview

    utils/call_llm.py serves as the centralized model inference gateway and hardware abstraction layer for the Codebase-Knowledge-Builder repository. Its primary responsibility is mediating between workflow orchestration nodes (defined in nodes.py and executed by flow.py) and external Large Language Model backends. It unifies disparate LLM API conventions into a uniform synchronous interface, providing transparent execution for Google Gemini models (via Google's genai SDK) and OpenAI-compatible completions endpoints, specifically catering to local runtimes such as Ollama and cloud aggregators such as OpenRouter.

    The module implements local JSON-based response caching, comprehensive token telemetry, and dynamic reasoning configurations. To minimize API costs and ensure deterministic execution across multi-pass pipeline cycles, prompt-response pairs are cached directly to llm_cache.json. Telemetry tracking calculates input token counts upfront via utils/token_utils.py and records execution latencies using an isolated logger (llm_logger). Logging configuration is deferred through a logging.NullHandler instance at import time, preventing unintended propagation to the root logger prior to the global setup in main.py.

    Dynamic reasoning budgets and context length queries ensure the system adapts to the execution environment. The module inspects model capabilities dynamically (querying the OpenRouter API for context window definitions and supported reasoning effort tiers) or maps string levels (low, medium, high) directly into Gemini SDK token budgets (ThinkingConfig). The control flow guarantees that whether an inference task is processed via Google Vertex AI, Gemini direct developer keys, or custom self-hosted REST endpoints, all upstream caller components receive an identical string payload under consistent error-handling semantics.

    Public API

    call_llm()

    Visibility: Public
    Signature: def call_llm(prompt: str, use_cache: bool = True, thinking_level: str | None = None) -> str:

    Description:
    Executes a synchronous inference call against the configured LLM provider. The function manages the full prompt lifecycle: computing token metrics via utils/token_utils.py, querying and populating the on-disk JSON cache, measuring execution duration, routing requests to either the Google Gemini client or the generic OpenAI-compatible completion endpoint, and logging formatted status traces.

    Phase 1: Ingress Logging and Token Metrics

        provider = get_llm_provider()
    model = os.environ.get(f"{provider}_MODEL", os.environ.get("GEMINI_MODEL", "unknown"))
    prompt_tokens = count_tokens(prompt)

    logger.info(f"{'=' * 80}")
    logger.info(
        f"LLM CALL START | provider={provider} | model={model} | thinking={thinking_level} | cache={'enabled' if use_cache else 'disabled'} | prompt_tokens={prompt_tokens:,}"
    )
    logger.info(f"PROMPT:\n{prompt}")
    This phase identifies the active provider using get_llm_provider() and resolves the target model identifier through environment inspection. The input prompt's volume is quantified using count_tokens(prompt), and operational parameters—including provider identifier, model string, thinking intensity, cache state, and prompt token count—are emitted to llm_logger.

    Phase 2: Cache Lookup and Hit Resolution

        # Check cache if enabled
    if use_cache:
        cache = load_cache()
        if prompt in cache:
            cached_response = cache[prompt]
            logger.info(f"CACHE HIT | response_chars={len(cached_response):,}")
            logger.info(f"RESPONSE (cached):\n{cached_response}")
            logger.info("LLM CALL END | result=cache_hit")
            return cached_response
    When use_cache is True, the execution attempts to load llm_cache.json using load_cache(). If an exact string match for prompt exists in the cache dictionary, the cached completion is retrieved, logged with character-count telemetry, and returned immediately, avoiding network latency and backend API consumption.

    Phase 3: Provider Dispatch and Latency Measurement

        # Make the actual LLM call
    start_time = time.time()
    logger.info(f"API CALL | sending request to {provider}...")

    if provider == "GEMINI":
        response_text = _call_llm_gemini(prompt, thinking_level=thinking_level)
    else:  # generic method using a URL that is OpenAI compatible API (Ollama, ...)
        response_text = _call_llm_provider(prompt, thinking_level=thinking_level)

    elapsed = time.time() - start_time
    logger.info(f"API CALL COMPLETE | elapsed={elapsed:.1f}s | response_chars={len(response_text):,}")
    logger.info(f"RESPONSE:\n{response_text}")
    If the prompt is absent from the cache or if caching is disabled, the function starts a monotonic timer. It inspects provider: if set to "GEMINI", execution routes to _call_llm_gemini(); otherwise, it dispatches to _call_llm_provider(). Once the provider returns the completion text, execution time is computed and output character statistics are recorded.

    Phase 4: Cache Persistence and Egress

        # Update cache if enabled
    if use_cache:
        cache = load_cache()
        cache[prompt] = response_text
        save_cache(cache)
        logger.info("CACHE WRITE | saved response to cache")

    logger.info(f"LLM CALL END | result=success | elapsed={elapsed:.1f}s")
    return response_text
    Following a successful network dispatch with caching enabled, load_cache() is invoked once more to minimize write-race collisions, the new prompt-response pair is assigned into the dictionary, and save_cache() flushes the updated dictionary to disk. The completion text is returned to the upstream caller.

    Parameters: * prompt (str): The raw text instructions and context provided to the model. * use_cache (bool, optional): Controls whether to query and write to the local cache file (llm_cache.json). Defaults to True. * thinking_level (str | None, optional): Reasoning effort level requested from the model (e.g., "low", "medium", "high"). Defaults to None.

    Returns: * str: The model's generated text completion.

    Raises: * ValueError: Raised if neither Gemini credentials nor generic provider configurations are present in the environment, or if provider payloads lack valid completion structures. * Exception: Raised when underlying network errors, timeouts, or HTTP status faults occur during the API call.

    Example: 

    # Extracted from utils/call_llm.py self-test block
test_prompt = "Hello, how are you?"

emit("SELFTEST_LLM_CALL")
response1 = call_llm(test_prompt, use_cache=False)
emit("SELFTEST_LLM_RESPONSE", response=response1)

    get_llm_provider()

    Visibility: Public
    Signature: def get_llm_provider() -> str | None:

    Description:
    Determines the active LLM backend provider based on environment variables. It reads LLM_PROVIDER, and if unset, infers "GEMINI" if either GEMINI_PROJECT_ID or GEMINI_API_KEY exists in the runtime environment.

    def get_llm_provider():
    provider = os.getenv("LLM_PROVIDER")
    if not provider and (os.getenv("GEMINI_PROJECT_ID") or os.getenv("GEMINI_API_KEY")):
        provider = "GEMINI"
    # if necessary, add ANTHROPIC/OPENAI
    return provider
    The implementation provides fallback resolution. By checking for Google Cloud project or API key variables, the system defaults to Gemini without requiring an explicit LLM_PROVIDER=GEMINI declaration. If no recognized variables exist, it returns None.

    Parameters: * None.

    Returns: * str | None: The resolved provider identifier string (such as "GEMINI", "OLLAMA", or "OPENROUTER"), or None if unresolvable.

    Example: 

    # Extracted from call_llm() internal logic
provider = get_llm_provider()
model = os.environ.get(f"{provider}_MODEL", os.environ.get("GEMINI_MODEL", "unknown"))

    get_model_context_length()

    Visibility: Public
    Signature: def get_model_context_length(endpoint_url: str, model_name: str, api_key: str = "") -> int:

    Description:
    Determines the maximum token context length for a given model endpoint. It applies domain heuristics for Google Gemini endpoints (defaulting to 1,000,000 tokens) and queries OpenRouter's metadata API for models routed through OpenRouter. For all other endpoints or upon request failure, it defaults to 100,000 tokens.

    Phase 1: Gemini Endpoint and Heuristic Detection

        default_limit = 100000
    try:
        if not endpoint_url:
            return default_limit

        if "generativelanguage.googleapis.com" in endpoint_url or "gemini" in model_name.lower():
            # Safely default to 1M tokens for Gemini models
            return 1000000
    This initial evaluation checks for empty endpoint definitions, returning the baseline 100,000 token limit immediately. It then scans for Google endpoint hostnames (generativelanguage.googleapis.com) or the presence of "gemini" in the model identifier, returning a context window of 1,000,000 tokens.

    Phase 2: OpenRouter Dynamic Metadata Querying

            if "openrouter.ai" in endpoint_url:
            resp = requests.get("https://openrouter.ai/api/v1/models", timeout=5)
            data = resp.json().get("data", [])
            for m in data:
                if m.get("id") == model_name:
                    return m.get("context_length", default_limit)
    except Exception as e:
        logger.warning(f"Failed to fetch context length for {model_name} at {endpoint_url}: {e}")

    return default_limit
    When an OpenRouter endpoint is detected, the function makes a synchronous GET request to OpenRouter's /api/v1/models route with a 5-second timeout. It traverses the returned list of model definitions to locate the item matching model_name and extracts its context_length attribute. Any network failures, timeouts, or JSON decoding errors trigger a warning log and fall back to default_limit.

    Parameters: * endpoint_url (str): The base or complete target URL of the inference endpoint. * model_name (str): The model identifier string (e.g., "google/gemini-2.5-flash"). * api_key (str, optional): Authorization key for protected endpoints. Defaults to "".

    Returns: * int: The maximum token context length supported by the model (e.g., 1000000 or 100000).

    Example: 

    # Typical usage for token allocation verification in workflow initialization
context_len = get_model_context_length(
    endpoint_url=os.environ.get("OPENROUTER_BASE_URL", ""),
    model_name=os.environ.get("OPENROUTER_MODEL", "")
)

    Description:
    Reads and deserializes the JSON cache stored at llm_cache.json. If the file does not exist, lacks read permissions, or contains invalid JSON syntax, the exception is caught, a warning is logged to llm_logger, and an empty dictionary is returned to allow operations to continue without caching.

    def load_cache():
    try:
        with open(cache_file) as f:
            return json.load(f)
    except Exception:
        logger.warning("Failed to load cache.")
    return {}
    The routine encapsulates all disk read exceptions within a generic except Exception block. This ensures that corrupted or unreadable cache files do not interrupt upstream knowledge extraction pipelines.

    Parameters: * None.

    Returns: * dict: A dictionary mapping prompt strings to cached response strings, or {} upon failure.

    Description:

    Internal Helpers

    _call_llm_gemini()

    Visibility: Private
    Signature: def _call_llm_gemini(prompt: str, thinking_level: str | None = None) -> str:

    Description:
    Directly interfaces with Google's official genai SDK. It authenticates through Google Cloud Vertex AI (using project and location environment variables) or direct Google AI Studio API keys, configures optional thinking budgets, dispatches generation requests, and extracts text content while filtering out non-text structural metadata.

    Phase 1: Authentication and Client Initialization

        if os.getenv("GEMINI_PROJECT_ID"):
        client = genai.Client(vertexai=True, project=os.getenv("GEMINI_PROJECT_ID"), location=os.getenv("GEMINI_LOCATION", "us-central1"))
    elif os.getenv("GEMINI_API_KEY"):
        client = genai.Client(api_key=os.getenv("GEMINI_API_KEY"))
    else:
        raise ValueError("Either GEMINI_PROJECT_ID or GEMINI_API_KEY must be set in the environment")
    model = os.getenv("GEMINI_MODEL", "gemini-3.7-flash")

    kwargs = {"model": model, "contents": [prompt]}
    The helper determines the client initialization strategy by evaluating GEMINI_PROJECT_ID first; if present, it instantiates genai.Client in Vertex AI mode using the specified or default ("us-central1") location. Otherwise, it checks for GEMINI_API_KEY. If neither is found, it raises a ValueError. The target model defaults to "gemini-3.7-flash" if GEMINI_MODEL is unset.

    Phase 2: Thinking Budget and Generation Configuration

        if thinking_level:
        # Map string levels to budgets for the installed SDK version
        budget_map = {"low": 1024, "medium": 4096, "high": 8192}
        budget = budget_map.get(thinking_level.lower(), 4096)
        thinking_config = types.ThinkingConfig(include_thoughts=True, thinking_budget=budget)
        kwargs["config"] = types.GenerateContentConfig(thinking_config=thinking_config)
    When thinking_level is specified, the string representation is converted into a concrete token budget using a predefined lookup table: "low" maps to 1,024 tokens, "medium" to 4,096 tokens, and "high" to 8,192 tokens (defaulting to 4,096 if an unrecognized string is provided). It builds a types.ThinkingConfig instance with include_thoughts=True and assigns it to a types.GenerateContentConfig container passed into the execution arguments.

    Phase 3: Content Generation and Text Extraction

        response = client.models.generate_content(**kwargs)

    # Extract only text parts to avoid "non-text parts: ['thought_signature']" warnings
    if response.candidates and response.candidates[0].content.parts:
        text_parts = [part.text for part in response.candidates[0].content.parts if part.text is not None]
        return "".join(text_parts)
    return ""
    The client executes generate_content. Upon receiving the response, the helper iterates over the first candidate's content parts, filtering specifically for items where part.text is not None. This prevents downstream logging warnings concerning non-text parts (such as reasoning thought signatures) and concatenates all text fragments into a single return string.

    Parameters: * prompt (str): The instruction text dispatched to the Gemini model. * thinking_level (str | None, optional): Reasoning depth label ("low", "medium", or "high"). Defaults to None.

    Returns: * str: The concatenated text output returned by the model candidate, or "" if candidates or parts are missing.

    Raises: * ValueError: Raised if neither GEMINI_PROJECT_ID nor GEMINI_API_KEY are defined in the environment.

    Example: 

    # Extracted from call_llm() provider switch branch
if provider == "GEMINI":
    response_text = _call_llm_gemini(prompt, thinking_level=thinking_level)

    _call_llm_provider()

    Visibility: Private
    Signature: def _call_llm_provider(prompt: str, thinking_level: str | None = None) -> str:

    Description:
    Executes HTTP completions calls against OpenAI-compatible REST endpoints. It validates environment-driven provider parameters, builds the /v1/chat/completions endpoint URL, injects model reasoning instructions for OpenRouter or Ollama, executes the request with defined connect/read timeouts, defensively validates the returned JSON payload structure, and maps HTTP/network errors into clear exceptions.

    Phase 1: Configuration Validation and URL Assembly

        # Read the provider from environment variable
    provider = os.environ.get("LLM_PROVIDER")
    if not provider:
        raise ValueError("LLM_PROVIDER environment variable is required")

    # Construct the names of the other environment variables
    model_var = f"{provider}_MODEL"
    base_url_var = f"{provider}_BASE_URL"
    api_key_var = f"{provider}_API_KEY"

    # Read the provider-specific variables
    model = os.environ.get(model_var)
    base_url = os.environ.get(base_url_var)
    api_key = os.environ.get(api_key_var, "")  # API key is optional, default to empty string

    # Validate required variables
    if not model:
        raise ValueError(f"{model_var} environment variable is required")
    if not base_url:
        raise ValueError(f"{base_url_var} environment variable is required")

    # Append the endpoint to the base URL
    url = f"{base_url.rstrip('/')}/v1/chat/completions"
    The routine verifies that LLM_PROVIDER is set. It constructs the expected provider-specific variable names (<PROVIDER>_MODEL, <PROVIDER>_BASE_URL, and <PROVIDER>_API_KEY) and extracts their values. If either the model or base URL variable is missing, a ValueError is raised. The base URL is stripped of trailing slashes and appended with /v1/chat/completions.

    Phase 2: Headers and Provider-Specific Reasoning Setup

        headers = {
        "Content-Type": "application/json",
    }
    if api_key:  # Only add Authorization header if API key is provided
        headers["Authorization"] = f"Bearer {api_key}"

    payload = {
        "model": model,
        "messages": [{"role": "user", "content": prompt}],
        "temperature": 0.7,
    }

    if provider == "OPENROUTER" and thinking_level:
        model_info = _get_openrouter_model_info(model)
        if model_info and "reasoning" in model_info:
            supported_efforts = model_info["reasoning"].get("supported_efforts", [])
            if thinking_level.lower() in supported_efforts:
                payload["reasoning"] = {"effort": thinking_level.lower()}
                payload["temperature"] = 1.0  # Required for many reasoning models
            else:
                logger.warning(f"Invalid thinking level '{thinking_level}' for model {model}. Supported efforts: {supported_efforts}")
        else:
            logger.warning(f"Model {model} does not support reasoning via OpenRouter API.")

    elif provider == "OLLAMA" and thinking_level:
        # Some Ollama SDKs / API versions look for `think`, others look for standard `reasoning_effort`
        payload["think"] = thinking_level.lower()
        payload["reasoning_effort"] = thinking_level.lower()
        payload["temperature"] = 1.0
    Standard JSON headers are initialized, appending an Authorization: Bearer <API_KEY> header only when an API key is present. The baseline payload is set with temperature: 0.7. If the provider is "OPENROUTER" with a requested thinking_level, _get_openrouter_model_info() verifies model capability and supported effort tiers. If valid, payload["reasoning"] = {"effort": ...} is configured and temperature is set to 1.0. For "OLLAMA", both think and reasoning_effort parameters are assigned alongside a temperature of 1.0.

    Phase 3: Network Transmission and JSON Parsing

        try:
        response = requests.post(url, headers=headers, json=payload, timeout=(10, 300))
        try:
            response_json = response.json()  # Log the response
        except (ValueError, requests.exceptions.JSONDecodeError):
            from utils.output import emit_raw

            emit_raw(
                "WARNING",
                f"Warning: Provider returned invalid JSON. Status Code: {response.status_code}, Response Text: {response.text}",
                dest="STDOUT",
            )
            logger.warning(f"Provider returned invalid JSON. Status Code: {response.status_code}, Response Text: {response.text}")
            raise ValueError(f"Provider returned invalid JSON. Status Code: {response.status_code}") from None
        response.raise_for_status()
    The HTTP request is dispatched with a timeout tuple: 10 seconds for initial socket connection and 300 seconds for read completion. The function attempts to parse the response body as JSON. If the response contains invalid JSON, it notifies the console via emit_raw() from utils/output.py, records a warning in llm_logger, and raises a ValueError. If valid JSON is decoded, response.raise_for_status() is called to catch 4xx and 5xx HTTP response codes.

    Phase 4: Defensive Payload Validation and Error Wrapping

            # Defensive check: API may return 200 with error/rate-limit payload missing 'choices'
        if "choices" not in response_json or not response_json["choices"]:
            error_detail = response_json.get("error", response_json)
            logger.warning(f"API returned 200 but no 'choices' in response: {error_detail}")
            raise ValueError(f"API response missing 'choices' key. Response: {error_detail}")

        return response_json["choices"][0]["message"]["content"]
    except requests.exceptions.HTTPError as e:
        error_message = f"HTTP error occurred: {e}"
        try:
            error_details = response.json().get("error", "No additional details")
            error_message += f" (Details: {error_details})"
        except Exception:
            pass
        raise Exception(error_message) from e
    except requests.exceptions.ConnectionError as e:
        raise Exception(f"Failed to connect to {provider} API. Check your network connection.") from e
    except requests.exceptions.Timeout as e:
        raise Exception(f"Request to {provider} API timed out.") from e
    except requests.exceptions.RequestException as e:
        raise Exception(f"An error occurred while making the request to {provider}: {e}") from e
    except ValueError as e:
        raise Exception(f"Failed to parse response as JSON from {provider}. The server might have returned an invalid response.") from e
    The helper defensively inspects HTTP 200 responses for the presence of the choices array, catching instances where proxies return successful status codes alongside error dictionaries. If choices is missing or empty, it extracts the error block and raises a ValueError. If validation passes, the content of the first choice's message is returned. Any caught network or protocol exceptions (HTTPError, ConnectionError, Timeout, RequestException) are wrapped into high-level descriptive exceptions.

    Parameters: * prompt (str): The prompt string submitted to the model endpoint. * thinking_level (str | None, optional): Requested reasoning depth string ("low", "medium", "high"). Defaults to None.

    Returns: * str: The generated content string from the response choice.

    Raises: * ValueError: Raised if required provider configuration variables are missing or if the API returns malformed payloads. * Exception: Raised on connection errors, timeouts, HTTP client/server errors, or general request failures.

    Example: 

    # Extracted from call_llm() provider switch branch
else:  # generic method using a URL that is OpenAI compatible API (Ollama, ...)
    response_text = _call_llm_provider(prompt, thinking_level=thinking_level)

    _get_openrouter_model_info()

    Visibility: Private
    Signature: def _get_openrouter_model_info(model_id: str) -> dict | None:

    Description:
    Fetches and caches metadata definitions for models registered on OpenRouter. The function utilizes a module-level cache (_openrouter_models_cache) to avoid redundant HTTP calls when querying model capabilities across multiple inference invocations.

    Phase 1: Lazy Cache Population

        global _openrouter_models_cache
    if _openrouter_models_cache is None:
        try:
            resp = requests.get("https://openrouter.ai/api/v1/models", timeout=5)
            _openrouter_models_cache = resp.json().get("data", [])
        except Exception:
            _openrouter_models_cache = []
    This phase checks whether the module-level variable _openrouter_models_cache is None. If unpopulated, it issues a GET request to OpenRouter's model catalog endpoint with a 5-second timeout, extracting the data list. If a network fault, timeout, or decoding error occurs, the cache defaults to an empty list [] to prevent repeated failed requests.

    Phase 2: Model Query Evaluation

        return next((m for m in _openrouter_models_cache if m.get("id") == model_id), None)
    Using a generator expression with next(), this phase scans the cached list of model dictionaries for an entry where the id field matches model_id. It returns the matching dictionary, or None if the model identifier is not found in the catalog.

    Parameters: * model_id (str): The identifier string of the model (e.g., "deepseek/deepseek-r1").

    Returns: * dict | None: The metadata dictionary containing model capabilities, context limits, and reasoning specifications, or None if not found.

    if model_info and "reasoning" in model_info:

    Data Structures

    Cache Storage Format (llm_cache.json)

    The on-disk cache is a flat key-value dictionary serialized as JSON. Prompts serve directly as keys, and raw model responses serve as values.

    Field Type Description
    key str Complete, exact string representation of the prompt text passed to call_llm().
    value str Raw text response returned by the LLM provider.

    Example structure: 

    {
  "Hello, how are you?": "I am an AI language model operating normally.",
  "Generate architectural summary for module X": "# Module X Architecture\nThis module manages..."
}

    OpenRouter Model Metadata Schema

    Structure of individual model objects returned by OpenRouter's /api/v1/models endpoint and stored in _openrouter_models_cache.

    Field Type Description
    id str Unique OpenRouter model identifier (e.g., "anthropic/claude-3.7-sonnet").
    context_length int Maximum context window length in tokens.
    reasoning dict Optional container specifying reasoning and thinking support.
    reasoning.supported_efforts list[str] List of supported reasoning effort strings (e.g., ["low", "medium", "high"]).

    Example structure: 

    {
  "id": "deepseek/deepseek-r1",
  "context_length": 65536,
  "reasoning": {
    "supported_efforts": ["low", "medium", "high"]
  }
}

    OpenAI-Compatible Chat Completion Request Payload

    Structure of the JSON dictionary transmitted by _call_llm_provider to the target provider's /v1/chat/completions endpoint.

    Field Type Description
    model str Model identifier string resolved from <PROVIDER>_MODEL.
    messages list[dict] List containing the prompt wrapped in a user message ({"role": "user", "content": prompt}).
    temperature float Sampling temperature. Defaults to 0.7, set to 1.0 when reasoning is enabled.
    reasoning dict OpenRouter-specific reasoning configuration ({"effort": thinking_level}).
    think str Ollama-specific parameter set to the lowercase thinking_level.
    reasoning_effort str Generic/Ollama fallback parameter set to the lowercase thinking_level.

    Error Handling

    utils/call_llm.py uses specific error handling strategies to account for the reliability issues inherent in distributed LLM APIs and local model runners:

    Provider Configuration and Environment Validation

    If neither GEMINI_PROJECT_ID nor GEMINI_API_KEY can be located when the Gemini client is requested, _call_llm_gemini() raises a descriptive ValueError: 

    raise ValueError("Either GEMINI_PROJECT_ID or GEMINI_API_KEY must be set in the environment")
    Similarly, _call_llm_provider() validates the presence of LLM_PROVIDER, <PROVIDER>_MODEL, and <PROVIDER>_BASE_URL, raising a ValueError identifying any missing variable before initiating network requests.

    Malformed Provider Payloads and Rate Limits

    Certain API gateways return HTTP 200 OK status codes while serving HTML error pages, rate limit warnings, or JSON objects lacking completions. The module defends against this in two ways: 1. JSON Decoding Failures: If response.json() fails, the raw status code and response text are routed to standard output through emit_raw() from utils/output.py and logged to llm_logger before raising a ValueError. 2. Missing Choices Array: If the response is valid JSON but lacks a non-empty choices list, the function extracts the error block from the payload and raises a ValueError: 

    if "choices" not in response_json or not response_json["choices"]:
    error_detail = response_json.get("error", response_json)
    logger.warning(f"API returned 200 but no 'choices' in response: {error_detail}")
    raise ValueError(f"API response missing 'choices' key. Response: {error_detail}")

    Network Fault Wrapping

    Low-level exceptions raised by requests are intercepted and re-raised as standardized Exception instances with actionable diagnostics: * requests.exceptions.HTTPError: Extracts nested error details from the response JSON body when available and re-raises with the status error string. * requests.exceptions.ConnectionError: Catches network unreachable states and advises the operator to verify their network connection. * requests.exceptions.Timeout: Wraps socket and read timeouts into an explicit timeout exception. * requests.exceptions.RequestException: General fallback wrapper for all other transmission faults.

    Safe Disk I/O Handling

    Both load_cache() and save_cache() swallow general exceptions (except Exception:) to prevent local disk errors, lock contentions, or syntax faults in llm_cache.json from disrupting long-running repository analysis tasks. Failures emit warning messages to llm_logger while the system continues execution using fallback in-memory empty dictionaries.
