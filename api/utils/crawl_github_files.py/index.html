    Technical Overview

    Following the inference abstraction layer established in call_llm.py, which coordinates LLM queries and token budgeting, crawl_github_files.py acts as the primary remote ingestion engine for the Codebase-Knowledge-Builder architecture. While local repositories are ingested through direct filesystem reads, remote targets require resilient retrieval mechanisms capable of traversing arbitrary Git trees, honoring repository ignore rules, parsing diverse Git reference specifications, and handling network or rate-limiting constraints. This module abstracts these challenges by providing a unified extraction interface that converts remote GitHub repositories into an in-memory dictionary of relative file paths and string contents.

    The module operates across two distinct operational pipelines selected dynamically based on the repository URL schema: an SSH shallow clone pipeline and a GitHub REST API v3 traversal pipeline. When an SSH URL (prefixed with git@ or suffixed with .git) is supplied, the module provisions an isolated temporary directory via Python's tempfile module, invokes GitPython (git.Repo.clone_from) to clone the working tree, loads .gitignore rules using pathspec, and performs a filtered breadth-first filesystem walk. Conversely, when an HTTPS GitHub URL is supplied, the module parses the owner, repository, commit SHA, or branch reference from the URI path, queries the GitHub Contents and Git Trees REST APIs, downloads files directly via raw blob endpoints or decodes Base64 payloads, and handles API rate-limit resets with exponential or header-derived backoff delays.

    Both pipelines converge on a common filtering and sanitization engine. Files and directories are matched against user-defined wildcard patterns (fnmatch) and Git-native .gitignore specifications (pathspec.PathSpec). The engine enforces strict file-size thresholds (defaulting to 1 MB) to prevent out-of-memory errors on massive assets, isolates binary artifacts by intercepting UTF-8 decoding failures, and standardizes progress telemetry via the centralized logging facilities in output.py. The final artifact is an ingested file mapping ready for downstream token profiling, document chunking, and LLM-driven architectural analysis.

    Visibility: Public
    Signature: def crawl_github_files(repo_url, token=None, max_file_size: int = DEFAULT_MAX_FILE_SIZE, use_relative_paths: bool = False, include_patterns: str | set[str] | None = None, exclude_patterns: str | set[str] | None = None) -> dict:

    Description:
    Orchestrates the retrieval of source code files from a remote GitHub repository at a target commit, branch, or subpath. The function normalizes pattern configurations, evaluates the connection protocol, and executes either a local Git clone workflow or a recursive GitHub REST API crawler. It filters entries through size caps, Git wildmatch rules, and file name matchers while recording statistics for logging.

    Parameters: * repo_url (str): Target repository URL. Supports SSH clone syntax (git@github.com:... or URLs ending in .git) and standard HTTPS tree URLs (e.g., https://github.com/owner/repo/tree/branch/subpath). * token (str, optional): GitHub Personal Access Token (PAT). Required for private repositories and recommended for public repositories to elevate GitHub API rate limits from 60 to 5,000 requests per hour. * max_file_size (int, optional): Maximum allowed size in bytes for downloaded source files. Defaults to 1_048_576 (1 MB). * use_relative_paths (bool, optional): When True, modifies keys in the returned file mapping to be relative to the queried subdirectory rather than the repository root. Defaults to False. * include_patterns (str | set[str] | None, optional): Glob pattern or set of glob patterns indicating which files must be included (e.g., "*.py" or {"*.md", "*.txt"}). If None, includes all files. * exclude_patterns (str | set[str] | None, optional): Glob pattern or set of glob patterns designating paths or filenames that must be omitted from ingestion.

    Returns: * dict: Ingestion payload containing two root keys: "files", mapping string file paths to their decoded string contents, and "stats", tracking metrics such as total crawled items, skipped entries, and configuration metadata.

    Raises: * ValueError: Raised when an HTTPS GitHub URL does not contain at least two path segments (owner and repo). * Exception: Raised when GitHub API rate limits are exhausted and no authentication token is provided to facilitate recovery.

    def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:
        """Determine if a file should be included based on patterns"""
        # If no include patterns are specified, include all files
        if not include_patterns:
            include_file = True
        else:
            # Check if file matches any include pattern
            include_file = any(fnmatch.fnmatch(file_name, pattern) for pattern in include_patterns)

        # Check gitignore if provided
        if include_file and gitignore_spec and gitignore_spec.match_file(file_path):
            return False

        # If exclude patterns are specified, check if file should be excluded
        if exclude_patterns and include_file:
            # Exclude if file matches any exclude pattern
            exclude_file = any(fnmatch.fnmatch(file_path, pattern) for pattern in exclude_patterns)
            return not exclude_file

        return include_file

The closure should_include_file is defined to encapsulate matching logic across both traversal pipelines. It sequentially validates whether a given file matches explicit inclusion filters, evaluates path compliance against compiled .gitignore rules via pathspec, and checks negative assertions defined by exclude_patterns.

    Phase 4: Directory Pruning and Local Filesystem Filtering

                        entry_num += 1
                        count_excluded += 1
                        emit("CRAWL_DIR_EXCLUDED", num=entry_num, path=dirpath_rel, reason=reason)

                for d in dirs.copy():

Each directory candidate is checked against the parsed gitignore_spec and user-defined exclude_patterns. Any matched directory is tracked in excluded_dirs, logged via emit("CRAWL_DIR_EXCLUDED"), and removed from dirs to prevent unnecessary filesystem overhead in ignored subtrees.

    Phase 5: Local File Reading and Content Decoding

                    except OSError:
                        continue

                        skipped_size_list.append(rel_path)
                        size_kb = file_size / 1024
                        emit("CRAWL_FILE_SIZE_LIMIT", num=entry_num, path=rel_path, size=f"{size_kb:.0f}")
                        continue

                        with open(abs_path, encoding="utf-8-sig") as f:

                    except (UnicodeDecodeError, ValueError):

                        skipped_non_text_list.append(rel_path)
                        emit("CRAWL_FILE_NOT_TEXT", num=entry_num, path=rel_path)
                    except Exception as e:
                        count_non_text += 1
                        skipped_non_text_list.append(rel_path)
                        emit("CRAWL_FILE_ERROR", num=entry_num, path=rel_path, error=e)
    Files located within retained directories are sorted alphabetically for deterministic ordering. Each file is validated via should_include_file() and checked against max_file_size using os.path.getsize(). Qualifying files are opened with UTF-8 byte-order-mark support (utf-8-sig). Files containing binary data or invalid character encodings throw UnicodeDecodeError or ValueError, which are caught to mark the file as non-text, log the event, and preserve engine stability.

    if len(path_parts) < 2:

    # Extract the basic components
    owner = path_parts[0]
    repo = path_parts[1]

    # Setup for GitHub API
    headers = {"Accept": "application/vnd.github.v3+json"}

    # Check if URL contains a specific branch/commit
    if len(path_parts) > 3 and path_parts[2] == "tree":

        def join_parts(i):
            return "/".join(path_parts[i:])

        branches = fetch_branches(owner, repo)
        branch_names = (branch.get("name") for branch in branches)

        # Fetching branches was not successful
        if len(branches) == 0:
            return None

        # Check branch name
        relevant_path = join_parts(3)

        # Find a match with relevant path and get the branch name
        filter_gen = (name for name in branch_names if relevant_path.startswith(name))
        ref = next(filter_gen, None)

        # If match is not found, check for is it a tree
        if ref is None:
            tree = path_parts[3]
            ref = tree if check_tree(owner, repo, tree) else None

        # If it is neither a tree nor a branch name
        if ref is None:
            emit_raw("ERROR", "The given path does not match with any branch and any tree in the repository.\nPlease verify the path is exists.")
            return None

        # Combine all parts after the ref as the path
        part_index = 5 if "/" in ref else 4
        specific_path = join_parts(part_index) if part_index < len(path_parts) else ""
    else:
        # Don't put the ref param in query
        # and let Github decide default branch
        ref = None
        specific_path = ""
    If the input URL targets an HTTPS GitHub resource, urlparse breaks down the URI path into individual segments. The engine validates that both owner and repo segments exist. When a /tree/ separator is detected, the engine determines whether the trailing segments refer to a branch name (which may contain slashes, such as feature/auth) or a direct Git tree/commit SHA. It queries fetch_branches() and matches path prefixes; if no branch matches, it verifies the SHA via check_tree(). It then extracts any remaining segments as the root subpath (specific_path).

    Phase 9: Recursive REST Content Crawling and Backoff Engine

        def fetch_contents(path):
        """Fetch contents of the repository at a specific path and commit"""
        url = f"https://api.github.com/repos/{owner}/{repo}/contents/{path}"
        params = {"ref": ref} if ref is not None else {}

        response = requests.get(url, headers=headers, params=params, timeout=(30, 30))

        if response.status_code in (403, 429) and "rate limit exceeded" in response.text.lower():
            if not token:
                raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")
            reset_time = int(response.headers.get("X-RateLimit-Reset", 0))
            wait_time = max(reset_time - time.time(), 0) + 1
            emit_raw("WARNING", f"Rate limit exceeded. Waiting for {wait_time:.0f} seconds...")
            time.sleep(wait_time)
            return fetch_contents(path)

        if response.status_code == 404:
            # ... [Handle 404 logging logic] ...
            return None

        if response.status_code != 200:
            emit_raw("ERROR", f"Error fetching {path}: {response.status_code} - {response.text}")
            return None

        contents = response.json()
        if not isinstance(contents, list):
            contents = [contents]
        # ...
    The internal worker fetch_contents recursively traverses repository directories via the GitHub Contents API. When it encounters HTTP status 403 or 429 indicating rate limits, it checks for an authentication token; unauthenticated requests fail fast with an exception, while authenticated requests calculate the wait window using the X-RateLimit-Reset header, sleep via time.sleep(), and resume execution. Single-item responses (returned when targeting a single file) are normalized into single-element lists.

    Phase 10: Remote Stream Retrieval and Base64 Fallback

            for item in contents:
            item_path = item["path"]

            # Calculate relative path if requested

                    api_counters["excluded"] += 1
                    emit("CRAWL_FILE_EXCLUDED", num=entry_num, path=rel_path)
                    continue

                file_size = item.get("size", 0)
                if file_size > max_file_size:
                    api_counters["size_limit"] += 1
                    api_skipped_size.append(rel_path)
                    size_kb = file_size / 1024
                    emit("CRAWL_FILE_SIZE_LIMIT", num=entry_num, path=rel_path, size=f"{size_kb:.0f}")
                    continue

                if item.get("download_url"):
                    file_url = item["download_url"]
                    file_response = requests.get(file_url, headers=headers, timeout=(30, 30))
                    content_length = int(file_response.headers.get("content-length", 0))
                    if content_length > max_file_size:
                        api_counters["size_limit"] += 1
                        api_skipped_size.append(rel_path)
                        continue

                    if file_response.status_code == 200:
                        files[rel_path] = file_response.text
                        api_counters["processed"] += 1
                        emit("CRAWL_FILE_PROCESSED", num=entry_num, path=rel_path)
                    else:
                        api_counters["non_text"] += 1
                        api_skipped_non_text.append(rel_path)
                        emit("CRAWL_FILE_HTTP_ERROR", num=entry_num, path=rel_path, status=file_response.status_code)
                else:
                    content_response = requests.get(item["url"], headers=headers, timeout=(30, 30))
                    if content_response.status_code == 200:
                        content_data = content_response.json()
                        if content_data.get("encoding") == "base64" and "content" in content_data:
                            if len(content_data["content"]) * 0.75 > max_file_size:
                                api_counters["size_limit"] += 1
                                api_skipped_size.append(rel_path)
                                continue

                            file_content = base64.b64decode(content_data["content"]).decode("utf-8")
                            files[rel_path] = file_content
                            api_counters["processed"] += 1
                            emit("CRAWL_FILE_PROCESSED", num=entry_num, path=rel_path)
            elif item["type"] == "dir":
                # ... [Directory exclusion validation and recursion] ...
                fetch_contents(item_path)
    Each entry in the API response is checked for type (file or dir). For files, relative paths are resolved if use_relative_paths is enabled, and exclusions and file sizes are checked. File contents are downloaded using download_url (raw endpoint) when available, verifying size via the Content-Length header. If download_url is absent, the crawler falls back to querying the Git blob API URL, verifying the payload size against an estimated Base64 ratio (len * 0.75), and decoding the UTF-8 text. Subdirectories are checked against exclusion filters before recurring.

    Phase 11: REST Summary Compilation and Metric Finalization

    should_include_file()

    Visibility: Private (Function-scoped closure within crawl_github_files)
    Signature: def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:

    Description:
    Validates whether a specific file should be ingested based on configured inclusion patterns, parsed .gitignore rules, and exclusion patterns. Inclusion patterns match strictly against the file's basename, whereas .gitignore specifications and exclusion patterns evaluate the full relative path.

        def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:
        """Determine if a file should be included based on patterns"""
        # If no include patterns are specified, include all files
        if not include_patterns:
            include_file = True
        else:
            # Check if file matches any include pattern
            include_file = any(fnmatch.fnmatch(file_name, pattern) for pattern in include_patterns)

        # Check gitignore if provided
        if include_file and gitignore_spec and gitignore_spec.match_file(file_path):
            return False

        # If exclude patterns are specified, check if file should be excluded
        if exclude_patterns and include_file:
            # Exclude if file matches any exclude pattern
            exclude_file = any(fnmatch.fnmatch(file_path, pattern) for pattern in exclude_patterns)
            return not exclude_file

        return include_file
    The helper implements a short-circuiting filter chain. It first checks include_patterns; if defined, the filename must match at least one pattern via fnmatch.fnmatch. If included, it then evaluates gitignore_spec.match_file(file_path); matching files are immediately rejected. Finally, if exclude_patterns are specified, the relative path is checked against each pattern. The file is accepted only if no exclusion rules match.

    Parameters: * file_path (str): Relative file path from the repository root or search directory. * file_name (str): Basename of the file (e.g., main.py). * gitignore_spec (pathspec.PathSpec, optional): Compiled PathSpec instance representing active .gitignore rules. Defaults to None.

    Returns: * bool: True if the file satisfies all inclusion and exclusion constraints; False otherwise.

    Raises: * None.

    Example:

        def fetch_contents(path):
        """Fetch contents of the repository at a specific path and commit"""
        url = f"https://api.github.com/repos/{owner}/{repo}/contents/{path}"

            wait_time = max(reset_time - time.time(), 0) + 1

            return fetch_contents(path)

            return None

        if not isinstance(contents, list):
            contents = [contents]

        for item in contents:
            item_path = item["path"]
            # ... Path calculation, file vs dir branch handling, content downloading ...
            if item["type"] == "dir":
                # ... Directory exclusion checks ...
                fetch_contents(item_path)

        return None

    Error Handling

    GitHub API Rate Limiting and Backoff

    GitHub imposes strict rate limits on REST API interactions: 60 requests per hour for unauthenticated callers and 5,000 requests per hour for authenticated callers. The module handles these limits through a two-tiered strategy: 1. Unauthenticated Fast-Fail: If an HTTP 403 or 429 status code is encountered with a response body indicating "rate limit exceeded" and no token was supplied, the module raises an Exception explaining how to provide authentication credentials via CLI flags or the GITHUB_TOKEN environment variable. 2. Authenticated Backoff: If an authenticated request encounters rate limits, fetch_contents parses the X-RateLimit-Reset HTTP header (a Unix epoch timestamp), computes the remaining sleep time (reset_time - time.time() + 1), logs a warning, and blocks execution via time.sleep(). Once the backoff period expires, it retries the request recursively:

    if response.status_code in (403, 429) and "rate limit exceeded" in response.text.lower():
    if not token:
        raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")
    reset_time = int(response.headers.get("X-RateLimit-Reset", 0))
    wait_time = max(reset_time - time.time(), 0) + 1
    emit_raw("WARNING", f"Rate limit exceeded. Waiting for {wait_time:.0f} seconds...")
    time.sleep(wait_time)
    return fetch_contents(path)

The module checks these conditions to provide contextual error feedback: * If no token is configured, it warns that the repository may be private and suggests supplying credentials. * If querying the repository root on branch main fails, it suggests verifying whether the default branch is named master. * Otherwise, it reports that the requested subpath was not found or the provided token lacks read access:

            "ERROR",

    Non-Text and Binary File Isolation

    Ingesting binary formats (e.g., compiled binaries, images, bytecode) into an LLM analysis pipeline can cause prompt corruption and context overflows. The module isolates binary files using two defenses: 1. Local Filesystem Encapsulation: When reading files cloned via SSH, files are opened using the utf-8-sig codec. Any UnicodeDecodeError or ValueError is caught, incrementing count_non_text and logging the event via CRAWL_FILE_NOT_TEXT. 2. REST Blob Stream Validation: For API responses, base64 payloads are decoded within a guarded try...except block, while unexpected or unparseable JSON structures increment api_counters["non_text"] and emit CRAWL_FILE_UNEXPECTED.

    Multi-Stage File Size Validation

    To prevent downloading massive assets, file sizes are checked at multiple stages: 1. API Metadata Inspection: File size is checked against item.get("size", 0) before initiating a download request. 2. HTTP Content-Length Inspection: When downloading raw files via download_url, the Content-Length header is checked before buffering the response body. 3. Base64 Payload Size Estimation: When decoding inline Base64 data, the unpacked size is estimated using len(content) * 0.75 before invoking base64.b64decode, skipping oversized blobs early.
