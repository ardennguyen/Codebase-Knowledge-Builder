    crawl_github_files.py

    Source: utils/crawl_github_files.py

    Following the inference and model interaction mechanics established in call_llm.py, crawl_github_files.py provides the remote codebase ingestion engine for the Codebase-Knowledge-Builder repository analysis pipeline. It extracts source code trees, documentation, and configuration files directly from remote GitHub repositories without requiring manual pre-cloning by the user.

    Technical Overview

    The crawl_github_files.py module exposes a dual-strategy ingestion engine capable of retrieving repository content through either local Git over SSH or the GitHub REST API v3. The crawler normalizes repository structures into an in-memory dictionary mapping file paths to UTF-8 decoded text content, paired with execution metadata and filtering metrics.

    Key Architectural Capabilities

    1. Dual Traversal Strategies:
    2. SSH Shallow Clone Mode: Automatically invoked when repository URLs use SSH syntax (git@...) or terminate in .git. It clones the target repository into an ephemeral directory via tempfile.TemporaryDirectory and git.Repo.clone_from(), walking the local filesystem via os.walk() to eliminate API quota consumption.

    3. GitHub REST API Mode: Used for standard HTTP/HTTPS GitHub URLs (including deep links pointing to subtrees or branches). It queries the GitHub REST API v3 (/repos/{owner}/{repo}/contents/{path}), handling directory recursions, single-file downloads, and base64 blob payload decompression.

    4. Branch, Tree, and Path Disambiguation:

    5. Inspects deep-link URLs structured as https://github.com/{owner}/{repo}/tree/{ref}/{path}.

    6. Resolves nested branch names containing forward slashes (e.g., feature/login-system) versus raw commit SHAs and Git tree objects by querying /repos/{owner}/{repo}/branches and /repos/{owner}/{repo}/git/trees/{tree}.

    7. Multi-Tier Filtering Engine:

    8. .gitignore Parsing: Dynamically fetches or reads .gitignore from the root of the repository and constructs a pathspec.PathSpec matcher utilizing gitwildmatch rules.
    9. Pattern Matching: Evaluates user-defined include_patterns and exclude_patterns using Unix shell-style wildcards (fnmatch.fnmatch).

    10. Size & Binary Guardrails: Enforces a strict byte-size ceiling (max_file_size) and catches binary encoding exceptions (UnicodeDecodeError, ValueError) to protect downstream LLM token context windows.

    11. Resilient Rate Limiting & Telemetry:

    12. Monitors GitHub API HTTP response headers for rate-limiting status codes (403, 429). When rate limits are encountered with authenticated sessions, it extracts X-RateLimit-Reset, sleeps until the reset epoch, and retries the operation.
    13. Integrates with utils.output (emit, emit_raw, get) to publish structured CLI events for file tracking, exclusions, directory skips, and summary tallies.

    def crawl_github_files(
    repo_url: str,
    token: str | None = None,
    max_file_size: int = 1 * 1024 * 1024,
    use_relative_paths: bool = False,
    include_patterns: str | set[str] | None = None,
    exclude_patterns: str | set[str] | None = None,
) -> dict:

    Description:
    Coordinates the entire extraction lifecycle for remote GitHub repositories. It sanitizes input patterns, identifies the transport mechanism (SSH local clone vs. HTTPS REST API), handles authentication and rate limiting, executes file filtering against gitignore specifications and glob patterns, and returns a dictionary of valid text files alongside ingest statistics.

    Parameters: * repo_url (str): Target repository URL. Can be an SSH clone address (git@github.com:org/repo.git), a standard HTTPS URL (https://github.com/org/repo), or a deep link to a specific commit/branch and directory (https://github.com/org/repo/tree/branch_name/sub/dir). * token (str | None, optional): GitHub Personal Access Token (PAT). Required for private repositories and recommended for public repositories to elevate API rate limits from 60 to 5,000 requests per hour. Defaults to None. * max_file_size (int, optional): Upper file size limit in bytes. Files exceeding this threshold are skipped. Defaults to 1048576 (1 MB). * use_relative_paths (bool, optional): When True and crawling a subdirectory via deep links, strips the base path prefix so returned keys are relative to that subdirectory. Defaults to False. * include_patterns (str | set[str] | None, optional): Shell-style glob patterns specifying which file names to include (e.g., {"*.py", "*.md"}). Defaults to None (includes all files). * exclude_patterns (str | set[str] | None, optional): Shell-style glob patterns specifying file or directory paths to exclude. Defaults to None.

    Returns: * dict: A dictionary containing: * "files" (dict[str, str]): Mapping of repository relative paths to their raw text content. * "stats" (dict[str, Any]): Ingestion metrics, including "downloaded_count", "skipped_count", "skipped_files", "base_path", "include_patterns", "exclude_patterns", and optional transport source info ("source").

    Raises: * ValueError: Raised if repo_url cannot be parsed into valid GitHub owner and repository segments. * Exception: Raised if GitHub API rate limits are exceeded and no token is supplied to authenticate the session.

    if exclude_patterns and isinstance(exclude_patterns, str):

                "stats": {

                    "skipped_count": 0,

    The function normalizes include/exclude pattern arguments into Python sets to ensure fast and consistent membership testing. When an SSH URL is detected, it delegates execution to GitPython's git.Repo.clone_from() inside a managed temporary directory context manager, guaranteeing that all downloaded repository artifacts on disk are cleaned up upon function exit or error. If an HTTPS URL is provided, it parses URL path segments to initialize REST API traversal.

    should_include_file()

    Visibility: Private (Nested Helper inside crawl_github_files)
    Signature: 

    def should_include_file(
    file_path: str,
    file_name: str,
    gitignore_spec: pathspec.PathSpec | None = None
) -> bool

    Description:
    Evaluates whether a candidate file should be ingested or ignored based on a three-tier predicate evaluation: inclusion pattern matching, .gitignore rule conformance, and exclusion pattern matching.

    Parameters: * file_path (str): Relative repository path of the file (e.g., src/utils/parser.py). * file_name (str): Basename of the file (e.g., parser.py). * gitignore_spec (pathspec.PathSpec | None, optional): Compiled pathspec instance representing active .gitignore rules. Defaults to None.

    Returns: * bool: True if the file satisfies all inclusion criteria and violates no exclusion or gitignore rules; False otherwise.

    # Implementation from utils/crawl_github_files.py
    def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:
        """Determine if a file should be included based on patterns"""
        # If no include patterns are specified, include all files
        if not include_patterns:
            include_file = True
        else:
            # Check if file matches any include pattern
            include_file = any(fnmatch.fnmatch(file_name, pattern) for pattern in include_patterns)

        # Check gitignore if provided
        if include_file and gitignore_spec and gitignore_spec.match_file(file_path):
            return False

        # If exclude patterns are specified, check if file should be excluded
        if exclude_patterns and include_file:
            # Exclude if file matches any exclude pattern
            exclude_file = any(fnmatch.fnmatch(file_path, pattern) for pattern in exclude_patterns)
            return not exclude_file

        return include_file

    The function prioritizes include patterns by matching file_name against include_patterns via fnmatch.fnmatch. If the file matches (or if no include patterns are configured), it passes the full file_path to gitignore_spec.match_file(). If the path is not ignored by git rules, it performs a final check against exclude_patterns. This multi-stage check prevents downloading or reading unnecessary test files, build artifacts, or secret configurations.

    Example: 

    # Execution inside crawl_github_files SSH walker
if not should_include_file(rel_path, filename, gitignore_spec=gitignore_spec):
    count_excluded += 1
    emit("CRAWL_FILE_EXCLUDED", num=entry_num, path=rel_path)
    continue

    fetch_branches()

    Visibility: Private (Nested Helper inside crawl_github_files)
    Signature: 

    def fetch_branches(owner: str, repo: str) -> list[dict]

    Description:
    Executes an HTTP GET request against the GitHub REST API endpoint /repos/{owner}/{repo}/branches to enumerate all remote branch heads. This enables the crawler to identify complex multi-segment branch names embedded in deep-link URLs.

    Parameters: * owner (str): Repository owner username or organization. * repo (str): Repository name.

    Returns: * list[dict]: List of branch metadata objects returned by GitHub, or an empty list [] if the request fails, the repository is missing, or permissions are insufficient.

    Raises: * Exception: Raised if a rate-limiting response code (403 or 429) is received when no authorization token is configured.

    # Implementation from utils/crawl_github_files.py
    def fetch_branches(owner: str, repo: str):
        """Get branches of the repository"""

        url = f"https://api.github.com/repos/{owner}/{repo}/branches"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        if response.status_code == 404:
            if not token:
                emit_raw(
                    "ERROR",
                    "Error 404: Repository not found or is private.\n"
                    "If this is a private repository, please provide a valid GitHub token via the 'token' argument or set the GITHUB_TOKEN environment variable.",
                )
            else:
                emit_raw(
                    "ERROR",
                    "Error 404: Repository not found or insufficient permissions with the provided token.\n"
                    "Please verify the repository exists and the token has access to this repository.",
                )
            return []

        if response.status_code != 200:
            emit_raw("ERROR", f"Error fetching the branches of {owner}/{repo}: {response.status_code} - {response.text}")
            return []

        return response.json()

    The function applies a dual connection and read timeout of (30, 30) seconds. If a 404 Not Found error is returned, it inspects whether a token was present to output contextual error messages differentiating between private repositories and invalid repository identifiers.

    Example: 

    # Resolution logic within crawl_github_files URL parsing
branches = fetch_branches(owner, repo)
branch_names = (branch.get("name") for branch in branches)

    def check_tree(owner: str, repo: str, tree: str) -> bool

    Description:
    Performs a lightweight verification request against the GitHub Git Data API /repos/{owner}/{repo}/git/trees/{tree} to determine whether a given URL segment represents a valid Git tree or commit SHA.

    Parameters: * owner (str): Repository owner username or organization. * repo (str): Repository name. * tree (str): Git commit SHA, tree SHA, or branch reference string.

    Returns: * bool: True if GitHub returns status code 200 confirming tree existence; False otherwise.

    # Implementation from utils/crawl_github_files.py
    def check_tree(owner: str, repo: str, tree: str):
        """Check the repository has the given tree"""

        url = f"https://api.github.com/repos/{owner}/{repo}/git/trees/{tree}"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        return response.status_code == 200

    This helper handles deep links targeting specific immutable commit SHAs rather than named branch heads. It allows URL resolution to distinguish between directory paths and commit hashes when parsing URLs with arbitrary segment lengths.

    def fetch_contents(path: str) -> None

    Description:
    Recursively navigates the GitHub repository directory hierarchy starting at path via the /repos/{owner}/{repo}/contents/{path} endpoint. It inspects metadata for each entry, skips excluded directories and non-matching files, downloads file payloads via download_url or base64 decode, and populates the parent files dictionary.

    Parameters: * path (str): Repository path to fetch. Pass an empty string "" to begin traversal from the repository root.

    Returns: * None: Mutates the enclosing scope's files dictionary and updates api_counters in-place.

    Raises: * Exception: Raised when GitHub API rate limits are hit and no authentication token is available to wait for reset.

    # Implementation excerpt from utils/crawl_github_files.py
    def fetch_contents(path):
        """Fetch contents of the repository at a specific path and commit"""
        url = f"https://api.github.com/repos/{owner}/{repo}/contents/{path}"
        params = {"ref": ref} if ref is not None else {}

        response = requests.get(url, headers=headers, params=params, timeout=(30, 30))

        if response.status_code in (403, 429) and "rate limit exceeded" in response.text.lower():
            if not token:
                raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")
            reset_time = int(response.headers.get("X-RateLimit-Reset", 0))
            wait_time = max(reset_time - time.time(), 0) + 1
            emit_raw("WARNING", f"Rate limit exceeded. Waiting for {wait_time:.0f} seconds...")
            time.sleep(wait_time)
            return fetch_contents(path)

        if response.status_code != 200:
            # ... 404 and unexpected status error logging ...
            return None

        contents = response.json()
        if not isinstance(contents, list):
            contents = [contents]

        for item in contents:
            item_path = item["path"]
            # ... path relativization, file processing, dir recursion ...
        return None

    "stats": {

    Error Handling & Edge Cases

    Scenario Detection Mechanism Resolution / System Action
    Private Repository (Unauthenticated) HTTP 404 on API endpoint Emits an error explaining that private repositories require a GitHub token via --token or GITHUB_TOKEN.
    API Rate Limit Exceeded (With Token) HTTP 403/429 with "rate limit exceeded" Reads X-RateLimit-Reset, sleeps until the reset epoch, and retries the request.
    API Rate Limit Exceeded (No Token) HTTP 403/429 without Token Raises a descriptive Exception prompting the user to supply credentials.
    Binary / Non-UTF8 Files UnicodeDecodeError / ValueError on decode Increments count_non_text, skips the file, and logs CRAWL_FILE_NOT_TEXT.
    File Exceeds Size Limit file_size > max_file_size Increments count_size_limit, skips downloading the payload, and logs CRAWL_FILE_SIZE_LIMIT.
    Branch with Forward Slashes URL containing tree/feature/name Enumerates /branches to find the longest matching prefix before extracting the subdirectory path.
