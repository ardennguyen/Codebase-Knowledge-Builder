    crawl_github_files.py

    Source: utils/crawl_github_files.py

    Technical Overview

    The crawl_github_files.py module provides automated file extraction and directory ingestion capabilities for remote GitHub repositories. It supports two primary ingest workflows: shallow cloning via Git SSH protocol for repository URLs using SSH syntax, and targeted tree traversal over the GitHub REST API (v3) for HTTP/HTTPS repository URLs. The crawler enables surgical repository extraction by allowing callers to target specific commits, branches, and subdirectories while filtering files through inclusion glob patterns, exclusion patterns, file-size ceilings, and repository-level .gitignore rules.

    When operating in REST API mode, the module parses the provided GitHub URL, extracts repository identifiers (owner, repo), resolves branch names or Git tree object identifiers (SHAs), and fetches contents iteratively. For directory resources, it inspects directory names and relative paths against exclusion criteria before recursing. For file resources, it evaluates size metadata against max_file_size, selectively uses direct download URLs (download_url) or base64 API payloads, and decodes textual file contents while discarding non-text binary assets. When configured for SSH execution, it clones the repository into a temporary workspace, parses the local .gitignore rules with pathspec, walks the file system, and gathers text content before cleaning up temporary disk allocations.

    Diagnostic telemetry and localized console notifications are integrated throughout the traversal lifecycle via utils.output. Ingest operations track processed files, excluded paths, size violations, and non-text decode rejections, generating a consolidated execution summary upon task completion.

    Public API

    DEFAULT_MAX_FILE_SIZE

    Visibility: Public

    Signature: DEFAULT_MAX_FILE_SIZE = 1_048_576 # 1 MB

    Description: The default file size threshold (1,048,576 bytes / 1 Megabyte) applied to repository files during crawling. Any file exceeding this limit is skipped during traversal to avoid excessive memory consumption or token bloat.

    crawl_github_files()

    Visibility: Public

    Signature: 

    def crawl_github_files(
    repo_url,
    token=None,
    max_file_size: int = DEFAULT_MAX_FILE_SIZE,
    use_relative_paths: bool = False,
    include_patterns: str | set[str] | None = None,
    exclude_patterns: str | set[str] | None = None,
)

    Description: Crawls files from a designated path in a GitHub repository at a specific branch or commit hash. It determines whether to perform a temporary local clone via Git SSH or to query the GitHub REST API based on the format of repo_url. Traversal filters file entries using include_patterns, exclude_patterns, .gitignore specifications, and max_file_size, decoding all text contents into an in-memory dictionary.

    The execution workflow is structured into six sequential phases:

    1. Input Normalization and Pattern Sanitization: Converts string-based inclusion and exclusion patterns into standard sets and determines protocol routing.
    2. SSH Repository Cloning and Local Tree Traversal: Clones SSH repositories to a temporary directory, parses the local .gitignore, and traverses files on disk.
    3. GitHub URL Parsing and Target Ref Resolution: Decomposes HTTPS URLs into repository components and verifies branch names or tree commit SHAs.
    4. Remote .gitignore Retrieval and Rule Parsing: Retrieves the remote .gitignore through the GitHub API and compiles gitwildmatch rules using pathspec.
    5. Recursive REST Directory Traversal and File Fetching: Walks the repository hierarchy remotely, applies directory exclusion filters, validates file sizes, and extracts content.
    6. Summary Telemetry and Return Assembly: Compiles traversal metrics into console events and packages the file contents and crawl metadata into a return dictionary.

It establishes the nested filter helper should_include_file, which sequentially applies positive glob matching against file names, negative pattern evaluation against .gitignore specifications, and explicit exclusion patterns against the relative file path. Finally, it checks the syntax of repo_url to select between the SSH execution path and the REST API execution path.

    Phase 2 executes when an SSH URL is detected. It provisions an isolated temporary directory via tempfile.TemporaryDirectory() and clones the repository using GitPython's git.Repo.clone_from(). If an exception occurs during cloning, it emits an error event and immediately returns an error structure. When the clone succeeds, it locates and loads .gitignore rules using pathspec, walks the file tree using os.walk(), and dynamically prunes ignored or excluded directories from dirs in-place. For individual files, it verifies pattern inclusion, validates size thresholds against max_file_size, and reads text content using utf-8-sig encoding, capturing UnicodeDecodeError or ValueError exceptions to categorize non-text binary assets.

Once the Git reference (ref) is identified, any trailing path segments are assembled into specific_path, defining the subdirectory within the repository where crawling should begin.

    Phase 6 compiles traversal metrics from either the REST execution counters or the SSH loop variables.     Parameters:

    • repo_url (str): Full URL of the GitHub repository, optionally containing branch, commit, and subdirectory paths (e.g., 'https://github.com/microsoft/autogen/tree/e45a15766746d95f8cfaaa705b0371267bec812e/python/packages/autogen-core/src/autogen_core' or an SSH URL like 'git@github.com:owner/repo.git').

    Returns:

    • dict | None: A dictionary containing extracted file contents under "files" and operational statistics under "stats", or None if branch/tree resolution failed.

    Raises:

    • ValueError: Raised if repo_url is an invalid HTTP GitHub URL with fewer than two path segments (owner and repository).
    • Exception: Raised if GitHub API rate limits (HTTP 403 or 429) are encountered when no authentication token is provided.

    def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool

    Description: Evaluates whether a candidate file should be ingested or skipped based on glob inclusion patterns, .gitignore path specifications, and exclusion patterns. Inclusion patterns check only the file's basename, whereas .gitignore specifications and exclusion patterns evaluate the repository-relative file path.

        def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:
        """Determine if a file should be included based on patterns"""
        # If no include patterns are specified, include all files
        if not include_patterns:
            include_file = True
        else:
            # Check if file matches any include pattern
            include_file = any(fnmatch.fnmatch(file_name, pattern) for pattern in include_patterns)

        # Check gitignore if provided
        if include_file and gitignore_spec and gitignore_spec.match_file(file_path):
            return False

        # If exclude patterns are specified, check if file should be excluded
        if exclude_patterns and include_file:
            # Exclude if file matches any exclude pattern
            exclude_file = any(fnmatch.fnmatch(file_path, pattern) for pattern in exclude_patterns)
            return not exclude_file

        return include_file

    The function executes three filtering stages. First, if include_patterns is populated, it tests the basename file_name against each glob with fnmatch.fnmatch. If the file matches (or if no include patterns exist), it consults gitignore_spec.match_file(file_path) if a compiled gitignore rule set was provided. Finally, if the file passes gitignore inspection, it evaluates exclude_patterns against file_path. If any exclude pattern matches, the file is rejected.

    Parameters:

    • file_path (str): Relative path of the candidate file within the repository.
    • file_name (str): Basename of the file (e.g., main.py).
    • gitignore_spec (pathspec.PathSpec | None): Compiled PathSpec matcher representing repository .gitignore rules, or None.

    Returns:

    • bool: True if the file passes all inclusion criteria, is not ignored by gitignore, and does not match any exclusion pattern; otherwise False.

    def fetch_branches(owner: str, repo: str)

    Description: Dispatches an HTTP GET request to the GitHub REST API to list all branches in the specified repository. Used to determine whether a URL path segment refers to a valid branch name.

        def fetch_branches(owner: str, repo: str):
        """Get branches of the repository"""

        url = f"https://api.github.com/repos/{owner}/{repo}/branches"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        if response.status_code == 404:
            if not token:

                )
            else:
                emit_raw(
                    "ERROR",
                    "Error 404: Repository not found or insufficient permissions with the provided token.\n"
                    "Please verify the repository exists and the token has access to this repository.",

        if response.status_code != 200:
            emit_raw("ERROR", f"Error fetching the branches of {owner}/{repo}: {response.status_code} - {response.text}")

        return response.json()

    fetch_contents()

    Visibility: Private (nested inside crawl_github_files)

    Signature: 

    def fetch_contents(path)

    Description: Recursively retrieves files and directory listings from the GitHub REST API at the specified directory path. Downloads file contents, applies exclusion and gitignore rules, validates file size thresholds, decodes textual payloads, and recurses into child directories.

        def fetch_contents(path):
        """Fetch contents of the repository at a specific path and commit"""
        url = f"https://api.github.com/repos/{owner}/{repo}/contents/{path}"
        params = {"ref": ref} if ref is not None else {}

        response = requests.get(url, headers=headers, params=params, timeout=(30, 30))

        if response.status_code in (403, 429) and "rate limit exceeded" in response.text.lower():
            if not token:
                raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")
            reset_time = int(response.headers.get("X-RateLimit-Reset", 0))
            wait_time = max(reset_time - time.time(), 0) + 1
            emit_raw("WARNING", f"Rate limit exceeded. Waiting for {wait_time:.0f} seconds...")
            time.sleep(wait_time)
            return fetch_contents(path)

        if response.status_code == 404:
            if not token:
                emit_raw(
                    "ERROR",
                    "Error 404: Repository not found or is private.\n"
                    "If this is a private repository, please provide a valid GitHub token via the 'token' argument or set the GITHUB_TOKEN environment variable.",
                )
            elif not path and ref == "main":
                emit_raw(
                    "ERROR",
                    "Error 404: Repository not found. Check if the default branch is not 'main'\n"
                    "Try adding branch name to the request i.e. python main.py --repo https://github.com/username/repo/tree/master",
                )
            else:
                emit_raw(
                    "ERROR",
                    f"Error 404: Path '{path}' not found in repository or insufficient permissions with the provided token.\n"
                    f"Please verify the token has access to this repository and the path exists.",
                )
            return None

        if response.status_code != 200:
            emit_raw("ERROR", f"Error fetching {path}: {response.status_code} - {response.text}")
            return None

        contents = response.json()

        # Handle both single file and directory responses
        if not isinstance(contents, list):
            contents = [contents]

        for item in contents:
            item_path = item["path"]

            # Calculate relative path if requested
            if use_relative_paths and specific_path:
                # Make sure the path is relative to the specified subdirectory
                if item_path.startswith(specific_path):
                    rel_path = item_path[len(specific_path) :].lstrip("/")
                else:
                    rel_path = item_path
            else:
                rel_path = item_path

            if item["type"] == "file":
                api_counters["entry"] += 1
                entry_num = api_counters["entry"]

                # Check if file should be included based on patterns
                if not should_include_file(rel_path, item["name"], gitignore_spec=gitignore_spec):
                    api_counters["excluded"] += 1
                    emit("CRAWL_FILE_EXCLUDED", num=entry_num, path=rel_path)
                    continue

                # Check file size if available
                file_size = item.get("size", 0)
                if file_size > max_file_size:
                    api_counters["size_limit"] += 1
                    api_skipped_size.append(rel_path)
                    size_kb = file_size / 1024
                    emit("CRAWL_FILE_SIZE_LIMIT", num=entry_num, path=rel_path, size=f"{size_kb:.0f}")
                    continue

                # For files, get raw content
                if item.get("download_url"):
                    file_url = item["download_url"]
                    file_response = requests.get(file_url, headers=headers, timeout=(30, 30))

                    # Final size check in case content-length header is available but differs from metadata
                    content_length = int(file_response.headers.get("content-length", 0))
                    if content_length > max_file_size:
                        api_counters["size_limit"] += 1
                        api_skipped_size.append(rel_path)
                        size_kb = content_length / 1024
                        emit("CRAWL_FILE_SIZE_LIMIT", num=entry_num, path=rel_path, size=f"{size_kb:.0f}")
                        continue

                    if file_response.status_code == 200:
                        files[rel_path] = file_response.text
                        api_counters["processed"] += 1
                        emit("CRAWL_FILE_PROCESSED", num=entry_num, path=rel_path)
                    else:
                        api_counters["non_text"] += 1
                        api_skipped_non_text.append(rel_path)
                        emit("CRAWL_FILE_HTTP_ERROR", num=entry_num, path=rel_path, status=file_response.status_code)
                else:
                    # Alternative method if download_url is not available
                    content_response = requests.get(item["url"], headers=headers, timeout=(30, 30))
                    if content_response.status_code == 200:
                        content_data = content_response.json()
                        if content_data.get("encoding") == "base64" and "content" in content_data:
                            # Check size of base64 content before decoding
                            if len(content_data["content"]) * 0.75 > max_file_size:  # Approximate size calculation
                                estimated_size = int(len(content_data["content"]) * 0.75)
                                api_counters["size_limit"] += 1
                                api_skipped_size.append(rel_path)
                                size_kb = estimated_size / 1024
                                emit("CRAWL_FILE_SIZE_LIMIT", num=entry_num, path=rel_path, size=f"{size_kb:.0f}")
                                continue

                            file_content = base64.b64decode(content_data["content"]).decode("utf-8")
                            files[rel_path] = file_content
                            api_counters["processed"] += 1
                            emit("CRAWL_FILE_PROCESSED", num=entry_num, path=rel_path)
                        else:
                            api_counters["non_text"] += 1
                            api_skipped_non_text.append(rel_path)
                            emit("CRAWL_FILE_UNEXPECTED", num=entry_num, path=rel_path)
                    else:
                        api_counters["non_text"] += 1
                        api_skipped_non_text.append(rel_path)
                        emit("CRAWL_FILE_HTTP_ERROR", num=entry_num, path=rel_path, status=content_response.status_code)

            elif item["type"] == "dir":
                # Check if directory should be excluded before recursing
                dir_excluded = False
                dir_reason = None

                if gitignore_spec and gitignore_spec.match_file(rel_path):
                    dir_excluded = True
                    dir_reason = get("CRAWL_REASON_GITIGNORE")

                if not dir_excluded and exclude_patterns:
                    dir_name = item["name"]  # basename of the directory
                    for pattern in exclude_patterns:
                        dir_pattern = pattern.removesuffix("/*")
                        if (
                            fnmatch.fnmatch(item_path, dir_pattern)
                            or fnmatch.fnmatch(rel_path, dir_pattern)
                            or fnmatch.fnmatch(dir_name, dir_pattern)
                        ):
                            dir_excluded = True
                            dir_reason = get("CRAWL_REASON_EXCLUDED")
                            break

                if dir_excluded:
                    api_counters["entry"] += 1
                    api_counters["excluded"] += 1
                    emit("CRAWL_DIR_EXCLUDED", num=api_counters["entry"], path=rel_path, reason=dir_reason)
                    continue

                # Only recurse if directory is not excluded
                fetch_contents(item_path)

        return None

    The function contacts the GitHub API endpoint /repos/{owner}/{repo}/contents/{path}. It automatically backs off and sleeps if secondary rate limits or standard limits are hit with a valid token, retrying upon expiration. For each entry in the received directory listing, it computes relative paths according to use_relative_paths. For file nodes, it validates patterns and size constraints, preferring direct raw CDN downloads via download_url, but falling back to base64 decoding of the API payload when download_url is absent. For directory nodes, it checks both gitignore rules and directory-level exclusion globs (stripping trailing /*) before triggering recursive calls to fetch_contents().

    Error Handling

    The module implements distinct error-handling strategies depending on whether operations occur over local disk abstractions or remote HTTP network transports:

    • URL Validation: If repo_url is an HTTP URL that fails to yield at least an owner and repository component when split by path delimiters (len(path_parts) < 2), a ValueError is raised immediately.
    • Rate Limit Handling:
      • Unauthenticated Calls: When requests to GitHub REST endpoints return HTTP status 403 or 429 indicating rate limits, an Exception is raised notifying the user that a token must be provided via --token or the GITHUB_TOKEN environment variable.
      • Authenticated Calls: When rate limits occur with a configured token, fetch_contents() inspects the X-RateLimit-Reset HTTP header, calculates the wait delta until quota replenishment (reset_time - time.time() + 1), logs a warning via emit_raw(), sleeps via time.sleep(), and retries the request recursively.
    • Missing Repositories and Authentication (HTTP 404): When GitHub returns HTTP 404 during branch lookups, tree checks, or content fetching, the module distinguishes between unauthenticated runs (suggesting the repository may be private and requiring a token) and authenticated runs (indicating missing permissions or incorrect branch names like main vs master).
    • SSH Clone Failure: Errors during git.Repo.clone_from() are caught via a generic Exception handler, logged via emit_raw("ERROR", ...), and returned as an error dictionary ({"files": {}, "stats": {"error": str(e)}}) rather than terminating the process.
    • Encoding and Binary Fallbacks: During both SSH local disk reads and REST API payload decoding, character decoding failures (UnicodeDecodeError, ValueError) are trapped. The problematic files are categorized as non-text assets, appended to skipped lists, and omitted from the returned files dictionary.
    • Gitignore Ingestion Resilience: Remote and local .gitignore ingestion is wrapped in try...except Exception: pass blocks, ensuring that malformed gitignore files or network errors do not prevent repository crawling.
