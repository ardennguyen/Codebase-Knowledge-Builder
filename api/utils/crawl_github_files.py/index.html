    crawl_github_files.py

    Source: utils/crawl_github_files.py

    Following the inference abstraction layer established in call_llm.py, utils/crawl_github_files.py provides the ingestion gateway for external source code hosted on GitHub. While call_llm.py transforms tokenized context into architectural documentation, this module is responsible for discovering, fetching, filtering, and sanitizing the source files that form that prompt context.

    Technical Overview

    utils/crawl_github_files.py automates the extraction of source files from remote GitHub repositories. It serves as one of two repository intake mechanisms in the pipeline (alongside local filesystem crawling). The module handles diverse remote repository topologies, supporting arbitrary branches, specific commit SHAs, sub-directory paths, and private repository authentication.

    The module implements a dual-mode ingestion strategy determined by repository protocol: 1. SSH Git Clone Execution Engine: When provided with SSH URLs (git@... or ending in .git), the module uses GitPython (git.Repo.clone_from) to perform an ephemeral clone into an isolated tempfile.TemporaryDirectory. It traverses the cloned filesystem on disk using os.walk, respecting .gitignore patterns and custom inclusion/exclusion filters. 2. GitHub REST API v3 Engine: When provided with standard HTTP(S) GitHub URLs, the module uses the GitHub REST API (/repos/{owner}/{repo}/contents/{path}). It resolves tree references, recursively walks repository directories over HTTP, dynamically decodes base64-encoded blobs or streams raw downloads, tracks rate limits, and backs off automatically using X-RateLimit-Reset telemetry.

    Both engines enforce bounded resource usage by validating file sizes before download, rejecting non-UTF-8 binary assets, compiling .gitignore definitions into pathspec.PathSpec rules, and streaming structured events to utils/output.py.

        def fetch_branches(owner: str, repo: str):
        """Get branches of the repository"""

        url = f"https://api.github.com/repos/{owner}/{repo}/branches"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        if response.status_code == 404:
            if not token:
                emit_raw(
                    "ERROR",
                    "Error 404: Repository not found or is private.\n"
                    "If this is a private repository, please provide a valid GitHub token via the 'token' argument or set the GITHUB_TOKEN environment variable.",
                )
            else:
                emit_raw(
                    "ERROR",
                    "Error 404: Repository not found or insufficient permissions with the provided token.\n"
                    "Please verify the repository exists and the token has access to this repository.",
                )
            return []

        if response.status_code != 200:
            emit_raw("ERROR", f"Error fetching the branches of {owner}/{repo}: {response.status_code} - {response.text}")
            return []

        return response.json()

On HTTP 404, it inspects whether a token was supplied to emit targeted diagnostics, differentiating between nonexistent repositories and insufficient authorization for private repositories.

    Returns: * list[dict]: Deserialized JSON list containing branch metadata dictionaries, or an empty list upon failure.

    Data Structures

    Crawl Result Dictionary

    The return payload produced by crawl_github_files follows a two-key dictionary schema:

    Field Type Description
    files dict[str, str] Key-value store mapping normalized repository file paths to UTF-8 file contents.
    stats dict[str, Any] Detailed telemetry and filter metadata tracking operation results.

    stats Sub-Dictionary Schema

    Field Type Description Example
    downloaded_count int Total number of files successfully read and stored. 42
    skipped_count int Total files bypassed (used in local crawl parity; initialized to 0). 0
    skipped_files list[str] List of paths skipped during ingestion. []
    base_path str \| None Root sub-path trimmed when use_relative_paths is enabled. "src/core"

    Error Handling

    The module implements multi-tiered error handling to address network, authentication, and file decoding issues across both crawling engines:

    API Rate Limit Throttling

    GitHub limits unauthenticated API requests to 60 per hour, while authenticated requests receive 5,000 per hour. When the API returns an HTTP 403 or 429 status code indicating rate limits: * Unauthenticated Requests: Execution halts immediately with an Exception instructing the user to configure a GITHUB_TOKEN. * Authenticated Requests: The module extracts the X-RateLimit-Reset Unix epoch timestamp, calculates the sleep duration (reset_time - time.time() + 1), logs a warning, and blocks via time.sleep before retrying the failed request.

    HTTP 404 Disambiguation

    The module provides contextual diagnostics for HTTP 404 responses: 1. Unauthenticated 404: Recommends supplying a GITHUB_TOKEN in case the target repository is private. 2. Authenticated 404 on Root (ref == "main"): Warns that the default branch may be master rather than main, advising explicit branch declaration. 3. Subpath 404: Distinguishes between nonexistent file paths and insufficient token permissions.

    Binary and Non-UTF-8 Rejection

    The crawler exclusively ingests text-based source code: * In the SSH engine, files are decoded using the utf-8-sig codec. Catches for UnicodeDecodeError and ValueError increment count_non_text and append the path to skipped_non_text_list without halting directory traversal. * In the REST API engine, payload sizes are validated against max_file_size prior to base64 decoding (using a len(content) * 0.75 size heuristic). Any decoding failure logs CRAWL_FILE_HTTP_ERROR or CRAWL_FILE_UNEXPECTED and skips the entry.
