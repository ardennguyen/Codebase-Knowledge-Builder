    crawl_github_files.py

    Source: utils/crawl_github_files.py

    Following the inference client architecture documented in call_llm.py, the crawl_github_files.py module provides the remote source repository ingestion engine for Codebase-Knowledge-Builder. While call_llm.py orchestrates interaction with multi-provider generative models, crawl_github_files.py is responsible for fetching, filtering, and preparing the raw codebase text assets from GitHub repositories before the AST and documentation extraction pipelines begin.

    Technical Overview

    crawl_github_files.py provides a dual-mode ingestion engine capable of extracting directory hierarchies and file contents from remote GitHub repositories. It accommodates two operational access patterns:

    1. Git-over-SSH / Local Temp Directory Clone: Invoked when SSH repository URLs (e.g., git@github.com:... or URLs ending in .git) are detected. This mode uses GitPython to perform an ephemeral shallow clone into a system temporary directory created via tempfile.TemporaryDirectory. It traverses the local filesystem snapshot using os.walk, parses repository-level .gitignore rules via pathspec, and filters files according to size thresholds and include/exclude glob rules.
    2. GitHub REST API v3 Crawler: Invoked for HTTPS repository URLs (e.g., https://github.com/owner/repo/tree/branch/subpath). It recursively traverses repository trees using GitHub's REST API /repos/{owner}/{repo}/contents/{path} endpoints. This mode dynamically resolves branch and commit tree identifiers, respects API rate limits via HTTP 403/429 inspection and automatic sleep backoff, fetches .gitignore definitions directly from remote tree roots, and retrieves file contents through direct download URLs (raw.githubusercontent.com) or Base64-encoded JSON payloads.

    Both traversal pathways converge on a standardized data dictionary containing sanitized relative file paths and UTF-8 decoded string contents, accompanied by crawl execution statistics and terminal telemetry dispatched through utils.output.

    should_include_file()

    Visibility: Private (Internal helper defined within crawl_github_files)
    Signature: def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:

    Description:
    Evaluates whether a candidate file should be ingested into the repository map. The evaluation follows a three-stage filter hierarchy: 1. Include Glob Check: If include_patterns is defined, the base filename must match at least one pattern via fnmatch.fnmatch. If not matched, the file is rejected immediately. 2. Gitignore Pattern Check: If a compiled pathspec.PathSpec object is provided, the full relative file path is checked against gitignore rules. If matched, the file is rejected. 3. Exclude Glob Check: If exclude_patterns is defined, the full relative file path is matched against all exclusion globs. If matched, the file is rejected.

    If the candidate file passes all three checks, the function returns True.

    Parameters: * file_path (str): Relative repository path of the file (e.g., src/core/parser.py). * file_name (str): Base filename component (e.g., parser.py). * gitignore_spec (pathspec.PathSpec | None, optional): Compiled gitignore path specification engine. Defaults to None.

    Returns: * bool: True if the file passes all inclusion filters and avoids all exclusion/gitignore rules; False otherwise.

        def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:
        """Determine if a file should be included based on patterns"""
        # If no include patterns are specified, include all files
        if not include_patterns:
            include_file = True
        else:
            # Check if file matches any include pattern
            include_file = any(fnmatch.fnmatch(file_name, pattern) for pattern in include_patterns)

        # Check gitignore if provided
        if include_file and gitignore_spec and gitignore_spec.match_file(file_path):
            return False

        # If exclude patterns are specified, check if file should be excluded
        if exclude_patterns and include_file:
            # Exclude if file matches any exclude pattern
            exclude_file = any(fnmatch.fnmatch(file_path, pattern) for pattern in exclude_patterns)
            return not exclude_file

        return include_file

    The function executes pattern matching against two distinct path representations: include_patterns evaluates against file_name (allowing simple filters like *.py), whereas exclude_patterns and gitignore_spec evaluate against file_path to support deep structural exclusions (e.g., tests/* or docs/build/*). Short-circuit boolean evaluation prevents unnecessary regex or glob matching if an upstream check fails.

        def fetch_branches(owner: str, repo: str):
        """Get branches of the repository"""

        url = f"https://api.github.com/repos/{owner}/{repo}/branches"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        if response.status_code == 404:
            if not token:
                emit_raw(
                    "ERROR",
                    "Error 404: Repository not found or is private.\n"
                    "If this is a private repository, please provide a valid GitHub token via the 'token' argument or set the GITHUB_TOKEN environment variable.",
                )
            else:
                emit_raw(
                    "ERROR",
                    "Error 404: Repository not found or insufficient permissions with the provided token.\n"
                    "Please verify the repository exists and the token has access to this repository.",
                )
            return []

        if response.status_code != 200:
            emit_raw("ERROR", f"Error fetching the branches of {owner}/{repo}: {response.status_code} - {response.text}")
            return []

        return response.json()

    The function incorporates defensive HTTP connection timeouts of (30, 30) seconds (connect/read) to prevent network deadlocks. It inspects 404 responses to issue context-aware error alerts through emit_raw, distinguishing between unauthenticated private repository requests and token permission failures.

        relevant_path = join_parts(3)

        # Find a match with relevant path and get the branch name
        filter_gen = (name for name in branch_names if relevant_path.startswith(name))
        ref = next(filter_gen, None)

        # If match is not found, check for is it a tree
        if ref is None:
            tree = path_parts[3]
            ref = tree if check_tree(owner, repo, tree) else None

        if ref is None:
            emit_raw("ERROR", "The given path does not match with any branch and any tree in the repository.\nPlease verify the path is exists.")
            return None

        # Combine all parts after the ref as the path
        part_index = 5 if "/" in ref else 4
        specific_path = join_parts(part_index) if part_index < len(path_parts) else ""
    else:
        ref = None
        specific_path = ""

    Because branch names may contain slashes (e.g., release/v2.0), simple index slicing against /tree/ is insufficient. The resolver queries all repository branch names via fetch_branches() and finds the branch that matches the prefix of the trailing path components (relevant_path.startswith(name)). If no branch matches, it treats path_parts[3] as a candidate commit SHA and verifies it via check_tree(). Once ref is identified, remaining path tokens are joined to construct specific_path.

    Data Structures & Schemas

    Return Payload Dictionary

    {
    "files": dict[str, str], # Mapping of normalized repository relative path to file text content
    "stats": {
        "downloaded_count": int,           # Count of successfully ingested text files
        "skipped_count": int,              # Files skipped (always 0; tracked via category lists)
        "skipped_files": list[str],        # Files skipped by explicit policy
        "base_path": str | None,           # Subdirectory path if relative path mapping was enabled
        "include_patterns": set[str] | None, # Include filter set used during crawl
        "exclude_patterns": set[str] | None, # Exclude filter set used during crawl
        "source": str                      # "ssh_clone" if cloned via Git SSH; omitted in REST mode
    }
}

    Crawl Execution Metric Schema

    Both SSH and API crawl modes track entry counters to provide terminal feedback via utils.output.emit: 

    # API Crawler Metric Registry
api_counters = {
    "processed": int,   # Successfully read and stored text files
    "excluded": int,    # Files/directories skipped due to glob patterns or gitignore
    "size_limit": int,  # Files rejected due to max_file_size limit
    "non_text": int,    # Files skipped due to binary encoding or HTTP read errors
    "entry": int        # Total sequence counter for all encountered nodes
}

    import os
