    crawl_github_files.py

    Source: utils/crawl_github_files.py

    Technical Overview

    Following the core inference gateway established in call_llm.py, utils/crawl_github_files.py serves as the primary remote code ingestion engine for the knowledge-building pipeline. Its principal responsibility is to ingest source code repositories hosted on GitHub—either via direct SSH cloning or through authenticated/unauthenticated GitHub REST API v3 traversals—and convert them into an in-memory mapping of relative file paths to decoded text contents. This data structure forms the foundational raw input consumed by downstream token counting, code graph construction, and model-driven document synthesis nodes.

    The module implements a dual-path retrieval strategy determined by URL structure. If an SSH format or .git suffix is detected, the engine executes a shallow clone into an ephemeral temporary directory using GitPython, evaluates file inclusion via local .gitignore specifications and pattern filters, reads text streams, and removes the workspace upon completion. For standard HTTP(S) GitHub URLs, the engine invokes recursive tree queries over GitHub's REST API. It resolves repository references (branches, tags, or commit trees), fetches .gitignore rules dynamically from the remote ref, traverses directory contents, handles API rate limits via exponential backoff using X-RateLimit-Reset headers, downloads raw text payloads, and gracefully falls back to base64 decoding when raw download endpoints are unavailable.

    Both acquisition pathways enforce rigorous ingestion boundaries. Files exceeding max_file_size (defaulting to 1 MB), non-text binaries that raise decoding exceptions, and paths matching gitignore rules or user-provided exclusion patterns are filtered out. File progress and exclusion diagnostics are continuously broadcast across the application through utils/output.py.

    Description: Evaluates whether a given file path should be included in the crawl based on include patterns, .gitignore rules, and exclude patterns.

        def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:
        """Determine if a file should be included based on patterns"""
        # If no include patterns are specified, include all files
        if not include_patterns:
            include_file = True
        else:
            # Check if file matches any include pattern
            include_file = any(fnmatch.fnmatch(file_name, pattern) for pattern in include_patterns)

        # Check gitignore if provided
        if include_file and gitignore_spec and gitignore_spec.match_file(file_path):
            return False

        # If exclude patterns are specified, check if file should be excluded
        if exclude_patterns and include_file:
            # Exclude if file matches any exclude pattern
            exclude_file = any(fnmatch.fnmatch(file_path, pattern) for pattern in exclude_patterns)
            return not exclude_file

        return include_file
    The helper evaluates files using a multi-step filter chain. First, it matches file_name against include_patterns via fnmatch.fnmatch; if include_patterns is empty or None, the file passes by default. Next, if an active gitignore_spec is provided and matches the relative file_path, the file is rejected immediately. Finally, if exclude_patterns are defined, the method checks the relative file_path against each pattern; a match results in rejection. The file is accepted only if it satisfies all three filter stages.

    Parameters: * file_path (str): Relative path of the candidate file from the crawl root. * file_name (str): The basename of the file (used for include pattern evaluation). * gitignore_spec (pathspec.PathSpec | None, optional): Compiled gitignore spec instance. Defaults to None.

    Returns: * bool: True if the file passes all inclusion and exclusion checks; False otherwise.

        def fetch_branches(owner: str, repo: str):
        """Get branches of the repository"""

        url = f"https://api.github.com/repos/{owner}/{repo}/branches"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        if response.status_code == 404:
            if not token:
                emit_raw(
                    "ERROR",
                    "Error 404: Repository not found or is private.\n"
                    "If this is a private repository, please provide a valid GitHub token via the 'token' argument or set the GITHUB_TOKEN environment variable.",
                )
            else:
                emit_raw(
                    "ERROR",
                    "Error 404: Repository not found or insufficient permissions with the provided token.\n"
                    "Please verify the repository exists and the token has access to this repository.",
                )
            return []

        if response.status_code != 200:
            emit_raw("ERROR", f"Error fetching the branches of {owner}/{repo}: {response.status_code} - {response.text}")
            return []

        return response.json()
    The helper issues a synchronous GET request to /repos/{owner}/{repo}/branches with a 30-second timeout. If unauthenticated requests receive an HTTP 403 or 429 response, it raises an exception indicating that the rate limit was exceeded. For HTTP 404 responses, it distinguishes between unauthenticated requests (which may indicate a private repository) and authenticated requests with invalid tokens, logging the appropriate diagnostic via emit_raw(). When the response code is 200, it parses and returns the branch metadata payload as a list of dictionaries.

    Returns: * list[dict]: Parsed JSON list of branch descriptor objects (containing branch name, commit, etc.), or an empty list upon failure.

    Visibility: Private (Closure inside crawl_github_files) Signature: def fetch_contents(path: str) -> None:

    Description: Recursively queries the GitHub /contents/{path} API endpoint to traverse directories, download raw text file payloads, decode base64 representations, and populate the parent files dictionary.

    Phase 1: API Request and Rate-Limit Backoff Loop

        def fetch_contents(path):
        """Fetch contents of the repository at a specific path and commit"""
        url = f"https://api.github.com/repos/{owner}/{repo}/contents/{path}"
        params = {"ref": ref} if ref is not None else {}

        response = requests.get(url, headers=headers, params=params, timeout=(30, 30))

        if response.status_code in (403, 429) and "rate limit exceeded" in response.text.lower():
            if not token:
                raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")
            reset_time = int(response.headers.get("X-RateLimit-Reset", 0))
            wait_time = max(reset_time - time.time(), 0) + 1
            emit_raw("WARNING", f"Rate limit exceeded. Waiting for {wait_time:.0f} seconds...")
            time.sleep(wait_time)
            return fetch_contents(path)

        if response.status_code == 404:
            if not token:
                emit_raw(
                    "ERROR",
                    "Error 404: Repository not found or is private.\n"
                    "If this is a private repository, please provide a valid GitHub token via the 'token' argument or set the GITHUB_TOKEN environment variable.",
                )
            elif not path and ref == "main":
                emit_raw(
                    "ERROR",
                    "Error 404: Repository not found. Check if the default branch is not 'main'\n"
                    "Try adding branch name to the request i.e. python main.py --repo https://github.com/username/repo/tree/master",
                )
            else:
                emit_raw(
                    "ERROR",
                    f"Error 404: Path '{path}' not found in repository or insufficient permissions with the provided token.\n"
                    f"Please verify the token has access to this repository and the path exists.",
                )
            return None

        if response.status_code != 200:
            emit_raw("ERROR", f"Error fetching {path}: {response.status_code} - {response.text}")
            return None

        contents = response.json()
    The helper constructs the /contents/{path} endpoint, appending the ref query parameter if resolved. When rate limits occur, it parses the X-RateLimit-Reset response header to calculate the required sleep duration, pauses execution via time.sleep(), and retries the request. If the path does not exist, it analyzes the request context (token presence, default branch name) to emit helpful diagnostic messages before aborting the current traversal branch.

    Phase 2: Directory Child Iteration and Relative Path Resolution

        if not isinstance(contents, list):
            contents = [contents]

        for item in contents:
            item_path = item["path"]

            # Calculate relative path if requested
            if use_relative_paths and specific_path:
                # Make sure the path is relative to the specified subdirectory
                if item_path.startswith(specific_path):
                    rel_path = item_path[len(specific_path) :].lstrip("/")
                else:
                    rel_path = item_path
            else:
                rel_path = item_path
    GitHub's /contents/ endpoint returns a single dictionary when pointing directly to a file and a list of dictionaries when targeting a directory. The helper normalizes single dictionaries into a one-element list. It then computes rel_path for each child item by trimming specific_path prefixes when use_relative_paths is enabled.

    Phase 3: Raw File Download with Base64 Fallback

                if item["type"] == "file":
                api_counters["entry"] += 1
                entry_num = api_counters["entry"]

                # Check if file should be included based on patterns
                if not should_include_file(rel_path, item["name"], gitignore_spec=gitignore_spec):
                    api_counters["excluded"] += 1
                    emit("CRAWL_FILE_EXCLUDED", num=entry_num, path=rel_path)
                    continue

                # Check file size if available
                file_size = item.get("size", 0)
                if file_size > max_file_size:
                    api_counters["size_limit"] += 1
                    api_skipped_size.append(rel_path)
                    size_kb = file_size / 1024
                    emit("CRAWL_FILE_SIZE_LIMIT", num=entry_num, path=rel_path, size=f"{size_kb:.0f}")
                    continue

                # For files, get raw content
                if item.get("download_url"):
                    file_url = item["download_url"]
                    file_response = requests.get(file_url, headers=headers, timeout=(30, 30))

                    # Final size check in case content-length header is available but differs from metadata
                    content_length = int(file_response.headers.get("content-length", 0))
                    if content_length > max_file_size:
                        api_counters["size_limit"] += 1
                        api_skipped_size.append(rel_path)
                        size_kb = content_length / 1024
                        emit("CRAWL_FILE_SIZE_LIMIT", num=entry_num, path=rel_path, size=f"{size_kb:.0f}")
                        continue

                    if file_response.status_code == 200:
                        files[rel_path] = file_response.text
                        api_counters["processed"] += 1
                        emit("CRAWL_FILE_PROCESSED", num=entry_num, path=rel_path)
                    else:
                        api_counters["non_text"] += 1
                        api_skipped_non_text.append(rel_path)
                        emit("CRAWL_FILE_HTTP_ERROR", num=entry_num, path=rel_path, status=file_response.status_code)
                else:
                    # Alternative method if download_url is not available
                    content_response = requests.get(item["url"], headers=headers, timeout=(30, 30))
                    if content_response.status_code == 200:
                        content_data = content_response.json()
                        if content_data.get("encoding") == "base64" and "content" in content_data:
                            # Check size of base64 content before decoding
                            if len(content_data["content"]) * 0.75 > max_file_size:  # Approximate size calculation
                                estimated_size = int(len(content_data["content"]) * 0.75)
                                api_counters["size_limit"] += 1
                                api_skipped_size.append(rel_path)
                                size_kb = estimated_size / 1024
                                emit("CRAWL_FILE_SIZE_LIMIT", num=entry_num, path=rel_path, size=f"{size_kb:.0f}")
                                continue

                            file_content = base64.b64decode(content_data["content"]).decode("utf-8")
                            files[rel_path] = file_content
                            api_counters["processed"] += 1
                            emit("CRAWL_FILE_PROCESSED", num=entry_num, path=rel_path)
// ...
    For items marked as file, the helper verifies inclusion criteria and checks the file's reported size against max_file_size. If valid, it downloads the raw text using item["download_url"]. If download_url is missing, it falls back to requesting item["url"], which returns JSON containing base64-encoded file data. It estimates the payload size (len * 0.75) to avoid decoding oversized files, decodes the base64 content into UTF-8 text, and stores the resulting string in the files dictionary.

    Phase 4: Recursive Directory Traversal

                elif item["type"] == "dir":
                # Check if directory should be excluded before recursing
                dir_excluded = False
                dir_reason = None

                if gitignore_spec and gitignore_spec.match_file(rel_path):
                    dir_excluded = True
                    dir_reason = get("CRAWL_REASON_GITIGNORE")

                if not dir_excluded and exclude_patterns:
                    dir_name = item["name"]  # basename of the directory
                    for pattern in exclude_patterns:
                        dir_pattern = pattern.removesuffix("/*")
                        if (
                            fnmatch.fnmatch(item_path, dir_pattern)
                            or fnmatch.fnmatch(rel_path, dir_pattern)
                            or fnmatch.fnmatch(dir_name, dir_pattern)
                        ):
                            dir_excluded = True
                            dir_reason = get("CRAWL_REASON_EXCLUDED")
                            break

                if dir_excluded:
                    api_counters["entry"] += 1
                    api_counters["excluded"] += 1
                    emit("CRAWL_DIR_EXCLUDED", num=api_counters["entry"], path=rel_path, reason=dir_reason)
                    continue

                # Only recurse if directory is not excluded
                fetch_contents(item_path)

        return None
    When encountering an item with type == "dir", the function checks if the directory is matched by gitignore_spec or any entry in exclude_patterns. If excluded, it increments the exclusion counters, emits an exclusion log, and skips the directory. Otherwise, it makes a recursive call to fetch_contents(item_path) to crawl the subdirectory.

    Error Handling

    The module handles remote network failures, API constraints, and file system anomalies across both ingestion paths:

    GitHub REST API Rate Limiting (HTTP 403 / 429)

    • Unauthenticated Requests: If the API responds with HTTP 403 or 429 and no token was provided, the function raises an Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var."). This halts execution immediately to alert the operator.
    • Authenticated Requests with Backoff: When a token is present and the response contains "rate limit exceeded", the function reads the X-RateLimit-Reset HTTP header, calculates the wait time (max(reset_time - time.time(), 0) + 1), logs a warning via emit_raw(), sleeps using time.sleep(wait_time), and transparently retries fetch_contents().

    Missing Repositories and Reference Failures (HTTP 404)

    • Private vs Missing Repositories: On HTTP 404 responses, the engine checks whether a token was provided. If missing, it notes that the repository may be private and require authentication. If a token was provided, it reports that permissions are insufficient or the target path does not exist.
    • Default Branch Mismatches: If traversing the repository root on ref main returns a 404, the engine logs a suggestion to verify if the default branch is named master.

    Encoding Failures and Binary Detection

    • Cloned Repositories: During local filesystem reads, file opens specify encoding="utf-8-sig". If reading raises UnicodeDecodeError or ValueError, the engine catches the exception, classifies the file as non-text, increments count_non_text, and continues traversing without failing.
    • API Ingestion: Files downloaded without a download_url fallback to base64 decoding via base64.b64decode(). If the decoded bytes cannot be parsed as UTF-8, or if the JSON payload lacks expected content structures, the file is logged as non-text and safely skipped.

    Git Clone Faults

    • During the SSH clone workflow, calls to git.Repo.clone_from() are wrapped in a generic try...except Exception block. If cloning fails (due to invalid host keys, unauthenticated SSH tokens, or network drops), the error is intercepted, logged via emit_raw("ERROR", ...), and returned safely in the stats dictionary: {"files": {}, "stats": {"error": str(e)}}.
