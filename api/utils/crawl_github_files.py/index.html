    crawl_github_files.py

    Source: utils/crawl_github_files.py

    Technical Overview

    The utils/crawl_github_files.py module provides content retrieval mechanisms for extracting source code trees and individual files from remote GitHub repositories. It supports targeting specific subdirectories, branches, or Git tree commit hashes. The module acts as an ingestion adapter for upstream documentation workflows, allowing the documentation generator to operate directly on remote repositories without requiring manual cloning or external repository staging.

    The retrieval pipeline provides two execution strategies determined by the repository URL scheme: 1. SSH Git Clone Strategy: When provided an SSH URL (prefixed with git@ or suffixed with .git), the module provisions an isolated local temporary directory via tempfile.TemporaryDirectory and executes a Git clone using git.Repo.clone_from. It traverses the cloned filesystem using os.walk, honors .gitignore rules via pathspec, enforces size caps, filters excluded paths, and reads text files encoded in utf-8-sig. 2. GitHub REST API Strategy: When provided an HTTP or HTTPS GitHub URL, the module interacts with the GitHub REST API (https://api.github.com). It parses the repository URL components, resolves branches or commit tree objects, downloads repository .gitignore definitions, and recursively navigates folder hierarchies via fetch_contents. During traversal, it automatically handles rate limits through backoff intervals derived from X-RateLimit-Reset response headers, checks content sizes, and retrieves raw file blobs via authenticated requests.

    Both execution paths emit telemetry events through utils.output (emit, emit_raw, get) to log crawling progress, path exclusions, rate limit warnings, and decoding anomalies. Extracted files are normalized into a unified dictionary structure mapping repository relative paths to their raw text content, accompanied by execution statistics.

        def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:
        """Determine if a file should be included based on patterns"""
        # If no include patterns are specified, include all files
        if not include_patterns:
            include_file = True
        else:
            # Check if file matches any include pattern
            include_file = any(fnmatch.fnmatch(file_name, pattern) for pattern in include_patterns)

        # Check gitignore if provided
        if include_file and gitignore_spec and gitignore_spec.match_file(file_path):
            return False

        # If exclude patterns are specified, check if file should be excluded
        if exclude_patterns and include_file:
            # Exclude if file matches any exclude pattern
            exclude_file = any(fnmatch.fnmatch(file_path, pattern) for pattern in exclude_patterns)
            return not exclude_file

        return include_file

    The function checks include_patterns against file_name via fnmatch.fnmatch. If inclusion passes, it queries gitignore_spec.match_file(file_path). If .gitignore allows the file, it iterates through exclude_patterns, matching against file_path. If an exclude pattern matches, the file is excluded.

        def fetch_branches(owner: str, repo: str):
        """Get branches of the repository"""

        url = f"https://api.github.com/repos/{owner}/{repo}/branches"

        if response.status_code == 404:

        if response.status_code != 200:

        return response.json()

    Description: Recursively traverses and downloads directory entries and file contents through the GitHub Contents API (https://api.github.com/repos/{owner}/{repo}/contents/{path}).

    Phase 1: API Request & Rate Limit Backoff Handling

        def fetch_contents(path):
        """Fetch contents of the repository at a specific path and commit"""
        url = f"https://api.github.com/repos/{owner}/{repo}/contents/{path}"
        params = {"ref": ref} if ref is not None else {}

        response = requests.get(url, headers=headers, params=params, timeout=(30, 30))

        if response.status_code in (403, 429) and "rate limit exceeded" in response.text.lower():
            if not token:
                raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")
            reset_time = int(response.headers.get("X-RateLimit-Reset", 0))
            wait_time = max(reset_time - time.time(), 0) + 1
            emit_raw("WARNING", f"Rate limit exceeded. Waiting for {wait_time:.0f} seconds...")
            time.sleep(wait_time)
            return fetch_contents(path)

        if response.status_code == 404:
            # ... [404 error logging] ...
            return None

        if response.status_code != 200:
            emit_raw("ERROR", f"Error fetching {path}: {response.status_code} - {response.text}")
            return None

        contents = response.json()
        if not isinstance(contents, list):
            contents = [contents]

    The helper requests path metadata from the GitHub REST API. If a 403 or 429 rate limit error occurs, it inspects whether a token was configured; without one, an Exception is raised. If a token is present, it extracts the X-RateLimit-Reset timestamp from the response headers, sleeps until the limit resets, and recursively retries the request. Responses are normalized into lists to handle both single-file and directory payloads uniformly.

    Phase 2: File Blob Retrieval & Size Guarding

            item_path = item["path"]

            # Calculate relative path if requested
            if use_relative_paths and specific_path:
                if item_path.startswith(specific_path):
                    rel_path = item_path[len(specific_path) :].lstrip("/")
                else:
                    rel_path = item_path
            else:
                rel_path = item_path

            if item["type"] == "file":
                api_counters["entry"] += 1
                entry_num = api_counters["entry"]

                if not should_include_file(rel_path, item["name"], gitignore_spec=gitignore_spec):
                    api_counters["excluded"] += 1
                    emit("CRAWL_FILE_EXCLUDED", num=entry_num, path=rel_path)
                    continue

                file_size = item.get("size", 0)
                if file_size > max_file_size:
                    api_counters["size_limit"] += 1
                    api_skipped_size.append(rel_path)
                    size_kb = file_size / 1024
                    emit("CRAWL_FILE_SIZE_LIMIT", num=entry_num, path=rel_path, size=f"{size_kb:.0f}")
                    continue

                if item.get("download_url"):
                    file_url = item["download_url"]
                    file_response = requests.get(file_url, headers=headers, timeout=(30, 30))
                    content_length = int(file_response.headers.get("content-length", 0))
                    if content_length > max_file_size:
                        api_counters["size_limit"] += 1
                        api_skipped_size.append(rel_path)
                        size_kb = content_length / 1024
                        emit("CRAWL_FILE_SIZE_LIMIT", num=entry_num, path=rel_path, size=f"{size_kb:.0f}")
                        continue

                    if file_response.status_code == 200:
                        files[rel_path] = file_response.text
                        api_counters["processed"] += 1
                        emit("CRAWL_FILE_PROCESSED", num=entry_num, path=rel_path)
                    else:
                        api_counters["non_text"] += 1
                        api_skipped_non_text.append(rel_path)
                        emit("CRAWL_FILE_HTTP_ERROR", num=entry_num, path=rel_path, status=file_response.status_code)
                else:
                    # Alternative method if download_url is not available
                    # ... [Base64 decoding fallback] ...

    When an item has type == "file", its path is adjusted if use_relative_paths is enabled. It is evaluated against should_include_file and checked against max_file_size. If a download_url is provided, the function downloads raw content directly, verifying Content-Length headers as an additional safeguard. If download_url is absent, it retrieves the blob metadata via the API, checks the estimated decoded size (len * 0.75), and decodes the Base64 content into UTF-8 text.

    Phase 3: Recursive Subdirectory Crawling

                elif item["type"] == "dir":
                # Check if directory should be excluded before recursing
                dir_excluded = False
                dir_reason = None

                if gitignore_spec and gitignore_spec.match_file(rel_path):
                    dir_excluded = True
                    dir_reason = get("CRAWL_REASON_GITIGNORE")

                if not dir_excluded and exclude_patterns:
                    dir_name = item["name"]  # basename of the directory
                    for pattern in exclude_patterns:
                        dir_pattern = pattern.removesuffix("/*")
                        if (
                            fnmatch.fnmatch(item_path, dir_pattern)
                            or fnmatch.fnmatch(rel_path, dir_pattern)
                            or fnmatch.fnmatch(dir_name, dir_pattern)
                        ):
                            dir_excluded = True
                            dir_reason = get("CRAWL_REASON_EXCLUDED")
                            break

                if dir_excluded:
                    api_counters["entry"] += 1
                    api_counters["excluded"] += 1
                    emit("CRAWL_DIR_EXCLUDED", num=api_counters["entry"], path=rel_path, reason=dir_reason)
                    continue

                # Only recurse if directory is not excluded
                fetch_contents(item_path)

        return None

    When an item has type == "dir", it is checked against .gitignore and exclude_patterns. If excluded, traversal into that subtree is pruned and logged via emit("CRAWL_DIR_EXCLUDED", ...). If permitted, fetch_contents is invoked recursively on item_path.

    Error Handling

    • Malformed URL Schemes: In the REST traversal flow, urlparse validates the GitHub URL structure. If fewer than two path segments (owner and repository) are present, a ValueError is raised immediately: 
      if len(path_parts) < 2:
    raise ValueError(f"Invalid GitHub URL: {repo_url}")
    • Unauthenticated API Rate Limiting: When making anonymous requests to GitHub REST APIs, HTTP status codes 403 or 429 raise an explicit Exception prompting the user to supply a token via GITHUB_TOKEN or --token: 
      if response.status_code in (403, 429) and not token:
    raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")
    • Authenticated Rate Limit Backoff: When an authenticated session hits rate limits, the module reads the X-RateLimit-Reset Unix epoch header, calculates the required sleep duration, pauses execution via time.sleep, and retries the request: 
      reset_time = int(response.headers.get("X-RateLimit-Reset", 0))
wait_time = max(reset_time - time.time(), 0) + 1
emit_raw("WARNING", f"Rate limit exceeded. Waiting for {wait_time:.0f} seconds...")
time.sleep(wait_time)
return fetch_contents(path)
    • Missing Repositories and Private Access (HTTP 404): Distinguishes between anonymous 404s (which typically indicate private repositories) and authenticated 404s (which indicate missing resources or permission deficiencies), emitting helpful guidance: 
      if response.status_code == 404:
    if not token:
        emit_raw(
            "ERROR",
            "Error 404: Repository not found or is private.\n"
            "If this is a private repository, please provide a valid GitHub token via the 'token' argument or set the GITHUB_TOKEN environment variable.",
        )
    • SSH Clone Failure: Catches generic exceptions during git.Repo.clone_from, logs the error via emit_raw, and returns an empty files dictionary containing an error key in stats: 
      try:
    repo = git.Repo.clone_from(repo_url, tmpdirname)
except Exception as e:
    emit_raw("ERROR", f"Error cloning repo: {e}")
    return {"files": {}, "stats": {"error": str(e)}}
    • Encoding & Non-Text File Faults: Handles binary or non-UTF-8 files by catching (UnicodeDecodeError, ValueError) and generic read exceptions, recording the skipped files without interrupting directory crawling: 
      except (UnicodeDecodeError, ValueError):
    count_non_text += 1
    skipped_non_text_list.append(rel_path)
    emit("CRAWL_FILE_NOT_TEXT", num=entry_num, path=rel_path)
