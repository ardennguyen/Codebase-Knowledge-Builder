    crawl_github_files.py

    Source: utils/crawl_github_files.py

    Technical Overview

    The crawl_github_files.py module serves as the repository ingestion component of the Codebase-Knowledge-Builder pipeline. Its primary role is to fetch, filter, and extract file contents from GitHub repositories into an in-memory dictionary mapping file paths to UTF-8 decoded source text. It supports two primary retrieval backends: an SSH git cloning mechanism using GitPython for local temporary disk operations, and a remote API crawler utilizing the GitHub REST API (v3) for selective downloading without cloning the entire repository.

    The module inspects target URLs to automatically select between SSH cloning and REST API access. When using the REST API backend, it parses repository paths to isolate owner, repository name, target tree/branch ref, and subdirectory paths. It accommodates multi-tier file filtering by integrating .gitignore rules (parsed using pathspec), pattern matching via glob expressions (fnmatch), and byte-size enforcement. The crawler also handles GitHub API rate limits through exponential reset backoff and provides fallback mechanisms for handling base64-encoded file payloads and raw download endpoints.

    DEFAULT_MAX_FILE_SIZE

    Visibility: Public

    Signature: DEFAULT_MAX_FILE_SIZE = 1_048_576 # 1 MB

    Description: The default threshold for maximum allowable file size in bytes (1 megabyte). Files exceeding this threshold during SSH disk scanning or GitHub API retrieval are skipped to prevent excessive memory consumption and avoid ingesting large binaries or assets.

    Signature:

    def crawl_github_files(
    repo_url,
    token=None,
    max_file_size: int = DEFAULT_MAX_FILE_SIZE,
    use_relative_paths: bool = False,
    include_patterns: str | set[str] | None = None,
    exclude_patterns: str | set[str] | None = None,
):

    Description: Coordinates the repository traversal and file ingestion workflow. It normalizes pattern filters, evaluates whether the URL targets an SSH repository or an HTTP(S) GitHub REST endpoint, and processes directory structures accordingly. It enforces file-level and directory-level exclusion rules, manages API rate limits, decodes text files, and aggregates execution metrics.

    Parameters:

    • repo_url (str): URL of the GitHub repository. Can be an SSH repository URL (e.g., git@... or ending in .git) or a web URL pointing to a commit, branch, or subfolder (e.g., https://github.com/owner/repo/tree/branch/subpath).
    • token (str | None): GitHub personal access token used for authentication against the REST API. Required for private repositories and recommended for public repositories to avoid rate limiting. Defaults to None.
    • max_file_size (int): Maximum allowable file size in bytes to download and parse. Defaults to DEFAULT_MAX_FILE_SIZE (1 MB).
    • use_relative_paths (bool): When True, modifies file keys in the returned dictionary to be relative to the requested subdirectory instead of the repository root. Defaults to False.
    • include_patterns (str | set[str] | None): File glob pattern or set of patterns (e.g., "*.py") that whitelist files for inclusion. If None, all files are included.
    • exclude_patterns (str | set[str] | None): File or directory glob pattern or set of patterns to reject. If None, no exclusions are applied.

    Returns:

    • dict: A dictionary containing two keys: "files" (mapping file paths to decoded text content) and "stats" (metadata containing counts and configuration details).

    Raises:

    • ValueError: Raised if repo_url does not contain at least an owner and repository segment in its URL path.
    • Exception: Raised when GitHub API rate limits are encountered on unauthenticated requests or when branch/tree queries fail due to missing credentials.

    • Does not raise exceptions.

        def should_include_file(file_path: str, file_name: str, gitignore_spec=None) -> bool:
        """Determine if a file should be included based on patterns"""
        # If no include patterns are specified, include all files
        if not include_patterns:
            include_file = True
        else:
            # Check if file matches any include pattern
            include_file = any(fnmatch.fnmatch(file_name, pattern) for pattern in include_patterns)

        # Check gitignore if provided
        if include_file and gitignore_spec and gitignore_spec.match_file(file_path):
            return False

        # If exclude patterns are specified, check if file should be excluded
        if exclude_patterns and include_file:
            # Exclude if file matches any exclude pattern
            exclude_file = any(fnmatch.fnmatch(file_path, pattern) for pattern in exclude_patterns)
            return not exclude_file

        return include_file

    The helper evaluates include_patterns against file_name using fnmatch.fnmatch. Gitignore checks and exclude_patterns are evaluated against file_path. This allows include filters to target extensions broadly while exclude filters can match specific nested subpaths.

        def fetch_branches(owner: str, repo: str):
        """Get branches of the repository"""

        url = f"https://api.github.com/repos/{owner}/{repo}/branches"
        response = requests.get(url, headers=headers, timeout=(30, 30))

        if response.status_code in (403, 429) and not token:
            raise Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.")

        if response.status_code == 404:
            if not token:
                emit_raw(
                    "ERROR",
                    "Error 404: Repository not found or is private.\n"
                    "If this is a private repository, please provide a valid GitHub token via the 'token' argument or set the GITHUB_TOKEN environment variable.",
                )
            else:
                emit_raw(
                    "ERROR",
                    "Error 404: Repository not found or insufficient permissions with the provided token.\n"
                    "Please verify the repository exists and the token has access to this repository.",
                )
            return []

        if response.status_code != 200:
            emit_raw("ERROR", f"Error fetching the branches of {owner}/{repo}: {response.status_code} - {response.text}")
            return []

        return response.json()

    The function executes a blocking GET request with 30-second connect and read timeouts. If rate limits are encountered on an unauthenticated session, it raises an Exception instructing the user to configure a token. On 404 responses, it distinguishes between public/private repository failures based on token presence and returns an empty list.

    The structure of item dictionaries returned by the GitHub Contents REST API endpoint (/repos/{owner}/{repo}/contents/{path}).

    Field Type Description
    type str Type of item ("file", "dir", or "symlink").
    name str Base file or directory name.

    Error Handling

    The module implements the following error handling patterns:

    • GitHub API Rate Limits (HTTP 403 / 429):
      • When no authentication token is provided, encountering a rate limit raises an explicit Exception("GitHub API rate limit exceeded. Please provide a GitHub token using --token or GITHUB_TOKEN env var.").
      • When an authenticated token is present, fetch_contents() intercepts HTTP 403/429 responses, inspects the X-RateLimit-Reset header, sleeps for the required duration plus a 1-second buffer, and retries the operation.
    • Missing or Inaccessible Repositories (HTTP 404):
      • The crawler distinguishes between missing tokens on private repositories and permission errors on authenticated tokens, outputting targeted diagnostics via emit_raw().
      • For branch/ref mismatches (e.g., checking main when the repository default is master), it emits guidance recommending branch overrides.
    • SSH Clone Failures:
      • Git exceptions raised by git.Repo.clone_from() are caught via except Exception as e. The failure is emitted as an ERROR event and returns an empty files dictionary with stats["error"].
    • File Size Thresholds:
      • Enforced across three checkpoints: local file stat (os.path.getsize) in SSH mode, GitHub API metadata (item["size"]), and HTTP Content-Length headers during download. Base64 payload lengths are checked using an estimated ratio (len * 0.75 > max_file_size) before decoding.
    • Encoding and Non-Text Files:
      • Binary files, image assets, and unsupported text encodings triggering UnicodeDecodeError or ValueError during file reads or base64 decoding are caught, counted under non_text, and tracked in skipped-item lists without interrupting traversal.
