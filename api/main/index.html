    main

    File Path: main.py

    Overview

    The main module serves as the primary command-line interface (CLI) entry point for the Codebase-Knowledge-Builder tool. It handles command-line argument parsing, environment variable initialization, fallback pattern matching configurations, context limit resolution, and orchestration of the execution graph via create_tutorial_flow().

    It configures a shared context dictionary containing all execution parameters (target repository or directory, inclusion/exclusion rules, LLM model settings, generation modes, and caching flags) and passes it to the pocketflow workflow engine. Additionally, it handles optional post-run cleanup of logs and cached LLM responses.

    Module Constants

    DEFAULT_INCLUDE_PATTERNS

    • Type: set
    • Value: {"*"}
    • Description: Default glob pattern set used when no explicit include patterns are passed via the --include argument. Matches all discovered codebase files.

    DEFAULT_EXCLUDE_PATTERNS

    • Type: set
    • Description: Global exclusion patterns covering media assets, data files, build distribution caches, lockfiles, dependency folders, native binary artifacts, test suites, IDE metadata, and modern AI tool directories (e.g., Cursor, Windsurf, Cline, Copilot).

    Functions

    main()

    Visibility: Public
    Signature: def main() -> None:

    Description:
    Executes the top-level CLI workflow for generating codebase documentation and tutorials: 1. Environment Setup: Loads environment variables from .env using dotenv.load_dotenv(). 2. CLI Parsing: Configures and parses command-line arguments using argparse.ArgumentParser. Supports mutually exclusive target source inputs (--repo for remote GitHub repositories or --dir for local paths), output directory selection, pattern filtering, documentation modes (tutorial, advanced, api-reference, sdk), token overrides, caching, and batching limits. 3. Authentication & Token Resolution: Resolves GitHub access tokens from the CLI argument --token or the GITHUB_TOKEN environment variable. 4. Context Window & Provider Resolution: Detects active LLM configuration (LLM_PROVIDER, endpoint URLs, and API keys) and queries context limits using get_model_context_length() if --max-tokens is not explicitly set. 5. Shared Store Instantiation: Constructs the shared dictionary that nodes read from and write to across pipeline execution. 6. Execution Graph: Instantiates the workflow graph using create_tutorial_flow() and executes it against the shared state. 7. Post-execution Cleanup: If the --cleanup flag is set, deletes the llm_cache.json file and removes the configured log directory.

    Parameters:
    None (Reads directly from sys.argv via argparse.ArgumentParser).

    Returns:
    * None

    Raises:
    * SystemExit: Raised by argparse if mandatory arguments (such as --repo or --dir) are missing or if --help is requested. * Exception: May propagate unhandled operational or I/O exceptions during flow execution or cleanup.

    Example: 

    # Generate a standard tutorial from a public GitHub repository
python main.py --repo https://github.com/octocat/Hello-World --language english

# Generate API reference documentation for a local directory with incremental caching
python main.py --dir ./my-project --mode api-reference --incremental --mkdocs
