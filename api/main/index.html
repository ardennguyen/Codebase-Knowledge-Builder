    main

    Original Source File Path: main.py

    Overview

    The main.py script serves as the primary command-line interface (CLI) and runtime orchestrator for the Codebase-Knowledge-Builder pipeline. It acts as the operational entry point that parses command-line parameters, loads environment variables via dotenv, sets up global default inclusion and exclusion file pattern registries, establishes shared memory state across processing nodes, and triggers execution of the tutorial generation pipeline defined in flow.

    At a high level, main.py is responsible for: - Initializing the environment and resolving authentication tokens (such as GITHUB_TOKEN). - Defining default ignore lists spanning media assets, build artifacts, package dependencies, compiler caches, IDE configuration, and modern AI workspace metadata. - Parsing CLI arguments spanning documentation modes (tutorial, advanced, api-reference, sdk), token budget constraints, batch processing thresholds, and incremental MD5 cache invalidation. - Dynamically deriving token context windows by querying model endpoints via utils.call_llm. - Initializing the shared pipeline dictionary (shared) and dispatching execution to the flow engine created by create_tutorial_flow(). - Performing post-run cleanup of volatile execution logs and local LLM response caches when requested.

    Module-Level Constants

    DEFAULT_INCLUDE_PATTERNS

    • Type: set[str]
    • Value: {"*"}
    • Description: The default wildcard matching rule applied during file discovery. By default, every file in the target repository or directory is considered for indexing unless filtered out by file size limits or exclusion lists.

    DEFAULT_EXCLUDE_PATTERNS

    • Type: set[str]
    • Description: A comprehensive blacklist of glob patterns systematically skipped during repository traversal in both utils.crawl_github_files and utils.crawl_local_files. The set is categorized into seven distinct domains:
    • Media, Data, and Static Assets: Binary media, images, video, audio, office documents, and compressed archives (e.g., assets/*, *.png, *.pdf, *.zip, *.tar).
    • Build, Distribution, and Framework Caches: Compiled outputs and framework build directories (e.g., dist/*, build/*, target/*, .next/*, .nuxt/*, *.log, *.tmp).
    • Environments, Dependencies, and Lockfiles: Dependency installation folders and lockfiles across JavaScript, Python, Rust, Ruby, PHP, and Elixir (e.g., node_modules/*, venv/*, .venv/*, package-lock.json, Cargo.lock, poetry.lock).
    • Language-Specific Exclusions: Bytecode, coverage reports, compiled binaries, object files, and shared libraries (e.g., __pycache__/*, *.class, *.jar, *.o, *.dll, *.so, *.dylib).
    • OS and Version Control Metadata: VCS directories and operating system desktop metadata (e.g., .git/*, .github/*, .DS_Store, Thumbs.db).
    • Classic IDEs: IDE project settings and configuration files (e.g., .vscode/*, .idea/*, *.iml, .vs/*).
    • AI Agents and Modern AI IDEs: System configuration and scratchpads from modern AI coding assistants (e.g., .cursor/*, .windsurf/*, .cline/*, .roo/*, .agent/*, .continue/*, .gemini/*, .claude/*, .copilot/*).

    Module-Level Functions

    main()

    Visibility: Public
    Signature: def main() -> None:

    Description: The primary execution orchestrator for the entire application. It constructs an argparse.ArgumentParser instance defining source options, generation parameters, filtering rules, LLM model switches, batching parameters, and documentation styles.

    It validates the input arguments (ensuring that features like --incremental are restricted to api-reference mode), handles cache manifest removal when --force-rebuild is specified, detects LLM context window capacities, instantiates the shared data dictionary consumed by nodes across the pipeline, and calls create_tutorial_flow().run(shared). Finally, it handles volatile log and cache deletions if --cleanup is asserted.

    Parameters: * None. (Arguments are read directly from sys.argv via argparse).

    Returns: * None

    Raises: * SystemExit: Raised implicitly by argparse when invalid CLI arguments, missing required mutually exclusive source parameters (--repo or --dir), or unrecognized arguments are supplied.

    Implementation Breakdown

    1. CLI Argument Parsing and Grouping

        parser = argparse.ArgumentParser(description="Generate a tutorial for a GitHub codebase or local directory.")

    # Create mutually exclusive group for source
    source_group = parser.add_mutually_exclusive_group(required=True)
    source_group.add_argument("--repo", help="URL of the public GitHub repository.")
    source_group.add_argument("--dir", help="Path to local directory.")

    parser.add_argument("-n", "--name", help="Project name (optional, derived from repo/directory if omitted).")
    parser.add_argument("-t", "--token", help="GitHub personal access token (optional, reads from GITHUB_TOKEN env var if not provided).")
    parser.add_argument("-o", "--output", default="output", help="Base directory for output (default: ./output).")
    parser.add_argument("-i", "--include", nargs="+", help="Files to include (e.g., '*.py' '*.js'). Defaults to '*' (all files).")
    parser.add_argument(
        "-e",
        "--exclude",
        nargs="+",
        help="Files to exclude. Custom patterns are automatically merged with a massive global exclusion list (build caches, node_modules, binaries, media, AI environments) AND your repository's native .gitignore rules.",
    )
    parser.add_argument("-s", "--max-size", type=int, default=200000, help="Maximum file size in bytes (default: 200000, about 200KB).")
    # ...
    The entry point configures the argument parser by enforcing a mutually exclusive requirement between --repo and --dir. It registers options for file path filtering (--include, --exclude), payload sizing limits (--max-size), and project naming overrides. Custom exclusions are later merged on top of DEFAULT_EXCLUDE_PATTERNS.

    2. Documentation Modes and Strategy Switches

        # --- Documentation Mode & Generation Styles ---
    parser.add_argument(
        "--mode",
        choices=["tutorial", "advanced", "api-reference", "sdk"],
        default="tutorial",
        help="Documentation style (tutorial, advanced, api-reference, sdk). (default: tutorial)",
    )
    parser.add_argument("--advanced", action="store_true", help="Legacy flag: equivalent to --mode advanced")
    parser.add_argument("--mkdocs", action="store_true", help="Format output for MkDocs Material (adds YAML frontmatter & nav snippet)")
    parser.add_argument(
        "--incremental", action="store_true", help="Enable MD5 incremental caching to skip unchanged modules (Only supported in --mode api-reference)"
    )
    parser.add_argument(
        "--force-rebuild", action="store_true", help="Clear incremental cache and regenerate all chapters from scratch (use with --incremental)"
    )
    The parser exposes multiple generation modes (tutorial, advanced, api-reference, sdk), MkDocs Material compatibility formatting flags (--mkdocs), and map-reduce file batching controls (--batch, --force-batch).

    3. Flag Validation and Cache Invalidation

        # Resolve mode (backward compatibility for --advanced)
    doc_mode = "advanced" if args.advanced else args.mode

    # Enforce incremental cache constraints
    if args.incremental and doc_mode != "api-reference":
        print(
            "\n\033[93m[Warning] --incremental caching is only effective in 'api-reference' mode due to stable 1:1 file mapping. Disabling incremental cache for this run.\033[0m\n"
        )
        args.incremental = False

    # Handle --force-rebuild: delete the cache manifest to force fresh generation
    if args.force_rebuild and args.incremental:
        project_name = args.name
        if not project_name:
            # Derive project name the same way FetchRepo does
            if args.dir:
                project_name = os.path.basename(os.path.abspath(args.dir))
            elif args.repo:
                project_name = args.repo.rstrip("/").split("/")[-1]
        if project_name:
            output_base = args.output or "output"
            manifest_path = os.path.join(output_base, project_name, ".doc_cache_manifest.json")
            if os.path.exists(manifest_path):
                os.remove(manifest_path)
                print(f"\033[93m[Force Rebuild] Deleted cache manifest: {manifest_path}\033[0m")
            else:
                print(f"\033[93m[Force Rebuild] No cache manifest found at {manifest_path} — all chapters will be generated fresh.\033[0m")
    elif args.force_rebuild and not args.incremental:
        print("\033[93m[Warning] --force-rebuild has no effect without --incremental. Ignoring.\033[0m")
    This section normalizes legacy flags and validates incremental execution constraints. Because incremental MD5 checksum tracking relies on deterministic 1:1 source-to-chapter file mapping, --incremental is automatically disabled with a warning if used outside api-reference mode. If --force-rebuild is asserted in conjunction with --incremental, the existing .doc_cache_manifest.json file is located and deleted.

    4. Shared State Store Construction

        # Prepare shared store to be passed between nodes
    shared = {
        "repo_url": args.repo,
        "local_dir": args.dir,
        "project_name": args.name,  # Can be None, FetchRepo will derive it
        "github_token": github_token,
        "output_dir": args.output,  # Base directory for CombineTutorial output
        # Add include/exclude patterns and max file size
        "include_patterns": set(args.include) if args.include else DEFAULT_INCLUDE_PATTERNS,
        "exclude_patterns": DEFAULT_EXCLUDE_PATTERNS.union(set(args.exclude)) if args.exclude else DEFAULT_EXCLUDE_PATTERNS,
        "max_file_size": args.max_size,
        # Add language for multi-language support
        "language": args.language,
        # Add use_cache flag (inverse of no-cache flag)
        "use_cache": not args.no_cache,
        # Add max_abstraction_num parameter
        "max_abstraction_num": args.max_abstractions,
        # Add thinking_level for LLM reasoning capabilities
        "thinking_level": args.thinking_level,
        # Add max tokens override
        "max_tokens": args.max_tokens,
        # Added mode, mkdocs, and incremental
        "mode": doc_mode,
        "mkdocs": args.mkdocs,
        "incremental": args.incremental,
        "advanced_mode": doc_mode == "advanced",
        # Batching settings
        "batch_size": args.batch,
        "force_batch": args.force_batch,
        # Debug mode
        "debug": args.debug,
        # Outputs will be populated by the nodes
        "files": [],
        "abstractions": [],
        "relationships": {},
        "chapter_order": [],
        "chapters": [],
        "final_output_dir": None,
    }
    A mutable dictionary named shared is initialized. This dictionary acts as the shared context bus passed between execution nodes across the pipeline. It stores user CLI configurations alongside placeholder output arrays (files, abstractions, relationships, chapter_order, chapters, final_output_dir) that downstream nodes populate sequentially.

    5. LLM Endpoint Discovery and Pipeline Execution

        from utils.call_llm import configure_logging, get_model_context_length

    context_length = args.max_tokens or get_model_context_length(endpoint_url, model_name, api_key)

    # Derive project name for logging (before flow runs, which may override shared["project_name"])
    if args.name:
        log_project_name = args.name
    elif args.dir:
        log_project_name = os.path.basename(os.path.normpath(args.dir))
    elif args.repo:
        log_project_name = args.repo.rstrip("/").split("/")[-1]
    else:
        log_project_name = "project"

    # Configure per-run logging: logs/{project}_{mode}_{datetime}.log
    log_file = configure_logging(project_name=log_project_name, mode=doc_mode)

    # ... [Display configuration output] ...

    # Create the flow instance
    tutorial_flow = create_tutorial_flow()

    # Run the flow
    tutorial_flow.run(shared)
    Environment variables corresponding to the active LLM provider (such as OPENROUTER, OPENAI, or GEMINI) are checked. The model's context window limit is retrieved via get_model_context_length, file logging is initialized through configure_logging, and create_tutorial_flow().run(shared) is executed.

    6. Cleanup of Logs and LLM Cache

        # Cleanup logs and cache if requested
    if args.cleanup:
        print("\nCleaning up cache and logs...")
        cache_path = "llm_cache.json"
        if os.path.exists(cache_path):
            try:
                os.remove(cache_path)
                print(f" - Removed {cache_path}")
            except Exception as e:
                print(f" - Failed to remove {cache_path}: {e}")

        log_dir = os.environ.get("LOG_DIR", "logs")
        if os.path.exists(log_dir) and os.path.isdir(log_dir):
            import shutil

            try:
                shutil.rmtree(log_dir)
                print(f" - Removed {log_dir} directory")
            except Exception as e:
                print(f" - Failed to remove {log_dir}: {e}")
    When --cleanup is provided in CLI arguments, main() attempts to delete the local cache file llm_cache.json and recursively delete the logging output directory (LOG_DIR or ./logs). Errors during file deletion are intercepted and output as warning strings without crashing the process.
