    nodes.py

    Technical overview and complete internal API reference for nodes.py. This module defines the core pipeline nodes that execute deterministic file crawling, dynamic LLM-based code discovery, abstraction modeling, cross-module relationship resolution, topological chapter ordering, chapter drafting, and multi-format documentation artifact generation.

    The module implements pipeline operations using the pocketflow computation framework (Node and BatchNode base abstractions). It interacts directly with LLM inference interfaces via utils.call_llm, filesystem traversal routines from utils.crawl_github_files and utils.crawl_local_files, prompt template builders from utils.prompts, and token context budgeting helpers from utils.token_utils.

    get_content_for_indices()

    Visibility: Public
    Signature: def get_content_for_indices(files_data: list[tuple[str, str]], indices: list[int]) -> dict[str, str]:

    Description: Resolves file index numbers into a formatted mapping of file identifiers and their associated raw source contents. It creates a dictionary where keys use the composite index format {index} # {path}, ensuring downstream prompt generators receive clear positional anchors.

    Parameters: * files_data (list[tuple[str, str]]): Sequence of (path, content) tuples representing all crawled project source files. * indices (list[int]): List of integer indices corresponding to the target files needed for context.

    Returns: * dict[str, str]: Mapping of structured index keys ("{i} # {path}") to raw file contents.

    Example: 

    def get_content_for_indices(files_data, indices):
    content_map = {}
    for i in indices:
        if 0 <= i < len(files_data):
            path, content = files_data[i]
            content_map[f"{i} # {path}"] = content  # Use index + path as key for context
    return content_map

    The function checks index bounds (0 <= i < len(files_data)) to prevent IndexError exceptions during lookups if an LLM outputs out-of-range indices. Any index outside the valid range is ignored silently.

    parse_yaml_response()

    Visibility: Public
    Signature: def parse_yaml_response(response: str) -> object:

    Description: Extracts fenced YAML blocks (```yaml ... ```) from model responses and parses them into native Python data structures using PyYAML's safe_load.

    Parameters: * response (str): Raw text response generated by the LLM.

    Returns: * object: Parsed YAML structure (list, dict, or scalar values).

    Raises: * ValueError: When the response string does not contain valid `yaml ` markers or contains unparseable YAML syntax.

    Example: 

    def parse_yaml_response(response):
    """Extract and parse YAML from an LLM response fenced in ```yaml blocks."""
    try:
        yaml_str = response.strip().split("```yaml")[1].split("```")[0].strip()
        return yaml.safe_load(yaml_str)
    except Exception as e:
        raise ValueError(f"Failed to parse YAML: {e}") from e

    This extraction strategy splits the string strictly by the yaml``` block delimiter and extracts everything before the closing `` delimiter. If a model fails to wrap its output within explicit YAML fences, index operations raise an IndexError, which is caught and re-raised as a ValueError to trigger pocketflow retry loops.

    create_token_counter()

    Visibility: Public
    Signature: def create_token_counter() -> collections.abc.Callable[[str], int]:

    Description: Instantiates a fast token counting callable using the tiktoken library parameterized with the cl100k_base BPE tokenizer encoding. It provides an inline fallback heuristic (len(text) // 4) if tiktoken encounters an import or initialization failure.

    Returns: * Callable[[str], int]: A function accepting a string and returning its calculated token length.

    Example: 

    def create_token_counter():
    """Create a token counting function using tiktoken with char-count fallback."""
    try:
        enc = tiktoken.get_encoding("cl100k_base")
        return lambda text: len(enc.encode(text, disallowed_special=()))
    except Exception:
        return lambda text: len(text) // 4

    The closure disables special token validation via disallowed_special=() to ensure arbitrary source code containing patterns like <|endoftext|> can be tokenized safely without raising exceptions.

    resolve_max_tokens()

    Visibility: Public
    Signature: def resolve_max_tokens(shared: dict) -> int:

    Description: Evaluates the maximum operational context window available for the active provider/model combination. If not explicitly set in the shared state, it detects environment variables corresponding to the configured LLM backend and calls get_model_context_length.

    Parameters: * shared (dict): The global pipeline shared memory store.

    Returns: * int: Total context window size in tokens.

    Example: 

    def resolve_max_tokens(shared):
    """Resolve max_tokens from shared store or auto-detect from provider env vars."""
    max_tokens = shared.get("max_tokens")
    if max_tokens is not None:
        return max_tokens
    provider = os.environ.get("LLM_PROVIDER")
    if provider == "GEMINI" or not provider:
        endpoint = "https://generativelanguage.googleapis.com"
        model_name = os.getenv("GEMINI_MODEL", "gemini-3.7-flash")
        api_key = os.getenv("GEMINI_API_KEY", "")
    else:
        endpoint = os.environ.get(f"{provider}_BASE_URL", "")
        model_name = os.environ.get(f"{provider}_MODEL", "")
        api_key = os.environ.get(f"{provider}_API_KEY", "")
    return get_model_context_length(endpoint, model_name, api_key)

    The resolver dynamically constructs configuration lookups for custom providers using the ${PROVIDER}_BASE_URL, ${PROVIDER}_MODEL, and ${PROVIDER}_API_KEY format when LLM_PROVIDER is not set to Google Gemini.

        def exec(self, prep_res):

            result = crawl_github_files(
                repo_url=prep_res["repo_url"],

                include_patterns=prep_res["include_patterns"],

                max_file_size=prep_res["max_file_size"],
                use_relative_paths=prep_res["use_relative_paths"],

            print(f"Crawling directory: {prep_res['local_dir']}...")

            result = crawl_local_files(
                directory=prep_res["local_dir"],
                include_patterns=prep_res["include_patterns"],
                exclude_patterns=prep_res["exclude_patterns"],
                max_file_size=prep_res["max_file_size"],
                use_relative_paths=prep_res["use_relative_paths"],
            )

        # Convert dict to list of tuples: [(path, content), ...]
        files_list = list(result.get("files", {}).items())
        if len(files_list) == 0:

        llm_logger.info(f"NODE COMPLETE | node=FetchRepo | files_found={len(files_list)}")

    ContextRouter.prep()

    Visibility: Public
    Signature: def prep(self, shared: dict) -> tuple:

    Description: Calculates token consumption across templates, directory trees, and source files. It checks context limits against resolve_max_tokens(shared) using a 95% safety margin.

    Parameters: * shared (dict): Pipeline shared store.

    Returns: * tuple: Structured routing tuple specifying the target branch and budget constraints.

    Example: 

        def prep(self, shared):
        files_data = shared["files"]
        max_tokens = resolve_max_tokens(shared)

        shared["max_tokens"] = max_tokens

        # --- Token estimation setup ---
        count_tokens = create_token_counter()

        # --- Calculate prompt overhead FIRST ---
        # 1. Prompt template (measure both, use the larger)
        prompt_dir = os.path.join(os.path.dirname(os.path.abspath(__file__)), "prompts")
        max_template_tokens = 0
        for subdir in ["tutorial", "advanced"]:
            template_path = os.path.join(prompt_dir, subdir, "map_abstractions.md")
            if os.path.exists(template_path):
                with open(template_path, encoding="utf-8-sig") as f:
                    t = count_tokens(f.read())
                max_template_tokens = max(max_template_tokens, t)

        # 2. Directory tree (built from all files, shared across batches)
        directory_tree = self._build_directory_tree(files_data)
        tree_tokens = count_tokens(directory_tree)

        # 3. File listing index (e.g. "- 0 # main.py\n- 1 # nodes.py\n...")
        file_listing_str = "\n".join(f"- {i} # {path}" for i, (path, _) in enumerate(files_data))
        listing_tokens = count_tokens(file_listing_str)

        prompt_overhead = max_template_tokens + tree_tokens + listing_tokens
        // ...
        # --- Effective limit = safety margin minus overhead ---
        safety_limit = int(max_tokens * 0.95)
        effective_limit = safety_limit - prompt_overhead
        force_batch = shared.get("force_batch", False)

        if shared.get("mode", "tutorial") == "api-reference":
            return ("deterministic", files_data, effective_limit, shared.get("batch_size", 50), None, None, directory_tree, False)

        if total_tokens <= effective_limit and not force_batch:
            return ("direct", files_data, effective_limit, shared.get("batch_size", 50), None, None, directory_tree, False)

        return (
            "batch",
            files_data,
            effective_limit,
            shared.get("batch_size", 50),
            file_token_map,
            count_tokens,
            directory_tree,
            shared.get("debug", False),
        )

    The node calculates prompt overhead before checking content tokens to protect against context truncation. It computes the maximum overhead between tutorial and advanced prompts and measures tree and listing sizes to determine the effective_limit.

    ContextRouter.exec()

    Visibility: Public
    Signature: def exec(self, prep_res: tuple) -> str | list[list[tuple[int, str, str]]]:

    Description: Executes routing logic. In "batch" mode, it groups files by directory and splits them into token-budgeted batches without mixing directories.

    Parameters: * prep_res (tuple): Parameter tuple returned by ContextRouter.prep().

    Returns: * str | list[list[tuple[int, str, str]]]: Returns routing keys ("direct", "deterministic") or a nested list of file batches.

    Example: 

        def exec(self, prep_res):
        route, files_data, effective_limit, batch_size, file_token_map, _count_tokens, directory_tree, debug = prep_res
        llm_logger.info(
            f"NODE EXEC | node=ContextRouter | action=route_decision | route={route} | files={len(files_data)} | effective_limit={effective_limit:,}"
        )

        if route == "direct":
            return "direct"
        if route == "deterministic":
            return "deterministic"

        # Group by directory for coherence, with pre-computed tokens
        dir_groups = defaultdict(list)
        for i, (path, content) in enumerate(files_data):
            dir_groups[os.path.dirname(path)].append((i, path, content, file_token_map[i]))

        # Build token-aware batches (never mix directories)
        batches = []
        for dirname in sorted(dir_groups.keys()):
            current_batch = []
            current_tokens = 0

            for i, path, content, tokens in dir_groups[dirname]:
                # Start new batch if adding this file would exceed effective limit or file count cap
                if current_batch and (current_tokens + tokens > effective_limit or len(current_batch) >= batch_size):
                    batches.append(current_batch)
                    current_batch = []
                    current_tokens = 0

                current_batch.append((i, path, content))
                current_tokens += tokens

            # Flush remaining files in this directory
            if current_batch:
                batches.append(current_batch)

        self._directory_tree = directory_tree
        return batches

    The batching algorithm preserves directory boundaries to maintain architectural locality. Files in the same folder are grouped together until they hit effective_limit or batch_size.
