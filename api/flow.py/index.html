    flow.py

    Source: flow.py

    Technical Overview

    The flow.py module defines the directed acyclic graph (DAG) workflow topology for the Codebase-Knowledge-Builder system. Built on top of the lightweight PocketFlow framework, it serves as the declarative pipeline orchestrator that wires together repository crawling, architectural analysis, factual verification, and document authoring into an executable workflow object. The module decouples the operational sequencing of tasks from their internal node execution logic, allowing individual analysis and generation steps to operate as modular units connected through operator-driven transitions.

    The pipeline architecture configured in this file bifurcates repository processing into two primary paradigms governed by context window capacity and execution mode: a dynamic heuristic pipeline and a deterministic fact-based pipeline. When operating under dynamic routing, the workflow branches into either a single-pass abstraction identifier (IdentifyAbstractions) for compact codebases or a distributed map-reduce abstraction pipeline (MapAbstractions and ReduceAbstractions) for larger repositories. In parallel, when deterministic mode is enabled, the graph routes execution through DeterministicFileMapper and ExtractFacts to enforce code-grounded structural accuracy before converging on the chapter generation stages (WriteChapters and CombineTutorial).

    At runtime, flow.py exposes a single factory function, create_tutorial_flow(), which instantiates all processing nodes with tailored retry budgets and backoff intervals, links their dependencies using PocketFlow's right-shift (>>) and action-channel (- "action" >>) operators, logs the graph construction event, and returns a unified Flow instance ready for invocation.

    Public API

    create_tutorial_flow()

    Visibility: Public
    Signature: def create_tutorial_flow():

    Description:
    Instantiates and configures the complete PocketFlow execution graph responsible for generating documentation. It initializes all operational nodes with specific retry policies, establishes data flow transitions and conditional action routes, logs the graph generation event to internal diagnostic logs, and wraps the entry node into an executable Flow instance.

    Parameters:
    This function takes no parameters.

    Returns:
    * Flow: An initialized pocketflow.Flow instance configured with FetchRepo as the root entry point.

    Raises:
    This factory function does not explicitly raise exceptions during graph definition; however, failures occurring during node initialization within third-party packages or invalid operator connections will raise standard runtime errors.

    Node Instantiation and Fault-Tolerance Configuration

        fetch_repo = FetchRepo()
    context_router = ContextRouter()
    map_abstractions = MapAbstractions(max_retries=5, wait=20)
    reduce_abstractions = ReduceAbstractions(max_retries=5, wait=20)
    identify_abstractions = IdentifyAbstractions(max_retries=5, wait=20)
    analyze_relationships = AnalyzeRelationships(max_retries=5, wait=20)
    order_chapters = OrderChapters(max_retries=5, wait=20)
    write_chapters = WriteChapters(max_retries=5, wait=20)
    combine_tutorial = CombineTutorial()
    deterministic_mapper = DeterministicFileMapper(max_retries=5, wait=20)
    extract_facts = ExtractFacts(max_retries=3, wait=10)  # one small call per file; the last attempt keeps what verifies

    Every stage of the documentation lifecycle is instantiated as a distinct node object. Nodes interfacing with Large Language Models (map_abstractions, reduce_abstractions, identify_abstractions, analyze_relationships, order_chapters, write_chapters, and deterministic_mapper) are configured with defensive retry policies: max_retries=5 and wait=20. This configuration accounts for upstream provider rate limits, transient connection drops, and API timeouts by enforcing exponential backoff intervals of twenty seconds across five attempts before failing.

    In contrast, extract_facts is configured with a leaner retry envelope of max_retries=3 and wait=10. Because ExtractFacts iterates over repository files individually, smaller retry counts and shorter wait times prevent pipeline stalls on edge-case files while the node retains verified claims gathered on final attempts. Non-LLM infrastructure nodes—fetch_repo, context_router, and combine_tutorial—rely on local filesystem I/O and deterministic string assembly, and therefore do not require retry wrappers.

    Execution Graph Wiring and Conditional Routing

        fetch_repo >> context_router

    context_router - "direct" >> identify_abstractions
    context_router - "batch" >> map_abstractions
    context_router - "deterministic" >> deterministic_mapper

    map_abstractions >> reduce_abstractions

    identify_abstractions >> analyze_relationships
    reduce_abstractions >> analyze_relationships

    analyze_relationships >> order_chapters
    order_chapters >> write_chapters

    deterministic_mapper >> extract_facts >> write_chapters

    write_chapters >> combine_tutorial

    PocketFlow overloads the Python bitwise right-shift operator (>>) and subtraction operator (-) to construct directed edges and conditional branching logic between nodes. Execution begins linearly with fetch_repo >> context_router, which ingests the codebase files and analyzes token volume. From context_router, three mutually exclusive transitions are defined: * "direct": Triggered when total repository tokens fit safely within a single context window, routing directly to identify_abstractions. * "batch": Triggered when token counts exceed single-prompt thresholds, routing to the map-reduce cluster where map_abstractions >> reduce_abstractions groups files into modular domains. * "deterministic": Triggered when operating in explicit structural documentation modes (e.g., API reference or SDK reference generation), bypassing heuristic abstraction clustering in favor of deterministic_mapper.

    Both dynamic abstraction branches converge into analyze_relationships, which correlates dependencies and interfaces across discovered abstractions. The workflow then orders narrative sections (order_chapters) and feeds into write_chapters. In parallel, the deterministic path executes deterministic_mapper >> extract_facts >> write_chapters, extracting ground-truth AST facts and signatures directly into the chapter writer. Finally, write_chapters >> combine_tutorial joins individual markdown files into the completed documentation suite.

    Telemetry Emission and Flow Construction

        emit_raw("DEBUG", "create_tutorial_flow | constructed PocketFlow execution graph", dest="LOG")
    return Flow(start=fetch_repo)

    Once all node instances and directional transitions are mapped, the factory issues a structured diagnostic trace via emit_raw. The message is assigned the "DEBUG" category and routed specifically to the "LOG" destination, ensuring the internal log file tracks graph initialization without cluttering the interactive terminal interface. Finally, the function returns a pocketflow.Flow object with its root set to start=fetch_repo, providing the caller with an executable pipeline container.

    Example: 

    # Extracted directly from flow.py: instantiation, wiring, and return
flow = create_tutorial_flow()

    Data Structures

    Flow

    The primary operational object returned by create_tutorial_flow(), declared in the external pocketflow library. It encapsulates the complete DAG topology starting from the root entry point.

    Field Type Description
    start Node (FetchRepo) The designated entry node where graph execution begins when Flow.run() is invoked.

    Shared store keys

    While flow.py does not declare custom dataclasses, the returned Flow relies on an in-memory dictionary (the PocketFlow shared store) passed across all connected nodes during execution. The following table describes the core schema elements populated, transformed, and read across the nodes orchestrated by this flow:

    Field Type Description
    repo_path str Filesystem directory path or remote Git URL specifying the target codebase.
    files dict[str, str] Mapping of relative file paths to their UTF-8 decoded text contents, populated by FetchRepo.
    abstractions list[dict] Core domain abstractions discovered by IdentifyAbstractions or ReduceAbstractions.
    relationships list[dict] Cross-module dependencies and architectural relationships mapped by AnalyzeRelationships.
    chapter_order list[str] Reading order and structural chapter outlines resolved by OrderChapters.
    module_facts dict AST-verified symbols, line numbers, and dependencies produced by ExtractFacts.
    written_chapters dict[str, str] Map of chapter identifiers to generated Markdown text produced by WriteChapters.
    final_output str Completed documentation site or combined Markdown output generated by CombineTutorial.

    Error Handling

    Fault tolerance within flow.py is established declaratively through node parameterization rather than try...except blocks. Because LLM interactions are subject to provider latency spikes, network partition events, and upstream rate limits, the flow embeds defensive recovery directly into the node definitions:

    • Exponential Backoff and Retries: Nodes performing non-deterministic LLM operations (MapAbstractions, ReduceAbstractions, IdentifyAbstractions, AnalyzeRelationships, OrderChapters, WriteChapters, and DeterministicFileMapper) are bounded by max_retries=5 and wait=20. If an underlying provider request fails, PocketFlow traps the failure, pauses for twenty seconds, and retries the node up to five times before terminating the workflow.
    • Granular Extraction Safeguards: ExtractFacts receives an isolated retry policy (max_retries=3, wait=10). As noted by the inline comment (# one small call per file; the last attempt keeps what verifies), AST factual extraction operates per file. Setting fewer retries and shorter backoffs prevents single anomalous files from stalling the entire graph, while the node guarantees that all claims verified up to the final attempt are preserved.
    • Deterministic Execution Integrity: The deterministic non-LLM nodes (FetchRepo, ContextRouter, and CombineTutorial) execute without retry loops, allowing local filesystem exceptions, missing permissions, or invalid UTF-8 decodings to fail fast before expensive LLM completions are initiated.
