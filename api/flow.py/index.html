    flow.py

    Source: flow.py

    Technical Overview

    The flow.py module defines and constructs the primary execution graph for the documentation generation pipeline using the pocketflow orchestrator framework. It serves as the workflow topology definition layer, linking distinct processing nodes—defined in nodes.py—into an executable Directed Acyclic Graph (DAG). The pipeline manages the lifecycle of repository ingestion, contextual routing based on codebase scale, abstraction extraction, factual AST verification, narrative chapter drafting, and final artifact bundling.

    The execution graph implements a polymorphic routing architecture centered around ContextRouter. Depending on the codebase size, structure, and operational mode, the workflow branches into one of three execution modalities: * Direct Path: For smaller codebases that fit within single-turn context windows, IdentifyAbstractions extracts key abstractions immediately. * Batch Path: For larger codebases requiring map-reduce decomposition, MapAbstractions partitions the codebase into chunks, which are subsequently consolidated by ReduceAbstractions. * Deterministic Path: For structured API reference generation, DeterministicFileMapper maps source files directly, feeding ExtractFacts for granular, AST-grounded code claims.

    The narrative branches (direct and batch) converge on AnalyzeRelationships and OrderChapters before drafting. The deterministic branch routes extracted code facts directly into WriteChapters, which also consumes the ordered narrative structure. Finally, all chapter artifacts pass to CombineTutorial for site compilation, navigation synthesis, and file emission.

    Public API

    create_tutorial_flow()

    Visibility: Public

    Signature: def create_tutorial_flow():

    Description: Assembles and returns the configured pocketflow.Flow execution graph for the documentation pipeline. The function instantiates all processing nodes with retry policies and backoff parameters, binds transitions using PocketFlow's right-shift (>>) and action-labeled subtraction-shift (- "action" >>) operators, emits a debug log entry, and returns the sealed graph initialized at FetchRepo.

    Node Instantiation and Retry Configuration

        fetch_repo = FetchRepo()
    context_router = ContextRouter()
    map_abstractions = MapAbstractions(max_retries=5, wait=20)
    reduce_abstractions = ReduceAbstractions(max_retries=5, wait=20)
    identify_abstractions = IdentifyAbstractions(max_retries=5, wait=20)
    analyze_relationships = AnalyzeRelationships(max_retries=5, wait=20)
    order_chapters = OrderChapters(max_retries=5, wait=20)
    write_chapters = WriteChapters(max_retries=5, wait=20)
    combine_tutorial = CombineTutorial()
    deterministic_mapper = DeterministicFileMapper(max_retries=5, wait=20)
    extract_facts = ExtractFacts(max_retries=3, wait=10)  # one small call per file; the last attempt keeps what verifies

    The node instantiation phase configures operational retry policies for resilient LLM communication across all network-bound steps. Compute-heavy and reasoning-intensive LLM nodes (MapAbstractions, ReduceAbstractions, IdentifyAbstractions, AnalyzeRelationships, OrderChapters, WriteChapters, and DeterministicFileMapper) receive a fault-tolerant policy of 5 maximum retries with a 20-second wait interval between consecutive attempts to absorb rate limits and transient gateway errors. In contrast, ExtractFacts uses a shorter policy of 3 retries with a 10-second wait interval because it performs atomic, single-file verification calls where partial verified states are preserved on terminal attempts. Non-LLM coordination nodes (FetchRepo, ContextRouter, and CombineTutorial) are instantiated with default execution settings without explicit retry loops.

    Directed Acyclic Graph Topology Definition

        fetch_repo >> context_router

    context_router - "direct" >> identify_abstractions
    context_router - "batch" >> map_abstractions
    context_router - "deterministic" >> deterministic_mapper

    map_abstractions >> reduce_abstractions

    identify_abstractions >> analyze_relationships
    reduce_abstractions >> analyze_relationships

    analyze_relationships >> order_chapters
    order_chapters >> write_chapters

    deterministic_mapper >> extract_facts >> write_chapters

    write_chapters >> combine_tutorial

    The topology binding phase specifies all valid transitions across the pipeline using PocketFlow's operator-overloaded routing semantics. Execution begins unconditionally with fetch_repo >> context_router. The ContextRouter node inspects shared state and dispatches execution dynamically to one of three outbound branches using action-labeled edges (- "direct" >>, - "batch" >>, or - "deterministic" >>). The direct and batch pipelines analyze architectural abstractions and converge on analyze_relationships >> order_chapters >> write_chapters. In parallel, the deterministic pipeline chains deterministic_mapper >> extract_facts >> write_chapters, providing verified AST assertions directly to the drafting stage. Both execution paths funnel into write_chapters, which terminates in the final publishing step combine_tutorial.

    Telemetry Emission and Flow Encapsulation

        emit_raw("DEBUG", "create_tutorial_flow | constructed PocketFlow execution graph", dest="LOG")
    return Flow(start=fetch_repo)

    The final phase logs the graph construction event and encapsulates the connected nodes into a runnable Flow instance. It invokes emit_raw with a DEBUG level and target destination LOG, recording the successful compilation of the execution graph without cluttering standard console output. The instantiated Flow(start=fetch_repo) object designates FetchRepo as the immutable entrypoint for workflow execution, returning a self-contained graph ready for sequential invocation.

    Parameters:

    This function takes no parameters.

    Returns:

    • Flow: An initialized pocketflow.Flow instance whose root entry node is set to fetch_repo.

    Raises:

    This function does not explicitly raise custom exceptions; however, initialization may propagate: * TypeError or AttributeError: Raised if imported node classes fail to meet the pocketflow.Node contract or if invalid edge connections are declared.

    Example:

    # Real usage from main.py
from flow import create_tutorial_flow

flow = create_tutorial_flow()
flow.run(shared)

    Data Structures

    Pipeline Action Routes

    The ContextRouter node routes execution dynamically across three distinct edge actions. The target node and downstream path are determined by the active generation mode and repository size:

    Action Key Target Node Execution Mode Description
    "direct" IdentifyAbstractions Tutorial / Advanced (compact codebase) Bypasses map-reduce partitioning; processes the repository layout within a single LLM prompt context.
    "batch" MapAbstractions Tutorial / Advanced (large codebase) Partitions codebase files into discrete batches for parallel or chunked abstraction mapping before reducing.
    "deterministic" DeterministicFileMapper API Reference / SDK Reference Bypasses subjective narrative clustering; deterministically assigns one documentation page per source file.

    Node Retry and Timeout Policies

    Every processing node in flow.py is instantiated with explicit fault-tolerance parameters passed to the underlying pocketflow.Node constructor:

    Node Variable Class Name max_retries wait (seconds) Operational Role
    fetch_repo FetchRepo Default (0) Default (0) Ingests repository files locally or via Git/GitHub.
    context_router ContextRouter Default (0) Default (0) Evaluates file volume and flags to choose routing action.
    map_abstractions MapAbstractions 5 20 Generates intermediate abstraction maps per file batch.
    reduce_abstractions ReduceAbstractions 5 20 Combines batched abstraction maps into a global summary.
    identify_abstractions IdentifyAbstractions 5 20 Discovers global architectural abstractions directly.
    analyze_relationships AnalyzeRelationships 5 20 Maps relationships between identified abstractions.
    order_chapters OrderChapters 5 20 Determines narrative pedagogical chapter sequencing.
    write_chapters WriteChapters 5 20 Synthesizes chapter prose and embeds verified facts.
    combine_tutorial CombineTutorial Default (0) Default (0) Compiles index navigation, outputs MkDocs/Markdown.
    deterministic_mapper DeterministicFileMapper 5 20 Maps each source module to a documentation target file.
    extract_facts ExtractFacts 3 10 Extracts and verifies AST facts and symbol claims.

    Error Handling

    Error handling in flow.py is configured declaratively at node instantiation rather than through imperative try/except blocks:

    • LLM Rate-Limit and Failure Recovery: All nodes invoking external language models are configured with max_retries=5 and wait=20. If an underlying provider raises rate-limit errors (HTTP 429), gateway timeouts (HTTP 504), or parsing exceptions, PocketFlow catches the error, delays for 20 seconds, and retries up to 5 times before failing.
    • Deterministic Verification Tolerance: The ExtractFacts node is configured with max_retries=3 and wait=10. This design reflects its per-file iterative verification strategy: on the final attempt, the node retains all verified claims extracted up to that point rather than aborting the entire pipeline run.
    • Deterministic State Integrity: Nodes that execute local filesystem operations or deterministic data transformations (FetchRepo, ContextRouter, CombineTutorial) do not define retries, allowing unrecoverable I/O or configuration errors to fail fast.
