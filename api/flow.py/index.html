    flow.py

    Source: flow.py

    Technical Overview

    flow.py defines the core executable workflow graph for the tutorial and documentation generation pipeline using the PocketFlow framework. It acts as the declarative assembly module of the application, taking computational and generative units defined in nodes.py and binding them into a directed, conditional execution graph. By configuring node dependencies and retry thresholds, this module governs how source repositories are analyzed, routed across distinct architectural discovery paths, synthesized into structured documentation chapters, and finalized.

    The workflow begins by fetching repository contents and evaluating code volume and complexity within a centralized routing node. Based on repository characteristics, the workflow dynamically branches into one of three processing topologies: direct full-context abstraction, batched map-reduce abstraction, or deterministic fact extraction. The direct and batched pathways converge into relationship analysis and chapter ordering, while the deterministic pathway extracts verified code facts and feeds them directly into the drafting stage. All paths ultimately converge at the chapter writing and combination stages to output unified documentation.

    Public API

    create_tutorial_flow()

    Visibility: Public

    Signature: def create_tutorial_flow():

    Description: Constructs, configures, and links all operational nodes required for the tutorial generation lifecycle into a unified PocketFlow.Flow instance. It configures node-level retry policies, specifies conditional routing actions, sequences upstream and downstream dependencies, and returns the ready-to-run flow anchored at the initial ingestion node.

    Parameters:

    None.

    Returns:

    • Flow: An initialized pocketflow.Flow execution instance with start=fetch_repo.

    Raises:

    This function does not explicitly raise exceptions. Any instantiation errors from underlying nodes or PocketFlow graph validation errors will bubble up to the caller.

    Node Instantiation and Retry Configuration

        fetch_repo = FetchRepo()
    context_router = ContextRouter()
    map_abstractions = MapAbstractions(max_retries=5, wait=20)
    reduce_abstractions = ReduceAbstractions(max_retries=5, wait=20)
    identify_abstractions = IdentifyAbstractions(max_retries=5, wait=20)
    analyze_relationships = AnalyzeRelationships(max_retries=5, wait=20)
    order_chapters = OrderChapters(max_retries=5, wait=20)
    write_chapters = WriteChapters(max_retries=5, wait=20)
    combine_tutorial = CombineTutorial()
    deterministic_mapper = DeterministicFileMapper(max_retries=5, wait=20)
    extract_facts = ExtractFacts(max_retries=3, wait=10)  # one small call per file; the last attempt keeps what verifies

    The initialization phase creates instances of the eleven workflow nodes responsible for repository processing. Nodes involving heavy Large Language Model (LLM) interaction or network calls—such as MapAbstractions, ReduceAbstractions, IdentifyAbstractions, AnalyzeRelationships, OrderChapters, WriteChapters, and DeterministicFileMapper—are configured with aggressive resilience policies consisting of max_retries=5 and an exponential backoff interval of wait=20 seconds. In contrast, ExtractFacts uses a more focused resilience profile (max_retries=3, wait=10) because it operates on granular, per-file AST verification tasks where partial factual extractions are preserved on the final attempt. Nodes that perform deterministic local transformations without external network calls (FetchRepo, ContextRouter, and CombineTutorial) are instantiated with default retry parameters.

    Execution Graph Topology and Routing

        fetch_repo >> context_router

    context_router - "direct" >> identify_abstractions
    context_router - "batch" >> map_abstractions
    context_router - "deterministic" >> deterministic_mapper

    map_abstractions >> reduce_abstractions

    identify_abstractions >> analyze_relationships
    reduce_abstractions >> analyze_relationships

    analyze_relationships >> order_chapters
    order_chapters >> write_chapters

    deterministic_mapper >> extract_facts >> write_chapters

    write_chapters >> combine_tutorial

    The graph assembly phase establishes dataflow pipelines and branching logic using PocketFlow operator overloads. The operator >> denotes unconditional sequential flow, while - "action" >> defines conditional routing predicated on the output action string returned by the predecessor node. ContextRouter branches execution along three mutually exclusive strategies: "direct" transfers execution immediately to IdentifyAbstractions for codebases fitting single-shot context windows; "batch" routes large codebases into a map-reduce pipeline across MapAbstractions and ReduceAbstractions; and "deterministic" routes to DeterministicFileMapper for AST-indexed, rule-based decomposition. Both conceptual abstraction pathways converge at AnalyzeRelationships, proceed through OrderChapters, and merge with the factual extraction stream from ExtractFacts into WriteChapters before concluding at CombineTutorial.

    Telemetry and Flow Initialization

        emit_raw("DEBUG", "create_tutorial_flow | constructed PocketFlow execution graph", dest="LOG")
    return Flow(start=fetch_repo)

    The final phase records an audit log entry via emit_raw, writing a debug-level milestone directly to the disk logging sink (dest="LOG") without cluttering terminal output. The compiled Flow object is then instantiated by binding start=fetch_repo as the designated root node of the directed acyclic graph. When executed by an external runner, the flow runtime traverses the graph beginning at fetch_repo and follows the wired state edges.

    Example:

    from flow import create_tutorial_flow

# Instantiate the configured PocketFlow graph
flow = create_tutorial_flow()

# Execute the flow starting from FetchRepo using a shared state context
shared_context = {
    "repo_path": "./local_repository",
    "output_dir": "./output",
}
flow.run(shared_context)

    Data Structures

    Node Execution Configuration

    flow.py parameterizes operational nodes with explicit retry and backoff attributes passed directly into node constructors during initialization:

    Parameter Type Default Value Target Nodes Description
    max_retries int 5 MapAbstractions, ReduceAbstractions, IdentifyAbstractions, AnalyzeRelationships, OrderChapters, WriteChapters, DeterministicFileMapper Maximum number of execution attempts permitted upon encountering retryable network or LLM errors.
    wait int 20 MapAbstractions, ReduceAbstractions, IdentifyAbstractions, AnalyzeRelationships, OrderChapters, WriteChapters, DeterministicFileMapper Initial wait duration in seconds before attempting subsequent retries under failure conditions.
    max_retries int 3 ExtractFacts Reduced retry ceiling tailored for discrete, per-file AST and source claim extractions.
    wait int 10 ExtractFacts Reduced retry sleep duration in seconds for fine-grained factual verification tasks.

    ContextRouter Action Routing Directives

    The branching behavior configured on ContextRouter relies on three distinct action keys that route execution through specific subgraphs:

    Action Key Successor Node Topology Strategy Context Criteria
    "direct" IdentifyAbstractions Single-Pass Analysis Source files and token count comfortably fit inside a single LLM context window.
    "batch" MapAbstractions Distributed Map-Reduce Token count exceeds single-pass context thresholds, requiring partitioned map analysis followed by reduction.
    "deterministic" DeterministicFileMapper Static AST Fact Extraction Mode configurations targeting rule-based fact verification and strict AST symbol mapping.

    PocketFlow Flow Instance Return Structure

    The Flow object returned by create_tutorial_flow() encapsulates the topological runtime structure:

    Attribute / Component Type Description
    start FetchRepo Root node where graph execution begins.
    Graph Edges Internal PocketFlow Edge Registry Declarative directional and conditional graph mapping connecting all eleven nodes.
    Telemetry Target File Sink (dest="LOG") Debug statement logged via emit_raw indicating successful graph assembly.

    Error Handling

    Error handling in flow.py is configured declaratively through node instantiation parameters rather than runtime exception trapping blocks:

    • LLM Call Resilience: Core analytical nodes (MapAbstractions, ReduceAbstractions, IdentifyAbstractions, AnalyzeRelationships, OrderChapters, WriteChapters, and DeterministicFileMapper) are provisioned with max_retries=5 and wait=20. This configuration ensures transient API rate limits (HTTP 429), gateway timeouts (HTTP 504), and temporary network disconnections are absorbed automatically by PocketFlow's retry mechanisms before escalating to a pipeline abort.
    • Partial Fact Verification Safeguard: ExtractFacts uses max_retries=3 and wait=10. This design prevents prolonged pipeline stalls during per-file extraction loops while adhering to the rule that the final attempt retains all verified assertions extracted up to that point.
    • Deterministic Fallback Routing: Unhandled or erroneous action tags emitted by ContextRouter will cause graph traversal to halt if an unexpected action key is emitted that does not match "direct", "batch", or "deterministic".
