    flow.py

    Source: flow.py

    Following the context window budgeting and telemetry instrumentation established in utils/token_utils.py, flow.py serves as the centralized workflow graph definition and execution pipeline orchestrator for the Codebase-Knowledge-Builder system. It defines the structural topology of the knowledge extraction process by assembling discrete computational units into a Directed Acyclic Graph (DAG) powered by the pocketflow framework.

    Technical Overview

    The primary responsibility of flow.py is to instantiate and interconnect the execution nodes defined in nodes.py. The pipeline ingests source code from either local filesystems or remote GitHub repositories, assesses the total context size against model capacity, dynamically branches into optimized extraction strategies, synthesizes structural relationships, and writes modular technical tutorials.

    The architecture supports three distinct execution paths governed by the ContextRouter node: 1. Direct Path ("direct"): Activated when the target codebase token count falls safely within a single LLM context window. The graph routes directly to IdentifyAbstractions, extracting high-level system components in a single pass. 2. Map-Reduce Path ("batch"): Activated when the codebase exceeds standard model context windows. Repository contents are partitioned into discrete chunks processed concurrently or sequentially via MapAbstractions, followed by consolidation and deduplication in ReduceAbstractions. 3. Deterministic Path ("deterministic"): Bypasses LLM-driven abstraction discovery entirely. Used for rigid 1:1 file-to-chapter documentation tasks via DeterministicFileMapper, routing directly to chapter generation.

    All abstraction-based pathways converge at AnalyzeRelationships, which builds dependency graphs and cross-module call topologies, followed by OrderChapters for pedagogical sequencing, WriteChapters for drafting content, and CombineTutorial for compiling the final Markdown/MkDocs documentation tree.

    Public API

    create_tutorial_flow()

    Visibility: Public
    Signature: def create_tutorial_flow() -> Flow:

    Description:
    Instantiates all functional pipeline nodes, assigns fault-tolerant retry policies, binds dynamic routing branches, and constructs the executable pocketflow.Flow graph. The function configures node dependencies using the pocketflow shift operator (>>) and action-conditional branching syntax (- "action" >>).

    Phase 1: Node Instantiation and Retry Configuration

    def create_tutorial_flow():
    fetch_repo = FetchRepo()
    context_router = ContextRouter()
    map_abstractions = MapAbstractions(max_retries=5, wait=20)
    reduce_abstractions = ReduceAbstractions(max_retries=5, wait=20)
    identify_abstractions = IdentifyAbstractions(max_retries=5, wait=20)
    analyze_relationships = AnalyzeRelationships(max_retries=5, wait=20)
    order_chapters = OrderChapters(max_retries=5, wait=20)
    write_chapters = WriteChapters(max_retries=5, wait=20)
    combine_tutorial = CombineTutorial()
    deterministic_mapper = DeterministicFileMapper(max_retries=5, wait=20)
    Each node in the execution graph is instantiated as a distinct operational unit. Nodes that perform external I/O or LLM inference (MapAbstractions, ReduceAbstractions, IdentifyAbstractions, AnalyzeRelationships, OrderChapters, WriteChapters, and DeterministicFileMapper) are initialized with exponential backoff parameters (max_retries=5, wait=20). Nodes performing local data transformations or routing without external network calls (FetchRepo, ContextRouter, CombineTutorial) are instantiated with default retry parameters to minimize operational overhead.

    Phase 2: Context Router Branching

        fetch_repo >> context_router

    context_router - "direct" >> identify_abstractions
    context_router - "batch" >> map_abstractions
    context_router - "deterministic" >> deterministic_mapper
    Execution begins with FetchRepo, which passes the crawled repository contents to ContextRouter. The router evaluates the codebase token footprint against context thresholds or user configuration flags and emits an action string ("direct", "batch", or "deterministic"). Conditional shift operators route the flow to the corresponding target node.

    Phase 3: Abstraction Map-Reduce and Relationship Convergence

        map_abstractions >> reduce_abstractions

    identify_abstractions >> analyze_relationships
    reduce_abstractions >> analyze_relationships

    analyze_relationships >> order_chapters
    order_chapters >> write_chapters
    The graph defines structural convergence for non-deterministic routes. If the "batch" route is triggered, map_abstractions streams partitioned abstraction candidates into reduce_abstractions. Both reduce_abstractions (from the batch path) and identify_abstractions (from the direct path) feed into analyze_relationships. Once cross-component interactions are analyzed, order_chapters builds a topological narrative sequence, which is then passed to write_chapters.

    Phase 4: Deterministic Bypass and Pipeline Assembly

        deterministic_mapper >> write_chapters

    write_chapters >> combine_tutorial

    return Flow(start=fetch_repo)
    When operating under the deterministic strategy, deterministic_mapper produces chapter definitions directly from the directory tree, bypassing abstraction identification, relationship analysis, and chapter ordering stages. It connects directly to write_chapters. Finally, write_chapters transitions to CombineTutorial for table-of-contents compilation and artifact persistence. The constructed pipeline is wrapped in a pocketflow.Flow instance with fetch_repo designated as the root entrypoint.

    Parameters: * None.

    Returns: * Flow: A fully wired, executable pocketflow.Flow pipeline ready to be run via .run() in main.py.

    Example: 

    # Extracted from main.py workflow execution
flow = create_tutorial_flow()
shared = {
    "repo_path": repo_path,
    "output_dir": output_dir,
    "language": language,
}
flow.run(shared)

    Data Structures

    Graph Topology Configuration

    The create_tutorial_flow() function configures the pipeline topology by instantiating nodes and passing runtime retry configurations:

    Node Variable Name Class Type Retry Strategy Operational Responsibility
    fetch_repo FetchRepo Default (max_retries=0) Ingests repository files from disk or GitHub REST/SSH endpoints.
    context_router ContextRouter Default (max_retries=0) Evaluates token budget and decides graph branching path.
    map_abstractions MapAbstractions max_retries=5, wait=20 Extracts architectural abstractions from file batches in parallel/sequence.
    reduce_abstractions ReduceAbstractions max_retries=5, wait=20 Consolidates and deduplicates batch abstraction outputs.
    identify_abstractions IdentifyAbstractions max_retries=5, wait=20 Performs single-pass abstraction extraction for small codebases.
    analyze_relationships AnalyzeRelationships max_retries=5, wait=20 Maps interfaces, call chains, and data flow between abstractions.
    order_chapters OrderChapters max_retries=5, wait=20 Topologically sorts chapters into a progressive tutorial outline.
    deterministic_mapper DeterministicFileMapper max_retries=5, wait=20 Maps files directly to chapters in 1:1 documentation modes.
    write_chapters WriteChapters max_retries=5, wait=20 Drafts comprehensive Markdown content for each chapter using LLM calls.
    combine_tutorial CombineTutorial Default (max_retries=0) Compiles final index, generates mkdocs.yml, and persists assets.

    Shared State Schema

    While flow.py defines the graph topology, all connected nodes read from and write to a shared dictionary (shared: dict[str, Any]) passed to Flow.run(). The following table documents the state keys manipulated across the graph:

    State Key Type Produced By Consumed By Description
    repo_path str Entrypoint (main.py) FetchRepo Local file path or remote Git URL of the target repository.
    files dict[str, str] FetchRepo ContextRouter, MapAbstractions, IdentifyAbstractions, WriteChapters Map of relative file paths to normalized UTF-8 file content.
    routing_strategy str ContextRouter ContextRouter Decision string: "direct", "batch", or "deterministic".
    file_batches list[list[str]] ContextRouter MapAbstractions Chunked file path lists partitioned for context window fitting.
    abstractions list[dict] IdentifyAbstractions, ReduceAbstractions AnalyzeRelationships, WriteChapters Identified architectural modules, core abstractions, and roles.
    relationships list[dict] AnalyzeRelationships OrderChapters, WriteChapters Directed relationships and interactions between abstractions.
    chapters list[dict] OrderChapters, DeterministicFileMapper WriteChapters, CombineTutorial Chapter definitions containing title, objective, and assigned files.
    written_chapters dict[str, str] WriteChapters CombineTutorial Map of chapter identifiers to generated Markdown text.
    language str Entrypoint (main.py) All LLM Nodes Target language code for localization (e.g., "en", "zh").

    Error Handling

    Error handling in flow.py is established declaratively through pocketflow node properties:

    • Inference and Network Retries: Nodes communicating with external APIs or LLM inference backends (IdentifyAbstractions, MapAbstractions, ReduceAbstractions, AnalyzeRelationships, OrderChapters, WriteChapters, DeterministicFileMapper) are initialized with max_retries=5 and wait=20. If an API call fails due to rate limits (HTTP 429), server timeouts (HTTP 500/503), or malformed JSON responses, pocketflow intercepts the exception, sleeps for 20 seconds, and retries the node execution up to 5 times before bubbling the exception up to the host process.
    • Deterministic Path Isolation: The routing design isolates failures across branches. If an invalid codebase structure is passed to DeterministicFileMapper, the error is confined to the deterministic branch without initializing unnecessary abstraction extraction nodes.
    • Graph Integrity: If any node in the active execution path exhausts its retry attempts, the Flow execution halts immediately, preventing incomplete or corrupted state data from reaching CombineTutorial.
