    flow.py

    Source: flow.py

    Following the token estimation and context analysis layer documented in utils/token_utils.py, flow.py defines the macro-orchestration graph for the Codebase-Knowledge-Builder pipeline. It assembles discrete computation and LLM generation nodes into an executable Directed Acyclic Graph (DAG) using the pocketflow framework.

    Technical Overview

    flow.py serves as the pipeline assembly blueprint for the codebase documentation system. It encapsulates the instantiation, parameter configuration, branch routing, and dependency wiring required to execute end-to-end repository analysis.

    The module models the documentation process across three distinct operational strategies determined dynamically at runtime: 1. Direct Context Flow: Ingests codebases whose token footprint fits within the target Large Language Model's (LLM) single-turn context window, extracting top-level abstractions directly. 2. Batch / MapReduce Flow: Decomposes large codebases into manageable semantic partitions, mapping individual file clusters to localized abstractions before reducing and synthesizing them into a global architectural model. 3. Deterministic 1-to-1 Mapping Flow: Bypasses heuristic abstraction clustering entirely, mapping every discrete source file directly to a dedicated technical reference chapter.

    Architectural Mechanics

    Graph Composition via PocketFlow Operators

    flow.py leverages operator overloading provided by pocketflow: * Unconditional Forward Chaining (>>): Connects the output of an upstream node to the input of a downstream node (e.g., fetch_repo >> context_router). * Action-Driven Conditional Routing (- "action" >>): Connects an upstream decision node's discrete return value to an explicit successor node (e.g., context_router - "direct" >> identify_abstractions).

    Fault Tolerance and Retry Policies

    LLM-backed nodes across all branches are initialized with standardized retry policies (max_retries=5, wait=20). This configuration guarantees resilience against: * External API rate limiting (HTTP 429 status codes from OpenAI, Gemini, or OpenRouter endpoints). * Transient network disconnections and gateway timeouts (HTTP 502/503/504). * Malformed JSON or schema validation failures during prompt-response extraction.

    In contrast, deterministic nodes that operate exclusively on local file systems or in-memory data structures (FetchRepo, ContextRouter, CombineTutorial) execute with default immediate-execution policies.

    Module-Level Functions

    create_tutorial_flow()

    Visibility: Public
    Signature: def create_tutorial_flow() -> Flow:

    Description:
    Instantiates all pipeline execution nodes defined in nodes.py, applies node-specific execution parameters, configures conditional and linear DAG transition edges, and packages the topology into an executable pocketflow.Flow runtime container anchored at the FetchRepo node.

    Parameters:
    * None.

    Returns:
    * Flow: A compiled PocketFlow DAG container configured with FetchRepo as the starting execution node (start=fetch_repo).

    Raises:
    * No exceptions are raised directly during compilation. Runtime execution errors within nodes are managed by pocketflow's execution engine according to node retry parameters.

    Example: 

    # Sourced from flow.py: Node instantiation and DAG assembly
def create_tutorial_flow():
    fetch_repo = FetchRepo()
    context_router = ContextRouter()
    map_abstractions = MapAbstractions(max_retries=5, wait=20)
    reduce_abstractions = ReduceAbstractions(max_retries=5, wait=20)
    identify_abstractions = IdentifyAbstractions(max_retries=5, wait=20)
    analyze_relationships = AnalyzeRelationships(max_retries=5, wait=20)
    order_chapters = OrderChapters(max_retries=5, wait=20)
    write_chapters = WriteChapters(max_retries=5, wait=20)
    combine_tutorial = CombineTutorial()
    deterministic_mapper = DeterministicFileMapper(max_retries=5, wait=20)

    fetch_repo >> context_router

    context_router - "direct" >> identify_abstractions
    context_router - "batch" >> map_abstractions
    context_router - "deterministic" >> deterministic_mapper

    map_abstractions >> reduce_abstractions

    identify_abstractions >> analyze_relationships
    reduce_abstractions >> analyze_relationships

    analyze_relationships >> order_chapters
    order_chapters >> write_chapters

    deterministic_mapper >> write_chapters

    write_chapters >> combine_tutorial

    return Flow(start=fetch_repo)

    The create_tutorial_flow function defines the orchestration topology for documentation generation:

    1. Node Instantiation: Ten discrete node classes are instantiated. Nodes executing generative tasks receive max_retries=5 and wait=20 (in seconds) to handle upstream LLM throttling.
    2. Ingestion Layer: fetch_repo transitions unconditionally via >> to context_router.
    3. Tri-Fork Routing: context_router inspects the ingestion parameters and repository payload, returning an action string ("direct", "batch", or "deterministic").
    4. Abstraction Processing:
    5. The "direct" route sends small codebases to identify_abstractions.
    6. The "batch" route triggers MapReduce summarization through map_abstractions followed by reduce_abstractions.
    7. Both abstraction pipelines converge on analyze_relationships, which calculates cross-module dependencies and passes data to order_chapters.
    8. Deterministic Mapping: The "deterministic" route bypasses abstraction discovery entirely, invoking deterministic_mapper to generate a 1-to-1 mapping of files to chapters.
    9. Convergence and Export: Both the abstraction flow (via order_chapters) and the deterministic flow converge at write_chapters. Once chapter generation completes, combine_tutorial synthesizes indexes, navigation manifests, and static site generator (SSG) assets.
    10. Flow Construction: Returns Flow(start=fetch_repo), establishing fetch_repo as the single entry point.

    Execution Topology Reference

    Predecessor Node Transition Operator Condition / Action Successor Node Description
    FetchRepo >> Unconditional ContextRouter Ingests repository files and immediately passes context to the router.
    ContextRouter - "direct" >> "direct" IdentifyAbstractions Triggered when repository size fits within the LLM context window.
    ContextRouter - "batch" >> "batch" MapAbstractions Triggered when repository size requires chunked MapReduce extraction.
    ContextRouter - "deterministic" >> "deterministic" DeterministicFileMapper Triggered when 1-to-1 source file-to-chapter documentation is requested.
    MapAbstractions >> Unconditional ReduceAbstractions Passes batch-extracted chunk summaries to the reducer for consolidation.
    IdentifyAbstractions >> Unconditional AnalyzeRelationships Passes extracted core abstractions to the relationship analysis node.
    ReduceAbstractions >> Unconditional AnalyzeRelationships Passes consolidated abstractions to the relationship analysis node.
    AnalyzeRelationships >> Unconditional OrderChapters Passes dependency matrices to determine pedagogical chapter order.
    OrderChapters >> Unconditional WriteChapters Passes ordered chapter plans to the content synthesis engine.
    DeterministicFileMapper >> Unconditional WriteChapters Bypasses ordering and sends file-to-chapter mappings directly to writer.
    WriteChapters >> Unconditional CombineTutorial Passes all generated markdown chapters to the aggregator and SSG builder.

    1. Ingestion Invariant: Downstream routing depends on FetchRepo successfully populating shared["files"] with a mapping of relative file paths to normalized file contents.
    2. Branch Invariant: Exactly one of the three paths (direct, batch, or deterministic) is executed for any given pipeline run.
    3. Synthesis Invariant: WriteChapters receives a normalized sequence of chapter specifications regardless of whether they originated from OrderChapters (conceptual abstractions) or DeterministicFileMapper (concrete file paths).
    4. Persistence Invariant: CombineTutorial assumes all markdown files referenced in the chapter manifest have been serialized to disk by WriteChapters.
