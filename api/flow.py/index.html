    flow.py

    Source: flow.py

    Following the volumetric profiling and context limit enforcement established in token_utils.py, the system requires an execution orchestrator to coordinate repository ingestion, conditional decomposition, abstraction analysis, and document assembly. The flow.py module defines this central workflow orchestration layer for the Codebase-Knowledge-Builder architecture.

    Technical Overview

    The flow.py module serves as the declarative pipeline factory for the entire repository documentation engine. Utilizing the lightweight PocketFlow framework, it wires discrete computational and LLM reasoning steps—defined in nodes.py—into a directed acyclic graph (DAG). The module establishes node dependencies, configures retry and backoff thresholds for upstream inference operations, and sets up conditional routing branches that adapt execution based on the volumetric dimensions of the target codebase.

    The execution graph initiates repository ingestion through FetchRepo before delegating routing decisions to ContextRouter. Depending on token budgets, repository topology, and user-selected processing strategies, execution branches into one of three distinct sub-pipelines: 1. Direct Path ("direct"): Executes single-pass abstraction discovery (IdentifyAbstractions) for compact codebases that fit within the model's active context window. 2. Batch Path ("batch"): Executes a map-reduce pipeline (MapAbstractions >> ReduceAbstractions) that divides large codebases into structural chunks, processes them in parallel, and merges intermediate abstraction records. 3. Deterministic Path ("deterministic"): Bypasses abstraction analysis entirely using DeterministicFileMapper, mapping source files directly to documentation chapters via algorithmic rules.

    All branches eventually converge on chapter generation (WriteChapters) and final document assembly (CombineTutorial), producing static documentation artifacts. Telemetry and structural auditing events are piped directly to the system logging layer via output.py.

    Public API

    create_tutorial_flow()

    Visibility: Public Signature: def create_tutorial_flow() -> Flow:

    Description: Assembles and returns the complete PocketFlow execution DAG for repository analysis and tutorial generation. It instantiates ten pipeline nodes, sets explicit retry parameters for LLM-bound operations, constructs conditional and linear graph edges, emits debug telemetry to disk logs, and packages the topology into an executable Flow instance rooted at FetchRepo.

    Parameters: * None.

    Returns: * Flow: An initialized pocketflow.Flow engine instance configured with FetchRepo as its starting node.

    Raises: * This factory function does not raise exceptions directly; any configuration or instantiation errors in the underlying nodes or PocketFlow framework will bubble up during invocation.

    Node Instantiation and Retry Policy Configuration

        fetch_repo = FetchRepo()
    context_router = ContextRouter()
    map_abstractions = MapAbstractions(max_retries=5, wait=20)
    reduce_abstractions = ReduceAbstractions(max_retries=5, wait=20)
    identify_abstractions = IdentifyAbstractions(max_retries=5, wait=20)
    analyze_relationships = AnalyzeRelationships(max_retries=5, wait=20)
    order_chapters = OrderChapters(max_retries=5, wait=20)
    write_chapters = WriteChapters(max_retries=5, wait=20)
    combine_tutorial = CombineTutorial()
    deterministic_mapper = DeterministicFileMapper(max_retries=5, wait=20)
    This phase constructs the ten discrete operational units of the documentation pipeline. Nodes interfacing directly with remote LLM inference endpoints (MapAbstractions, ReduceAbstractions, IdentifyAbstractions, AnalyzeRelationships, OrderChapters, WriteChapters, and DeterministicFileMapper) are explicitly configured with max_retries=5 and wait=20 (seconds). This design ensures that temporary network disconnects, model provider rate limits (such as HTTP 429 Too Many Requests), and transient server errors (HTTP 500/503) do not terminate the entire pipeline run. Conversely, purely algorithmic or local I/O nodes (FetchRepo, ContextRouter, CombineTutorial) are instantiated with default retry parameters since they execute locally without network-bound model dependencies.

    Tri-Modal Context Routing and Branch Topology

        fetch_repo >> context_router

    context_router - "direct" >> identify_abstractions
    context_router - "batch" >> map_abstractions
    context_router - "deterministic" >> deterministic_mapper

    map_abstractions >> reduce_abstractions
    This phase configures the ingestion pipeline and the conditional branching strategy. Using PocketFlow's right-shift operator (>>), FetchRepo is piped directly into ContextRouter. The router evaluates codebase token requirements and runtime flags, returning one of three action strings: "direct", "batch", or "deterministic". PocketFlow's conditional action-branching operator (- "action" >>) attaches each target node to its matching routing key. If "batch" is selected, execution flows through a map-reduce pipeline where MapAbstractions processes code chunks and passes intermediate abstraction maps directly into ReduceAbstractions for structural reconciliation.

    Graph Convergence, Synthesis, and Assembly

        identify_abstractions >> analyze_relationships
    reduce_abstractions >> analyze_relationships

    analyze_relationships >> order_chapters
    order_chapters >> write_chapters

    deterministic_mapper >> write_chapters

    write_chapters >> combine_tutorial

    emit_raw("DEBUG", "create_tutorial_flow | constructed PocketFlow execution graph", dest="LOG")
    return Flow(start=fetch_repo)
    This phase merges the parallel execution paths and connects the synthesis stages. Both IdentifyAbstractions (from the "direct" route) and ReduceAbstractions (from the "batch" route) converge on AnalyzeRelationships to evaluate cross-module dependencies, which then flows into OrderChapters to determine the pedagogical narrative structure. The "deterministic" path bypasses structural and relationship analysis entirely, routing DeterministicFileMapper directly into WriteChapters. At WriteChapters, all paths converge to author individual chapter Markdown files before CombineTutorial packages navigation files, copies assets, and writes static site files. Finally, the factory logs a diagnostic trace via emit_raw() to the persistent session log and encapsulates the graph into a Flow instance starting at FetchRepo.

    Example: 

    # Extracted from main.py: Instantiating and executing the flow
flow = create_tutorial_flow()
shared_context = {
    "repo_path": repo_path,
    "output_dir": output_dir,
    "language": language,
    "mode": mode,
}
flow.run(shared_context)

    Data Structures

    The flow.py module defines the structural topology of the pipeline and instantiates execution abstractions. The primary operational entities configured and returned by this module are detailed below.

    Node Instantiation Specifications

    Each node in the execution graph has specific runtime retry and backoff parameters:

    Node Name Class Reference LLM-Bound max_retries wait (seconds) Primary Operational Role
    fetch_repo FetchRepo No Default (0) Default (0) Clones remote Git repositories or scans local source directories.
    context_router ContextRouter No Default (0) Default (0) Evaluates token counts and routing parameters to select the execution path.
    map_abstractions MapAbstractions Yes 5 20 Analyzes code chunks in parallel to extract preliminary abstractions.
    reduce_abstractions ReduceAbstractions Yes 5 20 Merges chunked abstraction candidates into a deduplicated domain catalog.
    identify_abstractions IdentifyAbstractions Yes 5 20 Single-pass discovery of core abstractions for codebases within context limits.
    analyze_relationships AnalyzeRelationships Yes 5 20 Maps interactions, data flows, and dependencies between identified abstractions.
    order_chapters OrderChapters Yes 5 20 Sequences abstractions into a coherent, pedagogical reading curriculum.
    deterministic_mapper DeterministicFileMapper Yes 5 20 Heuristically maps codebase files into documentation chapters without abstraction discovery.
    write_chapters WriteChapters Yes 5 20 Generates detailed Markdown content for each chapter in the curriculum.
    combine_tutorial CombineTutorial No Default (0) Default (0) Builds MkDocs configuration, standardizes links, and writes documentation to disk.

    PocketFlow Flow Container

    The primary return type of create_tutorial_flow() is an instance of pocketflow.Flow.

    Field / Attribute Type Description
    start BaseNode The designated entry node of the DAG (fetch_repo).
    run Callable[[dict], None] Orchestration method that receives the shared dictionary and walks the DAG until all terminal nodes complete.

    Pipeline Shared Store Context Contract

    Although flow.py does not directly manipulate the shared state dictionary, it defines the graph edges that pass this state between nodes. The table below outlines the core schema expectations of the shared dictionary as it moves through the configured nodes:

    Key Expected Type Producer Node Consumer Node(s) Description
    repo_path str Entry (main.py) FetchRepo Filesystem path or remote URL of the target codebase.
    files_data list[tuple[str, str]] FetchRepo ContextRouter, All Mappers List of (relative_path, file_content) tuples extracted during crawl.
    directory_tree str FetchRepo ContextRouter, All Mappers Serialized text representation of the repository directory layout.
    context_mode str ContextRouter PocketFlow Routing Engine Resolved routing action: "direct", "batch", or "deterministic".
    abstractions list[dict] IdentifyAbstractions, ReduceAbstractions AnalyzeRelationships Extracted core architectural concepts and their source mappings.
    relationships list[dict] AnalyzeRelationships OrderChapters Cross-concept dependency and interaction definitions.
    chapters list[dict] OrderChapters, DeterministicFileMapper WriteChapters Ordered curriculum structure defining chapter titles, paths, and contents.
    written_chapters list[dict] WriteChapters CombineTutorial Synthesized Markdown chapter payloads with summary briefs.
    final_output_dir str CombineTutorial Exit (main.py) Destination path containing the rendered MkDocs site or standalone Markdown files.

    Error Handling

    The flow.py module establishes error resilience through declarative node configuration and graph design rather than explicit try/except blocks:

    • Inference Rate Limiting & Transient Network Faults: Remote LLM calls are vulnerable to network interruptions and provider throttling. Every node interacting with remote inference APIs (MapAbstractions, ReduceAbstractions, IdentifyAbstractions, AnalyzeRelationships, OrderChapters, WriteChapters, DeterministicFileMapper) is instantiated with max_retries=5 and wait=20. If an underlying call to call_llm() fails, PocketFlow catches the failure, blocks for 20 seconds, and retries up to five times before marking the node as failed.
    • Graph Path Isolation: Conditional routing guarantees path isolation. By segregating "direct", "batch", and "deterministic" paths at ContextRouter, the pipeline prevents incompatible processing states from executing simultaneously. For example, MapAbstractions will never run if ContextRouter selects "direct", preventing unneeded chunking overhead.
    • Deterministic Fallback Convergence: The "deterministic" route bypasses both abstraction analysis (IdentifyAbstractions / ReduceAbstractions) and relationship mapping (AnalyzeRelationships), feeding its outputs directly into WriteChapters. This ensures that even if a codebase cannot be processed via abstraction extraction, the graph can still converge at WriteChapters and complete document synthesis.
    • Flow-Level Failure Propagation: PocketFlow terminates execution and bubbles exceptions to the runtime caller (main.py) if any node exhausts its configured retry attempts. Unhandled failures inside local nodes (FetchRepo, ContextRouter, CombineTutorial) fail immediately without retries, surfacing bugs in file I/O or configuration without masking them.
