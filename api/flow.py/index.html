    flow.py

    Source: flow.py

    Following the token estimation, budgeting, and ratio calibration mechanics established in utils/token_utils.py, flow.py provides the declarative orchestration layer for the entire documentation pipeline. It compiles the discrete operational stages of codebase analysis, semantic abstraction, fact extraction, and chapter compilation into an executable Directed Acyclic Graph (DAG) using the pocketflow workflow engine.

    Technical Overview

    flow.py defines the macro-level execution graph for the Codebase-Knowledge-Builder system. The module exposes a single factory function, create_tutorial_flow(), which instantiates workflow nodes declared in nodes.py and wires them together using PocketFlow's domain-specific operator syntax. Through operator overloading (>> for sequential transitions and - "action" >> for dynamic conditional dispatch), flow.py establishes deterministic routing paths that adapt dynamically based on repository volume, token capacity, and operational generation mode.

    The graph architecture accommodates three distinct execution topologies anchored at the ContextRouter node: 1. Direct Path ("direct"): Activated for small codebases that fit entirely within the target model's context window. It bypasses chunking and dispatches directly to IdentifyAbstractions to extract high-level architectural concepts in a single unified prompt. 2. Batch Path ("batch"): Activated when a repository exceeds direct context budgets. It engages a MapReduce topology, routing source files through MapAbstractions to extract modular domain concepts across clustered file subsets, which are then consolidated by ReduceAbstractions. 3. Deterministic Path ("deterministic"): Activated for structured generation modes (such as api-reference or deterministic layouts). It bypasses heuristic abstraction discovery to map files systematically via DeterministicFileMapper and extracts ground-truth symbols and dependencies via ExtractFacts.

    These divergent pathways converge at key downstream integration nodes. The abstraction branches (IdentifyAbstractions and ReduceAbstractions) feed into AnalyzeRelationships to construct a unified dependency graph, which OrderChapters uses to sequence a didactic curriculum. In parallel, the deterministic branch streams ground-truth code citations from ExtractFacts directly into WriteChapters. WriteChapters reconciles the structural curriculum with verified source facts, drafting the individual documentation chapters before CombineTutorial serializes the final documentation site to disk.

    Public API

    create_tutorial_flow()

    Visibility: Public
    Signature: def create_tutorial_flow() -> Flow:

    Description: Constructs, configures, and returns the complete PocketFlow execution graph for the codebase analysis and documentation generation pipeline. It initializes all constituent nodes with operational retry and backoff thresholds, links them into sequential and conditional transitions, logs graph creation to the diagnostic log stream, and binds the flow execution root to FetchRepo.

    The method is structured into four distinct execution phases:

    Phase 1: Node Instantiation and Resilience Configuration

    def create_tutorial_flow():
    fetch_repo = FetchRepo()
    context_router = ContextRouter()
    map_abstractions = MapAbstractions(max_retries=5, wait=20)
    reduce_abstractions = ReduceAbstractions(max_retries=5, wait=20)
    identify_abstractions = IdentifyAbstractions(max_retries=5, wait=20)
    analyze_relationships = AnalyzeRelationships(max_retries=5, wait=20)
    order_chapters = OrderChapters(max_retries=5, wait=20)
    write_chapters = WriteChapters(max_retries=5, wait=20)
    combine_tutorial = CombineTutorial()
    deterministic_mapper = DeterministicFileMapper(max_retries=5, wait=20)
    extract_facts = ExtractFacts(max_retries=3, wait=10)  # one small call per file; the last attempt keeps what verifies
    # ...

    In this phase, all node instances participating in the pipeline lifecycle are instantiated with specific retry parameters. Network-bound and LLM-dependent operations—such as MapAbstractions, ReduceAbstractions, IdentifyAbstractions, AnalyzeRelationships, OrderChapters, WriteChapters, and DeterministicFileMapper—are initialized with max_retries=5 and an exponential backoff interval of wait=20 seconds to handle rate-limiting (HTTP 429), gateway timeouts (HTTP 504), and temporary provider capacity exhaustion. In contrast, ExtractFacts receives a tailored resilience profile (max_retries=3, wait=10), reflecting its per-file execution scope where each attempt audits verifiable facts against the source code, retaining verified citations across transient failures. Local I/O and routing nodes (FetchRepo, ContextRouter, and CombineTutorial) require no remote inference retries and operate under default execution constraints.

    Phase 2: Ingestion and Context-Aware Fan-Out Routing

        # ...
    fetch_repo >> context_router

    context_router - "direct" >> identify_abstractions
    context_router - "batch" >> map_abstractions
    context_router - "deterministic" >> deterministic_mapper
    # ...

    This phase wires the entry point and establishes conditional branching. The sequence begins with fetch_repo >> context_router, passing the raw repository ingestion payload (cloned Git directory or crawled local tree) directly into the routing engine. ContextRouter evaluates the overall codebase volume against active model context windows and inspects the execution mode. Using PocketFlow's conditional syntax (node - action >> target), the router branches execution into one of three isolated processing tracks: emitting "direct" routes execution to identify_abstractions for small single-context analysis; emitting "batch" routes execution to map_abstractions for MapReduce chunking; and emitting "deterministic" routes execution to deterministic_mapper for structured file-to-chapter layouts.

    Phase 3: Abstraction Analysis and Curriculum Sequencing

        # ...
    map_abstractions >> reduce_abstractions

    identify_abstractions >> analyze_relationships
    reduce_abstractions >> analyze_relationships

    analyze_relationships >> order_chapters
    order_chapters >> write_chapters
    # ...

    This phase manages the reduction and semantic synthesis of architectural concepts. If the batch path is chosen, map_abstractions streams chunked concept summaries into reduce_abstractions, which deduplicates and condenses entity models. Both identify_abstractions (from the direct path) and reduce_abstractions (from the batch path) converge on analyze_relationships. AnalyzeRelationships inspects the unified abstractions, resolves cross-cutting interfaces, and models architectural dependencies. Once the relationship graph is established, order_chapters digests the dependency topology to construct an incremental pedagogical curriculum. The ordered chapter list is then forwarded to the compilation engine, write_chapters.

    Phase 4: Fact Extraction Convergence, Assembly, and Graph Finalization

        # ...
    deterministic_mapper >> extract_facts >> write_chapters

    write_chapters >> combine_tutorial

    emit_raw("DEBUG", "create_tutorial_flow | constructed PocketFlow execution graph", dest="LOG")
    return Flow(start=fetch_repo)

    This phase converges factual ground-truth with curriculum drafting and exports the graph. In parallel with the abstraction pipeline, the deterministic branch links deterministic_mapper sequentially to extract_facts, which audits source files line-by-line to extract verified assertions, symbols, and dependencies. Both the chapter sequence from order_chapters and the verified source facts from extract_facts converge at write_chapters, ensuring that LLM chapter drafting is anchored by concrete ground-truth citations. Once chapters are drafted, execution transitions to combine_tutorial to write static assets, normalize links, generate MkDocs configurations, and output Markdown documents. Finally, emit_raw() logs graph construction to the debug log file, and a new Flow object initialized with start=fetch_repo is returned to the caller.

    Parameters: * None.

    Returns: * pocketflow.Flow: A fully wired, non-executed PocketFlow graph instance configured with FetchRepo as the root entry point.

    Raises: * This function does not raise exceptions internally. Node instantiation and edge connection are validated syntactically at runtime by the pocketflow engine.

    Example: 

    # Extracted from main.py:
from flow import create_tutorial_flow

# Initialize the workflow graph
flow = create_tutorial_flow()

# Execute the flow passing the shared runtime state dictionary
flow.run(shared_context)

    Data Structures

    flow.py orchestrates nodes that read from and write to a shared context dictionary passed through the pocketflow.Flow engine. The primary data structures and configuration parameters governing this module are documented below.

    Node Resilience and Retry Policies

    The following table details the operational retry configurations defined in flow.py:

    Node Variable Target Node Class max_retries wait (seconds) Primary Operational Rationale
    fetch_repo FetchRepo 0 (default) 0 (default) Local disk crawling or Git cloning; failures are deterministic and terminal.
    context_router ContextRouter 0 (default) 0 (default) In-memory token counting and mode inspection; no external network I/O.
    map_abstractions MapAbstractions 5 20 High-volume batch LLM prompts; guards against transient 429 and 5xx errors.
    reduce_abstractions ReduceAbstractions 5 20 Heavy multi-abstraction synthesis; protects against token context timeouts.
    identify_abstractions IdentifyAbstractions 5 20 Monolithic repository analysis; prone to extended chain-of-thought latency.
    analyze_relationships AnalyzeRelationships 5 20 Global graph modeling; retries on schema or JSON parsing failures.
    order_chapters OrderChapters 5 20 Pedagogical curriculum sorting; guards against malformed YAML index responses.
    write_chapters WriteChapters 5 20 Extended multi-page chapter generation; vulnerable to network read timeouts.
    combine_tutorial CombineTutorial 0 (default) 0 (default) Local file writing, link normalization, and MkDocs YAML synthesis.
    deterministic_mapper DeterministicFileMapper 5 20 LLM-assisted or rule-based module clustering in api-reference mode.
    extract_facts ExtractFacts 3 10 Granular per-file fact verification; lower retry count because verification persists.

    Routing Actions Schema

    The conditional transitions originating from context_router evaluate string action markers emitted by ContextRouter.run(). The table below outlines these routing contracts:

    Routing Action Key Target Node Activation Criteria Architectural Purpose
    "direct" IdentifyAbstractions Total repository tokens $\le$ model input token budget, and mode is heuristic (tutorial, etc.). Single-pass global abstraction discovery without file chunking.
    "batch" MapAbstractions Total repository tokens $>$ model input token budget, and mode is heuristic. MapReduce abstraction extraction across modular file slices.
    "deterministic" DeterministicFileMapper Execution mode is api-reference or deterministic layouts are requested. Strict 1:1 or 1:N file-to-chapter structural mapping.

    Shared State Context (PrepResult)

    Although flow.py does not declare classes, it configures the graph that mutates the pipeline's shared context dictionary. The key properties flowing through the graph include:

    Context Field Type Originating Node Consuming Nodes Description
    repo_url str \| None CLI / main.py FetchRepo Remote GitHub URL if crawling remote repositories.
    local_path str \| None CLI / main.py FetchRepo Local filesystem directory path if analyzing local code.
    files dict[str, str] FetchRepo ContextRouter, MapAbstractions, ExtractFacts Dictionary mapping relative file paths to decoded UTF-8 source contents.
    files_data list[tuple[str, str]] FetchRepo ContextRouter, DeterministicFileMapper Index-ordered list of (relative_path, content) tuples.
    directory_tree str FetchRepo IdentifyAbstractions, MapAbstractions Formatted ASCII directory hierarchy with file indices.
    abstractions list[dict] IdentifyAbstractions / ReduceAbstractions AnalyzeRelationships Extracted high-level domain concepts, roles, and responsibilities.
    relationships list[dict] AnalyzeRelationships OrderChapters Modeled dependency relationships and interaction patterns between abstractions.
    chapter_order list[dict] OrderChapters WriteChapters Sequenced curriculum defining chapter titles, paths, and abstraction scopes.
    facts dict ExtractFacts WriteChapters, CombineTutorial Ground-truth symbol tables, verified line citations, and module dependencies.
    chapters list[dict] WriteChapters CombineTutorial Rendered Markdown chapter bodies, file metadata, and relative links.

    Error Handling

    Error handling within flow.py is configured declaratively rather than imperatively:

    • Stochastic Failure Recovery: By injecting max_retries and wait into node constructors, flow.py delegates transient error recovery to PocketFlow. When a node encounters rate limits, network disconnects, or malformed LLM responses, PocketFlow pauses execution for the configured wait interval and retries the node execution up to the designated retry limit.
    • Partial Fact Verification Resilience: The configuration for extract_facts = ExtractFacts(max_retries=3, wait=10) contains inline defense logic: # one small call per file; the last attempt keeps what verifies. In ExtractFacts, each file is audited independently. If repeated retries fail on a subset of files, the node does not abort the entire pipeline; instead, it retains all citations verified during prior passes and marks unparseable items as unparsed, allowing WriteChapters to proceed with verified data.
    • Fail-Fast Graph Termination: If any node completely exhausts its retry budget (e.g., persistent HTTP 401 authentication rejections, terminal provider refusals via LLMRefusalError, or unrecoverable syntax errors), PocketFlow halts graph traversal immediately and propagates the unhandled exception up to the root caller in main.py. This prevents empty, corrupt, or partially hallucinated documentation from being written to disk.
