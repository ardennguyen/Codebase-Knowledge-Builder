    flow.py

    Source: flow.py

    Following the token sizing, context budgeting, and calibration mechanics implemented in token_utils.py, the flow.py module establishes the high-level execution topology for the entire documentation generation pipeline. While token budgeting utilities operate at the granular prompt and payload level, flow.py defines the macro-architectural orchestration layer, determining how codebase data flows between computational nodes, when conditional branching occurs, and how processing paths converge to produce structured technical documentation.

    Technical Overview

    The flow.py module serves as the central workflow definition engine for Codebase-Knowledge-Builder. Built on top of the lightweight PocketFlow graph orchestration framework, it declaratively defines the Directed Acyclic Graph (DAG) that executes repository crawling, abstraction extraction, relational architecture analysis, chapter ordering, drafting, and static-site synthesis. The module encapsulates the entire end-to-end lifecycle into a single factory function, create_tutorial_flow(), abstracting away graph instantiation and wiring from the application entry point in main.py.

    At runtime, the flow coordinates ten discrete task nodes imported from nodes.py. It handles three distinct structural pathways through dynamic routing: 1. Direct Path ("direct"): Sized for repositories whose code files fit comfortably within the LLM's active context window, routing directly through global abstraction identification (IdentifyAbstractions). 2. Batch Path ("batch"): Sized for massive codebases that exceed single-prompt context limits, breaking files into chunked sub-groups for parallel abstraction mapping (MapAbstractions) followed by an LLM-driven hierarchical reduction phase (ReduceAbstractions). 3. Deterministic Path ("deterministic"): Bypasses AI abstraction mapping entirely when configured for mode-specific direct file documentation (such as per-file API reference generators), dispatching directly to DeterministicFileMapper and bypassing intermediary relational analysis to feed raw file mappings directly into chapter drafting.

    Public API

    create_tutorial_flow()

    Visibility: Public
    Signature: def create_tutorial_flow() -> Flow:

    Description: Constructs, configures, and returns the executable PocketFlow.Flow instance containing the full codebase documentation pipeline. The function manages the instantiation of all underlying execution nodes from nodes.py, configures fault-tolerant retry parameters across inference-backed stages, links execution dependencies via operator overloading (>> and -), logs graph generation telemetry via output.py, and designates FetchRepo as the root entry point.

    Parameters: * None.

    Returns: * Flow: A fully wired PocketFlow.Flow execution graph initialized with FetchRepo as the starting node (start=fetch_repo).

    Raises: * This function does not raise runtime exceptions directly during construction; graph validation or node initialization errors are delegated to the underlying pocketflow library or node constructors.

    Implementation Phases:

    Node Instantiation and Parameter Configuration

        fetch_repo = FetchRepo()
    context_router = ContextRouter()
    map_abstractions = MapAbstractions(max_retries=5, wait=20)
    reduce_abstractions = ReduceAbstractions(max_retries=5, wait=20)
    identify_abstractions = IdentifyAbstractions(max_retries=5, wait=20)
    analyze_relationships = AnalyzeRelationships(max_retries=5, wait=20)
    order_chapters = OrderChapters(max_retries=5, wait=20)
    write_chapters = WriteChapters(max_retries=5, wait=20)
    combine_tutorial = CombineTutorial()
    deterministic_mapper = DeterministicFileMapper(max_retries=5, wait=20)

    During this initial phase, the function instantiates ten node objects. Distinct operational requirements are reflected in their initialization arguments: purely deterministic or filesystem-bound nodes (FetchRepo, ContextRouter, and CombineTutorial) are instantiated with default retry parameters because their execution relies on deterministic local logic or terminal disk I/O. Conversely, all nodes interfacing with remote LLM provider APIs (MapAbstractions, ReduceAbstractions, IdentifyAbstractions, AnalyzeRelationships, OrderChapters, WriteChapters, and DeterministicFileMapper) are explicitly injected with max_retries=5 and wait=20. This ensures that downstream transient network anomalies, remote provider HTTP 429 rate limits, and JSON/YAML deserialization issues are retried with 20-second backoffs before failing the flow.

    Graph Topology and Routing Definition

        fetch_repo >> context_router

    context_router - "direct" >> identify_abstractions
    context_router - "batch" >> map_abstractions
    context_router - "deterministic" >> deterministic_mapper

    map_abstractions >> reduce_abstractions

    identify_abstractions >> analyze_relationships
    reduce_abstractions >> analyze_relationships

    analyze_relationships >> order_chapters
    order_chapters >> write_chapters

    deterministic_mapper >> write_chapters

    write_chapters >> combine_tutorial

    This phase uses PocketFlow domain-specific operators to wire the pipeline's execution topology. Unconditional sequential steps are defined using the shift operator (>>), such that fetch_repo >> context_router ensures filesystem harvesting completes before evaluation starts. The conditional branching operator (- action >> target) splits execution from ContextRouter along three discrete paths based on repository size and mode ("direct", "batch", and "deterministic"). The graph then reconverges: both the "direct" and "batch" pipelines merge at AnalyzeRelationships, flow through OrderChapters, and reach WriteChapters. Concurrently, the "deterministic" path bypasses structural analysis entirely and links directly from DeterministicFileMapper to WriteChapters. Finally, chapter authoring unconditionally transitions to CombineTutorial for final site and file compilation.

    Telemetry Logging and Flow Encapsulation

        emit_raw("DEBUG", "create_tutorial_flow | constructed PocketFlow execution graph", dest="LOG")
    return Flow(start=fetch_repo)

    The final phase logs the graph creation event directly to disk logs using emit_raw() from utils/output.py. The call routes to dest="LOG" to prevent diagnostic noise from polluting standard interactive console streams. Once logged, the function wraps the complete execution topology into a pocketflow.Flow instance by binding fetch_repo as the designated root node, returning the flow object for downstream execution by main.py.

    Example: 

    # Call site extracted from main.py:
from flow import create_tutorial_flow

# ...
flow = create_tutorial_flow()
shared_context = {
    "repo_path": repo_path,
    # ... runtime parameters
}
flow.run(shared_context)

    Data Structures

    The flow.py module defines the structural integration between the underlying PocketFlow engine and the node implementations in nodes.py. It operates over the following structural contracts:

    Pipeline Node Execution Profiles

    The nodes instantiated within flow.py adhere to specific configuration profiles depending on whether they perform deterministic operations or remote inference:

    Node Variable Target Node Class Execution Category Configured Retries (max_retries) Backoff (wait) Upstream Dependencies Downstream Targets
    fetch_repo FetchRepo Deterministic I/O Default (0) Default (0) None (Start Node) context_router
    context_router ContextRouter Evaluation / Routing Default (0) Default (0) fetch_repo identify_abstractions, map_abstractions, deterministic_mapper
    identify_abstractions IdentifyAbstractions LLM Inference 5 20s context_router ("direct") analyze_relationships
    map_abstractions MapAbstractions LLM Inference 5 20s context_router ("batch") reduce_abstractions
    reduce_abstractions ReduceAbstractions LLM Inference 5 20s map_abstractions analyze_relationships
    deterministic_mapper DeterministicFileMapper LLM / Fallback 5 20s context_router ("deterministic") write_chapters
    analyze_relationships AnalyzeRelationships LLM Inference 5 20s identify_abstractions, reduce_abstractions order_chapters
    order_chapters OrderChapters LLM Inference 5 20s analyze_relationships write_chapters
    write_chapters WriteChapters LLM Inference 5 20s order_chapters, deterministic_mapper combine_tutorial
    combine_tutorial CombineTutorial Deterministic I/O Default (0) Default (0) write_chapters None (End Node)

    Branch Action Routing Contract

    The context_router node outputs string action tokens that determine edge traversal across the conditional branches:

    Action Identifier Trigger Condition Activated Node Skipped Subgraphs
    "direct" Single-prompt codebase token size below context ceiling. IdentifyAbstractions map_abstractions, reduce_abstractions, deterministic_mapper
    "batch" Large codebase token size exceeding context ceiling; requires batching. MapAbstractions identify_abstractions, deterministic_mapper
    "deterministic" Operational mode specifies 1:1 file-to-chapter documentation. DeterministicFileMapper identify_abstractions, map_abstractions, reduce_abstractions, analyze_relationships, order_chapters

    Error Handling

    The flow.py file delegates runtime exception handling to PocketFlow and the internal retry logic of individual nodes. However, it implements proactive fault tolerance through constructor parameter injection:

    • Inference Rate Limiting & Transient Flakiness: All nodes interacting with external LLMs (map_abstractions, reduce_abstractions, identify_abstractions, analyze_relationships, order_chapters, write_chapters, and deterministic_mapper) are configured with max_retries=5 and wait=20. When an underlying node encounters an API error, rate limit (HTTP 429), or malformed response format, PocketFlow intercepts the failure and sleeps for 20 seconds before retrying the node's prep -> exec -> post cycle, up to 5 times.
    • Deterministic Isolation: Nodes executing deterministic operations (FetchRepo, ContextRouter, and CombineTutorial) omit max_retries and wait. Failures within these stages (e.g., repository path not found, disk full, or write permission denied) are treated as fatal configuration or environmental errors and bubble up immediately to main.py without delaying the user with redundant retry cycles.
