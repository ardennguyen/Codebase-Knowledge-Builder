    Chapter Index

    Core Infrastructure & Telemetry

    Chapter Description
    output.py Manages terminal presentation, multi-lingual UI translation lookup, and timestamped file logging. It intercepts console output streams to ensure UTF-8 encoding and buffers early preflight telemetry until file handlers initialize.
    i18n.py Manages runtime UI string localization and automated translation of missing keys in strings.csv. Through auto_translate(), it batches untranslated strings, invokes configured LLMs, and safely persists updated catalogs using utf-8-sig encoding.

    Codebase Ingestion & Filtering

    Chapter Description
    exclude_patterns.py Defines centralized glob filtering rules to prevent ingesting binary assets, third-party libraries, build artifacts, and secrets. Its primary export, DEFAULT_EXCLUDE_PATTERNS, enables traversal engines to prune disqualified directories and files before tokenization.
    crawl_local_files.py Recursively traverses local directories to harvest source files into an in-memory dictionary. Through crawl_local_files(), it enforces .gitignore rules via pathspec, prunes directories in-place, and safely decodes UTF-8 text while skipping binaries.
    crawl_github_files.py Ingests remote repositories by downloading and decoding source code trees into memory. Through crawl_github_files(), it routes between Git-over-SSH cloning and GitHub REST API tree traversals, applying size gating, rate-limit backoffs, and path filtering.
    files.py Restructures ingested repository files and performs targeted content extraction to prevent context window overflow. Via build_directory_tree() and get_content_for_indices(), it compiles annotated ASCII directory trees and resolves file contents selected by model prompts.

    LLM Engine & Provider Adapters

    Configuration & Token Accounting

    Chapter Description
    llm_common.py Provides provider-neutral token accounting, execution telemetry, and error signaling across all LLM backends. It tracks usage across steps via usage_step(), hashes and memoizes deterministic API refusals, and flags truncated generations using TruncatedResponse.
    llm_config.py Centralizes configuration, credential preflight checking, and context-length resolution across supported LLM providers. Through resolve_llm_settings() and check_llm_auth(), it deterministically resolves models, endpoint URLs, and output token budgets before workflows execute.
    thinking.py Establishes cognitive budgeting and reasoning effort allocations across workflow nodes. It constructs per-node execution plans via build_thinking_plan() and uses clamp_level() to map canonical effort tiers onto provider-supported ranges.
    token_utils.py Manages token volume estimation, context budgeting, and cross-tokenizer calibration for heterogeneous model families. Through count_tokens() and observe_prompt_tokens(), it provides prompt thresholds and refines BPE ratios using empirical billing feedback.

    Dispatch & Model Adapters

    Chapter Description
    call_llm.py Serves as the centralized invocation gateway and provider abstraction layer for LLM operations. Through call_llm(), it coordinates SHA-256 content-addressable response caching, refusal short-circuiting, token pre-estimation, and routing across supported backend adapters.
    llm_anthropic.py Executes inference requests against Anthropic's Claude models over streaming HTTP connections. Through call_anthropic(), it adapts thinking effort budgets, escalates max token limits upon truncation, and handles transient SDK errors.
    llm_gemini.py Serves as the transport adapter for Google Gemini models via the google-genai SDK. Through call_gemini(), it manages server-sent event streaming, adapts thinking configurations, classifies refusal errors, and records multi-tiered token pricing.
    llm_openrouter.py Interfaces with OpenRouter's OpenAI-compatible completions API using a dynamic, catalog-driven architecture. Through call_openrouter(), it constructs completion payloads, aggregates Server-Sent Events streams, normalizes reasoning parameters, and tracks usage metrics.

    Prompt Engineering & Site Publishing

    Chapter Description
    prompts.py Composes prompts, resolves external Markdown templates, and parses structured model responses. Through load_prompt_template(), parse_yaml_response(), and parse_grouping_response(), it guarantees schema validation and catches truncated model outputs.
    mkdocs.py Synthesizes generated documentation chapters into interactive MkDocs Material sites or standalone Markdown bundles. Through write_mkdocs_output(), it builds navigation structures, fixes Mermaid diagrams, clusters API reference modules, and prunes stale pages.

    Workflow Pipeline & Execution

    Chapter Description
    nodes.py Implements the computational execution nodes that drive documentation generation within the workflow graph. It manages repository fetching, abstraction extraction, relationship analysis, chapter drafting with rolling context summaries, and documentation bundling.
    flow.py Models the workflow Directed Acyclic Graph orchestrating repository analysis and documentation generation. Through create_tutorial_flow(), it instantiates and connects PocketFlow nodes across direct, batch, and deterministic pathways with built-in retry backoffs.
    main.py Acts as the CLI entry point, runtime bootstrapper, and lifecycle manager for the platform. Through main(), it parses arguments, validates LLM credentials, initializes the shared blackboard state, and runs the workflow graph in flow.py.
