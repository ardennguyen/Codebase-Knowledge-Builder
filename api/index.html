    Chapter Index

    Application Entry Point

    Chapter Description
    main.py Serves as the centralized CLI entry point and execution harness for the documentation pipeline. It handles CLI argument parsing, environment preflight validation, LLM reasoning budget resolution, and workflow execution.

    Codebase Ingestion & Fact Extraction

    Chapter Description
    crawl_local_files.py Discovers, filters, and reads repository source files from local directories into an in-memory dictionary via crawl_local_files(). It enforces byte-size thresholds and respects hierarchical .gitignore rules and glob patterns.
    crawl_github_files.py Ingests source files from remote GitHub repositories through crawl_github_files(). It supports both Git cloning and GitHub REST API tree traversal while filtering out binary assets and oversized payloads.
    facts.py Extracts and validates code facts against source files without requiring language-specific AST parsers. It matches quote evidence against physical line intervals using SourceIndex and resolves cross-module dependencies via ModuleTable.
    files.py Provides in-memory file tree formatting and selective content retrieval for ingested source files. It formats indexed directory trees via build_directory_tree() and retrieves targeted code contents using get_content_for_indices().
    exclude_patterns.py Defines DEFAULT_EXCLUDE_PATTERNS, a set of glob patterns used across crawlers to filter out non-source files, binary assets, dependencies, and sensitive credentials during repository ingestion.

    Pipeline Orchestration & Synthesis

    Chapter Description
    mkdocs.py Synthesizes generated chapters into static MkDocs sites or standalone Markdown files via write_mkdocs_output(). It organizes navigation sections, generates Mermaid dependency diagrams, repairs markup defects, and prunes stale pages.
    nodes.py Defines the pipeline tasks and execution nodes governing ingestion, analysis, fact extraction, and chapter drafting under PocketFlow. Each node implements a three-phase prep, exec, and post lifecycle with atomic caching.
    flow.py Constructs the executable Directed Acyclic Graph for the documentation generation pipeline using PocketFlow. It wires discrete processing nodes into sequential and conditional routes through create_tutorial_flow().

    LLM Gateway & Provider Adapters

    Chapter Description
    llm_common.py Establishes provider-neutral data structures, error types like LLMRefusalError, and truncation wrappers like TruncatedResponse. It provides context-managed token accounting and SHA-256 refusal circuit breaking across pipeline steps.
    thinking.py Normalizes provider reasoning effort levels and compiles per-node computational budgets via build_thinking_plan(). It resolves assigned budgets with resolve_thinking_level() and projects normalized tiers onto model capabilities using clamp_level().
    llm_config.py Resolves model configurations, context limits, and credentials across LLM providers via resolve_llm_settings(). It runs preflight authentication checks with check_llm_auth() to halt execution early on missing dependencies or keys.
    llm_anthropic.py Implements the native Anthropic Claude provider adapter behind call_anthropic(). It handles streaming completions, adaptive reasoning parameters, prompt caching, token headroom clamping, and multi-iteration cost accounting.
    llm_gemini.py Implements the Google Gemini provider adapter via call_gemini(), routing requests to Google AI Studio or Vertex AI. It enforces whole-request deadlines, streaming responses, thinking budget fallbacks, and usage tracking.
    llm_openrouter.py Implements the OpenRouter API adapter via call_openrouter() using Server-Sent Events streaming. It queries dynamic model catalog metadata, clamps reasoning budgets, handles transient retries, and translates moderation rejections into structured errors.
    call_llm.py Acts as the centralized inference gateway for LLM communications across multiple providers. It coordinates SHA-256 disk caching, refusal circuit-breaking, and token usage accounting through call_llm().

    Prompt Management & Quality Assurance

    Chapter Description
    prompts.py Loads prompt templates from disk and dynamically formats context blocks and directives for LLM generation. It also implements fault-tolerant YAML response parsing and list salvaging via parse_yaml_response().
    chapter_check.py Performs deterministic quality assurance on generated Markdown chapters via run_chapter_check(). It validates CommonMark syntax, site renderer HTML markup fidelity, and factual consistency against verified source code facts.

    Telemetry, Logging & Localization

    Chapter Description
    output.py Provides centralized terminal color formatting, persistent file logging, and localized message emission via emit() and emit_raw(). It buffers early runtime events in memory and loads message templates from strings.csv.
    token_utils.py Handles token counting, context window headroom budgeting, and prompt sizing using tiktoken. It adaptively calibrates provider token ratios via observe_prompt_tokens() and formats financial cost breakdowns.
    i18n.py Manages internationalization by translating missing UI catalog strings in strings.csv via LLM inference calls. Its primary entry point auto_translate() parses batch translations and falls back safely to canonical English strings.
