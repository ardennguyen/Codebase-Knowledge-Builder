    main.py

    Source: main.py

    Technical Overview

    Serving as the primary runtime entry point for the Codebase-Knowledge-Builder toolchain, main.py bridges user-specified command-line configurations with the execution graph declared in flow.py. While flow.py defines the macro-architectural Directed Acyclic Graph (DAG) and data dependencies across discrete analysis nodes, main.py orchestrates the system's operational lifecycle: initializing environment parameters, validating inputs defensively, verifying remote API credentials, constructing the centralized mutable blackboard context (shared), dispatching workflow execution, and finalizing telemetry.

    The module executes a disciplined multi-stage bootstrapping procedure. It begins by loading local environment definitions through python-dotenv and compiling command-line arguments using argparse. Before delegating work to LLM nodes, main.py executes preflight validations: verifying that shell glob patterns did not inadvertently swallow other CLI flags, evaluating provider authentication credentials through utils/llm_config.py, configuring localized string registries via utils/output.py, and synthesizing a per-node reasoning effort plan through utils/thinking.py. Once preflight criteria are satisfied, the script builds a unified shared dictionary that encapsulates configuration parameters, input sources, filtering sets, and placeholder output references.

    During the execution phase, main.py instantiates the PocketFlow graph via create_tutorial_flow() and executes it against the shared state dictionary. A critical architectural invariant of this orchestrator is robust session durability: the pipeline execution is enclosed within a comprehensive try...finally block. Regardless of whether processing succeeds, halts on interruption, or crashes due to upstream rate limits, main.py guarantees the invocation of _emit_usage_summary() and shutdown(), ensuring that session costs, token usage metrics, and audit log file handles from utils/llm_common.py and utils/output.py are flushed to disk and displayed to the user.

    Public API

    parse_arguments()

    Visibility: Public Signature: def parse_arguments() -> tuple[argparse.ArgumentParser, argparse.Namespace]:

    Description: Configures the command-line argument schema, binds positional and keyword flags, defines custom argument validation types, and parses invocation parameters into an argparse.Namespace object. It handles mutual exclusivity between --repo and --dir, sets pipeline defaults, and registers flags across ingestion limits, documentation generation modes, static site generation, incremental build caching, and cognitive reasoning tiers.

    Parameters: * None.

    Returns: * tuple[argparse.ArgumentParser, argparse.Namespace]: A two-element tuple containing the active ArgumentParser instance (retained for contextual error formatting and introspection) and the populated Namespace encapsulating all parsed CLI options.

    Raises: * SystemExit: Implicitly raised by argparse when arguments violate declared constraints, unexpected flags are encountered, or required options are absent.

    Example: 

    # Extracted from main.py: main() orchestrator entry point
parser, args = parse_arguments()
# Resolved silently before init_output(): string translation itself uses the plan's translate_strings level.
thinking_profile, thinking_plan, invalid_overrides = resolve_thinking_plan(args)

    The function defines flags for repository sources (--repo, --dir, --cleanup), project identifiers (-n, --name, -t, --token, -o, --output), and path filters (-i, --include, -e, --exclude, -s, --max-size). It exposes documentation generation profiles through --mode (tutorial, advanced, api-reference, sdk), --mkdocs, --incremental, and --force-rebuild. Additionally, it binds granular LLM reasoning parameters (--thinking-level, --thinking-profile, --thinking-override) and batching configurations (--batch, --force-batch).

    resolve_mode_and_project()

    Visibility: Public Signature: def resolve_mode_and_project(args: argparse.Namespace) -> tuple[str, str]:

    Description: Normalizes the active documentation mode and derives the target project name from input sources. It arbitrates between the legacy --advanced boolean flag and explicit --mode selections, warning the user if conflicting flags are supplied. If an explicit project name is omitted from CLI arguments, it dynamically computes a fallback identifier using the directory name of local paths or the trailing slug of a Git repository URL (stripping .git suffixes).

    Parameters: * args (argparse.Namespace): Populated CLI options container.

    Returns: * tuple[str, str]: A tuple of (mode, project_name) where mode is one of 'tutorial', 'advanced', 'api-reference', or 'sdk', and project_name is the resolved canonical project directory name.

    Example: 

    def resolve_mode_and_project(args):
    """Resolve documentation mode (handling --advanced legacy flag) and derive project name.

    Returns:
        tuple[str, str]: (mode, project_name)
    """
    if args.advanced:
        if args.mode != "tutorial":  # User explicitly set --mode AND --advanced
            emit("WARN_ADVANCED_OVERRIDES_MODE", mode=args.mode)
        mode = "advanced"
    else:
        mode = args.mode
    project_name = args.name
    if not project_name:
        if args.dir:
            project_name = os.path.basename(os.path.abspath(args.dir))
        elif args.repo:
            project_name = args.repo.rstrip("/").split("/")[-1].removesuffix(".git")
        else:
            project_name = "project"
    return mode, project_name

    The function first checks if args.advanced was toggled. If true, it enforces mode = "advanced" and emits WARN_ADVANCED_OVERRIDES_MODE if --mode had also been configured to something other than 'tutorial'. For project name resolution, it prioritizes args.name; otherwise, it extracts the basename of the absolute local path for --dir, strips trailing slashes and Git extensions from remote URLs for --repo, or defaults conservatively to "project".

    build_shared_store()

    Visibility: Public Signature: def build_shared_store(args: argparse.Namespace, github_token: str | None, mode: str, thinking_plan: dict[str, str | None], project_name: str) -> dict[str, any]:

    Description: Assembles the master blackboard context (shared) utilized by all PocketFlow execution nodes. It transforms CLI arguments, authentication tokens, normalized patterns, and resolved reasoning strategies into a single mutable state dictionary. Furthermore, it initializes empty payload slots for ingestion assets, identified abstractions, relational maps, chapter orderings, drafted Markdown contents, and final disk locations.

    Parameters: * args (argparse.Namespace): Parsed command-line arguments. * github_token (str | None): Authenticated GitHub API token, or None if unauthenticated. * mode (str): Resolved documentation mode string. * thinking_plan (dict[str, str | None]): Mapping of individual workflow node identifiers to assigned thinking effort levels. * project_name (str): Resolved canonical project name.

    Returns: * dict[str, any]: The centralized state dictionary consumed by nodes.py and flow.py.

    Example: 

    def build_shared_store(args, github_token, mode, thinking_plan, project_name):
    """Construct the shared store dictionary passed between PocketFlow nodes.

    Returns:
        dict: The shared store with all CLI args, patterns, and empty output slots.
    """
    return {
        "repo_url": args.repo,
        "local_dir": args.dir,
        "project_name": project_name,  # Resolved once in main so logs, --force-rebuild and output agree
        "github_token": github_token,
        "output_dir": args.output,  # Base directory for CombineTutorial output
        # Include/exclude patterns and max file size
        "include_patterns": set(args.include) if args.include else DEFAULT_INCLUDE_PATTERNS,
        "exclude_patterns": DEFAULT_EXCLUDE_PATTERNS.union(set(args.exclude)) if args.exclude else DEFAULT_EXCLUDE_PATTERNS,
        "max_file_size": args.max_size,
        # Language for multi-language support
        "language": args.language,
        # Cache flag (inverse of no-cache)
        "use_cache": not args.no_cache,
        # Max abstractions
        "max_abstraction_num": args.max_abstractions,
        # LLM reasoning capabilities: global level (legacy) + per-node plan (utils/thinking.py)
        "thinking_level": args.thinking_level,
        "thinking_plan": thinking_plan,
        # Max tokens override
        "max_tokens": args.max_tokens,
        # Mode, mkdocs, and incremental
        "mode": mode,
        "mkdocs": args.mkdocs,
        "incremental": args.incremental,
        "advanced_mode": mode == "advanced",
        # Batching settings
        "batch_size": args.batch,
        "force_batch": args.force_batch,
        # Debug mode
        "debug": args.debug,
        # Outputs populated by downstream nodes
        "files": [],
        "abstractions": [],
        "relationships": {},
        "chapter_order": [],
        "chapters": [],
        "final_output_dir": None,
    }

    This constructor ensures that file exclusion sets merge the repository's internal rules with the static baseline catalog DEFAULT_EXCLUDE_PATTERNS from utils/exclude_patterns.py. It records operational controls, such as use_cache (the inverse of args.no_cache) and advanced_mode (derived from mode == "advanced"), guaranteeing downstream compatibility across heterogeneous node implementations.

    detect_llm_config()

    Visibility: Public Signature: def detect_llm_config(args: argparse.Namespace) -> tuple[str, str, str, str, int]:

    Description: Discovers the active LLM provider identity, target model name, base API endpoint URL, and effective context window limit from the runtime environment and CLI overrides. It delegates provider discovery to resolve_llm_settings() and resolves maximum token context length by either respecting args.max_tokens or querying get_model_context_length() from utils/llm_config.py.

    Parameters: * args (argparse.Namespace): Populated CLI options container containing optional max_tokens constraints.

    Returns: * tuple[str, str, str, str, int]: A 5-tuple representing: 1. provider (str): Resolved vendor string ("anthropic", "gemini", or "openrouter"). 2. model_name (str): Model family or deployment name. 3. endpoint_url (str): Target HTTP(S) completion endpoint. 4. api_key (str): Active API key retrieved from environment variables. 5. context_length (int): Input token context window ceiling.

    Example: 

    def detect_llm_config(args):
    """Detect LLM provider, model, endpoint, and context length from environment.

    Returns:
        tuple: (provider, model_name, endpoint_url, api_key, context_length)
    """
    from utils.llm_config import get_model_context_length

    provider, model_name, endpoint_url, api_key = resolve_llm_settings()
    context_length = args.max_tokens or get_model_context_length(endpoint_url, model_name, api_key)
    return provider, model_name, endpoint_url, api_key, context_length

    The function utilizes deferred local imports of get_model_context_length from utils/llm_config.py to preserve fast initialization. By allowing args.max_tokens to short-circuit dynamic context discovery, developers can manually bound pipeline memory footprints when operating on constrained tiers or non-standard models.

    resolve_thinking_plan()

    Visibility: Public Signature: def resolve_thinking_plan(args: argparse.Namespace) -> tuple[str, dict[str, str | None], list[str]]:

    Description: Constructs the per-node reasoning effort plan based on --thinking-override, --thinking-level, and --thinking-profile. This function is strictly pure and performs no console emissions, enabling it to execute before utils/output.py is initialized. This early resolution ensures that string localization tasks executed during output bootstrapping can query their assigned thinking level.

    Parameters: * args (argparse.Namespace): Parsed command-line options.

    Returns: * tuple[str, dict[str, str | None], list[str]]: A 3-tuple containing: 1. resolved_profile (str): Name of the resolved thinking profile ("global", "auto", "balanced", etc.). 2. thinking_plan (dict[str, str | None]): Mapping of node key strings (e.g., 'identify_abstractions', 'write_chapters') to normalized reasoning tiers or None. 3. invalid_overrides (list[str]): List of unrecognized or malformed CLI override strings for subsequent diagnostic validation.

    Example: 

    def resolve_thinking_plan(args):
    """Build the per-node thinking plan from --thinking-override / --thinking-level / --thinking-profile.

    Pure (no emit): runs before init_output(). Validation messages come from _validate_thinking_args().

    Returns:
        tuple[str, dict, list[str]]: (resolved profile name, {node_key: level | None}, invalid override strings)
    """
    mode = "advanced" if args.advanced else args.mode
    overrides, invalid = parse_overrides(args.thinking_override)
    profile = "global" if args.thinking_level else resolve_profile_name(args.thinking_profile, resolve_llm_settings()[0])
    return profile, build_thinking_plan(profile, mode, args.thinking_level, overrides), invalid

    The function leverages utils/thinking.py utilities. It maps the operational mode, evaluates CLI override tokens into a valid mapping and an invalid tracking list, checks whether a global thinking effort level overrides the active profile, resolves the profile against the detected LLM provider, and outputs the final per-node execution plan dictionary.

It outputs the source target, active language, AI provider details, endpoint addresses, model context ceilings, reasoning effort matrices, batch thresholds, caching flags, and filesystem log locations using localized UI message keys.

    Parameters: * args (argparse.Namespace): The active CLI namespace. * mode (str): Documentation generation mode. * provider (str): Active LLM vendor identifier. * model_name (str): Model deployment identifier. * endpoint_url (str): Active API endpoint. * context_length (int): Token context window size. * log_file (str): Absolute path to the active disk log file. * thinking_profile (str): Resolved thinking effort profile name. * thinking_plan (dict[str, str | None]): Node-to-level reasoning assignment dictionary.

    Example: 

    def display_config(args, mode, provider, model_name, endpoint_url, context_length, log_file, thinking_profile, thinking_plan):
    """Emit all configuration values to the console."""
    emit("START_GENERATION", source=args.repo or args.dir, language=args.language.capitalize())
    emit("CFG_HEADER")
    emit("CFG_AI_PROVIDER", value=provider)
    emit("CFG_AI_ENDPOINT", value=endpoint_url)
    emit("CFG_AI_MODEL", value=model_name)

    main()

    Visibility: Public Signature: def main() -> None:

    Description: The primary procedural orchestrator of the entire CLI application. It coordinates argument parsing, reasoning plan resolution, logging configuration, quote error checks, preflight authentication, string translation, incremental cache invalidation, shared store construction, pipeline graph instantiation, error-resilient execution, and teardown telemetry.

    Due to its orchestration responsibilities, its implementation is divided into five distinct logical phases:

    Phase 1: CLI and Thinking Plan Initialization

    Parses command-line inputs and calculates the per-node reasoning plan before initializing the console presentation layer.

        parser, args = parse_arguments()
    # Resolved silently before init_output(): string translation itself uses the plan's translate_strings level.
    thinking_profile, thinking_plan, invalid_overrides = resolve_thinking_plan(args)
    # Translation of missing strings is an LLM call: deferred until arguments and credentials are checked.
    init_output(
        language=args.language,
        use_cache=not args.no_cache,
        thinking_level=thinking_plan["translate_strings"],
        debug=args.debug,
        auto_translate=False,
    )
    _check_quoting_errors(parser, args)
    _validate_thinking_args(args, invalid_overrides)

    In this initial phase, the reasoning effort plan is computed in total isolation without emitting console logs. This ensures that when init_output is invoked, it can configure the translation subsystem with the precise reasoning budget allocated for translate_strings. Following output initialization, the CLI flags undergo defensive inspection for shell quoting mistakes and invalid override tokens.

    Phase 2: Preflight Validation and Internationalization

    Evaluates standalone cleanup requests, source availability, LLM provider credentials, and missing translation entries.

        # Handle standalone --cleanup (no --dir or --repo)
    if args.cleanup and not args.dir and not args.repo:
        _run_cleanup()
        return

    # Require --dir or --repo for generation
    if not args.dir and not args.repo:
        parser.error("one of the arguments --repo --dir --cleanup is required")

    # Fail fast (with setup instructions) before crawling if Claude cannot authenticate
    if not check_llm_auth():
        sys.exit(1)
    translate_missing_strings()

    If the invocation is a standalone cleanup task (--cleanup without --dir or --repo), cache stores and log directories are purged immediately, terminating the process early. For pipeline generation runs, the orchestrator asserts that at least one repository target was provided. It then invokes check_llm_auth() to verify provider credentials and SDK compatibility. Once authentication is confirmed, translate_missing_strings() processes missing target language entries.

    Phase 3: Project Identity and Cache Validation

    Resolves repository metadata, verifies documentation mode constraints, and arbitrates cache invalidation.

        # Get GitHub token from argument or environment variable if using repo
    github_token = None
    if args.repo:
        github_token = args.token or os.environ.get("GITHUB_TOKEN")
        if not github_token:
            emit("WARN_NO_GITHUB_TOKEN")
    elif args.token:
        emit("WARN_TOKEN_NO_REPO")

    mode, project_name = resolve_mode_and_project(args)

    # Enforce incremental cache constraints
    if args.incremental and mode != "api-reference":
        emit("WARN_INCREMENTAL_API_ONLY")
        args.incremental = False

    # --force-rebuild requires --incremental
    if args.force_rebuild and not args.incremental:
        emit("ERROR_FORCE_REBUILD_NO_INCREMENTAL")
        sys.exit(1)

    # Handle --force-rebuild: delete the cache manifest to force fresh generation
    if args.force_rebuild and args.incremental:
        output_base = args.output or "output"
        manifest_path = os.path.join(output_base, project_name, ".doc_cache_manifest.json")
        if os.path.exists(manifest_path):
            os.remove(manifest_path)
            emit("FORCE_REBUILD_DELETED", path=manifest_path)
        else:
            emit("FORCE_REBUILD_NO_MANIFEST", path=manifest_path)

    # Warn about args ignored in api-reference mode
    if mode == "api-reference" and args.force_batch:
        emit("WARN_FORCE_BATCH_API_REF")
        args.force_batch = False

    This phase resolves GitHub personal access tokens, warns when tokens are supplied without remote repositories, and computes canonical project basenames. It validates the constraints of the incremental cache engine, ensuring that incremental compilation is applied exclusively to api-reference documentation modes. If --force-rebuild is requested alongside --incremental, the on-disk cache manifest .doc_cache_manifest.json is located and unlinked.

    Phase 4: Context Store Assembly and Logging Initialization

    Constructs the central shared context dictionary, inspects LLM limits, initializes disk logs, and prints configuration telemetry.

        shared = build_shared_store(args, github_token, mode, thinking_plan, project_name)
    provider, model_name, endpoint_url, _, context_length = detect_llm_config(args)
    log_file = configure_logging(project_name=project_name, mode=mode)
    display_config(args, mode, provider, model_name, endpoint_url, context_length, log_file, thinking_profile, thinking_plan)

    The phase compiles all runtime state into the shared dictionary, inspects runtime LLM context length boundaries via detect_llm_config(), opens a dedicated run log file via configure_logging() (e.g., in logs/<project_name>_<mode>_<timestamp>.log), and outputs the finalized configuration block to standard output.

    Phase 5: Flow Execution and Lifecycle Teardown

    Compiles the PocketFlow execution graph, executes all nodes sequentially or concurrently, runs post-execution cleanups, and guarantees resource finalization in a finally block.

        # Create and run the flow
    tutorial_flow = create_tutorial_flow()
    try:
        tutorial_flow.run(shared)

        # Cleanup after run if requested
        if args.cleanup:
            _run_cleanup()
    finally:
        from utils.output import shutdown

        # Report spend even when the run fails — failed runs are often the expensive ones.
        try:
            _emit_usage_summary()
        except Exception as e:
            emit_raw("WARNING", f"Usage summary failed: {e}", dest="LOG")
        shutdown()

    The execution phase instantiates the workflow via create_tutorial_flow() from flow.py and executes it synchronously against shared. If --cleanup was specified alongside generation flags, _run_cleanup() purges intermediate caches upon completion. Crucially, the enclosing finally block ensures that even if an unhandled exception or SIGINT aborts pipeline processing, _emit_usage_summary() tabulates and logs cumulative token costs, and shutdown() flushes and closes active logging file handles.

    Internal Helpers

    _thinking_level_arg()

    Visibility: Private / Internal Signature: def _thinking_level_arg(value: str) -> str | None:

    Description: Type validation and normalization callable passed to argparse for the --thinking-level CLI parameter. It trims whitespace, lowercases input strings, maps empty inputs or the literal "default" to None (representing the LLM's native default behavior), and verifies that explicit levels belong to THINKING_LEVELS from utils/thinking.py.

    Parameters: * value (str): The raw string value passed via command-line arguments.

    Returns: * str | None: A normalized reasoning tier string ('minimal', 'low', 'medium', 'high', 'xhigh', 'max'), or None.

    Raises: * argparse.ArgumentTypeError: Raised if the string does not match allowed choices.

    Example: 

    def _thinking_level_arg(value):
    """argparse type for --thinking-level: a level from THINKING_LEVELS; '' or 'default' → None (model default)."""
    level = value.strip().lower()
    if level in ("", "default"):
        return None
    if level not in THINKING_LEVELS:
        raise argparse.ArgumentTypeError(f"invalid choice: {value!r} (choose from {', '.join(THINKING_LEVELS)}, default)")
    return level

    This helper guarantees that invalid thinking tiers are intercepted during argument parsing before any subsystem initialization occurs. By transforming empty strings and "default" into None, it allows upstream callers to distinguish between explicit user overrides and fallback model defaults.

    _check_quoting_errors()

    Visibility: Private / Internal Signature: def _check_quoting_errors(parser: argparse.ArgumentParser, args: argparse.Namespace) -> None:

    Description: Detects shell argument quoting mistakes where missing closing quotes in --exclude or --include arrays accidentally swallow subsequent command-line flags. Because shells treat unbalanced strings as continuous literal arguments, subsequent CLI flags (e.g., --language) are frequently merged into pattern lists, causing them to be silently ignored. This defensive validator inspects all extracted pattern strings against registered parser flags and terminates execution if an embedded flag is detected.

    Parameters: * parser (argparse.ArgumentParser): The active CLI argument parser used to extract registered options dynamically. * args (argparse.Namespace): Parsed argument namespace containing evaluated exclude and include lists.

    Returns: * None

    Raises: * SystemExit: Invokes sys.exit(1) upon identifying an embedded flag in any glob pattern.

    Example: 

    def _check_quoting_errors(parser, args):
    """Detect shell quoting errors where --exclude/--include values accidentally swallowed other CLI flags."""
    # Extract all registered flags (both --long and -short) from the parser
    known_flags = set()
    for action in parser._actions:
        for opt in action.option_strings:
            known_flags.add(opt)

    for pattern_list, flag_name in [(args.exclude, "--exclude"), (args.include, "--include")]:
        if not pattern_list:
            continue
        for pattern in pattern_list:
            for known_flag in known_flags:
                if f" {known_flag} " in pattern or (f" {known_flag}" in pattern and pattern.endswith(known_flag)):
                    emit(
                        "ERROR_QUOTING",
                        flag=flag_name,
                        pattern=pattern[:120],
                        embedded=known_flag,
                    )
                    sys.exit(1)

    The function queries parser._actions to extract all valid option strings (-n, --repo, --mode, etc.). It iterates over each pattern provided to --exclude and --include, checking whether an option string appears with leading whitespace (f" {known_flag} " or trailing f" {known_flag}"). If found, it emits a localized ERROR_QUOTING diagnostic and immediately halts execution, preventing confusing downstream crawl errors.

    _validate_thinking_args()

    Visibility: Private / Internal Signature: def _validate_thinking_args(args: argparse.Namespace, invalid_overrides: list[str]) -> None:

    Description: Audits the validity of cognitive effort configurations. It raises fatal errors for malformed override syntax, warns when users configure overrides for nodes not executed in the active --mode, and warns when a global --thinking-level overrides a specified --thinking-profile.

    Parameters: * args (argparse.Namespace): Parsed command-line argument namespace. * invalid_overrides (list[str]): List of malformed NODE=LEVEL override strings returned by resolve_thinking_plan().

    Returns: * None

    Raises: * SystemExit: Invokes sys.exit(1) if invalid_overrides contains any malformed strings.

    Example: 

    def _validate_thinking_args(args, invalid_overrides):
    """Report malformed --thinking-override values (fatal), overrides for nodes the mode never runs,
    and --thinking-level/--thinking-profile conflicts."""
    if invalid_overrides:
        emit("ERROR_THINKING_OVERRIDE", value=", ".join(invalid_overrides), nodes=", ".join(NODE_KEYS), levels=", ".join(THINKING_LEVELS))
        sys.exit(1)
    mode = "advanced" if args.advanced else args.mode
    overrides, _ = parse_overrides(args.thinking_override)
    unused = [node for node in overrides if node not in MODE_NODES[mode]]
    if unused:
        emit("WARN_THINKING_OVERRIDE_UNUSED", nodes=", ".join(unused), mode=mode, active=", ".join(MODE_NODES[mode]))
    if args.thinking_level and args.thinking_profile != "auto":
        emit("WARN_THINKING_LEVEL_OVERRIDES_PROFILE", level=args.thinking_level, profile=args.thinking_profile)

    The validator first halts execution via sys.exit(1) if any override fails parsing. It then compares specified override nodes against MODE_NODES[mode] from utils/thinking.py; if an override is provided for a stage not present in the active mode's DAG, it alerts the operator via WARN_THINKING_OVERRIDE_UNUSED. Finally, it warns if both a global effort level and a non-default profile are specified concurrently.

    _run_cleanup()

    Visibility: Private / Internal Signature: def _run_cleanup() -> None:

    Description: Purges disk-based cache artifacts and execution log directories. It unlinks persistent JSON response caches (llm_cache_v2.json, llm_cache_v2.json.tmp, llm_cache.json) and removes the active logging directory (resolved from LOG_DIR or defaulting to "logs").

    Parameters: * None.

    Returns: * None

    Raises: * None. Internal file operations trap and log exceptions via CLEANUP_FAILED without aborting cleanup passes.

    Example: 

    def _run_cleanup():
    """Clean up cache files and log directory."""
    emit("CLEANUP_START")

    for cache_path in ["llm_cache_v2.json", "llm_cache_v2.json.tmp", "llm_cache.json"]:
        if os.path.exists(cache_path):
            try:
                os.remove(cache_path)
                emit("CLEANUP_REMOVED", path=cache_path)
            except Exception as e:
                emit("CLEANUP_FAILED", path=cache_path, error=e)

    log_dir = os.environ.get("LOG_DIR", "logs")
    if os.path.exists(log_dir) and os.path.isdir(log_dir):
        try:
            shutil.rmtree(log_dir)
            emit("CLEANUP_REMOVED_DIR", path=log_dir)
        except Exception as e:
            emit("CLEANUP_FAILED", path=log_dir, error=e)

    The cleanup helper is designed for defensive execution. It checks for file and directory existence before unlinking assets. Individual deletion failures (e.g., due to file system locks or permission restrictions) are trapped and reported through CLEANUP_FAILED, allowing the remaining files to be processed.

    Description: Queries the cumulative session usage ledger from utils/llm_common.py and displays a formatted summary across all active providers.     Error Handling

    main.py enforces a defensive, fail-fast strategy across early validation phases, paired with a reliable teardown pattern in the workflow execution phase:

    • Quoting Error Interception (_check_quoting_errors): Catches shell quoting mistakes (e.g., passing unescaped globs that merge subsequent flags like --language into --exclude) by inspecting argument patterns against registered CLI flags. It displays ERROR_QUOTING and exits via sys.exit(1).
    • Argument Conflict and Override Validation (_validate_thinking_args): Detects malformed thinking overrides and terminates execution immediately (sys.exit(1)). It also emits non-fatal warnings if a global --thinking-level overrides a designated --thinking-profile, or if an override targets a node not used by the active --mode.
    • Credential Verification Preflight (check_llm_auth): Verifies provider credentials and required SDK installations before executing repository crawls or remote API calls. If authentication fails, the process exits with status code 1.
    • Incremental Mode Constraints: Ensures incremental caching is only used where supported. It disables incremental mode with a warning if used outside --mode api-reference, and rejects --force-rebuild when --incremental is absent.
    • Teardown and Exception Handling: Encloses the primary pipeline call tutorial_flow.run(shared) in a try...finally block. If node processing raises an unhandled exception or terminates early, the finally block traps internal errors, reports token usage via _emit_usage_summary(), and invokes shutdown() to flush logging buffers cleanly.
