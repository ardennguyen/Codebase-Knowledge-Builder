    main.py

    Source: main.py

    As established in the system hierarchy, flow.py defines the declarative Directed Acyclic Graph (DAG) that coordinates repository ingestion, abstraction mapping, relationship extraction, chapter ordering, and documentation synthesis. main.py serves as the primary application bootstrapper, command-line interface (CLI) driver, and runtime lifecycle controller for the Codebase-Knowledge-Builder platform. It bridges human operator intent, operating system environment variables, filesystem state, and remote provider credentials into the execution context consumed by the underlying computational graph.

    Technical Overview

    main.py functions as the centralized operational orchestrator responsible for validating runtime invariants, resolving complex configuration matrices, and executing the documentation pipeline. It begins execution by loading .env configuration files via dotenv.load_dotenv() and establishing terminal argument parsing. The module performs multi-tier input sanitization—detecting accidental shell glob swallows, reconciling legacy execution flags, verifying remote Large Language Model (LLM) authentication credentials prior to network-heavy crawling, and compiling per-node reasoning plans using provider-specific heuristics.

    At the core of its operational lifecycle, main.py constructs the canonical shared state store dictionary. This state dictionary acts as the persistent blackboard across all workflow graph nodes instantiated by flow.py. During the run, main.py configures disk logging, resolves model context ceilings, outputs diagnostic preflight summaries, initializes string localization engines, and hands execution control to the PocketFlow engine. The execution phase is wrapped within an isolated try...finally block, ensuring that comprehensive token ledger accounting, cumulative provider expenditures, and process resource teardown are performed even if an unhandled exception or terminal refusal occurs deep within pipeline inference stages.

    resolve_mode_and_project()

    Visibility: Public
    Signature: def resolve_mode_and_project(args: argparse.Namespace) -> tuple[str, str]:

    Description: Reconciles generation mode options and derives a normalized project identifier. It handles backward-compatibility logic for the legacy --advanced boolean flag, emitting a warning if both --mode and --advanced were specified concurrently. If an explicit project name was not supplied via -n/--name, it derives a deterministic name by inspecting filesystem base paths or stripping .git extensions from repository URLs.

    def resolve_mode_and_project(args):
    """Resolve documentation mode (handling --advanced legacy flag) and derive project name.

    Returns:
        tuple[str, str]: (mode, project_name)
    """
    if args.advanced:
        if args.mode != "tutorial":  # User explicitly set --mode AND --advanced
            emit("WARN_ADVANCED_OVERRIDES_MODE", mode=args.mode)
        mode = "advanced"
    else:
        mode = args.mode
    project_name = args.name
    if not project_name:
        if args.dir:
            project_name = os.path.basename(os.path.abspath(args.dir))
        elif args.repo:
            project_name = args.repo.rstrip("/").split("/")[-1].removesuffix(".git")
        else:
            project_name = "project"
    return mode, project_name
    The implementation uses defensive fallback resolution. When inspecting local directory paths, os.path.abspath normalizes relative markers (. or ..) before os.path.basename isolates the directory name. When evaluating remote repository URLs, trailing slashes are stripped via rstrip("/"), the terminal URI component is isolated via split("/")[-1], and .git suffixes are removed via removesuffix(".git"). If neither --dir nor --repo can yield a name (e.g., in edge cases or standalone cleanup runs), it falls back to the literal string "project".

    Parameters: * args (argparse.Namespace): Parsed command-line argument container.

    Returns: * tuple[str, str]: A 2-tuple where the first element is the normalized documentation mode ("tutorial", "advanced", "api-reference", or "sdk"), and the second element is the resolved project name string.

    Raises: * None.

    Example: 

    mode, project_name = resolve_mode_and_project(args)

    Description: Constructs the canonical shared state blackboard dictionary that is passed into PocketFlow.Flow.run() and mutated across all downstream workflow nodes. It centralizes operational limits, glob sets, reasoning allocations, credentials, and pre-allocated output slots.

    def build_shared_store(args, github_token, mode, thinking_plan, project_name):
    """Construct the shared store dictionary passed between PocketFlow nodes.

    Returns:
        dict: The shared store with all CLI args, patterns, and empty output slots.
    """
    return {
        "repo_url": args.repo,
        "local_dir": args.dir,
        "project_name": project_name,  # Resolved once in main so logs, --force-rebuild and output agree
        "github_token": github_token,
        "output_dir": args.output,  # Base directory for CombineTutorial output
        # Include/exclude patterns and max file size
        "include_patterns": set(args.include) if args.include else DEFAULT_INCLUDE_PATTERNS,
        "exclude_patterns": DEFAULT_EXCLUDE_PATTERNS.union(set(args.exclude)) if args.exclude else DEFAULT_EXCLUDE_PATTERNS,
        "max_file_size": args.max_size,
        # Language for multi-language support
        "language": args.language,
        # Cache flag (inverse of no-cache)
        "use_cache": not args.no_cache,
        # Max abstractions
        "max_abstraction_num": args.max_abstractions,
        # LLM reasoning capabilities: global level (legacy) + per-node plan (utils/thinking.py)
        "thinking_level": args.thinking_level,
        "thinking_plan": thinking_plan,
        # Max tokens override
        "max_tokens": args.max_tokens,
        # Mode, mkdocs, and incremental
        "mode": mode,
        "mkdocs": args.mkdocs,
        "incremental": args.incremental,
        "advanced_mode": mode == "advanced",
        # Batching settings
        "batch_size": args.batch,
        "force_batch": args.force_batch,
        # Debug mode
        "debug": args.debug,
        # Outputs populated by downstream nodes
        "files": [],
        "abstractions": [],
        "relationships": {},
        "chapter_order": [],
        "chapters": [],
        "final_output_dir": None,
    }

If no custom inclusion list was provided, it falls back to DEFAULT_INCLUDE_PATTERNS ({"*"}). Crucially, it sets up empty data structures (files, abstractions, relationships, chapter_order, chapters) that nodes in nodes.py incrementally populate during execution, ensuring that missing dictionary key exceptions do not occur.

    def detect_llm_config(args):
    """Detect LLM provider, model, endpoint, and context length from environment.

    Returns:
        tuple: (provider, model_name, endpoint_url, api_key, context_length)

    from utils.llm_config import get_model_context_length

    The function delegates base credential and endpoint resolution to resolve_llm_settings().     Visibility: Public

    def resolve_thinking_plan(args):
    """Build the per-node thinking plan from --thinking-override / --thinking-level / --thinking-profile.

    Pure (no emit): runs before init_output(). Validation messages come from _validate_thinking_args().

    Returns:
        tuple[str, dict, list[str]]: (resolved profile name, {node_key: level | None}, invalid override strings)
    """
    mode = "advanced" if args.advanced else args.mode
    overrides, invalid = parse_overrides(args.thinking_override)
    profile = "global" if args.thinking_level else resolve_profile_name(args.thinking_profile, resolve_llm_settings()[0])
    return profile, build_thinking_plan(profile, mode, args.thinking_level, overrides), invalid
    The implementation first parses raw key-value override strings into structured dictionaries and invalid token lists via parse_overrides() from utils/thinking.py. If a global --thinking-level was requested, the profile identifier is categorized as "global"; otherwise, resolve_profile_name() maps the requested profile (e.g., "auto", "balanced") against the active provider detected by resolve_llm_settings()[0]. Finally, build_thinking_plan() computes the final dictionary mapping each node key to an effort tier or None.

    main()

    Visibility: Public
    Signature: def main() -> None:

    Description: The primary entry-point orchestrator executing the full lifecycle of the application. It parses arguments, validates flags and credentials, handles caching, initializes telemetry, builds the shared state blackboard, executes the graph flow, and enforces cleanup and cost reporting in a finally block.

    Phase 1: Pre-Execution Validation and Output Bootstrapping

    def main():
    parser, args = parse_arguments()
    # Resolved silently before init_output(): string translation itself uses the plan's translate_strings level.
    thinking_profile, thinking_plan, invalid_overrides = resolve_thinking_plan(args)
    # Translation of missing strings is an LLM call: deferred until arguments and credentials are checked.
    init_output(
        language=args.language,
        use_cache=not args.no_cache,
        thinking_level=thinking_plan["translate_strings"],
        debug=args.debug,
        auto_translate=False,
    )
    _check_quoting_errors(parser, args)
    _validate_thinking_args(args, invalid_overrides)

    # Handle standalone --cleanup (no --dir or --repo)
    if args.cleanup and not args.dir and not args.repo:
        _run_cleanup()
        return

    # Require --dir or --repo for generation
    if not args.dir and not args.repo:
        parser.error("one of the arguments --repo --dir --cleanup is required")
    This phase bootstraps the environment while guarding against configuration flaws. Thinking plans are resolved before telemetry initialization so that the localized translation subsystem can inherit its configured thinking level. Calling init_output() configures stream encodings and initializes in-memory telemetry buffers while deliberately deferring LLM string translation (auto_translate=False). Defensive validators immediately inspect arguments for shell quoting errors or conflicting thinking overrides. If the standalone --cleanup flag was passed without an ingestion target, cleanup is executed immediately and the process terminates gracefully.

    Phase 2: LLM Preflight Authentication and Cache Sanitization

        # Fail fast (with setup instructions) before crawling if the configured provider cannot authenticate
    if not check_llm_auth():

    translate_missing_strings()
    notice_legacy_cache()

    github_token = None

    _check_quoting_errors()

    Visibility: Private
    Signature: def _check_quoting_errors(parser: argparse.ArgumentParser, args: argparse.Namespace) -> None:

    Description: Inspects multi-argument pattern lists for accidental shell glob swallowing. When users omit or misquote nested quotes in shell terminals (e.g. --exclude "dir/* "other/*" --language ja), the command-line shell can merge subsequent CLI flags directly into pattern values. This causes following arguments to be silently swallowed as file patterns. This function detects such occurrences dynamically by checking whether any pattern contains a registered CLI flag.

    def _check_quoting_errors(parser, args):
    """Detect shell quoting errors where --exclude/--include values accidentally swallowed other CLI flags.

    When users misquote patterns (e.g., --exclude "autogen/* "SmartFO/*" --language Vietnamese),
    the shell merges subsequent flags into the pattern value. This silently causes ALL following
    arguments to be ignored. We detect this by checking if any pattern value contains a known
    CLI flag string, which no legitimate file/directory pattern would ever contain.

    Flags are extracted dynamically from the argparse parser — no hardcoded list to maintain.
    """
    # Extract all registered flags (both --long and -short) from the parser
    known_flags = set()
    for action in parser._actions:
        for opt in action.option_strings:
            known_flags.add(opt)

    for pattern_list, flag_name in [(args.exclude, "--exclude"), (args.include, "--include")]:
        if not pattern_list:
            continue
        for pattern in pattern_list:
            for known_flag in known_flags:
                if f" {known_flag} " in pattern or (f" {known_flag}" in pattern and pattern.endswith(known_flag)):
                    emit(
                        "ERROR_QUOTING",
                        flag=flag_name,
                        pattern=pattern[:120],
                        embedded=known_flag,
                    )
                    sys.exit(1)
    The helper inspects all actions registered within the active ArgumentParser instance (parser._actions), compiling a set of known option strings (known_flags, including both short flags like -o and long flags like --output). It then iterates across elements in args.exclude and args.include. If an element contains an embedded flag token delimited by spaces or located at the end of the string, it emits an ERROR_QUOTING diagnostic and immediately terminates the process via sys.exit(1).

    Parameters: * parser (argparse.ArgumentParser): The active argument parser containing registered option strings. * args (argparse.Namespace): Deserialized CLI options to inspect.

    Returns: * None.

    Raises: * SystemExit: Raised with code 1 if a quoting violation is detected.

    Example: 

    _check_quoting_errors(parser, args)

    Error Handling

    main.py applies defensive input validation, preflight authentication verification, and fail-safe lifecycle teardown to ensure reliability across execution phases:

    • Shell Quoting Error Detection: Misquoted arguments (e.g., missing closing quotes around glob patterns) can cause subsequent CLI flags to be swallowed as pattern values. The _check_quoting_errors() helper inspects all --include and --exclude inputs against all registered flags in parser._actions. If an embedded flag is detected, the program emits ERROR_QUOTING with diagnostic details and exits immediately with code 1.
    • Malformed Reasoning Overrides: The _validate_thinking_args() helper checks for invalid NODE=LEVEL pairs. If unparseable entries are found, it emits ERROR_THINKING_OVERRIDE (listing supported nodes and effort tiers) and terminates with code 1. It also issues non-fatal warnings for unused overrides or conflicting --thinking-level and --thinking-profile arguments.
    • Preflight Authentication Gate: Before initiating filesystem crawling or remote repository downloads, main() invokes check_llm_auth() from utils/llm_config.py. If required API keys or environment variables are missing or malformed, the check prints actionable setup instructions and main() terminates via sys.exit(1), avoiding failed runs after expensive clone operations.
    • Incremental Rebuild Constraints: Incremental caching is validated against the active documentation mode. If --incremental is specified for modes other than api-reference, the flag is disabled with a WARN_INCREMENTAL_API_ONLY warning. If --force-rebuild is supplied without --incremental, the program emits ERROR_FORCE_REBUILD_NO_INCREMENTAL and terminates with code 1.
    • Guaranteed Accounting and Resource Cleanup: The entire execution pipeline is wrapped in a try...finally block. Regardless of whether the flow completes successfully, is cancelled by the operator, or raises an unhandled exception (such as an unrecoverable LLMRefusalError), _emit_usage_summary() runs inside the finally block to report accumulated token expenditures, reasoning costs, and cache metrics before utils.output.shutdown() closes logging streams.
