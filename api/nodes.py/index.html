    nodes.py

    Source: nodes.py

    Following the orchestration flow constructed in flow.py and initialized at application startup by main.py, nodes.py implements the concrete execution stages of the documentation pipeline. Each class in this module inherits from PocketFlow.Node or PocketFlow.BatchNode, encapsulating a lifecycle divided into preparation (prep), execution (exec), and state publishing (post).

    Technical Overview

    nodes.py serves as the operational engine for repository ingestion, abstraction extraction, topological relationship modeling, pedagogical sequencing, chapter synthesis, and documentation serialization. The module interacts with the central runtime blackboard dictionary (shared) to pass state between decoupled execution nodes. Depending on the volume of source code, repository structure, and user configuration, nodes dynamically adapt their behavior—switching between direct in-context analysis, batch chunking, and 1:1 deterministic file mapping.

    The architectural lifecycle consists of four functional phases: 1. Ingestion & Context Evaluation: FetchRepo retrieves source code trees from remote GitHub repositories or local directories via crawl_github_files.py or crawl_local_files.py. ContextRouter evaluates the token size of the source files against the model's effective context ceiling, subtracting prompt template overhead and reserved completion headroom. It then routes execution through a single direct prompt (direct), directory-bounded chunks (batch), or an isolated 1:1 module breakdown (deterministic). 2. Abstraction Extraction: Depending on the selected route, IdentifyAbstractions extracts core concepts from full codebase listings in a single inference pass; MapAbstractions processes directory-bound file batches in parallel, followed by ReduceAbstractions to consolidate partial abstractions into a unified architecture; or DeterministicFileMapper strips non-code files via LLM classification and maps remaining files directly to individual documentation chapters sorted by directory depth. 3. Relational Analysis & Sequencing: AnalyzeRelationships distributes prompt token budgets across abstractions to provide code context, prompts the model to infer architectural dependencies, and builds an indexed relationship graph. OrderChapters analyzes this dependency graph to establish a pedagogical reading order from foundational utility layers to high-level orchestration controllers. 4. Drafting & Final Emission: WriteChapters processes ordered abstractions sequentially, maintaining an in-memory sliding window of preceding chapter summaries to provide context while avoiding quadratic context token growth ($O(n^2)$). It also incorporates MD5-based incremental disk caching to bypass previously synthesized chapters. Finally, CombineTutorial synthesizes static HTML websites via MkDocs Material or emits standalone Markdown packages using mkdocs.py.

    Public API

    FetchRepo

    Visibility: Public
    Inherits from: pocketflow.Node

    FetchRepo coordinates the ingestion of source code from local filesystems or remote Git repositories. It normalizes paths, applies inclusion/exclusion filters, and populates the shared context with file tuples.

    FetchRepo.prep()

    Visibility: Public
    Signature: def prep(self, shared: dict) -> dict:

    Description: Resolves project naming metadata and extracts file traversal filters from the shared blackboard dictionary. If a project name was not explicitly specified, it derives one from the repository URL or the local directory path.

    Parameters: * shared (dict): The central runtime state dictionary populated by main.py.

    Returns: * dict: Traversal parameters containing repo_url, local_dir, token, include_patterns, exclude_patterns, max_file_size, and path normalization flags.

    Example: 

        def prep(self, shared):
        repo_url = shared.get("repo_url")
        local_dir = shared.get("local_dir")
        project_name = shared.get("project_name")

        if not project_name:
            # Basic name derivation from URL or directory
            if repo_url:
                project_name = repo_url.rstrip("/").split("/")[-1].removesuffix(".git")
            else:
                project_name = os.path.basename(os.path.abspath(local_dir))
            shared["project_name"] = project_name

        emit_raw(
            "DEBUG", f"FetchRepo prep | project_name='{project_name}' | source='{shared.get('repo_url') or shared.get('local_dir', '.')}'", dest="LOG"
        )

        # Get file patterns directly from shared
        include_patterns = shared["include_patterns"]
        exclude_patterns = shared["exclude_patterns"]
        max_file_size = shared["max_file_size"]

        return {
            "repo_url": repo_url,
            "local_dir": local_dir,
            "token": shared.get("github_token"),
            "include_patterns": include_patterns,
            "exclude_patterns": exclude_patterns,
            "max_file_size": max_file_size,
            "use_relative_paths": True,
        }
    The method resolves project metadata defensively by inspecting remote repository URLs or local paths. It falls back to calculating canonical folder names when configuration options are omitted. These extracted settings are returned as an execution bundle for the filesystem crawler.

    FetchRepo.exec()

    Visibility: Public
    Signature: def exec(self, prep_res: dict) -> list[tuple[str, str]]:

    Description: Dispatches file tree traversal to crawl_github_files.py or crawl_local_files.py. It extracts UTF-8 file contents into a list of (relative_path, content) tuples.

    Parameters: * prep_res (dict): Parameter dictionary compiled by FetchRepo.prep().

    Returns: * list[tuple[str, str]]: Collection of relative file path and content tuples.

    Raises: * ValueError: Raised if the crawl finds zero matching files after applying inclusion and exclusion filters.

    Example: 

        def exec(self, prep_res):
        source = prep_res["repo_url"] or prep_res["local_dir"]
        emit_raw("DEBUG", f"NODE EXEC | node=FetchRepo | action=crawl_files | source={source}", dest="LOG")

        if prep_res["repo_url"]:
            emit("CRAWL_REPOSITORY", url=prep_res["repo_url"])
            result = crawl_github_files(
                repo_url=prep_res["repo_url"],
                token=prep_res["token"],
                include_patterns=prep_res["include_patterns"],
                exclude_patterns=prep_res["exclude_patterns"],
                max_file_size=prep_res["max_file_size"],
                use_relative_paths=prep_res["use_relative_paths"],
            )
        else:
            emit("CRAWL_DIRECTORY", path=prep_res["local_dir"])

            result = crawl_local_files(
                directory=prep_res["local_dir"],
                include_patterns=prep_res["include_patterns"],
                exclude_patterns=prep_res["exclude_patterns"],
                max_file_size=prep_res["max_file_size"],
                use_relative_paths=prep_res["use_relative_paths"],
            )

        # Convert dict to list of tuples: [(path, content), ...]
        files_list = list(result.get("files", {}).items())
        if len(files_list) == 0:
            raise ValueError("No matching files found. Check your directory and include/exclude patterns.")

        emit_raw("DEBUG", f"NODE COMPLETE | node=FetchRepo | files_found={len(files_list)}", dest="LOG")
        return files_list
    The method delegates file discovery to either the GitHub API or the local filesystem crawler depending on the presence of repo_url. Traversal results return as a mapping of relative file paths to their decoded content buffers. If the filter drops all discovered files, execution halts immediately with a ValueError.

    ContextRouter

    Visibility: Public
    Inherits from: pocketflow.Node

    ContextRouter computes prompt overhead, token budgets, and context limits. It selects the execution path across direct, batch, and deterministic branches.

    ContextRouter.prep()

    Visibility: Public
    Signature: def prep(self, shared: dict) -> tuple:

    Phase 1: Context Limit and Prompt Overhead Calculation

    Estimates the prompt overhead required across templates, directory trees, and chapter listings to determine remaining context space.

        def prep(self, shared):
        files_data = shared["files"]
        max_tokens = resolve_max_tokens(shared)

        shared["max_tokens"] = max_tokens

        # --- Calculate prompt overhead FIRST ---
        # 1. Prompt templates: check both IA/MA (for batching) and WC (for chapter writing)
        #    Use the largest template across all modes as worst-case estimate
        prompt_dir = os.path.join(os.path.dirname(os.path.abspath(__file__)), "prompts")
        max_template_tokens = 0
        for subdir in ["tutorial", "advanced", "api-reference", "sdk"]:
            for template_name in ["map_abstractions.md", "identify_abstractions.md", "draft_chapters.md"]:
                template_path = os.path.join(prompt_dir, subdir, template_name)
                if os.path.exists(template_path):
                    with open(template_path, encoding="utf-8-sig") as f:
                        t = count_tokens(f.read())
                    max_template_tokens = max(max_template_tokens, t)

        # 2. Directory tree (shared across IA, MA, and WC prompts)
        directory_tree = build_directory_tree(files_data)
        tree_tokens = count_tokens(directory_tree)

        # 3. Chapter listing estimate (used in WC draft_chapters prompts)
        #    Format: "N. basename (doc: path.md)" per file
        chapter_listing_estimate = "\n".join(f"{i + 1}. {os.path.basename(path)} (doc: {path}.md)" for i, (path, _) in enumerate(files_data))
        listing_tokens = count_tokens(chapter_listing_estimate)

        prompt_overhead = max_template_tokens + tree_tokens + listing_tokens
        # ...
    This phase scans prompt templates across execution modes to calculate worst-case overhead. It combines this estimate with token counts for the directory tree and chapter listings. Measuring these structural components prevents context window exhaustion during subsequent drafting stages.

    Phase 2: Token Budgeting and Route Determination

    Compares codebase token volume against the model's effective context ceiling and selects an execution branch.

            # ...
        # --- Count file content tokens ---
        total_tokens = 0
        file_token_map = []
        for i, (path, content) in enumerate(files_data):
            entry = f"--- File Index {i}: {path} ---\n{content}\n\n"
            tokens = count_tokens(entry)
            total_tokens += tokens
            file_token_map.append(tokens)

        # --- Effective limit = context minus output reserve minus overhead ---
        # Reserve output for whichever consumer of this budget thinks more: IdentifyAbstractions
        # (direct route) or MapAbstractions (each batch is packed to effective_limit).
        safety_limit = min(
            input_token_budget(max_tokens, resolve_thinking_level(shared, "identify_abstractions")),
            input_token_budget(max_tokens, resolve_thinking_level(shared, "map_abstractions")),
        )
        effective_limit = safety_limit - prompt_overhead
        force_batch = shared.get("force_batch", False)

        if shared.get("mode", "tutorial") == "api-reference":
            emit("CAPACITY_API_REF_MODE")
            return ("deterministic", files_data, effective_limit, shared.get("batch_size", 50), None, None, directory_tree)

        if total_tokens > effective_limit and force_batch:
            # emit logging ...
            pass
        # ...
        else:
            emit(
                "CAPACITY_FITS", tokens=f"{total_tokens:,}", limit=f"{effective_limit:,}", safety=f"{safety_limit:,}", overhead=f"{prompt_overhead:,}"
            )
            return ("direct", files_data, effective_limit, shared.get("batch_size", 50), None, None, directory_tree)

        return (
            "batch",
            files_data,
            effective_limit,
            shared.get("batch_size", 50),
            file_token_map,
            count_tokens,
            directory_tree,
        )
    The phase calculates token allocations across all crawled files using token_utils.py. The effective token ceiling is calculated by subtracting output headroom and prompt overhead from the model's context window. If api-reference mode is active, the router immediately selects the deterministic route. Otherwise, it compares total file tokens against effective_limit to route to either direct or batch.

    ContextRouter.exec()

    Visibility: Public
    Signature: def exec(self, prep_res: tuple) -> str | list[list[tuple[int, str, str]]]:

    Phase 1: Direct and Deterministic Pass-Through

    Handles scalar execution pathways that do not require batch file chunking.

        def exec(self, prep_res):
        route, files_data, effective_limit, batch_size, file_token_map, _count_tokens, _directory_tree = prep_res
        emit_raw(
            "DEBUG",
            f"NODE EXEC | node=ContextRouter | action=route_decision | route={route} | files={len(files_data)} | effective_limit={effective_limit:,}",
            dest="LOG",
        )

        if route == "direct":
            return "direct"
        if route == "deterministic":
            return "deterministic"
        # ...
    When prep resolves to direct or deterministic, this phase returns the routing action key immediately. These execution pathways do not require batch aggregation, allowing PocketFlow's conditional branching to advance directly to downstream nodes.

    Phase 2: Directory Grouping and Capacity-Bounded Batch Assembly

    Groups candidate files by directory and splits them into token-bounded chunks.

            # ...
        # Group by directory for coherence, with pre-computed tokens
        dir_groups = defaultdict(list)
        for i, (path, content) in enumerate(files_data):
            dir_groups[os.path.dirname(path)].append((i, path, content, file_token_map[i]))

        # Build token-aware batches (never mix directories)
        batches = []
        for dirname in sorted(dir_groups.keys()):
            current_batch = []
            current_tokens = 0

            for i, path, content, tokens in dir_groups[dirname]:
                # Start new batch if adding this file would exceed effective limit or file count cap
                if current_batch and (current_tokens + tokens > effective_limit or len(current_batch) >= batch_size):
                    batches.append(current_batch)
                    current_batch = []
                    current_tokens = 0

                current_batch.append((i, path, content))
                current_tokens += tokens

            # Flush remaining files in this directory
            if current_batch:
                batches.append(current_batch)

        batch_word = "batch" if len(batches) == 1 else "batches"
        emit("CAPACITY_SPLIT", count=len(batches), word=batch_word)
        emit_raw("DEBUG", f"NODE COMPLETE | node=ContextRouter | route={route} | batches={len(batches)}", dest="LOG")
        return batches
    The phase groups files by directory to preserve architectural locality across prompts. Batches are packed until adding another file would exceed either effective_limit or batch_size. Files from different directories are never mixed within a single batch, ensuring partial abstractions maintain semantic cohesion.

    ContextRouter.post()

    Visibility: Public
    Signature: def post(self, shared: dict, prep_res: tuple, exec_res: str | list) -> str:

    Description: Persists the directory tree to the shared state dictionary and registers chunked batches under shared["file_batches"] if the batch route was selected.

    Parameters: * shared (dict): The central runtime state dictionary. * prep_res (tuple): The parameters emitted by prep(). * exec_res (str | list): The action token ("direct", "deterministic") or list of assembled batches.

    Returns: * str: Dynamic routing action consumed by PocketFlow ("direct", "deterministic", or "batch").

    Example: 

        def post(self, shared, prep_res, exec_res):
        emit_raw("DEBUG", f"ContextRouter post | route={'batch' if isinstance(exec_res, list) else exec_res}", dest="LOG")
        # Store the directory tree built during prep() for EVERY route: draft_chapters and
        # group_modules prompts read shared["directory_tree"] on direct/deterministic routes too.
        shared["directory_tree"] = prep_res[-1]
        if exec_res == "direct":
            return "direct"
        if exec_res == "deterministic":
            return "deterministic"
        shared["file_batches"] = exec_res
        return "batch"
    The method persists the cached ASCII directory tree to shared["directory_tree"] so subsequent nodes do not need to recompute it. It then inspects the structure of exec_res to emit the routing string that controls PocketFlow's conditional branching operators (- action >> target).

    DeterministicFileMapper

    Visibility: Public
    Inherits from: pocketflow.Node

    DeterministicFileMapper acts as the entry node for the api-reference pipeline. It classifies files via LLM inference to discard non-code assets and maps each remaining file directly to its own reference chapter.

    Returns: * tuple[str, bool, str | None, int]: Tuple containing (prompt, use_cache, thinking_level, max_tokens).

    Example: 

        def prep(self, shared):

        file_listing = "\n".join([f"{i} # {path}" for i, (path, _) in enumerate(files_data)])

    Description: Dispatches the classification prompt to the LLM to identify files containing substantive source code, returning a list of valid integer file indices.

    Parameters: * prep_res (tuple): Prepared execution tuple (prompt, use_cache, thinking_level, max_tokens).

        @safe_exec
    def exec(self, prep_res):

    DeterministicFileMapper.post()

    Visibility: Public
    Signature: def post(self, shared: dict, prep_res: tuple, exec_res: list[int]) -> str:

    Description: Constructs 1:1 abstraction objects for valid source files, sorts chapter order by directory depth (leaf files first), and updates shared["abstractions"].

    Parameters: * shared (dict): The central shared context store. * prep_res (tuple): Context tuple passed from prep(). * exec_res (list[int]): List of verified code file indices.

    Returns: * str: Default action token ("default").

    Example: 

        def post(self, shared, prep_res, exec_res):

        files = shared.get("files", [])
        valid_indices = set(exec_res)
        modules = []
        chapter_order = []

        for idx, (file_path, _content) in enumerate(files):
            if idx not in valid_indices:

    Error Handling

    nodes.py applies specific defensive patterns to maintain pipeline stability during long-running tasks:

    1. Standardized Execution Wrapper (@safe_exec): Node execution methods (exec) are wrapped with @safe_exec. If an exception occurs, the wrapper logs a standardized NODE_RETRY_ERROR event and emits full tracebacks to disk logs before re-raising the error. This triggers PocketFlow's retry policies without obscuring root causes.
    2. Defensive Parsing and Index Range Clamping: Outputs returned by LLMs as YAML are validated against unexpected types. String numbers, annotated lines ("3 # main.py"), and numeric ranges ("2-5") are normalized using parse_file_index. Indices are verified against the total file count (0 <= idx < total_files_count), and out-of-bounds references are dropped with warnings (WARN_PARSE_INDEX, WARN_INVALID_RELATIONSHIP).
    3. Budget Overflow Management: ContextRouter and AnalyzeRelationships proactively calculate token allocations to prevent prompt overflow. If file content exceeds token ceilings, context is truncated and warnings (WARN_CONTEXT_TRUNCATED) are emitted. In AnalyzeRelationships, unallocated files are summarized by path only under an Other files header.
    4. Resilient Chapter Fallback (exec_fallback): If chapter drafting in WriteChapters fails after exhausting all retries, exec_fallback returns a placeholder page with a failure notice. This maintains chapter index alignment across downstream nodes and sets hash: None to ensure subsequent incremental runs attempt regeneration.
    5. Cache Invalidation for Truncated Completions: If an LLM response is truncated by output limits (getattr(response, "truncated", False)), WriteChapters excludes the page's hash from .doc_cache_manifest.json. This keeps the partial draft for the current run while ensuring subsequent runs re-execute the step.
