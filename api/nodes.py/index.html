    nodes.py

    Source: nodes.py

    Following the orchestration graph definitions established in flow.py and the operational bootstrapping managed by main.py, nodes.py houses the executable node implementations for the Codebase-Knowledge-Builder architecture. It defines the discrete steps within the PocketFlow pipeline that ingest source repositories, evaluate token budgets, discover domain abstractions, verify code facts, draft instructional chapters, and package final documentation artifacts.

    Technical Overview

    nodes.py implements the core computation graph nodes inheriting from PocketFlow's Node and BatchNode base classes. Each node follows a strict lifecycle lifecycle: prep() extracts and formats state parameters from the shared execution dictionary (shared), exec() runs the primary transformation or LLM invocation (often shielded by retry logic via the safe_exec decorator), and post() mutates the shared pipeline state with downstream data structures. The module bridges high-level pipeline control with underlying utility subsystems, interfacing directly with remote/local repository crawlers, prompt templating, token counting, fact verification engines, and documentation compilers.

    The execution topology divides into three primary pathways managed dynamically at runtime: 1. Direct Path: Used when the cumulative codebase token count comfortably fits inside the LLM input token budget, extracting abstractions directly from the full concatenated source files. 2. Batch Path: Applied when repository token volume exceeds single-prompt safety thresholds, partitioning files into directory-aligned batches, mapping partial abstractions across batches, and reducing them into a consolidated domain model. 3. Deterministic Path: Triggered under api-reference mode, skipping fuzzy abstraction discovery in favor of a 1:1 file-to-chapter mapping with rigorous AST-independent fact auditing.

    Public API

    FetchRepo

    Visibility: Public
    Signature: class FetchRepo(Node):

    Description: The primary entry-point node for the pipeline. It derives project identification names and executes source code ingestion against either a remote GitHub URL or a local filesystem directory, filtering targets based on configured inclusion and exclusion wildcards.

    FetchRepo.prep()

    Visibility: Public
    Signature: def prep(self, shared: dict) -> dict:

    Description: Normalizes configuration properties from the shared store, derives the default project name from Git URLs or folder basenames if omitted, and packages crawling parameters into an execution configuration dictionary.

    Parameters: * shared (dict): The global workflow state dictionary containing CLI options and configuration flags.

    Returns: * dict: Parameter dictionary containing repo_url, local_dir, token, include_patterns, exclude_patterns, max_file_size, and use_relative_paths.

    Example: 

    class FetchRepo(Node):
    def prep(self, shared):
        repo_url = shared.get("repo_url")
        local_dir = shared.get("local_dir")
        project_name = shared.get("project_name")

        if not project_name:
            # Basic name derivation from URL or directory
            if repo_url:
                project_name = repo_url.rstrip("/").split("/")[-1].removesuffix(".git")
            else:
                project_name = os.path.basename(os.path.abspath(local_dir))
            shared["project_name"] = project_name

        emit_raw(
            "DEBUG", f"FetchRepo prep | project_name='{project_name}' | source='{shared.get('repo_url') or shared.get('local_dir', '.')}'", dest="LOG"
        )

        # Get file patterns directly from shared
        include_patterns = shared["include_patterns"]
        exclude_patterns = shared["exclude_patterns"]
        max_file_size = shared["max_file_size"]

        return {
            "repo_url": repo_url,
            "local_dir": local_dir,
            "token": shared.get("github_token"),
            "include_patterns": include_patterns,
            "exclude_patterns": exclude_patterns,
            "max_file_size": max_file_size,
            "use_relative_paths": True,
        }

    The method inspects repo_url and local_dir to populate missing project identifiers before extraction occurs. It logs debug telemetry indicating the ingestion source and packages inclusion and exclusion globs alongside size constraints into a dictionary. This prepared dictionary ensures that subsequent network or disk crawling functions operate over sanitized parameters without altering the shared store directly during preparation.

    FetchRepo.exec()

    Visibility: Public
    Signature: def exec(self, prep_res: dict) -> list[tuple[str, str]]:

    Description: Dispatches ingestion to crawl_github_files.py or crawl_local_files.py depending on whether repo_url is provided, transforming the decoded file mapping into an indexed list of path and content tuples.

    Parameters: * prep_res (dict): The crawling parameters returned by FetchRepo.prep().

    Returns: * list[tuple[str, str]]: A list of 2-tuples containing relative file paths and UTF-8 decoded source content strings.

    Raises: * ValueError: If no matching source files are identified after applying inclusion/exclusion filters.

    Example: 

        def exec(self, prep_res):
        source = prep_res["repo_url"] or prep_res["local_dir"]
        emit_raw("DEBUG", f"NODE EXEC | node=FetchRepo | action=crawl_files | source={source}", dest="LOG")

        if prep_res["repo_url"]:
            emit("CRAWL_REPOSITORY", url=prep_res["repo_url"])
            result = crawl_github_files(
                repo_url=prep_res["repo_url"],
                token=prep_res["token"],
                include_patterns=prep_res["include_patterns"],
                exclude_patterns=prep_res["exclude_patterns"],
                max_file_size=prep_res["max_file_size"],
                use_relative_paths=prep_res["use_relative_paths"],
            )
        else:
            emit("CRAWL_DIRECTORY", path=prep_res["local_dir"])

            result = crawl_local_files(
                directory=prep_res["local_dir"],
                include_patterns=prep_res["include_patterns"],
                exclude_patterns=prep_res["exclude_patterns"],
                max_file_size=prep_res["max_file_size"],
                use_relative_paths=prep_res["use_relative_paths"],
            )

        # Convert dict to list of tuples: [(path, content), ...]
        files_list = list(result.get("files", {}).items())
        if len(files_list) == 0:
            raise ValueError("No matching files found. Check your directory and include/exclude patterns.")

        emit_raw("DEBUG", f"NODE COMPLETE | node=FetchRepo | files_found={len(files_list)}", dest="LOG")
        return files_list

    The method branches on the presence of a repository URL, dispatching to crawl_github_files for remote repository retrieval or crawl_local_files for local filesystem crawls. Once retrieval finishes, it converts the underlying dictionary structure into an ordered list of (path, content) tuples. An explicit emptiness check enforces fail-fast error handling by raising a ValueError if all candidate files were excluded or missing, preventing subsequent nodes from attempting inference on an empty payload.

    FetchRepo.post()

    Visibility: Public
    Signature: def post(self, shared: dict, prep_res: dict, exec_res: list[tuple[str, str]]) -> None:

    Description: Persists the extracted list of file tuples directly to the shared store under the "files" key.

    Parameters: * shared (dict): The global pipeline state dictionary. * prep_res (dict): The output produced during prep(). * exec_res (list[tuple[str, str]]): The list of parsed (file_path, content) tuples from exec().

    Returns: * None

    Example: 

        def post(self, shared, prep_res, exec_res):
        shared["files"] = exec_res  # List of (path, content) tuples

    This method commits the harvested source code array into shared memory. By storing the source code as indexed tuples, downstream nodes can reference files using zero-based integer identifiers, reducing prompt token footprints across analysis operations.

    ContextRouter

    Visibility: Public
    Signature: class ContextRouter(Node):

    Description: Evaluates cumulative token capacity against model context constraints, prompt template footprints, and safety reserves. Dynamically selects between direct analysis, batch-mode MapReduce, or deterministic 1:1 API mappings.

    ContextRouter.prep()

    Visibility: Public
    Signature: def prep(self, shared: dict) -> tuple:

    The preparation phase measures prompt overhead and content token volumes across multiple sub-phases:

    Phase 1: Mode Check & Directory Tree Construction

        def prep(self, shared):
        files_data = shared["files"]
        max_tokens = resolve_max_tokens(shared)

        shared["max_tokens"] = max_tokens
        directory_tree = build_directory_tree(files_data)

        if shared.get("mode", "tutorial") == "api-reference":
            # One chapter per file, one page call each: no routing budget is needed.
            emit("CAPACITY_API_REF_MODE")
            return ("deterministic", files_data, 0, shared.get("batch_size", 50), None, None, directory_tree)
    The method resolves the model context window ceiling using resolve_max_tokens and generates an indexed directory tree string via build_directory_tree. If execution is configured for api-reference mode, token capacity checks are bypassed entirely, immediately routing to the "deterministic" topology since documentation is compiled per individual file without needing full repository context consolidation.

    Phase 2: Prompt Overhead Calculation

            # --- Calculate prompt overhead FIRST ---
        # 1. Prompt templates: check both IA/MA (for batching) and WC (for chapter writing)
        #    Use the largest template across all modes as worst-case estimate
        prompt_dir = os.path.join(os.path.dirname(os.path.abspath(__file__)), "prompts")
        max_template_tokens = 0
        for subdir in ["tutorial", "advanced", "api-reference", "sdk"]:
            for template_name in ["map_abstractions.md", "identify_abstractions.md", "draft_chapters.md"]:
                template_path = os.path.join(prompt_dir, subdir, template_name)
                if os.path.exists(template_path):
                    with open(template_path, encoding="utf-8-sig") as f:
                        t = count_tokens(f.read())
                    max_template_tokens = max(max_template_tokens, t)

        # 2. Directory tree (shared across IA, MA, and WC prompts)
        tree_tokens = count_tokens(directory_tree)

        # 3. Chapter listing estimate (used in WC draft_chapters prompts)
        #    Format: "N. basename (doc: path.md)" per file
        chapter_listing_estimate = "\n".join(f"{i + 1}. {os.path.basename(path)} (doc: {path}.md)" for i, (path, _) in enumerate(files_data))
        listing_tokens = count_tokens(chapter_listing_estimate)

        prompt_overhead = max_template_tokens + tree_tokens + listing_tokens
        emit(
            "CAPACITY_PROMPT_OVERHEAD",
            total=f"{prompt_overhead:,}",
            template=f"{max_template_tokens:,}",
            tree=f"{tree_tokens:,}",
            listing=f"{listing_tokens:,}",
        )
    The method computes the worst-case structural prompt overhead by surveying all Markdown prompt templates across available modes (tutorial, advanced, api-reference, sdk) and identifying the maximum template token count. It measures the token cost of the generated directory tree and synthesizes a simulated chapter listing string to estimate final drafting overhead. The sum of these values establishes prompt_overhead, which is broadcast via UI telemetry.

    Phase 3: Token Capacity Comparison & Route Selection

            # --- Count file content tokens (batch-encoded; memoized for the nodes that re-count entries) ---
        file_token_map = count_tokens_many([f"--- File Index {i}: {path} ---\n{content}\n\n" for i, (path, content) in enumerate(files_data)])
        total_tokens = sum(file_token_map)

        # --- Effective limit = context minus output reserve minus overhead ---
        # Reserve output for whichever consumer of this budget thinks more: IdentifyAbstractions
        # (direct route) or MapAbstractions (each batch is packed to effective_limit).
        safety_limit = min(
            input_token_budget(max_tokens, resolve_thinking_level(shared, "identify_abstractions")),
            input_token_budget(max_tokens, resolve_thinking_level(shared, "map_abstractions")),
        )
        effective_limit = safety_limit - prompt_overhead
        force_batch = shared.get("force_batch", False)

        if total_tokens > effective_limit and force_batch:
            emit(
                "CAPACITY_EXCEEDS_FORCE",
                tokens=f"{total_tokens:,}",
                limit=f"{effective_limit:,}",
                safety=f"{safety_limit:,}",
                overhead=f"{prompt_overhead:,}",
            )
        elif total_tokens > effective_limit:
            emit(
                "CAPACITY_EXCEEDS",
                tokens=f"{total_tokens:,}",
                limit=f"{effective_limit:,}",
                safety=f"{safety_limit:,}",
                overhead=f"{prompt_overhead:,}",
            )
        elif force_batch:
            emit(
                "CAPACITY_FITS_FORCE",
                tokens=f"{total_tokens:,}",
                limit=f"{effective_limit:,}",
                safety=f"{safety_limit:,}",
                overhead=f"{prompt_overhead:,}",
            )
        else:
            emit(
                "CAPACITY_FITS", tokens=f"{total_tokens:,}", limit=f"{effective_limit:,}", safety=f"{safety_limit:,}", overhead=f"{prompt_overhead:,}"
            )
            return ("direct", files_data, effective_limit, shared.get("batch_size", 50), None, None, directory_tree)

        return (
            "batch",
            files_data,
            effective_limit,
            shared.get("batch_size", 50),
            file_token_map,
            count_tokens,
            directory_tree,
        )
    The method batch-encodes file contents using count_tokens_many and aggregates total tokens. It resolves reasoning reserves via input_token_budget for both direct and batch abstractions, choosing the tighter bound and subtracting prompt overhead to compute effective_limit. If the codebase exceeds this limit or --force-batch is active, it returns a 7-tuple selecting the "batch" route; otherwise, it returns a 7-tuple selecting "direct".

    ContextRouter.exec()

    Visibility: Public
    Signature: def exec(self, prep_res: tuple) -> str | list[list[tuple[int, str, str]]]:

    Description: Passes through scalar route decisions ("direct" or "deterministic"), or executes directory-grouped token-bounded bin-packing when operating in "batch" mode to produce balanced file batches.

    Parameters: * prep_res (tuple): The routing payload returned by ContextRouter.prep().

    Returns: * str | list[list[tuple[int, str, str]]]: Either the literal strings "direct" / "deterministic", or a list of batches where each batch contains tuples of (original_index, path, content).

    Example: 

        def exec(self, prep_res):
        route, files_data, effective_limit, batch_size, file_token_map, _count_tokens, _directory_tree = prep_res
        # ...
        if route == "direct":
            return "direct"
        if route == "deterministic":
            return "deterministic"

        # Group by directory for coherence, with pre-computed tokens
        dir_groups = defaultdict(list)
        for i, (path, content) in enumerate(files_data):
            dir_groups[os.path.dirname(path)].append((i, path, content, file_token_map[i]))

        # Build token-aware batches (never mix directories)
        batches = []
        for dirname in sorted(dir_groups.keys()):
            current_batch = []
            current_tokens = 0

            for i, path, content, tokens in dir_groups[dirname]:
                # Start new batch if adding this file would exceed effective limit or file count cap
                if current_batch and (current_tokens + tokens > effective_limit or len(current_batch) >= batch_size):
                    batches.append(current_batch)
                    current_batch = []
                    current_tokens = 0

                current_batch.append((i, path, content))
                current_tokens += tokens

            # Flush remaining files in this directory
            if current_batch:
                batches.append(current_batch)
        # ...
        return batches

    When batching, files are segregated by parent directory using defaultdict(list). Traversal iterates through sorted directory groups, accumulating files until adding another entry would exceed either effective_limit tokens or batch_size file entries. Directories are kept isolated across batches to maintain contextual semantic coherence for downstream LLM prompts.

    ContextRouter.post()

    Visibility: Public
    Signature: def post(self, shared: dict, prep_res: tuple, exec_res: str | list) -> str:

    Description: Persists the directory tree to the shared store and assigns file_batches if batching was selected, returning the route key to dictate DAG routing transitions in flow.py.

    Parameters: * shared (dict): The global pipeline state. * prep_res (tuple): The preparation tuple containing the computed directory tree. * exec_res (str | list): The route name string or the packed file batches.

    Returns: * str: The dynamic route action name ("direct", "deterministic", or "batch").

    Example: 

        def post(self, shared, prep_res, exec_res):
        emit_raw("DEBUG", f"ContextRouter post | route={'batch' if isinstance(exec_res, list) else exec_res}", dest="LOG")
        # Store the directory tree built during prep() for EVERY route: draft_chapters and
        # group_modules prompts read shared["directory_tree"] on direct/deterministic routes too.
        shared["directory_tree"] = prep_res[-1]
        if exec_res == "direct":
            return "direct"
        if exec_res == "deterministic":
            return "deterministic"
        shared["file_batches"] = exec_res
        return "batch"

    The method sets shared["directory_tree"] unconditionally so downstream prompts across all routes can access layout metadata. It then acts as a PocketFlow action router, returning string literals that direct flow transitions.

    DeterministicFileMapper

    Visibility: Public
    Signature: class DeterministicFileMapper(Node):

    Description: Designed for api-reference generation. Filters out non-source files, identifies configuration manifests, builds a 1:1 module abstraction mapping for all valid source files, and sorts chapters by directory depth.

    DeterministicFileMapper.prep()

    Visibility: Public
    Signature: def prep(self, shared: dict) -> tuple[str, bool, str | None, int]:

    Description: Formats an indexed code file inventory, excluding empty or whitespace-only files, and constructs a classification prompt for LLM evaluation.

    Parameters: * shared (dict): The global workflow dictionary.

    Returns: * tuple[str, bool, str | None, int]: A tuple containing (prompt, use_cache, thinking_level, max_tokens).

    Example: 

    class DeterministicFileMapper(Node):
    def prep(self, shared):
        files_data = shared["files"]
        project_name = shared["project_name"]

        # Empty/whitespace-only files (e.g. bare __init__.py) are left out: post() skips unlisted indices,
        # so they are never documented instead of flipping in and out with the LLM's answer.
        file_listing = "\n".join([f"{i} # {path}" for i, (path, content) in enumerate(files_data) if content.strip()])

        prompt = build_code_file_filter_prompt(project_name, file_listing)
        emit_raw("DEBUG", f"DeterministicFileMapper prep | {len(files_data)} candidate files for filtering", dest="LOG")
        return prompt, shared.get("use_cache", True), resolve_thinking_level(shared, "filter_files"), shared.get("max_tokens", 100000)

    The method filters candidate files by verifying that content.strip() evaluates to a truthy value, omitting empty files like blank __init__.py markers. It uses build_code_file_filter_prompt from prompts.py to instruct the LLM to separate genuine code files from manifests and auxiliary assets.

    DeterministicFileMapper.exec()

    Visibility: Public
    Signature: def exec(self, prep_res: tuple) -> tuple[list[int], list[int]]:

    Description: Invokes the LLM to categorize files, parses YAML response arrays, and resolves file index boundaries for both executable source code and package manifests.

    Parameters: * prep_res (tuple): The parameters compiled by DeterministicFileMapper.prep().

    Returns: * tuple[list[int], list[int]]: A 2-tuple containing (code_indices, manifest_indices).

    Example: 

        @safe_exec
    def exec(self, prep_res):
        prompt, use_cache, thinking_level, max_tokens = prep_res
        emit("LLM_CALL_FILTER_FILES")
        log_token_estimation(self.__class__.__name__, prompt, max_tokens)
        response = call_llm(prompt, use_cache=(use_cache and self.cur_retry == 0), thinking_level=thinking_level, step="filter_files")
        parsed = parse_yaml_response(response)
        # {code: [...], manifests: [...]}; a bare list (older reply shape) is the code list
        code = parsed.get("code") if isinstance(parsed, dict) else parsed
        manifests = parsed.get("manifests") if isinstance(parsed, dict) else []
        indices = [idx for entry in (code if isinstance(code, list) else []) for idx in parse_file_indices(entry)]
        manifest_indices = [idx for entry in (manifests if isinstance(manifests, list) else []) for idx in parse_file_indices(entry)]
        return indices, manifest_indices

    safe_exec()

    Visibility: Private
    Signature: def safe_exec(func: callable) -> callable:

    Description: Decorator that standardizes error handling across PocketFlow node exec() implementations. Emits a localized NODE_RETRY_ERROR event, writes the full traceback to the debug log, and re-raises the exception to trigger configured PocketFlow retry logic.

    Parameters: * func (callable): The underlying exec(self, prep_res) method being decorated.

    Returns: * callable: The wrapped execution function.

    Raises: * Exception: Re-raises any exception thrown by the underlying method.

    Example: 

    def safe_exec(func):
    """Decorator that wraps Node.exec() with standardized error handling.

    On exception: emits NODE_RETRY_ERROR, logs traceback, and re-raises.
    Eliminates the identical try/except pattern duplicated across all nodes.
    """

    @wraps(func)
    def wrapper(self, *args, **kwargs):
        try:
            return func(self, *args, **kwargs)
        except Exception as e:
            emit("NODE_RETRY_ERROR", class_name=self.__class__.__name__, error=e)
            emit_raw("ERROR", f"[Node {self.__class__.__name__}] Error: {e}\n{traceback.format_exc()}", dest="LOG")
            raise

    return wrapper

    This decorator wraps node execution, intercepting errors to emit telemetry through utils.output and record stack traces in log files. It re-raises exceptions cleanly so upstream orchestrators can manage retry backoffs.

    ExtractFacts._follow_up()

    Visibility: Private
    Signature: def _follow_up(self, item: dict, claims: dict, asked: tuple | list = ()) -> tuple[dict, dict, int]:

    Description: Conducts multi-round completeness follow-up prompts (up to FOLLOWUP_ROUNDS = 3) focusing on declaration lines that were omitted from initial claims.

    Parameters: * item (dict): The module item dictionary. * claims (dict): The current validated claims dictionary. * asked (tuple | list, optional): Collection of line numbers that have already been queried. Defaults to ().

    Returns: * tuple[dict, dict, int]: A 3-tuple containing: 1. claims (dict): Merged and verified claims dictionary. 2. followup (dict): Follow-up status dictionary ("status", "asked"). 3. calls (int): Count of additional LLM queries executed.

    Example: 

        FOLLOWUP_ROUNDS = 3  # follow-up calls per module at most, each on FACTS_FOCUS_LIMIT lines not asked before

    def _follow_up(self, item, claims, asked=()):
        asked, calls, lines = list(asked), 0, split_lines(item["content"])
        for _round in range(self.FOLLOWUP_ROUNDS):
            hints = completeness_hints(item["content"], verify_file_claims(claims, item["content"]), claims)
            already = set(asked)
            pending = [number for number in hints["uncovered"] if number not in already]
            if not pending:
                break
            note = build_facts_focus_note([(number, lines[number - 1]) for number in pending])
            prompt = item["template"].format(project_name=item["project_name"], file_path=item["path"], source=item["content"], focus_note=note)
            emit("FACTS_FOLLOWUP", name=item["path"], count=len(pending))
            log_token_estimation(self.__class__.__name__, prompt, item["max_tokens"])
            answer = None
            for attempt in range(2):
                calls += 1
                try:
                    response = call_llm(
                        prompt,
                        use_cache=(item["use_cache"] and self.cur_retry == 0 and attempt == 0),
                        thinking_level=item["thinking_level"],
                        step="extract_facts",
                    )
                    answer = parse_facts_response(response)
                    break
                except Exception as e:
                    emit_raw("WARNING", f"FACTS FOLLOW-UP FAILED | {item['path']} | attempt {attempt + 1} | {e}", dest="LOG")
            if answer is None:
                return claims, {"status": "failed", "asked": asked}, calls
            claims = merge_claims(claims, answer)
            asked += pending[:FACTS_FOCUS_LIMIT]
        return claims, {"status": "done" if asked else "none", "asked": asked}, calls

    The method loops through candidate lines using completeness_hints. If declaration-like lines are missing from existing claims, it extracts up to FACTS_FOCUS_LIMIT (60) unqueried lines and prompts the model to classify them. Responses are parsed, verified, and merged into the primary claim set via merge_claims. If a follow-up query fails, existing claims are preserved and the status is recorded as "failed".

    Error Handling

    The nodes in nodes.py use defensive error-handling patterns to handle LLM variations and transient failures:

    • Decorator-Driven Retries (@safe_exec): Applied to all primary exec() methods. Catches unexpected exceptions, emits a NODE_RETRY_ERROR event to utils.output, logs the exception and full stack trace to the LOG destination, and re-raises the error to let PocketFlow's retry policies handle the failure.
    • Low Coverage Detection (ExtractFacts.exec): Verifies that LLM-claimed citations physically exist in the source code using verify_file_claims. If an LLM hallucinates quotes (finding fewer than 50% of claims across 4+ items), the node raises a ValueError to force an uncached retry rather than saving corrupt fact data.
    • Non-Blocking Follow-up Failures (ExtractFacts._follow_up): Wraps completeness queries in an internal retry loop. If follow-up calls fail or return unparseable YAML, the node logs a warning to LOG and preserves previously verified claims, marking the follow-up status as "failed" so subsequent runs can retry.
    • Graceful Chapter Fallbacks (WriteChapters.exec_fallback): If all retries fail when drafting a chapter, exec_fallback returns a placeholder page with UI_CHAPTER_UNAVAILABLE and sets hash: None. This keeps the pipeline running, adds a placeholder entry to chapter_summaries, and ensures the chapter will be regenerated on the next run.
    • Truncation Defense: Inspects LLM completions for truncation markers via getattr(chapter_content, "truncated", False). If a response was cut short by output token limits, its cache hash is cleared to prevent saving incomplete pages to .doc_cache_manifest.json.
    • Atomic Cache Persistence (CombineTutorial.post): Serializes .doc_cache_manifest.json to a .tmp file before renaming it with os.replace. This atomic write ensures that interrupted runs do not leave corrupted JSON caches on disk.
