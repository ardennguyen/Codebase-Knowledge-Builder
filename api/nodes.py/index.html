    Technical Overview

    The execution sequence orchestrated by main.py initializes global configuration, resolves runtime credentials, and populates the shared blackboard store before passing execution control to flow.py. In turn, flow.py defines the directed acyclic graph (DAG) topology using the PocketFlow engine. nodes.py serves as the concrete operational engine of this architecture, implementing every computational step, filesystem crawler adapter, Large Language Model (LLM) reasoning prompt, and site synthesizer.

    The module provides ten discrete node implementations extending PocketFlow's Node and BatchNode base classes. These nodes span local and remote repository ingestion (FetchRepo), volumetric context estimation and dynamic execution path branching (ContextRouter), deterministic file filtering (DeterministicFileMapper), single-pass and batched conceptual abstraction extraction (IdentifyAbstractions, MapAbstractions, ReduceAbstractions), architectural relationship mapping (AnalyzeRelationships), topological chapter sequencing (OrderChapters), stateful incremental chapter drafting (WriteChapters), and static documentation compilation (CombineTutorial).

    Node operations adhere to a strict three-phase lifecycle: prep() extracts and formats data from the blackboard context, exec() performs computation or LLM inference, and post() mutates the shared state or directs DAG routing. All LLM-facing exec() methods are wrapped with the @safe_exec decorator to standardize exception logging and retry tracking. State transfer between nodes is mediated through a mutable shared dictionary, decoupling node implementations while maintaining transactional data consistency.

    DeterministicFileMapper

    Visibility: Public
    Signature: class DeterministicFileMapper(Node):

    Description: A specialized pipeline node that bypasses conceptual abstraction clustering for API reference documentation generation. It prompts the LLM to inspect the complete indexed codebase file listing, filter out non-code assets (e.g., configurations, test fixtures, static text), and directly maps each remaining source file into an isolated documentation module ordered hierarchically by directory depth.

    class DeterministicFileMapper(Node):
    def prep(self, shared):
        files_data = shared["files"]
        project_name = shared["project_name"]

        file_listing = "\n".join([f"{i} # {path}" for i, (path, _) in enumerate(files_data)])

        prompt = build_code_file_filter_prompt(project_name, file_listing)
        emit_raw("DEBUG", f"DeterministicFileMapper prep | {len(files_data)} candidate files for filtering", dest="LOG")
        return prompt, shared.get("use_cache", True), shared.get("thinking_level", None), shared.get("max_tokens", 100000)

    The class inherits from Node and structures execution into filtering preparation, LLM inference, and deterministic chapter assignment. By mapping individual source code files directly to chapters, it establishes a predictable one-to-one documentation layout suitable for formal API documentation suites.

    DeterministicFileMapper.exec()

    Visibility: Public
    Signature: def exec(self, prep_res: tuple) -> list[int]:

    Description: Dispatches the filtering prompt to the LLM via call_llm(), parses the returned YAML block into a list of valid integer file indices, and strips invalid non-list responses.

    Parameters: * prep_res (tuple): The tuple (prompt, use_cache, thinking_level, max_tokens) generated by prep().

    Returns: * list[int]: A list of validated integer indices representing source code files to document.

    Raises: * Exception: Any network or model inference exception intercepted and re-raised by @safe_exec.

    Example: 

    # Extracted from DeterministicFileMapper.exec implementation
@safe_exec
def exec(self, prep_res):
    prompt, use_cache, thinking_level, max_tokens = prep_res
    emit("LLM_CALL_FILTER_FILES")
    log_token_estimation(self.__class__.__name__, prompt, max_tokens)
    response = call_llm(prompt, use_cache=(use_cache and self.cur_retry == 0), thinking_level=thinking_level)
    valid_indices = parse_yaml_response(response)
    if not isinstance(valid_indices, list):
        valid_indices = []
    return [int(idx) for idx in valid_indices]

    The method incorporates retry tracking, bypassing cache lookups (cur_retry == 0) on repeated attempts following execution failures. Responses are deserialized using parse_yaml_response() and converted strictly to integer values to prevent downstream indexing errors.

    DeterministicFileMapper.post()

    Visibility: Public
    Signature: def post(self, shared: dict, prep_res: tuple, exec_res: list[int]) -> str:

    Description: Converts validated file indices into module descriptors, orders modules by directory depth, and populates the shared store.

    Phase 1: Module Extraction and Filtering

    files = shared.get("files", [])
valid_indices = set(exec_res)
modules = []
chapter_order = []

for idx, (file_path, _content) in enumerate(files):
    if idx not in valid_indices:
        emit("SKIP_NON_CODE_FILE", path=file_path)
        continue

    clean_name = os.path.basename(file_path)

    modules.append(
        {"name": clean_name, "description": f"Internal API reference for `{file_path}`", "files": [idx], "original_path": file_path}
    )
    chapter_order.append(len(modules) - 1)

    The first phase iterates through all crawled files, cross-referencing each file index against valid_indices. Files omitted by the LLM filter trigger SKIP_NON_CODE_FILE events. Retained files are converted into abstraction module dicts containing the file base name, descriptive reference label, single-element index array, and the relative repository path.

    Phase 2: Depth-Based Chapter Ordering and State Persistence

    shared["abstractions"] = modules
# Sort chapter order by directory depth (deepest first, then alphabetical).
# This ensures utility/leaf files are processed before orchestration files,
# so their summaries are available as cross-chapter context.
# Works universally across all languages (Python, C#, C++, Java, etc.).
shared["chapter_order"] = sorted(
    chapter_order,
    key=lambda idx: (
        -modules[idx]["original_path"].count("/") - modules[idx]["original_path"].count(os.sep),
        modules[idx]["original_path"].lower(),
    ),
)
shared["relationships"] = {"summary": "Deterministic Internal API Reference.", "details": []}
emit("DONE_DETERMINISTIC_MAPPER", count=len(modules))
return "default"

    The second phase calculates path separator frequencies (/ and os.sep) to sort chapters in descending order of directory depth. Deeply nested leaf utilities are scheduled for documentation before higher-level orchestrators, ensuring that leaf module summaries are available as cross-chapter context during downstream chapter drafting. The method stores abstractions, chapter_order, and a static relationships payload into shared, returning "default" to advance the workflow DAG.

    ContextRouter

    Visibility: Public
    Signature: class ContextRouter(Node):

    Description: The volumetric profiling and flow dispatch controller of the pipeline. It calculates LLM prompt template overhead, measures codebase token volumes, compares them against dynamic model capacity ceilings, and routes execution down one of three paths: "deterministic", "direct", or "batch".

    class ContextRouter(Node):
    # Lifecycle methods: prep(), exec(), post()
    pass

    The router serves as the central traffic switch in the architecture. When projects exceed prompt capacity limits, ContextRouter creates token-bounded, directory-coherent file chunks, preventing context window overflow during downstream abstraction discovery.

    ContextRouter.prep()

    Visibility: Public
    Signature: def prep(self, shared: dict) -> tuple:

    Description: Conducts static token profiling across prompt templates, directory trees, chapter listings, and source code files to establish the effective token budget and determine the routing strategy.

    Phase 1: Context Overhead Estimation

    files_data = shared["files"]
max_tokens = resolve_max_tokens(shared)

shared["max_tokens"] = max_tokens

# --- Calculate prompt overhead FIRST ---
# 1. Prompt templates: check both IA/MA (for batching) and WC (for chapter writing)
#    Use the largest template across all modes as worst-case estimate
prompt_dir = os.path.join(os.path.dirname(os.path.abspath(__file__)), "prompts")
max_template_tokens = 0
for subdir in ["tutorial", "advanced", "api-reference", "sdk"]:
    for template_name in ["map_abstractions.md", "identify_abstractions.md", "draft_chapters.md"]:
        template_path = os.path.join(prompt_dir, subdir, template_name)
        if os.path.exists(template_path):
            with open(template_path, encoding="utf-8-sig") as f:
                t = count_tokens(f.read())
            max_template_tokens = max(max_template_tokens, t)

# 2. Directory tree (shared across IA, MA, and WC prompts)
directory_tree = build_directory_tree(files_data)
tree_tokens = count_tokens(directory_tree)

# 3. Chapter listing estimate (used in WC draft_chapters prompts)
chapter_listing_estimate = "\n".join(f"{i + 1}. {os.path.basename(path)} (doc: {path}.md)" for i, (path, _) in enumerate(files_data))
listing_tokens = count_tokens(chapter_listing_estimate)

prompt_overhead = max_template_tokens + tree_tokens + listing_tokens
emit(
    "CAPACITY_PROMPT_OVERHEAD",
    total=f"{prompt_overhead:,}",
    template=f"{max_template_tokens:,}",
    tree=f"{tree_tokens:,}",
    listing=f"{listing_tokens:,}",
)

    The first phase estimates worst-case prompt overhead before inspecting file contents. It loads template files across modes (tutorial, advanced, api-reference, sdk), tokenizes the directory tree built via build_directory_tree(), and estimates chapter index formatting costs. Summing these metrics produces prompt_overhead, reserving necessary context capacity for system instructions and metadata.

    Phase 2: Content Token Auditing and Safety Limit Computation

    total_tokens = 0
file_token_map = []
for i, (path, content) in enumerate(files_data):
    entry = f"--- File Index {i}: {path} ---\n{content}\n\n"
    tokens = count_tokens(entry)
    total_tokens += tokens
    file_token_map.append(tokens)

# --- Effective limit = safety margin minus overhead ---
safety_limit = int(max_tokens * 0.95)
effective_limit = safety_limit - prompt_overhead
force_batch = shared.get("force_batch", False)

    The second phase iterates through all crawled source files, formatting each into an indexed block to calculate precise BPE token metrics using count_tokens(). It maintains a file_token_map array for file-level lookups and sets an operational ceiling of 95% of max_tokens. Subtracting prompt_overhead from this safety limit yields the effective_limit for source code ingestion.

    Phase 3: Route Decision Evaluation

    if shared.get("mode", "tutorial") == "api-reference":
    emit("CAPACITY_API_REF_MODE")
    return ("deterministic", files_data, effective_limit, shared.get("batch_size", 50), None, None, directory_tree)

if total_tokens > effective_limit and force_batch:
    emit("CAPACITY_EXCEEDS_FORCE", tokens=f"{total_tokens:,}", limit=f"{effective_limit:,}", safety=f"{safety_limit:,}", overhead=f"{prompt_overhead:,}")
elif total_tokens > effective_limit:
    emit("CAPACITY_EXCEEDS", tokens=f"{total_tokens:,}", limit=f"{effective_limit:,}", safety=f"{safety_limit:,}", overhead=f"{prompt_overhead:,}")
elif force_batch:
    emit("CAPACITY_FITS_FORCE", tokens=f"{total_tokens:,}", limit=f"{effective_limit:,}", safety=f"{safety_limit:,}", overhead=f"{prompt_overhead:,}")
else:
    emit("CAPACITY_FITS", tokens=f"{total_tokens:,}", limit=f"{effective_limit:,}", safety=f"{safety_limit:,}", overhead=f"{prompt_overhead:,}")
    return ("direct", files_data, effective_limit, shared.get("batch_size", 50), None, None, directory_tree)

return (
    "batch",
    files_data,
    effective_limit,
    shared.get("batch_size", 50),
    file_token_map,
    count_tokens,
    directory_tree,
)

    The final phase evaluates execution parameters to select the routing mode. The "api-reference" mode immediately selects "deterministic". Otherwise, if total_tokens fits within effective_limit without force_batch enabled, it selects the "direct" route. If total content exceeds capacity or batching is explicitly forced, it returns "batch" alongside file_token_map.

    ContextRouter.exec()

    Visibility: Public
    Signature: def exec(self, prep_res: tuple) -> str | list[list[tuple]]:

    Description: Executes routing logic, packaging files into token-bounded, directory-coherent batches when the "batch" route is active.

    Phase 1: Pass-Through Routing Check

    route, files_data, effective_limit, batch_size, file_token_map, _count_tokens, directory_tree = prep_res
emit_raw(
    "DEBUG",
    f"NODE EXEC | node=ContextRouter | action=route_decision | route={route} | files={len(files_data)} | effective_limit={effective_limit:,}",
    dest="LOG",
)

if route == "direct":
    return "direct"
if route == "deterministic":
    return "deterministic"

    For "direct" and "deterministic" routing configurations, exec() acts as a pass-through return mechanism. It emits diagnostic state to the log sink and immediately returns the selected route string without performing file grouping operations.

    Phase 2: Directory-Aware Batch Clustering

    # Group by directory for coherence, with pre-computed tokens
dir_groups = defaultdict(list)
for i, (path, content) in enumerate(files_data):
    dir_groups[os.path.dirname(path)].append((i, path, content, file_token_map[i]))

# Build token-aware batches (never mix directories)
batches = []
for dirname in sorted(dir_groups.keys()):
    current_batch = []
    current_tokens = 0

    for i, path, content, tokens in dir_groups[dirname]:
        # Start new batch if adding this file would exceed effective limit or file count cap
        if current_batch and (current_tokens + tokens > effective_limit or len(current_batch) >= batch_size):
            batches.append(current_batch)
            current_batch = []
            current_tokens = 0

        current_batch.append((i, path, content))
        current_tokens += tokens

    # Flush remaining files in this directory
    if current_batch:
        batches.append(current_batch)

batch_word = "batch" if len(batches) == 1 else "batches"
emit("CAPACITY_SPLIT", count=len(batches), word=batch_word)
self._directory_tree = directory_tree
return batches

    When batching is required, files are grouped by parent directory (os.path.dirname) to preserve architectural coherence. Batches are accumulated sequentially per directory without mixing files across separate directories. A new batch is initiated whenever adding a file would exceed effective_limit or the batch_size limit (default 50). The pre-computed directory_tree is saved to self._directory_tree, and the list of batch lists is returned.

    ContextRouter.post()

    Visibility: Public
    Signature: def post(self, shared: dict, prep_res: tuple, exec_res: str | list) -> str:

    Description: Persists routing artifacts to the shared store and returns the action edge string that drives conditional DAG branching in flow.py.

    def post(self, shared, prep_res, exec_res):
    emit_raw("DEBUG", f"ContextRouter post | route={'batch' if isinstance(exec_res, list) else exec_res}", dest="LOG")
    if exec_res == "direct":
        return "direct"
    if exec_res == "deterministic":
        return "deterministic"
    shared["file_batches"] = exec_res
    # Reuse directory tree built during prep()
    shared["directory_tree"] = getattr(self, "_directory_tree", build_directory_tree(shared["files"]))
    return "batch"

    The method inspects exec_res to branch execution. For scalar strings ("direct" or "deterministic"), it returns them as the active action label. For list payloads, it assigns exec_res to shared["file_batches"], caches directory_tree in shared, and returns "batch".

    MapAbstractions.exec()

    Visibility: Public
    Signature: def exec(self, item: dict) -> list[dict]:

    Description: Executes abstraction discovery over a single file batch, formatting the prompt, tracking token consumption, and validating the parsed abstraction objects.

    Phase 1: Prompt Construction and Token Tracking

    batch_index = item["batch_index"]
files = item["files"]
emit("LLM_CALL_MAP_ABSTRACTIONS", batch_index=batch_index, file_count=len(files))

context = ""
for i, path, content in files:
    context += f"--- File Index {i}: {path} ---\n{content}\n\n"

prompt_template = load_prompt_template("map_abstractions", mode=item.get("mode", "tutorial"))

language = item.get("language", "english")
language_instruction = f"Output language MUST be entirely in {language.capitalize()}. " if language.lower() != "english" else ""
name_lang_hint = f" (in {language.capitalize()})" if language.lower() != "english" else ""
desc_lang_hint = f" (in {language.capitalize()})" if language.lower() != "english" else ""

prompt = prompt_template.format(
    project_name=item["project_name"],
    context=context,
    language_instruction=language_instruction,
    name_lang_hint=name_lang_hint,
    desc_lang_hint=desc_lang_hint,
    directory_tree=item.get("directory_tree", "Not available"),
)

token_usage = {
    "file_content": count_tokens(context),

    safe_exec()

    Visibility: Internal (Module-level decorator)
    Signature: def safe_exec(func: callable) -> callable:

    Description: A decorator that wraps Node.exec() implementations with standardized error handling. When an unhandled exception occurs during node execution, the decorator catches the error, emits a localized NODE_RETRY_ERROR telemetry event, logs a diagnostic traceback to the session log sink via emit_raw(), and re-raises the exception to trigger the PocketFlow retry policy.

    Parameters: * func (callable): The exec method of a Node or BatchNode instance.

    Returns: * callable: The decorated wrapper function.

    Raises: * Exception: Re-raises any exception thrown by func.

    Example: 

    # Extracted from safe_exec implementation in nodes.py
def safe_exec(func):
    @wraps(func)
    def wrapper(self, *args, **kwargs):
        try:
            return func(self, *args, **kwargs)
        except Exception as e:
            emit("NODE_RETRY_ERROR", class_name=self.__class__.__name__, error=e)
            emit_raw("ERROR", f"[Node {self.__class__.__name__}] Error: {e}\n{traceback.format_exc()}", dest="LOG")
            raise

    return wrapper

    The helper eliminates duplicate try/except blocks across nodes, ensuring uniform telemetry logging while allowing PocketFlow's DAG engine to manage retry policies via max_retries and wait.

    create_llm_context()

    Visibility: Private (Closure scoped within IdentifyAbstractions.prep)
    Signature: def create_llm_context(files_data: list[tuple[str, str]]) -> str:

    Description: Accumulates file contents into a single Markdown-formatted string, measuring token consumption per file and stopping if the safety limit (95% of max_tokens) is reached.

    Parameters: * files_data (list[tuple[str, str]]): Ordered list of (filepath, content) tuples.

    Returns: * str: The accumulated, token-bounded context string.

    Example: 

    # Extracted from IdentifyAbstractions.prep implementation in nodes.py
def create_llm_context(files_data):
    max_tokens = resolve_max_tokens(shared)

    safety_limit = int(max_tokens * 0.95)

    context = ""
    current_tokens = 0

    for i, (path, content) in enumerate(files_data):
        entry = f"--- File Index {i}: {path} ---\n{content}\n\n"

        entry_tokens = count_tokens(entry)

        if current_tokens + entry_tokens > safety_limit:
            emit("WARN_CONTEXT_TRUNCATED", index=i, path=path, limit=safety_limit)
            break

        context += entry
        current_tokens += entry_tokens

    return context

    The closure enforces context boundaries for small repositories. If adding a file would push total tokens past safety_limit, it emits a WARN_CONTEXT_TRUNCATED warning and breaks out of accumulation, protecting downstream LLM calls from context overflow.

    Error Handling

    Exception Interception via @safe_exec

    All LLM-facing exec() methods use the @safe_exec decorator. When an exception occurs during prompt execution or response parsing: 1. It emits a localized NODE_RETRY_ERROR event via emit() containing the node class name and exception message. 2. It logs a full stack trace to the persistent session log file via emit_raw(..., dest="LOG"). 3. It re-raises the exception to trigger PocketFlow's configured retry policy (max_retries=5, wait=20).

    Ingestion Validation

    In FetchRepo.exec(), empty file sets trigger an unrecoverable failure: 

    if len(files_list) == 0:
    raise ValueError("No matching files found. Check your directory and include/exclude patterns.")
    This fails fast if invalid glob patterns or empty directories are supplied, preventing downstream nodes from executing on empty inputs.

    Defensive Model Output Validation

    Nodes that deserialize LLM YAML responses implement strict structural checks: * IdentifyAbstractions.exec(): Verifies that the deserialized payload is a list of dictionaries with name, description, and file_indices keys. It validates string types and handles index strings, comments, and hyphenated ranges (e.g., 1-4), logging WARN_PARSE_INDEX and skipping invalid entries. * AnalyzeRelationships.exec(): Validates that relationships_data contains summary and relationships keys. It extracts integers from index strings via re.findall(r"\d+", ...), confirms both endpoints fall within [0, num_abstractions - 1], and emits WARN_INVALID_RELATIONSHIP for out-of-bounds references. * OrderChapters.exec(): Validates that the returned list forms a permutation of all abstraction indices. If an index is out of bounds, contains duplicates, or omits abstractions (len(ordered_indices) != num_abstractions), it raises a ValueError to trigger node retry.

    Manifest and Cache Fault Tolerance

    In WriteChapters.exec(), all interactions with .doc_cache_manifest.json are enclosed in try...except Exception as e: blocks. If the manifest file is corrupted, unreadable, or contains invalid JSON: 1. It emits a WARN_MANIFEST_CACHE_FAIL warning. 2. It falls back to clean LLM drafting without halting execution.
