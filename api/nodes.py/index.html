    nodes.py

    Source: nodes.py

    In the overall pipeline architecture, main.py bootstraps the runtime environment, validates provider credentials, and initializes the shared blackboard store before handing execution control over to the Directed Acyclic Graph (DAG) constructed in flow.py. The nodes.py module implements the concrete computational units of this DAG, defining every discrete transformation, LLM reasoning step, batch-processing routine, and file-emission task as a subclass of pocketflow.Node or pocketflow.BatchNode.

    Technical Overview

    nodes.py serves as the primary operational execution layer for the Codebase-Knowledge-Builder system. It bridges the gap between raw repository files and structured, multi-chapter technical documentation. The module consumes the blackboard dictionary initialized during bootstrapping, iteratively reading and mutating shared keys as execution progresses through repository ingestion, abstraction extraction, topological relationship modeling, narrative synthesis, and artifact publishing.

    The module implements three architectural execution pathways dynamically selected based on operational mode and token capacity constraints. In the Direct Route, whole codebases fitting within model context windows are analyzed holistically to extract core abstractions. In the Batch Route, codebases exceeding single-context safety thresholds are partitioned into directory-isolated batches, mapped across parallel or sequential LLM invocations, and reduced into a unified abstraction hierarchy. In the Deterministic Route (used for api-reference mode), code files are filtered and mapped directly to internal API chapters one-to-one, bypassing abstraction extraction entirely.

    Each node adheres to PocketFlow's three-phase execution contract: prep() validates inputs and builds prompts or batch items; exec() performs the primary computation or network I/O wrapped in standardized error-handling decorators; and post() unpacks results, mutates shared state, and determines graph routing transitions. Furthermore, the module embeds incremental disk caching, cross-chapter summary propagation, foundation-node topological highlighting, and dual-output format generation (MkDocs Material or standalone Markdown).

    Visibility: Public

    Phase 2: Worst-Case Prompt Overhead Estimation

    prompt_dir = os.path.join(os.path.dirname(os.path.abspath(__file__)), "prompts")
max_template_tokens = 0
for subdir in ["tutorial", "advanced", "api-reference", "sdk"]:
    for template_name in ["map_abstractions.md", "identify_abstractions.md", "draft_chapters.md"]:
        template_path = os.path.join(prompt_dir, subdir, template_name)
        if os.path.exists(template_path):
            with open(template_path, encoding="utf-8-sig") as f:
                t = count_tokens(f.read())
            max_template_tokens = max(max_template_tokens, t)

tree_tokens = count_tokens(directory_tree)
chapter_listing_estimate = "\n".join(f"{i + 1}. {os.path.basename(path)} (doc: {path}.md)" for i, (path, _) in enumerate(files_data))
listing_tokens = count_tokens(chapter_listing_estimate)

prompt_overhead = max_template_tokens + tree_tokens + listing_tokens
emit(
    "CAPACITY_PROMPT_OVERHEAD",
    total=f"{prompt_overhead:,}",
    template=f"{max_template_tokens:,}",
    tree=f"{tree_tokens:,}",
    listing=f"{listing_tokens:,}",
)
    To calculate available context space without overflowing model limits, the prep routine evaluates worst-case prompt framing overhead. It scans all prompt templates across all modes, measures the token volume of the rendered directory tree, and estimates the serialized chapter listing size.

    Phase 3: File Content Tokenization & Capacity Routing Decision

    file_token_map = count_tokens_many([f"--- File Index {i}: {path} ---\n{content}\n\n" for i, (path, content) in enumerate(files_data)])
total_tokens = sum(file_token_map)

safety_limit = min(
    input_token_budget(max_tokens, resolve_thinking_level(shared, "identify_abstractions")),
    input_token_budget(max_tokens, resolve_thinking_level(shared, "map_abstractions")),
)
effective_limit = safety_limit - prompt_overhead
force_batch = shared.get("force_batch", False)

if total_tokens > effective_limit and force_batch:
    emit("CAPACITY_EXCEEDS_FORCE", tokens=f"{total_tokens:,}", limit=f"{effective_limit:,}", safety=f"{safety_limit:,}", overhead=f"{prompt_overhead:,}")
elif total_tokens > effective_limit:
    emit("CAPACITY_EXCEEDS", tokens=f"{total_tokens:,}", limit=f"{effective_limit:,}", safety=f"{safety_limit:,}", overhead=f"{prompt_overhead:,}")
elif force_batch:
    emit("CAPACITY_FITS_FORCE", tokens=f"{total_tokens:,}", limit=f"{effective_limit:,}", safety=f"{safety_limit:,}", overhead=f"{prompt_overhead:,}")
else:
    emit("CAPACITY_FITS", tokens=f"{total_tokens:,}", limit=f"{effective_limit:,}", safety=f"{safety_limit:,}", overhead=f"{prompt_overhead:,}")
    return ("direct", files_data, effective_limit, shared.get("batch_size", 50), None, None, directory_tree)

return ("batch", files_data, effective_limit, shared.get("batch_size", 50), file_token_map, count_tokens, directory_tree)
    The node tokenizes every file entry in parallel via count_tokens_many. It subtracts prompt overhead from the reasoning-adjusted input budget to establish an effective_limit. If the total codebase tokens fit within this limit (and force_batch is False), the node routes to "direct"; otherwise, it routes to "batch".

    Phase 2: Directory Grouping and Token-Aware Batch Allocation

    dir_groups = defaultdict(list)
for i, (path, content) in enumerate(files_data):
    dir_groups[os.path.dirname(path)].append((i, path, content, file_token_map[i]))

batches = []
for dirname in sorted(dir_groups.keys()):
    current_batch = []
    current_tokens = 0

    for i, path, content, tokens in dir_groups[dirname]:
        if current_batch and (current_tokens + tokens > effective_limit or len(current_batch) >= batch_size):
            batches.append(current_batch)
            current_batch = []
            current_tokens = 0

        current_batch.append((i, path, content))
        current_tokens += tokens

    if current_batch:
        batches.append(current_batch)
    For "batch" routing, files are grouped by their parent directory to preserve structural coherence. Files within each directory are packed into batches, ensuring neither effective_limit nor batch_size (default 50) is exceeded. Directory boundaries are strictly maintained—files from different directories are never mixed into the same batch.

    Parameters: * shared (dict): The global workflow state dictionary. * prep_res (tuple): Input tuple from prep(). * exec_res (list[int]): Filtered list of integer file indices from exec().

    Returns: * str: Default PocketFlow transition token ("default").

    Example:

for idx, (file_path, _content) in enumerate(files):

        emit("SKIP_NON_CODE_FILE", path=file_path)
        continue

    clean_name = os.path.basename(file_path)
    modules.append(
        {"name": clean_name, "description": f"Internal API reference for `{file_path}`", "files": [idx], "original_path": file_path}

    chapter_order,

    Error Handling

    Standardized Execution Trapping (@safe_exec)

    Node execution logic is shielded using the @safe_exec decorator. When an exception occurs during exec(): 1. It emits a localized NODE_RETRY_ERROR event via utils.output.emit. 2. It writes the full exception traceback to the log file via emit_raw("ERROR", ..., dest="LOG"). 3. It re-raises the original exception, allowing PocketFlow's retry mechanism (max_retries=5, wait=20 configured in flow.py) to back off and retry transient failures.

    Graceful Batch Degradation (WriteChapters.exec_fallback)

    If an individual chapter repeatedly fails across all retry attempts (e.g., due to model refusals or unparseable responses), PocketFlow triggers WriteChapters.exec_fallback. Rather than crashing the entire pipeline, the fallback: * Logs a WARN_CHAPTER_FALLBACK warning with the underlying error. * Emits a placeholder chapter page displaying a localized UI_CHAPTER_UNAVAILABLE banner. * Appends an unavailable note to chapter_summaries to maintain index alignment. * Sets hash: None in the manifest record so that future --incremental runs re-attempt generation.

    Defensive Model Output Validation

    Responses returned by call_llm are validated across several stages: * YAML Validation: Deserialized via parse_yaml_response. Non-dictionary or non-list payloads immediately raise ValueError to trigger retries. * Index Extraction: Handled by parse_file_index, which extracts integers using re.findall(r"\d+", ...) and handles range tokens like "2-5". * Index Bounds Checking: Every parsed index is validated against 0 <= idx < len(files) or 0 <= idx < num_abstractions. Invalid indices emit warnings (WARN_PARSE_INDEX, WARN_INVALID_RELATIONSHIP) and are pruned. * Permutation Integrity: OrderChapters.exec checks that the returned list length matches the abstraction count exactly and contains no duplicate or missing indices.
