    Technical Overview

    While main.py manages top-level CLI argument parsing, environment resolution, and runtime initialization, nodes.py contains the operational execution units of the Codebase-Knowledge-Builder pipeline. The module implements the concrete processing nodes that populate the PocketFlow Directed Acyclic Graph (DAG) constructed in flow.py. These nodes interact through a shared blackboard state (shared), transforming raw source code into structured, multi-chapter technical tutorials, architecture guides, and API reference documentation.

    Architecturally, the module employs both single-unit Node and parallelizable BatchNode abstractions from the pocketflow framework. Each node strictly implements a three-stage lifecycle: prep() extracts and prepares inputs from the blackboard, exec() performs computation or LLM inference, and post() validates results, mutates shared state, and determines graph routing keys. The execution pipeline handles source retrieval, dynamic token-budget routing, architectural abstraction extraction, cross-chapter relationship mapping, sequential chapter writing with rolling LLM summaries, and multi-format site asset compilation.

    Public API

    build_directory_tree()

    Visibility: Public
    Signature: def build_directory_tree(files_data: list[tuple[str, str]]) -> str:

    Description: Constructs a compact, deterministic string representation of the codebase directory hierarchy from a list of (path, content) tuples. Files are grouped by parent directory and sorted alphabetically. Each file entry is annotated with its sequential integer index (idx:N), enabling language models in downstream prompts to reference files unambiguously without repeating verbose path strings.

    Parameters: * files_data (list[tuple[str, str]]): Ingested repository files represented as pairs of relative file paths and decoded text content.

    Returns: * str: A formatted, newline-delimited directory tree string listing folders followed by indented file basenames and indices.

    def build_directory_tree(files_data):
    """Build a compact directory tree string from the list of (path, content) tuples.

    Groups files by directory and formats as a hierarchical tree with file indices.
    Used by ContextRouter, IdentifyAbstractions, MapAbstractions, and CombineTutorial
    to give LLMs structural context about the project layout.
    """
    from collections import defaultdict

    dir_files = defaultdict(list)
    for i, (path, _content) in enumerate(files_data):
        dirname = os.path.dirname(path) or "."
        basename = os.path.basename(path)
        dir_files[dirname].append(f"{basename} (idx:{i})")

    lines = []
    for dirname in sorted(dir_files.keys()):
        lines.append(f"{dirname}/")
        lines.extend(f"  {fname}" for fname in sorted(dir_files[dirname]))
    return "\n".join(lines)

    The function normalizes empty directory paths to . and aggregates filenames using a collections.defaultdict(list). Sorting both the directory keys and the basenames within each folder ensures deterministic prompt formatting across identical repository states. This structural view is directly consumed by ContextRouter, IdentifyAbstractions, MapAbstractions, and CombineTutorial to provide global layout context to the model while consuming minimal tokens.

        def prep(self, shared):

        local_dir = shared.get("local_dir")
        project_name = shared.get("project_name")

        if not project_name:

            "max_file_size": max_file_size,

    The method infers project_name when not explicitly supplied by stripping .git from the remote repository URL tail or extracting the base directory name of an absolute local path. It forces use_relative_paths=True to normalize downstream cross-referencing and prompt generation.

    Signature: def exec(self, prep_res: dict) -> list[tuple[str, str]]:

    Description: Dispatches ingestion to either utils/crawl_github_files.py or utils/crawl_local_files.py depending on whether repo_url is populated.

    Parameters: * prep_res (dict): The crawled configuration dictionary emitted by prep().

    Returns: * list[tuple[str, str]]: An ordered list of (path, content) pairs representing all retained codebase files.

    Raises: * ValueError: If ingestion returns an empty file set due to restrictive filter patterns or an invalid source path.

        def exec(self, prep_res):

        llm_logger.info(f"NODE EXEC | node=FetchRepo | action=crawl_files | source={source}")

        if prep_res["repo_url"]:
            emit("CRAWL_REPOSITORY", url=prep_res["repo_url"])
            result = crawl_github_files(
                repo_url=prep_res["repo_url"],
                token=prep_res["token"],
                include_patterns=prep_res["include_patterns"],
                exclude_patterns=prep_res["exclude_patterns"],
                max_file_size=prep_res["max_file_size"],
                use_relative_paths=prep_res["use_relative_paths"],
            )
        else:
            emit("CRAWL_DIRECTORY", path=prep_res["local_dir"])

            result = crawl_local_files(
                directory=prep_res["local_dir"],
                include_patterns=prep_res["include_patterns"],
                exclude_patterns=prep_res["exclude_patterns"],
                max_file_size=prep_res["max_file_size"],
                use_relative_paths=prep_res["use_relative_paths"],
            )

        # Convert dict to list of tuples: [(path, content), ...]
        files_list = list(result.get("files", {}).items())
        if len(files_list) == 0:
            raise ValueError("No matching files found. Check your directory and include/exclude patterns.")

        llm_logger.info(f"NODE COMPLETE | node=FetchRepo | files_found={len(files_list)}")
        return files_list

    This method delegates lower-level traversal, .gitignore compilation, and binary format exclusion to the dedicated crawler utilities. Converting the resulting dictionary to a sequence of tuples establishes a stable index ordering for every file in the repository throughout the pipeline run.

    ContextRouter

    Visibility: Public
    Signature: class ContextRouter(Node)

    Description: The capacity budgeting and dynamic execution router of the pipeline. It evaluates the total token volume of the ingested files against the model's effective context ceiling, taking into account worst-case prompt templates and structural overheads. Based on this capacity analysis, it directs execution down one of three pathways: direct (single-pass extraction), batch (Map-Reduce decomposition), or deterministic (file-by-file API reference extraction).

    ContextRouter.prep()

    Signature: def prep(self, shared: dict) -> tuple:

    Description: Computes prompt overheads, tokenizes all file contents, adjusts limits using a 95% safety margin, and determines whether repository tokens fit in context.

    Parameters: * shared (dict): The global blackboard state.

    Returns: * tuple: A multi-element tuple containing the routing string, file data, effective token limits, batch sizes, token maps, counter functions, directory tree, and debug flags.

        def prep(self, shared):
        files_data = shared["files"]
        max_tokens = resolve_max_tokens(shared)

        shared["max_tokens"] = max_tokens

        # --- Token estimation setup ---
        count_tokens = create_token_counter()

        # --- Calculate prompt overhead FIRST ---
        # 1. Prompt templates: check both IA/MA (for batching) and WC (for chapter writing)
        #    Use the largest template across all modes as worst-case estimate
        prompt_dir = os.path.join(os.path.dirname(os.path.abspath(__file__)), "prompts")
        max_template_tokens = 0
        for subdir in ["tutorial", "advanced", "api-reference", "sdk"]:
            for template_name in ["map_abstractions.md", "identify_abstractions.md", "draft_chapters.md"]:
                template_path = os.path.join(prompt_dir, subdir, template_name)
                if os.path.exists(template_path):
                    with open(template_path, encoding="utf-8-sig") as f:
                        t = count_tokens(f.read())
                    max_template_tokens = max(max_template_tokens, t)

        # 2. Directory tree (shared across IA, MA, and WC prompts)
        directory_tree = build_directory_tree(files_data)
        tree_tokens = count_tokens(directory_tree)

        # 3. Chapter listing estimate (used in WC draft_chapters prompts)
        #    Format: "N. basename (doc: path.md)" per file
        chapter_listing_estimate = "\n".join(f"{i + 1}. {os.path.basename(path)} (doc: {path}.md)" for i, (path, _) in enumerate(files_data))
        listing_tokens = count_tokens(chapter_listing_estimate)

        prompt_overhead = max_template_tokens + tree_tokens + listing_tokens
        emit(
            "CAPACITY_PROMPT_OVERHEAD",
            total=f"{prompt_overhead:,}",
            template=f"{max_template_tokens:,}",
            tree=f"{tree_tokens:,}",
            listing=f"{listing_tokens:,}",
        )
// ...

    The method performs pre-flight overhead estimation before evaluating repository contents. It inspects Markdown templates across all available generation modes (tutorial, advanced, api-reference, sdk), tokenizes the generated directory tree, and projects the token footprint of the chapter listing index. This overhead is subtracted from the 95% capacity threshold to yield an accurate effective_limit.

    // ...
        # --- Count file content tokens ---
        total_tokens = 0
        file_token_map = []
        for i, (path, content) in enumerate(files_data):
            entry = f"--- File Index {i}: {path} ---\n{content}\n\n"
            tokens = count_tokens(entry)
            total_tokens += tokens
            file_token_map.append(tokens)

        # --- Effective limit = safety margin minus overhead ---
        safety_limit = int(max_tokens * 0.95)
        effective_limit = safety_limit - prompt_overhead
        force_batch = shared.get("force_batch", False)

        if shared.get("mode", "tutorial") == "api-reference":
            emit("CAPACITY_API_REF_MODE")
            return ("deterministic", files_data, effective_limit, shared.get("batch_size", 50), None, None, directory_tree, False)

        if total_tokens > effective_limit and force_batch:
            emit(
                "CAPACITY_EXCEEDS_FORCE",
                tokens=f"{total_tokens:,}",
                limit=f"{effective_limit:,}",
                safety=f"{safety_limit:,}",
                overhead=f"{prompt_overhead:,}",
            )
        elif total_tokens > effective_limit:
            emit(
                "CAPACITY_EXCEEDS",
                tokens=f"{total_tokens:,}",
                limit=f"{effective_limit:,}",
                safety=f"{safety_limit:,}",
                overhead=f"{prompt_overhead:,}",
            )
        elif force_batch:
            emit(
                "CAPACITY_FITS_FORCE",
                tokens=f"{total_tokens:,}",
                limit=f"{effective_limit:,}",
                safety=f"{safety_limit:,}",
                overhead=f"{prompt_overhead:,}",
            )
        else:
            emit(
                "CAPACITY_FITS", tokens=f"{total_tokens:,}", limit=f"{effective_limit:,}", safety=f"{safety_limit:,}", overhead=f"{prompt_overhead:,}"
            )
            return ("direct", files_data, effective_limit, shared.get("batch_size", 50), None, None, directory_tree, False)

        return (
            "batch",
            files_data,
            effective_limit,
            shared.get("batch_size", 50),
            file_token_map,
            count_tokens,
            directory_tree,
            shared.get("debug", False),
        )

    The second phase evaluates total repository content against the computed effective_limit. If the operating mode is api-reference, the node short-circuits directly to "deterministic". Otherwise, if force_batch is set or if total_tokens exceeds effective_limit, it routes to "batch"; otherwise, it returns "direct".

    ContextRouter.exec()

    Signature: def exec(self, prep_res: tuple) -> str | list[list[tuple[int, str, str]]]:

    Description: Constructs token-bounded, directory-coherent file batches when routing to "batch", or passes through the route string for "direct" and "deterministic".

        def exec(self, prep_res):
        route, files_data, effective_limit, batch_size, file_token_map, _count_tokens, directory_tree, debug = prep_res
        llm_logger.info(
            f"NODE EXEC | node=ContextRouter | action=route_decision | route={route} | files={len(files_data)} | effective_limit={effective_limit:,}"
        )

        if route == "direct":
            return "direct"
        if route == "deterministic":
            return "deterministic"

        # Group by directory for coherence, with pre-computed tokens
        dir_groups = defaultdict(list)
        for i, (path, content) in enumerate(files_data):
            dir_groups[os.path.dirname(path)].append((i, path, content, file_token_map[i]))

        # Build token-aware batches (never mix directories)
        batches = []
        for dirname in sorted(dir_groups.keys()):
            current_batch = []
            current_tokens = 0

            for i, path, content, tokens in dir_groups[dirname]:
                # Start new batch if adding this file would exceed effective limit or file count cap
                if current_batch and (current_tokens + tokens > effective_limit or len(current_batch) >= batch_size):
                    batches.append(current_batch)
                    current_batch = []
                    current_tokens = 0

                current_batch.append((i, path, content))
                current_tokens += tokens

            # Flush remaining files in this directory
            if current_batch:
                batches.append(current_batch)

        batch_word = "batch" if len(batches) == 1 else "batches"
        emit("CAPACITY_SPLIT", count=len(batches), word=batch_word)
        llm_logger.info(f"NODE COMPLETE | node=ContextRouter | route={route} | batches={len(batches)}")

        # Debug: show detailed batch info
        if debug:
            for idx, batch in enumerate(batches):
                content_tokens = sum(file_token_map[i] for i, p, _c in batch)
                emit("CAPACITY_BATCH_DEBUG", index=idx, file_count=len(batch), tokens=f"{content_tokens:,}", limit=f"{effective_limit:,}")
                for i, p, _c in batch:
                    emit("BATCH_FILE_ITEM", index=i, path=p)

        # Store directory tree for later use
        self._directory_tree = directory_tree

        return batches

    When batching is required, files are partitioned strictly along directory boundaries to preserve semantic context. Batches are segmented so that neither the file count cap (batch_size, defaulting to 50) nor the effective_limit token ceiling is exceeded. Directories are never split across batches unless a single directory's files exceed the capacity constraints.

    DeterministicFileMapper.exec()

    Signature: def exec(self, prep_res: tuple) -> list[int]:

    Description: Executes LLM inference to classify source files and parses the returned YAML list of valid integer file indices.

        def exec(self, prep_res):
        try:
            prompt, use_cache, thinking_level, max_tokens = prep_res
            emit("LLM_CALL_FILTER_FILES")

    This method delegates inference to utils/call_llm.py and extracts integer indices via parse_yaml_response. If the response contains invalid YAML, the caught exception triggers logging and re-raises to activate PocketFlow's retry mechanism.

    DeterministicFileMapper.post()

    Signature: def post(self, shared: dict, prep_res: tuple, exec_res: list[int]) -> str:

    Description: Transforms valid indices into module abstraction specifications and orders chapters by directory depth (deepest first).

        def post(self, shared, prep_res, exec_res):
        import os

        files = shared.get("files", [])
        valid_indices = set(exec_res)
        modules = []
        chapter_order = []

        for idx, (file_path, _content) in enumerate(files):
            if idx not in valid_indices:
                emit("SKIP_NON_CODE_FILE", path=file_path)
                continue

            clean_name = os.path.basename(file_path)

            modules.append(
                {"name": clean_name, "description": f"Internal API reference for `{file_path}`", "files": [idx], "original_path": file_path}
            )
            chapter_order.append(len(modules) - 1)

        shared["abstractions"] = modules
        # Sort chapter order by directory depth (deepest first, then alphabetical).
        # This ensures utility/leaf files are processed before orchestration files,
        # so their summaries are available as cross-chapter context.
        # Works universally across all languages (Python, C#, C++, Java, etc.).
        shared["chapter_order"] = sorted(
            chapter_order,
            key=lambda idx: (
                -modules[idx]["original_path"].count("/") - modules[idx]["original_path"].count(os.sep),
                modules[idx]["original_path"].lower(),
            ),
        )
        shared["relationships"] = {"summary": "Deterministic Internal API Reference.", "details": []}
        emit("DONE_DETERMINISTIC_MAPPER", count=len(modules))
        return "default"

    The sorting key -modules[idx]["original_path"].count("/") - modules[idx]["original_path"].count(os.sep) orders leaf and utility files ahead of high-level root coordinators. This bottom-up sequence ensures that when WriteChapters generates cross-chapter technical briefs, lower-level dependency summaries are already available as context for higher-level modules.

    IdentifyAbstractions

    Visibility: Public

    IdentifyAbstractions.prep()

    Signature: def prep(self, shared: dict) -> tuple:

    Description: Constructs repository context using a safe token ceiling, generates the directory tree, and packages execution configuration.

        def prep(self, shared):
        files_data = shared["files"]
        project_name = shared["project_name"]  # Get project name

        return lambda text: len(enc.encode(text, disallowed_special=()))
    except Exception:
        return lambda text: len(text) // 4

    Passing disallowed_special=() prevents encoding errors when processing source files containing tokens like <|endoftext|>. If tiktoken is unavailable, the fallback heuristic ensures token estimation continues uninterrupted.

    Error Handling

    Cache-Bypassing Retries

    All LLM-dependent execution nodes (DeterministicFileMapper, IdentifyAbstractions, MapAbstractions, ReduceAbstractions, AnalyzeRelationships, OrderChapters, WriteChapters) employ conditional cache bypassing: 

    response = call_llm(prompt, use_cache=(use_cache and self.cur_retry == 0), thinking_level=thinking_level)
    On the initial attempt (cur_retry == 0), the node uses the local cache if enabled. If execution fails and PocketFlow initiates a retry (cur_retry > 0), the cache is bypassed to avoid re-reading stale or corrupted cached responses.

    Node Error Trapping and Logging

    All node execution bodies are wrapped in comprehensive try-except blocks: 

    except Exception as e:
    emit("NODE_RETRY_ERROR", class_name=self.__class__.__name__, error=e)
    llm_logger.error(f"[Node {self.__class__.__name__}] Error: {e}", exc_info=True)
    raise e
    This logs the full stack trace to the diagnostic logger and emits a localized terminal warning before re-raising the exception to trigger PocketFlow's configured retry and backoff mechanisms (max_retries=5, wait=20).

    Context Safety Ceilings

    To prevent context window overflow when assembling prompts, ContextRouter, IdentifyAbstractions, and AnalyzeRelationships enforce a 95% safety margin: 

    safety_limit = int(max_tokens * 0.95)
effective_limit = safety_limit - prompt_overhead
    Files that would cause total tokens to exceed this threshold are truncated, and a WARN_CONTEXT_TRUNCATED signal is emitted.

    Defensive YAML and Index Parsing

    YAML parsing incorporates defensive fallbacks to handle common model formatting anomalies: * parse_yaml_response() extracts text strictly from within yaml ... code fences, ignoring any conversational preamble or postscript. * Index parsers strip inline comments (e.g., "3 # src/main.py" becomes 3) using regex integer matching: 

    idx_str = str(idx_entry).split("#")[0].strip()
nums = re.findall(r"\d+", idx_str)
    * Hyphenated ranges (e.g., "4-7") are expanded into discrete sequences: [4, 5, 6, 7]. * Endpoint validation drops edges referencing indices outside [0, num_abstractions - 1].
