    nodes.py

    Source: nodes.py

    Technical Overview

    nodes.py constitutes the computational core and generative backbone of the Codebase-Knowledge-Builder architecture. It implements all executable node definitions organized within the PocketFlow framework, defining both atomic single-execution tasks (Node) and parallelizable multi-item processing tasks (BatchNode). Each node conforms to a strict three-phase lifecycle: prep() extracts and prepares inputs from a centralized mutable state store (shared), exec() executes computational logic or invokes remote Large Language Models (LLMs), and post() mutates the shared store or routes the execution path through stateful action keys.

    The module provides three distinct architectural workflows governed dynamically by repository sizing and selected documentation modes. In tutorial, advanced, and sdk modes, ContextRouter evaluates the total token weight of the codebase against model context limits and safety thresholds to dynamically branch execution: small codebases take a direct path (IdentifyAbstractions to AnalyzeRelationships), while large codebases undergo directory-isolated chunking via a map-reduce pipeline (MapAbstractions to ReduceAbstractions). In api-reference mode, the module bypasses heuristic abstraction clustering entirely, employing DeterministicFileMapper for 1:1 file-to-chapter mapping and ExtractFacts for deterministic, evidence-backed fact verification without an Abstract Syntax Tree (AST).

    System-level resilience and caching are embedded directly across the node hierarchy. The safe_exec decorator wraps all execution bodies to guarantee structured logging and standard retry handling through PocketFlow. Downstream nodes, particularly WriteChapters and ExtractFacts, feature cryptographic fingerprinting via MD5 and SHA-256 digests over source code, prompt templates, and reasoning configurations. This enables fine-grained incremental compilation, ensuring that unmodified files reuse verified factual claims and cached Markdown chapters across build cycles.

    Public API

    safe_exec()

    Visibility: Public

    Signature: def safe_exec(func):

    Description: A higher-order decorator designed to wrap the exec methods of Node and BatchNode subclasses. It intercepts unhandled exceptions, publishes structured failure events via utils.output.emit, records the complete Python stack trace to persistent logs, and re-raises the exception to let the underlying PocketFlow retry engine manage backoff and retry lifecycles.

    Parameters:

    • func (callable): The exec method of a PocketFlow node instance.

    Returns:

    • callable: A decorated wrapper function preserving the original function signature and docstring.

    Raises:

    • Exception: Re-raises any exception thrown by the underlying wrapped method.

    Example:

    def safe_exec(func):
    """Decorator that wraps Node.exec() with standardized error handling.

    On exception: emits NODE_RETRY_ERROR, logs traceback, and re-raises.
    Eliminates the identical try/except pattern duplicated across all nodes.
    """

    @wraps(func)
    def wrapper(self, *args, **kwargs):
        try:
            return func(self, *args, **kwargs)
        except Exception as e:
            emit("NODE_RETRY_ERROR", class_name=self.__class__.__name__, error=e)
            emit_raw("ERROR", f"[Node {self.__class__.__name__}] Error: {e}\n{traceback.format_exc()}", dest="LOG")
            raise

    return wrapper

    The decorator wraps execution logic in a standardized try...except block, ensuring identical logging telemetry without duplicating boilerplate across every node. If an exception occurs, it emits an event identifying the failed node class name and writes the formatted traceback directly to the file logger destination before propagating the exception up the call stack.

    DeterministicFileMapper

    Visibility: Public

    Signature: class DeterministicFileMapper(Node):

    Description: A deterministic node utilized exclusively in api-reference mode. It bypasses LLM-based architectural clustering and instead maps candidate source files directly to individual documentation chapters. It invokes an LLM to distinguish functional source files from build manifests or non-code assets, then structures an ordered list of modules arranged by directory depth.

    Visibility: Public

    Signature: def prep(self, shared):

    Description: Filters out empty and whitespace-only candidate files from shared["files"], builds a formatted file listing, generates a classification prompt via build_code_file_filter_prompt, and extracts runtime configuration parameters.

    Parameters:

    • shared (dict): The central workflow state dictionary.

    Returns:

    • tuple[str, bool, str | None, int]: A 4-element tuple containing:
      1. prompt: The rendered file classification prompt string.
      2. use_cache: Boolean flag governing whether caching is active.
      3. thinking_level: Resolved reasoning effort string or None.
      4. max_tokens: Context token limit for model execution.

    Raises:

    • None.

    Example:

        def prep(self, shared):
        files_data = shared["files"]
        project_name = shared["project_name"]

        # Empty/whitespace-only files (e.g. bare __init__.py) are left out: post() skips unlisted indices,
        # so they are never documented instead of flipping in and out with the LLM's answer.
        file_listing = "\n".join([f"{i} # {path}" for i, (path, content) in enumerate(files_data) if content.strip()])

        prompt = build_code_file_filter_prompt(project_name, file_listing)
        emit_raw("DEBUG", f"DeterministicFileMapper prep | {len(files_data)} candidate files for filtering", dest="LOG")
        return prompt, shared.get("use_cache", True), resolve_thinking_level(shared, "filter_files"), shared.get("max_tokens", 100000)

    The method iterates over files_data, building an indexed string representation of non-empty files. It delegates prompt assembly to build_code_file_filter_prompt and resolves LLM reasoning effort specific to "filter_files".

    DeterministicFileMapper.exec()

    Visibility: Public

    Signature: def exec(self, prep_res):

    Description: Dispatches the classification prompt to the LLM via call_llm, parses the YAML response, and segregates identified file indices into code files and build manifest files. Wrapped with @safe_exec.

    Parameters:

    • prep_res (tuple): The 4-element parameter tuple generated by prep().

    Returns:

    • tuple[list[int], list[int]]: A 2-element tuple consisting of:
      1. indices: List of zero-based integer indices representing validated code files.
      2. manifest_indices: List of zero-based integer indices representing project manifest files.

    Raises:

    • Exception: Any network, timeout, or parsing error encountered during execution.

    Example:

        @safe_exec
    def exec(self, prep_res):
        prompt, use_cache, thinking_level, max_tokens = prep_res
        emit("LLM_CALL_FILTER_FILES")
        log_token_estimation(self.__class__.__name__, prompt, max_tokens)
        response = call_llm(prompt, use_cache=(use_cache and self.cur_retry == 0), thinking_level=thinking_level, step="filter_files")
        parsed = parse_yaml_response(response)
        # {code: [...], manifests: [...]}; a bare list (older reply shape) is the code list
        code = parsed.get("code") if isinstance(parsed, dict) else parsed
        manifests = parsed.get("manifests") if isinstance(parsed, dict) else []
        indices = [idx for entry in (code if isinstance(code, list) else []) for idx in parse_file_indices(entry)]
        manifest_indices = [idx for entry in (manifests if isinstance(manifests, list) else []) for idx in parse_file_indices(entry)]
        return indices, manifest_indices

    The method passes the prompt to call_llm and routes the YAML output into parse_yaml_response. It parses both code files and manifests, normalizing entries using parse_file_indices to extract integer index arrays.

    DeterministicFileMapper.post()

    Visibility: Public

    Signature: def post(self, shared, prep_res, exec_res):

    Description: Integrates validated code and manifest indices into shared. It builds module abstraction records for each source file, establishes an initial chapter sequence ordered inversely by directory depth (deepest leaves first), and initializes stub relationship entries.

    Parameters:

    • shared (dict): Central workflow state dictionary.
    • prep_res (tuple): The tuple returned by prep().
    • exec_res (tuple[list[int], list[int]]): The code and manifest index lists produced by exec().

    Returns:

    • str: Action directive "default".

    Raises:

    • None.

    Example:

        def post(self, shared, prep_res, exec_res):
        files = shared.get("files", [])
        code_indices, manifest_indices = exec_res
        valid_indices = set(code_indices)
        shared["manifest_files"] = sorted(
            {idx for idx in manifest_indices if 0 <= idx < len(files) and idx not in valid_indices and files[idx][1].strip()}
        )
        modules = []
        chapter_order = []

        for idx, (file_path, content) in enumerate(files):
            if idx not in valid_indices or not content.strip():
                emit("SKIP_NON_CODE_FILE", path=file_path)
                continue

            clean_name = os.path.basename(file_path)
            doc_path = file_path.replace(os.sep, "/")
            modules.append({"name": clean_name, "description": f"Internal API reference for `{doc_path}`", "files": [idx], "original_path": doc_path})
            chapter_order.append(len(modules) - 1)

        shared["abstractions"] = modules
        shared["chapter_order"] = sorted(
            chapter_order,
            key=lambda idx: (
                -modules[idx]["original_path"].count("/") - modules[idx]["original_path"].count(os.sep),
                modules[idx]["original_path"].lower(),
            ),
        )
        shared["relationships"] = {"summary": "Deterministic Internal API Reference.", "details": []}
        emit("DONE_DETERMINISTIC_MAPPER", count=len(modules))
        return "default"

    The method populates shared["manifest_files"] while filtering out code file overlaps. It constructs abstraction dicts for all valid files and orders shared["chapter_order"] such that leaf files in nested subdirectories appear before high-level orchestrators, providing bottom-up context during chapter drafting.

    ExtractFacts

    Visibility: Public

    Signature: class ExtractFacts(BatchNode):

    Description: A specialized batch processing node executed during api-reference workflows. It iterates over every module abstraction and manifest file, generating verbatim quotes of code claims (symbols, exports, configurations, dependencies, errors) via an LLM. Claims are audited against actual file contents using utils.facts.verify_file_claims. The node persists verified module metadata to disk in facts.json and supports incremental caching based on cryptographic source hashes.

    ExtractFacts.prep()

    Visibility: Public

    Signature: def prep(self, shared):

    Description: Constructs the batch work queue for code modules and manifest files. Computes a cache signature digest combining model settings, template hashes, and file content to determine whether previous factual extractions from facts.json can be reused.

    Parameters:

    • shared (dict): Central workflow state dictionary.

    Returns:

    • list[dict]: A collection of payload item dictionaries ready for per-item execution by exec().

    Raises:

    • None.

    Example:

        def prep(self, shared):
        files_data = shared["files"]
        template = load_prompt_template("extract_facts", mode="common")
        thinking_level = resolve_thinking_level(shared, "extract_facts")
        provider, model_name, _, _ = resolve_llm_settings()
        signature = f"{provider}|{model_name}|{thinking_level or 'default'}|{hashlib.md5(template.encode('utf-8')).hexdigest()}"
        self.facts_file = facts_path(shared.get("output_dir", "output"), shared["project_name"], shared.get("mkdocs", False))
        reuse = shared.get("incremental") or shared.get("use_cache", True)
        previous = load_facts(self.facts_file) if reuse else {}
        self.previous_manifests = load_facts(self.facts_file, section="manifests") if reuse else {}
        self.best = {}  # path → (found, claims) of the best attempt so far, kept when retries do worse

        items = []
        for module in shared["abstractions"]:
            file_path, content = files_data[module["files"][0]]
            path = module.get("original_path") or file_path.replace(os.sep, "/")
            item_hash = facts_hash(signature, path, content)
            cached = previous.get(path) if isinstance(previous.get(path), dict) else {}
            items.append(
                {
                    "path": path,
                    "content": content,
                    "facts_hash": item_hash,
                    "cached_claims": cached.get("claims") if cached.get("facts_hash") == item_hash else None,
                    "cached_followup": (cached.get("completeness") or {}).get("followup"),
                    "template": template,
                    "project_name": shared["project_name"],
                    "use_cache": shared.get("use_cache", True),
                    "thinking_level": thinking_level,
                    "max_tokens": shared.get("max_tokens", 100000),
                }
            )
        # ... manifests queue assembly skipped ...
        return items

    The method generates a unique configuration signature and opens the local facts.json file if caching or incremental mode is enabled. It compiles separate task descriptors for each code module and manifest file, associating existing claims if facts_hash matches.

    ExtractFacts.exec()

    Visibility: Public

    Signature: def exec(self, item):

    Description: Dispatches LLM extraction prompts for a single code module or manifest item. Audits returned quotes against source content, enforces coverage thresholds, initiates targeted follow-up extraction cycles when declarations remain unextracted, and caches the best attempt across retries. Wrapped with @safe_exec.

    Parameters:

    • item (dict): Task specification dictionary produced by prep().

    Returns:

    • dict: Result record containing verified claims, hash markers, follow-up metrics, and file paths.

    Raises:

    • ValueError: Raised if fewer than 50% of claimed quotes can be located within the file text when four or more claims are made.

    Example:

        @safe_exec
    def exec(self, item):
        if item.get("kind") == "manifest":
            return self._exec_manifest(item)
        if item["cached_claims"] is not None:
            emit("FACTS_CACHE_HIT", name=item["path"])
            followup = item["cached_followup"] if isinstance(item["cached_followup"], dict) else {"status": "none", "asked": []}
            if followup.get("status") != "failed":
                return {"path": item["path"], "facts_hash": item["facts_hash"], "claims": item["cached_claims"], "followup": followup}
            claims, followup, calls = self._follow_up(item, item["cached_claims"], followup.get("asked") or [])
            return {"path": item["path"], "facts_hash": item["facts_hash"], "claims": claims, "followup": followup, "followup_calls": calls}
        prompt = item["template"].format(project_name=item["project_name"], file_path=item["path"], source=item["content"], focus_note="")
        emit("LLM_CALL_EXTRACT_FACTS", name=item["path"])
        log_token_estimation(self.__class__.__name__, prompt, item["max_tokens"])
        response = call_llm(
            prompt, use_cache=(item["use_cache"] and self.cur_retry == 0), thinking_level=item["thinking_level"], step="extract_facts"
        )
        claims = parse_facts_response(response)
        checked = verify_file_claims(claims, item["content"])
        emit_raw("DEBUG", f"FACTS | {item['path']} | claimed={checked['claimed']} | found={checked['found']}", dest="LOG")
        if self.cur_retry == 0:
            self.best.pop(item["path"], None)
        best = self.best.get(item["path"])
        if best is None or checked["found"] > best[0]:
            self.best[item["path"]] = best = (checked["found"], claims)
        if checked["claimed"] >= 4 and checked["found"] * 2 < checked["claimed"] and self.cur_retry < self.max_retries - 1:
            emit("FACTS_LOW_COVERAGE", name=item["path"], found=checked["found"], claimed=checked["claimed"])
            raise ValueError(f"only {checked['found']}/{checked['claimed']} claims found in the source")
        claims, followup, calls = self._follow_up(item, best[1])
        return {"path": item["path"], "facts_hash": item["facts_hash"], "claims": claims, "followup": followup, "followup_calls": calls}

    The method inspects cache state, delegating manifest tasks to _exec_manifest(). If un-cached, it calls the LLM, validates returned claims using verify_file_claims, and records the best response in self.best. If hallucinated or paraphrased quotes depress verified coverage below 50%, it raises a ValueError to force an uncached retry before finally invoking _follow_up().

    ExtractFacts.exec_fallback()

    Visibility: Public

    Signature: def exec_fallback(self, item, exc):

    Description: Graceful degradation fallback invoked by PocketFlow when an item fails across all permitted retries. Preserves the best partially parsed claims if available; otherwise returns empty claims without a cache hash to force re-extraction on subsequent runs.

    Parameters:

    • item (dict): The failed task dictionary.
    • exc (Exception): The exception causing the fatal retry exhaustion.

    Returns:

    • dict: Fallback record containing available claims or None.

    Raises:

    • None.

    Example:

        def exec_fallback(self, item, exc):
        """The best earlier attempt if one parsed; else no facts for this module this run (no hash, so the
        next run retries it). The flow goes on either way."""
        emit("WARN_FACTS_FALLBACK", name=item["path"], error=exc)
        if item.get("kind") == "manifest":
            return {"kind": "manifest", "path": item["path"], "facts_hash": None, "claims": None}
        best = self.best.get(item["path"])
        if best is not None:  # no follow-up ran: the next run asks it
            return {"path": item["path"], "facts_hash": item["facts_hash"], "claims": best[1], "followup": {"status": "failed", "asked": []}}
        return {"path": item["path"], "facts_hash": None, "claims": None}

    If a prior retry successfully parsed valid claims, exec_fallback preserves that result with a "failed" follow-up status, ensuring the pipeline can proceed without losing all fact context for that file. If no parsing ever succeeded, it returns None for claims and hash.

    Visibility: Public

    Signature: def post(self, shared, prep_res, exec_res_list):

    Description: Aggregates batch results, constructs a global ModuleTable to resolve cross-file dependencies and path aliases, calculates line completeness metrics, serializes verified facts to facts.json, and records shared["module_facts"].

    Parameters:

    • shared (dict): Central workflow state dictionary.
    • prep_res (list[dict]): The item queues prepared in prep().
    • exec_res_list (list[dict]): Collection of execution result dictionaries returned by exec() and exec_fallback().

    Returns:

    • str: Action directive "default".

    Raises:

    • None.

    Example:

        def post(self, shared, prep_res, exec_res_list):
        manifest_results = [res for res in exec_res_list if res.get("kind") == "manifest"]
        exec_res_list = [res for res in exec_res_list if res.get("kind") != "manifest"]
        manifest_texts = {item["path"]: item["content"] for item in prep_res if item.get("kind") == "manifest"}
        manifests = {
            res["path"]: {
                **verify_manifest_claims(res["claims"], manifest_texts[res["path"]], res["path"]),
                "facts_hash": res["facts_hash"],

            for res in manifest_results
            if res["claims"] is not None
        }
        contents = {item["path"]: item["content"] for item in prep_res if item.get("kind") != "manifest"}
        checked = {res["path"]: verify_file_claims(res["claims"], contents[res["path"]]) for res in exec_res_list if res["claims"] is not None}
        table = ModuleTable(list(contents), {path: result["symbols"] for path, result in checked.items()}, contents, manifests)
        resolved = verify_dependencies({path: result["dependencies"] for path, result in checked.items()}, contents, table)
        # ... dict compilation, save_facts(), and telemetry emission ...
        return "default"

    The method segregates code results from manifest extractions, verifying manifest claims using verify_manifest_claims. It instantiates a ModuleTable across all verified symbols and resolves dependency edges via verify_dependencies. Finally, it compiles bidirectional depends_on and used_by links, formats completeness statistics, updates shared["module_facts"], and persists the document to disk via save_facts.

    ContextRouter

    Visibility: Public

    Signature: class ContextRouter(Node):

    Description: The pipeline's structural flow controller. Evaluates total codebase token size against LLM context boundaries to determine whether the codebase should be processed in a single prompt pass ("direct"), partitioned into directory-isolated token batches ("batch"), or handled through the deterministic file mapper ("deterministic").

    ContextRouter.prep()

    Visibility: Public

    Signature: def prep(self, shared):

    Description: Computes prompt overhead (templates, directory tree, chapter listings) and file token counts. Compares codebase volume to the effective input safety limit to select the optimal routing strategy.

    Parameters:

    • shared (dict): Central workflow state dictionary.

    Returns:

    • tuple: A 7-element routing tuple:
      1. route: Selected route name ("direct", "batch", or "deterministic").
      2. files_data: The raw list of file path and content tuples.
      3. effective_limit: Usable input token budget after reserving output tokens and template overhead.
      4. batch_size: Maximum file count permitted per batch.
      5. file_token_map: Pre-computed list of token counts per file (or None).
      6. count_tokens: Callable token estimation function reference (or None).
      7. directory_tree: Formatted directory structure string.

    Raises:

    • None.

    Example:

        def prep(self, shared):
        files_data = shared["files"]
        max_tokens = resolve_max_tokens(shared)

        shared["max_tokens"] = max_tokens
        directory_tree = build_directory_tree(files_data)

If declaration-like or import-like lines remain omitted from claims, it prompts the LLM specifically on those lines (up to FACTS_FOCUS_LIMIT lines per turn) for up to FOLLOWUP_ROUNDS iterations, merging the new claims into the accumulated claim set.

      1. claims: Updated claims dictionary merged with verified follow-up claims.
      2. followup_status: Metadata dictionary containing "status" ("done", "failed", or "none") and "asked" line lists.
      3. calls: Total count of follow-up network calls dispatched.

    Raises:

    • None.

    Example:

        def _follow_up(self, item, claims, asked=()):
        asked, calls, lines = list(asked), 0, split_lines(item["content"])
        for _round in range(self.FOLLOWUP_ROUNDS):
            hints = completeness_hints(item["content"], verify_file_claims(claims, item["content"]), claims)
            already = set(asked)
            pending = [number for number in hints["uncovered"] if number not in already]
            if not pending:
                break
            note = build_facts_focus_note([(number, lines[number - 1]) for number in pending])
            prompt = item["template"].format(project_name=item["project_name"], file_path=item["path"], source=item["content"], focus_note=note)
            emit("FACTS_FOLLOWUP", name=item["path"], count=len(pending))
            log_token_estimation(self.__class__.__name__, prompt, item["max_tokens"])
            answer = None
            for attempt in range(2):
                calls += 1
                try:
                    response = call_llm(
                        prompt,
                        use_cache=(item["use_cache"] and self.cur_retry == 0 and attempt == 0),
                        thinking_level=item["thinking_level"],
                        step="extract_facts",
                    )
                    answer = parse_facts_response(response)
                    break
                except Exception as e:
                    emit_raw("WARNING", f"FACTS FOLLOW-UP FAILED | {item['path']} | attempt {attempt + 1} | {e}", dest="LOG")
            if answer is None:
                return claims, {"status": "failed", "asked": asked}, calls
            claims = merge_claims(claims, answer)
            asked += pending[:FACTS_FOCUS_LIMIT]
        return claims, {"status": "done" if asked else "none", "asked": asked}, calls

    The method loops up to FOLLOWUP_ROUNDS times, calling completeness_hints to identify uncovered lines that look like declarations or imports.     Error Handling

    The module implements layered fault tolerance to survive network failures, token exhaustion, and non-deterministic model completions without aborting documentation generation:

    • Centralized Node Interception (@safe_exec): Every node's exec implementation is decorated with safe_exec(). Any unhandled runtime exception triggers an immediate NODE_RETRY_ERROR event via utils.output.emit, formats and records the full stack trace to the log file, and re-raises the exception so PocketFlow can manage retry limits and backoff schedules.
    • Low Coverage Re-Prompting (ExtractFacts.exec): Hallucinated or paraphrased quotes that cannot be found verbatim in source text are tracked by verify_file_claims. If a module generates four or more claims but fewer than 50% can be verified against physical source lines (checked["found"] * 2 < checked["claimed"]), the node raises a ValueError prior to its final retry, forcing an uncached retry to request verbatim quotes.
    • Batch Fallback Mechanisms (exec_fallback): Both ExtractFacts and WriteChapters implement exec_fallback(). If a file or chapter fails across all retry attempts:
      • ExtractFacts retains the best parsed claims from earlier attempts (with "status": "failed") or returns an empty claim set without an MD5 hash.
      • WriteChapters returns a placeholder Markdown document (UI_CHAPTER_UNAVAILABLE) with hash: None and inserts a placeholder summary into the context queue. Because failed items have their hash set to None, they are omitted from .doc_cache_manifest.json, ensuring they will be re-attempted on subsequent incremental runs.
    • Non-Blocking Follow-Up Failures (ExtractFacts._follow_up): Network drops or parsing errors during multi-turn follow-up passes are logged as warnings without raising exceptions, returning accumulated base claims with "status": "failed" so the pipeline can proceed safely.
    • Crash-Resilient Manifest Commits (CombineTutorial.post): Incremental manifest files are written to a .tmp file and committed atomically using os.replace. This prevents corrupt manifests if execution is interrupted mid-write.
