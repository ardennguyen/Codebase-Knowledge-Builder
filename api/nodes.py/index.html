    nodes.py

    Source: nodes.py

    Technical Overview

    The nodes.py module defines the concrete computational nodes and lifecycle methods executed within the pocketflow Directed Acyclic Graph (DAG) for codebase documentation generation. Acting as the operational heart of the pipeline, it translates high-level documentation goals into staged state transformations across ingestion, architectural discovery, fact extraction, chapter synthesis, and publishing. The module accommodates diverse codebase scales and documentation targets, dynamically routing execution between single-prompt holistic analysis (IdentifyAbstractions), Map-Reduce batching (MapAbstractions, ReduceAbstractions), and deterministic one-to-one module mapping (DeterministicFileMapper, ExtractFacts).

    Execution relies on a shared memory dictionary (shared), where each node executes a three-phase lifecycle: prep extracts and formats necessary inputs from shared state, exec executes deterministic parsing or Large Language Model (LLM) inference, and post validates payloads and mutates shared state for downstream consumers. LLM-facing nodes integrate with token counting, budget reservation, thinking profile resolution, and multi-tier caching to guarantee deterministic boundaries. Resilience is enforced via the safe_exec decorator, structured exception handling, and dedicated batch fallback methods (exec_fallback) that maintain graph progression during partial downstream failures.

    Public API

    safe_exec()

    Visibility: Public

    Signature: def safe_exec(func):

    Description: A decorator that wraps a node's exec() implementation with standardized error trapping and diagnostic emission. When an unhandled exception occurs during node execution, safe_exec intercepts the error, emits a UI event (NODE_RETRY_ERROR), logs the complete stack traceback to the destination file logger, and re-raises the exception to let PocketFlow's retry engine manage retry policies.

    Parameters:

    • func (Callable): The node exec() method to wrap.

    Returns:

    • Callable: The decorated wrapper function.

    Raises:

    • Exception: Re-raises any exception encountered during the invocation of func.

    Example:

    def safe_exec(func):
    """Decorator that wraps Node.exec() with standardized error handling.

    On exception: emits NODE_RETRY_ERROR, logs traceback, and re-raises.
    Eliminates the identical try/except pattern duplicated across all nodes.
    """

    @wraps(func)
    def wrapper(self, *args, **kwargs):
        try:
            return func(self, *args, **kwargs)
        except Exception as e:
            emit("NODE_RETRY_ERROR", class_name=self.__class__.__name__, error=e)
            emit_raw("ERROR", f"[Node {self.__class__.__name__}] Error: {e}\n{traceback.format_exc()}", dest="LOG")
            raise

    return wrapper

    The decorator intercepts failures originating from LLM network transport, YAML parsing, or invalid model structures across all decorated exec methods. By extracting the class name dynamically via self.__class__.__name__, telemetry events precisely identify the failing node. Logging the traceback directly to dest="LOG" preserves terminal cleanliness while providing comprehensive debugging context on disk.

    DeterministicFileMapper

    Visibility: Public

    Signature: class DeterministicFileMapper(Node):

    Description: A deterministic mapping node used primarily in api-reference mode to map codebase files directly to documentation pages on a 1:1 basis. It requests an LLM file classification pass to filter out non-code assets and build manifests, then establishes an ordered module list sorted hierarchically by directory depth.

    DeterministicFileMapper.prep()

    Visibility: Public

    Signature: def prep(self, shared):

    Description: Extracts the candidate file listing from shared["files"], filters out whitespace-only files (such as bare __init__.py markers), constructs an index-annotated file listing, and builds a filtering prompt using build_code_file_filter_prompt.

    Parameters:

    • shared (dict): Central shared pipeline dictionary containing "files", "project_name", and execution flags.

    Returns:

    • tuple: A 4-tuple containing (prompt, use_cache, thinking_level, max_tokens).

    Raises:

    • None.

    Example:

        def prep(self, shared):
        files_data = shared["files"]
        project_name = shared["project_name"]

        # Empty/whitespace-only files (e.g. bare __init__.py) are left out: post() skips unlisted indices,
        # so they are never documented instead of flipping in and out with the LLM's answer.
        file_listing = "\n".join([f"{i} # {path}" for i, (path, content) in enumerate(files_data) if content.strip()])

        prompt = build_code_file_filter_prompt(project_name, file_listing)
        emit_raw("DEBUG", f"DeterministicFileMapper prep | {len(files_data)} candidate files for filtering", dest="LOG")
        return prompt, shared.get("use_cache", True), resolve_thinking_level(shared, "filter_files"), shared.get("max_tokens", 100000)

    The method iterates through shared["files"] and excludes any entries where content.strip() is empty to prevent blank files from appearing inconsistently across LLM calls. It then formats the remaining entries into line-delimited index annotations ({i} # {path}) and constructs the prompt via build_code_file_filter_prompt. Finally, it returns the prompt alongside execution settings retrieved from shared.

    DeterministicFileMapper.exec()

    Visibility: Public

    Signature: def exec(self, prep_res):

    Description: Dispatches the classification prompt to the LLM under step "filter_files", parses the YAML response into code files and workspace manifests, and extracts numerical index arrays for both categories.

    Parameters:

    • prep_res (tuple): The 4-tuple generated by prep().

    Returns:

    • tuple: A 2-tuple (indices, manifest_indices) representing validated code files and package manifest files.

    Raises:

    • Exception: Any network, token, or parsing exception raised during call_llm or parse_yaml_response.

    Example:

        @safe_exec
    def exec(self, prep_res):
        prompt, use_cache, thinking_level, max_tokens = prep_res
        emit("LLM_CALL_FILTER_FILES")
        log_token_estimation(self.__class__.__name__, prompt, max_tokens)
        response = call_llm(prompt, use_cache=(use_cache and self.cur_retry == 0), thinking_level=thinking_level, step="filter_files")
        parsed = parse_yaml_response(response)
        # {code: [...], manifests: [...]}; a bare list (older reply shape) is the code list
        code = parsed.get("code") if isinstance(parsed, dict) else parsed
        manifests = parsed.get("manifests") if isinstance(parsed, dict) else []
        indices = [idx for entry in (code if isinstance(code, list) else []) for idx in parse_file_indices(entry)]
        manifest_indices = [idx for entry in (manifests if isinstance(manifests, list) else []) for idx in parse_file_indices(entry)]
        return indices, manifest_indices

    The execution flow delegates model invocation to call_llm with retry-aware caching policies (use_cache and self.cur_retry == 0). The returned YAML payload is evaluated using parse_yaml_response, normalizing both dictionary responses ({"code": [...], "manifests": [...]}) and legacy bare-list formats. Index ranges (e.g., "1-5") are resolved into discrete integer lists using parse_file_indices.

    DeterministicFileMapper.post()

    Visibility: Public

    Signature: def post(self, shared, prep_res, exec_res):

    Description: Validates extracted indices against physical file boundaries, populates shared["manifest_files"], generates 1:1 module descriptors in shared["abstractions"], and sorts shared["chapter_order"] by path depth (deepest subdirectories first, followed by alphabetical order).

    Parameters:

    • shared (dict): Central shared pipeline dictionary.
    • prep_res (tuple): The tuple returned from prep().
    • exec_res (tuple): The (indices, manifest_indices) tuple returned from exec().

    Returns:

    • str: Fixed action routing string "default".

    Raises:

    • None.

    Example:

        def post(self, shared, prep_res, exec_res):

        files = shared.get("files", [])
        code_indices, manifest_indices = exec_res
        valid_indices = set(code_indices)
        # Manifests are read by ExtractFacts (declared package names and path aliases), never documented as pages
        shared["manifest_files"] = sorted(
            {idx for idx in manifest_indices if 0 <= idx < len(files) and idx not in valid_indices and files[idx][1].strip()}
        )
        modules = []
        chapter_order = []

        for idx, (file_path, content) in enumerate(files):
            # Re-check emptiness: the LLM can return an index it was not shown (e.g. a contiguous range)
            if idx not in valid_indices or not content.strip():
                emit("SKIP_NON_CODE_FILE", path=file_path)
                continue

            clean_name = os.path.basename(file_path)
            # Forward slashes everywhere original_path is shown (nav dir labels, index) — the crawler keeps os.sep
            doc_path = file_path.replace(os.sep, "/")

            modules.append({"name": clean_name, "description": f"Internal API reference for `{doc_path}`", "files": [idx], "original_path": doc_path})
            chapter_order.append(len(modules) - 1)

        shared["abstractions"] = modules
        # Sort chapter order by directory depth (deepest first, then alphabetical).
        # This ensures utility/leaf files are processed before orchestration files,
        # so their summaries are available as cross-chapter context.
        # Works universally across all languages (Python, C#, C++, Java, etc.).
        shared["chapter_order"] = sorted(
            chapter_order,
            key=lambda idx: (
                -modules[idx]["original_path"].count("/") - modules[idx]["original_path"].count(os.sep),
                modules[idx]["original_path"].lower(),
            ),
        )
        shared["relationships"] = {"summary": "Deterministic Internal API Reference.", "details": []}
        emit("DONE_DETERMINISTIC_MAPPER", count=len(modules))
        return "default"

    The post-processing phase separates manifest assets from executable code, ensuring configuration manifests are marked for dependency and package-name inspection in ExtractFacts without producing standalone documentation chapters. Modules are constructed with uniform forward-slash doc paths (doc_path) regardless of host operating system path separators. Sorting chapter ordering by descending directory depth guarantees that leaf utilities are synthesized before high-level orchestrators, providing necessary summary context for cross-module linking.

    ExtractFacts

    Visibility: Public

    Signature: class ExtractFacts(BatchNode):

    Description: A batch processing node that extracts verified code facts (exported symbols, imports, configuration keys, and error behaviors) for each module. Facts are validated deterministically against the physical source code via utils.facts. Modules whose deterministic facts hash matches facts.json bypass LLM calls entirely.

    Signature: def prep(self, shared):

    Parameters:

    • shared (dict): Central shared pipeline dictionary containing "files", "abstractions", and "manifest_files".

    Returns:

    • list[dict]: List of extraction configuration dictionaries.

    Raises:

    Example:

        def prep(self, shared):
        files_data = shared["files"]
        template = load_prompt_template("extract_facts", mode="common")
        thinking_level = resolve_thinking_level(shared, "extract_facts")
        provider, model_name, _, _ = resolve_llm_settings()

        self.facts_file = facts_path(shared.get("output_dir", "output"), shared["project_name"], shared.get("mkdocs", False))
        reuse = shared.get("incremental") or shared.get("use_cache", True)

        return items

    The method constructs a model-and-template signature using provider settings and MD5 digests. Under --incremental or standard cache configurations, existing facts are deserialized from disk using load_facts(). Each item dictionary receives precomputed facts_hash markers and cached claims when the hash matches previous runs, allowing unchanged files to skip extraction entirely.

    ExtractFacts.exec()

    Visibility: Public

    Signature: def exec(self, item):

    Description: Executes claim extraction for a single batch item. If cached claims exist and no previous completeness follow-up failed, it returns cached records immediately. Otherwise, it queries the LLM, validates raw claims against physical source code lines using verify_file_claims, raises retry errors on low factual coverage, and triggers iterative completeness follow-ups.

    Parameters:

    • item (dict): Item configuration dictionary returned by prep().

    Returns:

    • dict: Verified extraction payload containing path, facts hash, claims dictionary, and follow-up metrics.

    Raises:

    • ValueError: Raised when verified claims cover less than 50% of claimed facts (when total claims $\ge 4$) before the final retry attempt, signaling hallucinated or paraphrased quotes.

    Example:

        @safe_exec
    def exec(self, item):
        if item.get("kind") == "manifest":
            return self._exec_manifest(item)
        if item["cached_claims"] is not None:
            emit("FACTS_CACHE_HIT", name=item["path"])
            followup = item["cached_followup"] if isinstance(item["cached_followup"], dict) else {"status": "none", "asked": []}
            if followup.get("status") != "failed":
                return {"path": item["path"], "facts_hash": item["facts_hash"], "claims": item["cached_claims"], "followup": followup}
            claims, followup, calls = self._follow_up(item, item["cached_claims"], followup.get("asked") or [])
            return {"path": item["path"], "facts_hash": item["facts_hash"], "claims": claims, "followup": followup, "followup_calls": calls}
        prompt = item["template"].format(project_name=item["project_name"], file_path=item["path"], source=item["content"], focus_note="")
        emit("LLM_CALL_EXTRACT_FACTS", name=item["path"])
        log_token_estimation(self.__class__.__name__, prompt, item["max_tokens"])
        response = call_llm(
            prompt, use_cache=(item["use_cache"] and self.cur_retry == 0), thinking_level=item["thinking_level"], step="extract_facts"
        )
        claims = parse_facts_response(response)
        checked = verify_file_claims(claims, item["content"])
        emit_raw("DEBUG", f"FACTS | {item['path']} | claimed={checked['claimed']} | found={checked['found']}", dest="LOG")
        if self.cur_retry == 0:
            self.best.pop(item["path"], None)
        best = self.best.get(item["path"])
        if best is None or checked["found"] > best[0]:
            self.best[item["path"]] = best = (checked["found"], claims)
        # Mostly unfindable quotes mean the model paraphrased: retry uncached, then keep the best attempt's
        # verified part rather than losing the module
        if checked["claimed"] >= 4 and checked["found"] * 2 < checked["claimed"] and self.cur_retry < self.max_retries - 1:
            emit("FACTS_LOW_COVERAGE", name=item["path"], found=checked["found"], claimed=checked["claimed"])
            raise ValueError(f"only {checked['found']}/{checked['claimed']} claims found in the source")
        claims, followup, calls = self._follow_up(item, best[1])
        return {"path": item["path"], "facts_hash": item["facts_hash"], "claims": claims, "followup": followup, "followup_calls": calls}

    The method tracks the highest-coverage extraction attempt in self.best across retries. If the ratio of verifiable claims to total claims is low, it forces an uncached retry to correct model hallucinations. Once an acceptable extraction is obtained, it enters _follow_up() to gather claims on any declarations or imports that were missed during the primary pass.

    ExtractFacts.exec_fallback()

    Visibility: Public

    Signature: def exec_fallback(self, item, exc):

    Description: Fallback handler invoked when all retries for an item are exhausted. Preserves the best partially verified extraction attempt achieved during earlier retries, stripping the facts_hash so subsequent runs re-attempt extraction while allowing the current workflow to proceed.

    Parameters:

    • item (dict): The batch work item that failed execution.
    • exc (Exception): The exception that triggered the fallback.

    Returns:

    • dict: Fallback fact payload preserving the best available claims or returning None.

    Raises:

    • None.

    Example:

        def exec_fallback(self, item, exc):
        """The best earlier attempt if one parsed; else no facts for this module this run (no hash, so the
        next run retries it). The flow goes on either way."""
        emit("WARN_FACTS_FALLBACK", name=item["path"], error=exc)
        if item.get("kind") == "manifest":
            return {"kind": "manifest", "path": item["path"], "facts_hash": None, "claims": None}
        best = self.best.get(item["path"])
        if best is not None:  # no follow-up ran: the next run asks it
            return {"path": item["path"], "facts_hash": item["facts_hash"], "claims": best[1], "followup": {"status": "failed", "asked": []}}
        return {"path": item["path"], "facts_hash": None, "claims": None}

    This method implements fault isolation, preventing a single malformed or paraphrased module from aborting the pipeline. If self.best contains a valid parsing pass from an earlier attempt, those claims are salvaged and tagged with "status": "failed" in the follow-up metadata. If no parsing attempt succeeded, claims evaluate to None, bypassing fact grounding for that file without terminating the run.

    ExtractFacts.post()

    Visibility: Public

    Signature: def post(self, shared, prep_res, exec_res_list):

    Description: Consolidates manifest and source extractions, performs cross-module symbol and dependency verification via ModuleTable and verify_dependencies, constructs the final facts.json ground truth document, and stores results in shared["module_facts"].

    Parameters:

    • shared (dict): Central shared pipeline dictionary.
    • prep_res (list): Original list of prepared work items.
    • exec_res_list (list): List of completed execution payloads.

    Returns:

    • str: Fixed routing action "default".

    Raises:

    • None.

    Example:

        def post(self, shared, prep_res, exec_res_list):
        manifest_results = [res for res in exec_res_list if res.get("kind") == "manifest"]
        exec_res_list = [res for res in exec_res_list if res.get("kind") != "manifest"]
        manifest_texts = {item["path"]: item["content"] for item in prep_res if item.get("kind") == "manifest"}
        manifests = {
            res["path"]: {
                **verify_manifest_claims(res["claims"], manifest_texts[res["path"]], res["path"]),
                "facts_hash": res["facts_hash"],
                "claims": res["claims"],
            }
            for res in manifest_results
            if res["claims"] is not None
        }
        contents = {item["path"]: item["content"] for item in prep_res if item.get("kind") != "manifest"}
        checked = {res["path"]: verify_file_claims(res["claims"], contents[res["path"]]) for res in exec_res_list if res["claims"] is not None}
        table = ModuleTable(list(contents), {path: result["symbols"] for path, result in checked.items()}, contents, manifests)
        resolved = verify_dependencies({path: result["dependencies"] for path, result in checked.items()}, contents, table)
        # ... modules dictionary assembly and dependency inversion ...
        save_facts(self.facts_file, build_facts_document(shared["project_name"], source_commit(shared.get("local_dir")), modules, manifests))
        shared["module_facts"] = modules
        # ... telemetry emission ...
        emit_step_subtotals("extract_facts")
        return "default"

    The post-processing method splits manifest and module execution payloads, feeding verified symbols and declared package structures into ModuleTable. Import claims undergo resolution against the module table to establish cross-module depends_on links, which are then inverted to populate reciprocal used_by relationships. The resulting ground-truth graph is serialized atomically to disk via save_facts() and made accessible to chapter writers via shared["module_facts"].

    ContextRouter

    Visibility: Public

    Signature: class ContextRouter(Node):

    Description: The architectural routing node that inspects codebase size against LLM context boundaries. It calculates prompt template token consumption, directory layout overhead, and source file volumes, routing execution down "deterministic", "direct", or "batch" pipelines.

    ContextRouter.prep()

    Visibility: Public

    Signature: def prep(self, shared):

    Description: Evaluates total file content tokens against calculated safety budgets. In api-reference mode, it short-circuits directly to "deterministic". Otherwise, it scans prompt templates to identify maximum prompt overhead, calculates batch-encoded file tokens, and returns routing decisions.

    Parameters:

    • shared (dict): Central shared pipeline dictionary containing "files", "mode", and token configurations.

    Returns:

    • tuple: 7-tuple containing (route, files_data, effective_limit, batch_size, file_token_map, count_tokens_func, directory_tree).

    Raises:

    • None.

    Example:

        def prep(self, shared):
        files_data = shared["files"]
        max_tokens = resolve_max_tokens(shared)

        shared["max_tokens"] = max_tokens
        directory_tree = build_directory_tree(files_data)

        if shared.get("mode", "tutorial") == "api-reference":
            # One chapter per file, one page call each: no routing budget is needed.
            emit("CAPACITY_API_REF_MODE")
            return ("deterministic", files_data, 0, shared.get("batch_size", 50), None, None, directory_tree)

        # --- Calculate prompt overhead FIRST ---

    Parameters:

        def exec(self, prep_res):

        # ... debug telemetry ...
        if route == "direct":
            return "direct"
        if route == "deterministic":
            return "deterministic"

        # Group by directory for coherence, with pre-computed tokens
        dir_groups = defaultdict(list)
        for i, (path, content) in enumerate(files_data):
            dir_groups[os.path.dirname(path)].append((i, path, content, file_token_map[i]))

        # Build token-aware batches (never mix directories)
        batches = []
        for dirname in sorted(dir_groups.keys()):
            current_batch = []
            current_tokens = 0

            for i, path, content, tokens in dir_groups[dirname]:
                # Start new batch if adding this file would exceed effective limit or file count cap
                if current_batch and (current_tokens + tokens > effective_limit or len(current_batch) >= batch_size):
                    batches.append(current_batch)
                    current_batch = []
                    current_tokens = 0

                current_batch.append((i, path, content))
                current_tokens += tokens

            if current_batch:
                batches.append(current_batch)
        return batches

As it iterates through lexicographically sorted directory groups, it tracks token accumulation using precomputed token maps (file_token_map).     Visibility: Private

    Signature: def _follow_up(self, item, claims, asked=()):

    Description: Executes targeted follow-up query rounds for source code lines identified as declaration-like or import-like that were missed during the primary extraction pass.

    Parameters:

    • item (dict): The active module work item.
    • claims (dict): Claims accumulated so far for the module.

    Example:

        def _follow_up(self, item, claims, asked=()):
        asked, calls, lines = list(asked), 0, split_lines(item["content"])
        for _round in range(self.FOLLOWUP_ROUNDS):
            hints = completeness_hints(item["content"], verify_file_claims(claims, item["content"]), claims)
            already = set(asked)
            pending = [number for number in hints["uncovered"] if number not in already]
            if not pending:
                break
            note = build_facts_focus_note([(number, lines[number - 1]) for number in pending])
            prompt = item["template"].format(project_name=item["project_name"], file_path=item["path"], source=item["content"], focus_note=note)
            emit("FACTS_FOLLOWUP", name=item["path"], count=len(pending))
            log_token_estimation(self.__class__.__name__, prompt, item["max_tokens"])
            answer = None
            for attempt in range(2):
                calls += 1
                try:
                    response = call_llm(
                        prompt,
                        use_cache=(item["use_cache"] and self.cur_retry == 0 and attempt == 0),
                        thinking_level=item["thinking_level"],
                        step="extract_facts",
                    )
                    answer = parse_facts_response(response)
                    break
                except Exception as e:
                    emit_raw("WARNING", f"FACTS FOLLOW-UP FAILED | {item['path']} | attempt {attempt + 1} | {e}", dest="LOG")

                return claims, {"status": "failed", "asked": asked}, calls
            claims = merge_claims(claims, answer)
            asked += pending[:FACTS_FOCUS_LIMIT]
        return claims, {"status": "done" if asked else "none", "asked": asked}, calls

    The method runs up to FOLLOWUP_ROUNDS (3) iterations, querying completeness_hints on each round to detect uncovered declaration or import lines. Unexamined lines are formatted into a focused prompt note using build_facts_focus_note (capped at FACTS_FOCUS_LIMIT per request). Each follow-up response is merged into the existing claims via merge_claims(). If a follow-up query fails, the existing claims are retained and the status is marked as "failed" to prompt a re-check on the next incremental run.

    Error Handling

    The module implements the following error handling and recovery patterns:

    1. Central Execution Shield (safe_exec): All public exec() methods are wrapped with @safe_exec. When an exception occurs, the decorator logs the class name, error message, and full stack traceback to the destination log file (dest="LOG") and emits a NODE_RETRY_ERROR telemetry event before re-raising. This ensures failures are recorded consistently while allowing PocketFlow's retry engine to manage backoff.

    2. Low Factual Coverage Detection: In ExtractFacts.exec(), extractions are verified against the source code via verify_file_claims. If a model returns 4 or more claims but fewer than 50% can be verified against the physical source lines (checked["found"] * 2 < checked["claimed"]), the method emits FACTS_LOW_COVERAGE and raises a ValueError. This triggers an uncached retry to correct paraphrased or hallucinated quotes.

    3. Batch Fault Isolation (exec_fallback): Both ExtractFacts and WriteChapters implement exec_fallback(). When an individual batch item exhausts all retry attempts:

    4. ExtractFacts checks self.best and returns the highest-coverage attempt parsed during earlier retries, or falls back to an empty record with facts_hash: None.

    5. WriteChapters emits WARN_CHAPTER_FALLBACK, appends a placeholder summary to self.chapter_summaries to maintain index alignment, and returns a placeholder chapter with hash: None.

    6. Atomic File Serialization: Incremental cache manifests (.doc_cache_manifest.json) and verified facts documents (facts.json) are serialized using atomic writes. Content is written to a .tmp sibling file before executing os.replace, ensuring abrupt terminations do not leave corrupted JSON files on disk.

    7. Defensive Schema and Index Validation: Every node that parses LLM responses validates the output against expected types and ranges. parse_yaml_response is coupled with type checks (isinstance(..., list), isinstance(..., dict)). File index references are parsed using regular expressions and bounds-checked against [0, len(files)). Out-of-bounds indices are discarded with descriptive warnings (WARN_INVALID_RELATIONSHIP, WARN_PARSE_INDEX), preventing IndexError exceptions during downstream lookups.
