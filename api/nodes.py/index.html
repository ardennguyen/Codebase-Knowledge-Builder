    Technical Overview

    The nodes.py module defines the concrete processing nodes and execution lifecycle logic that power the Codebase-Knowledge-Builder documentation pipeline. Built upon the pocketflow framework's Node and BatchNode abstractions, this module houses the computational, analytical, and generative engines responsible for converting raw source code repositories into navigable, fact-verified, structured Markdown documentation suites. The module handles ingestion, context-window budget planning, abstraction decomposition, architectural relationship discovery, topological chapter ordering, AST-grounded factual extraction, incremental chapter drafting, and static site synthesis.

    Architecturally, execution bifurcates into two distinct operating pathways managed by routing logic: 1. Dynamic Heuristic Pathway: Used for narrative modes (tutorial, advanced, and sdk). Repositories are evaluated by ContextRouter against context token limits. Codebases fitting within model context windows follow a single-pass extraction through IdentifyAbstractions, while larger codebases are batched across directory boundaries via MapAbstractions and unified through ReduceAbstractions. Dependencies are inferred by AnalyzeRelationships, sequenced by OrderChapters, drafted sequentially via WriteChapters with rolling context summarization, and compiled by CombineTutorial. 2. Deterministic Ground-Truth Pathway: Used for the api-reference mode. In this mode, DeterministicFileMapper maps every non-empty source file directly to a single chapter page without semantic abstraction grouping, sorting pages by directory depth to document leaf dependencies before orchestrators. Parallel static and LLM verification is executed by ExtractFacts, which validates symbol signatures, line boundaries, and cross-module dependencies against physical source files using utils.facts. These verified claims are injected into WriteChapters prompts to prevent hallucination.

    safe_exec()

    Visibility: Public Signature: def safe_exec(func):

    Description: A function decorator designed to wrap the exec lifecycle method of any Node or BatchNode subclass with unified error handling, diagnostic telemetry emission, and exception re-raising. When an exception escapes the decorated execution method, safe_exec intercepts the error, emits a localized "NODE_RETRY_ERROR" UI event specifying the calling node's class name and error message, writes a full stack trace to the persistent log file under the "ERROR" severity channel, and re-raises the caught exception. This allows upstream PocketFlow retry policies to trigger without repeating logging boilerplate across every node.

    Parameters: * func (callable): The node execution method (exec or exec_fallback) to wrap.

    Returns: * callable: The wrapped execution function preserving original signature and metadata via functools.wraps.

    Raises: * Exception: Re-raises any exception thrown by the underlying wrapped method after logging.

def exec(self, prep_res):
    prompt, use_cache, thinking_level, max_tokens = prep_res
    emit("LLM_CALL_FILTER_FILES")
    log_token_estimation(self.__class__.__name__, prompt, max_tokens)
    response = call_llm(prompt, use_cache=(use_cache and self.cur_retry == 0), thinking_level=thinking_level, step="filter_files")
    parsed = parse_yaml_response(response)

    Visibility: Public Signature: def emit_step_subtotals(*steps: str) -> None:

    Description: Diagnostic utility function invoked inside BatchNode.post() methods to query the runtime usage ledger in utils.llm_common and emit intermediate token consumption and financial subtotal metrics for specified pipeline operational steps. It iterates through the provided step labels, cross-references them with the snapshot returned by get_step_summary(), and formats console and log outputs via emit_step_usage.

    for step in steps:
        if step in summary:
            emit_step_usage("LLM_STEP_SUBTOTAL", step, summary[step])

    DeterministicFileMapper

    Visibility: Public Signature: class DeterministicFileMapper(Node):

    Description: A deterministic routing and mapping node used exclusively in api-reference mode. Instead of using LLM heuristics to cluster multiple source files into conceptual abstractions, this node establishes a 1:1 mapping between each project source file and a dedicated documentation chapter. It invokes an LLM to distinguish functional source code files from package manifests and build artifacts, filters empty or whitespace-only files, records manifests in shared state, and establishes an optimal documentation order based on directory nesting depth.

    DeterministicFileMapper.prep()

    Visibility: Public Signature: def prep(self, shared):

    Description: Extracts the codebase files and project name from the shared store, constructs a numbered file catalog excluding empty and whitespace-only files, builds a file-filtering prompt via build_code_file_filter_prompt, resolves the reasoning thinking level for "filter_files", and returns the execution parameters.

    Parameters: * shared (dict): Shared pipeline state dictionary containing "files", "project_name", "use_cache", and "max_tokens".

    Returns: * tuple: A 4-element tuple containing (prompt, use_cache, thinking_level, max_tokens).

    Example: 

    def prep(self, shared):
    files_data = shared["files"]
    project_name = shared["project_name"]

    # Empty/whitespace-only files (e.g. bare __init__.py) are left out: post() skips unlisted indices,
    # so they are never documented instead of flipping in and out with the LLM's answer.
    file_listing = "\n".join([f"{i} # {path}" for i, (path, content) in enumerate(files_data) if content.strip()])

    prompt = build_code_file_filter_prompt(project_name, file_listing)
    emit_raw("DEBUG", f"DeterministicFileMapper prep | {len(files_data)} candidate files for filtering", dest="LOG")
    return prompt, shared.get("use_cache", True), resolve_thinking_level(shared, "filter_files"), shared.get("max_tokens", 100000)

    DeterministicFileMapper.exec()

    Visibility: Public Signature: def exec(self, prep_res):

    Description: Dispatches the classification prompt to the LLM via call_llm to categorize project files into valid code modules and build/package manifests. Parses the returned YAML mapping using parse_yaml_response and expands ranges or composite index strings into discrete integer lists via parse_file_indices. Wrapped by @safe_exec.

    Parameters: * prep_res (tuple): The 4-element tuple returned by prep().

    Returns: * tuple[list[int], list[int]]: A tuple containing (indices, manifest_indices) representing validated code files and manifest files.

    Example: 

    @safe_exec
def exec(self, prep_res):
    prompt, use_cache, thinking_level, max_tokens = prep_res
    emit("LLM_CALL_FILTER_FILES")
    log_token_estimation(self.__class__.__name__, prompt, max_tokens)
    response = call_llm(prompt, use_cache=(use_cache and self.cur_retry == 0), thinking_level=thinking_level, step="filter_files")
    parsed = parse_yaml_response(response)
    # {code: [...], manifests: [...]}; a bare list (older reply shape) is the code list
    code = parsed.get("code") if isinstance(parsed, dict) else parsed
    manifests = parsed.get("manifests") if isinstance(parsed, dict) else []
    indices = [idx for entry in (code if isinstance(code, list) else []) for idx in parse_file_indices(entry)]
    manifest_indices = [idx for entry in (manifests if isinstance(manifests, list) else []) for idx in parse_file_indices(entry)]
    return indices, manifest_indices

    DeterministicFileMapper.post()

    Visibility: Public Signature: def post(self, shared, prep_res, exec_res):

    Description: Ingests the classified file indices, discards indices for empty files or non-code assets, and registers valid manifest files under shared["manifest_files"]. For every valid code file, it instantiates an abstraction dictionary with the file's basename as its title and its POSIX path as original_path. Crucially, it sets shared["chapter_order"] by sorting chapters by descending directory depth (deepest subdirectories first, then alphabetically). This bottom-up ordering guarantees that leaf modules and utilities are analyzed and summarized before root-level orchestrators, providing rolling context for downstream chapter drafting.

    Parameters: * shared (dict): Shared pipeline state dictionary. * prep_res (tuple): Output of prep(). * exec_res (tuple): Output of exec().

    Returns: * str: The string action "default".

    Example: 

    def post(self, shared, prep_res, exec_res):
    files = shared.get("files", [])
    code_indices, manifest_indices = exec_res
    valid_indices = set(code_indices)
    shared["manifest_files"] = sorted(
        {idx for idx in manifest_indices if 0 <= idx < len(files) and idx not in valid_indices and files[idx][1].strip()}
    )
    modules = []
    chapter_order = []
    # ...
    shared["abstractions"] = modules
    shared["chapter_order"] = sorted(
        chapter_order,
        key=lambda idx: (
            -modules[idx]["original_path"].count("/") - modules[idx]["original_path"].count(os.sep),
            modules[idx]["original_path"].lower(),
        ),
    )
    shared["relationships"] = {"summary": "Deterministic Internal API Reference.", "details": []}
    emit("DONE_DETERMINISTIC_MAPPER", count=len(modules))
    return "default"

    ExtractFacts

    Visibility: Public Signature: class ExtractFacts(BatchNode):

    Description: A parallel, AST-informed verification batch node operating in api-reference mode. For each module and package manifest identified by DeterministicFileMapper, this node extracts physical codebase ground truth—including declared symbols, function signatures, configuration keys, raised/caught exceptions, and cross-module import dependencies. It cross-examines LLM extraction claims against actual source code lines using utils.facts.verify_file_claims, initiates recursive follow-up passes for uncovered lines, validates cross-file import paths using ModuleTable, and compiles an atomic facts.json artifact.

    ExtractFacts.FOLLOWUP_ROUNDS

    Visibility: Public Signature: FOLLOWUP_ROUNDS = 3 # follow-up calls per module at most, each on FACTS_FOCUS_LIMIT lines not asked before

    Description: Class-level integer constant defining the maximum number of iterative follow-up query rounds executed per module to extract claims from lines missed during initial extraction.

Computes a deterministic configuration signature incorporating provider, model name, reasoning effort level, and prompt template MD5 hash. Resolves previous facts from disk using load_facts when --incremental or caching is active. For each file, computes its content-specific facts_hash via utils.facts.facts_hash. If a cache hit occurs, previously validated claims and follow-up states are attached to bypass redundant LLM extraction.

    Parameters: * shared (dict): Shared pipeline state dictionary.

    Returns: * list[dict]: A collection of item configuration dictionaries prepared for batch execution.

    ExtractFacts.exec()

    Visibility: Public Signature: def exec(self, item):

    Description: Executes factual claim extraction for a single module item or delegates to _exec_manifest if item["kind"] == "manifest". If cached claims are present and their follow-up state did not fail, the cached record is returned immediately. Otherwise, it formats the prompt template with full source code, queries the LLM, parses claims via parse_facts_response, and checks them against source text using verify_file_claims.

    The execution process follows distinct validation and retry phases: 1. Cache Validation: Reuses valid previous claims or executes follow-ups on previously failed incomplete extractions. 2. LLM Extraction & Verification: Submits un-cached modules to the LLM and runs verify_file_claims to check that claimed quote strings match source text. 3. Coverage Guard & Paraphrase Rejection: Tracks the highest claim count in self.best. If a response contains 4 or more claims but fewer than 50% can be verified in the source text, it indicates LLM hallucination or paraphrasing; the node emits "FACTS_LOW_COVERAGE" and raises a ValueError to trigger an uncached retry under PocketFlow. 4. Targeted Follow-up: Calls _follow_up on the best claims to discover symbols or imports on previously missed lines.

    Parameters: * item (dict): Module extraction task descriptor from prep().

    Returns: * dict: Module verification result containing path, facts hash, verified claims, follow-up metadata, and call counts.

    Raises: * ValueError: Raised when verified claim coverage falls below 50% across 4+ claims during initial attempts.

    Example: 

    @safe_exec
def exec(self, item):
    if item.get("kind") == "manifest":
        return self._exec_manifest(item)
    if item["cached_claims"] is not None:
        emit("FACTS_CACHE_HIT", name=item["path"])
        followup = item["cached_followup"] if isinstance(item["cached_followup"], dict) else {"status": "none", "asked": []}
        if followup.get("status") != "failed":
            return {"path": item["path"], "facts_hash": item["facts_hash"], "claims": item["cached_claims"], "followup": followup}
        claims, followup, calls = self._follow_up(item, item["cached_claims"], followup.get("asked") or [])
        return {"path": item["path"], "facts_hash": item["facts_hash"], "claims": claims, "followup": followup, "followup_calls": calls}
    # ...

    ExtractFacts.exec_fallback()

    Visibility: Public Signature: def exec_fallback(self, item, exc):

    Description: Fail-soft fallback method invoked by PocketFlow when all retry attempts for a module fail. If an earlier attempt successfully parsed and verified a subset of claims, exec_fallback recovers that best attempt from self.best, marking its follow-up status as "failed" so subsequent incremental runs can re-extract missing lines. If no claims were ever verified, it returns empty claim fields without a facts_hash, preventing unverified data from entering the cache while allowing the overall documentation pipeline to continue.

    Parameters: * item (dict): The task payload that failed execution. * exc (Exception): The exception that triggered the failure.

    Returns: * dict: Fallback extraction structure with partial or empty claims.

    Example: 

    def exec_fallback(self, item, exc):
    """The best earlier attempt if one parsed; else no facts for this module this run (no hash, so the
    next run retries it). The flow goes on either way."""
    emit("WARN_FACTS_FALLBACK", name=item["path"], error=exc)
    if item.get("kind") == "manifest":
        return {"kind": "manifest", "path": item["path"], "facts_hash": None, "claims": None}
    best = self.best.get(item["path"])
    if best is not None:  # no follow-up ran: the next run asks it
        return {"path": item["path"], "facts_hash": item["facts_hash"], "claims": best[1], "followup": {"status": "failed", "asked": []}}
    return {"path": item["path"], "facts_hash": None, "claims": None}

    Visibility: Public Signature: def post(self, shared, prep_res, exec_res_list):

    # ...

    ContextRouter

    Visibility: Public Signature: class ContextRouter(Node):

    Description: The context capacity and branching orchestrator of the pipeline. It evaluates the total token volume of the ingested codebase against model context limits, reasoning reserves, and prompt template overhead. Based on these measurements, it routes the workflow along one of three pathways: * "deterministic": Automatically selected when shared["mode"] == "api-reference". * "direct": Selected when the entire codebase fits comfortably within the effective token budget, delegating to IdentifyAbstractions. * "batch": Selected when codebase tokens exceed the effective limit or when --force-batch is specified, organizing files into directory-aligned batches for MapAbstractions.

    ContextRouter.prep()

    Visibility: Public Signature: def prep(self, shared):

    Description: Evaluates token capacity and establishes routing limits through three distinct operations: 1. Mode Check: If shared["mode"] == "api-reference", returns "deterministic" immediately without spending tokens calculating capacity. 2. Overhead Calculation: Computes worst-case template token overhead across all prompt files in prompts/, measures directory tree token size, and estimates the chapter listing token load. 3. Budget Partitioning: Measures token counts for all source files in parallel via count_tokens_many. Calculates safe input headroom by subtracting reasoning reserves (for IdentifyAbstractions or MapAbstractions) and fixed prompt overhead from resolve_max_tokens(shared). Returns a decision tuple indicating whether the repository fits within direct limits or requires batching.

    Parameters: * shared (dict): Shared pipeline state dictionary.

    Returns: * tuple: Route configuration tuple containing route name, files list, effective limit, batch size, pre-calculated token map, token counter reference, and formatted directory tree.

    Example: 

    def prep(self, shared):
    files_data = shared["files"]
    max_tokens = resolve_max_tokens(shared)
    shared["max_tokens"] = max_tokens
    directory_tree = build_directory_tree(files_data)

    if shared.get("mode", "tutorial") == "api-reference":
        emit("CAPACITY_API_REF_MODE")
        return ("deterministic", files_data, 0, shared.get("batch_size", 50), None, None, directory_tree)
    # ...
    total_tokens = sum(file_token_map)
    safety_limit = min(
        input_token_budget(max_tokens, resolve_thinking_level(shared, "identify_abstractions")),
        input_token_budget(max_tokens, resolve_thinking_level(shared, "map_abstractions")),
    )
    effective_limit = safety_limit - prompt_overhead
    # ...

    ContextRouter.exec()

    Visibility: Public Signature: def exec(self, prep_res):

    Description: Implements the routing decision. If the route is "direct" or "deterministic", it returns the string route name immediately. If the route is "batch", it groups files by parent directory using a defaultdict(list) and packs files into discrete sub-batches. Files from different directories are never mixed in a single batch to preserve cohesive module context. Sub-batches are split whenever adding a file would exceed effective_limit or batch_size.

    Parameters: * prep_res (tuple): The routing parameter tuple prepared by prep().

    Returns: * str | list[list[tuple[int, str, str]]]: Returns the string "direct" or "deterministic", or a list of file batches where each batch contains (index, path, content) tuples.

    Example: 

    def exec(self, prep_res):
    route, files_data, effective_limit, batch_size, file_token_map, _count_tokens, _directory_tree = prep_res
    if route == "direct":
        return "direct"
    if route == "deterministic":
        return "deterministic"

    # Group by directory for coherence, with pre-computed tokens
    dir_groups = defaultdict(list)
    for i, (path, content) in enumerate(files_data):
        dir_groups[os.path.dirname(path)].append((i, path, content, file_token_map[i]))

    batches = []
    for dirname in sorted(dir_groups.keys()):
        current_batch = []
        current_tokens = 0
        for i, path, content, tokens in dir_groups[dirname]:
            if current_batch and (current_tokens + tokens > effective_limit or len(current_batch) >= batch_size):
                batches.append(current_batch)
                current_batch = []
                current_tokens = 0
            current_batch.append((i, path, content))
            current_tokens += tokens
        if current_batch:
            batches.append(current_batch)
    return batches

    ContextRouter.post()

    Visibility: Public Signature: def post(self, shared, prep_res, exec_res):

    Description: Persists the directory tree generated during prep() into shared["directory_tree"] so subsequent nodes (WriteChapters, CombineTutorial) can reference global repository topology. If batch routing was executed, it stores the packed batches in shared["file_batches"] and returns "batch". Otherwise, it returns the string action ("direct" or "deterministic") to control downstream edge traversal in the PocketFlow DAG.

    Parameters: * shared (dict): Shared pipeline state dictionary. * prep_res (tuple): Output of prep(). * exec_res (str | list): Output of exec().

    Returns: * str: Action string ("direct", "deterministic", or "batch").

    Example: 

    def post(self, shared, prep_res, exec_res):
    emit_raw("DEBUG", f"ContextRouter post | route={'batch' if isinstance(exec_res, list) else exec_res}", dest="LOG")
    shared["directory_tree"] = prep_res[-1]
    if exec_res == "direct":
        return "direct"
    if exec_res == "deterministic":
        return "deterministic"

    Error Handling

    nodes.py uses defensive validation and fault-tolerant execution patterns to prevent individual LLM failures or malformed outputs from halting the entire documentation process:

    • Decorator-Driven Logging & Retries (safe_exec): All critical exec methods are wrapped by @safe_exec. When an unhandled error occurs, it emits "NODE_RETRY_ERROR", writes the full traceback to persistent logs under "ERROR", and re-raises the exception so PocketFlow's retry policies (with exponential backoff) can retry the operation.
    • Low Coverage Rejection: In ExtractFacts.exec, if an LLM returns 4 or more claims but fewer than half match physical source lines, the engine treats this as model hallucination or paraphrasing. It emits "FACTS_LOW_COVERAGE" and raises a ValueError to trigger an uncached retry.
    • Resilient Fallback Execution (exec_fallback):
    • In ExtractFacts, if all retries fail, exec_fallback recovers the best historical attempt (the run with the highest verified claim count). If no claims were ever verified, it returns empty structures without a facts_hash, allowing downstream nodes to run while ensuring the next incremental run retries the module.
    • In WriteChapters, if chapter drafting fails across all retries, exec_fallback inserts an unavailable notice placeholder into shared["chapters"] and records a stub summary. This maintains linear chapter indexing and allows the rest of the documentation suite to compile.
    • Truncation & Manifest Invalidation: If an LLM response is tagged with truncated = True (indicating token limit cutoff via TruncatedResponse), WriteChapters retains the partial page for immediate inspection but sets current_hash = None. This excludes the truncated chapter from .doc_cache_manifest.json, guaranteeing that subsequent --incremental executions will regenerate it.
    • Atomic Manifest Updates: The incremental cache manifest is never written during intermediate node execution. Instead, CombineTutorial.post writes to a temporary file (.doc_cache_manifest.json.tmp) and swaps it into place using os.replace only after all documentation pages have been written to disk. This prevents cache poisoning if a run is aborted midway.
