    flow

    Original File Path: flow.py

    This document provides the technical API and architecture reference for flow.py. As the first module in the documentation index, flow.py defines the orchestration pipeline for the Codebase-Knowledge-Builder system using the pocketflow framework.

    Technical Overview

    flow.py serves as the central Directed Acyclic Graph (DAG) construction module for the knowledge base generation pipeline. It instantiates the processing nodes implemented in nodes and wires their execution paths using operator overloading (>> for sequential chaining and - "branch_name" >> for conditional routing).

    The pipeline supports three distinct execution strategies depending on the repository context and processing mode routed by ContextRouter: 1. Direct Path ("direct"): Used for repositories that fit comfortably within the context window of the language model. Code is processed directly by IdentifyAbstractions. 2. Map-Reduce Path ("batch"): Used for large codebases requiring chunked processing. Code files are partitioned, mapped via MapAbstractions, and aggregated through ReduceAbstractions. 3. Deterministic Path ("deterministic"): Used for deterministic 1:1 file-to-page documentation pipelines without LLM abstraction discovery, bypassing abstraction identification to map files directly via DeterministicFileMapper.

    All three execution branches converge on chapter generation (WriteChapters) and final document compilation (CombineTutorial). LLM-dependent nodes are configured with standardized retry policies (max_retries=5, wait=20) to handle API rate limiting and transient network errors gracefully.

    Module-Level Functions

    create_tutorial_flow()

    Visibility: Public
    Signature: def create_tutorial_flow()

    Description:
    Constructs and configures the pocketflow.Flow instance that governs the repository processing lifecycle. This function initializes all ten pipeline node classes, configures retry/backoff parameters for LLM-backed nodes, connects sequential and conditional graph edges, and sets FetchRepo as the root entry point.

    Parameters:
    * None.

    Returns:
    * Flow: An initialized pocketflow.Flow execution graph instance ready to be run with a shared context dictionary.

    Raises:
    * None directly raised during definition; node initialization exceptions may propagate if node constructors fail.

    Example: 

    def create_tutorial_flow():
    fetch_repo = FetchRepo()
    context_router = ContextRouter()
    map_abstractions = MapAbstractions(max_retries=5, wait=20)
    reduce_abstractions = ReduceAbstractions(max_retries=5, wait=20)
    identify_abstractions = IdentifyAbstractions(max_retries=5, wait=20)
    analyze_relationships = AnalyzeRelationships(max_retries=5, wait=20)
    order_chapters = OrderChapters(max_retries=5, wait=20)
    write_chapters = WriteChapters(max_retries=5, wait=20)
    combine_tutorial = CombineTutorial()
    deterministic_mapper = DeterministicFileMapper(max_retries=5, wait=20)

    fetch_repo >> context_router

    context_router - "direct" >> identify_abstractions
    context_router - "batch" >> map_abstractions
    context_router - "deterministic" >> deterministic_mapper

    map_abstractions >> reduce_abstractions

    identify_abstractions >> analyze_relationships
    reduce_abstractions >> analyze_relationships

    analyze_relationships >> order_chapters
    order_chapters >> write_chapters

    deterministic_mapper >> write_chapters

    write_chapters >> combine_tutorial

    return Flow(start=fetch_repo)

    The create_tutorial_flow function builds the complete execution topology by linking instances of nodes derived from pocketflow.Node and pocketflow.BatchNode. Nodes that invoke external language model APIs (MapAbstractions, ReduceAbstractions, IdentifyAbstractions, AnalyzeRelationships, OrderChapters, WriteChapters, and DeterministicFileMapper) are instantiated with max_retries=5 and wait=20. This configuration ensures that transient HTTP failures or rate limits (such as 429 Too Many Requests) encountered during LLM inference automatically pause for 20 seconds before retrying, up to a maximum of 5 attempts.

    The routing logic relies on the transition actions emitted by ContextRouter.post(). If the router returns "direct", execution flows into IdentifyAbstractions to extract high-level architectural concepts in a single prompt. If it returns "batch", execution flows through MapAbstractions (processing chunks in parallel or batches) and then ReduceAbstractions (consolidating partial concepts). If it returns "deterministic", the flow bypasses abstraction generation and routes directly to DeterministicFileMapper. Both abstraction paths converge at AnalyzeRelationships before proceeding to OrderChapters and WriteChapters. The deterministic branch links directly from DeterministicFileMapper to WriteChapters, bypassing relationship analysis and chapter ordering. Finally, WriteChapters transitions into CombineTutorial to compile the generated Markdown files.
