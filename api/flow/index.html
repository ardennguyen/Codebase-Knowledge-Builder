    flow

    Source File: flow.py

    The flow.py module defines the core execution graph and workflow topology for the Codebase Knowledge Builder pipeline. It coordinates how repositories are ingested, how codebase contexts are routed across different processing strategies, and how educational chapter tutorials are synthesized, structured, and compiled into finalized Markdown documentation.

    The module constructs a directed execution flow using the pocketflow orchestration framework, interconnecting modular processing units defined in nodes.

    Architectural Overview

    The workflow returned by flow.py provides three distinct processing routes configured dynamically by repository characteristics and token budgets:

    1. Direct Path ("direct"): Used when the codebase fits within a standard prompt window, routing directly to abstraction identification.
    2. Batch Path ("batch"): Employs a Map-Reduce pipeline (MapAbstractions followed by ReduceAbstractions) to partition large codebases across multiple context windows before merging abstraction representations.
    3. Deterministic Path ("deterministic"): Bypasses dynamic abstraction clustering entirely, mapping individual source files directly into a 1:1 chapter layout (DeterministicFileMapper) before chapter generation.

    All routes converge into chapter generation (WriteChapters) and final tutorial compilation (CombineTutorial).

    Module-Level Functions

    create_tutorial_flow()

    Visibility: Public
    Signature: def create_tutorial_flow() -> Flow:

    Description:
    Instantiates, configures, and links all processing nodes to produce the end-to-end tutorial generation pipeline. Node retry policies are configured with max_retries=5 and exponential backoff parameters (wait=20) to tolerate API rate limiting and transient upstream failures when calling LLM endpoints.

    Parameters:
    None

    Returns:
    * Flow: An initialized pocketflow.Flow pipeline instance with FetchRepo designated as the root entry point.

    Raises:
    None directly raised during construction.* Execution-time exceptions are managed by individual node instances and pocketflow execution loops.

    Example: 

    def create_tutorial_flow():
    fetch_repo = FetchRepo()
    context_router = ContextRouter()
    map_abstractions = MapAbstractions(max_retries=5, wait=20)
    reduce_abstractions = ReduceAbstractions(max_retries=5, wait=20)
    identify_abstractions = IdentifyAbstractions(max_retries=5, wait=20)
    analyze_relationships = AnalyzeRelationships(max_retries=5, wait=20)
    order_chapters = OrderChapters(max_retries=5, wait=20)
    write_chapters = WriteChapters(max_retries=5, wait=20)
    combine_tutorial = CombineTutorial()
    deterministic_mapper = DeterministicFileMapper(max_retries=5, wait=20)

    fetch_repo >> context_router

    context_router - "direct" >> identify_abstractions
    context_router - "batch" >> map_abstractions
    context_router - "deterministic" >> deterministic_mapper

    map_abstractions >> reduce_abstractions

    identify_abstractions >> analyze_relationships
    reduce_abstractions >> analyze_relationships

    analyze_relationships >> order_chapters
    order_chapters >> write_chapters

    deterministic_mapper >> write_chapters

    write_chapters >> combine_tutorial

    return Flow(start=fetch_repo)

    The function instantiates eight specialized LLM-backed node instances with retry and backoff properties, along with two local control-flow nodes (FetchRepo and CombineTutorial). It establishes conditional transitions using pocketflow syntax (>> for sequential binding, - "action" >> for conditional branch targets). The resulting graph ensures that regardless of repository scale, the shared downstream synthesis nodes (WriteChapters and CombineTutorial) receive a consistent shared context payload.

    Pipeline Execution Stages

    Stage 1: Ingestion and Branch Selection

    1. FetchRepo: Ingests files from either local filesystem paths or remote GitHub repositories using utilities defined in utils.crawl_local_files and utils.crawl_github_files.
    2. ContextRouter: Inspects the total token volume and structure of the ingested repository, returning one of three action strings:
    3. "direct": Dispatched when the entire codebase fits comfortably within single-pass LLM context windows.
    4. "batch": Dispatched when token volume necessitates partitioning across chunked map-reduce passes.
    5. "deterministic": Dispatched when file-by-file chapter parity is requested.

    Stage 2: Abstraction Mapping and Relationships

    Depending on the routing action selected in Stage 1: - Direct Route: IdentifyAbstractions extracts architectural abstractions in a single pass. - Batch Route: MapAbstractions scans repository slices in parallel or sequential batches, which ReduceAbstractions then consolidates into a single unified conceptual index. - Both routes feed into AnalyzeRelationships to discover dependency relationships, followed by OrderChapters to determine optimal pedagogical sequence. - Deterministic Route: DeterministicFileMapper maps source files directly to individual chapter outlines without intermediate semantic clustering.

    Stage 3: Chapter Synthesis and Compilation

    1. WriteChapters: Consumes the chapter outlines (from either OrderChapters or DeterministicFileMapper) and concurrently prompts the model to generate detailed Markdown chapters incorporating code snippets, diagrams, and deep technical prose.
    2. CombineTutorial: Aggregates all completed chapter outputs, builds a table of contents, resolves cross-chapter index links, and writes the complete document structure to disk.
