    flow

    File Path: flow.py

    Overview

    The flow.py module defines the core execution graph and orchestration logic for the Codebase-Knowledge-Builder system. Built on top of the pocketflow framework, this module is responsible for instantiating the individual pipeline nodes, configuring their operational retry and backoff parameters, and defining the conditional and linear execution edges that govern repository processing and tutorial generation.

    The flow models three distinct processing strategies based on repository context size and structure: 1. Direct Path (direct): Bypasses abstraction chunking for smaller codebases by feeding repository context directly into abstraction identification. 2. Batch Path (batch): Employs map-reduce abstraction extraction for large codebases requiring parallel or batched decomposition. 3. Deterministic Path (deterministic): Uses a direct deterministic file mapping pipeline that maps repository source files to tutorial chapters, bypassing relationship analysis and chapter ordering.

    All paths ultimately converge to produce chapter content and combine them into a unified tutorial artifact.

    Module-Level Functions

    create_tutorial_flow()

    Visibility: Public
    Signature: def create_tutorial_flow() -> Flow:

    Description:
    Initializes all node instances required for repository analysis and tutorial generation, injects retry and wait configurations for LLM-backed nodes, connects the nodes into an executable directed acyclic graph (DAG) via PocketFlow stream redirection (>>) and conditional branching (- "action" >>) operators, and encapsulates the graph into a runnable Flow object initialized at FetchRepo.

    The function configures nodes with a standard fault-tolerance profile (max_retries=5, wait=20) to handle API rate limiting and transient network errors during LLM operations. It sets up conditional routing from ContextRouter across three distinct edges (direct, batch, and deterministic) and links downstream aggregation and write stages to converge at CombineTutorial.

    Parameters:
    None

    Returns: * Flow: An instantiated pocketflow.Flow execution graph configured with FetchRepo as its root entry point.

    Raises: * No explicit exceptions raised internally during graph construction.

    Implementation:

    def create_tutorial_flow():
    fetch_repo = FetchRepo()
    context_router = ContextRouter()
    map_abstractions = MapAbstractions(max_retries=5, wait=20)
    reduce_abstractions = ReduceAbstractions(max_retries=5, wait=20)
    identify_abstractions = IdentifyAbstractions(max_retries=5, wait=20)
    analyze_relationships = AnalyzeRelationships(max_retries=5, wait=20)
    order_chapters = OrderChapters(max_retries=5, wait=20)
    write_chapters = WriteChapters(max_retries=5, wait=20)
    combine_tutorial = CombineTutorial()
    deterministic_mapper = DeterministicFileMapper(max_retries=5, wait=20)

    fetch_repo >> context_router

    context_router - "direct" >> identify_abstractions
    context_router - "batch" >> map_abstractions
    context_router - "deterministic" >> deterministic_mapper

    map_abstractions >> reduce_abstractions

    identify_abstractions >> analyze_relationships
    reduce_abstractions >> analyze_relationships

    analyze_relationships >> order_chapters
    order_chapters >> write_chapters

    deterministic_mapper >> write_chapters

    write_chapters >> combine_tutorial

    return Flow(start=fetch_repo)

    The construction sequence instantiates eight processing nodes and one routing node. Nodes performing external language model calls (MapAbstractions, ReduceAbstractions, IdentifyAbstractions, AnalyzeRelationships, OrderChapters, WriteChapters, and DeterministicFileMapper) are initialized with max_retries=5 and wait=20 to ensure stability against model provider rate limits and transient connection dropouts. In contrast, purely deterministic data preparation nodes (FetchRepo, ContextRouter, and CombineTutorial) are initialized with default parameters as they do not perform remote API calls.

    Routing rules established via the - "action" >> syntax map the string outcomes emitted by ContextRouter.prep() to downstream execution paths: - When context_router outputs "direct", execution proceeds immediately to identify_abstractions, bypassing intermediate abstraction mapping. - When context_router outputs "batch", execution is routed to map_abstractions, which iterates over chunked repository contents before passing intermediate representations to reduce_abstractions. - When context_router outputs "deterministic", execution branches to deterministic_mapper, which assigns chapters directly to files and connects directly into write_chapters, bypassing analyze_relationships and order_chapters.

    Both the identify_abstractions and reduce_abstractions nodes feed into analyze_relationships, joining the direct and batched pathways. Downstream from chapter ordering, the write_chapters node receives dependencies from either order_chapters or deterministic_mapper. Finally, all generated chapter files are compiled into a unified tutorial via combine_tutorial. The function returns a Flow instance with start=fetch_repo.
