    flow

    Source: flow.py

    The flow module acts as the central orchestration layer for the Codebase Knowledge Builder pipeline. It defines and compiles the directed acyclic graph (DAG) of processing nodes using the pocketflow workflow framework. By wiring together repository fetching, context-aware routing, abstraction extraction, relational synthesis, chapter planning, content drafting, and final document aggregation, this module formalizes the end-to-end multi-agent execution pipeline.

    Technical Overview

    The primary responsibility of flow.py is the structural assembly of the tutorial generation workflow via create_tutorial_flow(). The execution graph supports three distinct processing routes depending on repository size, token budget, and user specification:

    1. Direct Path ("direct"): Routes smaller codebases directly to a single-pass abstraction identifier (IdentifyAbstractions), bypassing chunking and map-reduce phases.
    2. Batch Map-Reduce Path ("batch"): Routes larger codebases through chunk-level extraction (MapAbstractions) followed by aggregate summarization (ReduceAbstractions).
    3. Deterministic Path ("deterministic"): Bypasses dynamic abstraction analysis altogether via DeterministicFileMapper, mapping chapters directly from file hierarchies before chapter writing.

    Nodes executing LLM generation tasks are initialized with built-in retry and backoff policies (max_retries=5, wait=20) to handle transient rate-limiting and service disruptions gracefully.

    Module-Level Functions

    create_tutorial_flow()

    Visibility: Public
    Signature: def create_tutorial_flow() -> Flow:

    Description:
    Instantiates all processing nodes defined in nodes, sets their fault-tolerance parameters (maximum retry counts and exponential backoff wait durations), builds directional transitions and conditional routing branches between nodes, and wraps the resulting pipeline into an executable pocketflow.Flow instance starting at FetchRepo.

    Parameters:
    * None.

    Returns:
    * Flow: An initialized pocketflow.Flow pipeline with FetchRepo designated as the root entry point.

    Raises:
    * None directly during creation; errors in node instantiation or invalid routing declarations are propagated from pocketflow during runtime flow compilation.

    Implementation: 

    def create_tutorial_flow():
    fetch_repo = FetchRepo()
    context_router = ContextRouter()
    map_abstractions = MapAbstractions(max_retries=5, wait=20)
    reduce_abstractions = ReduceAbstractions(max_retries=5, wait=20)
    identify_abstractions = IdentifyAbstractions(max_retries=5, wait=20)
    analyze_relationships = AnalyzeRelationships(max_retries=5, wait=20)
    order_chapters = OrderChapters(max_retries=5, wait=20)
    write_chapters = WriteChapters(max_retries=5, wait=20)
    combine_tutorial = CombineTutorial()
    deterministic_mapper = DeterministicFileMapper(max_retries=5, wait=20)

    fetch_repo >> context_router

    context_router - "direct" >> identify_abstractions
    context_router - "batch" >> map_abstractions
    context_router - "deterministic" >> deterministic_mapper

    map_abstractions >> reduce_abstractions

    identify_abstractions >> analyze_relationships
    reduce_abstractions >> analyze_relationships

    analyze_relationships >> order_chapters
    order_chapters >> write_chapters

    deterministic_mapper >> write_chapters

    write_chapters >> combine_tutorial

    return Flow(start=fetch_repo)

    The function orchestrates node dependencies through operator overloading provided by pocketflow: * The standard forward transition operator >> establishes unconditional sequential execution between nodes (e.g., fetch_repo >> context_router). * The branch operator - "<action>" >> establishes conditional routing based on the action string returned by the preceding node's post() method (e.g., context_router - "direct" >> identify_abstractions). * Multiple upstream nodes converge onto downstream synchronization points; for instance, both identify_abstractions and reduce_abstractions converge into analyze_relationships, while order_chapters and deterministic_mapper both feed into write_chapters. * Fault-tolerant nodes (MapAbstractions, ReduceAbstractions, IdentifyAbstractions, AnalyzeRelationships, OrderChapters, WriteChapters, DeterministicFileMapper) are instantiated with max_retries=5 and wait=20 seconds to absorb API rate-limiting exceptions or transient network timeouts during execution.

    Node Configuration Matrix

    The following table summarizes the node instances configured within create_tutorial_flow():

    Node Name Class Reference Retry Count Backoff Wait (s) Role in Pipeline
    fetch_repo FetchRepo Default (0) Default (0) Fetches and prepares repository files from local paths or GitHub URLs.
    context_router ContextRouter Default (0) Default (0) Analyzes codebase token size and chooses the generation strategy.
    map_abstractions MapAbstractions 5 20 Extracts domain abstractions across chunked file batches in large codebases.
    reduce_abstractions ReduceAbstractions 5 20 Merges and deduplicates chunk-level domain abstractions.
    identify_abstractions IdentifyAbstractions 5 20 Extracts domain abstractions in a single pass for standard codebases.
    analyze_relationships AnalyzeRelationships 5 20 Analyzes interactions, interfaces, and data flow between abstractions.
    order_chapters OrderChapters 5 20 Determines pedagogical reading order and assigns prerequisite structures.
    deterministic_mapper DeterministicFileMapper 5 20 Maps files directly to chapters deterministically without abstraction analysis.
    write_chapters WriteChapters 5 20 Generates detailed Markdown content for each chapter concurrently or iteratively.
    combine_tutorial CombineTutorial Default (0) Default (0) Compiles all generated chapters into the final cohesive tutorial artifact.
